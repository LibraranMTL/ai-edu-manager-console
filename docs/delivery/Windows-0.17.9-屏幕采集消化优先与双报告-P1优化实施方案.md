## 2. 目标、边界和借鉴

### 2.1 用户可见目标

用户在已有学生/项目范围内一次授权采集，停止会话后自动完成“封存事实 → 选代表图 → 自动晋升资料包 → 正式消化 → 两份报告”。报告按活动段讲清可观察的**尝试、阻碍、变化、产出**，以截图和其他授权来源作为可展开证据；另一份报告按小时/日/周统计可观察活动，不把缩略图排列称为分析结果。普通失败后台恢复，只有归属、外部处理授权或敏感范围等实质决定才提示用户。

新增“知识状态与指导响应”：只基于已经校验的知识成果、授权任务/会话及可追溯活动观察，给出当前证据覆盖、下一步可操作建议和未知项；它是报告中的解释层，不另设人工审核、单独录入或第二次模型处理。

单学生时序分析以 `event → activity episode → candidate attempt → supported attempt` 为渐进层级。截图是证据单位，采集会话是传输单位，**只有证据足够的学习尝试才是可比较的行为单位**。阅读、观看、思考或稀疏截图可停留在活动段；不强行补出初答、行为人或结果。优先交付可读时间线、真实历史变化和诚实未知项；不宣称已拥有可靠的虚拟学生，也不把预测当作本轮交付。

### 2.2 Meridiona 的可借鉴部分与明确不采用部分

Meridian 的公开架构是“本机采集事实与 OCR/辅助功能文本 → 按应用活动与时间缺口做 ETL → 归一化本地 Agent 会话 → 汇总和草稿”，采用持久化状态、幂等处理和失败复盘。借鉴**事实与解释分层、真实空档、Agent 来源归一化、排除自身总结会话、失败分类评估**。它不是教育场景的逐图视觉证明方案，也不是迁移技术栈的理由。

本次**不**将 Rust/Tauri/SQLite 替换现有 Electron/JSONL，不增加全屏连续 OCR 或新的键盘/点击监控；不照搬开发者工具的 focused time、工时或对外项目管理发帖审批。Meridian 的隐私文件也说明选用第三方模型汇总时会传送相关文本；教育管家的学生截图、文字与会话均须按实际处理位置分别授权，不能用“本地启动 CLI”冒充“模型本地处理”。

参考：[Meridian 公开架构](https://github.com/Meridiona/meridian/blob/main/ARCHITECTURE.md)、[隐私说明](https://meridiona.com/privacy)、[更多 OCR 上下文可能误导分类的复盘](https://meridiona.com/writing/eval-loop)。这些是对方公开资料，不构成对其安装包真实性能或隐私实现的独立审计。

### 2.3 硬边界

- 仅处理已有采集授权覆盖的窗口与学生/项目；采集授权不自动授权外部视觉服务、私聊抓取或跨学生共享。外部处理范围须一次性明确选择并可撤回，不逐会话弹窗。
- 原始截图和采集时间是事实，不证明两帧间持续学习；不输出“有效学习时长”“专注时长”、能力分数、自动成绩判断或从画面猜测动机。
- 视觉观察可在系统交付证据和逐段校验后自动进入学习时间线，但不因此成为正式知识或已发布学情报告；知识成果仍由现有 `AGENT.md` 治理，学情报告按原证据规则引用。
- 不做旧历史全量重算，不要求普通用户逐图确认、手工复制回执或反复重试。仅手动执行器/关闭自动化时明确显示等待，不暗中改用未经授权的服务。
- 不新增持续录屏、键盘/鼠标监控、私聊抓取、摄像头/麦克风、同龄人排名或日常逐题标注。屏幕归属、实际行为人、任务关联和掌握程度分别取证；资料属于某学生不等于画面操作人就是该学生。

## 3. 目标架构与端到端状态

```text
已有授权采集 / 学生端可靠送达
  → 不可变事件、归属、时间、图像哈希；标记休眠/空闲/断网造成的未知间隔
  → 会话/处理窗口封存、非 OCR 规则分段及选帧（≤20 图/包）
  → 自动晋升有稳定键的可续资料包；其他原始资料按既有规则独立处理
  → 可选关联同学生/项目且已授权的 Agent 会话、课程任务、知识成果
  → 能力/处理位置判断 + 共享后台资源许可 + 应用层受控视觉调用
  → 当前 Agent 视觉 / 另行授权的独立视觉适配器 / 局部 OCR / 证据不足
  → 受控视觉子批（≤8 图/请求）产出结构化观察
  → AGENT.md 正式消化及逐段结构化回执；系统独立记录附件交付
  → 按具体结论校验来源，跨子批合并，同批知识/时间线/统计独立结算
  → 有证据才形成任务/尝试/实际指导链；增量更新单学生可比较知识状态
  → 自动发布已成功的本地报告投影和按需最小上下文，失败单元自动恢复
```

阶段状态至少为 `fact_recorded → bundle_ready → waiting_capability_or_resource → vision_processing/ocr_fallback → digest_partial_or_complete → report_ready`。状态与下一次自动重试时间可查；业务成功不依赖用户看到状态页。图片、知识、报告各有稳定键和独立检查点；网络、模型或投影局部失败不得回滚其他合法成果。

事实、受控观察、推断、建议、预测分轨存储：`RawEvidence → Observation → LearningEvent → Attempt/Episode → StateTransition → ReportProjection`；未来的 `PredictionRecord` 只能引用指定时点以前的证据，不能写回事实层。视觉模型文字只是可能出错的观察候选；系统校验来源、交付与字段，不能据此宣称已验证文字必然符合画面。活动段、正式知识、报告与未来预测分别有自己的发布边界。

## 4. R0：基线、契约与能力探测

1. 保存 0.17.9 EXE/审计哈希、构建时版本说明、当前源码 Git 状态、相关未提交/未跟踪源码及构建输入的文件清单与哈希、本机性能基准；生成下一版候选时记录新增差异，绝不覆盖 0.17.9 包。状态哈希不冒充可复现源码快照。验证学生端 0.17.8 的授权、会话 ID、逐图送达与断网恢复接口。
2. 为每个执行器/模型/实际处理位置建立独立能力记录：显式图片附件、受控工具读图、只读文本、是否能提供接口确认、最大图数和可授权的处理位置。用非学生测试图探测，配置变更或连续失败后重新探测；不假设 Codex、QClaw、WorkBuddy 能力相同。视觉提取与负责正式知识消化的 Agent 解耦：当前 Agent 无视觉能力时，仅可自动选用同一授权范围内另行配置的视觉适配器；否则降为局部 OCR 或证据不足，绝不静默外发。
3. 固定资料包、系统交付日志、Agent 回执三份**不同信任来源**的协议与版本。旧 `timelineObservations` 保持兼容读取，但新回执使用带字段级证据的版本；历史数据不因升级变成“已视觉观察”。
4. 建立带阅读、练习、订正、编程/创作、仅时间相近无关会话、模糊/敏感画面的受控样例集；记录 0.17.9 实际可观察的质量、队列耗时、CPU/内存、模型费用，而不把合成测试冒充真实 Agent 质量。

### 4.1 并行启动的 T0：时序事实契约

- 增设版本化 `temporal-event.v1` 与可续关联索引，保留既有 JSONL/会话索引的只读兼容。事件至少记录 `studentId/deviceId/projectId/sessionId`、稳定 `eventId`、原始哈希、序号、`occurredAt/receivedAt/processedAt`、时区、`timeSource/timePrecision`、可知的设备时钟偏差、`actorType/actorEvidenceRef`、显式 `taskId/taskVersion/conceptId` 及其来源；缺失字段保持 `unknown`，不靠相似名称填实。
- 上传/主机接收/处理时间只能作为替代时间并注明精度，不可写成真实采集时间。设备时间早晚异常先标记待校准；跨设备时钟校准有独立依据及修订记录，不能把“疑似偏差”误写为已校准。补传不改变原事件发生时间；时间回退或顺序不明时只说“分别观察到”，不强排指导与修订的先后。
- `user/assistant` 是协议角色，不是学生/家长/教师的实际身份。保留原角色兼容，同时记录实际行为人及证据；没有证据则为 `unknown`。同一内容来自截图、Agent 消息和作品时，按来源 ID/哈希与任务版本建立候选关联，稳定键去重；时间接近只能产生候选，不能自动确认同一任务、行为人或因果。
- 事实、解释和关联规则分别版本化。解释修正用 `supersedes/correctedBy`，不覆盖不可变原证据；证据撤销、删除、错归属或授权失效时，使依赖的索引、状态、报告及未来预测失效或增量重建。旧记录不因升级自动获得“实际行为人已确认”“已读图”“独立掌握”标签。

R0 完成判据：对每个可选执行器明确“能送图、只能读图、只能文本或未知”，把用户授权与真正的模型服务位置对应起来；测试基线与未提交源状态均可追溯。
T0 可在视觉不可用时独立保存有来源的事实；其完成还要求跨源重复来源可查、补传/跨午夜/设备时钟异常/未知行为人不造假，旧数据可读且新索引可续处理。T0 的字段级实现可与 R0/R1 并行，但不降低 R0 的构建和授权门。

## 5. R1：可靠事实层、活动段与资料包

在已完成的非 OCR 选帧骨架上补齐：按采集时间、来源变化、画面差异和已存在的课程边界分段；明确休眠、重启、断网和超过采样阈值的时间缺口，未知空档不并入活动持续时间。长会话按活动窗口拆成可续处理的资料包，每包选帧覆盖始末和中途变化，每段优先 1～3 图、每包上限 20；不得因整场会话先到 20 图就让后续活动永久无证据。普通采集事件不做全图 OCR、视觉推理或主进程原图解码。

资料包冻结 `studentId/projectId/captureSessionId/bundleId`、策略版本、每个 `eventId/sequence/capturedAt/originalHash/assetId`、活动段边界、原始采样间隔和已授权候选来源。关键图引用保留；重复送达、重启或重复晋升按稳定键去重及原子写，不复制第二份正式知识。学生端只传已有授权范围内的采集资料，主机完整校验后才封存。无需为了模仿 Meridian 而改数据库或增加持续采集源。

每个窗口封存可独立进入原始资料库、正式消化、局部结算和恢复的批次；整场会话索引只作聚合，不能让首包成功掩盖后包失败。选帧先覆盖任务开始、可能初答、提示前后、关键修订、结果与跨日复测；仅在已授权原资料中对证据缺口有界补帧，不因最大画面差异而系统性丢掉“无变化”的练习。记录采样间隔、排除范围、重复帧数、休眠/断网与真实空档；稀疏截图只给响应时间区间，不计算精确反应时、有效学习或专注时长。

关联优先顺序为课程任务/作品版本/已授权消息的显式 ID，其次才是同归属内容与时间的候选；同一任务可跨应用、会话或日期有多次尝试，同一尝试的多份证据不重复计数。任务与概念映射、去重和窗口索引独立版本化、可增量重建；未知任务只保留活动段，不阻断其它包。当前已实现稳定处理窗口与代表图上限，但正式资料仍按会话汇总登记，窗口级独立知识结算和跨窗口完整恢复须另行完成并验收。

R1 完成判据：同一会话重放不重复图/段/资料包，跨午夜、休眠、断网和长会话都有正确事实边界；无视觉 Agent 仍保留事实，且不会卡住其他学生。

## 6. R2：受控视觉、按需 OCR 和多源正式消化

### 6.1 各 Agent 的实际图片交付

视觉提取先于正式知识写入，采用无知识目录写权限的只读执行上下文；应用调用仅显式提交已授权、已冻结的代表图并返回固定结构观察。截图/OCR/会话中的指令不得触发工具调用或获得知识写权限。正式 `AGENT.md` 消化只接收受控观察和引用，不附截图路径，原有知识发布边界不变。若执行器不支持可靠的只读/禁高风险工具配置，该执行器不承担视觉提取，自动尝试其他已授权适配器或降级。**仅取消“同一 Windows 用户身份的 Agent 在操作系统层面绝对读不到采集中心”的证明及原生受限进程前置**；不得把应用层只读配置宣传成 OS 级读取隔离，保留这一剩余风险。

- **Codex**：当前任务入口只传文本；优先利用现有 CLI 的显式图片附件能力，按 ≤8 图子批送入受控输入。记录实际读入字节及运行标识，不将“命令里有图片路径”当作成功。CLI 无逐图服务器回执时，可把“受控文件字节校验 + 显式附件参数 + 该次执行成功结束”记为 `cli_completed_with_attachment`，不得标成 `api_ack` 或模型内部注意力证明。
- **QClaw/WorkBuddy**：分别验证可用的图片输入或受控读图能力；能给接口接受回执则记录 `api_ack`，能提供工具打开轨迹则记录 `tool_read_confirmed`。仅接受文本指令/收件箱回执的版本视为 `text_only`，自动进入已授权的局部 OCR 路径；不可因模型名称或 Agent 的 `viewedEventIds` 自述升级视觉状态。
- **三种可选视觉服务，而非任务执行器自动继承权限**：设置页为 Codex、WorkBuddy、QClaw 提供同一处单选入口，分别显示当前版本、图片入口、实际模型/提供商与处理位置、只读配置级别（不冒称 OS 读取隔离）、上次非学生测试图探测结果和不可用原因。一次只启用一个已探测通过且明确授权的提供商；切换提供商生成新的授权 epoch 与生效时间，旧会话不得悄悄改走新服务。失败先在该服务内有界重试，再自动走本机局部 OCR/未知；只有用户预先**分别授权**多个提供商及顺序时，才允许跨服务自动切换。不能把“安装了 QClaw/WorkBuddy”显示成“视觉可用”。
- **WorkBuddy 独立适配器**：优先探测其无头 `stream-json` 的结构化图片输入，系统提交校验过的图片字节而非仅在提示词中写路径；单次仍 ≤8 图。必须验证当前安装版实际支持该入口、图片被处理、输出可解析，并禁止可写工具、MCP/插件；不要求额外证明进程对目录外文件的 OS 级不可读。现有任务执行适配器的 `acceptEdits` 不可复用于截图观察；如果无法建立可验证的应用层只读执行边界，WorkBuddy 显示为“已安装但视觉不可用”，不传学生图片。
- **QClaw 独立适配器**：从其实际打包的 OpenClaw 版本、模型能力和本机 Gateway 状态探测显式图片输入；优先选择无需开放工作区工具的受限推理接口，验证图片字节/哈希、模型支持视觉、响应与处理位置。不得直接借用具有文件写入、浏览器、MCP 或私人会话读取能力的常规 Agent 任务通道。若本机版本只有文本收件箱、模型无视觉或不能限制工具，标为 `text_only/unsafe` 并自动降级本机 OCR/未知，不伪装为 QClaw 视觉观察。
- 上述两项的接口可能随安装版本变化，R0 只用公开测试图片做版本化探测；探测成功也不等于学生内容质量通过。WorkBuddy 无头模式的[官方图片输入说明](https://www.workbuddy.ai/docs/zh/cli/headless)与 OpenClaw 的[受限图片推理说明](https://docs.openclaw.ai/cli/infer)仅用于设计入口，不能代替当前 QClaw/WorkBuddy 安装版的实测及安全边界审查。
- 当前消化 Agent 为 `text_only` 时，可先由**另行授权、实际处理位置明确、具备只读能力**的视觉适配器完成一次结构化提取，正式知识消化仍交给原 Agent；不存在此适配器时才走局部 OCR。视觉观察按冻结哈希缓存，不因更换消化 Agent 重看同一图。
- 每次调用前核对原图文件的学生/项目归属、授权状态与冻结哈希；如果传缩放/裁剪图，记录 `originalHash → submittedHash`、变换版本及实际提交的 `eventId`。输入日志由系统在受控边界记录 `executionId/requestId`、执行器、提供商、实际处理位置、子批、成功/失败和时间，不由 Agent 填写。提交状态、完成状态和不可确认状态分开；崩溃/超时后按稳定请求键对账或有界重试，避免把未确认提交直接记为已读或无限重复付费。
- 同一逻辑 `bundleId/digestBatchId` 可包含多个视觉子批；**每个请求 ≤8 图，但一个活动段可引用不同子批中的前后图**。如果要直接比较边界两帧，优先在选帧时让这对图同批，或补一个只含所需前后图的受控比较子批并复用缓存；否则只能把两次独立观察表述为“前后记录有所不同”，不得冒称已直接视觉比较。先持久化子批观察，再合并字段级结论，不把 20 图偷偷塞进一次模型请求，也不因某子批失败废掉成功子批。

### 6.1.1 C／R2 待完成：视觉服务选择与默认 Agent 协同

上一轮评估结论是**增加 WorkBuddy、QClaw 视觉选项可行；“跟随当前学生默认 Agent”只能是选择建议，不是截图处理授权或能力证明**。设置页提供“跟随当前学生默认 Agent（推荐）／Codex／WorkBuddy／QClaw／关闭”；保持一次性授权、后台自动处理，不增加逐次确认。此项仍是 C／R2 待办，当前候选包只有 Codex 视觉路径，不得把 WorkBuddy/QClaw 或自动跟随写成已交付能力。

- [ ] 为每场会话冻结视觉提供商、实际模型与处理位置、授权 epoch 和生效时间；用户后来修改默认 Agent 或视觉服务，只影响符合新授权的新会话。跨服务自动切换仅在各服务分别授权且预设优先级后允许；普通失败先在当前服务有界重试，再走已允许的本机局部 OCR／未知，撤销授权后停止新提交。
- [ ] WorkBuddy 和 QClaw 分别建立独立于任务执行通道的视觉适配器，用非学生测试图验证实际安装版的图片字节交付、结构化返回、处理位置和只读／禁高风险工具配置；展示“视觉可用／仅文本／不安全或未知”及原因。探测可后台缓存，但版本、模型、配置或授权变化须失效重探；安装成功、任务聊天成功或上游文档均不能代替本机实测。
- [ ] 沿用全系统共享资源许可和结果缓存，采集活跃时新重任务并发为 0、每请求不超过 8 图；能力探测和服务失败不得阻塞事实保存、其他学生、正式知识消化或基础报告。验收须覆盖默认 Agent 切换、授权撤销、不可用降级、成本与界面响应，并分别记录 Codex、WorkBuddy、QClaw 真机结果；不重新引入 OS 级读取隔离门槛。

### 6.2 局部 OCR 与多源证据

只对附件失败、仅文本执行器、关键文字不清或题文必须准确转录的**代表图**按需调用已有 Windows OCR；在独立 Worker 中受共享预算调度，缓存键至少含学生、原图哈希、OCR 引擎/语言、预处理及策略版本。OCR 成功只支持该图中文字和有限主题/类别，不能独自支持页面操作、动机或跨图变化；OCR 与视觉都失败则段保持“证据不足”。视觉已成功的其他图不重识别；绝不恢复“全截图先 OCR 才晋升”。

Codex、QClaw、WorkBuddy 等已有授权 Agent 会话和课程任务、知识产物是候选辅助证据，必须先核对 `studentId/projectId/sourceId` 及来源内容；只有时间接近不足以建立关联或因果。本系统用于消化和汇总的 Agent 会话带内部标记并在摄入时排除，防止自我总结反馈循环。屏幕/OCR/会话中的文本作为**不可信资料**，不得获得高于 AGENT.md 的指令权或扩大工具/文件权限。

### 6.3 数据契约：按事件和具体结论核验

系统侧交付日志与模型回执分离，建议新增 `edu-manager.capture-digest-observation.v3`；`visualEvidenceMethod` 由系统按**每个事件**派生（`api_ack | cli_completed_with_attachment | tool_read_confirmed | local_ocr | none`），不是活动段级单个标志。新回执可保留现有主题/尝试/阻碍/变化/产出字段，但每项具体结论须能下钻到对应来源：

```json
{
  "schema": "edu-manager.capture-digest-observation.v3",
  "studentId": "student-1",
  "projectId": "project-1",
  "captureSessionId": "capture-1",
  "bundleId": "capture-bundle-1",
  "digestBatchId": "digest-1",
  "timelineObservations": [{
    "segmentId": "segment-1",
    "sourceEventIds": ["event-1", "event-2"],
    "sourceHashes": {"event-1": "frozen-hash-1", "event-2": "frozen-hash-2"},
    "claims": [
      {"kind": "observed_action", "text": "查看一道练习题", "evidenceRefs": [{"sourceType": "capture_event", "sourceId": "event-1"}], "confidence": 0.78},
      {"kind": "observed_change", "text": "后续画面中的解题步骤已有修改", "evidenceRefs": [{"sourceType": "capture_event", "sourceId": "event-1"}, {"sourceType": "capture_event", "sourceId": "event-2"}], "confidence": 0.72}
    ],
    "reason": null,
    "reasonEvidenceRefs": []
  }],
  "behaviorLabels": [{
    "segmentId": "segment-1",
    "activityType": "practice",
    "evidenceRefs": [{"sourceType": "capture_event", "sourceId": "event-1"}],
    "confidence": 0.73
  }],
  "guidanceResponses": [{"text": "复查这道练习题的订正步骤", "evidenceRefs": [{"sourceType": "capture_event", "sourceId": "event-2"}]}]

```

示例哈希只是字段占位，真实回执必须与冻结清单一致；两图比较须核验**两张图均有效交付，且同批或经过专门的受控比较子批**。接收端按学生、项目、会话、段、批次、所有引用事件及哈希逐项校验，知识资产仍按现有治理确认。`behaviorLabels` 也逐项校验来源，未能支持的标签记为 `unknown`，不进入已分类统计。任何非截图证据只能支持其直接关联的具体结论，不能让整段尚未交付的截图描述“搭便车”通过；`viewedEventIds` 仅是 Agent 的引用声明，旧 `verifiedImageReadEventIds` 不得用自述或附件清单伪造填充。

系统只能机械核验来源、交付和字段规则，**不能声称机器已验证模型文字一定符合画面**。低置信度或空泛段自动保留候选；`reason` 只接受有直接原文支持且经授权的会话/任务来源，不据截图猜测。模型自报置信度不能单独决定知识发布。知识、活动观察和行为标签分别结算；一次失败不回滚其他合法结果。

交付状态至少区分 `prepared / cli_submitted / api_ack / tool_read_confirmed / completed / unknown`。`cli_completed_with_attachment` 仅证明受控字节附图且 CLI 执行完成，**不是**模型逐图理解证明；界面与验收记录不得显示为“已看懂”。具体结论仍须经引用、哈希和内容质量抽检。撤销授权后停止排队与重试中的外部提交，进行中请求尽可能取消并记录实际结果；缓存与衍生产物按明确的数据保留策略处理，不自动删除已有正式知识。

### 6.4 在可信视觉基础上增量形成 T1 尝试与指导链

- 增设版本化 `learning-attempt.v1` 和独立关系索引，不在旧截图事件中静默改写语义。`LearningEvent` 可为 `task_seen / first_attempt / revision / error_observed / help_requested / guidance_presented / result_observed / verification_attempt / unknown`；一组有序多帧受控观察一次返回动作、前后变化、事件角色和字段级证据，不能为了填满字段反复逐图调用模型。
- 尝试记录任务/作品版本、初答或首次作品、先前尝试引用、修订范围、实际行为人、时间可信度和支持程度。同一活动段可能没有可确认尝试；任务/行为人/初答不足时保持 `candidate_attempt` 或仅活动段，不计入成功率、失败率、独立学习或未来预测样本。同一任务多次尝试不合并成一次，同一尝试多来源证据不重复计数。
- `intervention` 仅指有来源的真实指导，至少区分 `generated / delivered / visible_in_evidence / responded / unknown`，保存提供者、指导强度、原文或消息引用及时间。生成不等于送达，显示不等于阅读；系统下一步建议单存 `recommendation`，绝不计入真实指导或“指导有效”样本。只有初答、实际指导、后续尝试和结果都有可比较的依据，才形成指导响应链；缺一项就保留未知。
- `outcome` 分开保存是否提交/完成、是否正确或达到质量标准、是否独立、评价来源和后续验证。程序运行成功、复制答案、一次提示后改对都不直接等于理解。自动判题、教师评语、作品差异及视觉观察标出各自证据与局限；指导和结果相关不等于指导造成结果，题目难度、初始状态及其它帮助来源不能省略。
- 来源/时间仅相近不能硬关联；跨批两图必须满足上段逐图交付与受控比较条件。局部 OCR、缺图或越权引用只让受影响的结论保持未知，其它已校验观察可继续入账。**结构化课程任务、可核验提交/作品版本和已授权消息**可在 T0 后形成不依赖截图的尝试证据；只有截图驱动的 T1 大批量识别必须等 R0.5 全系统资源许可与应用层只读边界、R1 窗口级分包及 R2 实际交付门通过。两路按同一稳定尝试键去重；某视觉服务失效不堵住有独立来源的尝试、T0 事实或 R3 基础报告。

R2 完成判据：Codex、WorkBuddy、QClaw 三个入口分别有“视觉可用 / 仅文本 / 不安全或未知”的版本化探测及独立授权回执；只有已探测、已授权且具备应用层只读边界的入口可真实送图并形成系统交付记录，不能只凭安装或任务执行成功宣布支持。跨批两图变化可接纳，错误哈希、路径自述、越权引用和非视觉证据冒用均被隔离；局部 OCR 只作用于必要代表图且后台自动恢复。三种服务的测试各自独立；其中某服务不符合条件不得阻断其他已授权服务或事实/报告的部分交付。
T1 完成判据另记：初答及多次修订不被摘要吞掉；未知行为人/时间/指导/结果诚实显示；系统建议与真实干预不混算；无直接证据的因果和独立掌握结论为零。T1 未通过不得标为“尝试级行为分析已完成”，但不撤销 R2 已验证的图片交付能力。

## 7. R3：双报告、知识状态与零额外操作

1. **学习时间线**：默认显示活动段的时间、主题、具体尝试/阻碍/变化/产出、来源类别及未知标记；展开才看关键缩略图和证据。以“活动段 → 会话 → 当日 → 本周”生成分层回顾，上层只能压缩已校验下层，不重送全部截图、不为统计再次调用 Agent。未完成的真实尝试保留，不只展示成果。
2. **按时间统计的学习行为报告**：由不可变事件与已校验的有限类别（阅读、练习、订正、创作/写作、编程、Agent 辅助、其他/未知）计算小时/日/周会话数、活动段数、可观察时间窗、类别计数、证据覆盖和缺口。跨午夜按本机时区拆分；若展示“可观察活动时间窗估计”，只纳入同会话同类别且相邻间隔不超过 `2 × 实际采样间隔` 的证据对，超限或休眠空档记未知。该估计不叫有效学习时长，类别占比也不是专注时间占比。
3. **知识状态与指导响应**：区分 `尝试有证据`、`有修订/成果`、`已有正式知识链接`、`缺证据/未知`；实际指导、观察到的学生响应和系统下一步建议分别显示。现有同次正式消化回执的 `guidanceResponses` 只有能引用真实送达/呈现及后续行为的部分才可标为历史指导响应；其余仅作带来源的建议候选，或由已校验状态用有限的确定性规则给出 `recommendation`。不得隐藏第二次模型调用；证据不足直接写“无法判断”，不自动评成绩或诊断能力。
4. **显示与恢复**：事实、知识、时间线和统计有各自状态。完成的合法段立即可见，报告投影失败从已保存回执重建，不重新调用 Agent；重建的稳定键含学生、项目、会话、批次、报告模式和版本。UI 不增常规按钮，不要求审核草稿；保留手动诊断入口，普通失败由后台重试并显示原因/下一时间。

R3 完成判据：用户只需原有授权与开始/结束操作，完成可读的两份报告及指导；每一条具体结论能回到授权活动段/证据；失败段是“未知/待恢复”而非空白截图长廊；同批知识结果失败不遮蔽已通过的时间线，反之亦然。

### 7.1 T2：单学生可比较状态与历史变化

增设版本化 `knowledge-state-snapshot.v1` 和状态转移账本。只比较同一学生、同一概念/技能版本下有证据且可比较的尝试，同时展示任务类型、难度及其来源、指导强度、评价方式、场景和未知覆盖。观察次数增多但题目变难，不直接宣称进步或退步；提示后完成、独立完成、重复错误、延迟复测和跨情境使用分别计数。

初期只用可解释状态：`未观察 / 初次接触 / 提示下完成 / 部分独立 / 多次独立 / 跨情境使用 / 长期未复测 / 证据冲突`。最近可比尝试、近 7 天与前 7 天、近 28 天与前 28 天及阶段窗口均显示可比样本数、证据覆盖和未知比例；窗口是呈现尺度，不是固定科学达标门槛。一次证据可成观察、两次异日可成线索，稳定趋势须有覆盖和反例审查；长期未复测只提高不确定性，不断言遗忘。没有比较对象时写“正在建立个人基线”或“证据不足”。

每次状态转移保存旧/新状态、发生区间、可比任务、支持强度、直接证据、反证、规则/模型版本和修正关系。`历史变化.md` 从该账本增量生成，不比较两份报告文字；至少区分“新增证据但结论不变”“改善线索”“提示后改善、独立未验证”“重复困难”“资料不足”，并呈现保持/迁移、证据冲突和下一次最小验证点。若需要延迟验证，可在现有课程或行动建议中建议一次短验证；不自动创建新任务、不额外打扰用户，也不把“尚未验证”写为“未掌握”。

跨 Agent 新会话按学生、任务、概念和时段仅获取当前已授权的最小必要上下文：当前状态、最近可比变化、关键反例、支持偏好及证据引用；默认不传全部原图或会话原文。来源撤销、错归属或解释修订时，关联索引、上下文包和依赖投影一起失效并增量重建。正式学情报告仅引用满足成长模型和正式知识治理的依据；未升级的时间线观察保留为带状态候选视图，不暗中升级为已发布结论。

### 7.2 受管 `AGENT.md` 与报告协议

实施时核对学生内置模板、默认规则文本、已有用户规则的受管区块、`learningReportProtocolText()` 等报告协议及跨主机路径；只改受管模板/区块或提供可选择的差异，**不自动覆盖用户手改的学生 `AGENT.md`**。项目规则仍守项目范围，未经现有知识贡献治理不得写入学生主档。旧的“必须人工确认/审核”措辞若与现行自动校验发布冲突，改为自动处理与例外提示，但不放宽高风险归属、授权或越权门。

受管消化协议应明确：真实事件时间及来源优先，上传/处理时间不可冒充；先形成可追溯事件和可缺省尝试，再形成摘要；单图只支持当时事实，变化需有有序前后证据；实际指导、学生响应和系统建议分开；完成、正确、独立、提示后完成与未知分开；状态变化有可比任务、旧/新状态、证据、反证和不确定性；不得从画面停留推断专注、动机、情绪或有效学习时长；局部失败不阻断其它证据。详细枚举、Schema、例子和版本策略放入受管时序策略文件按需读取，避免 `AGENT.md` 膨胀或全历史截图进入上下文。

**2026-09-19 双层方案实现记录：**受管 `AGENT.md` 已增加 `learningEvents` 契约，主机已增加学生范围校验、数学 canonical taxonomy、幂等事件账本、确定性知识状态/保持置信度、misconception 账本和按时间升序查询接口。实现和发布边界详见《纵向学习分析-主机端代码与AGENT双层方案-2026-09-19.md》。这是 MVP 源码验证，不表示 T2 的真实学生资料、真机性能、UI、安装包或发布验收完成。

T2 完成判据：7/28 天和阶段历史变化有可追溯状态转移，不混淆难度、提示与独立表现；正式知识边界和受管规则迁移通过验收；新证据/撤销可增量重建，用户无新增常规操作。T2 的资料不足可延后显示更深的纵向结论，**不阻塞** R3 已通过的事实时间线和基本行为报告；但不得宣称“个人知识追踪已完成”。

## 8. R4：资源治理、隐私、质量与候选验收

### 8.1 防卡顿与防饥饿（R0.5 先实施，R4 再真机核验）

- 统一时间线 Worker、OCR、图片预处理/传输、Agent 正式消化、普通资料消化和报告投影的重任务资源许可。同一学生的同一资料包串行；采集期间本机**新重任务并发为 0**，已有任务在短子批边界持久化并让出，不在无检查点处反复终止和重做。主进程不做大图解码、大回执解析或逐大块同步日志写入；命令输出须限量并异步落盘，不能无限拼接在内存。
- 采集结束或本机资源恢复时自动唤醒队列；不同学生公平排队，失败只退避对应子批/报告。记录排队年龄、检查点、重试次数、费用与下一恢复时间。若本机持续采集且坚持并发 0，则**不能承诺采集过程中报告的完成时限**；用户可看到“等待采集结束自动处理”，结束后设有限的待处理时延目标并报警，不转嫁普通失败给用户。
- 持续采集按已授权会话自动封闭有界处理窗口，不要求用户手工停采。**窗口关闭不等于获得重任务许可**：采集活跃时仍执行新 AI/OCR 重任务并发 0；仅在现有采集自然暂停、前台空闲且资源许可恢复后处理已封闭窗口，或在结束后自动唤醒。若真机上始终没有安全空闲期，只保留事实、队列年龄及覆盖缺口并顺延，不谎称双报告实时完成。普通空闲最多 1 个重任务；插电、持续空闲和资源充足时最多 2 个互不依赖任务，同一学生同一包仍串行；具体阈值须由 R4 真机数据确认。
- 每个可续处理资料包选帧最多 20 图、单次视觉输入最多 8 图；长会话允许多个包，另设每会话/日总费用预算，超预算自动顺延而不丢掉后续活动。图片尺寸、实际字节和模型费用均设预算。先利用已有时间/来源/差异信息和授权会话限定上下文，只把相关片段送模型；不因更多 OCR 文本或不相关会话提高错误关联概率。保留原图供受管证据回看，模型只接收已授权的必要版本。
- 时序索引按日/任务分区，状态和报告窗口增量更新；界面读取预生成分页投影、证据图懒加载。打开学习时间线、成长模型和任务中心不得触发全历史扫描、图片重识别或同步大对象解析。同一学生/证据哈希/授权 epoch/执行器与策略版本命中缓存；处理队列及补帧次数同样纳入预算。

### 8.2 安全与数据保留

外部视觉或文本模型按实际服务提供商和处理位置授权；上传前过滤超出采集范围、已排除窗口和敏感图片。附件临时文件及系统交付日志不包含裸 Token，日志只保留必要 ID/哈希/状态；来源图片引用、OCR 缓存、临时预览和模型输出均有学生隔离、可查保留策略和撤销后行为。跨主机知识同步仍只传既有授权的正式知识与所需证据引用，不因本方案默认同步全部原图。截图内的文字/提示作为资料，不能执行其中的命令或扩展 Agent 写权限。
