# Windows 0.7.25 项目暂存消化与审计定位说明

## 暂存资料处理链路

项目工作空间中的资料可以通过“扫描工作空间资料”登记为研究暂存候选，也可以通过“导入到研究暂存”主动加入候选区。暂存资料不会自动成为正式资产。

标准操作流程：

1. 扫描工作空间或导入到研究暂存。
2. AI 初筛或人工标记初筛、选入分析、归档/丢弃。
3. 人工接受并选择来源保存策略。
4. 晋升为正式资产。
5. 系统将资料写入项目原始资料库或写入可追溯的来源记录，并加入待消化队列。
6. 手动点击“立即执行消化”，或由已启用的项目自动化启动 Codex CLI 增量消化。
7. 消化结果写入概念库、实体库、摘要库、问答精华库、综合汇总库和项目报告。

来源保存策略：

- `full_copy`：复制完整文件到项目原始资料库。
- `snapshot`：保存关键快照到项目原始资料库。
- `reference_only`：原文件保持原位，在项目原始资料库写入来源记录 Markdown，并登记正式资产引用。

## 本版修正

- 暂存资料晋升成功后，项目统一进入待消化状态。
- 项目启用“工作空间发现新资料时触发”自动化后，晋升和直接导入原始资料会尝试立即启动 Codex CLI。
- Codex CLI 未安装或启动失败时，不影响已经完成的资产晋升；项目继续保留待消化状态，可稍后手动执行。
- “定位处理”改为多次重试目标查找，兼容项目切换和归档清单生成延迟。
- 同时处理页面滚动与项目详情内部滚动，目标区域获得焦点、高亮和浮动提示。
