# Windows 统一 Agent 与课程／卡片 R10 WorkBuddy 真实验收

日期：2026-10-13。版本：Windows 0.21.1 开发候选。候选标签：`unified-agent-cards-r10-20261013`。本记录不等同于正式发布、代码签名、目标机或真实学生资料验收。

## 1. 结论

本轮完成 WorkBuddy 自动分类和受管项目消化的真实通道验收。测试使用 WorkBuddy 2.164.0、用户明确完成的独立官方登录配置和合成资料；没有读取或复制桌面凭据，没有把登录配置写入候选包，也没有向 Agent 开放工具、MCP、任意文件或知识目录写权限。

- 桌面自带 CLI 在独立官方授权下完成三轮稳定性验收：3 轮、18 次真实调用全部通过；每轮包含资格探针、精确项目、纯语义、双项目冲突、敏感资料和跨学生提示注入。
- 最长单次调用 34.341 秒，没有复现认证失败、首次并发故障、敏感场景超时、工具活动或异常进程退出。
- 受管项目消化通过：分类阶段的完整提取结果被消化阶段受控复用，合成图片全链路 OCR 仅 1 次；原件未变化，WorkBuddy 只返回知识候选，宿主校验并提交 1 个受管知识产物。
- 真实验收期间捕获到四种供应商格式漂移，均未造成自动投递：无候选结果附加解释字段、附加 `candidates_backup`、冲突候选缺少学生 ID、以及 JSON 后追加文字或只输出开头围栏。
- 修复后，敏感或冲突结果一律丢弃 Agent 候选并进入人工确认；只有无候选且已被风险标记的结果允许丢弃尾部说明；带候选结果仍必须满足完整学生、项目、证据和字段合同。

## 2. 安全边界

1. `sensitive=true` 或 `conflict=true` 时，宿主不采用任何 Agent 候选，只保留风险标记和理由。
2. 无候选结果中的额外供应商字段会被规范化丢弃，不能成为路由、路径或执行指令。
3. 带候选结果出现额外字段、越权学生、未知项目、伪造证据、重复候选或无效分数时仍整单拒绝。
4. 缺失结束围栏只在围栏后的全部内容是单个完整 JSON 时兼容；尾部文字仅允许用于“无候选且敏感／冲突”的阻断结果。多个 JSON、前置文字和带候选尾文仍拒绝。
5. 自动投递仍由宿主的来源授权、固定版本、唯一正文项目标识、阈值、候选差值和学生／项目范围共同决定；模型分数本身不授权投递。
6. Agent 无权移动原件或写入知识目录。受管项目消化由宿主固定来源版本、校验输出、暂存并提交。
