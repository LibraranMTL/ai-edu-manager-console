# Windows 0.7.37：任务协议与自动化闭环加固

## 封闭范围

本版本按审计顺序封闭五项缺口：执行批次校验、强制审核状态机、每日行动建议严格 Schema 与两日反馈、OpenClaw Cron 统一执行、行为级集成测试。

## 协议 1.2

- QClaw 领取、QClaw 结果和人工导入结果必须同时匹配 `protocolVersion`、`taskId`、`executionId` 和可接收结果的任务状态。
- QClaw 和人工任务先建立执行批次，再导出任务包，任务包中的 `executionId` 是结果回写的唯一批次身份。
- 过期、跨任务或协议不匹配的 QClaw 文件会移动到 `qclaw-results/rejected/` 并记录拒绝原因，不改变任务状态。
- `running` 和 `waiting_result` 不再允许直接进入 `succeeded`；只有 `reviewing` 经人工审核后才能成功。

## 每日行动建议

草稿必须包含严格 YAML frontmatter：

```yaml
---
date: YYYY-MM-DD
generated_at: ISO-8601 时间
status: pending_review
---
```

七个必需章节必须存在且非空。审核发布前会重新校验草稿，防止校验后文件被替换。完成、部分完成和跳过反馈只能提交到已发布任务；同日重复反馈会幂等更新，并只进入下一日任务输入。

## OpenClaw Cron 接管

- 只有名称以 `[教育管家]` 开头或 `metadata.owner` 为 `edu-manager` 的任务会被考虑接管。
- 托管定义必须提供命令、受支持的计划、本机时区、绝对读写权限和明确产物路径。
- 系统先持久化托管定义，再停用 OpenClaw 外部 Cron，避免停用后丢失计划。
- 每个计划周期生成独立任务 ID 和幂等键，由任务中心执行、降级、校验和审核。
- 未明确标记的 OpenClaw Cron 只统计观察，不会被停用或接管。

## 行为测试

测试覆盖：

- 成功必须经过 `reviewing`；
- 外部结果批次身份及过期结果拒绝；
- 每日建议严格 Schema；
- 第一天反馈进入第二天且不读取同日反馈；
- 权限穿越、未声明操作和越界产物拒绝；
- 重试排除失败执行器并最终降级人工；
- 每日和间隔 Cron 周期计算；
- 高风险操作排队、适配器注册、UI 详情和 Windows 多行中文命令。

## 兼容性

旧任务账本启动后迁移到协议 `1.2`，迁移前文件保存在 `migration-backups/`。旧协议外部结果不会自动套用到新执行批次，需要按新任务包重新生成结果。
