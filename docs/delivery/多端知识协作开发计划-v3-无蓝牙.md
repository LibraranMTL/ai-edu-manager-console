# 多端知识协作开发计划 v3（无蓝牙）

> 基线：Windows 主机端 0.16.8、Android 单机版 1.1.3、Android 学生端 0.6.14。普通 Windows/Android 学生端继续使用现有主机连接方式，不注册为知识协作节点。

## 1. 交付范围

完整知识节点支持以下组合：

- Windows—Windows：局域网发现、六位临时码或粘贴连接信息；局域网直传，Tailscale 备用。
- Windows—Android 单机版：二维码、六位临时码或粘贴连接信息；Android 主动连接 Windows。
- Android 单机版—Android 单机版：第二批交付；同一 Wi-Fi 或一台设备开启热点，双方在线时同步。

本计划不包含蓝牙、Wi-Fi Direct、云中继、复杂文本自动合并和普通学生端协议改造。

## 2. 核心模型

设备信任与学生授权分开保存：

1. `collaboration-device-binding.v1`：设备身份、能力、共享密钥、候选地址、暂停和撤销状态。
2. `student-collaboration-map.v1`：本机学生 ID、对端学生 ID、同步范围、最近共同版本和暂停状态。

设备只需配对一次；同一设备关系可以逐个增加多个学生。学生必须按 ID 精确映射，不按姓名推断，也不形成学生列表跨设备回退。

旧 `peer-binding.v1` 升级时转换为一个设备绑定和一个既有学生映射，不要求重新配对。

## 3. 同步规则

同步对象保存稳定对象 ID、相对路径、SHA-256、当前修订、父修订和来源节点。

- 本地不存在：写入。
- 哈希相同：跳过。
- 本地仍是共同基础版本：原子更新为远端新版本。
- 本地与远端均已修改：保留本地，远端写入冲突副本。
- 远端删除且本地未修改：移动到受控回收区。
- 远端删除但本地已修改：保留本地，登记删除冲突。

不得仅依赖设备时间判断新旧。二进制文件不自动合并。

### 3.1 非传递同步

远端写入且未在本机修改的文件，默认不自动转发到第三台设备，避免 A—B—C—A 环形关系产生回声和冲突风暴。用户在本机实质修改后形成新的本机修订，才允许发布给其他已授权设备。

### 3.2 路径与本机状态

跨设备包只携带相对路径、逻辑 ID 和内容哈希，不携带 Windows 绝对路径或 Android SAF URI。

以下内容不进入普通档案同步：

- 原始资料库；
- 草稿、占位模板和待审核报告；
- `.edu-manager`、`.ai-manager`、任务队列、锁、缓存和设备密钥；
- 本机绝对路径和运行期 Agent 日志。

知识库、原始资料库、成长模型、报告和档案版本目录可以位于互不包含的独立目录。接收端只使用本机已确认绑定，不接受远端包指定物理目标目录。

## 4. Android 运行模型

- SAF：用户明确授权知识目录，不申请全盘存储权限。
- Room：设备绑定、学生映射、版本清单、增量文件清单、队列、检查点和冲突记录。
- WorkManager：可恢复检查、重试和跨重启任务。
- 前台数据同步：用户点击“立即同步”后使用前台 Worker 并显示持续通知；后台恢复仍使用受系统约束的普通 WorkManager。
- Windows—Android：Android 主动连接持续运行的 Windows 主机服务。
- Android—Android：一端进入“接收协作”，另一端发起同步；未完成任务下次双方在线时继续。

## 5. 界面

“系统设置 → 知识协作”只保留三个用户区域：

1. 协作设备；
2. 共享学生；
3. 同步异常。

节点类型、协议版本、共享密钥、端口和队列技术参数默认不展示。高级连接信息和异常记录折叠显示。

## 6. 开发阶段

### P0 同步基础修复

- [x] 受治理收集器继续作为主进程实际导出，排除原始资料和未发布报告。
- [x] 独立目录按各自读写能力校验，不再要求知识库和原始资料库同属一个根目录。
- [x] 未修改的远端修订默认不转发给第三台设备。
- [x] 远端删除在本地未修改时进入受控回收区；本地已修改时形成删除冲突。
- [x] 冲突和回收文件保留原扩展名并使用稳定可追踪命名。
- [x] 完成全量自动化测试和生产构建。
- [ ] 完成 Windows 双机真机回归。

### P1 Windows 设备信任与学生映射

- [x] 建立设备绑定、学生映射双层数据模型，并从旧绑定自动派生兼容数据。
- [x] 档案同步优先使用精确学生映射，旧绑定仅作为兼容回退。
- [x] 同一对设备的多个旧学生关系在界面上合并为一台协作设备。
- [x] 完成原生设备级配对并复用现有局域网发现、直传、Tailscale 和断点续传。
- [x] 支持六位临时码、复制连接信息和自动双方确认；临时码十五分钟失效并限制连续尝试次数。
- [x] 一个设备绑定支持多个学生精确映射，不显示教师端、学生资料端或档案权威端设置。
- [x] 自动迁移旧绑定，保留既有项目发布、任务、知识查询和档案同步。
- [x] 完成协议、主进程接线、界面契约测试和生产构建。
- [ ] 完成 Windows 双机设备配对、多学生映射、撤销后重建和断网重试真机回归。

### P2 Android 协作节点基础

- [x] 引入 Room、WorkManager、Keystore 和 SAF 映射；设备密钥只以 Android Keystore 加密密文落入 Room。
- [x] 支持二维码、六位临时码局域网发现和完整连接信息；Android 只主动连接 Windows，不在 P2 开放接收服务。
- [x] 实现设备绑定、学生映射、版本清单、持久队列、检查点基础和冲突表；队列在应用重启后恢复 `running` 任务。
- [x] 学生共享必须人工选择本机精确学生 ID，并在入队前复核该学生 SAF 读写授权，不按姓名猜测。
- [x] 学生映射确认由 Android 自动回传 Windows；Windows 验证设备信任与原邀请后幂等落库，Android 仅在对端确认成功后启用映射，不再要求人工复制回执。
- [x] “系统设置 → 知识协作”只显示“协作设备、共享学生、同步异常”三个用户区域，高级信息不展示密钥或 SAF URI。
- [x] Android 编译、现有单元测试、Windows 生成确认签名的跨端固定向量测试及 Room v1 Schema 导出通过；新密文使用设备绑定 ID 作为 AES-GCM 附加认证数据，并兼容读取早期 P2 密文。
- [ ] 使用 Android 真机完成扫码、六位码局域网配对、完整连接信息、学生映射、暂停/撤销和杀进程恢复验收。

P2 只交付协作节点与可恢复状态基础；知识正文的拉取、推送、分块和冲突落盘仍属于 P3，不把“设备已连接”表述为“档案已同步”。

### P3 Windows—Android 同步

- [x] Android 主动拉取 Windows 待发送学生档案包，并主动把本机修订推送到 Windows；Android 不开放常驻接收服务。
- [x] 复用 Windows 直传请求签名、版本清单、SHA-256、1 MB 分块、断点和幂等提交协议。
- [x] Room v4 保存映射传输谱系、对象修订、增量文件清单、持久队列、冲突和“已物化/已确认”包检查点，应用或网络中断后不重复落盘。
- [x] 严格校验设备、映射、双方精确学生 ID、SAF 树授权、四类同步范围和路径边界；原始资料、草稿、冲突副本和回收副本不进入发件清单。
- [x] 本地未修改时快进；并发修改保留本地并写远端冲突副本；远端删除先进入可恢复回收区；远端原样修订不回传。
- [x] 支持局域网和 Tailscale 候选地址；每十五分钟后台尝试，也可在共享学生卡片点击“立即同步”。手工同步进入前台 Worker，失败任务按 Room 中最早重试时间精确续跑。
- [x] Android 与 Windows 的请求签名、清单回执签名和学生谱系固定向量测试通过。
- [x] Windows 与 Android 均按最多 999 个档案条目稳定分包，5005 条对象自动形成 6 个可断点、可幂等提交的包；Android 每个同步范围支持最多 20000 个文本文件，超限或单文件超过 64 MB 时明确失败，不静默跳过。
- [x] Android 使用 Room v4 增量清单复用一小时内且大小、修改时间完全一致的文件哈希；SAF 修改时间不可用时仍重新校验。大文件上传只打开一次 SAF 输入流并按断点连续读取，避免每个分块从头扫描。
- [ ] 完成 Windows—Android 真机的多包积压、64 MB 单文件、断网续传、杀进程、并发修改、删除、多学生隔离和 Tailscale 回退验收。

- [x] Android 单机版增加由用户主动开启、可随时停止的前台接收服务；只监听同一 Wi-Fi、热点或已配置的 Tailscale 网络，不增加蓝牙、Wi-Fi Direct 或云中继。
- [x] 两台 Android 单机版可通过局域网发现、二维码、六位临时码或完整连接信息建立双向设备信任；邀请十五分钟失效，请求令牌经 Android Keystore 加密保存。
- [x] 复用精确学生映射，必须人工选择本机学生，不按姓名猜测；学生映射回执同时校验设备信任、原邀请和共享签名。
- [x] 复用版本清单、请求签名、SHA-256、分块续传、Room 检查点、冲突副本、可恢复删除和非传递同步；一端点击“立即同步”时可完成发送，并通知在线对端回传其待同步修订。
- [x] 接收端只接受四类已治理成果，严格拒绝原始资料、草稿、本机绝对路径、SAF URI、Token、License 和密钥；普通 Android 学生端不注册接收服务或知识节点能力。

### P6 第二批候选包

- 路由器、热点、大文件、前后台切换、杀进程和冲突恢复。

## 7. 发布闸门

1. 不发生跨学生写入或姓名猜测绑定。
2. 不发送原始资料、草稿、本机绝对路径、SAF URI、Token、License 或密钥。
3. 三节点环形关系不会自动回传未修改的远端内容。
4. 冲突不静默覆盖，删除可恢复。
5. 旧绑定和普通学生终端连接继续工作。
6. Android 杀进程或重启后能够从持久检查点继续。
7. 候选包必须通过自动测试、生产构建和对应组合的真机验收后才能转正式版本。
