## 实际修复

1. **隐藏 `/login` 无法登录**：官方 CLI 源码在 stdout 非 TTY 时自动进入 print 模式。R16 以管道启动 `/login`，实际只得到 Authentication required，退出码甚至为 0，并未打开登录流程。
   - 改为官方 CLI `--serve` 的 account/login 接口。
   - 只绑定 127.0.0.1，随机临时端口；32 字节随机密码仅在进程环境/请求头中使用；强制 password 认证，保留官方请求安全头。
   - 保持受控工具、MCP、插件与 hooks 限制；无模型提示词随登录发送。
   - 不把服务日志、账户详情或登录 URL 返回渲染层。浏览器入口严格限制为 HTTPS 的 www.workbuddy.cn/login。
   - 完成、失败、超时均停止本轮登录子进程；官方状态与合成执行资格验证分开。
2. **交接失败仍显示等待**：等待桌面进程的 spawn/error 结果；启动异常、空链接、交接包写入失败均落盘为 failed，不继续假等待，不覆盖已变化的执行批次。
3. **手工动作标记丢失**：结果格式化保留宿主给出的 handoffState/requiresUserAction；Agent 回执不得自报该控制标记。收到有效回执后清除待发送标记。

## 下一步本人操作

在新候选包的“Agent 接入与调度中心”选择学生，点击“连接／授权 WorkBuddy”，在新打开的官方页面完成登录，再点击“已登录，验证并恢复分类”。登录共享，但学生/项目资料权限仍独立。资料消化执行资格会在消化前独立检查。

完成本人登录后，需再次运行 WorkBuddy-only 合成消化，确认 READY、受控执行资格和宿主知识提交均成功，才能把后台直接执行验收标为通过。无需重复开启其他 Agent 或扩大资料授权。
