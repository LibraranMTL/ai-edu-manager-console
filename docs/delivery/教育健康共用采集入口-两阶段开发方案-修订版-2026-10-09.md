# 教育与健康共用采集入口：两阶段开发方案（修订版）

日期：2026-10-09  
状态：开发规划，未实施；本文件替代本次讨论中的上一版两阶段计划。  
适用端：Windows 主机。保留现有教育功能、目录、接口和客户端兼容。

## 一、已确定的产品决策

1. 共用采集入口和底层文件处理能力，按人物、领域分流；教育与健康分别保存、处理和查询。
2. 引入通用个人档案 Profile，允许现有学生启用健康档案，也允许成人独立建立健康档案。
3. 第一阶段完成可靠归档；第二阶段完成“体检报告整理 → 指标趋势 → 就诊准备单”的非诊断管理闭环。
4. **备份与迁移直接导出，不新增加密、密码或密钥步骤。** 教育、健康都沿用现有非加密导出原则，保留文件哈希校验、恢复预检和失败回滚。已有旧加密包仍按原功能读取，不属于新增开发。
5. 已确定人物和领域时，一次保存即可完成收件登记和归档；正常资料后台处理，归属不明、识别冲突等例外才提示。
6. 两阶段均不引入机构账号体系、健康服务转介、支付预约、健康项目管理、跨领域综合分析、健康云分享或新的外部 Agent 开放接口。
7. 健康连续屏幕采集和健康自动会话采集后续另行安排；现有教育连续采集与会话采集照常使用。

## 二、架构与兼容原则

### 2.1 人物与领域

- Profile 只表示稳定人物身份，至少包含 ID、显示名称、状态、可选教育关联和时间戳。学生身份、成年状态和家庭关系不混入一个互斥 role 字段。
- 现有学生建立稳定一对一映射，保留 studentId，不按姓名合并人物；成人健康档案使用独立新 ID，无需创建 Student。
- 教育身份字段仍由 Student 维护，Profile 通过关联读取；健康独立人物的显示名称由 Profile 维护，避免姓名双向同步冲突。
- 现有学生映射按需建立并原子持久化，重复启动不重复创建。健康空间仅在用户启用时创建。
- 新增人物不自动推断家庭关系；首版支持人物列表、搜索、切换、新建、改名和归档。

### 2.2 存储与权威数据

- 教育原有 ID、目录、索引格式、Student 接口和 edu:// 引用不改写；通过适配层接入统一采集契约。
- 健康根目录放在配置资料位置下的独立“个人档案”区域，不能嵌套于任何教育知识库、原始资料库或项目扫描根目录；创建和重新绑定均检查真实路径交叉。
- 健康空间使用稳定 ID 绑定路径。改显示姓名不自动搬目录；UI 显示友好名称，不要求用户理解 ID。
- 健康目录包括资料收件箱、原始资料、健康记录、指标趋势、就诊与检查、用药与过敏、健康摘要，以及受管元数据目录；第二阶段需要时才生成派生内容。
- 原件是证据；主机维护的结构化账本是记录状态的权威来源；Markdown、图表、摘要是带来源和版本的派生视图。
- 复用任务中心执行、重试与状态展示机制，为任务增加人物和领域范围；健康任务只维护一份权威记录，不额外建立与任务中心竞争的任务账本。
- 复用资产登记、哈希和文件预览组件；健康资产拥有独立索引与范围过滤，不写入旧教育全局资产记录后再依赖 UI 隐藏。
- 去重范围限定为同一人物、同一领域。相同内容可以有多个来源或测量记录，不能仅靠文件哈希删除业务事件。

### 2.3 最小接口变化

内部统一使用以下概念，具体 IPC 命名沿用项目现有桥接约定：

```ts
type DomainId = 'education' | 'health';
type CollectionContext = { profileId: string; domain: DomainId };
type CollectionTarget = CollectionContext & {
  destinationType: 'profile_raw' | 'project_inbox';
  projectId?: string;
};
```

- 新增个人档案管理、领域采集上下文、健康资产查询和健康空间初始化接口。
- 旧采集接口仅解释为教育范围；新接口必须明确 domain，未知或缺失领域不得自动回落到教育。
- 健康首版只允许 profile_raw；教育项目仍校验当前学生关联与项目状态。
- 主进程解析人物和路径，前端只提交逻辑目标，不允许传入任意写入目录。
- 各任务、收件回执、索引与缓存均包含人物和领域；健康结果不能进入教育检索、成长模型、报告、同步或 query_education_knowledge。
- 同一 Windows 登录用户仍是本地主机操作者；“人物归属”不是“访问授权”。本轮不把多人物档案描述为多用户隐私账户或操作系统级隔离。

## 三、第一阶段：个人档案与可靠采集归档

### 3.1 开工验证与基线

- 当前检查到 package.json 为 0.19.10，开发开始时重新核对正式版、候选版与相关改动，版本号在打包时按版本规则确定，不预占 0.20.1/0.20.2。
- 现有工作区包含其他开发中的改动。建立记录了所需已跟踪及未跟踪文件的源码快照，再创建隔离开发工作区；仅从 Git HEAD 建新工作树不能代表当前候选源码。
- 先用 3—5 个工作日验证：成人无 Student 也能采集、教育原格式不改写、健康候选结果由主机受控接收。验证产物使用测试资料。

### 3.2 UI 与人物选择

- 复用现有采集入口、快捷工具条、文件列表、预览和空状态；教育页面与导航保持现有使用方式。
- 采集页面显示“人物 + 教育/健康”，学生默认教育，健康独立人物默认健康；人物未启用的领域不提供空入口。
- 从教育业务页面进入采集时固定教育，从健康页面进入时固定健康；通用快捷入口使用当前人物最近明确选择的领域，并一直显示该归属。
- 新增健康档案入口，第一阶段仅展示总览、资料与管理；第二阶段增加记录与趋势、行动。无需先让用户配置完整健康字段。
- 学生端、教师终端和 Android 不新增健康入口；其旧教育接口不获得健康能力。

### 3.3 采集渠道与状态

第一阶段支持：拍照、快速截屏、本机文件、下载目录、主动分享，以及录音原件保存。健康录音转写在第二阶段独立授权后启用。

- 已选好目标的本机文件、照片、截图和录音：先持久化收件记录，再自动登记正式原始资料，成功后显示“已归档”；归档失败保留原件并允许重试。
- 公共下载文件夹：保留浏览后选人、选领域、批量投递流程；归属不明确时只显示待分配，不自动调用模型判断。
- 主动分享指主机已有可用的分享接收和手动提交路径，不在本阶段新增手机系统分享端能力。
- 保留渠道现有限制：受控采集对象 20 MiB，本机/下载导入沿用既有白名单与上限；统一入口不把所有文件强制通过 20 MiB 的内存/base64 通道。
- 文件保存成功与可解析状态分别展示。暂不支持解析的文件可保存和预览，不显示为已经AI处理。
- 健康模式不启动教育连续分析、学习时间线或教育对话自动消化任务。

### 3.4 会话归属

- 未开始的配置和未保存快速截屏在人物/领域切换后失效。
- 拍照窗口、录音及已经提交的任务在开始时冻结人物和领域，标题固定显示归属；主页面切换不改变其保存目标。
- 改变正在进行的采集归属需要结束当前会话后重新开始；不默默转移未保存内容。
- 归属对象被归档、移除或失去有效绑定时停止新保存，保留可恢复状态并说明原因。
- 主进程令牌包含人物、领域和上下文版本；异步回执只更新对应上下文，不污染当前页面。

### 3.5 既有 Obsidian/QClaw 资料导入

- 用户选择来源目录后只读预检文件、容量、类型和人物，提供清单；不自动扫描其他个人目录。
- 复制支持的原件至健康空间，记录来源路径、哈希与导入批次；源目录、原有 AGENT.md 和笔记正文保持原样。
- Markdown 中的相对附件按清单一并复制，在新副本维护映射；外部链接或目录外附件标记未导入，不擅自读取。
- 旧 AGENT.md 作为历史规则资料留存，新健康空间使用受管模板；旧AI总结标记历史总结，不自动变成已确认健康事实。
- 首版提供复制导入，不提供原地接管与双向同步；重复导入按内容和来源登记去重。

### 3.6 纠错、归档与删除

- 用户明确发起“纠正归属”，展示原目标和新目标后执行受控复制、核验、登记及原归属撤销；任何一步失败保留恢复记录。
- 纠正归属涉及已处理资料时，旧领域的索引引用撤销，相关派生结果标为过期并重建；不让原领域继续查询到有效内容。
- 教育与健康之间仅允许用户主动转移原始资料；不自动携带学情结论、健康结论或自动触发对方领域的分析。
- 归档人物停止新采集和新后台任务，保留可查看历史；健康档案归档不改变关联 Student 的教育状态。
- 删除健康资料先进入可恢复回收状态，正文与活动索引退出查询；彻底删除前展示下游影响。审计只保留必要操作元数据，不保留被删正文。
- 物理删除、跨领域纠正按现有高影响操作方式确认；常规采集无需反复确认。

### 3.7 备份与迁移

- 新备份和迁移包直接导出，不加密、不设密码；保留清单与逐文件 SHA-256、复制前后校验、暂存恢复及状态回滚。
- 导出范围明确选择教育、健康或两者；健康导出包含人物映射、原件、收件状态、资产索引、记录、任务和派生文档。UI简短标注“包含健康资料，以普通文件保存”。
- 日常状态备份与完整资料迁移继续区分，不把只备份索引称作完整健康备份。
- 新版兼容旧教育迁移包；包含健康的新包由支持该版本的新程序恢复。版本过低在写入前拒绝，不要求旧程序识别新分类。
- 恢复后保留人物与记录 ID，重映射路径；外部模型授权不随资料包自动恢复。
- 回退测试在副本中执行：旧程序可正常使用教育数据，新健康数据留存但不由旧程序读取。不得把未经实际验证的降级称为已支持。

### 3.8 第一阶段交付门槛

使用已有学生和纯成人档案各完成一次：采集 → 自动归档 → 预览搜索 → 归属纠正 → 备份 → 恢复；教育业务和旧客户端回归通过。交付源码变更、接口说明、迁移说明、测试报告、独立候选包和操作说明。

## 四、第二阶段：健康资料自动整理与就诊准备

### 4.1 受控处理与授权

- 首次开启健康AI处理时展示执行渠道、处理内容和是否发送至外部模型；沿用现有凭据配置，但单独保存健康处理授权。
- 本地保存不以模型授权为前提。授权后正常批次后台处理，不要求用户逐份选择Agent或复制指令。
- 首版仅接通一个通过本机验证的执行通道，复用既有调度和资源限制；无可用通道时保留待处理状态，不自动切换未授权提供商。
- 主机冻结本批输入、源文件版本、处理范围和模板版本；Agent返回结构化候选，主机负责验证、去重、冲突检测和提交。
- 执行通道禁止可写工具及不必要插件/MCP；AGENT.md只描述领域规则，不能替代实际通道控制。保留同一Windows用户进程可访问其他文件的系统边界，不宣称OS隔离。
- 撤销授权阻止新提交并尽力取消运行任务；迟到结果不自动发布，界面不宣称已经撤回此前发送给提供商的数据。
- 用户手改规则保留，仅更新受管区块并存差异快照。

### 4.2 数据状态与证据

- 独立维护处理状态（待处理/处理中/完成/失败）与证据状态（机器提取/来源记载/本人确认/存在冲突）。格式校验通过不等于事实经过医学确认。
- 模型提取结果可在通过结构、来源和版本校验后自动展示；注明机器提取，可打开原件校对。
- 原始报告中的诊断、药物、剂量、过敏可保存为“来源记载”；更新“当前用药/当前过敏”等重要摘要需用户确认，不因最近上传自动取代当前状态。
- 人工校正写入更正版本，保留原始提取和证据；重跑模型不能覆盖人工校正。
- 资料归属不明、关键字段冲突、来源缺失和无法可靠解析进入待复核；无法核实的字段留空，不依赖模型自报置信度作唯一入档依据。
- 人物或来源在处理期间更改、撤销、删除时，拒绝过期结果提交。

### 4.3 指标、时间线与解析

- 记录测量/检查时间、报告时间、导入时间及时间精度；缺失测量时间不得用导入时间代替。
- 保留原始指标名称、数值或定性值、单位、参考区间、标本/部位、测量条件、来源页码和定位信息。
- 趋势仅合并明确可比的指标与单位；首版不自动转换不同单位，不因同名就合并空腹/餐后等不同条件。
- 同日多次测量是多条事件；同一报告重复扫描去重；报告更正以版本关系表达，不当作新一次测量。
- 支持图片、文本PDF和扫描PDF逐页提取，以及现有可解析文本格式；分页限量、有界并发和逐页回执，失败页面允许单独重试。
- 展示来源报告的参考区间和原有异常标记，不自行设置疾病阈值或生成诊断。

### 4.4 页面与输出

首版健康模块采用四个页面组：

| 页面组 | 内容 |
| --- | --- |
| 健康总览 | 最近更新、资料覆盖、待复核和近期行动 |
| 资料 | 原件、导入来源、处理状态、搜索与预览 |
| 记录与趋势 | 健康时间线、指标曲线、就诊检查、用药与过敏记录 |
| 行动 | 就诊准备、随访任务、阶段摘要及导出 |

- 就诊准备单整理近期事件、可比指标变化、已确认当前记录和待询问事项；支持本地打印/PDF导出并标明生成时间、资料范围与缺失项。
- 阶段摘要每条实质性陈述可回到来源；空白或资料不足明确显示，不补造结论。
- 原件更正、删除或归属变化后，摘要显示过期状态并后台更新；用户已导出的旧文件不会被声称自动撤回。
- 随访任务区分医生记录、用户设置和AI建议。明确的来源日期可生成带来源的待办；AI推测的复查时间先作为建议，确认后才成为任务。
- 任务沿用统一任务中心；应用内按领域过滤，系统通知默认仅显示“有健康事项待查看”。
- 健康录音转写保留原音频，转写作为机器提取资料进入同一链路，不直接更新当前用药或诊断。

### 4.5 第二阶段交付门槛

完成一份及多期体检资料的自动整理、人工纠正、指标趋势、就诊准备单和随访任务闭环。所有采用的陈述有来源；不提供诊断、疾病预测、处方、剂量调整或治疗决策。健康服务模块、跨领域关联分析和健康项目模板仍留待后续。

## 五、验收、排期与发布

### 5.1 必测场景

1. 既有学生启用健康、成人独立建档、同名人物并存、人物改名与归档。
2. 原教育目录与存储格式不改写；旧客户端、教育资产、报告、成长模型和教育查询正常。
3. 多窗口并行拍照/截屏/录音与主页面切换；归属冻结，旧回执不刷新新人物页面。
4. 保存后归档失败、结果未知、重启重试和重复提交；同一操作不重复登记，失败原件可恢复。
5. Obsidian Markdown与附件导入、重复批次、目录外附件、历史总结和旧规则保留。
6. 20 MiB采集对象和较大本机PDF分别遵守限制；保存成功与解析失败分别展示。
7. 误归属纠正、删除、恢复、处理中更正来源、人工修正后重跑；旧索引与摘要正确失效。
8. 教育健康交叉查询、错误domain、缓存污染、日志正文泄露、路径交叉与符号链接测试。
9. 普通文件完整导出、哈希损坏、版本过低、空间不足、恢复中断，以及两台Windows不同用户名和盘符的恢复。
10. 健康授权未开启、撤销、执行通道不可用、迟到回执及文档提示词注入；不能静默扩大处理范围。
11. 多期报告中数字、小数点、单位、时间、人物、参考区间和来源定位；同日多次测量、定性指标和更正报告。
12. 就诊准备PDF分页、打印、引用定位、资料缺失和过期提示；通知不包含健康详情。

### 5.2 质量门槛

- 先采用合成/脱敏样本，至少覆盖30份资料，并人工标注至少200个指标条目和所有人物归属；关键挑战样本覆盖模糊图片、跨页表格、小数点、单位差异及更正报告。
- 已发布陈述来源可追溯率100%；关键指标数值/单位/时间匹配准确率至少98%，同时报告提取覆盖率，防止通过全部留空达到准确率。
- 挑战样本中的明确关键错误、归属冲突应被标记或阻止进入当前摘要；不能通过自动校验的内容保留待复核。
- 跨人物/跨领域错投、静默覆盖人工校正、无法恢复的原件丢失均为发布阻断项。
- 指定测试电脑记录UI响应和处理耗时；大文件处理不在主线程同步扫描，模型失败不阻断保存和教育操作。
- 完成针对性测试、必要的既有回归、生产构建和隔离候选包验证，再做真实授权资料验收。上述样本门槛是工程验收，不等于临床准确性认证。
