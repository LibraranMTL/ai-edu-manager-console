# 智能资料归集 R8：Codex 授权恢复与项目提示修复

日期：2026-10-12。Windows 0.21.1 独立候选，不是正式发布。未替换正在运行的主机，未读取或重派真实学生资料，未修改生产任务账本、Agent 配置或安全隔离。

## 一、问题与修复结果

截图中的“需人工选择项目／需要重新登录并检测”不是 AI 已分析后无法选择项目，而是当前学生配置的 Codex 处于 `authorization` 熔断状态。分类在读取正文和调用 Agent 前已经停止，因此没有项目建议，也没有投递。

旧版本只能自动探测 `open/half_open` 故障，`authorization` 状态要求人工介入，却没有 Codex 的人工检测入口；即使用户已登录，熔断也无法从界面解除。R8 修复如下：

1. 资料收件箱识别该状态并显示“Agent 授权待恢复，尚未生成项目建议”，不再误导为“需人工选择项目”。原“手动指定位置并投递／纠正”入口保留。
2. 新增“检测当前学生 Agent 授权”。宿主根据当前学生保存的 `agentTool` 选择 Codex 或 WorkBuddy，渲染器不能提交任意执行器；学生不存在或 Agent 不受支持时失败关闭。
3. Codex 检测先重新读取 CLI 安装及登录状态，再发送一次固定的无工具、无 MCP、无学生资料合成 READY 请求。必须由用户确认，接入共享重任务资源门；可能消耗少量模型额度。
4. 只有登录检查和结构化合成检测都通过，才把 Codex 熔断写为 `closed`。未登录保持 `authorization`；检测失败进入冷却，不伪报恢复。持久化失败时不修改共享内存中的旧状态。
5. 检测通过只显示下一步，不自动重派文档或任务。用户必须明确勾选未完成资料并点击“重新分析”；未知执行仍须先核对回执。
6. 同一检测能力接入真实任务中心详情页，Codex 任务可显式检测，但检测成功同样不会自动重试任务。

## 二、安全与运行负担

- 检测文本固定为合成健康检查，不含学生姓名、文档正文、文件名、项目或路径；工作目录是临时空目录。
- 使用 `host-mediated-no-tools` 和严格 `{ready:true}` schema；不开放工具、网络、文件写入或任意路径。
- 检测仅由点击触发，不进入列表刷新、定时扫描或新计时器。无授权故障时页面不显示额外入口。
- 共享重任务运行时拒绝检测，避免与 OCR、消化或分类争抢资源。
- 成功恢复后仍需手工选择“重新分析”，防止旧资料在登录变化后被静默重派。

React 性能规范用于保持授权状态为派生显示、检测为用户事件，不新增 effect 探测或列表刷新副作用；前端验证按真实组件、隔离服务和实际浏览器交互执行。

## 五、需要用户参与的唯一缺陷复验

1. 确认没有运行中或“执行待核对”的任务，退出旧主机，运行文件名含 `smart-inbox-r8-20261012` 的候选；不要同时打开两个版本。
2. 打开“资料收件箱 → 待处理”，查看学生选择“赵书源”。界面应显示“Agent 授权待恢复”，而不是把授权失败说成“需人工选择项目”。
3. 点击“检测当前学生 Agent 授权”，阅读说明后确认。检测只发送合成 READY 请求，可能消耗少量 Codex 额度，不发送学生资料。
4. 若显示检测通过，勾选需要恢复的 DOCX，点击一次“重新分析”。检查生成的项目建议；可信项是否自动投递仍按来源开关和既有安全规则决定。
5. 若仍提示登录异常，只需在 Codex 官方界面／CLI 完成登录后再次检测；不要提供密码或 Token，也不要降低安全设置。若检测超时或结果未知，不连续重试真实资料，记录时间和界面提示即可。
