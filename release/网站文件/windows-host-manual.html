0.21.2 自动恢复、云端协同与资料治理更新

已保存的 Agent 授权会在启动时先恢复，再在后台完成健康检查。合同过期、CLI 或模型版本变化只触发合成数据复核；只有凭据明确失效、撤销或退出账号时才需要重新授权。

全局授权下的项目任务按冻结的项目成员、项目知识空间和权限指纹执行，并在正文发送前、结果提交前再次核对。成员或权限变化时停止发送或隔离结果，不会自动重复派发未知任务。

云端同步设置分为连接与授权、同步结果和成果收件箱。学生基础信息可逐项授权；教育资料默认只开启学情报告，学习资料、选题建议、比赛推荐和学习卡片需要主动勾选，健康资料始终单独授权。

Skills 管理支持扫描、不可变存档、浏览、哈希校验和受控导出；Codex／WorkBuddy 可执行安装预览、备份、回滚和卸载，QClaw 保持只读，插件与 MCP Skill 自动安装未开放。资料索引使用 SQLite 权威存储，并支持备份、迁移、重复资料隔离与恢复。

进入“系统设置 → AI 接入与调度中心”，一次设置全局授权、执行器连接和默认调度顺序。全局授权适用于现有及以后新增学生；厂商登录、API 密钥和本机 Hook 仍使用各自官方机制。LLM API 的地址、模型、密钥和连接测试在同一页面直接设置，没有学生档案时也可配置。

自动调度按“首选可用 Agent → 其他已启用且支持该任务的自动 Agent → LLM API → 手工交接”执行。WorkBuddy、Codex、OpenClaw、QClaw、TRAE、Qoder 只有在相应任务合同验证通过时才进入自动候选；只有桌面或网页入口的工具只创建一次待发送任务，不会连续打开多个应用。外部结果未知、取消、授权变化或已经收到结果时停止回退，避免重复派发。

“统一任务队列”支持选择当前筛选条件命中的全部任务，并批量归档、取消或删除。从未开始执行的待处理任务可直接安全删除；执行中、等待结果、等待审核或结果未知的任务会自动跳过。确认窗口会先显示可处理数量和跳过原因，删除后仍保留墓碑和审计记录。

“收集与整理 → AI 对话采集”包含“对话分享资料箱”和“Agent 会话自动采集”两个分页面。“Agent 数据管理”集中管理记忆、规则和人设；“Agent 连接管理”集中管理外部写入审核和 Agent 问答设置。新建学习项目已修复“项目 ID 无效”；学情页的顺序调整为学情报告、学习资料、知识点掌握、学习卡片，报告摘要和维护操作收纳在“高级”。

0.19.8 学习卡片更新

在学生资料中设置主要学习语言与可选辅助语言，首版支持简体中文和英语。进入“学情与学习 → 学习卡片”，保存练习计划后根据正式学情证据生成卡片。生成及独立复核均沿用学生语言设置；英语和语文保留目标练习语言。

卡片上方可以切换“正在进行”和“待练新卡”。查看新卡不会中断旧练习，也不会清除已选择的作答文件；可以先预览、导出或打印新卡，完成当前练习后再开始下一张。重复生成会显示复用提示，不堆积相同题目。

学情、计划或语言变化后，仅在新卡复核通过且输入未过期时替换尚未开始的待练卡，历史卡片和作答记录保留。已开始或已完成的卡片保持原语言；作答仍是待审核记录，不自动判定掌握。当前仍为手动生成流程，不代表已开启自动生成或自动投递。

首页显示当前学生与学习、项目和报告摘要；普通用户按“收集 → 整理 → 学习／项目 → 规划”操作。研究能力、来源诊断及运行细节收纳在高级区域；没有真实联网核验时，不把缓存或未完成结果标为最新。

0. 新版导航与主要入口

左侧固定八个一级菜单：首页、收集与整理、学情与学习、项目与成果、规划与指导、知识与协作、精选课程、系统设置。除系统设置保留展开项外，二级入口在页面内以 Tab 切换。旧入口名称仍可能出现在历史任务或下文原有流程说明中，按这里的新路径访问即可。

  • 左下角当前学生：点击后切换学生、查看编辑当前学生档案、新建学生档案及打开学生总览。学生总览只读聚合授权范围，不替换当前学生。
  • 收集与整理：默认收集总览；资料导入、拍照上传、屏幕采集、录音采集、AI 对话采集、资料收件箱和资料整理分别进入页面。AI 对话采集下含“对话分享资料箱”和“Agent 会话自动采集”两个分页面；统一任务队列位于资料整理。
  • 学情与学习：学情报告、学习资料、知识点掌握、学习卡片。云端文档从学情报告操作区进入；报告摘要和维护操作位于“高级”。
  • 项目与成果：新建项目、项目知识管理、成长模型、选题建议、推荐比赛；默认项目知识管理，推荐比赛位于选题建议之后。
  • 系统设置：AI 接入与调度中心负责全局授权、执行器连接、LLM API 和调度顺序；Agent 数据管理负责记忆、规则和人设；Agent 连接管理负责外部写入审核和 Agent 问答设置。版本检查与更新在基础设置页面下方。

0.1 个性化选题、规划与比赛

先在当前学生档案补充年级、出生日期或人工年龄段、当前地区、意向地区／国家、规划路径、个人兴趣、学科特长和职业方向。年龄只按出生日期动态计算，没有出生日期时使用人工年龄段，不按年级猜测精确年龄。

选题建议结合学生档案、已确认成长证据、学习资料与项目经历生成，支持“我的收藏”、比较和采用。采用仅预填新建项目草稿；仍需点击原有“创建学习项目”才会创建，取消草稿不会建项目。

规划与指导分别显示规划总览、升学路径、择校建议、专业探索、职业发展，以及更新记录与设置；不同 Tab 关注不同问题，不把同一段建议复制到每个模块。主机先建立本地证据快照，再生成去标识研究策略，调用已通过能力探测并获授权的 Agent，核对返回 URL、抓取时间、来源及适用条件后保存建议版本。没有可用执行器、断网、超时或来源不足时保留历史有效版本，显示未完成最新核验；自动研究不报名、不申请、不修改学生目标。

推荐比赛结合学生兴趣、学科特长、升学／职业方向和项目证据，显示国内外科创及社会实践比赛的官方来源、适用条件和待核实项；支持收藏和“我的收藏比赛”。过期收藏仍保留，但不表示仍可报名。月度与资料变化触发规则可在页面设置，手动更新需要联网研究执行器可用。

0.2 学习资料、学习卡片与外部查看

学习资料支持学科／课程和知识类型两个维度浏览，可增加自定义学科或课程。查看学生学情资料、项目知识空间时，可选择“打开 Obsidian 查看”；按当前选定目录建立／打开对应 vault，不复制或迁移知识文件。需先安装 Obsidian，目录不可用时先修复路径。

学习卡片根据当前证据生成练习，提供图片／PDF 分享打印；“我的作答”通过上传作答文件提交。卡片结果不自动把一次成功或提示后完成写成已掌握；需要确认和复测证据。卡片收藏不是本版承诺的已完成功能。

录音采集提供本地与云端转写引擎配置；云端转写会发送用户主动提交的音频，需核对服务地址、授权与隐私。拍照、录音及分享资料按当前学生接收，后续投递需要明确原始资料库或关联项目。

0.3 云端文档与分享

学情报告页面点击“云端文档”进入。上传授权、云端账号开通和实际同步是不同状态；开启授权后可点击“立即检查并上传”，查看最近回执，不能仅凭“自动上传：开启”判断已完成。服务不可达时保留本地报告，按页面失败原因处理。

选题建议与规划总览通过“分享至云端其他文档”上传派生文档，在云端“其他文档”查看，不混入正式学情报告。只分享当前获授权学生的选定内容，不自动公开原始截图、对话或完整学校档案。

0.4 资料收件箱：WPS 保存与浏览器下载

  1. 进入“收集与整理 → 资料收件箱”，默认是“下载文件”；“分享资料”仍是当前学生专属收件箱。
  2. 点击“选择／新建文件夹”，选择方便保存的普通本地目录。配置在当前主机用户数据目录中保存，重启后保留。不要选择磁盘根目录、系统目录、教育管家受管资料目录或链接目录。
  3. 在 WPS 另存为或浏览器下载保存时手动选择该目录；可在资源管理器中右键文件夹，固定到快速访问／主页。程序不会自动改变其他软件的保存设置。
  4. 保存完成后点击“刷新”。只读取目录直接文件，不递归；首版没有后台监控或自动投递。临时下载、Office 锁文件名、链接和仍在写入的文件跳过。
  5. 搜索、按修改时间／文件名／大小排序，按待处理／已投递查看；每页 25 项，可以全选当前页。单批最多 100 项。
  6. 明确选择获授权学生和“学生原始资料库”或其未封存关联项目，点击“投递选中资料／重试归档”。公共下载文件在投递前不属于任何学生；没有当前学生仍可浏览、配置与回收，但不能投递。
  7. 核验目标内容及登记回执成功后，原件才进入所选目录下“已投递”。原文件名保留，重名不覆盖。失败保留原件；“已投递，原件待归档”重试只归档，不重复导入。重启后未完成记录可手动恢复，不会自动再次投递。
  8. 删除待处理文件时点击“移入 Windows 回收站”，核对数量后确认；不提供永久删除，不删除已投递的目标资料。更换／断开关联只修改配置，不移动、不删除原目录文件。

沿用本机资料导入类型白名单，单文件最多 100 MiB；不支持或超限文件可显示原因，但不能投递。切换学生、更换目录会清空勾选和未提交目标；已启动的投递保持启动时的目标，不跟随界面变化。

0.5 快捷采集工具条

  1. 进入“收集与整理”的收集总览，点击“显示／定位快捷采集工具条”。工具条会显示在教育管家主窗口上方；再次点击可重新定位并置于前方。
  2. 点击“屏幕采集”，直接在工具条内选择屏幕或应用窗口、学生采集箱或当前学生的未封存关联项目、采集时长与策略，再点击“开始采集”。工具条随后恢复紧凑高度，显示重点截取、暂停／继续、采集箱和结束。
  3. 点击“拍照”，在独立悬浮窗打开摄像头预览。拍摄后摄像头立即关闭；确认画面后点击“保存照片”，原件才进入页面顶部所示学生的照片收件箱。可重拍或继续拍照，投递仍在“拍照上传”页面完成。
  4. 点击“录音”进入原录音采集页面；本机文件导入、资料收件箱、对话收集和会话自动采集位于“更多”，继续复用原页面和确认流程。资料“已收到”不等于“已整理”或“已形成成长证据”。
  5. 屏幕采集为截图会话，不是录像。拍照窗打开后切换主窗口学生不会改变本次照片归属；需要更换学生时关闭拍照窗，并在新学生上下文重新打开。

1. 启动与升级

  1. 关闭所有旧版 AI教育管家窗口。
  2. 启动新版程序。程序启用单实例保护，重复启动时会聚焦已有窗口。
  3. 首页显示当前学生摘要及主要业务入口；版本检查在“系统设置 → 基础设置”页面下方，Agent 工具控制在“Agent 设置管理”。便携 EXE 无需安装，解压 ZIP 后直接运行；程序未签名，首次运行可能出现 Windows 安全提示。首次启动仍受磁盘、杀毒软件和待处理任务影响，遇到明显卡顿请记录从启动到首页可操作的时间。
  4. 升级后系统优先读取主机学生索引，并同步界面缓存；不移动学生知识库物理目录。
  5. 升级前建议执行“创建日常备份”；更换电脑或资料磁盘时使用“创建迁移包”，系统会同时携带受管资料和必要应用状态。
  6. 0.16.5 起只接受由内部授权管理工具签发、绑定当前主机设备码的 License v3。旧式短码、License v2 和本地导入公钥不再参与验证；旧授权用户应先联系客服换发 v3，未换发期间已有档案保持只读且不会删除。
  7. 换发或新签发时，进入“系统设置 → 基本设置 → 许可证授权”，点击“复制设备码”，把显示的 host-... License v3 设备码交给授权人员。不要使用主机服务连接区域显示的 HOST-... 主机机器码；二者用途不同。

2. 创建学生档案

Windows 主机使用激活码中的“活跃学生席位”作为学生数量上限。新建、接管已有目录、备份恢复和换机恢复都会执行同一检查；达到上限时可联系升级授权。系统不会删除已经存在的超额档案，现有资料仍可浏览和备份。

  1. 点击左下角当前学生，打开档案弹窗，再选择“新建学生档案”；需要修改资料时选择“查看编辑当前学生档案”。
  2. 填写学生姓名、年级、学校和学习目标。
  3. 选择创建标准知识库或接管已有知识库。
  4. 点击“保存学生档案并初始化”。

一次操作会创建知识库目录、 AGENT.md 、LLM Wiki 目录、索引、日志和基础学情报告。右侧 Agent 工具连接是可选步骤，不会再次创建目录或覆盖 AGENT.md 。

点击任一 Agent 步骤卡片即可复制该步骤指令；如在“高级”中修改过内容，则复制修改后的指令。

3. 接管已有知识库

  1. 选择“接管已有知识库”。
  2. 选择现有知识库根目录。
  3. 确认系统识别出的 AGENT.md 、原始资料库、综合汇总和输出目录。
  4. 对未识别目录进行手动指定。
  5. 查看路径健康检查；需要时生成逻辑路径草稿或执行“备份后修复旧路径”。
  6. 确认接管。

接管不移动、不复制、不删除原文件。系统使用工作空间身份、逻辑路径和当前主机映射处理跨电脑同步后的路径差异。

4. 资料收集与处理

资料可从 Windows 主机本地导入、Windows 学生端上传、Android 学生端上传、项目工作空间晋升或屏幕采集箱进入系统。主机本地导入时也需要选择资料归属：

  • 学生原始资料库：用于日常作业、学习记录和不属于特定项目的资料；
  • 绑定项目原始资料库：用于项目研究、作品、过程资料和项目参考资料。

选择项目资料库时，只显示当前学生已经绑定且未封存的项目。处理区按学生显示：

  • 待提交消化：尚未交给 Agent 的资料；
  • 等待 Agent 回执：已提交，但 Agent 尚未写回完成证据；
  • 已处理：已匹配完成回执；
  • 失败或需复核：回执失败、低置信度或覆盖不足。

5. Agent 资料消化

  1. 选择学生，确认页面显示待处理数量。
  2. 点击“开始处理”。系统会重新核对真实待处理资料、冻结本批文件清单，并自动选择当前可用的 Agent 通道。
  3. 页面进入“处理中”后可以离开当前页面；顶部后台任务条会持续显示状态，Agent 返回结果时系统自动校验并更新，无需再点击“标记已提交”或“同步结果”。
  4. 全部通过时显示“已完成”；只完成部分资料时显示“部分完成”，点击“重试未完成项”只会处理剩余资料。
  5. 点击“查看新增知识”可打开现有知识目录。

已完成批次学习事件补录

如果 Agent 在资料批次完成后才将纵向学习事件候选写入该学生的 digest-receipt.json ，无需把原材料重新标记为待处理，也无需重新消化。请在左侧学生列表选择正确学生，回到“资料收集与处理”；当该学生的处理卡片显示“已完成”时，在卡片主行下方、“高级与诊断”上方点击“已完成批次学习事件补录”。

主机会要求回执明确指向当前学生和最近已完成批次，并逐一核对回执中已处理的材料 ID、材料状态、批次快照及原文件 SHA-1。学习事件仍需通过知识点、发生时间、表现维度和证据引用校验；重复事件不会重复入账。若材料已变化、回执不匹配或候选证据不足，页面会给出拒绝原因，原材料和已完成批次保持不变。此入口只处理当前学生的最近已完成批次，不是对任意历史批次重新消化。

建立学生消化批次前，系统会在“当前学生”的原始资料库内执行路径预检：先按已登记相对路径查找，再用文件大小和 SHA-1 对唯一候选进行复核。资料因换盘、迁移或目录重绑而改变位置时，只有在内容指纹完全一致且候选唯一时才自动修复；修复前会备份 materials.json 与上传记录，并写入路径修复历史。系统不会跨学生目录查找，也不会移动、删除或改写原始文件。

单个缺失、仍在写入、内容不一致或存在多个候选的文件，不再阻断其他可读资料。每批最多 100 份、合计不超过 512 MB；其余资料保留为下一批，自动 Agent 完成本批后会继续下一批。人工 Agent 模式需要为下一批再次复制指令。页面“资料路径预检”会分别显示本批、自动修复、后续批次和待确认数量；可点击“重新检查并自动修复”，或对非临时问题点击“手工选择文件”。手工选择只接受当前学生原始资料库内、且与原指纹一致的文件。

学生资料和学习项目仍保留内部逐文件批次用于追踪来源，但 Agent 回执采用宽松自动归并。JSON、JSON 代码块、嵌套输出、Markdown、纯文本完成说明、分段结果以及不同字段名均可识别；系统可按资料 ID、相对路径、唯一文件名或 SHA-1 任一信息与当前真实资料匹配。Agent 未写逐文件结果时，只要本批次之后确实更新了 index、log 或知识产物并给出完成信号，系统也会自动结算。普通用户无需查看批次、哈希或粘贴回执。

如果本机没有可直接调用的 Agent，页面会自动降级为人工方式：系统准备并复制一次完整指令，用户在已有 Agent 中粘贴执行，再把 Agent 返回结果粘贴回当前页面。整个过程不需要进入任务中心，也不需要手工修改资料状态。

0.10.4 支持 Agent 分多次返回同一批资料的处理结果，也兼容内容正确但文件名不同的 JSON digest 回执。对于只有一份源资料的项目批次，如果 QClaw 已在本批提交后写出明确标注当前项目和完成状态的 Markdown 消化回执，并同时生成至少一份知识产物，系统会在严格核对项目、批次、相对路径和 SHA-1 后自动补成标准回执。多文件批次和证据不足的结果不会推断完成。系统会把空文件或协议明确忽略的资料结算为“无效”或“已忽略”，避免反复提交。消化通过后，系统在后台完成知识资产登记、来源覆盖分析和质量检查；低风险记录不占用日常待办，只有缺失、空文件或越界等问题才提示检查。

6. 消化覆盖审计

大量图片或复杂资料消化后建议执行二次核对：

  1. 点击“生成覆盖审计”。
  2. 查看完整覆盖、部分识别、失败、待回执、源文件缺失等状态。
  3. 选择待复核资料并复制二次核对指令。
  4. 将指令交给任意可访问知识库的 Agent。
  5. Agent 独立执行视觉识别、OCR 和逐文件比对，并把当前轮次结果写入 digest-review-receipt.json ；首次消化的 digest-receipt.json 保持不变。
  6. 点击“同步复核结果”。

系统只接收与当前 digest-review-request.json 中复核轮次、消化批次和资料 ID 完整匹配的新回执。若 Agent 只在对话中报告、回执过期或缺少资料，界面会保持原状态并明确提示原因。回执包含未转义引号或字符串换行时，系统会尝试容错修复并保留无效回执备份。

7. 屏幕资料采集

位置： 资料收集与处理 → 屏幕资料采集 。

Windows 支持整个屏幕或指定应用窗口，并提供智能混合、内容变化、固定间隔三种策略。可设置 15 至 120 分钟，采集中支持暂停、继续、重点截取和结束。

快捷键：

  • Ctrl+Shift+1 ：立即截取；
  • Ctrl+Shift+2 ：暂停或继续；
  • Ctrl+Shift+3 ：标记重点。

截图先进入候选采集箱并登记为候选资产；正常结束后由主机自动完成晋升与后续整理，异常或归属不明的资料保留待检查。屏幕截图只是带来源的观察，不会单凭画面推断学生掌握程度。

8. 文件资产中心

文件资产中心用于查看资产身份、来源、版本、重复组、引用关系和治理风险。

选择学生后，资产总数、重复组、治理候选、风险、最近七日曲线、资产列表和详情会统一切换到该学生范围。搜索、来源、类型和“只看重复”只筛选列表，不改变学生范围看板。

“最近 7 天资产变化”包括每日新增资产和每日新增引用。旧记录缺少历史日期时不会猜测日期，并会显示未计入数量。

9. 新建学习项目

位置： 学习项目 → 新建学习项目 。

  1. 填写项目名称、类型、目标和参与学生。
  2. 选择项目模板或自定义模板配置。
  3. 自定义项目工作空间文件夹，或选择“使用已有项目文件夹”。
  4. 确认工作空间与知识空间位置。
  5. 创建项目。

项目工作空间面向学生和教师，项目知识空间使用原始资料、概念、实体、摘要、问答精华、综合汇总的统一结构。

10. 学习项目四步工作流

已有项目页会根据当前状态推荐下一步，日常操作按四步完成：

  1. 添加资料 ：扫描工作空间，导入网页、论文、截图和草稿等候选资料；核心资料也可直接采用，已有正式资产可直接复用。
  2. AI 整理建议 ：AI识别相关性、重复和资料价值；用户主要确认冲突、低置信度和需排除资料。
  3. 自动消化与整理 ：系统自动采用来源完整、无冲突的低风险资料，确认高置信且项目归属明确的知识，再将严格批次任务交给 Agent 消化并检查回执；只有来源缺失、冲突或低置信项需要用户处理。
  4. 完成项目 ：审核风险知识和每名学生的独立成长证据，生成归档清单并发布到学生长期档案或成长模型。

“系统建议下一步”会依据真实待整理、待消化、待审核和待归档数量突出一个主操作。筛选、批量状态、手工保存策略和目录模板仍可在“高级操作”中使用。

“核心资料直接采用”适合已经确认的官方文件、原始数据、教师反馈和最终成果，会跳过暂存筛选，但仍保留来源和资产登记。

“复用已有正式资产”支持按文件名、学生、来源、文件类型、SHA-1 或路径搜索。搜索在全部已加载资产中执行，已经被当前项目引用的资产不会重复显示。点击“引用所选资产”只建立项目引用和来源记录，不复制原始文件。

资料状态遵循统一顺序：“已收集/已初筛/选入分析”属于尚可人工确认的暂存阶段；“已晋升”表示已经加入项目资料库；“已分析”只表示已晋升资料完成知识消化。已晋升或已分析资料不会再次出现在“选择待采用”中，也不能重复加入知识库。旧版本中仅由 AI 初筛误标为“已分析”、但没有人工接受和晋升记录的资料，会自动恢复为“已初筛”，等待用户确认；已经真实晋升或消化的记录保持不变。

11. 已有学习项目

位置： 学习项目 → 已有学习项目 。

项目详情提供：

  • 打开项目根目录、项目工作空间、项目原始资料库和项目知识空间；
  • 编辑项目名称、类型、说明和策略；编辑面板不修改目录；
  • 使用详情页工具栏中的“更换工作空间”修改工作空间来源目录；使用“绑定知识空间”修改项目知识空间目录。两个目录互相独立；
  • 复制项目模板和知识策略，不复制无关资料或历史贡献；
  • 导入、导出项目包；
  • 安全删除项目和从“已删除项目”恢复；删除只移出项目索引，不删除工作空间、知识空间、资产或审计文件；
  • 生成贡献申请、归档确认、贡献审计和发布到成长模型。

扫描、资料整理、加入知识库、Agent 回执、知识审核和完成项目的结果会显示在当前阶段，并提供下一阶段定位入口。

多学生项目共享项目知识，但每名学生的成长证据独立生成和审核。

11.1 使用“更换工作空间”修改工作空间来源目录

  1. 进入“学习项目 → 已有学习项目”，打开目标项目。
  2. 在项目详情页工具栏点击“更换工作空间”。无需进入“编辑项目”；编辑面板只修改项目资料。
  3. 选择本机已经存在的项目文件夹作为新的工作空间来源目录。
  4. 核对旧路径、新路径和未完成任务提醒，再确认修改。
  5. 系统只更新项目的逻辑绑定并重新扫描新目录；旧目录、项目根目录和项目知识空间都不会被移动、复制、删除或覆盖。

新目录必须存在且可读取，不能与项目根目录、项目知识空间或管理目录相同或互相包含，也不能已经绑定到另一个学习项目。修改后如果发现选错目录，可在“工作空间扫描与模板设置”中回滚上一次目录修改。

11.2 绑定已有项目知识空间

“绑定知识空间”用于盘符变化、换机或接收协作项目后，重新指定本机真实的项目知识空间。它不会修改工作空间来源目录。

  1. 在项目详情页点击“绑定知识空间”，选择已经存在且包含实际资料的项目知识空间。
  2. 在原生确认窗口核对项目名称、旧路径、新路径、文件数量和知识空间 ID。
  3. 确认后，系统只更新教育管家的知识空间绑定、受控路径区块和路径变更日志，不会移动、复制或删除原文件。
  4. AGENT.md 、 index.md 、 log.md 等文件中的用户正文不会做全局字符串替换；系统只维护带有教育管家标记的受控路径区块，并追加审计记录。

所选目录不存在、不可读、没有实质文件、必要结构缺失或已被其他项目占用时，绑定会在写入前停止。不要用空目录代替丢失的旧知识空间。

12. 项目仪表盘

仪表盘用于检查资料治理、知识覆盖、待审核项、贡献状态和风险。可查看指标应作为入口打开对应清单，不只是静态数字。

自动化触发可由新资料、项目阶段变化和定时任务产生。关闭自动运行总开关后，触发器只生成待办，不会自动调用 Agent。

13. 统一任务中心

任务中心统一承接 Agent 自动任务和人工任务，记录任务输入、执行工具、决定状态、日志、超时、重试和结果校验。普通资料消化、成长模型刷新和学情报告不增加日常审批：系统在确定性校验通过后自动继续；只有缺失依据、学生归属冲突、结构损坏或其他会破坏闭环的问题才生成一条“需要补充”提示，旧结果继续保留。

支持方式：

  • WorkBuddy、Codex、OpenClaw、QClaw、TRAE、Qoder：按本机连接状态、全局启用状态和逐任务合同验证结果进入自动候选；不同任务的自动能力可能不同。
  • LLM API：作为并列执行器配置，并在适用的 Agent 自动通道明确失败后接管；结构、来源或任务合同不满足时不会伪装成功。
  • Marvis、Claude Code、其他内置工具和自定义工具：默认使用手工交接；接入标准 CLI 并通过连接与任务合同验证后，才可按具体任务开放自动执行。
  • 手动模式：一次关闭全部自动运行，阻止新请求；已经执行或结果未知的任务按原执行身份等待核对，不会切换执行器重复生成。

可在当前筛选结果中选择全部任务，批量归档、取消或删除。系统会先预检每项状态：从未开始的草稿、待处理、已批准和排队任务，以及已结束或已归档任务可以安全删除；执行中、等待结果、等待审核和外部结果未知任务会跳过。批量删除只移除任务卡和可见历史，继续保留业务资料、生成结果、墓碑和审计事件。

“检测到 Agent 已安装”不等于“Agent 已开始执行”。点击资料处理按钮后，页面必须明确显示“已启动”“已有任务等待回执”“已打开 Agent，指令已复制”或失败原因之一。如果资料账本有待处理文件、但旧任务没有任何同批次的已提交文件，系统会自动解除旧任务占位并建立当前批次；不会要求用户删除账本或把未验证资料手工标成完成。

四类学情输出统一由任务中心调度：能力画像按月更新，历史变化按周更新，阶段总结按月更新，每周行动建议按周更新。新增成长证据、能力模型变化或项目阶段变化时，对应报告任务会重新进入待处理状态。每名学生在同一周期只保留一项当前任务，旧周期任务退出当前队列但保留历史记录。

每周行动建议包括每日固定动作、每周重点、阶段性里程碑，以及分别面向学生、家长和老师的建议。能力画像、历史变化和阶段总结只使用已确认的成长证据；没有实质变化时必须明确写明“本周期无实质变化”，不得虚构进展。

点击“查看任务”后，页面会定位到任务详情并直接显示 Agent 反馈摘要、校验状态和行动反馈；存在结果文件时可点击“打开结果文件”。点击“打开来源”会进入对应学生的资料处理、每周行动建议或教育档案页面，不再顺带复制和提交新指令。

资料消化完成后，系统每 5 秒自动扫描 Agent 标准输出、约定回执目录、index、log 和知识产物，不要求用户粘贴结果。项目页面的“导入历史结果”只用于迁移旧任务，支持 JSON、Markdown、文件清单或纯文本完成说明。回执缺少任务 ID、批次号、状态或逐文件字段时，系统会结合当前任务自动补齐；原始资料在提交后发生变化时，该资料继续留在待处理队列。四类学情报告仍按学生归属、成长模型指纹、依据引用和内容结构进行确定性校验后自动发布。

任务中心默认只显示待处理项，并在页面可见时每 60 秒后台刷新；手工刷新不会阻塞其他页面操作。QClaw 返回文件通过内容识别，不要求固定文件名，通过校验后自动移入 processed 归档。超过 5 MiB 的事件日志会轮转到历史目录，不再反复扫描同一批大文件。

任务包会自动附带当前学生或项目的最小档案上下文。 ArchiveAccess v1 只读取已授权知识、报告和分析结果，使用 edu:// URI 保留引用；原始资料目录不进入默认检索。该能力由程序内部提供，不需要普通用户安装 MCP、配置端口或安装技能包。

每周行动建议的更新闭环为：执行任务、粘贴或同步 Agent 结果、系统校验并自动发布。发布成功后，控制台会自动进入学情中心并刷新“每周行动建议”；没有实质变化时不会重复发布。界面名称已经按周呈现，底层继续写入原 每日行动建议.md 以兼容既有学生知识库。

14. 学生成长模型与学情报告

项目知识不是直接复制到学生目录。治理后的学生知识资产和明确归属于该学生的项目证据会自动形成“观察中”成长记录，并保留来源路径、内容指纹和系统来源；共享项目资料不会直接变成某名学生的个人结论。

成长模型看板分为三个视图：

  • 能力画像 ：按能力维度汇总已确认、观察中和待审核的证据，并显示成熟度、趋势、来源项目和最近观察时间；
  • 项目贡献 ：列出项目状态、贡献发布状态、支撑能力和已确认证据，可点击进入对应学习项目；
  • 成长证据 ：按状态、能力和关键词筛选候选证据，并执行确认、观察或驳回。

成长证据默认显示“需要关注”，不会用低风险项目证据占满日常待处理列表。系统自动确认来源完整且归属明确的低风险项目证据，把信息不足的普通记录转为“继续观察”；来源失效、冲突、敏感、跨学生或归属不明的高风险证据保持不变、留待逐条处理。自动处理记录保留批次 ID、处理时间、系统策略身份和完整历史。

“成长模型目录”卡片可直接打开学生知识库下的成长模型文件夹。旧版 成长证据.md 会在结构化索引升级时兼容导入，不移动、不删除、不覆盖原文件。

学情报告是独立呈现层，读取成长模型中的已确认结论和可追溯观察：整体画像引用能力画像，历史变化引用能力时间线，阶段总结引用项目贡献和成长证据，每周行动建议由统一任务中心生成。报告通过确定性校验后自动发布；校验失败时保留上一版并显示一条异常提示。点击“查看依据”可只读查看当前学生及其绑定项目范围内的来源，再次点击可定位原文件；旧报告没有依据标记时会明确提示，不会猜测来源。为兼容已有知识库，底层仍沿用原 每日行动建议.md 文件名。

成长索引不在启动时全量重建。资料消化、知识资产或学生专属项目证据发生变化时，只标记并刷新对应学生；系统另有 15 分钟低频兜底，只处理已经标记为变化的学生。

点击“导出完整档案”可把当前学生的教育档案、四类学情报告、成长摘要和可校验清单一次性导出。系统优先保存到下载目录；如果下载目录不可写、位于受限盘符根目录或暂时被占用，会自动改用文档、桌面或应用导出目录，并明确显示实际保存位置。只有内容发生实质变化时才生成新的档案版本，重复点击不会制造相同版本。

打开任一学情报告后，可直接选择“导出 Markdown”或“导出 PDF”。Markdown 保留原始可编辑内容；PDF 使用 A4 中文排版，保留标题、列表、表格、分页和页码。导出只读取当前选中的学生和报告，不会混入其他学生内容。

点击“导出与分享”可进入教育内容智能出版：

  1. 选择正式报告、简明报告、成长要点等模板，并选择 PDF、PNG 或 Markdown；需要打印时可切换彩色或黑白。
  2. 默认使用“忠实原文”，系统只整理当前报告或档案中的已有内容；需要提炼时可选择“Agent 智能提炼”。
  3. Agent 结果中的每条结论必须能够对应原文摘录和来源章节；数字、表格和结构校验失败时，系统保留忠实原文草稿，不会用无依据内容补齐。
  4. 在预览区可编辑本次派生草稿，也可恢复系统自动整理稿。编辑不会修改原始学情报告、教育档案、成长模型或知识资产。
  5. PDF 适合正式阅读和打印；PNG 使用 9:16 手机比例，长内容自动采用紧凑单栏排版并输出完整高度；Markdown 适合继续编辑。

在“查看教育档案”的 Markdown 阅读器中也可以点击“生成报告或卡片”。系统只允许当前学生学情分析汇总目录内的可信 Markdown 作为来源，拒绝 AGENT.md 、日志、回执、内部索引和其他学生文件。正式报告会保留主体内容，并自动去除开头 YAML 表头、末尾依据来源及教育档案内部说明章节；Markdown 表格会按真实行列渲染，历史单行表格会先兼容修复。

页面中的流程按钮采用当前皮肤的颜色变量自动引导：主题强调色表示现在建议点击的唯一下一步，绿色表示已经完成，主题描边表示可选操作，灰色表示条件不足。颜色由真实资料、Agent 回执和确认状态计算，不能通过跳着点击后续按钮绕过前置条件。

14.1 自动会话记忆与手动导入

在“收集与整理 → AI 对话采集 → Agent 会话自动采集”选择会话归属并确认全局采集授权已启用。同一授权会自动接入本机已经安装的 Codex、QClaw、WorkBuddy、OpenClaw、Claude Code 和 Hermes；以后新安装受支持 Agent 时，AI教育管家会在后台检测并接入，无需每次新会话重复授权。

Codex 首次安装或 AI教育管家 Hook 定义更新后，页面会显示一次确认卡片并打开 Codex CLI。此时只需输入一次 /hooks ，审查并信任 EDU-MANAGER-LIFECYCLE ，确认 Review = 0 、 Active = 1 。AI教育管家会在后台自动复核 Hook 状态并记住已信任的定义；定义未变化时，新会话、重启应用和重启 Codex 都不需要再次输入 /hooks 。如果 Codex 后续确实检测到 Hook 定义发生变化，仍由 Codex 自身要求重新审查，AI教育管家不会绕过安全确认。

自动采集只处理授权后 Agent 生命周期明确发出的用户和助手正文。新会话可正常采集；已打开的 Codex 会话若已加载并信任教育管家 Hook，可从授权后的下一条用户提问开始采集，授权前正在进行的轮次不会补录。不扫描授权前历史或漏采轮次，也不读取其他会话、系统提示、工具密钥、缓存或教育管家任务中心上下文。事件先写入当前学生授权绑定的本地离线队列，主机恢复运行后自动补交；重复事件不会重复保存。会话正常结束后自动归档，异常退出的会话会在超时后标记失败或取消。

状态含义：

  • 自动采集中 ：授权有效且当前 Agent 已开始产生生命周期事件；
  • 已接入 ：生命周期配置已经完成，等待授权后的 Agent 会话事件；
  • 需要处理 ：Agent 未安装、配置冲突、Codex Hook 尚未完成首次信任或接入失败，可按页面提示完成一次确认或重新检查安装状态。

不支持自动采集的桌面版或网页版 AI，以及自动接入失败的会话，使用“收集与整理 → AI 对话采集 → 对话分享资料箱”。向下滚动到“粘贴对话历史（备用入口）”，选择来源 Agent，粘贴正文并点击“保存对话导入记录”；也可导入 .md/.txt/.json 文件，或在页面顶部粘贴可公开读取的分享链接。系统会保存不可变原文，生成 Interaction、ConversationAsset、稳定消息 ID 和内容哈希；相同内容重复导入不会产生重复记录。

需要把已经连接教育管家原生知识工具的当前或选定对话一次性投递到学生或项目时，仍可明确提出“把当前对话保存到某学生”或“把选中的对话保存到某个学习项目”。高级集成使用 submit_education_conversation ，普通用户不需要手工调用工具名；该入口与自动会话记忆相互独立。

系统会优先按用户明确指定的学生和项目归属；指定项目必须是该学生仍然有效关联的项目。无法唯一确认学生或项目时，本次对话不会写入其他学生，而会进入“系统设置 → 知识协作”的待确认归属入口，等待用户选择正确目标。

复制新的 AI 提取指令时，每条结果必须返回候选内容、逐字原文和消息 ID。点击“保存为逐条候选”只登记候选，不会直接改写 UnifiedMemory、UnifiedSoul、咨询精华或待办。

“P2 逐条候选治理”支持：

  • 查看候选内容、逐字原文、消息定位和风险原因；
  • 编辑与补证、拒绝、合并、标记冲突、标记过期或恢复候选；
  • 对敏感信息进行明确风险确认；
  • 选择通过的候选并点击“事务晋升所选”；
  • 在事务列表点击“撤销本次晋升”。

缺少来源、原文不匹配、提示注入或冲突未解决时，整批候选都不会写入。撤销只移除该事务写入的标记内容，并同步更新候选索引；原始对话不会删除。

15. 使用模式与学生终端

Windows 主机端的“系统设置”分为左侧三个子菜单：

  • 基础设置 ：本机资料根目录、使用模式、Agent、许可证、更新与备份；
  • 主机连接 ：局域网、Tailscale、学生终端服务、登录 ID 与设备；
  • 知识协作 ：完整 Windows 知识节点之间，以及 Windows 与 Android 单机版之间的设备信任、学生映射、任务/知识交换和异常恢复。普通学生端仍使用“主机连接”。

原设置值升级后保持不变。“系统设置 → 知识协作”始终可见，以便首次建立协作。有效协作关系只决定页面内显示的对象、状态和可执行操作，不控制菜单是否出现，也不要求用户设置教师或学生角色。

  1. 在“系统设置 → 基础设置 → 使用模式”选择“主机-终端模式”，并在“主机连接”中启动学生终端协作服务；只在本机管理时选择“主机模式”。
  2. Windows 学生端、Android 学生端和 Android 教师端均可扫描局域网主机、按固定主机码筛选并申请连接；主机核对终端码和终端名称后点击“接受”或“拒绝”。
  3. 主机也可点击“查找学生终端”，输入固定终端码筛选 Android/Windows 设备并发送邀请；终端必须明确点击“接受”或“拒绝”。
  4. 学生设备在设备卡片选择“个人终端”或“共享终端”。个人终端固定绑定一名学生；共享终端不绑定学生范围。教师端由配对请求声明教师角色，不需要选择学生终端模式或绑定个人学生。
  5. 系统为每名既有和新建学生自动生成稳定的学生登录 ID 和二维码，可在“学生登录 ID 与二维码”中查看或复制。
  6. 共享终端由学生输入 ID 或扫码进入；未进入时不返回学生名单，进入后只返回本人资料和本人绑定且未封存的项目，退出即清空会话。
  7. 学生终端首页可查看已提交资料、已完成知识化、近 7 天新增和近 30 天活跃频率，并在当天没有资料时提示“提交本日学习资料”。其中知识化数量是已经消化完成的资料数，不代表知识库文件总数。
  8. Android 个人终端可授权一个自动投递文件夹并选择学生或绑定项目目标；共享终端自动关闭持续投递。Android 屏幕采集按学生目录隔离，并允许当前学生预览和清理已上传图片。
  9. Windows 学生端和 Android 学生端均不提供档案初始化、项目管理、知识治理或报告发布功能。
  10. Android 教师端配对时会声明“教师终端”角色。连接成功后可以检索全部学生、查看其教育档案/报告/成长模型/关联项目，并把文件、图片、拍照、Downloads 或自动投递文件夹中的资料上传到选定学生或其关联项目的原始资料库；该上传只写入 Windows 主机资料库，不会向学生设备发送文件、通知或已读任务。教师端档案缓存保持启用，断开主机后可继续查看已缓存档案。
  11. 主机设备记录应把 Android 教师端显示为教师终端。若旧设备记录仍显示学生终端，应撤销旧记录并从教师端重新申请配对；不要通过恢复学生端连接备份来获得教师角色。

学生登录 ID 不替换内部学生 ID，不改名、不移动既有学生目录，也不需要额外 PIN。旧设备若原来只授权一名学生，会自动迁移为个人终端；原来授权多名或全部学生的设备迁移为共享终端。

局域网主机服务默认使用 HTTP 端口 18777 ，Android 与 Windows 学生终端自动发现使用 UDP 端口 18778 。若学生终端找不到主机，请确认两端位于同一局域网、主机服务正在运行，并允许 AI教育管家通过 Windows 防火墙的专用网络。部分访客网络或启用客户端隔离的网络会阻断局域网广播，此时使用粘贴连接信息等兼容方式。不要在同一台 Windows 电脑同时运行主机版和学生端，以免发现端口冲突。

为兼容旧版客户端，主机可能同时发送新版 V2 发现信息和旧版 V1 发现信息。Android 0.6.3 会按发现端点和设备身份自动合并同一主机：同一 IP、同一端口或同一主机身份只显示一条记录，并优先保留包含固定主机码的 V2 记录。该兼容广播不会创建第二台真实主机。

固定机器码只用于识别设备，不是认证凭证。连接仍要求另一端明确接受，后台请求令牌两分钟后失效；无需增加 PIN。展开“其他连接方式”后，仍可使用二维码、6 位配对码、粘贴连接信息或连接备份。旧客户端可继续使用 V1 六位短码；局域网广播不包含 API Token、设备令牌或旧配对码。

设备可在卡片内重命名。已撤销设备可恢复或删除记录；活跃设备需先撤销才能删除。删除授权记录不会删除历史上传审计。

15.1 完整知识节点协作

发布整个学习项目

Windows 0.11.3 起，完整 Windows 主机可以把本机项目定向发布给另一台已建立知识协作关系的完整 Windows 主机：

  1. 在“已有学习项目”中进入项目详情；
  2. 点击工具栏中的“发布项目”；
  3. 系统只检查项目关联学生已经明确映射到的协作节点；项目没有关联学生或没有学生映射时会停止并提示先完成映射；
  4. 只有一个接收节点时直接发布；有多个接收节点时勾选本次需要的接收方。系统不会回退到无关协作节点；
  5. 系统为每个已选接收节点分别生成定向发布包，整理项目原始资料、已确认/已发布知识和来源关系，并加入内置直传队列；
  6. 接收端收到完整包后自动创建或匹配本地项目，使用接收端自己的资料根目录，不要求两台电脑具有相同盘符或路径。

普通发布只需这一次操作。系统不会发送未审核知识、任务账本、运行缓存或本机绝对路径；相同 SHA-256 文件会跳过，同名但内容不同的文件会隔离另存，不覆盖接收端已有成果。局域网不可达时自动尝试 Tailscale；对方离线时保留在发送队列。Syncthing 不参与普通项目发布，仅作为高级兼容方案保留。

不要在 A、B 两台主机上分别独立创建同名项目，再把它们当作同一项目互相发布。两个独立创建的项目具有不同项目 ID 和协作谱系；系统不会仅凭名称合并，接收端会保留为单独的“项目名（协作）”项目。正确做法是：先在一台主机创建项目并首次发布；另一台主机使用系统自动创建的协作项目，再在项目详情页点击“重新定位”，绑定到该主机自己的现有项目文件夹。此后两端沿用同一协作谱系继续发布。

“发布项目”同步的是项目原始资料、已确认/已发布知识及来源关系，不同步工作空间文件夹本身。两端可以绑定不同的本机工作空间，但各自在工作空间中新加入的文件，必须先完成扫描、采用并进入项目原始资料库，之后再次发布才会到达另一台主机。

两台安装 Windows 主机版的电脑可以分别承担教师协助节点和学生资料权威节点。教育管家内置直传是默认方案：优先使用局域网地址，局域网不可达时自动尝试双方已有的 Tailscale 地址；任务包到达后会自动校验、导入并刷新任务中心。对方离线时任务会进入本机持久发送队列，按低频指数退避自动重试；大文件支持分块续传，程序重启后继续未完成传输。旧交换目录链路继续保留，并在界面中明确标为“Syncthing 高级兼容”。

  1. Windows—Windows 可使用局域网发现、六位临时码或粘贴完整连接信息；Windows—Android 单机版可由 Android 扫描 Windows 连接二维码、输入六位临时码或粘贴完整连接信息。设备信任只需建立一次。
  2. 需要同步学生成果时，由一端针对准确学生创建学生映射邀请；接收端人工选择本机准确学生。系统按学生 ID 建立一对一映射，不按姓名自动匹配。
  3. 正常使用不需要安装或设置 Syncthing。只有主动选择高级兼容方案时，才同步两端“打开兼容交换目录”所指向的受控目录；不要同步本机任务账本、索引、运行锁或 Agent 缓存。
  4. 教师选择学生，在“跨主机任务与协作请求”填写名称、要求、截止时间和可选资料，然后点击“布置给所选学生”。
  5. 内置直传完成后接收端会自动刷新任务中心。学生可接受、稍后处理或无法完成；普通成功路径无需检查收件箱。
  6. 教师随任务发送的附件先保留在学生协作收件箱。学生可继续暂存、采用到学生原始资料库、加入已绑定项目或拒绝；采用动作不会因重复同步生成重复副本。
  7. 学生填写完成说明，也可点击“选择成果文件”随结果返回作业、图片或其他文件。教师收到后从“打开成果附件”进入受控收件箱查看，成果附件不会自动写入教师资料库。
  8. 教师可确认完成或反馈修改；学生再次提交后仍回到原任务，最终关闭状态同步到两端。任务详情中的“协作沟通记录”按时间显示双方提交说明、反馈修改、再次提交和确认信息。

“已连接”表示协作关系有效。新建立的连接会同时交换双方可用的局域网和 Tailscale 地址；0.11.9 起，旧版连接缺少直传地址时，两台主机在局域网互相发现后会自动补齐地址，并把每个项目最新的完整发布包从兼容队列转入内置直传，无需重新邀请或手工重发。正常任务不需要手工检查收件箱。“知识协作”的发送队列只在异常时提供暂停、继续、立即重试和取消操作，不增加日常确认。连续发送、程序重启或同一协作包经直传与兼容目录重复到达，都不应产生重复任务或重复附件；异常包会进入隔离区。

15.2 教育管家问答与跨主机知识查询

“教育管家问答”会根据当前选择的范围自动准备知识依据。默认顺序为：

  1. 先查询当前主机已经授权的学生知识和该学生仍然关联的项目知识；
  2. 本机没有命中时，才向已经建立有效知识协作关系的 Windows 主机查询；
  3. 远程查询优先使用局域网，局域网不可达时自动尝试双方已有的 Tailscale 地址；
  4. 对方离线时，系统使用带更新时间的可用快照，或者明确返回“等待远程知识”，不会把旧结果显示成实时结果。

每条结果保留学生、项目、来源节点、更新时间、新鲜度和传输通道，并使用 edu:// 引用定位授权范围内的依据。界面不会向 Agent 暴露另一台电脑的绝对路径，默认也不检索远程原始资料目录。

查询当前学生

在教育管家问答中先选择学生，再输入问题。系统只查询该学生及其仍然有效关联的项目；问题中明确写出学生姓名或 ID 时也会自动收窄范围。学生不存在、姓名有歧义或项目不属于该学生时，系统会停止查询并要求确认，不会回退到其他学生。

查询本机或远程团队知识

完整 Windows 主机可以在未指定学生时查询获准的团队范围：

  1. 进入“系统设置 → 知识协作”；
  2. 按需要开启“允许本机团队知识查询”；
  3. 只有确实需要查询协作主机时，再开启“允许远程协作团队知识查询”；
  4. 回到“教育管家问答”，选择“本机团队”“远程协作团队”或“当前允许的全部范围”后提问。

两个开关是长期策略，默认关闭。远程主机只返回双方有效学生映射允许的知识；某台主机离线时，已经取得的本机或其他主机结果仍会保留，并显示范围未完全覆盖。Windows 和 Android 轻量学生终端始终只允许查询当前登录学生及其有效关联项目，不提供团队范围入口。

15.3 已确认知识与教育档案同步

对已经建立知识协作关系且完成学生映射的两个完整知识节点（Windows—Windows 或 Windows—Android 单机版），系统使用内置持久队列同步以下已确认成果：

  • 已确认知识资产；
  • 成长模型；
  • 已发布学情报告；
  • 最新完整教育档案版本。

同步采用稳定对象与内容指纹去重。顺序更新可以自动前进，并发修改会保留冲突分支，不会静默覆盖任一端；对方离线时进入队列，恢复连接后继续发送。

进入“系统设置 → 知识协作”，选择学生后可以查看“跨主机档案同步”状态。只有协作关系内双方都存在唯一的一对一学生 ID 映射时才允许同步；系统不按相似姓名推断，也不会把一个学生映射到多个远端学生。用户可以按学生暂停、恢复或立即同步，并看到目标主机 ID 与目标学生 ID。映射不唯一时系统会停止写入并提示处理协作关系。

0.17.6 起，学生同步卡片持续显示该学生最新同步包的等待发送、正在发送、等待网络恢复、已暂停、已送达或异常状态，并显示文件数、尝试次数、送达时间或下次自动重试时间和最近错误。点击“立即同步”后，即使学生档案没有新变化，也会明确说明上一同步包是否已经送达；“无实质变化”只代表本机没有需要再生成的新版本，不代表对方已经收到。0.17.7 起，若直传请求先超时、稍后由后台自动重试送达，主机顶部提示会按本次同步包的异步送达回执自动更新，不再继续显示旧错误；“全部协作设备发送队列”可能包含其他学生或项目，应以当前学生卡片的精确状态为准。

以下内容 不会自动双向同步 ：

  • 学生原始资料库中的试卷、照片、录音、视频和其他原始文件；
  • 成长证据草稿、待审核知识和待审核报告；
  • 本机任务账本、运行缓存、锁文件和 Agent 私有历史。

需要把原始资料交给另一台主机时，请使用学生资料上传/投递；项目资料使用“发布项目”；随协作任务发送的文件先进入接收端受控收件箱。两台主机各自的学生原始资料目录保持本地权威，这是产品边界，不是同步故障。

Windows 主机端 0.17.7 与产品签名 Android 单机版 1.2.2 已具备多端知识协作能力；Windows—Android 配对、5000+ 文件、接近 20000 文件边界、64 MB 文件、断网重启、并发修改和 Tailscale 回退没有全部通过前，不表述为正式稳定功能。QClaw 远程知识路由与运行期间的教育档案自动更新仍保留复测门禁。对必须按时到达的资料，请使用明确的上传、投递或项目发布，并在“知识协作”中核对到达状态。

16. 精选课程

左侧一级菜单“精选课程”下分为两个二级菜单：

  • “课程学习”：所有版本均可进入，用于查看并打开当前已启用的课程；
  • “课程管理”：已激活的专业版、机构版和平台版可以打开。专业版、机构版管理机构自选课程和学生分配；平台版在同一页面直接获得平台课程草稿编辑、发布和恢复能力，不再区分平台身份。家庭版、试用版、未激活或已过期授权会显示锁定状态。

点击一级菜单“精选课程”可以展开或收起两个二级菜单。切换二级菜单不会改变学生档案或课程分配；如果许可证在“课程管理”打开期间过期或降级，系统会自动返回“课程学习”。

16.1 使用课程学习

  1. 在左侧展开“精选课程”，点击“课程学习”。
  2. 确认当前学生。页面只显示机构已启用、且按年级或学生规则分配给当前学生的课程。
  3. 点击课程卡片的“安全打开课程”。课程在独立受限浏览器中打开，不会获得教育管家本机文件、摄像头、麦克风或下载权限。
  4. 课程窗口顶部先显示“待开始”采集条。打开课程不会自动采集；如需留存课程资料，应主动选择学生、可选学习项目以及屏幕或窗口，再点击“开始采集”。
  5. 开始后，顶部待开始条收起并切换为现有悬浮控制条，可执行暂停、继续、重点截取和结束。结束后如课程仍打开，顶部重新显示“待开始”，不会自行开启下一次采集。
  6. 学习结束后关闭课程页面。打开、停留或采集课程资料不会自动标记课程完成。

采集资料始终绑定开始时选择的具体学生，并记录课程、提供方、链接和采集时间；选择项目时，该项目必须属于同一学生且未封存。未选择项目时，资料进入该学生的原始资料流程。

如果课程列表为空，请让专业版或机构版管理员进入“课程管理”，检查课程是否启用、年级是否匹配、学生是否被分配，然后点击“保存并下发”。

16.2 使用课程管理

先确认右上角许可证状态为已激活的专业版、机构版或平台版，再进入“精选课程 → 课程管理”。首批平台课程为 Starfall 英文小学数学和 Code.org 少儿编程与人工智能英文资源。课程管理支持：

  • 启用或隐藏课程；
  • 调整课程显示顺序；
  • 按年级限制；
  • 精确分配给一个或多个学生；
  • 导入经过版本、文件哈希和完整性校验的平台课程包；
  • 直接填写课程名称、课程简介和课程链接，选择课程图片后保存一门机构自选课程；
  • 编辑已有机构自选课程的名称、简介、图片和链接，同时保留课程 ID 与原有分配关系；
  • 删除不再使用的机构精选课程；平台版可把平台精选课程加入待删除并随新版课程包正式发布删除；
  • 专业版和机构版下载 Excel 模板，只填写“课程名称、课程图片、课程简介、课程链接”后导入机构自选课程。
  • 平台版顶部显示“生成/导出平台课程包”，可发布并导出新版、重新导出当前已发布版本，或显式恢复旧课程包；发布和接收过程由程序自动校验版本、文件哈希和完整性。

完成启用、顺序、年级或学生分配调整后，必须点击“保存并下发”。保存成功后，Windows 与 Android 学生端下次刷新时只接收当前学生的有效课程，不会看到其他学生的分配信息。

16.3 直接上传一门机构自选课程

直接上传适合临时增加一门课程，不需要先制作 Excel：

  1. 在“课程管理”找到“单门课程 · 直接上传”。
  2. 填写“课程名称”“课程简介”和“课程链接”。
  3. 点击“上传课程图片”，选择 PNG、JPG/JPEG 或 WebP 图片；确认预览和文件名正确。
  4. 点击“保存课程”。保存成功后，新课程会出现在下方课程管理列表。
  5. 设置课程启用状态、年级和学生分配，再点击“保存并下发”。

直接上传规格：

  • 仅已激活的专业版和机构版可用；
  • 课程名称必填，不超过 120 个字符；
  • 课程简介必填，不超过 1200 个字符；
  • 课程链接必填，必须使用 HTTP 或 HTTPS，不能带网址用户名或密码；优先使用 HTTPS；
  • 课程图片必选，支持 PNG、JPG/JPEG、WebP，单张不超过 5 MB；
  • 保存时系统把图片复制到主机受控课程目录，不依赖原图片继续保留在用户文件夹；
  • 相同课程链接再次保存会更新同一门自选课程，不会生成重复课程；
  • 直接上传与 Excel 导入共用最多 200 门机构精选课程的总量上限，不会覆盖平台精选课程。

文件选择后，渲染页面只持有一次性选择凭据；真正的本地图片路径和格式校验在 Windows 主进程完成，网页内容不能伪造路径读取其他本机文件。

16.4 编辑已有机构自选课程

  1. 在“精选课程 → 课程管理”的课程列表中找到带有“机构自选”标识的课程。
  2. 点击“编辑课程”。页面会回到上方编辑表单，并自动填入课程名称、课程简介、当前课程图片和课程链接。
  3. 按需修改名称、简介或链接；如需更换图片，点击“重新选择课程图片”。不重新上传时保留当前图片。
  4. 点击“保存修改”。系统保持原课程 ID、启用状态、显示顺序、年级限制和学生分配不变。
  5. 返回课程卡片点击“预览课程”，确认新链接和图片正确；如果另外修改了启用或分配策略，再点击“保存并下发”。

专业版和机构版不能编辑平台精选课程；“编辑课程”只出现在机构精选课程上。平台精选课程仅在持有有效平台版 License 的主机上显示“编辑平台课程”。修改后的链接必须使用 HTTP 或 HTTPS，且不能与另一门机构精选课程重复。

16.5 删除机构精选课程或平台精选课程

删除和隐藏的作用不同：隐藏只停止向学生端展示，保留课程和全部分配设置；删除会把课程从有效目录中移除。

删除机构精选课程：

  1. 专业版、机构版或平台版主机在课程卡片点击“删除课程”。
  2. 核对课程名称并确认删除。系统立即移除该机构课程，同时清除启用状态、顺序、年级和学生分配规则。
  3. 已打开的同一课程会自动关闭；Windows 与 Android 学生端下次刷新后不再显示该课程。

删除平台精选课程：

  1. 只有有效平台版 License 会显示“删除平台课程”。点击并确认后，课程先标记为“待发布删除”，不会立即修改当前已发布目录。
  2. 如操作有误，可在课程卡片或待删除清单点击“取消删除”。
  3. 确认无误后点击“发布并导出平台课程包”，选择新版 .edu-coursepkg 保存位置。系统生成高于当前目录版本的新包，完成文件哈希和完整性回验后，在平台主机本机正式删除该课程。
  4. 专业版、机构版或其他平台版主机导入这一新版课程包后，同步移除该平台课程及其本机分配规则；未导入新版包的主机仍保留旧目录。

课程封面文件可能继续保留在受控资源目录中用于审计、回滚和旧课程包恢复，但不会继续出现在有效课程目录或学生端。

16.6 平台版编辑和发布平台课程

License 管理工具发放激活码时只需选择“平台版”，不再选择平台课程编辑、平台课程发布或平台管理员身份。有效平台版 License 统一获得平台课程编辑、发布和恢复能力，共用现有 Windows 主机安装包和课程管理页面，不增加新端口。

平台课程操作步骤：

  1. 使用有效平台版 License 激活受控 Windows 主机，进入“精选课程 → 课程管理”。
  2. 点击已有平台课程的“编辑平台课程”，或在“平台课程编辑与发布草稿”直接新增。
  3. 与机构精选课程一样，只填写课程名称、课程简介、课程链接和课程图片。课程链接优先使用 HTTPS；课程网站确实没有 HTTPS 时可以填写 HTTP。
  4. 点击“保存平台草稿”。草稿独立保存，不修改当前已发布课程，也不会立即推送学生端。
  5. 可填写发布说明，然后点击“发布并导出平台课程包”并选择 .edu-coursepkg 保存位置。系统生成新版课程包、保存到指定位置，并在本机重新校验后同步应用；顶部“生成/导出平台课程包”执行相同操作。
  6. 每次成功发布或导入的原始课程包会按目录版本和 SHA-256 留存受控副本。如果交付文件丢失且当前目录版本未改变，可点击“重新导出当前版本”；程序先复核原始包完整性，再逐字节复制，不增加目录版本、不重新发布课程。
  7. 如需恢复旧目录，使用“从课程包恢复”，明确选择以前发布的有效 .edu-coursepkg ；操作需要二次确认并写入审计记录。

有效平台版 License 是发布平台精选课程的唯一权限条件，不再配置“平台发布主机”，也没有课程目录私钥、公钥包或发布确认码。专业版、机构版和平台版接收主机可直接导入平台课程包；系统验证版本、路径安全、文件哈希和完整性，校验失败时保留最后可用目录。

平台 License 的正常流程是：在授权管理工具 0.3.1 的“平台 License 密钥管理”中创建或导入密钥，签发版本为“平台版”的 .aielicense ；平台版不再选择编辑、发布或管理员身份。目标主机导入许可证后直接获得统一的平台课程编辑、发布和恢复能力。要求绑定设备时，激活码必须包含该主机显示的稳定主机 ID；验证失败不会覆盖当前机构版许可证。

16.7 用 Excel 导入机构自选课程

  1. 在“课程管理”点击“下载 Excel 模板”，选择保存位置。
  2. 打开模板，只在“课程导入”工作表填写数据，不修改四个表头。
  3. 每门课程填写一行，四列都必须填写：课程名称、课程图片、课程简介、课程链接。
  4. 保存为 .xlsx 文件，回到课程管理点击“导入自选课程 Excel”。
  5. 导入成功后设置启用、年级和学生分配，再点击“保存并下发”。

Excel 规格：

  • 文件必须为 .xlsx ，文件大小不超过 10 MB；
  • 四个表头必须出现在第一个工作表的前 10 行中；空白行会忽略；
  • 一次最多导入 200 门课程；
  • 课程名称不超过 120 个字符，课程简介不超过 1200 个字符；
  • 课程图片可填写与 Excel 同目录的图片文件名、图片完整本地路径，或 HTTPS 图片网址；
  • 图片支持 PNG、JPG/JPEG、WebP，单张不超过 5 MB；
  • 课程链接必须使用 HTTP 或 HTTPS，不能带网址用户名或密码；优先使用 HTTPS，只有课程提供方确实没有 HTTPS 时才使用 HTTP；
  • 相同课程链接再次导入会更新该课程；同一个 Excel 内不能出现重复课程链接；
  • 已有平台精选课程不会被 Excel 覆盖。

模板也兼容“课程连接”作为“课程链接”的表头，但建议始终使用模板默认的“课程链接”。如果需要携带本地图片一起迁移到另一台主机，请把 Excel 和相对引用的图片放在同一个文件夹内整体复制。

16.8 导入平台离线目录

“导入平台课程包”接受平台版主机生成的 .edu-coursepkg ，并兼容旧版课程目录 .json 。操作步骤：

  1. 从平台或受信任交付渠道取得 .edu-coursepkg 文件，不要解压、重打包或编辑其中内容；旧版 .json 只用于兼容已有交付。
  2. 在“课程管理”点击“导入平台课程包”，选择该文件。
  3. 系统自动校验目录结构、文件 SHA-256、完整性清单、目录版本和最低主机版本。
  4. 校验通过后才替换当前平台目录；校验失败时保留本机最后可用目录，不影响现有课程学习。

课程包规格为：单包不超过 250 MB、最多 1000 个归档文件、单张课程图片不超过 5 MB；图片只接受 PNG、JPG/JPEG 或 WebP。系统拒绝路径越界、重复文件、未知文件、展开体积超限、哈希不符、主机版本过低或普通导入中的目录降级。校验失败时保留最后可用目录。

专业版或机构版用户可以导入平台课程包，页面会明确提示“只有平台版可以生成或导出平台课程包”。需要增加本机构自己的课程时可直接上传，需要批量增加时使用 Excel 导入；机构精选课程只下发给本机构学生，不会进入平台课程包，也不能伪装成平台包导出。

课程在独立受限浏览容器中打开，仅允许课程目录明确登记的 HTTP 或 HTTPS 域名；新窗口、下载、未知跳转和权限申请会被阻止。HTTP 兼容不会开放任意网站，也不会绕过 HTTPS 证书错误。对于已知只支持 HTTP 的金榜学霸站点，旧 https://www.jinbangxueba.com 地址会自动迁移为 http://www.jinbangxueba.com/ 。

主机课程页可点击“全屏学习”。进入后顶部固定保留“退出全屏（Esc）”；点击该按钮或直接按键盘 Esc ，都会退出系统全屏、恢复普通窗口并重新显示左侧栏。即使焦点正在第三方课程网页内， Esc 仍然有效。

目录完整性或版本检查失败时继续使用本机最后可用目录。平台课程名称、简介、链接和图片只能由有效平台版 License 形成草稿并发布。

打开第三方课程、停留在网页或采集屏幕资料，不代表课程完成、答题正确或形成学情结论。账号、会员、收费、年龄和服务条款以第三方页面当时说明为准。

17. 备份与恢复

系统设置的“备份与迁移”提供两种不同用途：

  • 创建日常备份 ：保存主机状态、学生索引、设备授权、上传记录、应用索引及每名学生最新教育档案，适合升级前和配置恢复；
  • 迁移到新电脑 ：携带学生资料根目录中的实际文档、项目、知识、报告、课程图片和必要应用状态，适合更换电脑或资料磁盘。

17.1 创建和恢复日常备份

“创建日常备份”生成轻量 JSON。恢复时会校验档案清单和文件哈希；损坏版本会被隔离，不会覆盖现有有效档案。恢复后学生列表、学习项目、文件资产和主机状态会立即刷新。

从另一台 Windows 电脑恢复备份时，系统会识别备份中的旧资料根目录和旧 Windows 用户目录，把受管学生、项目、资产及协作配置重映射到当前电脑的“学生资料”根目录。位于其他盘符、且不属于原受管根目录的外部接管知识库不会被自动改写。若学生知识库已通过同步或复制到新位置，可在学生详情使用以下两种方式：

  • “手工选择原始资料库”：只调整原始资料库路径，保留当前学生知识库路径；
  • “手工选择学生知识库”：只调整学生知识库根目录及学情汇总/wiki 路径，保留当前原始资料库路径。

两个入口分别校验所选目录确实存在且包含实质文件，并各自显示旧路径、新路径供人工确认。取消选择或确认框不会修改配置。绑定只更新所选路径、教育管家路径映射和受控路径区块，不移动、复制、删除或新建资料目录。成功后系统重新读取主机学生索引；另一条未选择的路径保持不变。

Windows 主机端 0.16.7 已在真机完成“更改目录路径 → 重新分析迁移内容 → 创建迁移包 → 新电脑恢复”的闭环验证。若旧电脑的原始资料库和学生知识库位于不同目录或不同盘符，应分别使用上述两个入口绑定真实目录，再重新创建迁移包；不要依赖空的默认目录或占位文件。

注意：日常备份不等于完整资料文件备份。换电脑时应使用下面的完整迁移包，不再要求用户手工拼接 JSON 和资料目录。

17.2 创建完整换机迁移包

  1. 在“系统设置 → 基础设置 → 备份与迁移”展开“迁移到新电脑 / 从迁移包恢复”。
  2. 点击“分析迁移内容”。系统会分别盘点受管资料，以及每名学生位于受管根目录之外的知识库、原始资料、学情分析汇总、成长模型、输出结果和教育档案历史版本；同时盘点项目根目录、工作空间、原始资料、知识空间和管理记录。
  3. 所有学生资料目录均为必选，不能取消；项目外部目录默认全部包含，如确实不需要迁移某个项目才取消勾选。父目录已经覆盖子目录时系统自动合并，但并列目录必须分别列出并进入迁移包。
  4. 点击“创建迁移包”，选择 U 盘、移动硬盘或其他独立保存目录。保存位置不能位于“学生资料”、接管知识库或项目工作空间内部，也不要选择这些目录的子目录。
  5. 等待文件数进度完成。不要在导出过程中拔出外接存储或强制关闭程序。

迁移包是一个完整目录，包含 migration.json 、 manifest.json 、 manifest.sha256 、 migration-report.md 和 payload 。新版迁移包不设置密码，使用短英文目录和哈希载荷文件名，并通过逐文件 SHA-256 校验完整性。可直接将整个目录复制到 U 盘；原来的中文文件名和目录会在新电脑恢复时自动重建。不要只复制其中的某个文件，也不要编辑或重命名载荷。如确需压缩，压缩后应先完整解压为目录，再由主机端校验和恢复。

迁移包包含受管资料、知识、项目、报告、成长模型、任务中心、采集资料、机构课程和课程图片。以下敏感身份不会进入迁移包：License、API Token、固定主机身份、终端授权令牌、协作直传密钥、平台 License 私钥和课程私钥。

17.3 在新电脑恢复迁移包

  1. 安装版本不低于迁移包来源版本的 Windows 主机端。
  2. 打开“备份与迁移”，点击“选择并校验迁移包”，选择迁移包目录。系统会校验清单和全部载荷 SHA-256。
  3. 新版迁移包无需密码；如果程序识别为旧版加密迁移包，界面才会显示密码输入框，此时输入原来的迁移包密码。
  4. 点击“恢复到空白目录”，选择一个空白文件夹作为新的学生资料根目录。不能选择磁盘根目录或已有资料的非空目录。
  5. 系统检查磁盘空间，先把全部内容恢复到同盘符暂存目录，完成路径重映射和原文 SHA-256 复核后才切换正式目录；旧版加密包会在暂存恢复过程中完成解密。
  6. 完成后重新激活本机 License，并重新连接学生终端和跨主机协作关系。
  7. 查看新资料根目录 .edu-manager/migration-report.json 。如果存在 needs_relocation ，学生进入“目录绑定与路径修复”；项目分别使用“更换工作空间”或“绑定知识空间”。

完整迁移只复制并验证数据，不会删除旧电脑资料。确认新电脑上的学生、项目、报告、原始资料和知识文件均可打开后，再自行决定是否停用或清理旧电脑。

17.4 迁移失败处理

  • 文件损坏 ：恢复会在正式切换前停止，不覆盖新电脑当前状态；请重新取得完整迁移包。
  • 旧版加密包密码错误 ：输入创建旧版迁移包时使用的正确密码；新版迁移包没有此步骤。
  • 目标目录非空 ：新建或选择空白目录，不要把迁移直接覆盖到已有学生资料上。
  • 磁盘空间不足 ：至少保留迁移原始数据容量 110% 的可用空间。
  • 提示迁移包位于资料目录内 ：重新选择 U 盘、移动硬盘或与所有来源目录相互独立的位置；不要把迁移包保存到“学生资料”、接管知识库或项目工作空间内部。
  • 提示导出期间存在后台变化 ：迁移仍会完成，报告会列出新增、删除或修改的文件示例。包内每个文件都是复制前后 SHA-256 一致的稳定版本，但导出开始后由 Obsidian、Agent 或同步任务再次产生的内容可能未包含；如需最接近当前时刻的完整快照，可暂停相关任务后再创建一次迁移包。
  • 提示单个源文件在复制过程中变化 ：该文件无法形成稳定版本，迁移会停止。暂停正在写入该文件的 Agent、编辑或同步任务后重试。
  • 来源版本较新 ：先升级新电脑主机端，再重新校验和恢复。
  • 出现恢复诊断目录 ：不要删除提示的 .staging 或 migration-unactivated 目录；先导出诊断日志并核对恢复报告。
  • 迁移后只有占位报告或少量文件 ：旧迁移包可能只纳入了接管知识库根目录，遗漏并列的学情分析汇总、成长模型或原始资料。保留旧电脑原文件，在旧电脑安装修复后的主机版本，重新执行“分析迁移内容”；确认所有学生必选目录和项目目录的文件数、容量均合理后重新创建迁移包。缺失正文无法仅在新电脑上凭空恢复。
  • 项目外部目录被取消 ：学生必选目录仍会完整迁移；被取消的项目资料保留在旧电脑，新电脑需要在项目详情使用“重新定位”重新绑定。

18. 常见问题

新版看不到原学生

先确认旧版窗口已关闭。0.10.4 使用单实例保护和主机索引校准；如仍缺失，恢复主机备份并检查学生知识库路径。

待消化数量不变

无需手工标记提交或同步。先等待最多 5 秒让页面自动刷新；如果仍未变化，展开“高级与诊断”查看简短原因。单文件项目批次满足前述 Markdown 回执和知识产物条件时会自动兼容；多文件批次、只有知识文件没有完成回执或证据不足时仍会继续显示处理中。此时可点击“重试未完成项”，或在人工降级区粘贴正确结果。

提示“资料无法读取/未建立批次”

新版会先处理其余可读文件，不再因为一项路径失效而整批失败。若文件刚上传或正在同步，等待约 3—5 秒后点击“重新检查并自动修复”；若提示“当前原始资料库中未找到文件”或“找到多个相同文件”，在“资料路径预检”中点击“手工选择文件”，从当前学生原始资料库选择原文件。系统会核对 SHA-1；内容不一致、位于其他学生目录或原始资料库之外的文件不会绑定。若确实是新文件，应先正常导入当前学生原始资料库，而不是用旧记录强行绑定。

项目消化回执已写入但无法同步

Windows 0.10.7 会按内容识别并合并当前批次的分段 JSON 回执，不要求 QClaw 严格使用单一文件名，也可读取带 UTF-8 BOM 的 Agent JSON；单文件项目批次还可按前述保守条件兼容 Markdown 完成回执。项目回执使用 digestStatus 、 digestFiles 和 digestStats 时，只有项目、批次、完整文件集合、逐项 SHA-1 以及“实际消化数 + 明确跳过数 = 总数”全部闭合才会自动结算。旧批次回执会隔离保存，不会误结算当前任务。若进入人工诊断，回执必须使用当前请求中的 projectId 与 digestBatchId 。

数学图片未被识别

生成覆盖审计，选择失败或低置信度图片，执行二次核对并同步复核结果。

项目工作空间打不开

进入项目详情点击“更换工作空间”，选择真实存在的工作空间来源目录。该操作只修改工作空间绑定；如果打不开的是项目知识空间，应点击“绑定知识空间”，不要用工作空间目录替代知识空间。

学生终端已连接但没有学生

个人终端请在主机设备卡片绑定学生；共享终端请让学生扫描主机生成的本人二维码或输入完整学生 ID。共享终端不会显示可选择的学生名单。

教师端连接后只能看到一个学生或提示需要学生登录

确认 Windows 主机版本为 0.16.1 或更高，并重新使用教师端完成一次配对。主机设备记录应显示教师终端角色；从旧学生端授权记录直接恢复不会自动获得教师角色。教师端不需要绑定个人学生，也不需要进入共享学生登录流程。

Android 或 Windows 学生端找不到附近主机

确认 Windows 主机服务已启动，主机和学生终端连接同一局域网，且路由器没有启用访客网络或客户端隔离。允许 Windows 防火墙的专用网络访问后重新搜索。终端发起时选择“扫描局域网主机”，在 Windows 主机的“等待主机接受”中核对机器码后接受；主机发起时让 Android 或 Windows 学生端停留在连接页面，再由主机查找并邀请。仍无法发现时，可展开“其他连接方式”，使用二维码、六位配对码、粘贴连接信息或连接备份。

Android 学生端发现两个 IP 相同的主机

Windows 为兼容旧版客户端，可能同时发送新版和旧版发现信息。Android 0.6.3 会自动把同一发现端点或同一设备身份合并为一台主机，并保留带固定主机码的新版记录。若仍看到两个相同 IP 的条目，请确认 Android 终端确为 0.6.3，退出连接页后重新进入并再次查找；不要选择不显示主机码的旧版记录。

程序运行变慢

在任务中心关闭全部自动运行，停止不需要的屏幕采集会话，并检查是否存在大量待处理 OCR、审计或资产扫描任务。

课程管理显示锁定

确认许可证已经激活，且版本为专业版、机构版或平台版。家庭版、试用版、未激活或已过期授权仍可使用“课程学习”，但不能打开课程管理、导入目录或保存分配策略。平台版不再区分身份，也不需要另行配置发布主机或发布凭据。

Excel 课程导入失败

确认文件为 .xlsx 且不超过 10 MB；四个必填表头位于第一个工作表前 10 行；每个非空数据行四列均已填写；图片格式和大小符合要求；课程链接以 https:// 或 http:// 开头且没有重复。导入失败不会部分写入课程，可修正后重新导入。

单门课程无法保存

确认许可证为已激活的专业版或机构版，并且课程名称、课程简介、HTTPS 课程链接和课程图片都已填写。图片必须为 PNG、JPG/JPEG 或 WebP 且不超过 5 MB；名称不能超过 120 个字符，简介不能超过 1200 个字符。若课程图片在选择后被移动或删除，请重新点击“上传课程图片”后保存。相同课程链接会更新原课程，不会新增第二条。

团队知识查询没有远程结果

确认两台电脑已经在“系统设置 → 知识协作”显示“已连接”，并且发送端开启“允许远程协作团队知识查询”。先检查局域网是否可达；使用 Tailscale 时确认双方在线。结果如果标为离线快照，应按显示的更新时间判断是否继续使用；明确显示“等待远程知识”时，不要把它当作零结果。

另一台主机看不到刚添加的原始资料

学生原始资料不自动双向同步。请使用学生资料上传/投递，或者在学习项目中执行“发布项目”。已确认知识、成长模型、已发布报告和完整教育档案属于另一条同步通道，不能代替原始资料交付。

Agent 对话进入了待确认归属

这表示系统不能唯一确认学生或学习项目。进入“系统设置 → 知识协作”的待确认入口，核对对话摘要后选择正确学生和有效关联项目。不要为了清空提示而选择相似姓名的其他学生；确认后系统沿用原提交 ID，不会重复保存同一对话。
