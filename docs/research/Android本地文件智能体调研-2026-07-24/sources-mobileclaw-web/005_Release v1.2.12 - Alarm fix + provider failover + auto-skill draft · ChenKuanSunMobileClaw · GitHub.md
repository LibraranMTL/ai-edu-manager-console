## v1.2.12

Five bundled work items + one doc, all behind feature flags (default OFF) so v1.2.11 user behavior is unchanged unless you opt in via Settings → Advanced.

### Bug fix - Alarm via chat (beta tester report)

  * `AlarmTimerTool.set_alarm` was silently dropped on Android 10+ from background context (BAS), returning fake Success.
  * Now uses `AlarmManager.setAlarmClock` \+ new `AlarmReceiver`. Manifest declares `SCHEDULE_EXACT_ALARM` \+ `USE_EXACT_ALARM`.
  * Honest error path on missing exact-alarm permission, with the standard `REQUEST_SCHEDULE_EXACT_ALARM` deep link.



### UX fix - Calendar permission

  * New `StructuredToolError` DTO. `CalendarTool` returns it on permission denied, with `Settings.ACTION_APPLICATION_DETAILS_SETTINGS` deep link.
  * `ChannelManager` system prompt instructs LLM to relay actionHint verbatim instead of paraphrasing into a generic "I can't access your calendar".



### Upstream sync - OpenClaw v2026.4.25-4.27

Selective cherry-picks (skipped 4.27 wholesale due to known regressions):

  * `9189b16` Bedrock Opus 4.7 max thinking, flag-gated to opus-4-7 only.
  * `38aac70` Feishu skip blank `{"text":""}` events to prevent MiniMax "messages must not be empty (2013)" rejections.



### Feature - Provider Failover Chain (Settings → Advanced)

  * New `RetryPolicy` extracts retry-on-failover decision into pure data.
  * `ClaudeApiClient.sendMessage` retries on 429/408/502/503/504/SocketTimeout/ConnectException only — never on auth or 4xx logic errors.
  * Fallback request automatically swaps model to fallback provider's first listed model (providers expose disjoint model catalogs).
  * `ClaudeResponse` now carries `actualProviderId`, `actualModelId`, `attemptTrace` so debug shows the full path.
  * UI: toggle + 2 fallback dropdowns + max-attempts (1 or 2). Fallback chain auto-strips removed providers.



### Feature - Auto-skill MVP (Settings → Advanced, opt-in)

  * `SkillAuthorTool.create` accepts new `id_strategy` parameter:
    * `"exact"` (default): unchanged v1.2.11 behavior — confirmation + auto-enable.
    * `"or_suffix"`: auto-write draft, no confirmation, suffix on collision, NEVER auto-enabled.
  * `AgentRuntime` triggers a hidden follow-up after `end_turn` when ≥2 distinct tools succeeded with no rejected confirmations.
  * Follow-up uses isolated tool registry containing only `skills_author` — runs OUTSIDE the agent flow, no chat history pollution.
  * Modes: Off / AutoOnRemote (skip local Gemma + localhost CUSTOM) / Always.



### Doc - LiteLLM Proxy as CUSTOM provider

`docs/integrations/litellm-proxy.md` shows zero-code setup pointing CUSTOM provider at a self-hosted LiteLLM Proxy.

### Tests

247 unit tests green (214 baseline + 33 new across 6 test files).

### Process

Cross-reviewed with Codex (gpt-5.4) via 5 rounds:

  * Rounds 1-2: design alignment.
  * Round 3: spec review — added Rollback / Migration / Observability sections + 4 boundary entries.
  * Round 4: blocker check — fixed Manifest/README missing from §3.
  * Round 5: implementation review — caught a real blocker (failover sent original model ID to fallback provider) — fixed before ship.



### Defaults

All new features OFF: `bedrockMaxThinkingEnabled=false`, `failoverEnabled=false`, `autoSkillMode=Off`.
