# AI教育管家 Skills 存档、浏览与本地安装开发计划

版本：v1.0（开发评审稿）  
日期：2026年10月18日  
范围：Windows 主机版“Agent设置管理 → Skills管理”，包括本机 Skill／插件扫描、下载与导入、版本化存档、自动标签、分类浏览，以及安装到本机 Agent。  
状态：方案已编制；本文所列新增能力尚未开发、测试、打包或发布。

## 1. 本轮决策与范围

### 1.1 产品决策

1. 在“Agent设置管理”增加第五个同级 tab：`Skills管理`。
2. `Skills管理`包含两个二级页面：
   - `Skill存档管理`：扫描来源、下载／导入、存档路径、版本、检查结果、隔离区和操作记录。
   - `Skill浏览`：分类、搜索、详情、兼容性、风险、安装、升级、回滚和验证。
3. 页面名称沿用“Skills管理”，但底层资产类型同时支持 `skill` 和 `plugin`；列表中必须明确显示类型，不能把插件伪装成普通 Skill。
4. 本轮所有能力均为 Windows 主机级能力，不绑定学生、项目或当前页面所选学生。
5. 存档默认保存在 Electron `app.getPath('userData')/skill-library`，用户可迁移到自定义目录。
6. 首批自动安装目标为 Codex 和 WorkBuddy 的本地 Skill；插件安装及其他 Agent 适配按分阶段闸门开放。
7. QClaw 本轮只做受控扫描、选择、导出和保存到教育管家 Skill 存档；不向 QClaw 安装、升级、卸载或回滚 Skill／插件。
8. “发现”“已存档”“已检查”“已安装”“已加载”“已验证”是不同状态，不得互相替代。

### 1.2 明确暂缓

本轮不开发以下内容：

- 不新增 MCP 工具、MCP 权限或远程安装接口。
- 不允许外部 Agent 通过教育管家连接器发起安装。
- 不修改 `edu-manager.agent-capabilities.v1`。
- 不建设云端 Skill 商店或跨设备 Skill 同步。
- 不默认上传 Skill 内容、扫描结果或使用记录。
- 不做无人值守安装、静默权限扩大或自动执行插件 Hook。
- 不把 Skill 存档纳入学生知识库、项目资料库或教育资料云同步。

本地业务服务应保持可复用边界，未来如恢复 MCP 方向，可调用同一个 `SkillLibraryService`；但本轮不预埋可被外部调用的入口、令牌或权限。

## 2. 建设目标与完成标准

### 2.1 用户目标

普通用户应能完成以下流程：

```text
打开 Skills管理
→ 扫描本机已安装 Agent 的有效 Skill／插件来源
→ 查看发现项与风险摘要
→ 选择存档或从本地／网络导入
→ 自动生成分类标签
→ 在 Skill浏览中筛选和查看详情
→ 选择目标 Agent
→ 查看安装预览并确认
→ 教育管家执行本地安装
→ 重启／刷新目标 Agent
→ 验证实际加载状态
```

当用户后来安装一个新的 Agent 时：

```text
教育管家刷新 Agent 安装状态
→ 新 Agent 出现在目标列表
→ 用户从本地存档选择 Skill
→ 使用该 Agent 的本地安装适配器
→ 返回安装、需重启、已加载或不支持自动安装的明确状态
```

### 2.2 首版完成标准

首版不得只以“文件已复制”为完成标准。至少满足：

1. 能从受控根目录发现合法 `SKILL.md`，并排除缓存、依赖目录和越界符号链接。
2. 能把一个 Skill 以不可变内容版本存档，重新读取时哈希一致。
3. 能区分同名不同发布者、同名不同内容和完全重复内容。
4. 能显示来源、简介、标签、风险、兼容性、存档路径和各 Agent 安装记录。
5. Codex、WorkBuddy 各至少完成一次真实本机 Skill 安装、重启／刷新后发现和最小调用验证。
6. 安装目标在预览后发生变化时拒绝覆盖。
7. 安装失败能够恢复原目录或保留可操作的恢复记录。
8. 不读取、复制或输出 Agent 凭据、`.env`、令牌文件及无关用户配置。

## 4. 信息架构与页面设计

### 4.1 导航结构

```text
Agent设置管理
├─ AI 接入与调度中心
├─ Agent 数据管理
├─ Agent连接管理
├─ 云端同步设置
└─ Skills管理（新增）
   ├─ Skill存档管理
   └─ Skill浏览
```

页面可在没有学生档案、没有当前学生时正常打开。安装操作只允许教师（父母）或设备管理身份执行；学生身份只读浏览或完全隐藏安装按钮，具体沿用 Windows 主机现有身份策略。

### 4.2 Skill存档管理

页面分为六块：

1. **存档位置**
   - 当前路径、可用空间、写入状态、最近校验时间。
   - “使用默认位置”“选择自定义位置”“迁移存档”“打开目录”。
   - 路径变更必须走迁移，不允许只修改配置指针。

2. **本机 Agent 来源**
   - Agent 名称、安装状态、已解析的有效根目录、扫描能力、最近扫描结果。
   - 单个扫描、全部扫描、停止扫描。
   - 不显示凭据目录内的文件清单。

3. **导入／下载**
   - 导入本地 Skill 目录。
   - 导入 ZIP 包。
   - 从 HTTPS 地址下载 ZIP。
   - 从 Git 仓库和固定 ref 导入，作为第二阶段能力。
   - 来源必须保存原始 URL／仓库／ref，不允许只保存文件名。

4. **待存档与检查结果**
   - 新发现、内容变化、完全重复、同名冲突、不支持、风险阻止。
   - 批量存档只允许对已完成检查的项目执行。

5. **隔离区**
   - 路径越界、压缩炸弹、疑似秘密、不可识别清单、二进制、Hook、危险安装脚本等。
   - 隔离项默认不能安装；用户可查看原因、删除隔离副本或重新导入修复版。

6. **操作记录**
   - 扫描、下载、存档、迁移、安装、升级、卸载、回滚和验证回执。
   - 默认保留最近记录；清理回执不影响实际存档和安装。

### 4.3 Skill浏览

列表支持：

- 关键词：名称、简介、发布者、标签。
- 类型：Skill／插件。
- 分类：教育、研究、文档、开发、媒体、自动化、知识库、办公、其他。
- 来源：本机扫描、本地导入、ZIP、HTTPS、Git、官方市场。
- 兼容 Agent：Codex、OpenClaw、QClaw、Claude Code、WorkBuddy、其他。
- 信任状态：自建、官方、已核验来源、未知来源、已阻止。
- 风险：纯指令、含脚本、含依赖安装、含网络、含 MCP、含 Hook、含二进制。
- 安装状态：未安装、部分安装、已安装、需升级、需重启、待验证、验证失败。

详情抽屉或详情页展示：

- `name`、`description`、发布者、许可证、版本、语言。
- 来源地址和固定 ref／版本。
- `packageSha256`、`treeSha256`、文件数量和总大小。
- 自动标签、用户标签和标签依据。
- 关键文件树；默认不渲染或执行 HTML／脚本。
- 观察到的能力与声明能力差异。
- 每个目标 Agent 的兼容性、安装路径、当前版本和操作按钮。
- 历史版本、安装回执和回滚入口。

## 5. 统一资产模型

### 5.1 SkillArtifact

建议结构：

```json
{
  "schema": "edu-manager.skill-artifact.v1",
  "artifactId": "skill-uuid",
  "kind": "skill",
  "identity": {
    "name": "pdf-processing",
    "publisher": "publisher-id-or-unknown",
    "displayName": "PDF Processing"
  },
  "currentVersionId": "version-uuid",
  "tags": {
    "system": ["documents", "pdf"],
    "semantic": ["文档处理"],
    "user": ["常用"],
    "manualLocked": true
  },
  "compatibility": [],
  "installations": [],
  "createdAt": "ISO-8601",
  "updatedAt": "ISO-8601"
}
```

身份不能只使用 `SKILL.md.name`。推荐逻辑键为：

```text
kind + normalizedPublisher + normalizedName
```

发布者未知时保留独立来源身份；不得把两个未知来源的同名 Skill 自动合并。

### 5.2 SkillVersion

每个版本至少保存：

- `versionId`
- `artifactId`
- `declaredVersion`
- `sourceType`
- `sourceUri`
- `sourceRef`
- `downloadedAt`／`discoveredAt`
- `packageSha256`：原始 ZIP 或下载对象哈希，可为空。
- `treeSha256`：排序后的相对路径、文件大小和单文件哈希形成的目录树哈希。
- `manifestSha256`
- `fileCount`
- `totalBytes`
- `entryPoint`
- `description`
- `license`
- `observedCapabilities`
- `riskFindings`
- `inspectionStatus`
- `archiveObjectPath`

目录树哈希必须基于原始字节，不规范化换行或编码。来源追踪元数据与可安装载荷分开保存，避免宿主自己的 lock／origin 文件改变载荷身份。

### 5.3 InstallationRecord

```json
{
  "installationId": "install-uuid",
  "artifactId": "skill-uuid",
  "versionId": "version-uuid",
  "providerId": "codex",
  "scope": "user",
  "targetPath": "resolved-absolute-path",
  "adapterVersion": 1,
  "planHash": "sha256",
  "beforeFingerprint": "sha256-or-empty",
  "installedFingerprint": "sha256",
  "state": "restart_required",
  "installedAt": "ISO-8601",
  "verifiedAt": "",
  "backupReceiptId": "receipt-uuid"
}
```

安装路径用于展示和审计，但 renderer 不得自行传入任意绝对路径。renderer 只能提交 `artifactId`、`versionId`、`providerId` 和已登记 `scope`，目标路径由主进程适配器解析。

## 6. 默认存储布局

```text
<userData>/skill-library/
├─ settings.json
├─ catalog.json
├─ objects/
│  └─ sha256/<treeSha256>/payload/...
├─ sources/
│  └─ <sourceId>.json
├─ staging/
├─ quarantine/
│  └─ <operationId>/...
├─ receipts/
│  ├─ scans/
│  ├─ imports/
│  ├─ installs/
│  └─ rollbacks/
└─ backups/
   └─ <providerId>/<installationId>/...
```

规则：

- `objects` 内容不可原地修改；新内容生成新版本。
- `catalog.json` 只保存索引和相对引用，不内嵌大文本或二进制。
- `staging` 每次启动执行有界恢复；未完成操作不得自动变成已存档或已安装。
- `quarantine` 与可安装对象物理分离。
- 自定义存档根目录只改变上述库的位置；指针和迁移状态仍保存在 `userData`，防止自定义盘离线后丢失配置。
- 存档库不随卸载 Agent 删除，也不因卸载教育管家而静默删除。

## 7. 扫描与发现设计

### 7.1 原则

1. 不扫描整个用户主目录或磁盘。
2. 每个 Agent 由适配器返回允许的根目录、来源类型和优先级。
3. 优先使用 Agent 官方 CLI／状态接口列出有效 Skill；没有接口时才扫描受控目录。
4. `node_modules`、临时目录、日志目录、下载缓存和无清单目录默认排除。
5. 插件缓存可作为“宿主观察来源”，但不能直接当作安装源；需回溯插件清单和来源身份。
6. 跟随符号链接前检查 realpath；目标超出允许根目录时记录阻止项，不读取目标内容。
7. 发现 `SKILL.md` 后停止向其子目录继续寻找独立 Skill，除非插件清单明确声明多个 Skills 根。

### 7.2 首批来源适配器

| Agent | 扫描策略 | 本轮安装／导出策略 | 插件策略 |
|---|---|---|---|
| Codex | 解析 `CODEX_HOME`、用户 Skills 根、repo 级 Skills 和已登记插件市场；缓存单独标注 | 将受检 Skill 安装到解析后的受管 Skills 根，要求新会话验证 | 第二阶段调用官方插件／市场机制；不得直接写 cache |
| WorkBuddy | 结合已发现的 WorkBuddy 运行时、配置目录、当前版本支持的官方 CLI／设置接口解析有效 Skill 根；区分 `.workbuddy`、`.codebuddy` 和缓存 | 优先使用当前版本明确支持的本地 Skill 安装接口；若为受支持目录安装，则使用事务复制。会话临时 Skill 目录或环境变量不算持久安装 | 第二阶段仅在官方插件机制可验证时开放；不得写入运行时缓存 |
| QClaw | 只扫描 QClaw 当前配置声明的有效 roots 或可验证 Gateway／CLI 返回；禁止递归整个 `.qclaw` | 仅把用户选中的有效 Skill 导出并保存到教育管家对象库，生成来源、版本、哈希和导出回执；绝不写回 QClaw | 本轮不安装、不升级、不卸载、不回滚；不能因底层类似 OpenClaw 就推定兼容 |
| OpenClaw | 可复用官方 inventory 思路做后续适配研究，但不属于首批安装闭环 | 本轮不作为自动安装验收对象；后续批次另行开放 | 后置 |
| Claude Code | 解析当前版本支持的 Skill／插件来源；只读发现先行 | 有稳定官方本地接口后开放 | 使用官方插件管理流程，不直接编辑未知结构 |
| Hermes／TRAE／Qoder | 仅在适配器能证明根目录及格式时扫描 | 首版人工安装 | 后置 |

QClaw 的“导出保存”固定为单向流程：`QClaw 有效 Skill 根 → 只读检查 → 用户选择 → 教育管家 staging → 安全检查与哈希 → 不可变存档 → 导出回执`。扫描和导出过程中不得修改 QClaw 配置、锁文件、插件目录、Gateway 状态或原 Skill 文件。

### 7.3 有界扫描

默认限制建议：

- 每个来源最多 2,000 个目录项。
- 单个候选最多 500 个文件。
- 单文件默认不超过 25 MiB。
- 单个 Skill 解包后默认不超过 50 MiB。
- 扫描深度由来源适配器指定，通用上限 8 层。
- 每批扫描支持取消；取消后保留已完成的只读结果，不进入自动存档。
- 大目录扫描放入 Worker 或独立受限子进程，避免阻塞 Electron 主进程。

阈值应作为版本化策略保存在设置中；首版不向普通用户开放任意放大。

## 8. 导入、下载与安全检查

### 8.1 支持来源

阶段一：

- 本地 Skill／插件目录。
- 本地 ZIP。
- HTTPS ZIP 地址。
- 从已安装 Agent 扫描结果存档。

阶段二：

- 固定 Git 仓库和 ref／commit。
- Codex 本地／团队插件市场来源。
- OpenClaw／ClawHub 官方搜索和版本来源。

不抓取网页 HTML 猜下载地址，不从聊天文本执行安装命令，不接受 `file://`、UNC 网络路径或未确认的局域网下载源作为首版网络导入。

### 8.2 网络下载约束

- 只允许 HTTPS。
- 限制重定向次数；每次重定向重新检查协议和目标。
- 阻止 loopback、链路本地、私网、云元数据地址和 DNS 解析后落入受限地址的目标。
- 使用总大小上限、连接超时和下载超时。
- 下载到 `staging`，不直接写入对象库或安装目录。
- 保存最终 URL、响应时间、内容长度、内容类型和 SHA-256。
- 用户提供预期哈希时必须匹配；不匹配直接隔离。

### 8.3 ZIP 与目录检查

检查至少包括：

1. 禁止绝对路径、盘符、`..`、空名称、NUL 和归一化后逃逸。
2. 禁止设备文件、命名管道和未经允许的符号链接／硬链接。
3. 限制条目数、单文件大小、总解压大小和异常压缩比。
4. Skill 包必须有且只有一个有效入口 `SKILL.md`；插件按其清单声明解析 Skills 根。
5. 校验清单引用均停留在包根目录内。
6. 识别脚本、可执行文件、DLL、PowerShell、批处理、Shell、安装清单、依赖锁文件、MCP 配置和 Hook。
7. 检测疑似私钥、访问令牌、`.env` 和凭据文件；命中时阻止进入活动对象库。
8. 不在检查阶段执行包内任何代码、安装依赖或加载动态模块。

### 8.4 YAML frontmatter

当前项目没有通用 YAML 解析依赖。实施前二选一并冻结：

- 推荐：引入体积可控、维护活跃且锁定版本的 YAML 解析库，禁用自定义标签和代码构造。
- 备选：首版仅实现 Agent Skills 必需字段的严格子集解析，并将复杂 YAML 标为“不支持”，不得写一个看似成功但会误解析嵌套字段的宽松解析器。

无论采用哪种方式，至少验证 `name`、`description`、编码、长度、名称规范及入口唯一性；未知扩展字段原样记录，不据此授予能力。

## 9. 自动标签设计

### 9.1 两级标签

**确定性标签**由主机代码生成：

- 类型：skill／plugin。
- 来源 Agent 与来源类型。
- 语言。
- 文件类型。
- 是否包含脚本、依赖、网络、MCP、Hook、二进制。
- 许可证状态。
- 兼容宿主。
- 风险等级。

**语义标签**由合格 Agent 生成候选：

- 教育／研究／文档／开发／媒体／自动化／知识库／办公。
- 更细用途，如 PDF、PPT、视频、浏览器自动化、服务器运维等。
- 建议关键词和一句话中文简介。

### 9.2 Agent 标签合同

新增内部任务档 `skill_catalog_tagging.v1`，但不新增 MCP：

- 输入只包含名称、简介、清单、标题列表、有限长度的 `SKILL.md` 正文摘要和确定性标签。
- 不向 Agent 提供包内脚本内容、凭据疑似内容、绝对路径或安装权限。
- 输出只能包含固定 taxonomy 的候选 ID、置信度和依据片段。
- 主机校验候选 ID、长度和来源后保存。
- 无合格 Agent、失败或结果不合法时，条目仍可存档和浏览，仅显示“语义标签待补充”。
- 用户修改标签后设置 `manualLocked: true`；后续扫描和新版导入不得覆盖用户标签，只能提示差异。

## 10. 本地安装事务

### 10.1 安装预览

用户点击安装后，主进程生成不可变安装计划，包含：

- 目标 Agent 和范围。
- 由适配器解析的目标路径或官方 CLI 行为。
- 当前安装版本与指纹。
- 将新增、替换、保留的文件摘要。
- 脚本、网络、MCP、Hook、二进制和依赖变化。
- 是否需要重启／新会话。
- 是否可回滚。
- `planHash` 和有效期限。

前端确认时只提交 `planId`、`planHash` 和用户确认，不重新提交路径或命令。

### 10.2 执行顺序

```text
读取当前宿主能力和目标指纹
→ 比对安装预览时的 beforeFingerprint
→ 创建同卷临时目录
→ 从不可变对象库复制并逐文件核对哈希
→ 运行宿主适配器的静态验证／官方 dry-run（如支持）
→ 备份现有受管目标
→ 原子替换或调用官方 CLI
→ 重新读取安装目标并计算 installedFingerprint
→ 写入安装记录和回执
→ 返回 restart_required／verification_pending
```

若目标在预览后变化、存档对象哈希不一致或 Agent 版本／安装接口发生变化，停止并要求重新预览。

### 10.3 回滚

- 只回滚教育管家持有有效安装回执和备份的操作。
- 未受教育管家管理的既有安装只允许“采用后管理”或人工处理，不能直接删除。
- 回滚前重新核对当前目标指纹；用户或 Agent 已修改内容时不覆盖，生成冲突报告。
- 回滚成功后保留被替换版本的存档和操作回执。
- 删除备份必须是独立操作，且不得删除当前唯一可恢复副本。

### 10.4 卸载

- 首版可只开放教育管家安装项的卸载。
- 通过官方 CLI 安装的插件优先使用官方卸载接口。
- 卸载不删除 Skill 存档。
- 卸载后验证目标清单消失或变为禁用；“命令退出码 0”不能单独视为卸载完成。

## 11. 宿主适配器合同

定义统一接口，但每项能力独立声明：

```text
detect()
listRoots()
inventory()
capabilities()
previewInstall(artifactVersion, scope)
install(plan)
verify(installation)
previewRollback(installation)
rollback(plan)
uninstall(installation)
```

`capabilities()` 至少返回：

- `canScan`
- `canInstallSkill`
- `canInstallPlugin`
- `canUpdate`
- `canRollback`
- `canUninstall`
- `canVerifyInventory`
- `requiresRestart`
- `supportedScopes`
- `reason`

不得因为 Agent 已安装或目录存在就把所有能力标记为可用。适配器需要绑定 Agent 版本、CLI 指纹或配置格式版本；发生变化后重新探测。

## 13. 存档路径迁移

自定义路径迁移必须单独实现事务：

1. 检查目标目录是否为空或是否为同一存档库。
2. 检查可用空间和文件系统可写性。
3. 冻结新的存档／安装操作，已有只读浏览可继续。
4. 复制对象、索引、回执和必要备份到目标临时目录。
5. 按 `treeSha256` 和账本逐项核对。
6. 原子提交目标库标记。
7. 更新 `userData` 中的活动根指针。
8. 保留旧库为可回滚状态，不自动删除。
9. 用户确认新库可用后，另行执行旧库清理。

移动盘离线、盘符变化或目录不可用时，回退为只读错误页并允许重新定位；不得自动新建空库覆盖原指针。

## 14. 状态机

### 14.1 资产状态

```text
discovered
→ inspecting
→ ready_to_archive | quarantined | unsupported
→ archived
→ changed_available
```

### 14.2 安装状态

```text
not_installed
→ preview_ready
→ installing
→ restart_required | verification_pending
→ verified

installing
→ failed_recoverable | failed_needs_attention

verified
→ update_available | rollback_available | uninstalling
```

未知结果不得自动重试覆盖。应用崩溃后根据 staging、目标指纹、备份和回执判断：

- 明确未提交：安全清理 staging。
- 明确提交且指纹匹配：补写回执并进入待验证。
- 目标与备份均存在但状态不明：等待用户选择检查／恢复。
- 目标已被其他程序修改：停止自动恢复。

## 15. 测试计划

### 15.1 单元测试

- Agent Skills 必需字段和复杂／无效 frontmatter。
- BOM、CRLF、大小写 `SKILL.md`、重复入口。
- 目录树哈希稳定性与单字节变化。
- 同名不同来源、同内容不同路径、同来源新版本。
- 标签 taxonomy、置信度、越界候选和 `manualLocked`。
- 状态机非法跳转。
- 设置、索引、回执原子写入和损坏恢复。

### 15.2 安全测试

- ZIP Slip、绝对路径、盘符、混合分隔符和 Unicode 路径混淆。
- 符号链接／junction 逃逸。
- 超大条目、超多条目、压缩炸弹和嵌套 ZIP。
- 可执行文件、DLL、PowerShell、批处理、Hook、MCP 和依赖安装识别。
- 私钥、`.env`、典型令牌格式和凭据文件名阻止。
- HTTPS 重定向到 HTTP、localhost、私网和元数据地址。
- 预览后目标变化、TOCTOU、并发安装和重复提交。
- 任意路径输入、renderer 篡改 targetPath、未登记 providerId。

### 15.3 适配器测试

使用隔离临时 HOME／CODEX_HOME／WorkBuddy 配置目录，不触碰真实用户配置：

- 未安装 Agent。
- Agent 已安装但 CLI 不支持 Skills。
- 空目录首次安装。
- 同名未受管 Skill 冲突。
- 教育管家已安装版本升级。
- 用户手工修改后的回滚拒绝。
- CLI 超时、退出非零、输出过大和进程中断。
- 安装成功但库存刷新失败，保持“待验证”。

### 15.4 UI 测试

- 1440px、800px、420px 三种视口。
- 一级／二级 tab、刷新返回和筛选状态。
- 存档路径不可用、扫描中取消、空库、隔离区和大列表分页。
- 安装预览的权限变化、确认和错误恢复。
- 无学生档案时页面仍可使用。
- 学生身份不显示或不能触发安装。
- 键盘导航、状态提示和无水平溢出。

### 15.5 真实宿主验收

Codex：

1. 在教育管家导入一个只含指令的合成 Skill。
2. 安装到真实 Codex 用户 Skill 位置或官方支持位置。
3. 重启／打开新会话。
4. 检查 Skill 是否出现在宿主可用列表。
5. 用明确请求触发一次，不读取真实学生数据。
6. 升级 Skill，确认旧版本可回滚。

WorkBuddy：

1. 核对当前真实 WorkBuddy 版本、运行时、配置根和实际支持的持久 Skill 加载接口。
2. 教育管家生成安装预览并通过受支持的官方接口或受管 Skill 根安装。
3. 重启 WorkBuddy 或打开新会话，确认目标 Skill 被宿主真实发现。
4. 用不接触学生资料的合成任务触发一次 Skill，保留宿主侧加载／调用证据。
5. 升级到第二个合成版本并回滚，确认不是会话临时目录或一次性环境变量造成的假加载。
6. 不支持持久安装、缺少依赖、目标冲突和策略阻止分别呈现；不能降级为“复制成功”后宣称闭环完成。

QClaw：

1. 只读列出当前配置真正可见的 Skill，排除 `node_modules`、缓存和无效副本。
2. 用户选择一个或多个 Skill 导出到教育管家存档。
3. 存档对象的来源、目录树哈希、文件数和版本回执完整。
4. 导出前后 QClaw 原目录和配置指纹不变。
5. 页面不提供“安装到 QClaw”“升级 QClaw Skill”“卸载”或“回滚”按钮。

插件验收必须与 Skill 分开：插件清单、MCP、Hook、认证、重启和真实加载分别核对。

## 16. 分阶段实施计划

闸门：schema 评审通过；夹具不含真实凭据或真实学生数据。

- 实现默认存档位置。

闸门：只读扫描不修改任何 Agent；恶意夹具全部被阻止；重复扫描不重复存档。

闸门：生产 React 组件和真实 IPC 通过桌面／窄屏测试；无 Agent 时仍可导入和浏览。

- 实现 WorkBuddy Skill 安装、升级、验证、卸载和回滚；禁止以会话临时 Skill 目录冒充持久安装。
- 实现并发指纹、计划哈希、备份和崩溃恢复。
- 完成真实新会话加载验收。

闸门：Codex、WorkBuddy 分别完成真实安装—加载—触发—升级—回滚闭环；合成测试不得修改真实配置。若当前 WorkBuddy 版本没有可验证的持久 Skill 加载接口，P3 保持未通过并形成厂商能力缺口，不能用目录复制替代。

### P4：下载、Git 与插件适配（约 6—10 个工程日）

任务：

- 实现安全 HTTPS ZIP 下载。
- 实现固定 Git ref／commit 导入。
- 接入官方市场来源元数据和版本固定。
- 实现 Codex、WorkBuddy 插件预览及官方安装机制，但只在各自稳定官方机制可验证时开放。
- OpenClaw Skill／插件作为第二批宿主另行适配和验收。
- QClaw 保持“只读扫描 + 导出存档”，本计划内不因能力探测结果扩大为安装支持。

闸门：插件与 Skill 状态完全分离；含 Hook／MCP／脚本的插件有独立风险确认和真实加载验证。

### P5：候选构建与设备验收（约 3—5 个工程日）

任务：

- 全量测试、Vite 生产构建、Electron 主进程语法检查。
- 检查 ASAR 内新增运行时和依赖可达性。
- 包体、敏感信息、许可证和依赖审计。
- Windows 目标机覆盖安装、旧库保留、自定义盘离线、Agent 新装后安装 Skill。
- 生成独立候选，不覆盖正式 manifest，不自动发布。

闸门：候选哈希、实际 Authenticode、真实设备结果和未完成项分别记录；自动测试通过不替代正式发布。

### 总体估算

单人连续开发约 28—43 个工程日。该估算包含源码、自动测试、QClaw 单向导出验证和 Codex／WorkBuddy 两类真实宿主验收，不包含厂商接口变化等待、正式代码签名、公开市场审核和 MCP 能力。

建议先交付 P0—P3，形成“可靠存档 + 浏览 + QClaw 扫描导出 + Codex/WorkBuddy Skill 安装”可用闭环；插件和更多宿主进入后续候选，避免第一版范围失控。

| UI-02 | 无学生场景 | 可扫描、存档和浏览；不要求选择学生 |
| PKG-01 | 候选包 | 模块可达、无真实凭据、哈希与签名状态真实记录 |

## 18. 发布与状态表述

实施和报告必须分别记录：

1. 源码已实现。
2. 单元／集成测试通过。
3. 生产 UI 构建通过。
4. 隔离宿主配置测试通过。
5. 真实 Codex／WorkBuddy 安装配置完成，QClaw 导出存档完成且原宿主未被修改。
6. 宿主重启或新会话已加载。
7. Skill 真实触发验证通过。
8. Windows 目标机候选验收通过。
9. 安装包签名状态。
10. 正式版本清单和公开发布状态。

只有第 6—7 项通过，才可描述为“目标 Agent 已能使用该 Skill”。文件复制、CLI 退出码 0、列表可见或教育管家显示“已安装”都不能单独替代真实加载和触发验证。

## 19. 主要风险与控制

| 风险 | 控制 |
|---|---|
| 将缓存／依赖误当成用户 Skill | 宿主适配器列根、来源分级、`node_modules` 默认排除、插件清单回溯 |
| 恶意 Skill 提示或脚本 | 存档不等于启用；静态检查、风险摘要、安装确认、首次只支持纯指令优先 |
| 插件带 MCP／Hook 扩权 | 单独类型、单独确认、官方安装适配器、真实权限变化预览 |
| 下载供应链变化 | 固定版本／ref、保存来源和哈希、不可变对象库 |
| 覆盖用户手工修改 | beforeFingerprint、计划哈希、并发拒绝、只管理有回执的安装 |
| 自定义盘离线或损坏 | 指针与库分离、只读错误、重新定位、旧库保留 |
| 扫描拖慢主界面 | Worker、有界目录、取消、增量指纹和空闲调度 |
| Agent 标签误判 | 固定 taxonomy、主机校验、依据片段、人工锁定 |
| 厂商格式变化 | 适配器绑定版本／CLI 指纹，变化后降级为只读或人工安装 |
| 把候选当正式发布 | 独立候选、哈希、Authenticode、真机和真实宿主验收分别记录 |

## 20. 开发开始前检查

1. 重新检查当前 Git 工作树及相关文件的已有未提交改动，避免覆盖其他开发线。
2. 冻结 P0 schema 和首批支持矩阵，不在 P1 临时扩大宿主范围。
3. 确认 Codex、WorkBuddy 当前实际版本及持久本地 Skill 安装行为；WorkBuddy 会话临时 Skill 目录不能作为完成依据。
4. 确认 QClaw 当前实际可见 Skill 根和导出范围，不开启任何写回适配器。
5. 为真实验收准备不接触学生资料的合成 Skill。
6. 确认候选构建目录、版本号策略和签名环境；未签名候选不得称正式发布。
7. 本文评审通过后再开始产品代码开发。

## 21. 参考的当前官方格式边界

- OpenAI Skills：Skill 为包含 `SKILL.md` 及可选 scripts／references／assets 的目录；安装或提供给运行环境前应检查内容和安全风险。  
  https://developers.openai.com/api/docs/guides/tools-skills
- OpenAI Plugins：插件可组合 Skills、MCP、Hook 和资源；本地插件市场与缓存是不同概念。  
  https://developers.openai.com/plugins/build/plugins
- OpenClaw Skills：仅作为开放 Skill 格式、受控 roots 和安全检查的参考，不代表本轮为 OpenClaw 或 QClaw 提供安装支持。  
  https://docs.openclaw.ai/skills
- Anthropic Agent Skills：`SKILL.md` 至少包含 name 和 description，Skill 指令和代码具有安全风险。  
  https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview
