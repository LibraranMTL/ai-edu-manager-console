# Windows 0.19.10 快速截屏候选验收

日期：2026-10-08。Windows versionCode：250。状态：本地候选，待用户真机测试。

## 使用路径

打开程序并选择学生，使用已有“显示／定位快捷采集工具条”入口。点击工具条“屏幕采集”，首次默认“快速截屏”，可切换“连续采集”。

1. 选择屏幕或应用窗口，选择学生资料收件箱或关联项目。
2. 点击“立即截取”。工具条和拍照窗短暂隐藏后恢复，直接在浮条显示预览。
3. 点击“重新截取”更新预览，或“重新选源”返回来源列表。
4. 点击“确认保存”才登记 PNG 原件；预览前不写入文件。保存失败保留同一预览用于重试，重复提交只登记一份。
5. “查看收件箱”直接进入当前学生“资料收件箱 → 分享资料”并刷新列表。记录标为“快速截屏”；关联项目显示为投递提示，可点击“选中并使用此投递目标”，再通过原有“投递选中资料”完成投递。

切换学生、收起设置或隐藏工具条清除未保存预览。截图属于当次选定学生，界面传入其他学生 ID、截图字节或目标 ID 不会改变已锁定原件。关闭程序前须确认保存；内存预览不提供重启恢复。保存后的原件复用受控收件账本，可按原有流程投递和回收。

连续采集保留原采集时长、策略、暂停／继续、重点截取和结束控制。快速截屏不启动连续采集或自动分析任务；截屏保存本身不形成已确认成长证据。区域框选、裁剪、标注与快捷键留待后续；录音沿用原页面。

## 实现边界

- 复用 `quick-capture-direct.cjs` 的学生上下文令牌，增加内存截图及确认保存；主进程保留 PNG，渲染进程只得到预览及提交 ID，不能替换保存字节。
- 原生 `desktopCapturer` 重新读取所选来源，检查关闭／不可用／受限窗口。单次图片最长边采集请求为 4096px，单项受控原件上限 20 MiB；高于采集请求的源画面可能缩放。
- 截取前后复核学生及项目，取消、切换、重截使旧预览不能提交；重复保存复用提交编号和原件哈希。
- 原有 `capture-inbox.cjs` 增加 `screen` 来源，复用目录、受控对象、哈希、重试和回收合同。关联项目作为提示，投递仍重新校验实际目标。
- 从浮条查看收件记录会直接打开分享资料，并通过新请求刷新该学生列表；普通下载收件流程仍可由页内切换访问。
