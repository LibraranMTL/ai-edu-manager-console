# R21 统一知识连接器与 WorkBuddy 兼容修复（r10）

日期：2026-10-15。状态：代码、自动化回归、包内隔离联调、真实 WorkBuddy 联网复验和候选构建完成；不是签名正式发布。现有用户宿主配置未被本轮测试改写，需要用户在新包点击原位升级并重启宿主完成最终验收。

## 本轮合并结论

接入用户粘贴的《Agent连接器是否必须这样设置》讨论，不再把“全部学生”理解为仅扩大可绑定名单。首期允许一个会话跨学生查询和向明确学生分别写入，默认仍是单学生会话。

1. `edu-manager-knowledge` 原位升级，服务名不变；保留 12 个旧工具名兼容入口。新旧名称都走 R21 同一鉴权和业务链，不复制业务资料库。旧参数缺会话信息时拒绝，不回退共享活动学生。
2. Codex、WorkBuddy 独立连接凭据。升级前备份已有配置，保留其他 MCP；配置异常时停止，不覆盖未知结构。已存在并列 R21 服务时拒绝继续，提示消除重复。
3. 设置页直接显示单学生／全授权学生会话两种模式、新学生继承选项及原位升级按钮。凭据生成不等于已安装，配置更新不等于宿主重启后的真实验证。
4. 全学生目录只含 ID/姓名；批量只读查询最多 50 名学生，逐学生校验并分组保留来源。每项写入强制唯一 targetStudentId，复用受管资料保存、草稿、项目范围、幂等台账与回执。
5. 每次调用检查授权、排除、停用、撤销、到期与权限降级。改变会话模式增加 contextRevision。全学生写入幂等键加入学生 ID，旧单学生幂等键和会话记忆标识保持原算法，避免升级后重复保存。
6. 升级后对应宿主的旧活动学生生命周期归档停止，防止继续按旧描述符串档。全学生完整对话／会话记忆暂拒绝；明确属于学生的成果可经资料保存工具写入。

## WorkBuddy 修复

仅兼容根级 `sources_note` 为不超过 4000 字符的文本时移除该附加说明。其他未知字段、对象／数组／超长 sources_note、嵌套未知字段和缺少必填字段仍拒绝。说明文字不构成搜索、来源或授权证据。

保留匹配 WebSearch 调用与结果回执、工具白名单、真实 HTTPS 来源抓取、公开 DNS 校验、重定向复核、响应大小上限、取消和超时保护。未通过联网合同不因连接验证成功而放行。

## 原位升级操作

1. 退出旧版教育管家，启动本轮候选（本次开发不会强行关闭用户实例）。
2. 系统设置 → Agent 调用能力 → Agent 连接管理 → 外部 Agent 连接器，选择档位与学生访问范围并保存。
3. 分别点击“原位升级 Codex”“原位升级 WorkBuddy”。只有显式确认才更新对应宿主配置；不会因安装软件被检测到而扩大旧授权。
4. 重启相应 Agent，刷新工具列表。调用 education_open_session；按需要使用 list_authorized_students、education_query_students 或单学生绑定。
5. 全学生会话每项写入提供 targetStudentId；查看分学生回执，不将已保存冒充已消化或已检索命中。

运行脚本保留 PowerShell 入口，增加 ConnectorConfig 指向各宿主独立连接文件，实际执行统一 Node 桥。连接文件持有凭据文件引用；主机启动刷新便携 EXE 路径和本机端口。桥接失败不得回退旧固定学生。PowerShell 与子进程采用逐行并发、逐条刷新 stdin/stdout，防止真实 MCP 长连接初始化等待 EOF。
