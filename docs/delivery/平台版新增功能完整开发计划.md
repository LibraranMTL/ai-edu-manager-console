# AI教育管家平台版新增功能完整开发计划

> 制定日期：2026-08-02
> 当前基线：Windows 主机端 `0.15.6`、授权管理工具 `0.2.0` 受控候选
> 当前收口目标：Windows 主机端 `0.15.8-platform-simple-v1` 受控候选
> 产品原则：不增加独立平台客户端，不增加新的网络端口；继续使用同一 Windows 主机安装包，由签名 License 决定版本、身份和能力。
> 发布边界：完成生产密钥初始化、可信公钥部署、真机升级与发布回滚验收前，不表述为平台版正式发布。

## 2026-08-02 简化决策（覆盖后文旧设计）

- 平台版不再设置 `PLATFORM_EDITOR / PLATFORM_PUBLISHER / PLATFORM_ADMIN` 身份。有效平台版 License 直接获得平台课程编辑、发布和恢复能力。
- 授权管理工具签发平台版时不显示或写入平台身份字段；历史测试阶段带角色的平台 License 仅作兼容解析，并统一折算为平台版权限。
- 专业版、机构版和平台版接收主机不再导入课程验证公钥包，也不显示相关入口。官方验证公钥随 Windows 主机安装包内置，导入平台课程包时自动验签。
- 课程目录私钥仍只存在于指定发布主机。首次点击“配置平台发布主机”导入与内置公钥匹配的官方凭据，此后直接“发布平台课程”。
- 课程签名与验签机制继续保留，用于防止课程包损坏或被本地篡改；简化的是用户操作和角色模型，不是取消完整性校验。
- 课程密钥轮换通过新版安装包更新验证公钥，不要求接收用户逐台执行密钥操作。

## 执行状态（2026-08-02）

- P0：代码门禁已实现，包括两类独立密钥用途、RSA 3072 初始化、动态工具版本、源码/暂存运行时/ASAR/EXE 秘密特征扫描。实际生产密钥创建、公钥入正式安装包、加密 U 盘双副本和基础目录生产重签仍属于受控密钥仪式，未在源码工作区代替执行。
- P1：已实现授权工具和主机图形化密钥管理、公钥信任包、License 文件导入、多 `keyId`、稳定主机 ID 绑定、原子升级失败保留旧 License。
- P2：已实现课程密钥签名挑战、变更摘要与确认码、按 `keyId` 验签、签名包立即回验、最后可用目录保护、撤回和二次确认回滚。
- P3：已实现密码加密备份、恢复演练、当前密钥切换、私钥撤销、历史公钥验证及许可证/发布/回滚/密钥审计。BitLocker To Go 实际介质双副本和独立年度演练仍需运维执行。
- P4：代码、测试、文档、网站和受控候选构建按 0.15.8 简化方案收口。Authenticode、机构版升级平台版、多 Windows 主机和 Android 学生端真机验收仍是正式发布前门禁。

## 一、计划目标

1. 在同一个 Windows 主机端中增加平台版能力，同时保持家庭版、专业版、机构版现有功能与激活码兼容。
2. 允许机构版主机通过重新激活平台版 License v2 原地升级，不重装、不迁移、不删除学生、项目、知识库、课程和设备数据。
3. 建立平台课程“草稿—版权校验—签名发布—离线导入—撤回/回滚—审计”的完整闭环。
4. 将平台 License 签名和课程目录签名分为两套独立密钥体系，避免一种密钥泄露同时影响授权与课程供应链。
5. 取消普通操作者手工设置环境变量的体验，把密钥操作收敛为受控终端首次初始化、状态检查、备份和恢复流程。
6. 专业版、机构版只管理机构自选课程，不持有课程目录私钥，也不能修改或伪造平台签名课程。
7. 保持学生端只读和按当前学生过滤，不向学生端下发平台草稿、其他学生策略、私钥路径或平台权限信息。

## 二、明确不做

- 不新建平台版独立安装包、独立后台或新端口。
- 不把平台 License 私钥或课程目录私钥写入源码、安装包、Git、日志、License、课程包或同步目录。
- 不把课程目录私钥发给专业版、机构版或普通平台编辑人员。
- 不允许旧版 `AIE-...` 激活码通过文本修改获得平台版权限。
- 不允许平台草稿未经版权确认和完整性校验直接进入学生有效课程目录。
- 不在本阶段建设云端课程商城、收费、排课、学习进度接口或完整多租户 SaaS 后台。
- 不把“打开第三方课程网页”表述为课程完成率、正确率或学习效果。

| 课程类型 | 维护者 | 是否需要课程目录私钥 | 传播范围 |

## 五、两套密钥与信任链

### 5.1 平台 License 密钥对

```text
私钥：只在内部授权管理终端签发 AIE2 License
公钥：内置或受控导入 Windows 主机
建议 keyId：license-platform-2026-01
用途：证明该终端获得的平台版本、角色和能力
```

### 5.2 课程目录密钥对

```text
私钥：只在指定的平台课程发布终端签发 .edu-coursepkg
公钥：内置 Windows 主机，用于回验和离线导入
建议 keyId：course-catalog-2026-01
用途：证明课程目录、链接、图片、版权声明和版本来自平台且未被修改
```

### 5.3 强制规则

- 两套私钥不得复用，也不得使用网站 TLS、Authenticode 或其他业务私钥。
- License 只授予“可以调用发布流程”的权限，不携带课程目录私钥。
- 专业版、机构版和普通平台编辑终端只接收公钥，不持有课程目录私钥。
- 私钥运行副本保存在受控本地目录、Windows 证书库或后续硬件密钥设备中；不得长期从 U 盘直接运行。
- 私钥备份只能进入 BitLocker To Go 或等效加密的离线介质；恢复密码与介质分开保存。
- 两类私钥优先使用不同 U 盘备份，至少保留两份加密恢复副本并分开放置。
- 备份应同时保存对应公钥、`keyId`、指纹、用途、创建日期、状态和最近恢复验证日期。

## 六、平台版完整业务流程

### 6.1 机构版原地升级平台版

1. 授权管理终端使用平台 License 私钥签发 `AIE2...` 平台许可证。
2. 待升级主机先安装包含对应可信公钥的受控版本。
3. 在“系统设置 → 许可证授权”直接输入或导入平台 License，不需要先移除机构版许可证。
4. 主机完整验证签名、`keyId`、最高版本、有效期、设备策略、角色和能力。
5. 仅在验证全部通过后原子替换 `settings.license`；失败时继续保留机构版许可证。
6. 学生、项目、知识库、设备、机构课程和课程策略全部保留。
7. 激活成功后立即刷新菜单；必要时提示重启，不执行数据迁移。
8. 记录升级前后许可证摘要和结果，不记录完整激活码或私钥。

### 6.2 平台课程编辑

1. 平台编辑人员进入“精选课程 → 课程管理 → 平台课程发布”。
2. 新建课程或从已发布课程创建草稿。
3. 填写名称、提供方、简介、HTTPS 链接、精确域名、图片、适用范围、账号要求和法律说明。
4. 填写版权状态、证据引用、审核人和审核时间。
5. 保存草稿并在受限 `WebContentsView` 中预览；保存草稿不影响学生端。
6. 权利状态不是“已确认”时允许继续编辑，但禁止发布。

### 6.3 平台课程发布

1. 发布人员查看变更摘要并填写发布说明。
2. 主进程再次检查 License 签名、有效期和 `platform_course_publish`。
3. 检查发布机课程目录私钥状态及其公钥指纹是否与安装包一致。
4. 校验全部草稿、版权信息、HTTPS 域名、图片格式/大小、课程 ID 和目录版本。
5. 生成 `.edu-coursepkg`，签名覆盖清单、目录和全部资源哈希。
6. 使用安装包内置公钥立即回验刚生成的包。
7. 回验通过后记录发布审计，并可在当前主机应用；失败时继续使用最后可用目录。
8. 其他主机只需公钥即可离线导入，不需要任何私钥。

### 6.4 撤回和回滚

- 撤回通过一个更高版本把课程标记为 `withdrawn`，不删除历史版本。
- 普通导入禁止低版本覆盖。
- 回滚必须携带明确回滚意图，并由具有 `platform_course_rollback` 的有效 License 执行。
- 回滚仍生成新的审计记录和发布包哈希。
- 当前正在打开的课程被撤回后立即关闭受限课程视图。

## 七、新增与调整功能清单

### 7.1 授权管理工具

- 新增“平台密钥管理”页面。
- 提供“使用已有密钥”和“创建新密钥对”两个受控入口。
- 生成新密钥时默认 RSA 3072 位、PKCS#8 私钥、SPKI 公钥，并自动生成唯一 `keyId`。
- 显示密钥用途、`keyId`、公钥指纹、创建时间和当前状态，不显示私钥正文。
- 私钥选择后在主进程校验格式、公私钥匹配和用途；渲染层不获得私钥内容。
- 支持导出“可信 License 发行方公钥包”，供主机安装包或受控导入流程使用。
- 平台版签发前明确显示角色及能力摘要。
- 支持长 License v2 文件导出与导入，避免完全依赖剪贴板粘贴超长 `AIE2...` 文本。
- 应用版本从 `package.json` 动态读取。
- 发码记录增加 License ID、`keyId`、角色、设备策略和公钥指纹；不记录私钥。

### 7.2 Windows 主机许可证

- 增加可信发行方公钥包的受控导入和校验，不要求普通用户输入 JSON 环境变量。
- 新公钥导入必须经过现有可信链或本机管理员确认，不能由普通课程包偷偷增加信任。
- 支持新旧多个 `keyId` 并存，满足无中断密钥轮换。
- 激活成功前保留原许可证；失败不得覆盖机构版状态。
- 平台版激活时显示版本、角色、期限、设备数、学生数和公钥指纹摘要。
- 完成稳定主机设备 ID 绑定、换机、解绑和重新签发流程。
- 平台降级为机构版时只收回平台能力，不删除平台历史包、机构课程或业务数据。

### 7.3 平台发布机初始化

- 在“平台课程发布”区域增加“初始化发布机”。
- 可选择已有课程目录私钥，或由受控流程创建新的独立课程密钥对。
- 选择私钥时必须与安装包内置公钥做签名挑战验证，禁止仅检查文件扩展名。
- 保存的只能是受控密钥引用或安全存储句柄，不在普通设置中保存私钥正文。
- 初始化完成后显示“密钥已配置、`keyId`、公钥指纹、最近验证时间”。
- 发布时发现 U 盘路径、网络路径、同步目录或公钥不匹配时应阻止操作并给出中文处理建议。
- 保留环境变量方式作为内部应急兼容入口，但不再作为正常用户流程。

### 7.4 密钥备份、恢复和轮换

- 提供不导出私钥正文到界面的“创建加密备份”说明或向导。
- 备份介质必须加密；恢复密码和介质分离。
- 恢复后执行一次签名挑战，不产生正式 License 或正式课程版本。
- 每年至少执行一次恢复演练，并记录结果。
- 支持新旧两个公钥过渡期：新签发/发布只用新私钥，主机暂时同时信任新旧公钥。
- 旧 License 换发或旧课程目录完成迁移后再撤销旧公钥。
- 密钥疑似泄露时立即停止签发、生成新密钥对、发布新信任包并记录安全事件。

### 7.5 课程管理体验

- 保持“精选课程 → 课程学习 / 课程管理”导航不变。
- 平台编辑仅看到草稿、预览和校验；发布/管理员额外看到签名发布和回滚。
- 明确区分“机构自选课程”和“平台官方课程”，避免机构用户误以为需要私钥。
- 发布按钮旁显示阻塞原因：License 身份、版权未确认、字段校验、签名密钥未初始化或版本冲突。
- 所有错误提供下一步操作，不直接暴露环境变量或底层堆栈。

## 八、实施阶段与优先级

### P0：生产信任基础，阻塞平台发布

收口目标：`0.15.8-platform-simple-v1`；该候选覆盖统一平台权限、接收端内置公钥自动验签和课程顶部待开始采集条。

- 确认尚未正式发放平台版 License 和课程签名包。
- 新建独立的平台 License 密钥对和课程目录密钥对。
- 私钥进入受控终端和加密离线备份，公钥及指纹进入交付清单。
- 用新课程公钥替换现有候选公钥，重新签署内置基础目录。
- 主机端加入平台 License 可信发行方公钥及最高版本限制。
- 完成源码、ASAR、安装包和日志的私钥特征扫描。
- 修复授权工具动态版本号。

### P1：密钥初始化与授权升级体验

预计 3—4 个净开发日。

- 授权工具新增密钥状态、选择/创建、匹配校验和可信公钥包导出。
- 主机增加可信 License 公钥包导入与多 `keyId` 支持。
- 平台发布机初始化取代正常流程中的环境变量手工配置。
- 增加平台 License 文件导入。
- 完成机构版 → 平台版原子升级和失败保留原许可证。
- 完成设备绑定、换机和重新签发规则。

### P2：课程发布与供应链加固

预计 2—3 个净开发日。

- 私钥与内置公钥签名挑战校验。
- 发布前变更摘要、版权确认和二次确认。
- `.edu-coursepkg` 发布、立即回验、离线导入、撤回和显式回滚真机闭环。
- 签名密钥未初始化、公钥不匹配、路径不安全和包被篡改的可操作错误提示。
- 保证导入失败继续使用最后可用目录。

### P3：备份、恢复、轮换和审计

预计 2—3 个净开发日。

- 编写两套密钥的备份/恢复清单和操作向导。
- 验证 BitLocker To Go 离线备份、第二副本和恢复演练。
- 实现新旧公钥并存、轮换、撤销和泄露处置记录。
- 补齐许可证升级、课程发布、回滚和密钥操作审计。

### P4：交付与发布门禁

预计 2 个净开发日，另需独立真机验收时间。

- 更新主机操作手册、授权工具说明、网站、版本日志和故障排查。
- 全量自动测试、生产构建、ASAR/资源审计和私钥扫描。
- 机构版升级平台版、平台发布、专业/机构隔离、Windows/Android 学生读取真机验证。
- 生成 Windows 受控候选包和哈希清单。
- Authenticode 完成前继续标记为受控候选；通过代码签名和全部真机门禁后再评估正式发布。

合计建议投入：11—15 个净开发日，加 2—3 个真机验收日。P0、P1 是上线阻塞项；P2 完成后才具备可信课程发布；P3、P4 完成后才具备可维护的生产运营条件。

## 九、测试与验收矩阵

### 9.1 旧版本兼容

- 家庭版、专业版、机构版旧 `AIE-...` 激活码继续有效。
- 新增平台公钥不改变旧许可证解析和业务数据。
- v1 伪造平台版被拒绝。
- 机构版重新输入有效旧激活码可降级，平台能力立即收回，数据保持不变。

### 9.2 License v2

- 正确签名、篡改、过期、未知 `keyId`、发行方版本上限和设备不匹配测试。
- 平台 License 私钥与课程目录私钥交叉使用必须失败。
- 激活失败时继续保留原机构版许可证。
- 重新启动和许可证周期复核后平台能力保持正确。

### 9.3 权限隔离

- 专业版、机构版能管理 `tenant_custom`，不能读取平台草稿或调用平台发布 IPC。
- 平台编辑不能发布或回滚。
- 平台发布和管理员才能使用课程目录私钥。
- 学生端只接收当前学生有效已发布目录。

### 9.4 课程签名包

- 任意修改目录、图片、清单或签名均导入失败。
- ZIP 路径穿越、重复条目、未知类型、超限文件和低版本覆盖被拒绝。
- 正常发布、撤回、显式回滚和最后可用版本保护通过。
- 私钥不进入 `.edu-coursepkg`、安装包、日志和导出记录。

### 9.5 密钥运维

- 加密 U 盘备份可恢复，错误密码、错误私钥和错误公钥被拒绝。
- 恢复演练不会生成正式许可证或正式课程版本。
- 新旧公钥过渡期均可验证对应历史产物；撤销后旧密钥不能签发新产物。
- U 盘丢失、私钥疑似泄露和发布终端损坏均有明确处置流程。

### 9.6 真机门禁

- 机构版原地升级平台版并保留全部学生、项目、课程和设备数据。
- 平台课程发布后在 Windows 主机、Windows 学生端和 Android 学生端按学生策略正常显示和打开。
- 发布失败、断电、重复导入、离线和回滚情况下仍保留最后可用目录。
- 平台菜单、角色提示、密钥状态和错误操作在窄窗口及常用 Windows 缩放比例下可用。

## 十、完成定义

同时满足以下条件才视为平台版开发完成：

1. 同一 Windows 安装包能依据有效 License 显示家庭、专业、机构和平台能力。
2. 机构版可原地升级平台版，失败不覆盖旧许可证，升级不迁移或删除业务数据。
3. 两套生产密钥独立生成、受控部署、加密备份并通过恢复演练。
4. 授权和课程发布正常流程不再要求操作者手工设置环境变量。
5. 平台编辑、发布、管理员权限在界面和主进程均严格隔离。
6. 专业版、机构版不持有课程目录私钥，仍可正常管理机构自选课程。
7. 平台课程草稿、已发布目录和最后可用目录相互隔离。
8. `.edu-coursepkg` 生成、回验、导入、撤回和显式回滚通过自动测试和真机验证。
9. 学生端继续严格按当前学生和有效课程策略过滤，且不暴露平台草稿或权限信息。
10. 私钥扫描、完整测试、构建审计、文档同步和 Windows 真机门禁全部通过。
11. Windows Authenticode 未完成时仍明确标为受控候选，不作为公开稳定版发布。
