# 学情报告云端本地试点

此目录是尚未公开发布的单实例试点服务。默认只监听 `127.0.0.1:8755`，不读取现有真实学生档案，也不替代 Windows / Android 本机文件。云端数据保存在操作者指定的独立目录；报告和文档对象不公开。

## 0.22.2 候选合同（优先于下方历史试点说明）

- 来源端首次开通使用受信任产品许可和本机设备证明调用 `/v2/source-auto-enroll`，服务端自动创建或稳定匹配云端学生；不要求管理员预建学生，也不要求生成或输入开通码。管理页的旧学生创建与开通码功能只为 `/v1` 兼容保留，不是新版正常流程。
- C0-C2 覆盖基础信息修订、五类教育资料、接收主机配对/自动建档、显式下载与正式导入。健康资料使用独立的对象级读写许可，不从普通资料许可继承。
- C3 提供只读远程 MCP、独立设备连接、撤销、受保护资源发现以及授权码加 S256 PKCE；C4 仅索引当前修订，PDF/DOCX 在 Worker 中异步提取，扫描件 OCR 通过显式配置的隔离适配器执行。
- C5 成果收件箱采用“提交、租约领取、正文及附件校验落盘、本机收件箱、处理回执”流程；附件仅允许 Markdown、PDF、DOCX，单个不超过 512 KiB、合计不超过 2 MiB。
- 这是候选实现。公网 HTTPS 部署、生产 OAuth 配置、两个真实异地 Agent 宿主验收和正式容量治理仍属于发布验收，不应由源码测试替代。

## 本机启动

需要 Node.js 24（当前使用 Node 内置 SQLite，API 仍带实验提示）和仓库现有的 pnpm 依赖。先执行 `pnpm build:cloud-web`，再在同一个 PowerShell 会话中设置：

```powershell
$env:CLOUD_REPORT_DATA_DIR = Join-Path $env:LOCALAPPDATA 'AI教育管家\cloud-report-trial'
$env:CLOUD_REPORT_ADMIN_TOKEN = '<至少24字符的私密随机管理凭据>'
node cloud-report-service/http.cjs
```

然后打开 `http://127.0.0.1:8755/`。管理凭据仅用于本地管理页，不填进 Android 或 Windows 客户端。管理页登录后仅在页面内存中持有 8 小时会话，刷新页面须重新登录，退出会在服务端撤销会话；长期管理凭据不写入浏览器存储。登录每来源地址每分钟最多尝试 5 次，反向代理应限制来源地址且不能依赖客户端伪造的转发头。长期凭据仍可作为本地维护 API 的 Bearer 使用，不代表已有多管理员身份体系。不要把凭据写入仓库、截图或聊天记录。管理页可浏览学生、报告、其他文档和设备授权，也保留 `/v1` 试点的手工建档与一次性开通码入口；0.22.2 的来源端正常开通不使用这些入口。报告与其他文档共用一次下载许可，后续无需逐份开通。下载许可默认一年，期限内可随时撤销，到期后同一主机重新配对续期；撤销或到期只阻止新的云端读取，不会远程删除接收端已下载的缓存。Windows 主机用本机加密保存的 P-256 私钥逐请求签名；单独泄漏设备令牌不足以下载，旧的无私钥试点配对需重新办理。

试点默认每名云端学生保留最多 256 MiB 的报告修订与其他文档逻辑字节数，回收站仍计入；满额时拒绝新的报告或文档，不自动删除旧数据，重复提交相同报告不增加用量。启动前可用 `CLOUD_REPORT_MAX_STUDENT_BYTES` 设置正整数覆盖默认值；管理员可读 `GET /v1/students/<cloudStudentId>/storage` 查看用量。此上限是本地试点保护值，正式容量/保存期限仍须确认。

## 本地多设备试点边界

`localhost` 仅适合同一台开发机上的接口联调。Android 真机与另一台 Windows 要访问该服务，需先配置可信的局域网 HTTPS 入口、证书和访问控制；Android 应用默认不信任任意用户自签 CA，必须在目标真机验证完整信任链，或使用受系统信任的证书和域名。服务仍仅绑定 `127.0.0.1`，由 HTTPS 反向代理转发；不能把 HTTP 服务直接暴露到局域网或互联网，也不能绕过证书校验。未完成该入口与真机验收前，不上传真实学生报告。关闭服务不会删除数据。

局域网联调前置条件：确定独立的测试域名和受两端系统信任的证书（优先使用受信任域名证书，经 DNS 验证签发）；将该域名在测试局域网解析到试点主机；反向代理仅在局域网开放 HTTPS，后端继续监听回环地址；限制防火墙来源，并分别在 Android 应用和两台 Windows 主机上验证严格证书校验下的 `/health`。若改用自建测试 CA，须先限定为专用调试包并证明 Android 应用确实信任该 CA，不能将忽略证书错误作为替代方案。完成后仅用去标识报告按“Android 上传 → 第一台 Windows 下载 → 另一台 Windows 上传 → 第一台 Windows 再下载”验收；没有设备连接与证书信任证据，不将接口模拟称为真机通过。

## 手动备份与恢复校验

可在试点服务运行期间生成一致的 SQLite 快照，逐一校验报告与文档对象哈希。备份目录必须是新的独立目录；恢复只写入一个**不存在**的新数据目录，不覆盖正在运行的试点数据。PowerShell 示例：

```powershell
$trialDir = Join-Path $env:LOCALAPPDATA 'AI教育管家\cloud-report-trial'
$snapshotDir = Join-Path $env:LOCALAPPDATA 'AI教育管家\cloud-report-backups\snapshot-20260925-01'
node cloud-report-service/backup.cjs backup $trialDir $snapshotDir
node cloud-report-service/backup.cjs verify $snapshotDir
node cloud-report-service/backup.cjs restore $snapshotDir (Join-Path $env:LOCALAPPDATA 'AI教育管家\cloud-report-restore-check')
```

如需本地自动快照，在启动服务前设置独立于数据目录的**绝对路径** `CLOUD_REPORT_BACKUP_ROOT`；服务启动时先创建并校验一个快照，此后默认每 24 小时再建新快照。可用 `CLOUD_REPORT_BACKUP_INTERVAL_HOURS` 设置 1 分钟至 30 天范围内的小时数。服务不会覆盖已有快照，日志会显示成功路径或失败原因；停止服务时等待进行中的备份结束。备份根目录不得与数据目录相同或相互包含。当前**不会自动删除旧快照**，操作者须监控磁盘空间并另行确定保留策略。备份包含学生索引与私有文档正文，须按敏感数据保护。此工具仍不负责加密、异地保存、独立审计或在线恢复切换；恢复出的目录需单独验证后再决定是否用于服务。

管理员可在选定学生的“操作记录”查看许可、上传、下载和文档变更；只读接口为 `GET /v1/audit-events?studentId=<cloudStudentId>&cursor=<id>`，每页最多 100 条。记录仅存时间、操作类别及内部对象/设备标识，不保存凭据、配对码或文档正文。它是单实例试点的数据库操作日志，尚不具备防篡改、拒绝事件覆盖或独立保留策略。来源端“关闭自动上传”仅修改本机学生的上传开关；管理员撤销的是许可，来源端不能通过重新开启开关自行恢复。

## 2026-09-26 安全与维护更新（优先于上文历史试点说明）

- 管理员改为数据库内的单一身份，凭据加盐派生保存。启动变量只在首次建立身份时使用，不再是维护 API 的 Bearer；后续启动仍须提供变量，但不会覆盖已更换的凭据。管理页可更换凭据并立即撤销全部会话。尚无多管理员账号体系。
- Android 和 Windows 来源端均须 P-256 逐请求签名，签名覆盖请求方法、路径、时间、随机数及正文 SHA-256；仅有令牌无法上传。旧试点来源端需管理员签发新开通码重新开通。管理页支持撤销来源设备的全部许可；来源令牌轮换接口为 `POST /v1/devices/credential`，须使用旧来源私钥签名，正文为新的随机 `nextToken`。常规用户无需处理此接口。
- 报告详情可撤回云端修订：列表隐藏、读取及同设备重复上传返回 410，离线重试不会恢复该修订。原件和已经下载的缓存不远程删除；撤回内容仍占容量，不自动物理清除。
- 其他文档分页每页最多 100 条；PDF 经许可读取后在页面只读预览。20 MiB 上传以流式临时文件接收，完成时再次验证会话/许可、类型、容量和哈希，失败清理临时对象。下载仍按单文档读取，不宣称无限容量流式服务。
- Windows 缓存成功上传哈希，无变化不再次上传；离线更新有界退避，许可失败停止自动重试。Android 延用唯一后台任务与整组快照校验，SAF/休眠/重启行为仍需真机验证。
- 管理页“服务器备份与存储状态”可查看磁盘空间、最近备份成功和失败状态。默认磁盘告警阈值 512 MiB。
- 自动备份保留默认关闭。设置 `CLOUD_REPORT_PRUNE_BACKUPS=1` 才启用清理；默认至少保留最新 7 份，并且仅删除其余超过 30 天且通过完整校验的自动快照，可用 `CLOUD_REPORT_BACKUP_KEEP`、`CLOUD_REPORT_BACKUP_DAYS` 调整。手工 `node cloud-report-service/maintenance.cjs retention <备份绝对目录>` 仅预览，加 `--apply` 才实际删除；损坏快照阻止清理，不删除源数据。
- 设置独立的 `CLOUD_REPORT_AUDIT_ROOT` 和至少 32 字符的 `CLOUD_REPORT_AUDIT_KEY` 后，每次定时备份成功会另存 HMAC 完整性校验的审计归档。可用 `maintenance.cjs audit-verify <归档绝对路径> [数据绝对目录]` 校验归档及已归档的数据库历史。审计密钥不得放进源码/备份。数据库之外的目录不等于异地或不可变存储：磁盘加密、独立访问控制、异地及保留锁仍是部署事项。401/403 拒绝也有不含凭据的记录；429 覆盖不作完整安全事件平台承诺。
- 恢复到新目录时保留报告和审计，但撤销全部设备/许可及管理会话，避免旧备份复活被撤销的授权。恢复后更换管理员凭据，并重新办理来源开通和 Windows 主机下载许可，再决定是否切换服务。恢复不覆盖运行目录。
