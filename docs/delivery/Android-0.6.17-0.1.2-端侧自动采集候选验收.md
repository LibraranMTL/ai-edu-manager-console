# 端侧自动采集候选验收（Windows 学生端 → Android 学生端 → Android 教师端）

日期：2026-09-15  
状态：**仅供真机候选验收，尚未替换线上正式下载或更新清单。**

## 已实现范围

### S1：Windows 学生端

Windows 学生个人终端沿用已完成的本机 Agent 生命周期采集：只允许个人终端绑定的当前学生，用户授权后将新事件先写入本机队列，主机恢复可达时自动补送。Codex 的 Hook 仍只需在首次安装或定义更新后完成一次信任；已授权旧会话只从授权后的新轮次开始收集，不扫描此前历史。

Windows S1 的 r2 候选还修复了屏幕资料采集入口：点击卡片会打开应用内浮动设置面板，可选择“智能混合 / 内容变化 / 固定间隔”策略与 15、30、45、60、90、120 分钟时长；真正开始后，屏幕右下角出现独立、始终置顶的控制条，可重点截取、暂停/继续、打开采集箱或结束。结束或到达所选时长后，控制条关闭并按既有队列自动送达。

本次仅重建 Windows 学生端候选包，未扩大到共享终端、主机账户或其他学生。

### S2：Android 学生端

候选版在学生主动启动的新屏幕采集会话中增加“采集结束后自动投递”选择：

- 学生先选择自动投递或保留本机，再由 Android 系统显示录屏授权；没有系统授权不会开始采集。
- 采集期间使用前台服务和持续通知，通知中可暂停、查看高亮或停止。
- 会话结束后，只有本学生、该会话目录内的截图会被一个网络受约束的 `JobScheduler` 任务投递；离线时由系统重试。主机把该会话标记为“Android 学生端屏幕采集”，全部送达后自动完成会话并进入既有处理链。
- 每一项成功后会写入本会话的本地投递回执，避免重复投递；失败截图留在本机，等待后续重试或手动处理。

### S3：Android 教师端

教师端采用相同的会话后自动投递，但投递前必须显式选择学生；项目只可从该学生的关联项目中选择。后台任务重新从会话元数据检查学生根目录与项目目标，主机收到请求后继续按令牌和目标范围复核；主机保留“Android 教师端屏幕采集”来源，不会因教师端缓存或选择切换而写入其他学生。

## 对话边界

Android 端没有、也不会因为本候选版而新增以下能力：读取其他应用私有数据库、无障碍读取、通知监听、后台 OCR 聊天记录或扫描既有会话历史。对话资料仍只支持用户主动使用 Android 分享功能发送正文，或在应用中粘贴正文后确认提交；只给出链接的内容不会被当作对话抓取。

## 真机验收矩阵

1. Windows 学生端：确认个人终端绑定后，一次 Hook 信任即可在新轮次产生队列记录；断网后恢复主机，确认仅当前学生收到记录。验证共享或未绑定终端不能启用。
2. Windows 学生端屏幕采集 r2：点击“屏幕资料采集”后确认出现浮动设置面板；分别选择一种策略和一个时长，开始后确认右下角置顶控制条出现，并验证重点截取、暂停/继续、结束及自动到时结束。确认敏感窗口仍不可选择，且资料仅送达当前学生或其关联项目。
3. Android 学生端：确认自动投递时，授权录屏、持续通知、会话停止、在线送达、离线后重试、手动保留本机这六个路径；切换学生或取消授权后不得产生新投递。
4. Android 教师端：分别对两个不同学生、各自关联项目执行一次；检查主机回执的学生和项目完全匹配选择项，切换选择或解绑项目后必须被阻止或降级为学生教育档案。
5. 三端对话：从外部应用分享明确正文并确认提交；验证未主动分享的私有聊天、通知、历史会话和仅 URL 均不会被读取或入库。

候选只有在以上真机矩阵完成并核对回执、版本、哈希与签名后，才可更新正式下载页、版本清单与服务器文件。
