# 成长证据兼容映射 v1

> 状态：P1 已实现  
> 映射模式：只读、原地兼容、不迁移原文件  
> 输入：`成长证据审核.json`、`growth-index.json`  
> 输出：`edu-manager.education-growth-compatibility.v1`

## 目标

让现有成长模型可以被 Education Domain Protocol 读取和审计，同时保持学生 ID、项目 ID、成长证据 ID、文件内容和物理路径不变。

兼容视图只随读取响应返回，不写回或替换原 JSON。现有 UI、报告和项目贡献流程继续使用原结构。

## 映射规则

| 旧字段/对象 | 协议视图 | 规则 |
| --- | --- | --- |
| Student | Profile | `id` 不变，补充 `type=person`、`domain=education` |
| review candidate / index evidence | Education Claim | 原 ID 可移植时保持不变；知识类型固定为 `observation` |
| `sourcePath` | Evidence `sourceUri` | 保留 `originalSourcePath`；绝对路径转为 `file://`，相对路径标记为 `legacy-path://` |
| `projectId/projectName` | Claim context / Project | 项目 ID 和贡献关联保持不变 |
| `ability` | Claim legacy metadata | 不直接升级为画像结论 |
| index abilities | derived ability view | `publishableClaim=false`，不得绕过审核发布 |
| index projects | Project compatibility view | 保留 projectId、contributionId、evidenceIds 和发布时间 |

## 状态兼容

| 旧状态 | 新 Claim 状态 | 原因 |
| --- | --- | --- |
| `pending` | `candidate` | 等待审核 |
| `watching` | `candidate` | 观察中不是正式结论 |
| `confirmed` 且有完整人工审核记录 | `confirmed` | 可满足新协议审核条件 |
| `confirmed` 但缺 reviewerRole/reviewerId/reviewedAt | `candidate` | 保留 `legacyStatus=confirmed`，要求补审，不伪造审核人 |
| `rejected` | `rejected` | 保留拒绝状态和历史 |

旧系统“确认”只记录状态，通常没有审核人和审核时间。兼容层不会静默制造这些字段，也不会让历史确认直接绕过新协议。

## 来源语义

如果旧记录已有 `sourceType/actorRole`，直接保留。否则兼容层根据有限字段推断并明确记录 `LEGACY_SOURCE_SEMANTICS_INFERRED`：

- AI/Agent 生成：`agent_inference / agent`；
- 教师确认：`teacher_assessment / teacher`；
- 项目或资料路径：`learning_artifact / student`；
- 无一手来源：`system_record / system`，同时记录 `LEGACY_PRIMARY_SOURCE_MISSING`。

推断后的来源类型只是兼容元数据，不等于事实确认。

## ID 与路径

- 可移植旧 ID 原样作为协议 ID；
- 不符合 KnowledgeEngine ID 约束的旧 ID 不修改原文件，兼容视图生成稳定哈希 ID，并在 `idMappings` 保留原 ID；
- `sourcePath` 始终保留在 `originalSourcePath`；
- 映射不移动、重命名或重新索引原文件。

## 产品接入

以下读取响应新增 `protocolCompatibility`，原 `review` 和 `index` 字段继续保留：

- `getGrowthEvidenceReview`；
- `rebuildGrowthIndex`；
- `getGrowthIndex`。

实现：

- `electron/education-growth-compatibility.cjs`；
- `tests/education-growth-compatibility.test.cjs`。

## 后续闸门

1. 新的确认操作必须记录审核角色、审核人 ID 和审核时间；
2. 旧 confirmed 证据需要补审队列和用户可见说明；
3. 画像级能力结论需要独立来源、反例检查和时间跨度；
4. 纠正、申诉、superseded 和历史展示仍需实现；
5. 冻结协议前需确定年龄阶段、监护人和教师权限边界。
