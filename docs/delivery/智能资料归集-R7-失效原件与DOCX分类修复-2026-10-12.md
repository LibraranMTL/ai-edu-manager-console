# 智能资料归集 R7：失效原件、DOCX 分类与学生视图修复

日期：2026-10-12。Windows 0.21.1 独立候选，不是正式发布。未替换正在运行的主机，未操作用户生产待办、删除真实原件或将真实资料重新发送给 Agent。

## 一、确认的问题与修复

1. 原件删除后，发现器只增加记录，不标记旧待办。确认学生时才返回原始 ENOENT。现在完整扫描后只对未见到的旧待办做元数据核验，确认为 ENOENT 才标记“原件已失效”；权限失败、受管排除、链接等不冒充文件不存在。确认／重试／打开时发现原件缺失，也给出可操作提示。未知执行、已投递或有回执的记录不转成可移除待办。
2. 待处理行新增“移除记录”，复用忽略决策、版本和幂等回执：移至“已忽略”，保留记录和操作历史，可恢复。不删除原件、快照、项目资料或任何被引用的资料。原件失效时禁用确认学生与直接投递；恢复文件后按版本重新扫描。
3. R6 将所有提取 warnings 视作 truncated，导致正常 DOCX 的常规范围说明也阻止 AI。R7 区分实际截断、异常警告、已知提取范围说明。已知说明的可读正文可以推荐；coverage 为 partial 或缺少完整性证明的图像／Office 提取，只推荐，不自动投递。未知警告、空正文和截断仍停止派发。敏感资料保护、学生隔离、证据校验、版本和回执检查不变。
4. 分类缓存采用 schema 2。旧轻量分类缓存重新判定质量，向原学生范围提取器请求时仍可命中完整提取缓存，不因本修复重做 OCR。保存提取说明供诊断；完整提取结果继续按学生、版本及授权复用于项目消化。
5. 增加显式“查看学生”筛选。批量确认学生成功后自动切换该列表范围，重置来源筛选和分页，保留当前学生的待确认项；已自动投递项在“已投递”。手动投递默认学生随视图更新。全部失败时不再显示“已确认 0 项”的成功式提示。
6. “重新分析”通过版本核验后立即排入统一手动队列，不必等下次计划。人工锁定、未知执行、已投递、暂停来源仍有保护。没有在列表刷新中新增扫描、OCR、Agent 探测或计时器。

本次根因检查发现原下载来源的 5 份 DOCX 有正文提取缓存，但分类调用次数为 0、没有投递回执；不是实际投递后文件丢失。原件内容不会因“分类分析”被改写。保留原件来源采用复制；旧下载中转来源继续在核验投递成功后归档。

## 四、需要用户操作

1. 确认没有正在运行或结果待核对的任务，正常退出旧主机，再启动文件名含 `smart-inbox-r7-20261012` 的候选，不同时开两个版本。
2. 对失效的 Geography 记录点击“移除记录”；也可先在“来源管理”点一次“立即扫描”，核对其明确显示“原件已失效”。记录应在“已忽略”，不是删除磁盘资料。
3. “查看学生”选择赵书源，在待处理中勾选此前 5 份 DOCX，点击一次“重新分析”。升级不会悄悄把历史受阻资料重新发给 Agent，此操作才发起恢复分析。
4. 有图表、公式等未完整识别内容时，核对建议后批量“确认建议并投递”；可信完整正文且来源授权自动化的资料可自动投递。核对“已投递”回执和实际项目位置／原件归档位置。
5. 无需重新登录 WorkBuddy、移动原始资料、重建学生和项目或关闭安全设置。真实 Agent 业务建议及目标机结果由此受控使用确认，不由本轮合成测试代替。
