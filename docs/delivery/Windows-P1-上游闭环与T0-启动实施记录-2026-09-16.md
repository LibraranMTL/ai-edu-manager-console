# Windows P1 上游闭环与 P1-T0 启动实施记录

日期：2026-09-16。性质：源码与方案的阶段性改动记录，**不是候选安装包、真机验收或正式发布回执**。

## 本轮决策

- 主线以《Windows-0.17.9-屏幕采集消化优先与双报告-P1优化实施方案.md》修订版为准：先补 R0/R0.5/R1/R2/R3/R4 的依赖门；轻量 P1-T0 并行，不抢跑 T1 大批量视觉尝试识别或 T3 预测。
- R2 增加 Codex、WorkBuddy、QClaw 三个**独立能力与授权**的视觉入口。WorkBuddy/QClaw 的普通任务执行能力不等于安全视觉能力；本轮没有向二者投递学生图片，也没有把尚未探测通过的入口开放为可用视觉服务。外部提供商不可用时，仅在已有授权范围内尝试有界本机 OCR，保留未知与自动恢复。
- 活动段可独立存在；只有证据足够的尝试才进入纵向比较。未知行为人、替代时间和缺少任务 ID 不阻断事实保存或其他学生的报告。

## 已落地并本机验证

| 范围 | 具体改动 | 边界 |

| R2 提供商守卫（基础合同） | 视觉核心记录提供商、处理位置及与授权 epoch 绑定的请求 ID；非 Codex 提供商没有本地新鲜安全证明时在调用执行器前拒绝 | 测试使用模拟安全证明仅验证核心合同；没有实现两家真实执行器，也没有开放实际学生传图 |

| R1 长会话事实 | 按日期、活动段和事件数拆成稳定处理窗口，每窗口最多 240 个原始事件、20 张代表图；独立持久化窗口清单，整场会话索引仍兼容既有知识/报告接口 | 长会话后段不再因前 20 张占满而永久缺图；目前正式原始资料仍按会话登记一个汇总 Markdown，尚非多个独立可结算知识批次 |
| R1 视觉子批 | 每个窗口按活动段边界组织最多 8 图/请求，同段最多 3 图不跨请求拆散 | 保证同段前后图可直接比较；跨活动段、跨请求的变化复核仍未完成 |
| R0.5 资源许可（部分） | 时间线 Worker、报告投影 Worker 和截图视觉共用自适应许可；同一学生串行；采集开始后视觉在下一子批边界落盘让出 | 普通资料消化与其他 Agent 子进程尚未全部纳入同一许可；不是全系统重任务治理或 OS 级只读隔离 |

本轮没有修改任何已有学生档案、已有 `AGENT.md`、正式 EXE、线上清单或官网。当前工作树原有 Android/学生端并行修改及 `electron/main.cjs` 的原有改动均保留；本轮仅对所需片段做局部补丁。

本轮增加了 QClaw 本地配置和模型目录的只读检查；只向 WorkBuddy 发送过**仓库公开品牌图标**，没有向 WorkBuddy/QClaw 发送学生图。WorkBuddy 的单图识别成功只证明显式附图输入有效，不证明工具禁用、只读沙箱、处理地域或教育场景质量。特别是现有 `workbuddy-runtime.cjs` 的普通任务执行参数含 `acceptEdits`，不能复用为视觉观察执行器。OpenClaw [官方推理接口说明](https://docs.openclaw.ai/cli/infer)确认本地 `model run --file` 属于不加载聊天工具/MCP 的单次推理，仍须以已安装版本和本机隔离实测为准；WorkBuddy [官方无头输入说明](https://www.workbuddy.ai/docs/zh/cli/headless)提供结构化图片输入样例，但不替代本机只读验证。

补充的非学生文本试验中，同样携带 `--tools ''` 的 WorkBuddy 运行无实际工具调用记录，却自称读取了仓库 `package.json` 并报出错误的 `name=edu-launcher-app`（真实值为 `edu-manager-launcher`）。因此既不能凭初始化列出的工具目录断言已执行工具，也不能凭模型自述当作已读文件证明；必须核对系统工具调用/附件交付与实际返回内容。学生截图入口仍关闭。

## 验证与未通过的门

- 全量 Node 测试：**1010 项，1009 通过、1 跳过、0 失败**；包括新增的长会话/跨午夜稳定窗口、删除与来源修订、共享许可、采集时子批让出、疑似时钟偏差和未验证提供商拒绝用例。`electron/main.cjs` 另通过 `node --check`。
- Vite 正式模式构建：3712 个模块转换成功，输出到独立临时目录，未覆盖现有 `dist/` 或 0.17.9 发布包。既有大 chunk 警告仍在。
- 500 帧合成基准：5 个窗口、共 100 张代表图，每窗口最多 20 张；Worker 首轮约 279 ms，定向查询 P95 约 1.35 ms、主线程定时器最大漂移约 2.66 ms，无预消化 OCR。这只是本机合成负载，不能推断低配真机、实际图片模型或长时采集无卡顿。相比上次 100 帧基准的约 93 ms，并非同样负载，不能据此判断回归。
- **未通过发布门**：R0 可复现构建输入与 WorkBuddy/QClaw 公共图片端到端能力矩阵（已有工作树审计快照不等于可复现基线）；R0.5 全系统重任务许可与操作系统级只读隔离；R1 窗口级独立知识结算、持久检查点和跨活动段/跨子批变化复核；R2 两家 Agent 的实际安全传图、独立授权界面、全字段对账及真实内容质量；R3 真实学生截图的可读报告；R4 低配机、双机、休眠断网、回滚、签名和新候选发布。P1-T0 的可信时钟校准、结构化任务映射和跨来源去重也未完成。

下一步应先处理 R0.5 的共享调度与硬只读边界、R1 长会话分包；WorkBuddy/QClaw 只能先用非学生测试图片探测当前安装版的显式输入与安全限制，通过后再分别开放授权选择。R3/R4 必须以经授权的真实样本及真机数据验收，不让普通用户逐图审核或手工恢复后台失败。
