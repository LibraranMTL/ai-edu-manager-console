# AI教育管家不同设备智能体调用云端文档方案

> 2026年10月17日修订说明：本方案已纳入[云端模块升级开发方案](AI教育管家云端模块升级开发方案-2026-10-17.md)。最新设置入口为“Agent设置管理 → 云端同步设置”；“已下载的本机副本”保留在业务页面；增加五类资料授权、云端学习资料下载、稳定逻辑资料版本与成果收件箱设计。以下旧版“系统设置—云端协同”菜单、缓存迁移及仅按名称归并的约定由新方案替代。本文及同名Word文件保留为历史方案，后续开发以新方案为准。

版本：v1.2  
日期：2026年10月16日  
适用范围：异地电脑、移动设备、网页端和不原生支持远程MCP的智能体宿主

## 一 结论与立项建议

建议单独建设“AI教育管家云端 Agent 网关”，让不同设备上的外部智能体通过远程 MCP 或同源 REST API，只读调用用户已经明确分享至云端的报告和文档。该网关不直接连接家庭 Windows 主机，不要求主机持续在线，也不把本地完整私域知识库复制到云端。

本方案与现有本地连接器并行：Windows 本机 stdio MCP 继续访问本地私域知识并承担受控回写；云端连接器只访问云端共享副本，首期不开放写入正式档案。两者共用连接身份、权限目录、结果元数据和审计格式，但工具可见范围必须明确区分，避免智能体把“云端已分享资料”误解为“教育管家全部资料”。

Windows 端同时调整页面职责：学情报告下的“云端文档”页面只承担报告和文档浏览、下载与只读预览；云端地址、连接测试、上传授权、下载许可、本机缓存和外部 Agent 授权统一迁入“系统设置—云端协同”。云端报告和其他文档采用“当前版本加历史修订”模型，默认列表和 Agent 检索只返回当前版本，旧修订保留追溯但不重复进入常规查询范围。

截至2026年10月16日，教育管家云端文档入口已经部署在 `https://www.greatbg.com/edu-cloud/`，本次只读核验返回 HTTP 200，页面标题为“AI教育管家 · 云端文档”，可以确认已有可访问的 HTTPS 云端入口。现有云报告服务同时具备学生许可、报告和其他文档列表、正文下载、撤回、哈希校验和审计基础；2026年10月15日复测 `cloud-report-service/service.test.cjs` 共15项，15项通过。需要继续区分的是：HTTPS 页面可访问不等于远程 Agent 接入已经投产，远程 MCP、OAuth、连接级撤销、生产限流、容量策略和真实跨设备验收仍需建设或验证。因此项目当前状态应表述为“已有 HTTPS 云端入口和可复用数据底座，远程只读 Agent 能力待开发与验收”，不能表述为已经正式支持异地 Agent。

| 设置入口分散 | 云端浏览页同时承担连接、配对、缓存和上传设置，普通浏览与高风险管理操作混杂 | 新增“系统设置—云端协同”，浏览页只保留内容操作和前往设置入口 |
| 同名资料缺少当前版本语义 | 更新后的整体画像或同名文档会与旧版本同时出现在列表及后续检索范围 | 增加资料系列、当前版本和替代关系；默认只列出和检索当前版本，历史修订按需展开 |

### 2.3 必须长期保持的数据边界

远端 Agent 可以读取：已正式上传的学情报告；用户主动分享的规划摘要、Markdown、PDF、DOCX；后续明确纳入云分享范围的知识成果。

远端 Agent 不能自动读取：尚未上传的本地知识库；原始截图、录音、对话和项目原件；本地主机实时变化但尚未同步的资料；其他学生或被排除的项目；本地连接器的完整13项权限；本机任意路径。

云端副本与本地原件相互独立。撤销许可可以阻止后续读取，但不能远程删除第三方 Agent 已经下载或处理过的副本。授权页必须明确提示：资料会进入所选 Agent 提供商的处理环境，相关留存和训练政策由该提供商决定。

## 三 总体架构

```text
不同设备上的 Agent
  ├─ 原生支持远程 MCP ───────────────┐
  ├─ 只支持 REST 或厂商连接器 ────────┤
  └─ 只支持本地 stdio MCP ─ 本地轻量代理 ┤
                                           ↓
                         AI教育管家云端 Agent 网关
                         HTTPS  OAuth  限流  审计
                                           ↓
                   连接授权解析和学生范围校验
                                           ↓
                  现有云端报告与文档服务适配层
                                           ↓
              用户明确分享的报告和其他文档副本
```

网关只承担协议适配、身份验证、权限解析、内容编排、限流和审计。现有云报告服务继续负责学生许可、对象索引、撤回状态和哈希验证。任何请求都必须同时通过 OAuth 身份、连接状态、学生范围、资料状态和具体操作权限五层校验。

本地连接器与云端连接器采用同一语义合同，但使用不同数据平面：

| 连接面 | 传输 | 数据范围 | 首期写入 | 典型使用场景 |
|---|---|---|---|---|
| 本地连接器 | stdio MCP 加本机窄接口 | 本机私域知识和授权项目 | 按现有13项权限受控执行 | 同一 Windows 主机上的 WorkBuddy、Codex 等 |
| 云端连接器 | 远程 MCP Streamable HTTP | 用户已分享的云端副本 | 不开放 | 异地电脑、手机、平板、网页智能体 |
| 云端轻量代理 | 本地 stdio MCP 转远程 HTTPS | 与云端连接器相同 | 不开放 | 不支持远程 MCP 但可运行本地进程的宿主 |
| 同源 REST/OpenAPI | HTTPS JSON 或文件下载 | 与云端连接器相同 | 不开放 | 只支持厂商连接器或 OpenAPI 的宿主 |

## 四 不同设备的接入方案

| 设备或宿主 | 推荐方式 | 授权方式 | 本地组件 | 能力边界 |
|---|---|---|---|---|
| 教育管家所在 Windows 主机 | 优先使用现有 stdio MCP | 本机连接授权和独立凭据 | 现有本地连接器 | 可访问本地授权知识；云端只作为补充 |
| 另一台 Windows 或 macOS Linux 电脑 | 远程 MCP | 浏览器授权码加 PKCE | 无 | 只读云端共享副本 |
| 支持远程 MCP 的 Android iOS Agent | 远程 MCP | 系统浏览器授权；返回 App | 无 | 只读云端共享副本，受移动网络和宿主文件能力限制 |
| 不支持远程 MCP 但支持本地 stdio 的桌面 Agent | 云端轻量代理 | 首次由系统浏览器完成 OAuth | 轻量代理，仅保存加密刷新凭据 | 代理不保存完整档案，不扩大权限 |
| 只支持 REST OpenAPI 的网页或 SaaS Agent | 同源 REST 或厂商连接器 | OAuth 重定向 | 无 | 只暴露同一只读权限和数据合同 |
| 受控教育终端或无便捷键盘设备 | 远程 MCP 或专用客户端适配 | 设备授权流程或管理员预配的第一方连接 | 可选第一方客户端 | 仍按用户、连接、学生和资料范围校验 |

禁止把 Windows 下载端的 P-256 私钥复制给第三方 Agent，也禁止让所有 Agent 共用一个长期 API Key。每个 Agent 安装实例都应获得独立 connectionId、clientId 和可撤销令牌；同一厂商的多个设备也按连接实例分别登记。

## 五 云端连接器能力合同

### 5.1 首期只读工具

| 工具 | 作用 | 最小权限 | 关键输入 | 关键输出 |
|---|---|---|---|---|
| `connection.get_scope` | 查看当前连接可访问范围和有效期 | `edu.scope.read` | 无 | connectionId、学生范围、资料类型、到期时间、限制项 |
| `cloud_material.list` | 列出已分享报告和文档 | `edu.material.list` | studentId、type、cursor、limit | 资料元数据、nextCursor |
| `cloud_material.read` | 读取指定资料版本 | `edu.material.read` | studentId、materialId、revisionId、mode、cursor | 正文或下载描述、哈希、下一分段游标 |
| `cloud_report.list` | 列出正式报告修订 | `edu.report.list` | studentId、cursor | 报告类型、发布时间、来源、修订和哈希 |
| `cloud_report.read` | 读取报告正文 | `edu.report.read` | studentId、revisionId、cursor | Markdown 分段、哈希、来源设备 |

第二阶段增加 `cloud_material.search`。搜索只覆盖已经进入云分享范围且提取成功的派生文本；结果必须返回 materialId、revisionId、原件哈希、命中片段和提取版本，不把搜索索引当成新的原始证据。

### 5.2 统一结果信封

每条结果至少包含：

- `studentId` 和只用于显示的学生名称；
- `materialId`、`revisionId`、资料类型和 MIME 类型；
- `originDeviceId`、来源平台、发布时间和云端接收时间；
- `contentSha256`、字节数和版本状态；
- `availability`，取值为 `available`、`withdrawn`、`expired`、`forbidden`、`corrupted` 或 `local_only`；
- `originalLocation`，明确为 `cloud_copy` 或 `local_original_only`；
- `providerProcessingNotice`，说明正文将由外部 Agent 提供商处理；
- `traceId`，便于用户在调用记录中定位一次访问。

### 5.3 大文件和二进制处理

Markdown 和报告正文按 UTF-8 分段返回，单次返回设置字符和字节上限。PDF、DOCX 首期不强制转换为正文：支持文件资源的宿主获取短时、单对象、不可转让的下载地址；不支持文件资源的宿主得到明确的“仅可下载原件，尚无派生文本”状态。第二阶段提取文本后，`mode=text` 返回派生内容，同时保留 `derivedFromHash` 和提取器版本。

网关不得在一次工具调用中无上限返回整个大型文件，也不得把长期对象地址写入模型上下文。短时下载地址应绑定 connectionId、对象、有效期和一次或有限次数读取，并继续接受撤回检查。

## 六 OAuth 和授权设计

### 6.1 身份与许可分层

OAuth 负责确认“哪个用户通过哪个客户端访问哪个资源服务器”；教育管家许可继续决定“这个连接能读取哪些学生和哪些资料”。两者不能相互替代。

建议令牌至少包含或可解析：`sub`、`client_id`、`connection_id`、`aud`、`scope`、`exp`、`jti`。资源服务器校验签名、签发者、受众、过期时间和所需 scope；随后按 connectionId 查询授权代次、暂停或撤销状态、学生范围和资料类型。学生 ID 永远由服务端权限表校验，不能因为客户端在参数中提供就放行。

### 6.2 用户授权界面

普通设置只保留一个主开关：

> 允许我连接的外部智能体读取已经分享至云端的教育资料。

添加连接时显示该 Agent 名称、提供商、回调域名和将获得的只读能力。高级设置提供：全部已分享学生或指定学生；报告和其他文档分别授权；授权有效期；是否允许全文搜索；单独暂停或撤销某个连接；调用记录。

“一次全局授权”表示用户不必逐篇批准读取，不表示所有连接共享令牌，也不表示未来新增 Agent 自动获得权限。只有用户明确建立的连接可以继承当前全局策略；连接级限制只能减权。

### 6.3 系统设置中的云端协同

Windows 端在“系统设置”下新增独立菜单“云端协同”。该菜单与现有“知识协作—协作设置”并列但不合并：现有协作设置继续管理本地或局域网设备信任、学生映射和多端知识协作；云端协同专门管理 `https://www.greatbg.com/edu-cloud/`、云端报告与文档同步以及外部 Agent 云端调用。

“云端协同”下设置两个页签：

| 页签 | 纳入的设置 | 不应放入的内容 |
|---|---|---|
| 云端文档同步设置 | HTTPS 服务地址与连接测试；打开云端管理页；Windows 主机下载许可；已下载本机副本及按学生清除；本机学生上传开通、自动上传开关、立即同步、同步状态和配对确认 | 报告正文预览、日常文档浏览和 Agent 提供商令牌 |
| Agent云端同步设置 | 外部 Agent 总开关；连接列表；每个连接的学生、报告、其他文档、搜索和有效期范围；OAuth 状态；暂停与撤销；调用记录；提供商处理提示 | 本地 stdio Agent 的13项权限、教育管家调用模型的调度策略和本地完整知识库授权 |

截图所示“Windows主机下载许可”“已下载的本机副本”“本机学生上传与授权”，以及当前页面上方的“云端服务设置与连接测试”，全部迁入“云端文档同步设置”。迁移后“学情报告—云端文档”只保留学生选择、学情报告与其他文档页签、刷新、下载、只读预览、当前版本和历史版本入口，并提供“前往云端协同设置”的明确跳转。

“Agent云端同步设置”中的“同步”仅表示外部 Agent 对已分享云端副本的授权和读取连接，不表示把本地完整知识库、原始录音截图或本机路径同步给 Agent。设置迁移不得重置现有服务地址、配对凭据、上传开关、已下载缓存或学生授权；组件拆分后仍复用现有主进程接口和安全存储。

### 6.4 云端资料当前版本与历史修订

可以解决同名资料不断累积的问题，但推荐“逻辑更新”而不是直接物理覆盖。新内容仍生成不可变修订和新哈希，服务端原子更新哪个修订是当前版本；旧修订进入历史视图，不再出现在默认列表、Agent 列表和全文检索中。这样既控制查询量，也保留审计、回滚、引用复现和撤回证据。

当前代码的报告唯一约束包含学生、来源设备、报告类型和内容哈希；因此整体画像内容变化后会形成新修订，`listReports` 又会返回全部未撤回修订。其他文档仅对同一学生、来源、名称、类型和内容哈希的完全重复上传去重；内容变化后仍会新增 documentId。实施时增加以下合同：

- 报告系列键：`studentId + originDeviceId + reportType`。同一来源设备上传更新后的整体画像时，新修订自动替代该系列旧的当前修订。
- 其他文档系列键：`studentId + originDeviceId + normalizedDisplayName + contentType`。同源同名且类型相同的新内容默认作为下一版本；重命名或跨来源同名不自动互相覆盖。
- 数据字段：`seriesId`、`versionNumber`、`isCurrent`、`supersedesId`、`supersededAt`；每个系列只能有一个未撤回当前版本。
- API 默认 `versionScope=current`；管理界面或明确的“查看历史版本”使用 `versionScope=history` 或指定 revisionId。Agent 首期不获得批量搜索全部历史版本的默认权限。
- 同一内容哈希重传继续返回幂等回执，不增加版本号；已撤回修订不得因重试自动恢复。
- 多来源出现同名资料时分别保留系列，并显示来源设备；如业务需要每个报告类型只选一个“对 Agent 生效的主要来源”，必须由用户明确指定，不能按文件名静默覆盖。
- 旧数据迁移先备份，再按学生、来源、报告类型或规范化文件名分组；各组按发布时间、接收时间和稳定 ID 选出候选当前版本。时间冲突、缺少来源或名称歧义进入待核对清单，不自动删除。
- 历史保留期、版本数量和永久删除策略由产品配置决定。达到策略阈值时先从当前查询和索引排除，再按审计规则清理对象；已经被 Agent 引用的 revisionId 在保留期内仍可精确读取或明确返回已过期状态。

### 6.5 令牌和密钥规则

- 第三方交互式 Agent 使用短时访问令牌和可轮换刷新令牌，优先采用授权码加 PKCE。
- 资源服务器必须校验令牌受众，拒绝为其他资源签发的令牌。
- 独立连接可单独撤销；刷新令牌轮换并检测重复使用。
- 浏览器和移动宿主不保存教育管家设备私钥；第一方轻量代理使用操作系统安全存储保存刷新凭据。
- 日志不记录访问令牌、刷新令牌、授权码、文档正文或配对码。
- 权限降级、学生排除、连接暂停和撤销对新请求立即生效；正在传输的大文件在提交响应前再次校验。

## 七 主要调用流程

### 7.1 首次连接

1. 用户在 Agent 中选择“连接 AI教育管家云端”。
2. Agent 读取受保护资源元数据并跳转到教育管家授权页。
3. 用户登录，确认 Agent、学生范围、报告或文档类型、有效期和提供商处理提示。
4. 授权服务器为该安装实例建立独立 connectionId，签发面向云端 Agent 网关的令牌。
5. Agent 调用 `connection.get_scope`，显示实际可用范围；此步骤只验证授权，不代表资料读取已经成功。
6. Agent 用一个去标识测试资料完成列表和读取自检，状态分别记录为“已授权”“列表已验证”“正文已验证”。

### 7.2 正常读取

1. Agent 调用列表工具并指定学生；默认只请求当前版本。
2. 网关校验 OAuth、连接状态、权限代次和学生范围。
3. 适配层调用现有云文档服务；服务再次检查 `cloud_document.read`、撤回和到期状态。
4. 对象读取后重新核对哈希，网关返回统一结果信封。
5. 审计记录 traceId、connectionId、学生、对象、工具、结果、字节数、时间和拒绝原因，不记录正文。

### 7.3 撤销和已下载副本

用户撤销连接后，访问令牌在网关侧立即失效或被授权代次拒绝，刷新令牌同时撤销。列表、读取、搜索和短时下载地址均停止工作。界面同时提示：撤销不能删除 Agent 提供商已经接收的内容，用户需要按该提供商的机制处理历史副本。

## 八 检索和派生文本方案

第二阶段先采用关键词全文检索，不把向量数据库作为首期依赖。

1. Markdown 直接规范化和分段。
2. PDF、DOCX 生成派生文本，记录提取器版本、时间、原件 SHA-256 和失败原因。
3. 索引按用户、学生、connection 可见范围、资料状态和当前版本过滤；修订被替代或撤回后立即从默认搜索结果隐藏。
4. 返回命中片段时保留原页码或段落位置；无法可靠定位时明确标记位置不可用。
5. OCR 只作为后续可选能力；OCR 文本标记为机器识别结果，不覆盖原件。
6. 索引重建不改变原件，也不新增证据数量。

全文搜索权限与正文读取权限分开。未授权搜索的连接仍可按列表读取已知资料，但不能批量探测全部内容。默认搜索仅覆盖当前版本；确需追溯历史时，用户应明确选择历史范围，结果仍返回具体 revisionId、版本号和内容哈希。

## 九 安全 运维与审计

### 9.1 部署要求

- 复用现有 `https://www.greatbg.com/edu-cloud/` HTTPS 入口时，为远程 MCP、OAuth 资源端点和 REST API 设置明确的路径隔离；如运维边界需要，也可使用独立 API 子域。
- 验证公网证书链、自动续期、反向代理、Host 与 Origin 校验；后端不直接暴露现有本地试点端口。
- API 网关或 WAF 校验 Host、Origin、请求大小、速率和异常模式。
- MCP 网关、授权服务器、云文档服务和对象存储使用最小权限网络策略。
- 数据库和对象存储加密，备份使用独立密钥、异地保存和恢复演练。
- 文档和派生索引设置容量、保留期和删除策略，不能沿用试点默认值直接上线。
- 结构化审计进入独立保留域；安全拒绝事件与正常读取事件可区分查询。

### 9.2 限流建议

按用户、connectionId、clientId、学生、工具和来源地址组合限流。列表、正文、搜索和文件下载分别计量；429 返回可重试时间。对连续403、无效学生枚举、哈希异常和下载地址滥用触发安全告警，不把一次普通网络错误直接判定为攻击。

### 9.3 状态和错误合同

| 情形 | HTTP 或 MCP 表现 | Agent 应向用户说明 |
|---|---|---|
| 未登录或令牌过期 | 401 `invalid_token` | 需要重新授权，不自动猜测内容 |
| 权限不足 | 403 `insufficient_scope` 或业务拒绝 | 当前连接无此学生或资料权限 |
| 资料已撤回 | 410 或 `availability=withdrawn` | 该修订已撤回，不能继续读取 |
| 资料不存在 | 404 | 未找到指定版本，不改读其他学生或版本 |
| 内容哈希异常 | 500 `content_integrity_failed` | 暂停返回正文并提示稍后重试或联系管理员 |
| 频率过高 | 429 | 按服务端时间退避，不并发放大请求 |
| 派生文本未就绪 | 200 元数据加 `extraction_pending` | 可下载原件或稍后再试，不称为检索无结果 |

## 十 分期实施方案

### 第一阶段 远程只读最小闭环

交付内容：新增“系统设置—云端协同”及“云端文档同步设置”“Agent云端同步设置”两个页签；把云端浏览页的连接、许可、缓存和上传设置完整迁入；增加资料系列、当前版本和历史修订合同；默认列表及 Agent 调用只返回当前版本。在此基础上完成现有 HTTPS 入口的远程 Agent 路由与生产加固、远程 MCP 网关、OAuth 资源服务器接入和授权页、独立连接与撤销、`connection.get_scope`、列表、读取和元数据工具、同源 REST、审计、限流、短时下载及至少两个真实异地 Agent 验收。

完成条件：设置迁移前后的服务地址、设备凭据、上传开关、学生许可和本机缓存保持一致；云端浏览页不再出现管理设置折叠项；同源整体画像连续上传三版时默认列表和 Agent 查询只出现最新版，历史入口仍可读取前两版；同名跨来源文档不会静默互相覆盖。同一用户的两个 Agent 使用不同 connectionId 和令牌；一个连接撤销不影响另一个；两个学生并发访问不串人；主机离线仍能读取已分享副本；撤回、到期、哈希异常和大文件均有真实证据；测试数据、候选和正式发布状态分别记录。

### 第二阶段 知识检索优化

交付内容：Markdown 索引；PDF、DOCX 派生文本；关键词全文检索；分段读取；索引状态和重建；撤回后的搜索清除。

完成条件：搜索结果只出现授权学生和未撤回资料；每个命中可追溯到原件版本和哈希；提取失败不会冒充“没有相关资料”。

### 第三阶段 受控成果回传

交付内容：云端收件箱；Agent 提交分析成果和来源引用；本地主机主动拉取；用户确认归属；进入既有分类、消化和归档流程。

完成条件：远端 Agent 不能直接改写正式档案、正式报告或本机任意路径；重复提交幂等；本地主机离线时保留待收取状态；用户纠正优先且不可被 Agent 覆盖。

### 第四阶段 按需求评估实时本地主机调用

只有出现必须查询未上传本地资料的明确业务需求，并且云分享无法满足时，才评估出站隧道或中继。该阶段单独进行威胁建模、家庭网络影响、主机在线率和用户可理解性评估，不作为前三阶段的隐含承诺。

## 十二 验收矩阵

| 类别 | 必须通过的场景 |
|---|---|
| 身份 | 未登录、过期令牌、错误受众、错误签发者、令牌重放和刷新令牌重复使用均拒绝 |

| 学生隔离 | 学生A连接不能列出、读取或搜索学生B；篡改参数仍由服务端拒绝 |

建议首批验收组合为：一台异地桌面设备上的标准远程 MCP 客户端，加一个只支持 REST 或需要轻量代理的不同类型宿主。仅在两个宿主分别完成授权、读取、越权拒绝和撤销后，才更新兼容矩阵；不能把一个宿主的结果推广为所有 Agent 可用。

## 十三 风险与控制

| 风险 | 影响 | 控制措施 |
|---|---|---|
| 用户误以为云端包含全部私域知识 | 产生错误回答或隐私预期 | 工具命名、范围查询、结果元数据和界面持续标明 `cloud_shared` |
| 第三方留存已读取正文 | 撤销后仍可能存在副本 | 授权前提示、最小范围、连接级审计和提供商删除指引 |
| 学生参数被篡改 | 跨学生泄露 | 网关和底层服务双重校验，禁止客户端决定许可 |
| 二进制文件过大 | 模型上下文膨胀和成本失控 | 分段、短时下载、字节上限和派生文本 |
| OAuth 配置错误 | 错发令牌或受众混淆 | 独立资源标识、签发者和受众校验、PKCE、自动化安全测试 |
| 同名资料和历史修订持续进入查询 | Agent 查询量、成本和回答冲突增加 | 默认只列出、索引和检索当前版本；历史按显式范围读取；设置保留策略和容量告警 |
| 仅按文件名覆盖 | 不同来源或不同资料被错误合并 | 系列键包含学生、来源、类型；跨来源覆盖必须由用户明确选择主要来源 |
| 设置迁移重置凭据或授权 | 同步中断或权限意外变化 | 只迁移界面职责，复用同一持久化键和主进程接口；增加迁移前后状态快照与回归测试 |
| 仅因现有 HTTPS 页面可访问就直接开放试点接口 | 缺少 Agent 协议、身份、限流和生产隔离 | 在现有 HTTPS 入口前设置生产网关和部署基线，不把8755端口直接开放 |
| 测试通过被误写为正式发布 | 决策失真 | 保留原型、合成、候选、真机、签名和正式发布状态 |

## 十四 需要确认的产品决策

进入开发前建议确认以下六项，不影响本方案的架构方向：

1. 首批真实验收的两个 Agent 宿主及其远程 MCP、OAuth 和文件资源能力。
2. 云端共享资料的默认有效期、单学生容量、每个系列保留的历史版本数量和超过保留期后的清理规则。
3. PDF、DOCX 首期是否必须让 Agent 直接读取正文，还是允许先提供受控下载、第二阶段再提供派生文本。
4. 使用自建授权服务器还是接入现有身份提供商；无论选择哪种方式，云端 Agent 网关都只作为 OAuth 资源服务器验证令牌，不自行混用设备私钥。
5. 远程 Agent 端点采用现有域名下的独立路径，还是使用独立 API 子域；两种方式都必须与用户可见的云端文档页面、内部服务端口和运维权限清晰隔离。
6. 同一学生同一报告类型存在多个来源时，是否允许用户指定一个“对 Agent 生效的主要来源”；在确认前不得自动按文件名合并或覆盖。

上述官方资料支持采用远程 HTTP MCP、OAuth Bearer Token、受保护资源元数据、资源受众校验和按操作 scope 校验。具体协议版本应由服务端兼容矩阵和真实宿主协商结果决定，不应只因服务端实现最新协议就宣称所有宿主兼容。

## 十六 最终建议

批准以“远端 Agent 只读调用用户明确分享的云端知识”为首期目标，并把“系统设置—云端协同”和资料当前版本治理纳入第一阶段必做范围。首期不建设云端完整知识库，不开放远程主机控制，不允许直接改写正式档案，也不把全文检索、成果回传和实时本机访问捆绑为上线前置条件。

该路径可以最大程度复用现有云报告和文档服务，同时把最敏感的本地档案、原始材料和写入能力继续留在用户主机。项目成败的关键不在“能否下载文档”，而在于连接身份、学生隔离、撤销、提供商处理提示、生产运维和真实跨设备验收是否形成完整证据。
