# AI教育管家每周知识增长统计图开发方案

**目标**　在 Windows 主机的知识中心展示当前学生本周的知识库新增情况，一键保存适合微信分享的 PNG。产品入口可沿用“每周知识增长”，但图中必须常驻说明“统计知识库首次登记，不代表掌握度或学习能力增长”。用户打开微信后自行选择好友、群聊或朋友圈。

**首版范围**　一张图、两个指标、七个日期、一个「保存图片」按钮。仅展示当前自然周，在本机完成统计、绘图和保存。适用对象是单名获授权学生。

**技术路线**　沿用 Electron、React、TypeScript、Node.js 和现有资产索引。资产总量读取现有汇总，知识点按稳定 ID 和首次登记时间统计，PNG 用 Canvas 编码。无需 AI 生成、微信接口、云端上传或新的定时任务。

**对接基线**　2026 年 11 月 1 日复核时，Git HEAD 仍为正式 Windows 0.21.6 所在提交 `1bc23c68`，但当前工作树 `package.json` 已标为 0.22.8，并包含大量未提交候选改动；0.22.8 验收记录仍是“预候选、不得发布”。实施起点必须是实际目标候选的干净工作树，并记录源码状态、包体/`app.asar` 指纹、资产库 schema、学习事件格式和验收状态。当前资产汇总已经支持按 `studentId` 过滤；缺少学生 ID 或传入 `all` 时仍会落到全库，因此权限检查必须先于统计调用。

**实施顺序**　先使两个指标能独立对账，再开发周图，最后接入保存并做真机验收。三个任务可各自形成一个可回归的提交；开发代理可用 `superpowers:executing-plans` 逐项执行。

## 〇　评估结论与修订决策

**总体判断：这是三份方案中最适合先落地的功能，UI 和导出风险低，真正的难点只有“首次登记”是否可持久、可撤回且不重复计算。** 原方案方向正确，但必须把“统计口径”从展示文字提升为可恢复的数据契约。

| 评估项 | 结论 | 修订后的处理 |
|---|---|---|
| 用户价值 | 明确，适合作为低风险试点和微信分享素材。 | 保留一张图、两指标、七天、一个保存按钮。 |
| 语义风险 | “知识增长”容易被理解为学习进步；资产总量与知识点新增是不同实体。 | 图中分别写“知识资产总量”和“本周知识库新增知识点”，并常驻非掌握度说明，不做两者比例或综合分。 |
| 数据风险 | 现有事件有 `recordedAt` 与 `occurredAt`，但没有已核实的“首次登记永不后移”权威表。 | 新建可重建且保留墓碑的首次登记投影/账本；旧数据不能可靠回填时标未知。 |
| 一致性风险 | 资产总量和知识点新增可能来自两个存储、两个时刻。 | 返回同一 `asOf`、学生范围和授权版本；读取中范围或代次变化则丢弃并重试。 |
| 工期 | UI 很小，数据迁移和回归占主要成本。 | 若目标版已有可靠首次登记表，约 5–8 人日；若需新增持久账本、旧档兼容和恢复，约 8–12 人日。基线冻结后重估。 |

**明确非目标。** 本功能不评价掌握度、不生成学习建议、不自动发送微信、不调用 Agent、不创建定时任务、不因打开页面而重建资产或消化知识。

## 一　用户看到什么

在当前版本实际的「知识中心」中放置「每周知识增长」卡片。已核对的 0.21.6 对应入口采用「知识与协作 → 知识资产治理 → 文件资产中心」，放在现有七天资产趋势图附近。页面明确显示当前所选学生；只有选定一名学生才启用周图。选中「全部学生」时提示「请选择一名学生查看周图」。

| 图片位置  | 示例文案或内容                             |
| ----- | ----------------------------------- |
| 标题与日期 | 每周知识库新增 · 2026 年 10 月 26 日至 11 月 1 日 |
| 左侧大数字 | **知识资产总量　128 项**                    |
| 右侧大数字 | **本周新增知识点　12 个**                    |
| 主图    | 周一至周日七柱，单位为「个」。示例依次为 2、0、3、1、2、3、1  |
| 页脚    | 截至 11 月 1 日。新增按知识点首次登记统计，不代表掌握度变化。 |

以上数字为验收样例。默认输出 1080 × 1920 的竖版 PNG，白底，数值直接标在柱旁。当天注明「截至今日」，尚未到来的日期保留位置、标为「—」。确实为零的已过日期显示「0」。页面可提供图表文字描述，所有操作都能用键盘完成。

## 二　统计口径

| 指标         | 开发规则                                                                                                                                                              |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 知识资产总量（项）  | 主进程先确认当前学生及访问权限，再读取 `assetIndexSummary({ studentId }).total`。统计生成时归属于该生的唯一资产记录。一个资产在多个地方被引用仍计一项。共享项目按资产中心已登记的学生归属计数。页面搜索、类型筛选及「只看重复」不改变图片总量。资产移出该生范围后，总量跟随资产中心调整。 |
| 本周新增知识点（个） | 在单个学生范围内，按已有规范化 `knowledgePoint.id` 去重。仅把首次可靠登记落在本周、截至生成时仍有有效来源的知识点计入。一项知识点多次出现在资料、作答或多个项目中仍计一次。                                                                  |
| 每日柱值       | 使用同一批首次登记记录，按统计快照中冻结的产品时区归桶。周一 00:00 为起点，下周一 00:00 为排他终点，只取截至本次生成时的数据。周值必须等于七个日期中所有已知柱值之和。首版默认使用主机当前产品时区并写入快照；主机时区在一周内改变时不重写旧快照，重新生成会明确采用的新时区。跨月、跨年及夏令时均按本地日历推进。 |
| 缺失与异常      | 旧知识点首次日期无法确认时，排除该点并注明「另有 N 个知识点首次登记日期不明，未计入趋势」。查询失败、账本损坏或学生范围不明时提供重试并暂停保存。两个来源都读取成功且数据为空时，可以导出零值图。                                                                |

**“首次登记”和“学习发生”可能跨周。** 例如，学生上周完成练习，本周一才把记录导入。若该知识点此前没有登记，计入本周一；如果上周已经登记，本周补交第二份资料贡献零个新增。图片表达知识库的增长，学习掌握程度仍沿用原有评价方式。

## 三　开发任务与接口

### 任务〇　先修复知识资产统计更新链

- [ ] 在开发周图前执行《2026-11-01-Windows基础体验与项目新建补充开发方案》的任务 A。当前运行库已核实健康、资产行数与汇总一致，但最后一次已观察的持久化更新为 2026-11-01 08:55（北京时间）；同时 `refreshAssets()` 主要依赖进入资产页、手动刷新和少数显式操作，项目页等消费者可能持有旧快照。
- [ ] 用受控测试文件分别验证上传、项目采纳、目录扫描、恢复和撤回，记录上游回执、资产行、代次和页面值。只有“成功回执存在但资产行缺失”才能判为后端漏写；资产行存在但页面不变应判为刷新/通知缺陷。
- [ ] 建立带 `generation/asOf` 的统一资产统计快照和事务提交后的 `asset-index:changed` 通知。首页、项目页、资产页与本周图使用同一服务，按代次丢弃旧响应；打开页面不得触发全量重建。
- [ ] 提供显式、幂等的差异预览与回补，不在启动时静默重扫。该任务未通过前，本周图中的“知识资产总量”只能作为开发数据，不能进入正式验收样图。

### 任务一　取得可复核的单学生统计

- [ ] 在目标版本定位资产总量、规范化知识点 ID 和首次登记来源。已核对的 `electron/asset-index-store.cjs` 在缺少学生 ID 或传入 `all` 时会取全库。周图入口必须在调用前拦截；授权检查及学生目录解析放在主进程。
- [ ] 先为首次登记编写失败用例，再实现。0.21.6 的 `electron/learning-analytics.cjs` 在接纳事件时保存 `recordedAt`（入账时间）和 `occurredAt`（活动时间）。已有「近 7 天知识活动」按活动时间计事件次数，无法直接提供本周新增。首次日期必须先跨历史按 ID 判定，再筛选本周。
- [ ] 若交付版已有可靠的首次登记表，直接使用。否则新增独立、版本化的 `knowledge-first-seen` 投影/账本，不直接改写历史学习事件。正常接纳首条有效事件时与来源登记同一提交写入“学生＋规范知识点 ID＋首次可靠登记时间＋首个来源”；重复导入、复习、重扫均不后移。按来源撤回时保留最小墓碑和原首次日期，仅当该点仍有有效来源时展示；全部撤回后再导入也不算第二次新增。投影必须能从仍保留的接纳事件重建，并对无法重建的旧记录标未知。删除整份学生档案时按现有删除策略处理。
- [ ] 兼容旧账本。首次读取以原账中已接纳事件的最早可靠 `recordedAt` 初始化视图，首次正常写入时持久化；无需启动时全量迁移。某个知识点存在可能更早的无日期记录时标为未知，不能以导入时间、文件修改时间或今天补齐。升级前来源已被物理撤回的旧档，仅能追溯至现存记录，首次使用时在页面说明这一限制。
- [ ] 增加只读统计方法 `getWeeklyKnowledgeGrowth(studentId)`。主进程先验证可信学生范围，再冻结 `asOf`、产品时区、资产库代次、知识账本代次和授权版本；两个指标必须使用这一个快照。读取前后任一代次变化则丢弃结果并重试，不能拼接两个时刻。知识点历史扫描放到后台，优先复用现有知识投影 Worker，返回精简汇总。卡片按需加载，同一学生的并发请求合并。资料入库或撤回后，下次查看重新取数。大档案的读取也应允许用户切换学生、滚动和取消。

**最小返回结构**　成功时包含内部学生标识、生成时间/`asOf`、时区、周起止日、资产库代次、知识账本代次、授权版本、资产总量、周新增、七项日期及其数量、首次日期未知项数和口径版本。未来日数量为 `null`。失败时返回原因码。对外图片由允许展示的字段单独组装，内部 ID 只用于核对归属。

### 任务二　接入周图并确保预览与文件一致

- [ ] 在 `src/AssetCenterPanel.tsx`（或目标版对应的知识中心）挂载独立组件 `src/WeeklyKnowledgeGrowthCard.tsx`。沿用现有学生选择器和皮肤。数据加载、真实零值、缺少学生、读取失败分别呈现；失败可以重试。
- [ ] 用固定版式将统计快照绘为 PNG，只编码一次。预览显示这份图片，保存沿用同一份字节。图中及默认文件名仅含标题、日期、两个汇总、每日数及必要口径说明。图片不带姓名、学校、知识点名称、项目名、源文件路径、ID 或链接。
- [ ] 切换学生、跨自然周或失去授权时清除原图并废弃迟到响应。保存前核对快照学生仍是当前所选学生。本地跨日后重新进入或恢复窗口时更新本周数据；保存按钮在新图准备完毕前保持禁用。旧图片对象 URL 随替换释放。

### 任务三　本地另存为与交付验证

- [ ] 在 `electron/preload.cjs` 和宿主桥类型中新增专用 `saveWeeklyKnowledgeGrowthPng`。在 `electron/main.cjs` 注册处理器，沿用可信宿主窗口、现有许可和学生访问校验。按已有原生保存流程弹出 PNG 对话框，默认文件名如 `每周知识增长_2026-10-26_2026-11-01.png`。
- [ ] 保存端限制 PNG 格式、约定尺寸及合理字节上限，仅向用户选择的文件写入。取消保存安静返回；写入失败保留预览并允许重试；只有写入成功才显示「图片已保存，可在微信中发送」。双击只开一个保存框，学生切换或权限变化发生在弹窗期间时结束过期请求。
- [ ] 对照下表执行统计、跨学生、文件和布局验收。在 Windows 主机用测试档案生成实际 PNG，至少在一部手机查看微信尺寸下中文、数字、零值及日期是否清晰。验证由测试人员使用测试图自行发送，不向真实群组自动投递。

**可复用路径**　`src/main.tsx` 已有图谱的 Canvas PNG 导出示例，`electron/practice-card-export.cjs` 已有原生保存对话框和取消处理。智能出版可参考手机排版；直接调用其整套流程会另写出版索引。这里用专用统计模板，生成结果只写到用户指定位置。

## 四　验收清单

| 场景        | 必须观察到的结果                                                                             |
| --------- | ------------------------------------------------------------------------------------ |
| 双指标对账     | 学生 A 的资产中心无筛选总量为 128，周内七柱合计为 12。图上分别显示「128 项」「12 个」。搜索资产或反复引用同一资产，图片总量不受界面筛选和引用次数影响。 |
| 上周旧点与本周新点 | 旧点在本周出现 4 次仍增加 0；同一个新点在两份资料出现 3 次只增加 1，归入第一次登记当天。                                    |
| 撤回与再导入    | 上周登记的点撤回首条来源、保留第二条本周来源，仍不计本周新增。全部撤回后再导入，已知首次日期不后移。                                   |
| 时间边界      | 周日深夜和周一零点分属两周。跨月、跨年、夏令时切换时仍显示周一至周日七个日期。周三生成时，周四至周日标「—」。                              |
| 无资料和缺日期   | 合法空库得零值；含旧日期不明记录时给出遗漏说明；索引读取失败显示重试，无法导出伪零值图。                                         |
| 多学生与项目    | 将学生 B 的独有资产和知识点加入测试库后，A 的数值不变。共享资产按各自现有归属计。由 A 切到 B 时，即使 A 的读取延迟返回，也只能保存 B 的图。       |
| 图片与保存     | 导出的 PNG 为 1080 × 1920。保存文件与当前预览字节哈希一致；默认文件名、图片正文和元数据不泄露身份。取消不生成文件，失败后能重试。            |
| 性能与回归     | 以目标版代表性大档案记录打开页面和生成图片耗时。读周图不触发资产重建、知识重新消化或全文报告生成。主窗口可持续交互，原有活动趋势及学习卡导出仍通过回归。         |
| 一致性与时区     | 统计期间插入新资产、撤回来源或改变学生授权时，旧响应被废弃并用新代次重算。改变主机时区后旧快照不被改写；新图明确采用新时区，七柱与周合计仍可复算。 |

**建议验证命令**　新增 `tests/weekly-knowledge-growth.test.cjs` 和 `tests/weekly-knowledge-growth-export.test.cjs`。先运行失败用例，再实现并复跑。完成后在目标工作树运行以下检查。

```bash
node --test tests/learning-analytics.test.cjs tests/asset-index-store.test.cjs tests/asset-dashboard-filter-contract.test.cjs tests/practice-print.test.cjs

```

**交付判定**　同一测试学生的资产总量可与资产中心对账，周新增可由首次登记样本逐笔复算，预览与落盘图片一致。提交开发变更时附目标版本、测试结果、匿名样图、手机预览和未通过项。

## 五　与另外两份方案的依赖

1. 本功能可先行交付，用于验证单学生范围解析、同一截止时刻快照、授权变化时废弃迟到响应和安全导出。
2. 首次登记账本只服务“知识库新增”统计；学情模块不得把它直接解释为掌握、方法有效或效率改善。
3. 项目报告可复用本功能的导出权限复验和对象 URL/迟到响应处理方式，但项目材料和项目 Claim 使用独立证据快照。
4. 三个模块共享 `SubjectScope`、`AsOfCutoff`、`AccessProjection` 和口径版本的字段含义；本功能不需要共享复杂的 Finding/Action/ReportRevision 状态机。
