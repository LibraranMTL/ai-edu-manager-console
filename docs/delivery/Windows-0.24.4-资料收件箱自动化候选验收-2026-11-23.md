基线为 Windows 主机版 0.24.3，开发分支为 `codex/smart-inbox-automation-20261123`。本次交付为本地候选，验收日期按北京时间记录。

## 实现范围

| 开发阶段 | 已接入的行为 |
| --- | --- |
| 自动分流与来源复用 | 识别资料性质、学生主体证据、主题标签和项目核验范围。无项目的学习资料可进入学生原始库，召回项目经过竞争核验后可自动投递。纯系统会话可恢复忽略，助手提到其他学生作为引用线索。来源支持单学生智能分类、固定目标和共享来源。共享来源开启自动归属后，正文中唯一的明确学生主体可自动确认，并继续核验分类。 |
| 异常恢复与分组处理 | 找回分类结果后复用原决策、核验当前上下文并继续投递。服务和相关项目上下文变化后恢复符合条件的任务，重新评估原始库的项目关联。跨页问题组支持预览、排除个别项、整组确认、暂停继续和逐项结果。 |
| 人工纠正与规则学习 | 同一学生、来源中的明确项目标识或子目录形成窄规则。三份独立人工反馈后进入观察，五份一致观察且覆盖两个会话或采集批次后自动生效。提供仅本次特殊处理、规则暂停、反例停用和受影响资料复核。 |

每组原件、归属、项目和策略上下文最多使用三次正文分类调用，已完成阶段及同学生同内容结果可复用。尚未发送正文的授权失败不消耗正文分析预算。细分类不确定时保留已明确的学生或项目归集。

历史资料通过“自动处理／问题组 → 试算历史积压”创建预览。预览后确认一次，主机分批复核和处理。既有人工锁定、来源暂停、原件变化与执行待核对均有独立处理结果。

## 接口与兼容

`smartInboxAction` 新增 `groups`、`previewBatch`、`batchDetail`、`controlBatch`、`learnedRules` 和 `pauseLearnedRule`。批任务在收件箱 `batches` 目录持久化，成员、资料版本、来源版本和排除范围在确认时固定。

分类策略升级到 `smart-inbox-routing-v6`，增加可为空的 `assessment`。新模型输出使用严格 JSON Schema，旧结果补齐空评估后继续校验原有候选和正文引用。运行时和模型偏好变化触发分类能力复核。

新增 JSON 字段采用缺省兼容方式。JSON 账本继续作为可恢复状态，SQLite 继续作为查询投影。学生原始库标签保存在收件箱元数据中。

可以分别设置以下环境变量暂停新增能力。

- `EDU_DISABLE_INBOX_AUTOMATIC_TRIAGE=1`
- `EDU_DISABLE_INBOX_EVENT_RECOVERY=1`
- `EDU_DISABLE_INBOX_LEARNED_RULES=1`

## r7 自动回收与处理恢复

### 实现与保留边界

- 新增统一的本机内容判别器，采集后的处理、试算和历史复核共用。固定内部请求、精确匹配的Windows学生端采集测试，以及稳定的0字节或纯空白文本可自动回收。混合真实请求、报告成果、OCR失败、扫描件和普通无项目资料继续保留。
- “自动回收”页提供确定性回收、到期副本清理、技术恢复三个开关。默认保留30天；首次升级给已有自动忽略记录建立保留信息，不提前物理清理。
- 后台每15分钟检查到期记录，每轮最多20项或5MiB，遵守资源门控。清理前检查原件仍可读取、指纹一致、文件位于该记录的受管副本目录，且无其他活动引用、人工锁定或未知执行。原件不可用时保留副本，避免失去唯一恢复来源。
- 持久化清理日志覆盖准备、文件释放和元数据提交；中断后可恢复。用户原件、正式成果、登记回执和原始执行结果不属于到期删除对象。恢复操作取消后续清理并保留记录，防止再次自动回收。
- 分类采用可读消息正文和逐段引用映射，兼容JSON转义与换行；原始文件指纹不变。校验错误分为格式、引用、学生范围和项目范围。非业务、无候选且无主体的返回中，解释性“主体证据”可被丢弃，不能转换为归属证据。
- 有界原始结果保存在本机，先尝试重新验证已有结果，再决定是否重新调用。三次分析预算持久化；同一来源资料更名、来源改名及重启不重置。真正的上下文、执行器或合同变化使用新的核验范围。格式纠正调用同样计入预算。
- 投递明确区分原采集学生、资料主体和目标学生。原会话按采集范围解析，目标按更正后的学生核验；操作标识进入导入与登记记录。已验证登记直接复用，仅明确无副作用且不存在在途操作的记录可以幂等续接，不能凭“找不到回执”重投。
- 批次保留原状态字段，另提供业务结果和技术等待计数。界面显示“全部完成”“已恢复处理中”或“本轮结束，仍有待处理”，不将分类服务失败归为人工指定项目。
