# Windows 统一 Agent 与课程／卡片 R9 候选验收

日期：2026-10-13。版本：Windows 0.21.1 开发候选。候选标签：`unified-agent-cards-r9-20261013`。本记录不等同于正式发布、签名、目标机或用户业务验收。

## 1. 结论

本轮确认“Agent 授权待恢复”包含两个不同问题：

1. 收件箱此前只读取资料行中保存的旧错误 `需要重新登录并检测`，没有读取当前执行器与任务熔断状态。即使检测通过，重新进入页面后仍会把历史失败显示成当前授权失败。
2. WorkBuddy 桌面正常登录不等于后台 CLI 获得认证。本轮桌面自带通道和保留的独立测试配置均真实返回 `AUTHENTICATION_REQUIRED`；没有复制凭据、降低隔离或把失败改写为通过。Codex 当前真实合成分类通过。

R9 已修复第一类状态错误，并按《统一 Agent 调用机制与多 Agent 适配开发方案》落地最小任务档合同：

- `classification_readonly.v1`：Codex、WorkBuddy；固定正文与候选 ID，无工具，宿主校验并投递。
- `digest_host_mediated.v1`：Codex、WorkBuddy；Agent 只返回候选知识，宿主校验、暂存和提交。
- `learning_card_generation.v1`：目前只开放已验证的 Codex；未把 WorkBuddy／TRAE／Qoder 的普通任务能力自动升级为卡片资格。

统一任务中心仍是唯一任务账本。页面状态读取不探测、不发送正文；检测必须由用户明确触发，只使用合成数据。历史失败不会因状态恢复自动重派。

## 2. 本轮实现

### 授权状态与收件箱

- 新增任务档支持矩阵与统一状态：`ready`、`login_required`、`qualification_required`、`cooldown`、`unsupported`、`unavailable`。
- 已登录但熔断仍处于授权阶段时，显示“已登录，等待受控检测”，不再误报“需要重新登录”。
- 检测通过后显示“Agent 已恢复，等待重新分析”；刷新和重新进入仍读取持久熔断状态，不依赖当前 React 内存状态。
- 行内旧诊断改为“历史失败已保留；重新分析后更新结果”，避免与当前可用状态冲突。
- 不自动重派失败资料；用户仍需勾选并点击“重新分析”。

### WorkBuddy 与资料整理

- 资料收件箱的学生／项目智能分类继续允许通过受控 WorkBuddy 分类档执行；只有后台认证、合成资格、执行器版本和宿主校验均通过才发送固定资料正文。
- 受管项目资料消化不再因项目类型硬编码 Codex，优先采用项目已配置且支持 `digest_host_mediated.v1` 的 Codex 或 WorkBuddy。
- Agent 不取得文件移动或知识目录写权限；原件、学生范围、资料版本、目标项目及知识提交继续由宿主验证。
- TRAE、Qoder 等尚未完成对应任务档真实验收，仍保留原任务中心适配／人工交接，不自动获得学生资料资格。
- 旧式学生原始资料库“目录消化”尚未迁移为 WorkBuddy 宿主提交链路；本轮所称“学生资料自动整理”指统一收件箱内的分类、投递以及投递到受管项目后的受控消化，不扩大为 Agent 任意整理学生目录。

### 学习卡片与统一发布

- 保留已有“提示／公式不一致时最多自动修正一次，再独立复核”的质量闭环。
- 修复卡片生成直接调用 Codex、绕过任务熔断和重任务资源准入的问题；现在生成与复核均检查 `learning_card_generation.v1` 状态，并共用后台重任务名额。
- 后台正在处理资料时，卡片生成明确等待，现有卡片不变；授权未通过时给出任务档状态原因。
- 课程／卡片阶段一的本地发布、学生范围、版本固定、撤回后历史可读、作答与反馈、平台包 worker 回归通过。本轮没有把云市场、支付或未验收的真实设备项目冒充完成。

### 万条任务性能

- 任务 Worker 对同一不可变账本快照建立派生读索引，缓存白名单摘要、总览、执行器和排序结果；新持久快照通过对象身份自动失效。
- 合成 10,000 条任务：首次建索引 `22.61 ms`；随后 200 次筛选／分页查询 P50 `0.08 ms`、P95 `0.17 ms`、最大 `0.58 ms`。
- 仍保留每次持久写入完整任务账本的现有机制；本轮没有把读性能数据冒充写入性能或四小时低配机稳定性结果。

## 5. 方案评估

结合统一 Agent 方案进行修复是合理且必要的，但应分阶段落地。R9 完成的是任务档、统一状态、分类调用和受控项目消化选择这一最小切片；完整的 `Provider.describeCapabilities / qualify / invoke / getStatus / cancel` 抽象、按执行器哈希持久保存资格、研究任务迁移以及其他厂商真实验收仍未全部实现。

这样处理的用户价值是：授权提示可信、失败不丢资料、恢复后操作明确、用户配置的 WorkBuddy 可在合格时用于分类和受管项目消化；同时不会为了“多 Agent”而给未验收执行器学生资料权限。运行效率方面，状态读取零模型调用，卡片与资料处理共享重任务准入，万条任务翻页不再重复构建全部摘要和排序。
