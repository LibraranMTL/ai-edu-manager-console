# Windows 分类 Agent 恢复与备用切换 R13 验收报告

> 此候选已由 R14 取代。R13 要求用户选择官方 CLI 目录，且对旧认证失败记录采取了过度保守的未知执行判断；请使用 [R14 验收报告](Windows-分类Agent恢复与空间优化-R14-验收报告-2026-10-13.md)。

日期：2026-10-13。Windows 0.21.1 开发候选，最终标签 `smart-material-agent-recovery-r13d-20261013`。

## 实现

- 分类备用策略存于学生记录，已有学生默认关闭；在资料收件箱可明确允许另一个 Provider 处理该学生资料。学生信息同步保留此策略，启用/关闭操作使用版本及请求幂等校验。
- 统一分类路由最多尝试主、备各一次。合成资格不通过可切换；正文发送前持久化 `possibly_sent`，发送后超时、网络错误或本地进程退出均不触发备用重发。敏感拒绝不绕过。
- 资格按 Provider、任务档、运行程序、调用合同、认证目录及授权版本隔离。并发资格请求合并；成功30分钟、失败5分钟；登录完成继续操作更新认证版本并恢复符合条件的批次。
- 官方登录使用持久的 `classification-auth/workbuddy-profile`，实际分类使用相同环境。缺少官方完整登录模块时提示选择已下载的官方完整 CLI 包目录；不复制桌面凭据、不打包认证目录。官方登录没有可靠结束通知时，用户点击“我已完成登录，继续”。
- 列表返回结构化阻塞原因，不再通过中文错误文案判断项目是否需要人工确认。恢复入口保留手动指定项目和移除待办。
- 自动恢复排除暂停来源、忽略、人工锁定、未知执行、原件失效和学生范围冲突。切换复用当前学生与当前版本的提取缓存。
- 旧认证失败记录在迁移前复制至 `smart-inbox/migration-backup-agent-v2`；没有发送阶段证据的历史记录保留待核对，不自动重派。迁移标记为 `agent-recovery-migration-v2.json`。

第一轮全量回归有1条旧界面文案断言失败，已更新为新的恢复入口与结构化状态契约，重跑通过。R13和R13b中间包的ASAR运行程序指纹检查失败；Electron虚拟条目的时间字段不能作为普通原件的稳定性证据，修正为真实外层归档元数据与条目内容哈希校验后通过。R13d进一步将CMD包装器引用的原生程序纳入资格指纹。早期真实探针遗漏Windows命令桥接及VM的Buffer，探针修正后使用包内真实桥接完成验证；这些探针错误未误记为厂商授权失败。R13/R13b/R13c均被最终R13d替代。

WorkBuddy正常完成学生资料任务的验收仍未通过：本机正式后台认证仍需用户官方登录。本轮通过的是“实际认证失败→受控Codex备用→宿主投递”的真实异常恢复链路，不宣称WorkBuddy认证问题已由代码替用户完成。

## 性能与未通过门槛

开发机为12逻辑CPU、63.8GiB内存，不是四核/8GB目标机。

- 10000个历史文件和10000条收件箱记录，无变化扫描三次约502–558ms；正文读取、提取/OCR、Agent及内容哈希均为0。
- 增加10份资料仅提取/分类10份；扫描中列表查询P95约1.99ms，宿主RSS增量约44.45MiB（加载加扫描约52.71MiB）。
- 10000任务账本并发完整写入时，查询P95约987.27ms，耐久写P95约1092.21ms；进度日志P95约2.19ms，确认未重写完整账本。该存储压力指标不等同UI延迟，但不能作为≤300ms验收通过证据。
- 四核/8GB/SSD前台P95及相对劣化、四小时混合运行、真实提取进程与外部Agent资源、200份独立标注质量、5名代表用户效率测试尚未完成。未以开发机短测或测试分类器代替这些门槛。
