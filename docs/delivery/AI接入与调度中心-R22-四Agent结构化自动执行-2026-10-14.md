# AI 接入与调度中心 R22：四 Agent 结构化自动执行

## 交付状态

R22 是基于 Windows `0.21.1` 的本地候选包，候选标识为 `ai-control-r22-structured-agents-20261014`。本次没有更新公网下载，也没有声明代码签名或四家 Agent 的真实账号环境验收完成。

## 本轮变化

OpenClaw、QClaw、TRAE、Qoder Work 已接入统一的结构化执行接口，并可按任务类型开放自动能力：

| 任务合同 | R22 状态 | 关键限制 |
| --- | --- | --- |
| `classification_readonly.v1` | 可自动 | 只读分类结果，宿主校验结构 |
| `digest_host_mediated.v1` | 可自动 | 宿主管理输入、结果与正式写入 |
| `learning_card_generation.v1` | 可自动 | 结构化卡片结果，宿主验证后保存 |
| 联网研究 | 未开放 | 缺少四个通道逐一验证的研究合同 |

只有发现可非交互调用的 CLI／运行时，并针对“执行器 + 任务合同 + 运行时／配置指纹”完成合成资格验证后，执行器才进入自动候选。仅安装桌面端或只有网页入口时仍显示为手工交接。

## 调度与安全边界

- 默认顺序仍由统一调度中心管理；任务能力差异由执行器注册表过滤。
- 前一执行器只有在证明请求未发送时才会进入下一执行器。
- 未知结果、取消、授权变化、非零退出或可能已经发送时停止回退，防止重复生成。
- 四个 Agent 均明确未发送后，允许继续尝试已配置的 LLM API。
- 自动执行器全部失败后只生成一次手工交接，不连续打开多个应用。
- 学生、项目与允许操作仍由宿主绑定；Agent 返回内容不能直接越过宿主校验写入正式数据。

## 升级与迁移

R22 不重置全局授权、调度顺序、学生／项目归属、现有任务执行身份或 LLM API 密钥。已有运行中、结果未知及等待手工交接的任务继续保留原执行身份，不因新增自动执行器而重新派发。新增自动资格是可撤销、可过期的运行时状态；执行器路径或配置发生变化后必须重新验证。
