# 教育管家档案架构升级说明

版本：Windows 0.6.8 起，0.6.9 补充知识贡献发布闭环

## 升级目标

本次升级采用渐进式方式，把现有学生知识库、资料上传、学情报告和主机 API 保持兼容，同时新增四层能力：

- 文件资产中心：为导入和上传文件建立资产索引、SHA-1 指纹和引用关系。
- 学习项目知识空间：让短期学习项目拥有独立的 LLM Wiki 知识空间。
- 知识贡献申请：项目完成后用 Markdown 贡献报告替代简单文件夹合并。
- Growth Layer：把学情报告升级为成长模型输出，而不是普通摘要文件夹。

## 已实现范围

### 文件资产中心 v1

- Windows 手动导入、平板上传记录、多资料来源导入会同步登记资产。
- 资产记录包含文件名、SHA-1、大小、类型、物理路径、所属学生、引用空间、来源和更新时间。
- Windows 端新增“文件资产中心”高级视图，可按学生、关键词、重复文件筛选。
- 支持扫描历史上传记录和学生原始资料库，为旧文件补建资产索引。

### 学习项目知识空间 v1

- Windows 端新增“学习项目”对象，可绑定学生。
- 创建项目时自动生成用户项目空间和项目知识空间。
- 项目知识空间使用 LLM Wiki schema：项目原始资料库、概念库、实体库、摘要库、问答精华库、综合汇总库、项目报告、知识贡献。
- 可从资产中心选择文件加入项目，建立项目引用并复制到项目原始资料库。
- 项目资料不会自动写入学生主档案。

### 知识贡献申请 v1

- Windows 端可为项目生成 Markdown 形式的“知识贡献申请”。
- 报告包含项目概况、资产清单、建议归档项、成长证据、冲突检查和 Agent 执行指令。
- v1 不自动覆盖学生主档案，由管理员复制给 Agent 或人工确认后执行。

### Growth Layer v1

- Windows 端新增“成长模型”入口。
- 可为学生补建“成长模型”目录，包含 `index.md`、`能力画像.md`、`成长证据.md`、`项目贡献.md`。
- 学情报告模板增加成长证据来源和项目贡献来源字段。
- 后续报告生成优先引用成长模型、综合汇总库和项目贡献记录。

## 0.6.9 下一阶段补充

- 文件资产中心菜单已调整到左侧“智能体知识管理”之后，作为更偏底层的管理员工具入口。
- 学习项目增加“发布到成长模型”动作：
  - 自动生成或读取该项目的知识贡献申请。
  - 将发布记录追加到绑定学生的 `成长模型/项目贡献.md`。
  - 将成长证据占位记录追加到 `成长模型/成长证据.md`。
  - 在学生综合汇总目录下维护 `项目贡献汇总.md`。
  - 项目状态标记为 `published`。
- 发布动作只记录来源和待整理事项，不移动、不删除、不覆盖项目文件和学生主档案内容。

## 0.7.0 归档确认闭环

- 学习项目新增“归档确认清单”：
  - 文件条目支持 `引用 / 吸收 / 跳过`。
  - 知识条目和成长证据条目支持 `发布 / 跳过`。
  - 执行前由管理员逐项确认，不自动推断覆盖。
- 执行归档后自动写入：
  - 学生综合汇总目录：`项目归档记录.md`、`项目贡献汇总.md`。
  - 学生成长模型：`项目贡献.md`、`成长证据.md`。
  - 项目知识空间：`知识贡献/归档执行日志.md`。
- `吸收` 动作会复制文件到学生原始资料库并重新登记资产引用。
- 文件资产中心新增：
  - 资产引用详情。
  - 重复文件分组提示。
  - 重复治理仅提示，不自动删除物理文件。

## 0.7.1 管理体验增强

- 归档确认清单增加批量动作：
  - 文件全部引用、文件全部吸收、知识全部发布、全部跳过。
  - 执行前显示将写入的目标、发布/引用/吸收/跳过数量。
  - 执行后显示成功、失败和各动作数量摘要。
- 学习项目增加状态流转：
  - 草稿、进行中、待归档、已归档、已发布、已封存。
  - 项目详情显示状态、更新时间、归档时间和发布时间。
- 文件资产中心增加治理筛选：
  - 按学生、来源、文件类型、重复 SHA-1 组合筛选。
  - 补建资产索引会扫描学生原始资料库和项目原始资料库，便于登记旧目录中的历史文件。

## 0.7.2 多学生项目绑定

- 学习项目创建时支持一次绑定多个学生，符合“一个学习项目可服务一个或多个学生”的原始架构设计。
- 已创建的学习项目可在项目详情中继续调整绑定学生，调整后归档确认清单和发布目标会重新按最新绑定关系生成。
- 项目知识空间新增自动维护的 `绑定学生.md`，记录当前绑定学生及其学生知识库、原始资料库和学情分析汇总路径。
- 更新绑定学生时不会自动覆盖 `AGENT.md`，避免破坏用户或 Agent 已经调整过的工作协议。

## 0.7.3 研究暂存层 v1

- 学习项目详情新增“研究暂存层”，可先导入论文、网页快照、截图、候选素材等项目研究资料。
- 暂存资料默认只写入项目工作空间下的 `研究暂存` 目录，并维护 `staging-index.json` 与 `研究暂存清单.md`；未晋升前不会进入正式文件资产中心。
- 暂存资料支持生命周期状态：已收集、已初筛、选入分析、已分析、已晋升、已归档/丢弃。
- “晋升为正式资产”会把选中的暂存资料复制到项目原始资料库，并登记为项目资产引用；随后才参与项目资料消化和知识贡献流程。
- “丢弃/归档”只更新状态，不删除物理文件，便于后续追溯研究筛选过程。

## 兼容策略

- 不改变现有学生 `rootPath`、`rawPath`、`summaryPath`、`agentPath` 含义。
- 不改变平板上传到学生原始资料库的路径。
- 不移动、不删除旧文件。
- 资产中心 v1 使用 JSON 索引，不引入数据库。
- 平板端暂不开放项目管理，只消费学生档案和已发布报告结果。

## V2.1 架构补充：研究暂存层与知识资产晋升机制

### 新增目标

在现有“文件资产层（Asset Layer）→ 知识层（Knowledge Layer）”之间增加“研究暂存层（Research Staging Layer）”，用于处理项目研究过程中大量临时参考资料、AI搜索结果、网页、论文、截图和候选素材。

该补充的核心判断是：并非所有研究资料都应立即进入正式文件资产中心。项目资料应先进入研究环境，经过筛选、引用或知识化处理后，再晋升为正式资产，避免文件资产中心长期积累低价值、重复或未使用资料。

### 新增分层

```text
Research Staging Layer
研究暂存层

        ↓

Asset Layer
文件资产层

        ↓

Knowledge Layer
LLM Wiki知识层

        ↓

Project Insight Layer
项目洞察层

        ↓

Growth Layer
学生成长模型
```

### 研究暂存层职责

研究暂存层属于项目工作区的一部分，主要用于资料收集、初筛和生命周期管理。典型内容包括：

- 网络搜索资料、在线论文、参考案例。
- 临时截图、网页快照、AI搜索中间结果。
- 未阅读文献、候选数据集、视频或图片素材。

这些资料默认不进入学生长期知识库，也不默认成为正式文件资产；系统可以对它们进行批量筛选、去重分析、来源记录和自动清理。

### 资产晋升机制

正式资产采用生命周期管理：

```text
Collected
已收集

↓

Screened
已初筛

↓

Selected
已选入分析

↓

Analyzed
已完成AI分析

↓

Promoted
已晋升正式资产

↓

Archived / Discarded
归档或清理
```

只有满足以下条件之一时，资料才进入正式文件资产中心：

- 被项目正式引用。
- 被 AI 分析实际使用。
- 支撑项目结论。
- 被教师确认。
- 被学生标记为重要。
- 成为最终成果组成部分。

### 来源保存策略

- Full Copy：保存完整文件。适用于原始数据、最终作品、教师反馈、官方文档。
- Reference Only：仅保存标题、作者、URL、发布时间、获取时间等来源信息。适用于网络文章、在线论文、官方网页。
- Snapshot：保存关键页面或关键片段。适用于新闻页面、长网页、在线课程内容。
