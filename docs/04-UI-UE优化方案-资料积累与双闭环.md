> 编制日期：2026-09-26

> 范围：Windows 主机、Android 家庭单机版及学生/教师终端的导航与体验协同。各端根据实际能力和权限提供入口。  
> 本轮交付：仅修订本方案；不修改 Demo、正式程序、数据协议、执行看板或发布状态。下文涉及规则和协议的内容均为后续开发要求，不代表本次已经实现。

## 1. 核心决策

建议按用户任务重新组合菜单，使用“简洁导航 + 少量明确操作按钮 + 资料列表与预览 + 情境化下一步”的界面结构。

教育管家的界面应让用户看清三件事：最近积累了什么，系统整理出了什么，现在可以做什么。

产品以学生长期资料与知识积累为共同基础，支持两条应用闭环：

1. **日常学习**：资料收集 → 学情分析与知识掌握跟踪 → 建议、提分卡与题目 → 练习反馈与复测 → 更新档案。
2. **长期发展**：资料积累 → 兴趣与问题发现 → 研究与实践项目 → 作品和成果 → 升学、专业探索及职业发展 → 新经历回到档案。

近期主题为**可信判断、行动回流、交付减负**。首页与资料详情仍是体验入口，但实施优先级不以页面顺序决定：先纠正判断和统计口径，再贯通一条真实服务链，随后验证机构与家庭能否低成本持续使用。

本次修订保留五个主要入口，增加从学生身份区直达的个人教育档案总览。发展目标归属于个人档案，可关联多个项目、成果与学习记录；不要求先创建项目才能进行学科或专业探索。

八个 Demo 单元保留为总体覆盖地图，不再作为下一次迭代必须同时扩展的范围。下一版原型先证明“同一份证据怎样改变下一次帮助”，不能仅以页面齐全、按钮可点击或新增反馈列表宣称闭环完成。Demo 展示、源码实现、候选包、真机验收与正式发布分别管理。

本次在 v1.2 战略与分期基础上补齐功能迁移审计，不推翻既有取舍。**AI 会话自动采集与 AI 对话收件箱是两项核心工作能力，不是普通导入按钮或助手配置的附属项。** 下一版 Demo 将二者列为必须补齐的重点：授权后持续采集、会话接收与归属、原文阅读、知识候选及资料投递必须可连续体验。原型补齐不等于正式产品新增全端采集能力，也不要求其他所有扩展同时开发。

本次继续保留 v1.3 版本号，按复评补入文件夹自动投递、Agent 调用授权与审批、跨 Agent 记忆/人设/规则、团队知识查询、项目定向发布、自动整理与维护六项能力，以及八类端侧细项。新增迁移行是保留已有能力，不是新建六个一级菜单；文档补全不等于 Demo 已覆盖或旧入口可以立即删除。

### 1.1 修订取舍

- 采纳：个人总览、情境化再利用、目标独立归属、资料角色、跨闭环连接、线下反馈、功能迁移清单、视觉与端侧规范、完整原型验收。
- 保持简洁：不为论文、图书、专利、升学和求职分别增加一级菜单；通过项目/成果类型和发展目标类型承载。
- 限定自动化：基于明确来源提出少量建议，用户可采用、调整、忽略；不自动替用户立项、确定专业、提交申请或宣称成果已获认可。
- 复用既有基础：新界面复用学生、资料、项目、引用和学习事件，不另建平行档案或重复调度系统。完整事实记录仍由主机/单机代码维护，Agent 负责理解与候选建议。
- 前置可信度：掌握判断、资料/成长计数、证据范围和反馈归属作为发布门槛，不能用更换文案掩盖后台规则问题。
- 按服务任务排序：日常辅导客户突出学习行动，项目服务客户突出当前项目与成果；不要求每位用户的首页同时等权展示两条路径。
- 不以新增功能证明价值：先验证已有能力的持续使用和交付成本，再决定音频、自动出题、申请素材及通用 Agent 能力的扩展。
- 不以简化导航删除能力：既有研究暂存、资产治理、知识贡献、任务协作、课程管理和会话采集/收件箱必须有明确归属；原型未覆盖如实记录，正式重组未完成时保留旧入口。
- 自动化不退化为手动搬运：受支持且已授权的会话正常后台接收，用户只处理必要接入确认、归属异常和既有高风险确认；粘贴、分享链接和文件导入是独立备用路径。

### 1.2 战略依据与商业起点

采用[战略研究报告 v1.1](../../../output/research/AI-education-strategy-2026-09-26.md)的近期决策：未来 6–12 个月以教育产品交付、持续使用和学生价值验证为经营主线，在同一产品中积累可信个人数据与跨 Agent 能力，不另起通用数据底座或完整数字分身产品线。

- 用户确认温州培训机构购买 30 套、已有家庭购买，并与面向中小学的推广机构签约；这是已发生的商业基础，不能表述为尚无客户。
- 深度价值实验学生约 3–5 人，仍在验证。30 套成交不等于 30 名活跃学生，更不等于 30 个有效实验样本；渠道签约不等于已完成部署和转化。
- 本次沿用报告中的证据口径，没有重新审计销售或读取合作合同。家庭项目服务的购买不能直接折算为纯软件订阅价格。
- 近期优先验证：学生得到什么帮助、家长付出多少操作、普通教师能否独立交付、服务人员每生每周花费多少时间。功能数量与报告数量不替代这些结果。

## 2. 产品定位与客户价值

### 2.1 对外定位

**AI教育管家，持续整理孩子的学习与实践资料，帮助看清学情、改善学习，并把长期积累用于研究成果和未来发展。**

客户价值分为三层：

| 层次 | 客户得到什么 | 典型用途 |
| --- | --- | --- |
| 日常用得上 | 资料有序、便于查找，理解学情并获得下一步建议 | 作业整理、学情报告、复习与针对性练习 |
| 长期做得成 | 从积累中发现问题，持续推进研究、创作与项目 | 研究课题、论文选题、参赛项目、图书、发明构想、创业项目 |
| 关键时刻拿得出 | 真实经历、作品、过程和反馈可被重新组织 | 升学规划、学科与专业选择、个人陈述、简历、奖学金及求职申请 |

“背景提升”具体体现为真实项目、作品和实践经历的持续积累。AI 提出的方向、尚未完成的项目和已经完成的成果应明确区分；发明构想不等于获得专利，建议方向不等于已验证的能力结论。

### 2.2 与 StudyFetch 的定位关系

基于本次讨论所查阅的官方资料，StudyFetch 主要围绕课程材料提供整理、辅导、练习和学习计划。教育管家应围绕学生跨课程、跨项目和跨工具的长期积累组织体验。这是重心差异，不能表述成对方没有整理、引用或持续跟踪能力。

本地优先、来源可查、学生隔离、档案可迁移和 Agent 可替换，是长期托付的基础。界面优先呈现可理解的实际成果，技术细节放入适当的详情或设置。

### 2.3 外部分析带来的设计启发

用户提供的人人都是产品经理文章主要讨论 StudyFetch 的短视频和创作者增长策略。对本方案的启发是：在真实场景中清楚呈现输入、处理和结果，让用户迅速理解用途。

本方案据此提出“输入资料—整理成果—后续使用”的呈现方法。这属于本项目的设计推论，不是文章提供的教育管家菜单方案。文中用户量、收入和传播数据不作为本项目设计或教育效果的验证依据。

## 3. 当前基线与主要问题

本节根据本次讨论期间查阅的本地源码、手册和更新日志整理，不等同于各端完整真机验收。工作区存在其他开发修改，实施前须重新冻结目标版本。

| 当前观察 | 对用户的影响 | 优化方向 |
| --- | --- | --- |
| Windows 首页已有添加资料、处理中、需要补充、知识更新、成长变化、报告与档案六个步骤 | 正常流程和异常处理并列，用户容易把补充资料理解为必经步骤 | 异常独立提示；主流程围绕收集、整理成果和使用 |
| 首页同时显示流程数量及多张相近统计卡 | 数量重复，具体整理价值不够突出 | 压缩统计，突出可直接打开的成果 |
| “教育档案”包含建档、成长模型、报告和学情资料 | 管理动作与阅读/分析内容混合 | 建档归学生管理，内容按资料和学情重组 |
| “智能体知识管理”包含对话、采集、记忆及配置 | 用户需要理解技术模块才能寻找操作 | 按采集、资料和配置用途分流 |
| Android 已有按钮式入口，仍包括 OCR、消化等技术词 | 换成按钮本身不足以降低理解成本 | 调整文案、任务顺序和操作后反馈 |
| 档案分类主要按原始资料、摘要、问答、概念、报告等结构展开 | 按学科、主题、时间查找不够直接 | 增加组合筛选与关联浏览 |
| Windows 首页存在用已处理数量兜底显示成长变化的表达 | 资料处理可能被误读为能力变化 | 分别显示处理结果与有证据的变化，不混用计数 |

当前有文件、拍照、屏幕和对话采集，以及资料加工、项目知识、成长与报告基础。录音完整流程、通用学科筛选、提分卡与自动复测、选题发现和申请材料工作流，不因本方案出现而视为已经交付。

### 3.2 必须闭环的评估发现

下表中的“现状”是评估证据，不是已完成修复。产品缺陷与独立 Demo 缺陷不得互相套用。

| 编号 | 对象与现状 | 必须达到的结果 | 改动性质 |
| --- | --- | --- | --- |
| R01 | 产品规则反例：单条记录、提示等级 4、无独立/迁移证据，三个已记录维度为 4，仍得到“基本掌握”、低复测优先级和 21 天后复测 | 该反例停留在需独立核验；基本掌握及更高状态均有证据条件，复测优先级不因辅助高分降低 | 主机规则及回归测试；不是文案修复 |
| R02 | 产品首页用已处理资料数兜底“成长变化”；证据数量与变化混用 | 处理量、证据量、可比较变化独立定义，零证据不兜底，个人/全体范围明确 | 聚合口径及 UI |
| R03 | 产品知识轨迹主要呈现知识点/事件/来源 ID，复测仍为文字建议 | 先读懂变化与行动，再一键回查可用原件；不可达给出准确原因；提交结果能关联原行动 | 视图、定位接口及行动合同 |
| R04 | Android 资料页仍由用户衔接 OCR、视觉解析、消化等步骤 | 已支持资料类型走自动处理；未支持或失败有明确下一步，不以隐藏按钮冒充自动化完成 | 端侧调度、能力检测及 UI |
| R05 | 产品首页重复流程/统计，技术模块较多；Demo 手机首屏行动靠后 | 结果与一个主行动优先，技术配置降权；手机首屏可见具体行动，不以零横向溢出作为体验通过 | 信息架构及响应式布局 |
| R06 | Demo 看过提示后同题重做，被标为独立作答 | 保留答案暴露与同题历史，“本轮未点提示”不等于未受辅助 | Demo 状态及正式作答合同 |
| R07 | Demo 英语历史报告推荐数学练习，英语项目助手取了无关资料 | 同学生内也严格绑定报告、知识点、项目和选材范围，缺证据不借用其他内容填充 | 上下文解析、引用及回归测试 |
| R08 | 机构与家庭的持续交付尚缺普通使用者验证，云同步仍为候选 | 先验证一条真实交付链及人工成本，不能将送达报告等同完成辅导 | 机构工作视图、试点与真机验收 |
| R09 | Demo 将 AI 对话缩减为“主动保存”弹窗，缺少自动采集工作页与对话收件箱 | 分开呈现授权接入、会话接收、归属、知识候选和投递去向；手动导入不能代表自动采集 | 核心功能迁移与原型补齐 |
| R10 | Demo 整理过程中刷新，会将处理中资料直接标为已整理；已用部分失败样例复现 | 恢复实际模拟任务状态，失败与部分成功不被刷新清除，不为消除等待图标伪造成功 | Demo 状态恢复；不据此认定正式程序有同样缺陷 |
| R11 | Demo 代码中新增事件列表替代初始资料时间线；路由切换统一回顶部，未保存输入缺少保护 | 历史与新事件按同一索引合并、可下钻；返回恢复位置，退出编辑保留草稿或提示 | Demo 档案与导航状态 |
| R12 | Demo 目标草稿把资料摘要统一放入“支持的事实”，未组合成果与本人贡献 | 按片段角色和事实核实状态选材，AI 建议不转成个人成就；直接引用成果及贡献记录 | 证据选材与申请素材状态 |
| R13 | Demo 所有纸上回收使用同一提交标识，第一次以后新的作答也可能被当重复 | 同次重传幂等，不同练习/版本/作答与复测分别记录 | Demo 作答身份；正式合同独立验收 |
| R14 | Demo 将阶段成果条目按顺序显示为版本，缺少同一成果的版本关系和贡献字段 | 成果身份、版本、原件、日期、贡献者和反馈可区分，阶段完成有对应依据 | 成果模型的原型表达 |
| R15 | Demo 实测存在 13px 按钮文字、42px 按钮和 38px 图标按钮；部分移动入口与宽屏核对结构未落实 | 按第 8 节校准可读字号、44×44 点击区域、课程触达、批量操作、并排核对及长任务页面 | 视觉与交互回归，不只检查溢出 |

R01/R02/R06/R07/R10/R12/R13 属于可信度门槛；R03/R04/R08 决定最小服务链是否能交付；R09/R11/R14/R15 涉及功能迁移与体验完整性。R10 和 R15 含本轮前序浏览器实测，R11–R14 主要来自 Demo 代码核查；本次文档更新未重新运行这些测试，也未修复相关问题。各项验收与后续实施阶段见第 9、10 节。

### 3.3 当前 Demo 的功能完整性结论与缺口

当前独立 Demo 已验证五导航、浅色深绿视觉、学科浏览、核心学习与项目路径，但只能称“核心场景原型”，不能称“全部原有功能已迁移”或“方案全面验收通过”。页面数量、跨尺寸检查通过、没有运行错误，不替代功能与连续任务验收。未接真实 AI/录音/同步是合法演示边界；缺少业务入口、数据关系与模拟状态则是原型缺口，不能以未接后端解释。

两条闭环的补齐重点：日常从“记录一次练习”推进到“新证据改变下一次帮助”；长期从“关联项目与目标”推进到“成果原件 → 本人贡献 → 核实/反馈 → 个人档案 → 多目标复用”。模拟数据也须维持同一对象与前后状态，不能用固定报告永远推荐同一道题，或把所有资料摘要改写成申请事实。

### 3.4 v1.3 复评补全范围

复评发现的是方案粒度不足，不新增正式产品缺陷结论：六项已有能力虽可归入泛称模块，却缺明确操作与验收，现单列 M26–M31；八类细项通过第 4.4.2 节补回原矩阵。AI 会话、自动文件投递、Agent 调用权限是三种不同授权；团队查询、档案同步、项目发布、任务附件、云报告是不同作用范围，不能借“统一”删掉差异。源码和手册是本次迁移依据，不等同每端真机通过。

## 4. 信息架构与菜单重组

### 4.1 五个主要入口

| 主入口 | 用户目的 | 二级内容 |
| --- | --- | --- |
| 首页 | 看最近积累和下一步 | 最近整理成果、学情建议、进行中的项目、最近查看 |
| 收集与整理 | 把资料交给系统并了解处理状态 | 收集概览、添加资料、AI 会话自动采集、AI 对话收件箱、自动收集/文件夹投递、研究待筛选、整理队列与自动整理计划 |
| 资料与知识 | 查找、阅读和复用积累 | 全部资料、学科/主题筛选、各类知识与对话、收藏/资料集；有权限端的资产治理、跨工具记忆整理、健康检查与维护；统一知识查询 |
| 学情与学习 | 看清学习情况并采取行动 | 学情报告、知识点表现、成长依据、行动建议；后续接入提分卡、练习和复测 |
| 项目与成果 | 推进研究实践并保留成果 | 我的项目、项目资料与知识、过程记录、作品成果；后续接入候选选题及个人发展目标快捷入口 |

辅助常用入口为“精选课程”，设置固定在导航底部。协作按具体项目/资料提供入口，设备与同步配置放入设置。辅助常用入口可以保持可见，不强迫高频课程用户经过多层页面。

“查看个人档案”固定在当前学生姓名/头像旁，与学生切换分为两个明确动作；个人档案内提供发展目标、档案导出和管理入口。首页也保留文字快捷链接，避免将产品核心藏在头像菜单中。

收集页二级导航必须直接包含“AI 会话自动采集”和“AI 对话收件箱”，不可收进“其他采集方式”或只放设置；手机收集页同样有带名称的入口。自动采集负责持续接收，收件箱负责查看、归属与处理，资料与知识负责长期检索和复用，三者引用同一对话记录。“AI 助手”是基于资料提问的另一能力，不能替代采集页或收件箱。

| 知识协作 | 项目/内容的协作操作；设置中的连接与同步 | 业务协作和设备配置分开呈现 |

| 项目工作空间/知识空间、知识贡献 | 项目与成果 → 资料与知识/成果；个人档案 → 成长证据 | 保留双空间语义与多学生贡献，不能用普通资料集替代 |
| 教育内容智能出版 | 报告/成果 → 导出与出版 | 保留忠实版/整理版、模板和格式范围，不改写原报告 |
| 自动投递文件夹 | 收集与整理 → 自动收集 → 文件夹自动投递 | 保留目录授权、目标绑定、立即检查及队列；学生个人/共享端限制不变 |
| Agent 调用授权与待审批操作 | 设置 → AI 与授权；首页异常/任务中心 → 待审批操作 | 只读、受控写入授权与单次审批分开，不能混入会话采集开关 |
| 跨 Agent Memory/Soul/规则操作 | 资料与知识 → 跨工具记忆整理；设置 → 人设与规则 | 保留来源导入、比较、编辑、合并、适配与迁移预览，不只剩只读内容 |
| 本机团队/远程团队知识查询 | 统一知识查询 → 范围选择；设置 → 查询策略 | 管理端可按现有授权扩大范围，学生端不显示团队入口 |
| 项目定向发布、协作附件收件 | 项目详情 → 发布给协作节点；任务详情 → 附件与成果 | 保留映射节点选择、发布包状态及附件采用/拒绝；不以云报告同步替代 |
| 定时整理、周期报告和知识库维护 | 收集 → 自动整理计划；学情 → 周期更新；资料管理 → 健康检查 | 保留自动运行开关、运行条件、任务账本与维护报告，复用既有调度 |

发展目标归属个人档案：个人总览提供主入口，项目与成果提供同一页面的快捷入口或页签，不复制目标记录。目标可在没有项目时建立，可引用不同学科、反馈、项目和成果。目标流程成熟且使用频率证明有必要时，再评估独立导航。升学、奖学金、求职等采用目标类型，不分别新增一组一级菜单。

### 4.3 导航与上下文规则

- 页面顶部持续显示当前数据范围；个人页面显示当前学生，项目页还显示项目及成员/归属。获准团队查询明确显示团队范围，不能挂单个学生标题暗示个人结论。
- 学生是数据范围，家庭/教师/机构工作视角只是展示差异，不新增复杂角色系统，也不改变既有权限。
- 多学生管理端支持全部学生概览，进入个人学情时明确定位单个学生。
- 切换学生清空界面中的上一学生搜索结果、详情和助手上下文；未提交输入先提示或按原归属保存草稿，不暗中丢弃或重绑。既有教师端隔离缓存不因切换学生删除；共享学生退出规则见第 4.5.1 节。
- 搜索、收藏和历史入口都跳到同一个资料详情，不维护重复副本。
- 列表进入详情再返回时保留筛选、滚动位置；旧导航入口可兼容重定向至相同对象。

### 4.5.1 终端进入、退出与离线缓存

个人学生终端沿用主机绑定的学生；共享终端在 ID/扫码进入前不显示学生名单，不开启持续文件夹自动投递，也不开放个人终端会话自动采集。连接有效不等于已进入学生空间，主机连接页与学生进入页应区分。

采集开始冻结学生与目标，采集中不能换人或退出；结束后也不能把该批资料改投给下一位学生。主动退出/超时后按原合同清空学生会话可见的报告、项目列表、正文及待传状态，处理中的资料按原归属结束或明确取消，不能随新登录继续。个人终端解绑/改绑亦需校验原队列，不静默转交新学生。

Android 教师端的既有缓存按学生/项目隔离，切换学生或断开主机不等于删除缓存；离线只展示此前成功读取且按当前访问规则允许的内容，标明缓存时间，重连后刷新。缓存不授予新的学生或发布权限。学生共享退出清理与教师持久缓存不得共用一条全端规则；设备撤权后的缓存处置沿用各端合同并单独验收，不推测断网缓存已被远程擦除。

连接备份只恢复受支持的连接配置，不能替代共享学生登录，也不能将教师连接备份当学生端配对使用；局域网/远程连接、邀请确认、到期与重连均保留可见状态。纯布局角色切换不改变上述身份和权限。

### 4.6 机构交付工作列表

Windows 管理端在首页提供轻量学生工作列表，优先呈现当前权限内“待处理结果、待回收行动、需要协助、最近已交付”的学生；它不是班级排名，也不是新增教务/CRM 系统。

每行包括学生、当前服务任务、最近结果及发生时间、下一步、已有责任人（未记录则留空）、待回收状态与一个操作入口。只有处理日志而没有人员行动记录时，显示“暂无行动记录”，不得推测未完成或失联。全部学生汇总与选定学生详情有明确范围标签。

教师/机构进入学生 → 核对依据 → 安排已有权限支持的任务 → 收到结果 → 记录本次反馈 → 留下下一步。机构确认已交付报告、学生提交结果、教师完成反馈分别记录；下载/阅读报告不自动标为辅导完成。首次纳入现有付费机构的小批次验证，不假设 30 套都已启用。

```text
最近查看 / 收藏资料 / 最近完成的成果
```

上述数字和内容仅为布局示例。正式首页必须从实际数据生成。

规则：

1. “添加资料”常驻；全局搜索显示当前检索范围。
2. 展示可打开的具体成果名称、来源及更新时间，不仅显示数量。
3. 异常有需要时出现，不作为主流程的一步；正常后台处理用紧凑状态显示。
4. 按真实服务任务突出学习或项目路径，另一条保持可达；无项目时仅给简短起步入口，不占大面积空卡。不凭资料数量自动推断用户偏好。
5. 只呈现当前端可用能力。规划中的提分卡、选题发现等不显示为可执行正式入口。
6. 不用资料量、处理量或在线时长代替掌握程度、成长变化或能力分数。
7. 已有结果可继续查看，新任务失败不将上一版有效内容清空。
8. 首屏优先当前学生/范围、一个具体主行动和最近结果入口；没有可靠建议时显示真实的添加/查看操作，不编造薄弱点或空占位建议。
9. 删除大面积愿景介绍和装饰性纸张/背景，压缩问候、数量与重复流程。皮肤选择移到设置，品牌保持可辨识，不把换色作为本轮核心交付。
10. 建议完成或失效后，首页同步更新为待评价、待独立核验或下一步；不得永远推荐同一已完成任务。状态判定由权威数据提供，不由页面自行猜测。
11. 对已支持的会话采集提供紧凑条目，例如“已接入，等待会话／自动采集中 · 最近收到…… [查看采集] [打开收件箱]”；待归属或失败才突出提醒。最近对话可直接打开，不用大统计卡挤占主行动。最近接收次数、完整会话数、消息数分开，不能把收到一轮说成整段会话归档完成。

### 5.1.1 首页指标口径

| 指标 | 定义与展示 | 禁止替代 |
| --- | --- | --- |
| 新增资料 | 指定学生/全体范围及时间窗内成功保存的原始资料 | 不算能力增长；重复导入按既有去重口径处理 |
| 整理结果 | 同一范围内完成处理且可打开的有效结果；注明按资料还是产物计数 | 不称“成长变化”，不与待处理数量重复铺卡 |
| 新增学习证据 | 通过归属、来源与事件校验的新增记录；可下钻 | 不把全部历史已确认证据数称为本期变化 |
| 有依据的变化 | 可比较的前后记录支持的具体变化，含完成条件、时间和适用范围 | 没有可比样本就显示“待核验”；不得用其他计数兜底 |
| 本期服务进展 | 已安排、结果已收到、反馈已完成等实际人员行动状态 | 后台成功、报告生成或下载不等于学生完成或服务完成 |

所有计数应说明范围与时间窗；空值/读取失败不同于零。界面、导出和 Agent 查询使用一致口径，不为 UI 单独维护另一份“成长数”。

### 5.2 首次使用与工作视角

- 无学生档案：建立或接管学生档案 → 添加第一份资料 → 查看具体整理结果与出处 → 选择一个适用动作；有足够个人表现才进入学情判断。
- 已有档案但无资料：提供采集入口和可选演示；演示数据显著标明且不写入正式档案。
- 家庭单机版：突出当前学生的资料、学情、课程和项目；技术配置收纳到设置。
- Windows 管理端：允许全部学生的异常/更新概览；汇总计数和个人计数明确区分。
- 学生端：只呈现本人已有权限范围的采集、资料、课程及学习操作。
- 教师端：围绕选定学生/项目收集和查看授权内容，不因导航统一而增加发任务或写档案权限。
- 手机/窄屏：以底部五个短标签“首页、收集、资料、学习、项目”承载主要入口，课程等进入相关页快捷区；平板横屏和 Windows 使用侧栏。

首次体验使用一份内容具体的演示作业或项目记录，展示“发现了什么、来自哪里、能继续做什么”，不以通用的“已保存，可复用”作为唯一收益。学生、标题等已知信息继承；分类与证据角色可自动建议并稍后修正，无法确认时保留未知，不强迫普通用户先掌握内部术语。

学生首页回答“今天做什么”；家长首页回答“近期发生什么、需要我做什么”；机构首页回答“谁需要处理、交付到哪一步”。相同资料和行动复用同一对象，不按工作视角复制档案。工作视角不授予权限，也不把学生姓名切换当作完整机构工作流。

### 5.3 个人教育档案总览

首页回答“最近发生了什么、现在做什么”，个人总览回答“这个人一路积累了什么”。从学生身份区、首页文字链接和其他页面面包屑可达，不新增一级菜单。

总览使用“概览、学习与实践时间线、作品与成果、发展目标”四类内容，概览展示学科积累、阶段性学情、进行中的项目和已有成果。每个摘要可进入对应模块的同一对象，不建立重复报告或成果副本。

时间线按真实发生时间组织；导入时间单列，日期未知留在待补时间区。可按学期、学科和项目筛选，区分原始记录、他人反馈、AI 整理与外部确认成果。避免把长期档案压缩为无依据的单一能力总分。

档案管理提供编辑基本信息、导出范围预览、备份与迁移入口。展示本机保存位置的易读说明和最近备份状态，只有实际存在备份时显示时间；云端报告缓存不能显示成完整档案备份。

新增事件与已有历史统一索引与去重，不能在出现第一条新事件后替换掉旧资料时间线；每条事件关联具体资料、行动、项目或成果，可回到同一对象。发生时间未知时不借导入日期制造成长顺序。

## 6. 各模块 UI 与关键交互

### 6.1 收集与整理

首屏以图标加文字提供拍照、文件导入和屏幕采集；明确展示“AI 会话自动采集”和“AI 对话收件箱”两个二级工作入口。手动保存对话放在“导入对话”中，不能替代前两项。录音在完整能力接入后加入。正式入口只显示当前平台实际支持的能力；Demo 逐项标注模拟和适用端。

添加时继承当前学生和可选项目，明确显示归属；不重复要求填写已知信息。学科、类别等优先自动建议，可稍后纠正，不阻塞保存。

保存后立即反馈“已保存到谁的哪个资料范围”，并分开显示保存状态和整理状态。统一语义为：已保存、等待整理、整理中、部分完成、已整理、需要补充。它们映射既有状态，不在 UI 内创建另一套业务账本。

处理结束提供“查看摘要”“打开原件”“查看相关项目”等结果动作。可自动执行的常规流程沿用已授权配置；需要手工触发的路径给出一次明确操作。既有人工 Agent 任务包路径仍需如实显示人工步骤。

相同文件重复导入可复用符合范围和版本条件的处理结果；同一道题的再次作答、修改版本和新的反馈是独立记录，不因内容相似直接去除。

Android 对已具备能力并已授权的类型，目标路径为“保存 → 自动识别/整理 → 查看结果”，不要求用户逐项选择 OCR、视觉解析和消化。实现前核对识别产物、调度就绪条件、资源/费用限制与失败重试；仅隐藏按钮不算自动化交付。能力尚未接通时保留真实的一次手工操作和原因，不借用暂停中的家庭版计划宣称完成。

断网、服务未配置、额度不足、识别失败和部分成功分别展示；只重试未完成部分，复用有效结果、避免无意义重复调用并保证结果幂等，记录失败重试用量，不承诺外部供应商对失败调用免计费。普通用户看到“处理中、已更新、待联网、需要补充”，维护人员可展开既有技术状态。该自动链涉及端侧任务代码，单独验收，不在本次文档修订中改协议。

### 6.1.1 AI 会话自动采集工作页

用户价值：在受支持来源完成授权与必要接入确认后，照常使用 AI 工具，对话持续留存，无需逐次复制粘贴。页面是业务工作页，不是开关弹窗或高级设置；“一次授权”不等于绕过第三方信任，也不等于授权前历史可以补采。

| 页面区域 | 默认可读内容与操作 | 边界 |
| --- | --- | --- |
| 当前授权 | 当前学生、可选有效关联项目/归属规则、授权范围与时间；授权、暂停、恢复、撤销 | 后台按授权绑定接收；切换当前浏览学生不把旧会话重绑给新学生；暂停与撤销对队列的影响沿用现有合同并说明 |
| 来源接入列表 | 受支持 AI 工具及“未授权、待接入确认、已接入、自动采集中、需要处理”等状态；具体下一步 | 安装检测、配置完成、收到事件分别显示；无事件只能称已接入/等待事件，不能称正在采集 |
| 最近会话活动 | 标题、来源、开始时间、最近接收时间、归属、消息/轮次覆盖、采集中/已结束/待补交/失败；打开同一对话 | 收到片段不等于完整归档；异常退出和缺失范围如实显示，不编造缺失正文 |
| 异常与隐私 | 离线待补交、接入失败、信任定义变化等原因及恢复入口；可展开处理记录 | 正常后台流不反复弹确认；只显示当前用户获准查看的来源与会话 |

首次流程：选定学生与授权范围 → 确认授权 → 对需要的来源完成一次接入/信任 → 显示等待授权后事件 → 收到事件后显示采集中 → 正常结束后显示归档结果及收件箱入口。以 Codex 为例，首次或 Hook 定义变化需由用户完成既有信任流程，定义未变化时不要求每次会话重复执行；具体支持来源与可用端按目标版本核验，不在本方案中承诺所有品牌/网页版均支持。

仅处理授权后受支持生命周期或受控接口实际发出的用户/助手正文，不扫描授权前历史、其他未授权会话、系统提示、工具密钥或缓存。离线队列、重试、重复事件去重和授权范围复核沿用已有机制；撤销后停止新增采集，已保存记录的保留/删除是另一个明确操作。撤销时队列补交如何处理应按既有授权合同说明并验证，不能先发送再校验。

Windows、家庭版、学生端、教师端逐端说明支持范围；Android 主动分享/粘贴不能标成第三方后台自动采集，也不通过无障碍、通知、剪贴板监听等旁路补齐。已安装应用不作为实际采集成功证据。

Demo 使用虚构来源和“模拟收到一轮对话／模拟会话结束／模拟离线恢复”操作驱动状态，不读取其他应用、不调用真实授权、不安装 Hook。首次确认、正常等待、收到片段、结束归档和失败恢复应各有可见结果；刷新不能把未完成任务改成成功。

### 6.1.2 AI 对话收件箱工作页

该页承接既有“对话资料箱”与待确认归属入口，负责接收后的查看与处理；不是聊天助手，也不是再建一份档案。保留旧链接兼容，待归属记录仅在原有授权的管理范围内展示，普通学生不能浏览未归属或他人的会话。

桌面采用“分类页签 + 可筛选列表 + 对话详情”，宽屏支持列表/详情并列，窄屏进入独立详情并保留返回位置。列表显示标题、来源工具、采集方式、时间、归属、会话完整性、整理/投递状态和具体下一步；支持按来源、学科/主题、时间、项目、状态与关键词筛选，搜索范围与索引覆盖明确。

| 分类 | 主要内容与操作 | 与现有能力的关系 |
| --- | --- | --- |
| 待确认归属 | 无法唯一确定学生/项目的记录；展示原因与允许的目标，确认或按既有规则处理 | 对应既有待归属收件入口；明确归属的内容不强制再次确认 |
| 已接收对话 | 自动采集、主动投递、分享链接、文件、粘贴记录；阅读、选取、关联和整理 | 界面名称可替代“已导入对话”，不改变记录身份；采集方式逐条保留 |
| 知识候选 | 候选内容、逐字原话、消息定位、风险与目标；编辑、补证、拒绝、合并、冲突/过期处理 | 沿用既有逐条候选治理；登记候选不等于写入个人知识 |
| 已投递／已入库 | 投递到学生/项目的原始资料、已确认知识及其去向、时间和回执 | “投递原始资料”和“确认知识入库”分别标记；高级详情保留晋升事务与撤销 |
| 回收站 | 回收范围、关联依赖及恢复 | 沿用原始记录保留与恢复规则，回收不暗示所有引用和原文已删除 |

详情先展示原始对话，明确学生/用户与 AI 发言、消息时间和来源；长会话分段阅读与定位，不把 AI 回答压缩成无出处的事实摘要。另设“整理与候选”“使用去向/处理记录”；同一条对话从采集页、收件箱和资料与知识打开时保持一致身份。

普通用户动作以“查看原话、确认归属、整理可用内容、投递到资料/项目、确认知识入库、查看去向”命名。批量处理沿用既有权限和确认规则，展示影响范围及逐项结果，失败项保留原因。敏感、来源不匹配、提示注入或冲突未解决时按既有治理规则阻断；撤销一次入库只撤销该事务产物，不删除原始对话。技术事务 ID 按需展开。

“导入对话”提供公开可读取分享链接、文件和粘贴等已支持方式；主动投递当前/选定对话与自动采集也分别登记。无权限读取的链接明确失败，不绕过登录/访问限制。手动路径保持可用，但不能重新变成所有用户的默认必经流程。

Android 家庭单机版保留现有“收件箱、待处理、候选知识、已归档、回收站”的可达视图，不硬套 Windows 的待归属分类。打开原文前校验其完整性，失败不继续作为证据；处理中记录不能回收，有消化结果/候选/采用依赖的原文不能永久删除。合法永久删除仍按原规则确认并保留不含正文的删除审计。旧版本已消化但没有候选索引的记录留在已归档，不从摘要反推不存在的候选；批量确认上限沿用目标端合同。学生/教师轻终端只提供实际支持的主动导入及回执，不因统一导航获得治理权。

### 6.1.3 对话从接收到再利用的状态与验收原则

```text
授权后的受支持会话 ──→ 自动接收／离线待补交 ──┐
主动投递／链接／文件／粘贴 ──→ 保存原文 ─────┤
                                                ↓
对话收件箱：明确归属直接进入；归属不明进入受控待确认区
  → 阅读原话 → 整理候选／选取资料 → 按既有规则确认投递或知识入库
  → 资料与知识／项目 → 成果、学习观察或发展目标 → 回查原消息
```

采集状态、对话保存状态、知识处理状态、业务使用状态分别展示，不能用单一“已完成”覆盖全链路。“已保存对话”不等于“知识已核实”，“知识已入库”不等于“学生已掌握”；学生在 AI 提示后的回答也不能当作独立表现。来自对话的研究建议只作为候选方向，未经实践核实不成为已完成成果。

复用现有会话、消息、资料、候选、投递/晋升事务及其稳定关联；来源、学生、有效项目、授权时间边界、消息定位、内容去重和处理回执不得因换菜单丢失。字段映射与兼容性另行核验，不在本次文档更新中新建协议。用户只在必要异常和高风险节点介入；原始资料的正常自动整理不强制套用知识晋升的人工确认流程。

下一版 Demo 必须用同一组虚构记录走通 E13–E18，并从首页、两个工作页、资料详情互相到达；不可仅增加入口、说明卡或成功提示。空收件箱、无事件等待、部分收到、无法归属、重复接收、暂停/撤销、失败恢复和撤销入库都要有可解释状态。

### 6.1.4 研究暂存与两类任务

研究资料保留“暂存候选 → 分析与风险 → 采纳/拒绝 → 整理/晋升 → 使用去向”的流程，复制、来源记录、快照等策略沿用现有规则并说明，不默认把所有候选直接放入正式知识。收集页与项目研究资料共享批次，不重复搬运原件。

后台队列保留批次、阶段、覆盖审计、局部失败、学习事件补录、执行日志、人工 Agent 任务包与回执等已有路径；等待/超时/取消/恢复不可省略。人员任务则在学习/项目里保留指派、接受/稍后/无法执行、附件、提交、退回修改、补交和确认。任务中心可作聚合入口，但两类状态与完成口径分开，不额外建立第二套调度器。

### 6.1.5 文件夹自动投递

在“自动收集 → 文件夹自动投递”保留目录选择/授权、准确学生与有效项目目标、启用/关闭、立即检查、最近检查时间、新文件/上传中/等待网络/失败/已收到等状态。源文件不移动或删除，文件稳定后才投递；同文件版本与同目标去重，新的修订保留版本关系。投递成功仍需区分主机收到与后续整理完成。

Windows/Android 个人学生端及 Android 教师端按现有路径提供；共享学生端禁用并解释原因。教师变更学生或项目时明确确认投递目标，旧队列保持原归属或按用户确认取消，不能重绑。关闭自动投递停止后续扫描，已接收资料不删除，队列如何继续/取消沿用现有规则。目录权限失效、文件变化未稳定、重复、离线重试与目标失效要能单独查看。Demo 只向虚构队列加入文件事件，不扫描真实目录。

### 6.1.6 屏幕采集与语义时间线

保留当前端已有的屏幕/应用窗口选择、三类采集策略、支持的时长、浮动控制/系统持续通知、重点截取、暂停/继续和结束；不要求所有端具有相同控件。Android 每次系统要求录屏授权时仍由用户确认；不能把 AI 会话的一次授权用于持续录屏。

来源记录保留学生、项目、课程/页面（适用时）、会话及发生时间。结束后是自动排队还是确认投递，按实际端和版本展示：既有正式手动路径不能被候选自动投递状态替代。已支持或候选的语义层按“会话 → 活动段/每日学习记忆 → 摘要/知识 → 原始画面”回查，标明证据覆盖与处理阶段；不把屏幕时长、前台应用或截图次数推断为专注度、独立作答或掌握。

活动段、截图、课程笔记与通用资料引用同一资料身份；分页与渐进加载沿用现有性能边界，缓存清理考虑引用依赖。屏幕样例与会话自动采集样例分别验收，不能以一个开始/停止弹窗代表两种完整流程。

### 6.1.7 本地处理与外部服务选择

在处理方式中保留“仅本地 OCR”和“本地识别 + 可选视觉理解”等当前端能力；首次配置/改变处理去向时说明哪些页面或预览会发往哪个配置服务。正常处理沿用已确认策略，不重复逐张询问，也不能因为自动化默认增加外发范围。没有外部服务时仍可用已支持的本地识别与原件核对。

设置分别配置/测试文本模型与视觉模型，测试使用非学生的最小样例；结果分别显示文本通过、视觉失败等状态，不把应用已安装等同任务服务可用。停用、缺配置、网络或额度异常给出明确降级；外部视觉失败不清除本地 OCR。密钥使用既有安全存储，不进入提示词、日志、报告或备份。Demo 用模拟去向和状态，不真实上传用户材料。

### 6.1.8 自动整理计划与维护

收集页提供自动运行/仅手动及每日整理计划，学情页可查看对应周期报告任务；展示启用状态、执行时间、范围、下次运行或等待条件、最近结果及失败原因。Android 保留网络、仅充电和每学生处理上限等已有设置；Windows 按现有 Agent/主机调度显示，工具不支持自动任务时如实保留人工执行。关闭自动运行不伪装成禁止用户主动处理，也不自动撤销另一类采集授权。

资料管理的“健康检查与维护”保留单学生任务账本、维护报告、批量路径核对，以及旧路径、断链、重复摘要、规则与索引一致性检查。查看/检测与执行修复分开；修复、补建或重建索引显示影响范围与可用恢复措施，不改写原始事实或已发布报告。正常浏览不触发维护写盘或全量扫描，任务节流、资源条件和恢复沿用原调度，不建立页面专用任务账本。

### 6.2 资料与知识

浏览采用搜索、组合筛选、列表/缩略图与详情组合，不把所有资料都做成大按钮。

| 维度 | 示例 | 规则 |
| --- | --- | --- |
| 学科 | 数学、英语、物理、跨学科、未分类 | 允许多学科，人工修正不被自动覆盖 |
| 内容类别 | 作业、试卷、课堂笔记、教师反馈、作品、参考资料 | 与文件格式分开 |
| 时间 | 学期、日期范围 | 区分资料发生时间和导入时间，未知时间不猜测 |
| 主题/项目 | 电路实验、二次函数、演讲项目 | 基于标签与关联，不强制移动文件 |
| 文件形式 | 图片、PDF、文字、对话、音频、视频 | 不支持预览时提供系统打开 |
| 来源与状态 | 本机、终端、云端报告；整理中、已整理 | 来源不改变权限或正式记录归属 |

旧资料可渐进补分类，不要求重新上传。第一期优先学科、类别、时间；更细的知识点分类待样本验证。

**统一详情结构：原始资料｜整理结果｜相关资料｜使用去向。**

- 桌面宽屏可原件与摘要并排，窄屏用页签切换。
- 摘要/报告引用可定位原页或片段；云端没有原件时明确告知原件所在设备，不能展示无效回链。
- “使用去向”展示关联项目、报告与成果；来源更正后逐步支持受影响结果提示。
- 常用动作：基于此资料提问、关联项目、加入资料集、收藏、导出。
- 搜索结果优先显示命中片段、日期、来源和位置，再提供基于结果的综合回答。
- 未命中或索引未覆盖时说明范围；不能用通用知识伪装成个人档案内容。

### 6.2.1 资料角色与学情依据

资料同时具有“内容类别”和“证据角色”，两者不混用。一份资料可能包含不同角色的片段，允许按片段分别标识。

| 角色 | 例子 | 可支持的用途 |
| --- | --- | --- |
| 学习资源 | 教材、讲义、教师讲解、参考论文 | 学习、知识整理、问题发现；本身不证明学生掌握 |
| 个人表现 | 学生作答、实验记录、演讲、作品过程 | 在归属和任务条件明确时支持对应表现观察 |
| 外部反馈 | 教师评语、评审意见、评价结果 | 作为有来源的评价，不自动等同独立测试结果 |
| 系统整理 | AI 摘要、分析、建议、旧报告 | 辅助理解与导航，结论需要追到合格来源 |

详情页默认显示易读角色标记，选材页提示所选资料能支持的分析范围。上传教材可以增加知识资源，不能增加掌握分数；对话中的 AI 解答和学生独立回答分开处理。仅有已生成摘要且找不到支撑原件时，显示覆盖不足，不将历史 AI 结论循环作为新的证明。

### 6.2.2 “使用这些资料”与情境再利用

资料详情、列表多选、资料集均提供同一个再利用入口；选中内容以引用带入，并显示学生、资料数量、资料角色和目标用途。

| 用户目的 | 展示操作 | 输出去向 |
| --- | --- | --- |
| 改善学习 | 分析所选作答、汇总错因、准备复习摘要、生成针对性练习 | 学情建议/学习活动；学习资源不单独触发个人诊断 |
| 发现研究方向 | 梳理反复出现的问题、比较观点、提出候选研究课题/论文选题 | 候选方向，用户选择后进入项目 |
| 推进研究与创作 | 整理实验过程、研究提纲、参赛素材、图书章节素材、发明构想记录 | 已有或新建项目中的草稿/过程记录 |
| 支持发展选择 | 汇总兴趣与实践证据、列出学科/专业探索问题、比较候选方向 | 个人发展目标与探索行动 |
| 准备沟通或申请 | 整理家校沟通材料、经历清单、作品集、个人陈述/简历素材 | 目标材料组合或导出草稿 |

流程：选资料 → 选用途与必要范围 → 查看产物及来源 → 保存到对应位置/暂不采用。沿用现有自动处理策略，不增加常规逐项审核；面向外部的材料由用户检查和发出。改换目标不重复上传原资料。

操作按资料类型、当前端能力和上下文呈现，默认展示最相关的少数项目，其余进入更多用途。资料不足时说明缺口；批量任务过大时显示分批进度，失败可保留已完成部分。

### 6.2.3 有依据的发现与推荐

资料整理或项目更新后，可在相应上下文显示少量发现，例如“最近三次实验都涉及测量误差，可汇总成一个待探索的问题”。每项显示引用、关联理由、待核实之处，并提供查看依据、加入已有项目/转为候选、暂不关注。

只在有新的相关证据或用户主动请求时更新，合并同主题建议，不把已忽略内容反复弹出。默认以页面内条目呈现，不引入强制通知；不能把某类材料数量直接推断为兴趣、特长或适合某专业。

### 6.2.4 知识类型、资产治理与使用关系

原始资料、概念、实体、摘要、问答精华、综合汇总和对话知识保留各自可读入口及来源关系；“学科”是跨内容类型的浏览维度，不替代这些类型，也不把知识全部降为文件。个人记忆中的知识内容可读可查，人格/行为规则/调用能力的配置仍在设置，二者分开。

资料管理向有权限的管理端提供版本、重复组、唯一引用、治理风险、覆盖不足及相应变化记录；可从列表“管理资料”进入，不要求普通学生理解内部资产结构。疑似重复先比较来源、版本与使用关系，不能仅凭内容相同删除一次新的作答。批量更正、回收和恢复预览受影响的资料集、项目、报告及成果；原始识别、人工纠错和重新整理结果分别留存。

“使用这些资料”先让用户选择用途，再选择项目/目标等承载位置；已有用途表覆盖学习分析与题目、研究/论文选题、参赛、图书、发明构想、创业探索和申请材料。没有合适目标时可在流程内新建并保留选材，不要求退出后重选。仅提供“加入资料集/关联项目/支持目标”不算完成再利用工作流；不能执行的用途明确标为后续设计或受限。

### 6.3 主题资料集

将同一次课堂、实验或主题中的照片、课件、音频、问答和结果关联起来。资料集是视图和引用集合，不复制原件、不替代项目工作空间。

优先基于明确课程、项目和采集会话归组；仅凭时间接近推测的关联以建议呈现。允许移出资料集，原件和其他引用不受影响。

资料集首页展示主题摘要、包含资料、相关知识和使用记录；练习是其中一个再利用出口。

### 6.4 学情与学习

推荐顺序：本期主要发现 → 建议行动 → 知识点表现 → 支撑资料与历史变化。

保留整体画像、历史变化、阶段总结、每周行动建议四类已有报告，以及能力画像、项目贡献、成长证据等阅读视图；不能只留下一个数学诊断样例。导出与出版保留忠实版/整理版、正式报告/简报/成长卡模板及目标端已支持的 PDF、PNG、Markdown 格式，区分打印样式与可编辑衍生副本，不改写原报告。Demo 可模拟预览/下载，但不能以索引文本宣称完整出版或档案备份。

每项发现显示适用时间、来源覆盖和最近更新；掌握判断区分独立完成、提示后完成和缺少复测。无可比样本时明确说明，不将一次成功或缺少记录解释为稳定掌握或遗忘。

### 6.4.1 可信判断与可读证据

- “基本掌握”及更高状态都必须满足明确的独立表现、可比较记录和必要迁移条件；不能只限制最高状态，而允许辅助高分进入“基本掌握”。具体证据门槛由规则规格冻结并经样本验证，不在界面层另设阈值。
- R01 合成反例必须返回需独立核验的状态；复测优先级要考虑独立证据缺口和不确定性，不能仅看分数、记录新鲜度或错误次数。改状态标签但仍排到低优先级，不能算修复。
- 默认以“证据有限、待独立复查、已有可比表现”等可解释文字呈现。确定性公式所得置信度不当作准确率或掌握概率；规则分值、版本、来源 ID 和事件 ID 放进高级详情。
- 知识轨迹先显示“何时、做了什么、是否有提示、结果如何、与上次是否可比”，再显示下一步。每项来源为可操作引用，优先定位原页、题目或片段；只有文件级定位时如实降级，不伪造精确位置。
- 原件撤回、无权读取、未同步或索引缺失各自说明；不得展示空链接或用其他来源替换。受影响当前建议标记待重新核验，历史报告保留原版本与依据快照，不静默改写。

提分卡接入后，每张卡展示练习重点、推荐原因、预计用时和完成后的反馈入口。题目需保留来源依据、题目/评分版本；反馈记录作答、提示情况和自评信心。复测建议与原知识点关联，由可比较记录更新判断。

当前未支持端到端行动反馈的端，先使用“查看建议 → 教师/家长指定一个具体任务 → 用户执行 → 添加结果资料”的真实路径。没有行动关联合同的端只称结果收集，不能称自动闭环；最小闭环需补齐第 6.4.3 节的关联与状态。自动出题、定向投递和自动复测不是这一最小路径的前置条件。

### 6.4.2 建议采用、难度调整与线下反馈

每项建议提供“采用、调整、稍后、不适合”，调整可修改目标、预计时间或难度；不适合原因可跳过。学生可反馈太难、太简单、没理解，反馈影响下一次建议，不自动判为能力下降。

两种完成路径共用同一练习记录：

- 在线：查看推荐依据 → 作答/分层提示 → 提交答案与可选信心 → 反馈解释 → 安排复测。
- 线下：查看/打印提分卡 → 纸上完成 → 拍照添加结果 → 关联原练习 → 识别与核对不清楚的部分 → 反馈与复测。

打印/导出时保留可回关联的练习标识，不默认印出档案路径或多余个人信息。优先从原练习进入提交结果；独立导入照片时允许选择关联练习，匹配不确定不能凭相似题目自动绑定。

不同次作答保留各自时间、题目版本、提示使用与结果来源；自评信心不替代评分。纸质识别不清时留作待补，不自动判错。用户报告完成、答案已收集、已评价和已复测是不同状态；复测后有足够可比证据才更新相应判断。

“未点提示”“独立完成”“同题重做”“未见答案的变式复查”分别记录。看过题解、提示或答案后重做同题，必须保留暴露历史，不能通过重新练习按钮清零。未知辅助条件显示未知，不默认独立；不得用额外监控推断学生是否在其他设备看过答案。

### 6.4.3 最小行动闭环与状态回流

```text
有来源的建议 → 采用或调整为一个行动 → 待执行 / 执行中
  → 结果已收到 → 待评价 / 需补充 → 本次反馈已完成
  → 需独立核验 / 安排下一步 / 暂无新行动
```

这是待实现的业务语义，不要求所有端照搬所有按钮。基于现有任务、资料和学习事件扩展关联，不能另建独立调度器；未实现的状态不靠前端缓存伪装持久化。

| 状态/动作 | 界面反馈 | 更新边界 |
| --- | --- | --- |
| 采用/调整建议 | 显示一个具体目标、依据、执行者及预计时间；执行者沿用现有身份 | 保存来源与版本，不改写原报告；不自动分配权限 |
| 添加结果 | 从原行动进入，自动继承学生与关联；说明保存成功及评价状态 | 保存同一行动下本次记录；重复提交幂等，同题新作答保留独立记录 |
| 本次反馈完成 | 对照预期与实际结果，显示提示/答案暴露、未知项和可比性 | 评价必须有可核对依据；仅用户自述完成不升级掌握状态 |
| 需独立核验/下一步 | 首页、学情页和机构列表显示同一当前状态，提供继续/稍后入口 | 历史报告不变；报告后的新证据与当前建议单列 |
| 取消/失效/异常 | 说明原因，可恢复或重新安排；原结果仍可查看 | 旧建议不继续充当当前推荐，不删除历史证据 |

实现前冻结最小关联：学生、行动、来源资料/报告及其版本、目标知识点或项目、执行方式、实际发生时间、结果资料、本次作答/反馈记录、提示与答案暴露条件、题目及评分版本（涉及题目时）、幂等键和状态变更来源。保留“事件发生时间”与“系统收到时间”，字段缺失不猜测回填；具体字段映射另做兼容性评审。

报告页必须区分“当期历史判断”“报告后新增证据”“当前行动”。例如完成一次提示下订正后，显示“已收到辅助完成记录，待独立核验”，不能继续显示“尚未练习”，也不能直接改为“已掌握”。一次结果回流至少能从原行动、当前学生记录和当前建议三处找到同一记录。

### 6.4.4 成长证据维护与报告审核

成长依据页保留添加候选、从已有原件补来源、确认采用、继续观察、驳回及查看审核记录；来源缺失时通过资料选择器补齐，不强迫普通用户手填 URI/内部 ID。本人贡献、外部反馈和一般学习记录仍按各自来源核实，不以“有材料”替代“已确认”。家庭单机与主机按各自权限管理，轻量学生/教师终端只读范围不变。

报告列表区分草稿、待审核、已发布及历史版本；只有合格的已确认依据进入正式报告，草稿生成不自动发布。缺少模型服务或处理失败保留已有有效正文，补生成与周期更新显示具体任务，不用占位说明替换已有报告。补建成长模型、重建结构化索引放高级维护，保留可核对输入/结果，不作为普通阅读的必经动作。

### 6.5 项目与成果

列表默认展示进行中项目及其最近更新，新建/接管作为动作。项目详情采用“概览、资料与知识、过程记录、成果”结构。

阶段可按项目类型配置为准备、探索、制作/研究、反馈、完成；阶段完成需要明确记录或成果，不由 AI 擅自判断。

未来候选选题应展示来源积累、关联理由、尚缺材料和可行性待核实项。用户选择后转为项目；已有资料通过引用带入。

成果记录包含作品原件、版本、贡献者、完成时间、反馈和过程引用。图书、论文、参赛作品、发明或创业构想等采用类型字段，状态区分构想、草稿、完成、已提交及外部确认。

项目管理保留既有模板、新建/接管、编辑、学生绑定、目录健康及迁移、模板复制、导入导出、封存、移除和恢复；具体操作按支持端与权限展示，不能把封存当删除。项目工作空间承载过程与候选，知识空间承载已整理知识；普通资料集不替代双空间及其治理。

同一成果有稳定身份，其下才有版本；新增一个不同成果不自动成为上一成果的 v2。阶段完成需关联记录、成果或有来源的人工确认，不能只勾阶段标签而无依据。多学生项目分别记录本人承担工作和支撑片段，不把团队全部成果写入每个学生。

从成果进入“确认本人贡献／纳入个人档案”，沿用既有审核/发布规则，展示确认者、时间、证据和状态；项目成果、个人成长证据、目标材料引用同一记录。待核实贡献不冒充已确认成就，也不因成果数量增加直接提升能力判断。

发展目标可包括学科/专业探索、升学、奖学金、求职等。其归属和工作流见 6.7，可从项目关联已有个人目标；个人陈述和简历中的事实须可核对，不补造奖项、身份或结果。

### 6.6 AI 助手与协作

保留统一问答入口，同时在资料、报告和项目中提供“解释这段内容、汇总这些反馈、对比这些记录、列出下一步”等情境操作。调用前展示当前学生、项目及资料范围；切换上下文后不沿用其他学生资料。

同一学生内也要遵守任务范围：历史报告的建议绑定该报告主题和版本，项目助手默认只引用该项目已关联且获准访问的材料，所选资料助手只使用选材范围。不能默认取当前学生最近两份资料作为所有页面的依据。扩大范围需明确显示新增材料和理由，并遵守既有授权；缺材料就说明缺口，不用无关材料补齐回答。

Agent 调用配置放在设置；来源工具名称和接入状态在自动采集页/收件箱可见，不因技术降权而隐藏必要来源。助手执行状态如实说明直接调用、打开外部工具或需人工执行，不能把打开工具当作任务完成。

协作动作贴近具体项目与成果，设备信任、学生映射和同步诊断进入设置。既有同步范围、授权和冲突处理规则保持有效。

云端报告以“结果送达”能力服务机构/家庭：显示来源端、报告周期/版本、同步时间、只读副本和原件可达性；不要再建一份学生权威档案。开通、配对和许可维护集中在首次连接/设置，已授权正常使用直接看报告。撤销后的本机缓存保留边界须明确说明；缓存不是备份，送达/下载不是辅导完成。暂不因本方案扩成通用网盘或多租户教务平台。

针对 0.18.2/1.2.6 云报告候选，Demo 可提供明确标为候选的本机/云端来源切换、已授权自动上传与暂停、离线只读缓存、下载、过期/撤回/失败状态；沿用独立云端学生与许可路径，不强制先新建本地学生。配对、信任、映射、撤销、冲突和交付回执需可查看；原始资料不因报告同步而默认上传。服务端管理及真正撤权效果另行验收，不以静态说明或前端开关代替权限验证。

### 6.6.1 Agent 调用授权与待审批操作

“设置 → AI 与授权”管理长期能力，“首页异常/任务中心 → 待审批操作”处理具体意图，均复用既有 `agent-capabilities` 与审批数据。主机管理员查看目标学生/已允许项目、外部 Agent、能力范围和撤销状态；不把接口、密钥或内部令牌作为普通输入项，不向页面或对话展示完整令牌。

| 授权/确认 | 实际作用 | 不能替代 |
| --- | --- | --- |
| 会话采集授权 | 接收授权后符合范围的会话事件 | 不等于外部 Agent 可随意查询/写入 |
| Agent 只读/受控写入授权 | 分开允许既有查询能力、提出受控写入预览 | 只读不自动升级为写入；受控写入不开放正式知识发布、删除或迁移 |
| 单次写入审批 | 核对目标、预览与内容摘要后批准/拒绝某一意图 | 批准不等于已经执行成功，变更内容不能复用旧批准 |
| 知识候选确认 | 决定候选是否进入受管知识/成长记录 | 不是接口权限，也不代替资料归属和来源校验 |

工作流：外部请求形成预览 → 查看目标与内容/风险 → 批准或拒绝 → 等待执行 → 查看回执/失败/可恢复状态；提供撤销长期授权。拒绝按既有合同清理待写入输入，保留必要审计。二进制材料只能预览元数据的地方如实说明，不暗示已看过正文；执行按原内容摘要、幂等和有效授权校验。报告写入为草稿不自动发布，任务创建不等于任务已执行；旧授权不静默追加新能力。原型只能模拟审批，真实 Agent 联调与真机门槛独立验收。

### 6.6.2 跨 Agent 记忆、人设与规则

资料与知识中的“跨工具记忆整理”保留来源 Memory 的手动导入、用户发起扫描、候选选择、统一记忆合并/编辑/复制；显示来源与统一版的关系，不将所有内容压成只读知识条目。设置中的“人设与规则”保留来源 Soul 备份、与统一人设对比和编辑保存；规则文件的创建/改名/编辑、适配规则生成、差异比较及纵向学习协议迁移预览。

上述是用户明确发起的受控文件/配置管理，与后台会话正文采集分开；不能以会话授权为依据扫描其他 Agent 的配置。保存/合并/生成前显示学生、目标文件和覆盖影响，沿用已有来源记录与备份；不自动覆盖未选择的工具配置，不把导入的人设/规则作为未经确认的执行指令。普通用户可只使用统一知识，维护动作折叠但可达；未支持端不照搬 Windows 管理按钮。

### 6.6.3 团队及跨主机知识查询

统一查询保留“当前学生及关联项目、本机团队、远程协作团队、当前允许的全部范围”选择；默认个人上下文，只有完整节点管理端在现有长期策略允许后才显示可用团队范围。不能为减少学生选择而默认开启团队检索；轻终端始终仅本人及授权项目。团队结果显示团队范围，不能自动归入当前学生成长记录。

查询沿用已有本机优先、受控远程与快照策略，不由新 UI 自行放宽回退条件；受限项目/授权范围不满足时按原合同停止或标覆盖受限。结果显示来源节点、学生/项目范围、更新时间、新鲜度、快照时间与未覆盖部分；远端离线保留已获得的有效局部结果，“未命中”不等于授权外资料不存在。引用使用既有受控定位，不暴露远端绝对路径，也不默认检索远端原始资料。

### 6.6.4 项目定向发布与协作附件

项目详情保留“发布给协作节点”：先核对项目关联学生映射 → 单个有效节点直接发布/多个节点选择 → 展示包范围与发送状态 → 接收端按项目 ID/协作谱系创建或匹配项目 → 打开送达结果。没有有效映射时停止并引导连接，不回退到无关节点。工作空间可各自绑定本地目录，新工作文件先扫描采用到项目原始资料库才进入发布范围；同名独立项目不能按名称合并。

| 传递方式 | 允许内容与去向 | UI 必须区分 |
| --- | --- | --- |
| 学生知识/档案同步 | 已确认知识、成长模型、已发布报告及档案 | 默认不含原始资料、待审草稿和运行缓存；按学生映射显示送达 |
| 项目定向发布 | 项目原始资料、已确认/已发布知识与来源关系 | 不等于复制工作空间目录；按谱系匹配，同名不同内容隔离不覆盖 |
| 任务附件/成果回传 | 任务中的文件先到受控收件区 | 暂存、采用到学生资料/有效项目或拒绝；回传成果不自动进入教师资料库 |
| 云端报告 | 许可范围的报告及只读缓存 | 不替代前三种完整节点协作，也不承诺原件随报告到达 |

任务详情保留双方提交说明、修改反馈、再次提交、确认与附件去向。发送队列的离线、重试、恢复、送达、暂停/取消与异常隔离沿用现有机制；无本机新变化不等于已送达。正常直传不要求手工搬包，兼容交换目录仅高级可选。学生/教师轻终端不因此变成完整节点或获得项目发布权。

### 6.7 个人发展目标与材料组合

没有项目的学生也可以建立“探索物理与工程方向”等目标；目标由用户表达，不由算法自动指定。页面按“目标与考虑因素、已有依据、信息缺口、探索行动、相关成果与材料”组织。

目标类型包括学科选择、专业探索、升学规划、实践与背景积累、奖学金申请、求职及创业探索。既展示相关支持材料，也保留不一致反馈与未验证假设。比较方向时给出依据和待体验事项，不生成没有验证基础的适配率或录取概率。

目标可引用学习表现、阅读记录、本人兴趣表达、教师反馈、不同项目与成果；一项成果可服务多个目标。修改目标不会修改原始经历。

选材器直接列出可引用的成果版本、本人贡献与反馈，不能只让用户选择原始资料或项目标题。草稿区分“本人已核实事实、外部反馈、系统建议、待补充”，不能把所有资料摘要统一列为事实。不同目标可共用技术组件，但须按用途展示不同证据要求与提纲；缺少事实保持空缺，来源撤回/更正需提示相关材料待复核。

申请材料流程：明确目标 → 选择真实经历和成果 → 发现缺口 → 组织提纲/草稿 → 核对引用及事实 → 本地导出 → 用户自行提交或录入外部反馈。显示草稿、已导出、用户标记已提交和外部结果的区别，导出成功不能显示申请成功。

个人陈述、简历、作品集和沟通材料共用来源组合能力，不分别维护事实副本。论文、图书、参赛作品、发明/专利相关材料和创业计划按实际阶段保存；若后续使用学校、赛事、奖学金或招聘的具体要求，显示来源与核验日期。正式目标匹配阶段再接入相应信息，不用静态 Demo 冒充最新申请条件。

### 6.8 两条闭环的交叉路径

| 触发情境 | 下一步 | 回流位置 |
| --- | --- | --- |
| 学习资料中反复出现本人提出的研究问题 | 展示问题与依据，选择是否形成候选课题 | 个人档案及研究项目 |
| 实验项目中出现具体数学理解困难 | 关联相关学习记录，提出针对性练习建议 | 学情与学习；不由项目困难推断整体能力 |
| 针对性练习后取得新的可核对表现 | 更新对应记录，提示可回到项目继续验证 | 学习事件、项目过程与个人时间线 |
| 项目形成作品或收到反馈 | 保存版本、本人贡献和评价，选择关联发展目标 | 成果记录与目标材料 |
| 发展探索发现缺少实际体验 | 建立一项探索行动或关联现有项目 | 后续实践资料回到个人档案 |

跨模块跳转携带当前学生、来源资料和相关任务/项目标识，返回时保留原上下文。只新增关联和必要事件，不在每个模块复制正文或重复计算一份“掌握程度”。

### 6.9 课程与必要管理功能

精选课程保留学习和有权限端的管理入口；新增/编辑、删除/隐藏、排序、学生/年级分配、批量表格导入、课程包导入及已支持的草稿/发布/导出/恢复逐项映射，不要求所有端具有管理权。手机从首页和学习页可直接进入课程；打开外部课程不自动开始屏幕采集，也不标学完。

设置保留本地根目录、运行模式、AI/Agent 配置与测试、许可、更新、设备连接、同步和诊断；主流程只露出需要处理的异常。学生建档与接管显示保存位置、归属及目录异常；管理员操作与学生日常阅读分开。统一助手保留自由输入、所选资料范围和直接/人工 Agent 执行差异，不只有预设问题。

导出范围明确区分资料索引、当前学生完整档案、可恢复备份、整机迁移；恢复提供范围与冲突预览、结果和失败说明。Demo 不执行正式恢复、迁移或删原件，但必须可模拟这些步骤，不能用一段风险说明替代全部管理体验。

### 6.9.1 分端备份与跨端迁移

提供按用户目的进入的向导，但不把不同产品的包和权限压成同一操作：

| 路径 | 界面必须保留的步骤与风险 |
| --- | --- |
| Windows 日常备份 | 轻量状态/索引和既有档案范围预览、校验恢复、损坏隔离；不能称为全部原始资料备份 |
| Windows 换机迁移 | 分析实际文档/项目/课程等范围、稳定复制与哈希校验、空目标与容量检查、路径重映射和诊断；新版目录包与旧加密包密码步骤区分 |
| Android 加密备份 | 密码设置/输入、独立保存位置、空目录恢复；忘记密码不能承诺可恢复；密钥和系统授权不随包迁移 |
| Android 学生端升级单机版 | 从准确学生发起快照、单机版空目录接管、保持 ID；一次迁入不自动建立长期同步，大资料引导 U盘路径 |
| Windows→Android U盘迁入 | 学生/项目/文件/容量预览、目录授权、逐文件进度与校验、断开后继续，不重传已核验文件 |
| Android 整机换平板 | 新设备独立激活、空白业务状态及空目录、容量/版本/席位校验、断点续传、URI 重映射、结果报告；不合并两个已有家庭档案库 |

恢复完成提示重新配置密钥、授予目录/录屏权限、建立必要连接和设备许可；具体排除项按包格式列出，不能让旧设备身份、License、API Key 或录屏授权随迁移自动生效。原机数据不因复制完成删除；目标非空、密码错误、空间不足、文件损坏、来源版本较新或路径待修复时给出准确下一步。连接备份与资料备份分别标明，不以连接恢复表示档案已经恢复。

### 6.9.2 学生生命周期、许可与平台偏好

学生管理保留解除本机登记与删除真实资料的区别：默认操作按该端现有规则，删除目录必须再次确认具体学生、授权路径、依赖与备份提醒，不使用含混“移除”按钮暗示可恢复。不能凭另一个学生同名目录删除数据；执行后说明实际删除范围与可恢复性，未激活只读等状态不得绕过限制。Demo 仅模拟，不删除真实目录。

首次使用和设置保留设备码、粘贴/扫码/相册识别等当前端已支持的激活方式、有效期/席位信息、升级检查及错误解释；相机权限拒绝时保留可用替代入口。席位不足时新增/接管/迁移按原规则停止，已有档案的浏览和备份按许可合同保留。未激活、过期、读取失败不是同一状态；许可升级不自动扩大数据范围。

各端使用独立更新清单和包类型；本地候选、正式下载目标、签名与安装/真机验收分别说明，不用主机版本覆盖学生/教师端版本。保留已有界面语言（目标端支持者）、主题皮肤及横屏/竖屏/自适应布局与升级后的偏好，不因新浅色 Demo 强制移除既有深色方案。长翻译文本、大字体和系统权限拒绝均纳入回归。

## 7. 录音收集专项设计

录音作为资料来源接入统一收集与整理流程：保存原音 → 带时间位置转写 → 摘要和分类 → 搜索、回听与引用。

建议先验证已有音频导入、转写与回听，再增加应用内录音、暂停续录、标记重点和中断恢复，最后扩展长课堂分段处理。

详情页提供播放器、转写和摘要。引用可跳转时间片段；识别不清处保留标记。教师讲解作为学习资源，学生回答作为可能的学习表现来源，不通过未经核实的说话人判断生成个人能力结论。

主动录制时显示录音状态和停止入口；转写如需发送到模型服务，应清楚说明处理去向。录制失败保留已经成功保存的部分并明确覆盖范围，不显示“全程完成”。

## 8. 通用交互、文案与视觉规则

| 场景 | 推荐形式 | 文案示例 |
| --- | --- | --- |
| 采集入口 | 大触达区域的图标文字按钮 | 拍照添加、导入文件、保存对话 |
| 会话采集 | 独立工作页、来源状态和紧凑活动列表 | 已接入，等待授权后会话；最近收到一轮对话 |
| 对话收件箱 | 分类页签、列表/详情、局部批量操作 | 待确认归属；已投递到实验项目；查看原话 |
| 处理队列 | 状态列表和局部进度 | 已保存，等待整理；已整理 8 页，2 页需要补充 |
| 内容浏览 | 列表/缩略图、筛选、预览 | 数学课堂摘要 · 来源 3 份资料 |
| 学情阅读 | 摘要、知识点列表和适量趋势 | 本次独立完成；尚无后续复测 |
| 项目推进 | 阶段清单和成果列表 | 继续实验记录、查看教师反馈 |

“OCR/视觉解析”面向普通用户可表述为“识别资料内容”，“消化资料”表述为“整理成知识”；高级详情保留技术名称。更名不等于流程自动化，必须同时检查第 6.1 节的实际处理链。按钮使用具体动作，避免孤立的“生成”“处理”“执行”。

每个主要区域突出一个主动作，其他动作次级呈现。图标辅助文字，颜色辅助状态，不依靠颜色单独传达结果。保持统一主色、清晰字号、可见焦点和充分对比度，避免多色按钮与统计卡争夺注意力。

触控主操作建议至少 44×44 CSS 像素或约 48dp；支持键盘操作、表单标签、焦点恢复和减少动效。缩放与窄屏不截断关键按钮，长文件名可展开读取。

加载、无资料、无筛选结果、无权限、离线、部分失败分别设计。搜索与列表渐进加载，缩略图按需读取，不为切换页面全量扫描和哈希档案。

自动化沿用一次配置后正常运行、异常时提示的原则；界面不能默认增加逐项审核。家庭版与机构版按各自已实现策略展示，系统自动观察也不能标成人工确认。

### 8.1 首版视觉基准

保留 v1.1 的“浅色资料工作台 + 深绿主动作 + 清晰文档预览”作为原型参考，不以重做品牌/皮肤为近期目标。正文区域以中性白和清晰分隔为主，避免大面积同色装饰。视觉重心是可读内容与来源；页面区域采用无框布局，仅重复结果项、弹窗或必要工具使用卡片，避免卡片嵌套和大统计卡占据首屏。

| 设计变量 | 首版建议值 | 使用约定 |
| --- | --- | --- |
| 页面/内容底色 | `#F6F7F3` / `#FFFFFF` | 大面积稳定阅读背景 |
| 主色/导航 | `#234C40` | 主动作、选中状态及品牌识别 |
| 正文/次要文字 | `#20332B` / `#59665F` | 字段、说明和正文，重要信息不依赖过浅文字 |
| 边框/弱选中底色 | `#D8DFD8` / `#E8EFE9` | 列表分隔和范围选择；控件边界另验对比度 |
| 成功/待补/失败/信息文字 | `#276344` / `#865513` / `#AB3434` / `#315D84` | 配合文字和图标，不作为学科装饰色 |
| 字体 | 系统中文无衬线，Windows 优先 Microsoft YaHei，移动端用系统字体 | 不依赖在线字体才能正常阅读 |
| 字号/行高 | 正文 16px；次要 14px；页标题 28px；局部标题 20px；正文行高 1.6 | 12px 仅辅助元信息，不能承载核心状态 |
| 间距 | 4、8、12、16、24、32、48px | 对齐优先，列表支持舒适/紧凑密度 |
| 圆角 | 控件与重复内容项不超过 8px；对话框沿用现有组件规范 | 普通页面分区不做浮动卡片，不使用厚重阴影 |
| 交互动效 | 150–220ms；页面短淡入、抽屉滑入、状态局部更新 | 仅表达变化；遵循减少动效偏好 |

以上是 Demo 设计基准，不覆盖正式产品已有皮肤。正式接入时映射到现有主题变量；深色或其他皮肤若纳入交付，需分别验证对比度与状态一致性。正文目标对比度不低于 4.5:1，关键非文字控件目标不低于 3:1，以实测为准。

### 8.2 布局与组件约定

- 桌面宽屏（建议 ≥1200px）：约 224px 侧栏，内容区 32px 留白；资料详情支持原件与整理结果双列，窄于可读宽度时改页签。
- 平板/中宽屏（建议 768–1199px）：收窄或折叠导航，16–24px 留白；保留图标文字，禁止截掉关键操作。
- 窄屏（建议 <768px）：底部五项导航，内容单列；原件/摘要切换，批量操作使用底部工具条。课程通过首页和学习页直达。
- 页面用于可收藏、可回退的主要任务：档案、资料详情、报告、项目、发展目标。抽屉用于临时查看来源、单项属性或上下文助手；不再在抽屉里层层打开抽屉。
- 弹窗仅用于短表单、归属选择和有明确影响范围的操作；较长录音/编辑任务采用独立页面。关闭时有未保存输入才提示，常规浏览不反复确认。
- 全局添加资料为导航级常驻入口，当前工作区的主动作按任务突出；不得将导航动作和局部次级按钮做成同等强度。
- 统一组件：学生身份区、范围筛选、资料行、结果卡、证据引用、处理状态、下一步建议、阶段清单、空态、错误提示、导出范围预览。
- 列表多选后显示选中数量与批量动作；用户可撤销分类/关联修改。主操作具备加载、可重试、成功和禁用原因，不用短暂提示代替完整结果页。
- 在 390×844 和 360×800 的目标手机视口，首屏应能看到当前学生、一个具体主行动和最近结果入口；没有结果则显示首次添加动作。该目标需实际渲染验证，不能用固定像素高度挤压文字。大字体/200% 缩放允许顺序重排，保证操作可达且不重叠。
- 1440×900 与 1024×768 的桌面首屏不重复铺开处理流程和同义统计；导航可折叠但不把当前学生或主操作藏入多层菜单。窄屏“整页无横向溢出”只是底线，不等同首屏可用。
- 技术 ID、品牌配置、皮肤选择与日志按需展开；面向用户的知识点名、来源标题和作答条件默认可读。图标按钮有可访问名称，陌生图标提供提示。

### 8.3 状态呈现与纠错

系统整理标记 AI 生成并列来源，外部反馈保留作者/来源，用户输入按真实身份标注。修改标题、标签或识别内容后显示已更正及相关版本；如影响摘要/报告，提示需更新哪些结果。

“正在处理”“模拟处理中”“需人工执行”采用不同文字。远程原件不可达、无权访问、索引未覆盖和没有资料分别说明原因与可用下一步，不能统一显示为空。

界面应允许关闭非必要推荐、查看处理记录和回到原件，技术日志在详情中可达。撤回或恢复操作说明是否只影响关联、是否涉及原件，不默认新增日常确认环节。

刷新/重启应恢复可核对状态；未知或中断显示待恢复，绝不直接把处理中改成成功。返回列表保留筛选与滚动位置，关闭有未保存内容的长编辑/录音时提示或保存草稿。检测已安装、已配置、实际收到、已保存、已整理、已核实、已导出、用户标记已提交和外部确认均是不同状态，不能以一个绿色完成标记代替。

建议分为三个交付批次，不承诺未经估算的工期：

2. **最小服务链批**：UI-C2-a + 必要的 UI-A/B，在现有 3–5 名学生中选择一个知识点或项目任务贯通。Android 仅对确认支持的资料类型补齐自动衔接；所选端或协议未就绪时明确降级，不假称全端闭环。
3. **可复制交付批**：在已有机构/家庭中小批次验证普通用户独立操作、结果回收和人工成本；云同步完成真实部署与设备门槛后接入。是否进入 C2-b、C1 或更多 UI-D 扩展，以实际需求和试点结果决定。

UI-A 不借界面重组新建评分算法；规则修正归 UI-G，另列负责人、输入输出、兼容策略和测试。UI-B 的用途选择由实际能力决定。Agent 受控写入继续遵守已有授权、审批和幂等合同，不能以“减少操作”为由绕过安全边界；一般资料自动处理与通用 Agent 写授权是两种不同流程。

开发开工前把 M01–M31 的“待核”细项填入第 4.4 节迁移台账，沿用已补录的六项映射和八类细项，继续记录具体目标版本、数据读写影响和回退方式。每个实际交付项必须有原功能回归与新流程验证；未纳入本期的细项保留原有可用入口。

独立 Demo 的完善顺序与正式产品交付批次分开：第一优先修正 R07/R10/R12/R13 等误导状态，并补齐 UI-AI 两页及端到端会话样例；随后按迁移台账补知识类型、研究暂存、资产治理、项目贡献、任务、课程管理与出版等原功能；再完善双闭环的结果回流和跨设备视觉。R06 等已列可信度问题同样不得搁置。保留现有五导航与风格，不以增加首页卡片代替业务流程。此排序不意味着所有新增音频、出题、申请类型都必须同期实现。

复评补全的 M26–M31 与八类细项纳入上述原能力迁移批，并按第 4.4.1 节落实责任模块；M27/M29 的权限和范围是相关页面替换旧入口前的门槛。新增 E20–E31、T18–T30 按所涉及端逐项声明是否适用、计划批次和证据，不以“高级功能”名义静默排除；未适用要写明端/版本/权限原因。本轮只把要求写入方案，不更改既有交付阶段或替所有验收打勾。

与现有家庭版自动处理、云报告及多端工作合并核对：报告缓存不能覆盖本机权威记录，云端报告不能承诺打开未同步原件。每端分别记录源码、自动测试、候选包、真机和发布状态。

六项补全能力不另增 Demo 一级单元：M26/M31 的收集与计划进入 D02，M28 记忆/M29 查询/M31 健康检查进入 D03，周期报告与成长审核进入 D04，M30 项目发布进入 D06，M27 审批与人设规则/分端迁移设置进入 D08。端侧身份与许可由 D01/D08 承接。保留八单元编号，不以单元数掩盖未覆盖的子功能。

所有演示数据虚构；录音、AI 生成、同步、发布和入账均按模拟状态标明。默认不调用真实麦克风、不发送资料到外部服务、不连接正式档案。模拟导出可以产生明确标为演示的文件；备份/恢复、外部提交及删除真实资料只展示流程。

主交互必须可点击得到具体页面、数据关联或可复查状态，不能全部由提示气泡替代。同一资料在不同页面使用同一演示身份；练习反馈、资料关联、项目建立要在相关列表和时间线可见。切换演示学生后范围同步切换；提供恢复演示初始状态。重置只影响独立 Demo 数据。

模拟服务也必须维护连贯状态：完成任务后当前建议改变，历史报告不被改写，引用与页面范围一致；不能以“没有接真实 AI”为理由保留 R06/R07。预设报告与真实生成报告分别标注，预设答案不能成为独立表现证据。

每个演示批次声明具体数据集、起始状态、预期变化及未覆盖项。会话样例至少含明确归属的自动采集记录、待确认归属记录、主动导入记录和有风险的知识候选；贯通后从同一记录查看项目/知识去向及原消息。不得只在收集页加两个入口后宣称自动采集与收件箱已覆盖。

Demo 按本批声明的连续任务和反例验收，不以页面数量计完成率；没有全量完成第 10.4 节就不称“八单元全部完成”。公开演示区分模拟、新设计和正式功能，不把原型录屏当作真机验收。

### 10.2 用户任务验收

使用相同样本对比现版和原型，分别记录首次使用者与熟悉用户表现。以下时间为待验证的设计目标，不是已取得的性能结果。

| 用户任务 | 建议目标 |
| --- | --- |
| 找到添加资料入口 | 10 秒内，无口头提示 |
| 添加资料后找到整理结果 | 从完成反馈直接到达，最多 2 次主要导航动作 |
| 找到某学科上月的教师反馈 | 30 秒内，能说明当前筛选范围 |
| 从学情结论找到原始依据 | 最多 2 次主要导航动作；无原件时得到准确解释 |
| 把旧资料用于现有项目 | 不重新上传、不复制原件即可建立关联 |
| 区分原始事实、AI 建议和已完成成果 | 阅读标签后能正确说明状态 |
| 找到下一步行动 | 普通使用者无需讲解，在首屏找到一个适用主动作；无依据时理解为何暂无建议 |
| 完成一次结果回流 | 不重填已知学生/任务；能在原行动、学生记录及当前建议找到同一结果 |
| 教师处理一名学生 | 从机构工作列表进入，核对依据、记录反馈并留下下一步；记录任务耗时和求助次数 |
| 理解首次整理收益 | 能说出整理发现、原始出处及一个可用动作；仅说出“保存成功”不算收益理解通过 |
| 找到会话功能 | 从首页或收集页最多 2 次主要导航动作到采集页/收件箱，不依赖高级设置 |
| 理解采集状态 | 能区分已安装、已接入等待事件、实际收到、完整归档；知道何时需处理而非每次手动导入 |
| 找回并复用对话 | 从接收记录读原话，确认必要归属，查看投递/知识去向；不重复上传或重建会话 |

补充验收：学生切换后不串档；旧链接可定位；返回保留筛选；离线可读已有内容；局部失败可重试；未知日期不冒充发生日期；无数据不生成趋势；各端许可和角色边界不变；大档案翻页不触发重复全量扫描。

### 10.3 成效指标

优先观察资料保存成功率、整理结果到达率、找到指定内容的耗时、原文回查成功率、旧资料被项目/报告复用的情况，以及建议执行后能否形成可比较记录。

上传量、按钮点击量、报告数仅为过程指标，不直接代表学习改善。先用自愿样本和本地可核对记录验证，不因测量新增默认外发的个人行为采集。

对现有 3–5 名学生逐人建立经授权的验证记录：基线问题与证据、任务目标、支持方式及提供者、同题/变式与答案暴露、独立结果、延迟复查、本人体验、人工投入及工具贡献。缺少可比结果时记为未验证；不做小样本显著性宣传，不把老师/创始人陪伴效果全部归因于软件。

机构和家庭同时记录每生每周整理、辅导、催收、核对与客服时间；区分首次配置成本和重复使用成本，记录模型/处理失败重试费用。先测基线再商定可接受目标，不编造续费率、节省比例或提升幅度。保留原有教育支持，不为试验强行中断辅导。

购买、激活、持续使用、行动完成、可比较表现和续费分别统计，并标注各自分母、时间窗和缺失情况。与推广机构验证“演示 → 成交 → 开通 → 首次收益 → 后续支持”的交付链，不能拿签约数量代替使用验证；小批次是否扩展由实际用户接受度和成本决定。

### 10.5 可信度反例门槛

以下必须在适用层分别验证。原型测试、主机单元/行为测试、实际设备端到端测试不能互相替代；未验证层明确列为待验。

| 编号 | 输入/操作 | 通过条件 |
| --- | --- | --- |
| T01 对应 R01 | 单条合成记录：概念/程序/方法评分均为 4，迁移未知、提示等级 4，无独立证据；同日评估 | 不出现“基本掌握”及更高状态，不因高分降低独立复查优先级；旧反例的低优先级/21 天安排不能沿用 |
| T02 对应 R06 | 看提示/题解后答对，点重新练习，再答同题且本轮不点提示 | 保留暴露历史，标为同题重做，不作为新的独立掌握证据 |

| T08 对应 R03/R08 | 结果重复上传、报告下载、后台任务完成，随后真正提交人员行动结果 | 不重复计完成；下载/后台成功不当人员完成；真实结果关联后相关页面更新 |
| T09 对应 R07 | 切换学生/项目期间旧异步请求返回；修改或撤回正在引用的来源 | 旧结果不得落入新范围；受影响当前建议失效/待核验，历史版本可追踪 |
| T10 对应 R05 | 指定桌面/手机视口、长中文标题、键盘及 200% 缩放 | 主行动可达、文字不重叠、来源可读；正常手机首屏符合第 8.2 节，不只检查横向溢出 |
| T11 对应 R09/R10 | 模拟部分失败的资料/会话处理中刷新，再恢复任务 | 保留原任务与有效部分；未完成不变已整理，部分收到不变完整归档 |
| T12 对应 R11 | 原有资料时间线加入一个新事件，进入详情后返回，关闭未保存编辑 | 历史不消失；事件下钻正确；筛选/位置恢复，草稿保留或退出提醒有效 |
| T13 对应 R12/R14 | 选教材、AI 摘要、已核实本人贡献和两个不同成果，生成目标提纲 | 资源与建议不变成个人事实；贡献回查正确；不同成果不冒充同一成果版本 |
| T14 对应 R13 | 同一纸上作答重传，再提交同题新作答和新练习 | 仅重传去重，新作答分别记录题目/版本/条件/时间与原行动 |
| T15 对应 R09 | 仅安装来源、完成配置但无事件、授权前历史、撤销后迟到事件、切换学生 | 无事件不称采集中；不补采历史；迟到补交遵守授权合同；不会按当前页面学生错误归档 |
| T16 对应 R09/R12 | 候选缺原文、原话不匹配、敏感/冲突未确认或含提示注入，再尝试入库与撤销 | 按现有治理阻断；输入内容不成为执行指令；撤销范围限定原事务，原文和无关成果保留 |
| T17 对应 R15 | 窄屏进入课程/收件箱并多选，宽屏核对原文，检查文字和触控区域 | 五导航短标签、课程直达、底部批量工具可用；原文/整理可并排；字号与点击区域符合第 8 节 |
| T18 对应 M26 | 共享学生启用文件夹监听、教师换目标、重复与未稳定文件、离线恢复 | 共享禁用；旧队列不改归属；稳定后发送、重传幂等，新修订不丢 |
| T19 对应 M27 | 仅采集/只读授权发起写入；预览后改内容；批准后撤权或重复执行 | 越权/内容变化阻断，执行复核授权；旧批准不扩大范围，结果幂等、令牌不泄露 |
| T20 对应 M28 | 导入相冲突规则、生成适配文件、取消迁移预览 | 有差异与覆盖提示；取消不改原文件；导入内容不成为自动指令，未选工具配置不变化 |
| T21 对应 M29 | 团队策略关闭、学生端切范围、远端离线、仅部分授权项目命中 | 不越权；局部结果保留且标覆盖不足/时间；无命中不等于不存在，不回退到无权范围 |
| T22 对应 M30 | 同名不同谱系项目、多接收方映射、离线重复包、任务附件拒绝 | 不按名称合并、不送无关节点、不重复任务/附件；拒绝不入库，不覆盖接收端已有成果 |
| T23 对应 M31 | 非充电/网络不满足、关闭自动后手动执行、重启恢复计划、仅打开维护页 | 准确显示等待条件；允许原有手动动作，不重复建任务；页面读取不触发修复和全库写盘 |
| T24 对应 M17 | 错密码、非空目录、容量/席位不足、U盘中断、旧版本目标、恢复系统授权 | 正式切换前阻断风险；可恢复文件不重做；密钥/录屏授权不随包恢复，原机数据不删除 |
| T25 对应 M01/M15 | 共享退出/超时后另一学生进入；教师切学生后离线看已缓存报告 | 共享上人正文/状态清空，教师缓存按学生隔离保留；未缓存内容不凭空生成，采集不能转人 |
| T26 对应 M21 | Android 原文哈希改变、处理中回收、有依赖永久删除、旧归档无候选 | 不把被替换原文作依据，非法删除阻断；旧归档不反推候选，合法删除审计不含正文 |
| T27 对应 M01/M18 | 未激活删除、席位不足建档、相机权限拒绝、教师端检查更新、长翻译与横竖屏 | 限制有效；可用替代激活入口保留；不下载其他端包；偏好不丢、文字可读和动作可达 |
| T28 对应第 3.1 节 | Agent 安装检测进行中/失败，反复读取资料/报告元数据 | 不误报卸载或改默认工具，保留上次结果并标状态；不隐式全量哈希/重建，实际处理仍校验证据和权限 |
| T29 对应 M09/M24 | 未确认候选用于正式报告、轻终端尝试审核、缺模型时生成、重建索引 | 未核实/越权阻断，已有有效正文保留；索引重建不重写原始事实及历史发布版本 |
| T30 对应 M03/M18 | 仅本地 OCR、视觉测试失败、外部服务停用、录屏未授权 | 本地操作不外发，非学生测试样例可核对；OCR 保留，服务降级准确；录屏不沿用会话授权 |

再检查移动端触达、桌面键盘操作、弹层焦点恢复、缩放、减少动效及对比度。M01–M31 逐项声明本批支持、仅示意或未纳入；已有管理能力不能在导航重组中静默丢失。E19 为抽查路径，不代替逐项台账；只有完成全部适用旧功能盘点与验证后才可声称全量迁移。以上门槛不替代云端 HTTPS、许可撤销、断网恢复、真实设备和发布审计。
