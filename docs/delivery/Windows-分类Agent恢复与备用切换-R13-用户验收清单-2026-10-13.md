# R13 用户验收清单

仅使用 `smart-material-agent-recovery-r13d-20261013` 最终候选。R13/R13b为包内验证失败的中间构建，R13c也已被替代，不安装使用。

## 需要您操作

1. 关闭当前教育管家后使用最终候选，在资料收件箱选定学生。确认认证故障显示“等待 Agent”，不再误称“需人工选择项目”。
2. 若继续使用WorkBuddy，点击“重新授权 WorkBuddy”，在官方页面完成登录；不要提供密码或Token。桌面自带CLI缺少登录模块时，按对话框选择此前下载的官方完整CLI包目录（包含`package.json`）。完成后点击“我已完成登录，继续”。
3. 若允许备用，在本学生的“分类 Agent 设置”点击“允许 Codex 作为备用并继续”。这会允许此学生的必要资料发送给Codex；仅启用需要使用该能力的学生。Codex需使用其官方登录。
4. 新加入一份项目归属明确的普通教育资料，确认WorkBuddy不可用时可由Codex完成建议；来源已开启自动投递且资料满足可信条件时检查“已投递”中的实际位置。证据不足仍应留在待确认。
5. 对无Agent可用的普通待办，测试手动指定项目投递；检查原件仍在、登记位置正确。关闭备用后不得再向备用Agent派发。
6. 对历史“执行待核对”记录先查详情及既有投递记录。这些记录缺少旧版本发送证据，升级不会自动重发；不要以反复点击、删除账本方式绕过核对。无法判断时保留待办，将记录编号和非正文诊断交给开发侧排查。

## 需要您提供场景，开发侧负责测量

- 四核/8GB/SSD目标设备上的页面翻页、切换学生、扫描与分析并发，以及四小时混合运行。
- 已授权且独立标注的资料样本，核验跨学生为0、自动投递准确率与覆盖率。
- 代表用户30份资料的实际操作与纠正时间。

开发侧已负责代码回归、隔离页面、包内任务中心及合成资料测试。上述目标机与业务质量项目仍为待验收，不能因候选包生成而视为完成。
