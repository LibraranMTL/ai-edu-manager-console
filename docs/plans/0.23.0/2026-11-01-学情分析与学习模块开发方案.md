# AI教育管家学情分析与学习模块开发方案

**交付目标**　学生提交一次周反馈或完成一次练习后，系统能说明「当前目标是什么、遇到了什么问题、下一步做什么」，并把下一步直接变成可执行的任务或学习卡。学生完成后，结果自动回到同一条学习记录，更新问题优先级和后续行动。

**需求依据**　2026 年 10 月 29 日《AI教育管家 学情分析与学习模块功能说明》客户沟通版，第一至第七节及三张表。原文规定一个状态总览和五个持续跟踪维度，分别为**学习目标、学习心态、学习问题、学习方法、学习效率**。原文要求的自动发布、用户纠正、撤回和权限控制贯穿三个阶段。[客户沟通版原文](https://chatgpt.com/library?file_id=libfile_85834636dd1081919ebde1eecc96f1ae&account_id=personal)

**技术基线**　2026 年 11 月 1 日复核时，Git HEAD 仍为正式 Windows 0.21.6 所在提交 `1bc23c68`，但当前工作树 `package.json` 已标为 0.22.8，并包含大量未提交候选改动；0.22.8 验收记录仍是“预候选、不得发布”。实施必须先从实际目标候选建立干净工作树，记录源码状态、包体指纹、数据库版本和配套终端版本。下文标为「建议」的阈值、工期、存储和接口名均是工程决策，供试点校准。

## 〇　评估结论与修订决策

**总体判断：产品目标清楚，自动发布与自动下一步也已有较完整的安全边界；主要问题是一期同时包含状态模型、问卷、目标、问题、任务、卡片、学生端和恢复，规模被低估。** 修订后将一期拆为 1A“状态可读”与 1B“行动闭环”两个放行门，仍保留自动发布和自动行动的产品决定。

| 评估项 | 结论 | 修订后的处理 |
|---|---|---|
| 五维模型 | 适合持续跟踪，但五维证据类型不同，不适合合成单一总分或排名。 | 分维呈现事实、趋势、覆盖和建议；不提供“综合学情分”“心态分”或跨学生比较。 |
| 自动行动 | 可行，现有任务、卡片、回执和未知结果保护可复用。 | 先自动发布观察项；达到版本化规则后才创建行动。每个问题同一复测窗口最多一个有效行动，并受学生总容量限制。 |
| 身份与权限 | 主机管理员能力不等于真实教师/家长授权。 | 未完成可信绑定前，只提供管理员选择读者的授权摘要导出；不宣称独立家长在线查看已交付。 |
| 数据质量 | `occurredAt`、`recordedAt`、作答根、提示状态和撤回事件均可能缺失。 | 所有指标显示分母/覆盖；未知不填零；同一作答的订正和复评不算独立证据。 |
| 工期 | 原 30–47 人日只适合作为前置能力齐全时的内部试点估算。 | 准备阶段给出 P50/P80；当前低置信参考为 39–63 人日，另计真实周反馈、延迟复测自然时间和身份系统缺口。 |

**产品边界。** 五维总览用于帮助学生采取下一步，不用于医学/心理诊断、纪律处分、自动排名或对教师绩效作评价。学习心态原话默认按敏感字段处理；普通报告只使用经授权的最小摘要。

## 三　数据如何进入和离开系统

| 原文规定的来源 | 接入与归属要求 |
|---|---|
| 学生定期反馈 | 学生身份下提交首次基线或本地自然周反馈，保存题版、已答项、跳答项和提交标识。历史档案文字不充当学生本人答卷。 |
| 学习资料 | 订阅已完成消化或评阅的作业、测验、错题、订正、项目成果。引用材料版本和具体位置；资料内提到某知识点，只能证明有接触。 |
| 学习过程 | 使用作答、提示、独立复测、返工和任务达标事件。绑定学生、任务及作答根 ID；同一次作答的修订或复评沿用同一根。 |
| 学习对话与求助 | 从已获授权的对话中提取与目标有关的困惑、尝试和求助方式。系统给出的建议与学生已采用的做法分别记载。 |
| 教师或家长观察 | 由获授权的观察者记录时间、场景及观察内容并保留作者角色。外部观察可以补充或与学生自述并列，不能覆盖自述。 |

**建议采用主机端六类记录。** `Goal` 存目标、标准与里程碑；`CheckIn` 存问卷类型、周期、题版及授权；`Evidence` 存来源、发生/入账时间、版本、学生归属与访问范围；`Finding` 存维度、事实或推断、置信度及理由、规则版本和证据引用；`Action` 存路由、到期日、实体 ID、回执与状态；`Correction` 记录补充、更正、撤回与受影响的派生项。原始文件沿用现有索引，敏感自由文本单独存放，普通证据只保留受控引用。

**先冻结状态机再建表。** `Goal` 至少区分草稿、进行中、已达成、放弃、被替代；`Finding` 区分观察、推断、待复核、有争议、已撤回、被替代；`Action` 区分意图、排队、可开始、进行中、已完成、取消、暂停、过期和失败。`Action=已完成` 只证明行动发生，不能自动把 `Goal` 或知识掌握改为达成。`Correction` 采用追加式记录，不物理覆盖原结论；当前视图由有效版本投影得到。

六类记录应与项目报告统一 `SubjectScope`、`EvidenceRef`、`AsOfCutoff`、`AccessProjection`、`CommitKey` 和 `Correction/Withdrawal` 的字段含义，但不共享判断状态机。每条派生结果必须能回答“哪个学生、截至何时、基于哪些有效来源、按哪个规则版本、对哪个读者可见”。

优先复用目标版本已有的学生状态存储。若无可用域表，建议在主机受控数据目录增设 `learning-state.sqlite3`，按学生隔离、版本化迁移，后台短事务写入。状态变更与待执行行动意图同一事务提交；向既有卡片/任务系统派发后回填实体 ID。用现有 Worker 和资源协调策略消费，不另设独立常驻调度器。旧档案没有问卷或目标标准时显示「待建立基线」，更新不扫描全体学生。

## 四　分析规则和自动行动

**发布口径。** 总览明确区分「学生自述」「家长或教师观察」「系统观察」「系统推断」。每条正式展示携带时间、来源、覆盖度、分析版本、置信度及其理由。有效自述可立即发布为「学生本周自评……」；一次有来源的错题可立即成为观察项。资料不足、来源冲突或不同任务不可比时仍可展示已知事实，同时标记待补证据。合格结果通过机器校验后直接发布，日常不设置人工审批队列。

**如何解释置信度。** 学生自述显示「本人填报」和时间，不对学生的诚信打分。对系统推断，首版用低、中、高三级并解释原因：只有单次间接线索为低；有可追溯的直接观察可显示中；多个独立、可比的来源相互支持且无未解冲突，才可显示高。覆盖度列出所用来源及最近日期，来源数量本身不决定置信度。心态趋势优先跟踪同题自评变化，系统观察和外部观察仅作补充。

| 分析结果 | 第一版行为和目标入口 |
|---|---|
| 同类知识错误、薄弱点、到期复测 | 单次观察；建议初值为同一学生、同一知识点/错因在 14 天内至少两个独立作答根出现，升级为优先问题，向学习卡片发出一项专项练习、订正或间隔复测。一次明确的测评复测要求也可直接触发。 |
| 目标临近或进展不足 | 仅在目标仍有效且未达标时进入任务中心。建议默认截止前 3 天提醒；无进展以目标约定的检查周期判断。仅缺上传记录时让学生更新进展，不能声称学生没有行动。 |
| 方法调整 | 需要学生准备材料、拆任务、复盘错因或做方法实验时进入任务中心；可通过一次有明确目标的作答验证时生成学习卡。主行动选一个去向，关联已有行动可直接复用。 |
| 效率明显变化 | 在可比任务中发现有效产出、独立性或返工变化，创建「检查返工原因」或「调整下次计划」的任务。只有自报负荷上升时可建议缩小任务或调整安排，明确标为自述。 |

**防止自动循环。** 一份材料重复投递、同一次评阅重放、同一个结果换措辞均不新建行动。用「学生＋目标或问题实例＋行动类型＋复测轮次/到期窗口」做稳定业务键，数据库唯一约束和目标实体外部键同时生效。分析版本只用于追溯，不能靠改版本绕过去重。只有有实质新证据或新的复测窗口才开启下一轮。学生取消未开始动作后保存抑制记录，普通刷新不能让它复活。

## 五　三个阶段的开发任务

### 准备　锁定基线和端到端样本

- [ ] 产品和开发逐条核对本文第二至四节与原文，从目标候选建立干净、可回滚的实施工作树，锁定实际 Windows/学生端/教师端版本、源码/包体指纹、数据库、现有权限以及可用执行器。当前 0.22.8 底座候选未通过发布门禁时，本模块只能形成开发候选。
- [ ] 同一份夹具包含首次反馈、两项独立错题、一次订正、一次老师观察、一段私密原话、一次延迟复测。给每项规定预期归属、可见读者、允许产生的行动数量和停止条件。先保存旧版报告与卡片基准。

### 一期　总览、基线、目标、问题与行动闭环

**一期 1A 放行门：状态可读。** 先交付证据/状态存储、首次基线、周反馈、目标与问题视图、更正撤回和权限投影；关闭自动行动时仍能完整演示。必须通过跨学生隔离、重复提交、历史截止时刻和页面零副作用测试。

**一期 1B 放行门：行动闭环。** 只有 1A 稳定后才启用自动任务/卡片。达到规则的同一问题在同一复测窗口最多一个有效行动；容量上限、提醒窗口和升级阈值均须版本化、可配置，并在准备阶段用试点样本冻结初值。执行未知、卡位已满或配对端离线时保留同一行动意图，不新建替代行动。

- [ ] **1. 建立证据与状态存储。** 拟增 `electron/learning-state-store.cjs`、`learning-state-analysis.cjs`。学生范围由主机或登录会话解析。对外来证据使用稳定来源 ID、来源版本与事件类型去重，保留作答根。接入资料消化、练习评阅、项目进展和授权对话；项目团队成果只有在学生贡献归属明确时才成为个人表现。
- [ ] **2. 做出总览和周反馈。** 在 `src/main.tsx` 的「学情与学习」增加 `LearningStatePanel.tsx`。首次基线记录近期重点、当前目标和五个心态观察项；每周用约五次点选覆盖目标清晰度、信心、困难感、受挫后恢复和负荷，可选补充一句。允许跳答和本周订正。主机可管理；在已有受认证学生入口提供最小提交及查看行动能力，使一期能由学生亲自走通。
- [ ] **3. 让目标和问题可追溯。** 提供新建/修改目标、关联任务或成果、核对完成标准、查看逾期或缺进度。日期驱动的到期提醒复用主机已有定时唤醒，即使当天没有新资料也能触发。问题按观察中、需行动、待复测、已缓解或已关闭呈现；用户能打开来源，补充说明、纠正或撤回。勾选任务完成只说明做过，达成目标仍需符合其标准。重复错题阈值、检查窗口为可版本化规则。
- [ ] **4. 自动派发两个去向。** 拟增 `electron/learning-state-actions.cjs`。学习任务作为专门的学生行动投影进入现有任务中心，具备待开始、进行中、部分完成、完成、暂停及取消等状态；后台 Agent 任务只表示系统执行。知识卡复用 `createPracticeCards` 的生成、独立质量复核和学生端 `workspace/start/submit`，增加业务行动键、指定知识点和来源。没有个人计划时，为本次有依据的请求提供最小定向练习参数，不能改写学生原计划。卡位已满则保留意图进入队列，执行器离线则显示等待，拿到真实卡 ID 才显示「已生成」。[学习卡学生入口](https://github.com/LibraranMTL/ai-edu-manager-console/blob/1bc23c68d09c495bd0f9d2800ccbe1d46b5c937e/electron/student-publications.cjs)
- [ ] **5. 收到反馈才闭环。** 任务完成提交结果/成果引用，卡片作答进入原有评阅流程。按行动 ID 及有效作答版本回写证据、重算状态和优先级。执行未知先查原任务或卡片回执；进程在「卡片创建成功、行动绑定未写回」之间退出，重启后找到同一卡并补记。暂停学生自动化时停止新派发；允许用户暂停、恢复或取消未开始动作，保留已经开始的作答历史。

**一期交付门槛**　用原有界面提交两次独立错题，自动出现一个有关联依据的问题和一张可开始的卡，学生作答后在总览看到变化。全程无需人工点「批准」。若卡片学科没有可验证映射，仍保存行动和反馈，正式知识掌握度保持原有验证门槛。

一期还必须提交 1A 与 1B 各自的开关、迁移和回退证据；关闭 1B 后，已经开始的卡片可继续完成，未开始的自动行动不再派发，1A 状态与历史仍可读。

### 二期　方法实验、效率与延迟保持

- [ ] **6. 采集可解释的过程信号。** 从 `practice-feedback.cjs` 与 `learning-analytics.cjs` 复用提示使用、`rootAttemptId`、修订链、评阅版本和来源撤回。同一作答的改判以最新有效结果替代；订正用于记录返工，不算第二次独立尝试。未记录是否受助时显示「未知」。新增返工原因、明确的独立尝试、方法实验和新题延迟复测事件。[评阅与订正](https://github.com/LibraranMTL/ai-edu-manager-console/blob/1bc23c68d09c495bd0f9d2800ccbe1d46b5c937e/electron/practice-feedback.cjs)
- [ ] **7. 建立个人方法库。** 每条方法保存适用学科/任务、学生做法、使用条件、前后任务及证据、当前结论。可由「先独立尝试」「先拆分步骤」发起小实验。仅在难度、目标、提示条件大致可比时描述变化；只有自评就显示「学生认为有帮助」，样本少时保留「待验证」。允许学生添加解释及修正适用场景。
- [ ] **8. 产出效率明细。** 显示到期目标达标数/可评价到期目标数、有依据的有效产出数、独立完成数/受助状态已知的可比任务数、每轮返工与原因、到期复测中的保持结果。投入优先取自愿填写或可验证的有效工作段。每项显示分子、分母或样本量；分母为零、时间未知或前后不可比时明确说明。屏幕时长、资料量和登录次数只作背景，不生成综合效率分。

**二期交付门槛**　用两次相近任务、一份订正、一次延迟复测解释哪种方法在何种条件下可能有用，并生成一次相应的调整行动。只导入一批资料、只延长屏幕时间或对同一作答重新评阅时，不产生效率改善或能力下降的结论。

### 三期　融合正式报告、按角色展示和交付

- [ ] **9. 固定报告截止时刻。** 分别接入 `buildPeriodicLearningReportTask`、`buildWeeklyActionTask` 两条生成路径，以及 `learning-report-workflow.cjs`、`report-auto-publication.cjs` 的发布校验。整体画像引用较稳定的目标和方法，历史变化给可比窗口，阶段总结列进展与证据，每周行动建议直接引用已存在的任务/卡。两路报告的更新判断和发布前复验均纳入五维快照指纹、权限版本和来源撤回；同周期重新生成报告不能重复发任务。保留旧文件名和既有报告校验，新增五维证据命名空间及解析器，按截止时刻重建状态，不能把最新状态倒填到旧周期。[报告发布校验](https://github.com/LibraranMTL/ai-edu-manager-console/blob/1bc23c68d09c495bd0f9d2800ccbe1d46b5c937e/electron/report-auto-publication.cjs)
- [ ] **10. 分端授权。** 学生看到本人的目标、自评、依据和行动；教师看到主管学生获准的教学证据、行动及其变化；家长得到与绑定学生相关的简明趋势、行动和可提供的支持。机构按授权查看流程和状态。主机侧生成不同读者的字段白名单投影；正文、历史、差异、原文、导出与云同步一致过滤。教师设备现有宽范围读取不能自动授权敏感原话；家长身份/绑定如果尚不可验证，先提供管理员选择已授权读者的摘要导出，并将独立在线家长查看作为绑定完成后的放行项。
- [ ] **11. 恢复和试点。** 在 Windows 主机、受支持 Windows/Android 学生端及实际教师端各验证一个授权流程。离线周反馈用同一提交键重放，切换学生清旧缓存。将新增状态库、存储版本、撤回记录及行动绑定纳入备份/迁移；敏感原话按单独权限与备份策略处理。恢复后先核验授权与原行动回执，再重建视图。灰度按学生开关启用，关闭后停止新增派发，保留已有可核对的资料和行动记录。

## 六　接口、权限和纠错

| 拟新增服务接口 | 最低契约 |
|---|---|
| `submitCheckIn(scope, payload, clientSubmissionId)` | 同一学生同类同周期只有一份有效反馈，重试返回原记录，主动更正生成新版本。作者、采集方式、题版和答题时刻可核查。 |
| `upsertGoal(scope, goal, expectedRevision)` | 校验学生归属、目标类型、截止时间、完成标准。更新带版本前置条件，避免覆盖学生刚做的修改。 |
| `ingestEvidence(scope, sourceRef, revision)` → `publishFindings(studentId)` | 在同一学生范围接纳来源或撤回事件。用户可见内容只从有效证据生成；自述、外部观察、系统观察和推断明确分列。旧批次不能覆盖新状态。 |
| `dispatchLearningAction(actionKey)` / `recordActionFeedback(actionId, feedbackId)` | 相同业务键返回原任务或卡；反馈按有效版本去重。新增证据才触发后续分析，读取页面、重启和重放旧回执不会驱动循环。 |
| `correctOrWithdraw(scope, objectId, revision, reason)` | 保留最小更正痕迹，撤除失效结论，重算依赖项，取消仅由其支撑且未开始的行动；已开始或完成的保留操作事实并标明依据变化。不得将已撤回原话继续带入摘要。 |
| `getLearningState(reader, studentId, asOf)` | 由服务端验证身份、学生范围、数据分类与用途。无权读取的原话、标题及衍生句不进入响应、缓存、Agent 输入或日志。导出和同步使用同一授权投影。 |

学习心态只产生学习支持建议，例如缩小本周任务、安排一次短复盘。系统不做医学或心理诊断，不用“厌学、焦虑”等标签解释行为。学生说「本周有些吃力」且作业按时完成时，两条都可以是真实记录；把它们并列给读者，不用一个覆盖另一个。

## 七　放行测试与交付证据

| 编号 | 场景 | 可观察的通过条件 |
|---|---|---|
| A1 | 首次基线、周反馈、跳答和断网重发 | 基线与周反馈分开。相同提交只有一条有效记录；漏交显示「未反馈」。用学生试填记录周反馈完成时长，目标约 1 分钟。 |
| A2 | 自评负荷高，教师观察正常，任务已完成 | 分列三种来源、时间与覆盖，推断标识可见。可提出学习安排建议；没有诊断性标签。 |
| A3 | 一份错题多次导入，之后第二个独立作答再错 | 首次自动发布观察项；重放不升级。第二个独立根触发优先问题与一张可打开的专项卡。 |
| A4 | 目标到期、未同步进度、确有里程碑达标 | 到期只派一项提醒；没有过程证据时提示更新。达标证据到达后目标与未开始的提醒同步更新。 |
| A5 | 卡位已满、执行器离线、执行未知、创建后断电 | 页面准确区分等待、失败和已生成；恢复后绑定同一张卡。已开始作答保留；取消或暂停的未开始动作不会被刷新复活。 |
| A6 | 学生提交任务反馈、作答、改判、撤回 | 完成任务不等于知识掌握；评阅反馈能返回原问题。改判或撤回后旧推断、已排队行动和授权摘要按规则收敛。 |
| A7 | 学生自报方法有效，实际训练条件不同 | 显示自评与证据差异。不能比较的任务不会产生“方法有效”的确定结论；同类任务有证据时能形成可复用条目。 |
| A8 | 仅增加时长/文件量，同题多次订正，之后做新题复测 | 前两者不抬高效率或保持指标；新题复测独立计入。未知受助状态不计入独立完成率分母。 |
| A9 | 两名学生共享设备，教师或家长只获其中一人的摘要权限 | 在原话中插入唯一的合成标记。切换、原文下钻、历史、报告、日志、文件导出、云上传请求及撤权后的待传重试均不得向无权读者暴露该标记。现有云投影仅移除本机路径，需要新增按可见字段生成摘要的步骤。 |
| A10 | 新周反馈改变了状态，但原成长模型数据未改；重启或更换主机 | 五维快照使相应报告可更新，旧周期仍按其截止时间展示。恢复保留行动 ID、取消/撤回和当前权限，不重复派发。 |

**真实使用验收**　每期交一组匿名原始输入、预期状态、实际任务/卡 ID、反馈回执和权限对照。试点重点观察三项：周反馈完成时长、中途放弃比例，以及已触发行动中可由学生实际打开并完成的比例。重复派发、跨学生泄露、虚假掌握结论、未经证实就显示完成，任一出现即暂停相应自动路径并修正。发布条件是通过目标安装包和真实终端验证；本方案中的用例与排期尚待实施。

## 八　与另外两份方案的依赖

1. “每周知识增长统计图”的知识点首次登记只表示知识库新增，不能直接作为本模块的学习进步、方法有效或效率改善证据。
2. “项目总体报告”的项目事实和个人贡献可通过受控 `EvidenceRef` 进入本模块；团队成果未确认个人归属时不得成为学生个人学情结论。
3. 三个模块共享截止时刻、授权投影、更正/撤回和幂等提交测试夹具；学情模块独占目标、问题、方法、效率和行动状态机。
4. 建议先交付周图验证单学生范围与导出，再交付一期 1A/1B，最后把稳定的证据与授权契约接入项目报告 M1/M2。
