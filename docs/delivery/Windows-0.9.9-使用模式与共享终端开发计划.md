# Windows 0.9.9 使用模式与共享终端开发计划

> 实施状态：代码开发、自动化测试、操作手册与三端程序包已经完成；发布前仍需在真实 Android / Windows 学生终端上完成多人轮换、扫码或输入 ID、上传、退出与断线重连验收。

> 计划日期：2026-07-22  
> 开发基线：Windows 主机版 / Windows 学生终端 0.9.8，Android 学生终端 0.6.0  
> 候选版本：Windows 主机版 / Windows 学生终端 0.9.9，Android 学生终端 0.6.1  
> 计划性质：开发范围与验收基线；版本号只在代码、测试和程序包全部完成后正式更新  
> 产品原则：不增加 PIN、密码、角色或细粒度权限；学生扫码或输入个人 ID 后，系统只负责把资料、项目和报告稳定隔离到当前学生  

## 一、开发目标

本轮解决两个相互关联的问题：

1. 教室中多人共用同一学生终端时，取消学生名单选择，改为扫码或输入学生个人 ID，避免误选档案和上传错目录。
2. 将首页中的“使用模式”及重复的主机服务配置迁入“系统设置”，形成主机版和学生终端一致的使用模式入口。

完成后的产品结构：

```text
Windows 主机版
├─ 主机模式：教师/家长只在本机管理资料，不启动终端协作服务
└─ 主机-终端模式：启动主机服务，接收 Android / Windows 学生终端

Android / Windows 学生终端
├─ 个人终端：首次扫码或输入 ID 后固定绑定一名学生
└─ 共享终端：每次扫码或输入 ID 建立当前学生会话，退出后可由下一名学生使用
```

Windows 主机版和 Windows 学生终端继续保持两个独立程序包，不把管理端和学生端重新合并为一个可切换身份的 EXE。

## 二、范围边界

### 2.1 本轮纳入

- 主机模式、主机-终端模式、个人终端、共享终端的统一模式模型。
- “使用模式”从主机首页迁入系统设置。
- 主机服务、设备配对、设备模式、个人终端绑定和共享终端说明统一收口到系统设置。
- 学生档案自动生成稳定、唯一、可输入的登录 ID 和对应二维码。
- Android 和 Windows 学生终端支持个人终端 / 共享终端选择。
- 共享终端支持扫码或输入 ID 进入当前学生会话，不显示学生名单。
- 普通文件、截图、屏幕采集、项目资料、报告和档案全部按当前学生会话隔离。
- 现有学生、项目、知识库目录、内部学生 ID 和文件路径原地兼容。
- 主机端保留后台上传记录和设备诊断，但不把内部会话、Token 和隔离校验暴露给学生。

### 2.2 本轮明确不做

- 不增加 PIN、密码、短信验证码、人脸识别或统一账号中心。
- 不建设教师、家长、学生等角色权限体系。
- 不把学生登录 ID 作为隐私或安全认证凭据；它只用于识别当前资料归属。
- 不允许共享终端长期运行自动投递文件夹。
- 不合并 Windows 主机版和 Windows 学生终端安装包。
- 不更换现有 LLM Wiki Engine，不引入 GBrain、数据库、Docker、外部 MCP 或常驻服务。
- 不修改成长模型、学情报告和知识消化的业务结构，只调整终端访问和资料归属入口。

## 三、统一使用模式设计

### 3.1 模式枚举

内部统一使用以下模式：

| 模式 | 程序 | 行为 |
| --- | --- | --- |
| `host` | Windows 主机版 | 本机管理；主机服务默认停止 |
| `host_terminal` | Windows 主机版 | 启动或允许启动终端协作服务 |
| `terminal_personal` | Android / Windows 学生终端 | 固定绑定一名学生；启动后自动进入该学生 |
| `terminal_shared` | Android / Windows 学生终端 | 每次扫码或输入 ID；退出后清空当前学生状态 |

主机版只展示前两项，学生终端只展示后两项。界面统一命名为“使用模式”，但不向用户展示内部枚举值。

### 3.2 模式持久化

当前首页的 `homeMode` 只是前端临时状态。本轮改为正式持久化设置：

- 主机模式写入主机设置文件，应用重启后保持。
- 终端模式同时保存在终端本地和主机设备记录中。
- 模式切换写入主机事件记录，供故障诊断使用。
- 主机模式切换为主机-终端模式时不自动弹出技术配置，只展示“启动服务”主操作。
- 主机-终端模式切回主机模式时停止接收新终端请求；正在上传的文件先完成或明确失败，不截断到半文件状态。

### 3.3 模式切换规则

- 个人终端首次使用时扫码或输入一次学生 ID，主机记录 `boundStudentId`。
- 个人终端后续自动建立该学生会话，不重复选择学生。
- 个人终端改为共享终端时，解除固定绑定、结束当前会话并关闭自动投递。
- 共享终端改为个人终端时，需要扫码或输入一次学生 ID 完成固定绑定。
- 主机端可查看设备当前模式，并执行“解除个人绑定”或“结束当前学生会话”。

## 四、信息架构调整

### 4.1 首页调整

首页不再放置使用模式选择卡和完整主机服务面板。首页只保留：

- 当前使用模式摘要。
- 主机服务运行状态。
- 已连接终端数量。
- 今日上传和待处理资料摘要。
- “前往系统设置”入口。
- 首次使用清单；相关按钮统一跳转到系统设置中的“使用模式”。

主机上传记录属于日常资料处理，不属于模式设置，迁入“资料收集与处理”模块；首页只显示数量摘要。

### 4.2 系统设置中的“使用模式”

系统设置首段新增“使用模式”，包含：

1. 主机模式 / 主机-终端模式选择。
2. 主机服务启动、停止和状态。
3. 局域网连接信息、端口和诊断。
4. 终端配对和已连接设备列表。
5. 每台终端的个人 / 共享模式、个人绑定学生和当前会话状态。
6. 学生登录 ID 与二维码管理入口。

现有系统设置中重复的“主机服务连接信息”和首页配对面板合并为一套组件，不再双份维护。

### 4.3 学生终端设置

Android 和 Windows 学生终端的设置页统一增加“使用模式”：

- 个人终端。
- 共享终端。
- 当前主机。
- 当前绑定学生或当前登录学生。
- 退出当前学生。
- 解除个人绑定。

共享终端的默认首页改为学生 ID 输入 / 扫码入口；未进入学生会话前不显示报告、档案、项目和上传目标。

## 五、学生登录 ID 与二维码

### 5.1 数据字段

在现有学生对象上增量增加：

```json
{
  "id": "现有内部学生ID，保持不变",
  "loginId": "S-7K3M-2",
  "loginIdVersion": 1,
  "loginIdIssuedAt": "ISO-8601"
}
```

约束：

- `id` 继续作为知识库、项目、报告和文件资产的内部关联键。
- `loginId` 只用于终端识别，不替换现有内部 ID。
- 创建学生档案时自动生成 `loginId`。
- 旧学生档案在首次启动迁移时补建并持久化，不能每次启动重新生成。
- 字符集排除 `0/O、1/I` 等易混淆字符。
- 最后一位使用校验位，拦截多数手工输入错误；校验位不是 PIN。
- 主机端生成时检查唯一性，冲突时重新生成。

### 5.2 二维码协议

二维码使用结构化载荷：

```json
{
  "type": "AI_EDU_STUDENT_LOGIN",
  "version": 1,
  "loginId": "S-7K3M-2"
}
```

- Android 复用现有扫码能力，并区分主机配对码和学生登录码。
- Windows 学生终端优先支持手工输入和 USB 扫码枪的键盘输入模式。
- Windows 摄像头扫码优先使用 Electron/Chromium 可用的本地能力；不可用时保留 ID 输入，不新增外部运行时依赖。

## 六、学生会话与主机接口

### 6.1 会话定位

学生会话是数据隔离状态，不是账号安全系统。设备 Token 继续证明终端已经与主机配对；学生 ID 决定本次操作属于哪名学生。

建议增加：

```text
POST /api/student-session/login
POST /api/student-session/auto
GET  /api/student-session/me
POST /api/student-session/logout
```

- `login`：共享终端提交 `loginId`，主机返回当前学生会话。
- `auto`：个人终端按设备记录中的 `boundStudentId` 自动进入。
- `me`：返回当前学生摘要和可用功能，不返回其他学生列表。
- `logout`：结束当前会话。

### 6.2 会话规则

- 会话记录至少包含 `sessionId、deviceId、studentId、terminalMode、createdAt、lastSeenAt`。
- 会话 Token 使用随机值，只作为防止请求串线的内部技术标识，不向用户显示。
- 共享终端退出或应用重新启动后默认重新输入 ID；个人终端可自动续建会话。
- 共享终端连续无操作后自动退出，初始固定默认值，不新增复杂的用户配置项。
- 同一学生可同时在多台终端建立会话。
- 同一共享终端同一时刻只允许一个活跃学生会话。

### 6.3 数据接口收口

共享终端进入会话前，设备 Token 只允许调用连接、心跳、模式和学生登录接口。数据接口按以下规则修改：

- `/api/students` 不再向共享终端返回学生名单。
- 学生报告、档案、消化状态和上传接口要求当前学生会话。
- 即使 URL 中保留 `studentId` 兼容旧路径，也必须与会话中的 `studentId` 一致。
- 项目列表只返回当前学生绑定且允许终端查看的项目。
- 项目上传同时校验当前学生是否绑定该项目、项目是否封存。
- 主机管理 Token 仍可读取全部学生，不受学生会话限制。

## 七、资料、采集、缓存与报告隔离

### 7.1 普通文件和项目资料

- 当前学生会话建立后，默认目标为该学生原始资料库。
- 可选目标只显示该学生绑定且未封存的项目原始资料库。
- 主机从会话确定学生归属，不能只信任终端提交的 `studentId`。
- 上传记录继续写入设备、学生、项目、来源和稳定上传编号。

### 7.2 截图与屏幕采集

- 开始采集时立即写入不可变的 `ownerStudentId` 和 `sessionId`。
- 采集结束后切换学生，不得把原采集批次重新归给下一名学生。
- 当前学生退出时，有未上传采集资料则明确提示“保留给原学生稍后上传”或“删除本地临时资料”，不能静默转移。
- 主机收到采集资料时再次核对采集所有者和会话学生。

### 7.3 自动投递文件夹

- Windows 个人终端继续支持自动投递文件夹。
- 自动投递配置固定保存 `boundStudentId` 和目标资料库。
- Windows 共享终端禁用自动投递；切换为共享模式时停止监测但不删除本地文件。

### 7.4 报告和档案缓存

- 缓存继续按内部学生 ID 分区保存。
- 切换或退出学生时必须清空当前页面正文、列表、项目和缩略图状态。
- 共享终端只能在已建立的当前学生会话中读取对应缓存。
- 第一阶段不增加加密缓存和离线密码；个人终端继续保留现有离线报告能力。
- 共享终端完成一次在线登录后可在该会话存续期间读取本学生缓存；应用重启或退出后需要重新连接主机并输入 ID。

## 八、兼容迁移

### 8.1 学生数据迁移

- 现有学生 `id、name、rootPath、rawPath、summaryPath` 原样保留。
- 只补充 `loginId` 字段，不移动目录、不重命名文件。
- 迁移前备份 `students.json`，失败时保持旧数据可读。

### 8.2 设备迁移

- 旧设备只授权一名学生：默认迁移为个人终端并绑定该学生。
- 旧设备授权多名或全部学生：默认迁移为共享终端。
- 已撤销设备保持撤销状态。
- 新版终端通过能力字段声明 `student-session-v1`。
- 旧版终端不继续获得共享学生名单；主机明确提示升级终端，避免新旧协议混用后继续误投递。

### 8.3 模式迁移

- 当前首页 `local` 迁移为 `host`。
- 当前首页 `host` 迁移为 `host_terminal`。
- 模式写入正式设置后删除仅用于首页显示的临时状态。

## 九、分阶段实施顺序

### 阶段 A：模式与协议冻结

- 定义四种使用模式、学生登录 ID、二维码和学生会话协议。
- 增加 ID 生成、校验、唯一性和迁移单元测试。
- 增加会话 API 的纯函数与契约测试。

交付闸门：协议和迁移测试通过后再调整终端界面。

### 阶段 B：主机数据模型与会话 API

- 扩展学生和设备记录。
- 实现旧学生 / 旧设备原地迁移和备份。
- 实现登录、自动进入、当前学生和退出接口。
- 将学生、项目、报告、档案和上传接口接入会话校验。

交付闸门：伪造其他 `studentId` 的上传、报告和项目请求全部被拒绝或纠正到当前学生。

### 阶段 C：主机信息架构重构

- 将首页使用模式和主机服务配置迁入系统设置。
- 合并重复的主机服务、配对、诊断和连接信息组件。
- 首页改为状态摘要和业务入口。
- 上传记录迁入资料收集与处理模块。
- 增加学生登录 ID / 二维码查看与打印入口。

交付闸门：首页与系统设置不再出现两套主机服务控制；重启后模式保持。

### 阶段 D：Android 个人 / 共享终端

- 增加终端模式选择。
- 增加学生登录二维码识别和 ID 输入。
- 共享模式移除学生列表选择。
- 报告、档案、普通上传、分享上传和屏幕采集全部使用当前会话。
- 切换学生时清理页面状态并固定待上传资料归属。

交付闸门：学生 A 退出后，学生 B 登录不会看到或上传 A 的当前状态和待上传文件。

### 阶段 E：Windows 个人 / 共享终端

- 增加与 Android 相同的模式和学生会话状态机。
- 支持 ID 输入、扫码枪输入和可用时的摄像头扫码。
- 个人模式保留自动投递，共享模式禁用。
- 文件上传和屏幕采集按会话归属。

交付闸门：Windows 和 Android 对同一主机 API 的隔离结果一致。

### 阶段 F：回归、文档与发布

- 完成三端联调、升级回滚和断网恢复测试。
- 更新主机手册、Windows 学生终端手册、Android 学生终端手册、三端初始设置指南和网站下载页。
- 更新 CHANGELOG、版本清单、程序内版本和发布包名称。
- 分别构建 Windows 主机、Windows 学生终端和 Android APK，并核对实际产物后再更新正式版本号。

## 十、测试矩阵

### 10.1 主机接口

- 无学生会话时，共享终端不能读取学生名单、报告、档案和项目。
- 登录有效 ID 后，只返回当前学生。
- 无效 ID、校验位错误和已删除学生返回明确提示。
- 学生 A 会话请求学生 B 路径时不能读写 B。
- 项目不属于当前学生或已封存时拒绝上传。
- 退出和超时后旧会话不能继续上传。
- 管理端接口继续可读取全部学生。

### 10.2 Android / Windows 学生终端

- 个人模式首次绑定、重启自动进入、解除绑定。
- 共享模式扫码、输入 ID、退出、切换学生。
- 学生 A 截图后切换学生 B，截图仍属于 A 或保持待处理，不进入 B。
- 学生 A 的报告正文和项目列表不会残留到 B 的页面。
- Windows 共享模式无法启用自动投递。
- 上传中切换模式时不产生半文件和错误归属。
- 主机离线、重新联网和会话过期均有可理解的反馈。

### 10.3 信息架构与发布

- 首页不再包含模式选择和完整配对配置。
- 系统设置只保留一套主机服务控制。
- 当前模式摘要与实际运行状态一致。
- 0.9.8 升级后学生目录、项目、报告和设备记录不丢失。
- Windows 主机、Windows 学生终端和 Android 三端手册术语一致。

## 十一、验收标准

满足以下条件才可标记本轮完成：

1. 新建和旧学生均有稳定唯一的个人登录 ID 和二维码。
2. 共享终端进入前不需要也不显示学生名单。
3. 学生扫码或输入 ID 后可上传本人资料、选择本人绑定项目、查看本人报告和档案。
4. 主机端从会话限定资料归属，客户端修改 `studentId` 不能造成跨学生写入。
5. 个人终端无需重复登录，共享终端切换学生后不残留上一人的当前状态。
6. 截图、屏幕采集、失败重试和离线缓存不会因切换学生而改变所有者。
7. 使用模式已从首页迁入系统设置，重复主机服务配置已合并。
8. 旧学生知识库和内部 ID 不迁移、不重命名，0.9.8 数据可原地升级。
9. 自动化测试、三端人工联调、Windows 两个程序包和 Android APK 均验证通过。
10. 操作手册、下载网页、版本清单和 CHANGELOG 与实际程序一致。

## 十二、改动级别与主要风险

| 改动 | 级别 | 说明 |
| --- | --- | --- |
| 主机鉴权上下文与学生会话 | 重大 | 决定所有资料和报告是否真正按学生隔离 |
| Android / Windows 终端状态机 | 重大 | 涉及登录、切换、采集、上传、缓存和恢复 |
| 使用模式持久化与设备迁移 | 中等 | 需要兼容现有授权设备和旧设置 |
| 首页迁移到系统设置 | 中等 | 现有首页和设置存在重复组件，需一次去重 |
| 学生登录 ID 与二维码 | 中等 | 必须稳定、唯一且不改变内部学生 ID |
| 文档与网站 | 一般 | 三端术语、截图和版本必须同步 |

最大风险不是扫码界面本身，而是上传队列、截屏会话或缓存继续沿用上一个学生。开发时必须先完成主机会话约束，再开放共享终端界面，不能只依赖前端当前选择值。
