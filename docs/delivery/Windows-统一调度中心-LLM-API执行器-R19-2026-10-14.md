# Windows 统一调度中心：LLM API 执行器 R19

日期：2026-10-14
版本：0.21.1 候选功能增量

## 本次完成

- 在“Agent 接入与调度中心”加入与 Codex、WorkBuddy 并列的 `LLM API` 执行器。
- 支持学生级授权的资料分类、资料消化、学习卡片三个结构化任务合同。
- 支持在策略中设置主执行器与回退顺序，例如 `WorkBuddy -> Codex -> LLM API`。
- Agent 在发送学生资料前已明确失败时，调度中心可继续尝试后续执行器。
- Agent 已接收请求、执行结果不确定、任务被取消、权限或项目范围变化时，不自动回退，避免重复发送、重复计费或重复写入。
- 资料消化的 LLM API 通道只接收宿主提取并冻结的正文与 JSON Schema；API 无文件、Shell、浏览器或其他工具权限。结果仍由宿主校验资料 ID、版本、哈希和目标路径后提交。
- API 密钥通过 Electron `safeStorage` 加密后保存，渲染器、策略文件、任务记录和公开状态均不返回明文。
- 配置变更会使旧检测失效；首次处理学生资料前必须用合成数据完成结构化连接检测。

## 支持边界

| 任务合同 | LLM API | 说明 |
| --- | --- | --- |
| 资料分类 | 支持 | 只返回分类建议，宿主控制采用与落盘 |
| 资料消化 | 支持 | 宿主供给正文、无工具、宿主校验并提交知识 |
| 学习卡片 | 支持 | 结构化生成后仍走现有合同校验与审核流程 |
| 联网研究 | 暂不支持 | 尚未为通用 API 建立可核验来源、引用与网页证据合同 |
| 任意任务中心任务 | 不开放 | LLM API 不暴露为可写文件或执行命令的通用 Agent |

## 配置与验收

1. 打开“Agent 工具控制 / Agent 接入与调度中心”。
2. 在 LLM API 卡片中填写兼容 OpenAI Chat Completions 的 API 地址、模型和密钥。
3. 保存后执行“验证连接”；验证只发送固定合成内容，不发送学生资料。
4. 在具体学生（资料消化可进一步细化到项目）的任务策略中勾选授权，将 LLM API 放入需要的回退顺序并确认。
5. 用无敏感信息的测试资料检查路由历史，确认失败通道显示 `not_sent` 后才进入 LLM API。

本地自动化已覆盖配置加密、端点限制、合成检测、结构化输出、资料消化宿主提交、三执行器回退顺序及未知结果不回退。由于本次未提供真实 API 地址、模型和密钥，真实供应商调用、额度、模型兼容性与计费尚未验收，不能标记为正式发布。
