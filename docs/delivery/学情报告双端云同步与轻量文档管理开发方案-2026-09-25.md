# 学情报告双端云同步与轻量文档管理开发方案

日期：2026-09-25  
状态：本地试点源码开发中；尚未真机与发布验收  
源码基线：Windows 主机 `0.18.1` 候选；Android 单机版 `1.2.5 / code 29`。`edu-launcher-app-family` 是独立家庭版开发分支，其本机视觉网关试点不是云端报告服务。本方案不改 Windows 学生端或普通 Android 学生端。

## 1. 交付范围与用户流程

一套私有的轻量云端应用接收 Android 单机版与 Windows 主机端提交的**正式学情报告**，按学生、来源端、报告类型和修订管理。每端按学生取得一次上传许可并开启后，后续本机正式报告更新即自动排队上传，无需逐份确认；用户可随时关闭上传。某台 Windows 主机取得某个**云端学生档案**的文档下载许可后，可下载该学生由 Android 单机版或**其他 Windows 主机**上传的报告和获许可的其他文档；即使本机没有这个学生的本地档案，也可以在独立的云端文档入口查看。本机上传的报告已有原件，无需再从云端下载。

云端网页首版只提供“学生 → 学情报告 / 其他文档”：报告按名称、类型、日期筛选，查看来源、生成时间与历史修订并下载；其他文档由用户主动上传、下载、重命名展示名称、移入回收站及恢复。Markdown/PDF 可做安全的简单预览，DOCX 首版仅下载；标签、备注、复杂预览与云端正文编辑均暂缓。不自动同步原始资料、成长证据、知识库或全设备文件。文件类型与大小上限在 P0 定义，建议从 Markdown、PDF、DOCX 开始。同一主机-学生下载许可覆盖该学生的报告和其他文档；自动报告上传与手动文档上传分别管理和计量。

Android：学生档案 → 云端报告 → 一次许可并开启自动上传/查看状态。Windows 本地学生：学情报告 → 云端 → 一次许可并开启本机报告自动上传。首次开启只作一次清晰告知：将上传该学生当前有效的正式报告及此后的正式更新；不再增加“是否补传旧报告”的逐项选择，草稿和失效旧版本不上传。Windows 读取云端文档：云端文档 → 出示本机配对码 → 由已有权限的来源端确认学生并开通 → 查看/下载，不要求先创建本机学生档案，也不按文档来源分别申请。普通使用中只显示最近同步时间、待同步数、失败原因与重试，不重复弹出授权确认。上传是每个学生、每台来源设备的独立选项，默认关闭；关闭后立即停止新入队和待上传任务，已上传的云端报告仍保留，删除须单独操作。重新开启时只核对并补送当前有效的正式版本，不集中补传已被替代的旧修订。上传许可与下载许可分别管理；界面不区分由学生还是监护人在操作。

**如何找到指定学生：**接收端 Windows 在“云端文档”出示短时二维码及可手输的短配对码，代表这台主机的一次性授权请求，而不是学生身份。已有云端学生权限的 Android 单机版扫码并选中准确学生后确认；来源 Windows 或云端管理页可输入短配对码并选择学生确认。一次操作可明确勾选多个学生。接收端自动显示获许可学生的名称、来源及许可状态供核对；不公开列出所有学生，不按姓名搜索他人档案，也不凭可猜测的学生 ID 授权。配对码过期或用过则重新出示，但后续每次下载不再配对。配对须核验短时挑战与设备持有凭据，并限制短码猜测次数，不能只信可伪造的设备码；若配对双方不在同一设备上，短码可由用户转告，无需 Windows 摄像头。

**许可持续多久：**确认成功后，同一台 Windows 对同一云端学生的一次下载许可覆盖其后续报告修订和其他文档，无需逐次操作；打开列表和下载时由软件自动核验许可并领取短时文件凭证。短时凭证到期由软件自动更新，不要求用户再输配对码。只有许可被撤销、许可期限/云服务权益结束，或更换 Windows 主机时才需要重新开通；服务端持续核对设备持有凭据、学生和许可状态。

## 2. 当前代码事实与复用边界

- Android 四类报告在 `GrowthModelService.kt` 中形成 `整体画像/历史变化/每日行动建议/阶段总结.md`，带 YAML `student_id`、`type`、`status` 等字段，正式生成状态是 `active`；`EducationPublicationPolicy.kt` 已有正式状态、正文和归属校验。Android 学生 ID 为 `student-UUID`，报告通过 SAF 学生空间存储。当前发布循环依次写入四份文件，必须在整组写入完成并核对快照后才触发上传；单份写入不等于整组成功。
- Windows 主机 `electron/main.cjs` 使用对应四类报告和学生目录 `学情报告/`，正式状态兼容 `published/current/updated/active`。`listLearningReports()` 还会执行恢复、模板补建及草稿恢复；云同步应新增纯读取快照接口，不以此函数作为上传扫描器。现有 Windows 模板及部分旧报告不保证含 `student_id`；须依据受信本地学生记录和目录绑定判定归属，再在上传信封补足云端归属，不改写旧报告原件；归属不唯一时拒传。
- Windows 现有学生 ID 可以由姓名与时间生成；不能用姓名、目录名或本地 ID 猜测两端是同一学生。云端新增不可猜测的 `cloudStudentId`。上传设备保存经确认的 `cloudStudentId ↔ localStudentId` 绑定；接收 Windows 凭设备持有证明、`cloudStudentId` 和 `cloud_document.read` 许可访问该学生来自任一其他设备的云端文档，**不需要本机 localStudentId 或本地学生席位**。只有用户另行选择把云端学生关联到已有 Windows 本地档案时，才检查同名异 ID、重复绑定和许可证席位；旧本地 ID 不改写。若同一 Windows 还要上传本地该学生报告，须另有该本地学生的 `report.write` 许可；可以在同一次配对中合并明确确认，不用另走一套找学生流程。
- 现有 License v3 是 `WINDOWS_HOST` / `ANDROID_STANDALONE` 的产品激活和设备绑定，不包含云端学生范围。新增云端文档下载许可，不把产品激活码或设备码直接当作云端下载凭据。用户只进行一次“为本机开通此学生云端文档下载”的软件许可操作；服务端记录许可编号、设备公钥/持有证明、云端学生 ID、`cloud_document.read` 范围、有效期和撤销状态。设备私钥或等价密钥安全保存在本机，服务端在列表和下载时验证持有证明；授权发布方确认许可，Windows 不能自行勾选取得权限；许可有效期内无需逐份文档确认，换机重新许可。
- Android 已使用 WorkManager 做持久任务与网络约束，Windows 已有本地任务/状态机制；复用调度原则，建立专用云同步队列和凭据。现有局域网协作、Agent 授权或产品 License 均不自动成为云报告权限。
- 2026-09-24 家庭版计划中的“Android 上传、Windows 经授权只读下载”可复用隐私和只读缓存原则；本方案增加 Windows 上传及云端文档管理，协议需重新冻结。家庭版视觉/自动报告开发仍按用户要求暂停，不作为本方案依赖。

## 3. 系统与数据合同

```text
Android 单机版 ──上传正式报告修订──┐
                                    ├─ HTTPS API ─ 私有报告/文档对象存储
Windows 主机端 ──本机学生报告更新后自动上传──┘   │
       └──────── 按主机-学生许可拉取 ────── 许可、元数据与审计数据库
云端管理页 ────── 管理身份与权限检查 ────────────┘
```

首版可用单个 API 服务、关系库、私有对象存储和轻量网页。服务端负责云端学生及设备绑定、主机-学生文档许可、报告索引、文档目录、权限、幂等、审计和备份。小体积 Markdown 报告走单次 HTTPS 报告提交，服务端校验大小、SHA-256、归属、状态后写入私有对象存储并原子提交索引，避免每次报告都走多步预签名流程；较大的手动文档才使用短时、单对象上传凭证及 `reserved → uploaded → committed` 流程，超时孤儿对象可回收。下载仍由服务端鉴权后发短时单对象凭证。跨学生查询始终按管理身份、云端学生和设备许可过滤；来源端首次开通云服务完成一次身份/设备绑定，接收 Windows 配对后凭设备许可使用，不额外要求每次登录云端网页。

建议冻结 `edu-manager.cloud-report.v1`：`tenantId, cloudStudentId, originDeviceId, originPlatform, localStudentId, reportType, reportPeriod, sourceStatus, publishedAt, sourceUpdatedAt, receivedAt, sourceSha256, contentSha256, revisionId, filename, contentType, byteSize, displaySourceRefs, syncState`。正文作为不可变 Markdown 对象；`sourceSha256` 标识本地正式原件，`contentSha256` 标识去敏后实际上传的内容，`revisionId` 由云端身份、来源设备、类型和上传内容 SHA-256 派生/校验，相同内容重送返回原回执。`publishedAt` 与 `receivedAt` 分开，不能用上传时间冒充报告时间。正文包含的本机绝对路径、设备码、密钥或不宜外传的引用需在客户端预检并形成最小对外版本；原始来源路径和原件不上传。

云端每个学生/报告类型展示“各来源最新”和完整修订历史，不因 Windows 与 Android 同时上传而互相覆盖。修订仅追加；客户端只上传**本机正式报告**，从云端下载的缓存不得再次上传，防止回环。Windows 拉取时过滤当前设备自己上传的修订，同一云端学生的 Android 和其他 Windows 来源报告按同一下载许可展示。上传许可持续有效时，以完整发布事件触发后台入队，按内容 SHA-256 去重、合并短时间内连续更新；每学生保留同步游标/清单，恢复时只核对四类目标文件，不反复全目录扫描。网络失败有界退避重试，不阻塞生成、启动或界面主线程，不调用模型/Agent。关闭上传立即阻止本机新任务和未送达任务，撤销云端 `report.write` 后服务端也拒绝后续写入；离线关闭时本机先停，联网上报撤销，短时凭据到期前的边界在验收中核对。重新开启时对当前正式快照做差异补传，已被替代的旧版本不突发上传。撤回/删除产生带审计的墓碑；离线设备恢复后不能把已删除的旧修订重新发布。手动上传的其他文档用独立 `documentId/category` 合同，不伪装成正式学情报告。

服务接口首版需要：来源端/云端管理身份与设备注册、创建/绑定云端学生、接收 Windows 创建短时配对挑战、来源端确认学生并签发/撤销主机-学生 `cloud_document.read` 许可、授予/撤销来源设备的 `report.write`、直接提交小报告、按许可学生增量列出报告和文档/领取下载凭证、较大手动文档预签名上传/列出/下载/更新展示名/移入回收站/恢复、同步状态与审计查询。权限判断必须在每次列表、详情和短时下载凭证签发时执行；仅知道学生 ID、文件名、链接或已有产品 License v3 不能读取云端文档。

## 4. 端侧改动

### Android 单机版

增加一次云端身份/设备绑定与按学生一次性许可开启自动上传。四类报告在本机整组发布完成后生成稳定快照，校验全部成功后按内容哈希后台入队；部分写入失败不上传半成品，报告生成不等待网络。首次开启自动核对该学生当前有效的正式报告并告知会补传，无逐份选择。恢复时仅核对四类目标 Markdown；复用 `EducationPublicationPolicy` 校验，并对新报告要求 `student_id` 精确匹配、类型白名单、SHA-256 和敏感路径检查；旧报告只有能通过可信学生空间归属和正文/状态校验时才上传，归属不清的提示修复，不默默上传。使用独立 WorkManager 队列处理断网、重启、有界退避与幂等回执；关闭上传后取消未送达任务并停止后续入队，保留本机报告和现有 SAF 权限。

### Windows 主机端

对已有本机学生提供“一次许可并开启本机正式报告自动上传”选项。开启后每次正式报告发布/更新自动入队，关闭后停止新入队和待上传任务；既有云端缓存、草稿和占位模板不可上传。另设“云端文档”入口，支持为**当前 Windows 主机与指定云端学生**办理一次下载许可；该学生可由 Android 单机版或另一台 Windows 主机上传报告，本机无需有对应学生档案。许可包含签发、兑换、有效期、撤销与设备换绑状态，不按上传来源或逐份文档重复办理。一次有效许可覆盖该云端学生许可范围内后续报告修订和手动文档，撤销即停止新的拉取。

新增纯读取的报告快照与上传队列，覆盖实际正式发布路径；读取本地正式目录并校验归属、状态、正文与哈希，不能调用带恢复副作用的 `listLearningReports()` 执行后台扫描。旧报告不要求修改原件来补 `student_id`，而依据受信学生记录与目录绑定生成上传信封，归属有歧义则阻止上传并提示。发布事件入队，重启/重连时只核对四类目标文件的哈希；网络与文件读取异步执行，不拖慢报告页面或主线程。下载端按设备持有证明、`cloudStudentId` 与 `cloud_document.read` 读取许可学生由 Android 或其他 Windows 主机上传的增量文档，跳过本机已上传内容；下载报告存入当前用户下按 `cloudStudentId/reportType/revisionId` 分层的只读缓存，核对长度与 SHA-256 后原子落盘。独立的云端文档入口可浏览无本地档案的学生；若用户显式关联本地学生，界面再并列展示“本机报告 / 其他设备云端报告”。均标明来源、生成时间、同步时间、版本和许可状态。本机正式报告目录及成长模型不可被云端内容覆盖；从云端读取的报告不参加本机生成或证据计算。撤销后本地既有副本的保留/清除应在界面明确说明，并提供清除缓存操作。

### 云端文档管理

网页以“学生 → 学情报告 / 其他文档”组织。报告可按名称、类型、日期筛选，查看来源与修订并下载；其他文档由有权限用户手动上传、下载、修改展示名和移入回收站/恢复。Markdown/PDF 可安全简单预览，DOCX 首版只下载；不做标签、备注、复杂格式转换或在线编辑。文件名仅作展示，服务端生成对象键；不得将路径或文件名直接用于存储定位。报告删除、文档删除和账户删除分开处理，保留期及备份清除规则在上线前明确。

## 5. 分阶段开发与验收

| 阶段 | 工作 | 必须通过的验收 |
| --- | --- | --- |
| P0 合同与样本（约 1 周） | 冻结云端学生身份、主机-学生文档下载许可、来源设备上传许可、报告 `v1`、撤销、历史修订、删除和文档范围；准备去标识双端新旧报告样本；以 Windows `0.18.1`、Android `1.2.5` 在同设备同数据下测性能基线 | 同名异 ID、同 ID 异人、草稿/占位、缺 `student_id` 的旧正式报告、双端同类型修订、主机换机与撤销规则有明确预期；确认接收 Windows 出码、来源端选学生流程；产品 License v3 不能单独下载云端文档；确定云服务部署账户、域名和数据保存区域；据基线冻结性能阈值 |
| P1 云端最小服务（约 1–2 周） | 私有存储、元数据库、设备持有证明与配对挑战、直接报告 API、较大文档上传接口、增量索引、幂等和审计；先用合成报告端到端跑通 | 未授权/跨学生/跨账户读写拒绝，伪造设备码不能授权；重复提交只得一修订；旧修订不覆盖新修订；备份恢复后对象与索引一致；普通报告一次请求提交 |

## 6. 发布边界与待定决策

2026-09-26 更新：以下 0.18.1/1.2.5 和试点缺口描述为实施前历史，最新候选源码为 Windows 主机 0.18.2、Android 单机 1.2.6（30）。1–5 项补齐已覆盖来源签名与单管理员凭据轮换、报告撤回及恢复后许可失效、文档分页与流式上传/PDF 预览、可选备份保留及独立审计校验、性能基准及独立候选打包。完成证据与当前门槛见 `云同步候选交付-2026-09-26.md`。多管理员、异地存储/磁盘加密配置、可信 HTTPS 与真实跨设备验收不作为已完成事项；不改线上下载清单，不声称已经正式发布。

当前 Windows `0.18.1` 是本地候选，Android `1.2.5` 已有正式 APK 但真机覆盖与打印等另有待验；线上清单的 Windows 主机/Android 单机版本分别仍是 `0.17.11/1.2.2`。新功能必须增加版本号和独立候选包，不覆盖既有产物。`edu-launcher-app` 工作树有未跟踪资料，家庭版分支另有 P1/P2 工作；实施前固定各自提交/差异与构建输入，在隔离工作树开发，合并时逐项复核。

需要在 P0 确定的产品选择：① 哪些已绑定来源端/云端管理身份可确认学生授权、配对码有效期与多学生一次确认的上限；② 主机-学生下载许可期限、云服务权益结束后的行为及换机流程（逐份下载无需重复许可已确定）；③ “其他文档”允许的格式、单文件/总容量与保留期；④ 撤销下载许可后 Windows 已缓存报告由用户清除还是按产品策略自动清除；⑤ 同设备同数据的性能回退阈值，以及报告去敏后是否影响展示。首次开启默认补传当前有效正式报告、后续更新自动上传已作为简化方案冻结，不再让用户逐份选择。产品界面统一为软件许可操作，不按学生或监护人区分操作流程。缺少这些决策时可完成合同和合成样本开发，不能宣称真实数据试点可用。

公开发布前需证明：Android/Windows 来源学生与准确云端学生绑定；接收 Windows 出码、来源端选择学生并一次确认后，可在没有本地学生档案时下载该学生来自 Android 和其他 Windows 主机的报告及许可文档；两端一次上传许可后当前正式报告及后续更新自动上传、关闭后停止，上传设备不下载自己上传的内容；Android 四份报告完整发布后才入队，Windows 旧报告归属可信且不改写原件；双端来源与历史修订保留；撤销和换机；弱网/断网/重启幂等；多学生隔离；云端文档管理；数据库与对象备份恢复；同设备同数据性能对照；实际 APK/EXE 签名、真机及线上清单一致。云端报告是共享副本，不是本机原始资料或完整教育档案备份。

## 7. 2026-09-25 本地实现核对

- Android 四份报告发布前写私有待提交标记，四份 SAF 文件全部写入并回读一致后，原子写入仅含哈希的整组清单。后台在读取整组正文并比对清单后才上传；缺份、损坏或写入一半会停止上传。旧版四份正式报告仅在没有未完成发布标记时建立一次初始清单。云快照写入失败会暂停云上传并留下错误，不阻断本机报告生成。JVM 测试和 Android 构建通过，尚需真机验证 SAF 提供者行为与崩溃恢复。
- Windows主机下载许可新增 P-256 设备私钥逐请求签名、时间戳和一次性随机数；服务端拒绝只有令牌、伪造签名和重放。8 位配对确认有限速；下载许可试点期限暂定一年，服务端在列表与下载时执行到期和撤销校验，续期需同一主机重新配对。该期限仍属待确认产品选择，不能因试点默认值推断正式权益。旧无私钥配对须重新办理。来源端上传目前仍使用经本机加密保存的设备令牌，云端正式管理员身份、审计与备份仍未完成。
- 当前试点仅 `127.0.0.1:8755`，并未建立局域网 HTTPS。Android 目标 API 34，正式包默认只信任系统 CA；需确定受信任的域名/证书或仅用于调试包的测试 CA 配置。未完成证书、设备连接和双 Windows 真实验证前，不上传真实学生报告，不宣称 P2–P4 真机验收完成。
