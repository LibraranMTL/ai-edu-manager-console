## 已在 Windows 0.7.11 收口的档案架构任务

  - 支持导入候选资料、复制 AI 初筛指令、导入 AI JSON 初筛结果、生成治理建议、选择治理候选、晋升正式资产和归档/丢弃。

  - 支持资产筛选、重复文件分组、资产引用详情、治理建议报告、历史文件补建索引和项目资产引用。

## 多语言完整覆盖

  - 初始化教育管家与新建教育智能体中的步骤说明。

- 初始化指令文件需要支持按界面语言生成对应版本：

## 定时任务模块细分

> 进展：Windows 0.7.9 已完成界面分区，将任务拆成“定时消化”和“定时维护 / lint”，并提供维护指令复制和路径核对入口。后续重点是更细的调度状态、去重账本和自动维护报告。

- 将现有“定时任务”能力拆分为两类任务：
  - 定时消化：定期触发资料消化，读取学生原始资料库中的新增资料，并写入学情分析汇总、index.md、log.md。
  - 定时维护 / lint：定期检查知识库结构、索引、日志、重复摘要、断链、命名规范、规则文件一致性和 Agent 记忆/人设同步状态。
- 后续界面建议：
  - 在“定时任务”模块中增加任务类型筛选或分区。
  - 初始化向导中创建的默认任务归入“定时消化”。
  - 知识库健康检查、规则文件检查、档案索引检查归入“定时维护 / lint”。
- 后续实现注意：
  - 定时消化应避免重复处理已消化资料。
  - 定时维护 / lint 默认不修改用户原始资料，只生成检查报告或待处理建议。
  - 支持 QClaw / OpenClaw 等具备定时任务能力的工具，也支持控制台侧提醒或手动复制指令模式。

## 知识库可迁移与路径抽象层

> 进展：Windows 0.7.8 已实现 `.ai-manager/metadata.json`、`.ai-manager/pathmap.json`、路径健康检查和迁移日志；Windows 0.7.9 已实现旧路径备份修复、当前主机工作规则复制和逻辑路径版 AGENT 草稿；Windows 0.7.10 起，新生成的长期 AGENT/规则/Soul 模板默认使用逻辑路径，避免跨主机同步后继续写死旧电脑绝对路径。

- 新增知识库工作空间身份与路径抽象能力，解决跨主机同步后 `AGENT.md` 中绝对路径失效的问题。
- 标准新建知识库和接管已有知识库时，自动维护隐藏配置目录：
  - `.ai-manager/metadata.json`
  - `.ai-manager/pathmap.json`
  - `.ai-manager/health-report.md`
  - `.ai-manager/migration-log.md`
- 支持逻辑路径占位符：
  - `@KB_ROOT`
  - `@AGENT_FILE`
  - `@RAW_DIR`
  - `@SUMMARY_DIR`
  - `@OUTPUT_DIR`
  - `@GROWTH_DIR`
  - `@PROJECT_ROOT`
  - `@ASSET_ROOT`
- 接管已有知识库时增加路径健康检查：
  - 扫描 `AGENT.md`、规则文件、Soul / Memory 模板中的 Windows 绝对路径。
  - 检测旧路径在当前主机是否存在。
  - 对照当前知识库根目录生成路径映射。
  - 生成路径健康检查报告。
  - 默认不自动覆盖已有 `AGENT.md`。
- 增加安全修复操作：
  - 复制当前主机工作规则。
  - 生成逻辑路径版 `AGENT.md` 草稿。
  - 备份后修复 `AGENT.md` 中的旧路径。
- 指令生成采用双轨策略：
  - 给当前主机 Agent 立即执行的初始化、消化、咨询指令，可以使用当前主机绝对路径。
  - 长期写入知识库的规则文件，优先使用逻辑路径占位符和 `.ai-manager/pathmap.json`。
- 后续实现注意：
  - 不把“自动替换路径”作为唯一方案，优先建立 Path Resolver。
  - 不破坏接管知识库的原始目录和规则文件。
  - 学生记录中的 `rootPath`、`rawPath`、`summaryPath`、`agentPath` 仍作为当前主机真实路径。
  - 文件资产中心中的资产 ID 和引用关系应逐步与工作空间 ID 绑定，而不是仅绑定物理路径。

- 在 Windows 端内置 MarkdownView 中增加 Mermaid 代码块识别与渲染。

- Mermaid 渲染失败时必须回退显示源码，避免渲染异常导致页面白屏。

## 已完成开发、待真机验收：使用模式与共享终端数据隔离

> 详细计划：[Windows 0.9.9 使用模式与共享终端开发计划](Windows-0.9.9-使用模式与共享终端开发计划.md)

当前状态：Windows 主机版、Windows 学生终端和 Android 学生终端已经完成代码、自动化测试、操作手册和程序包更新；发布前仍需进行真实课堂多人轮换验收。

- 将首页“使用模式”迁入系统设置，合并重复的主机服务、配对、诊断和连接信息入口。
- Windows 主机版只提供主机模式、主机-终端模式；Windows 主机版与 Windows 学生终端继续使用独立程序包。
- Android / Windows 学生终端提供个人终端、共享终端两种模式。
- 个人终端首次扫码或输入学生 ID 后固定绑定；共享终端每次扫码或输入 ID 建立当前学生会话。
- 不增加 PIN、密码、角色或细粒度权限；学生 ID 只负责识别资料归属。
- 主机按学生会话限制上传、项目、档案和报告，不能只依赖终端传入的学生 ID。
- 截图、屏幕采集、失败重试、缓存和待上传资料必须固定原学生归属；共享终端禁用自动投递文件夹。
- 旧学生内部 ID、目录和知识库保持不变，只补充稳定登录 ID 和二维码。
