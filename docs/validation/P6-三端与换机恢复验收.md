# P6 三端与换机恢复验收

## 自动门禁

1. Windows 主机：资料导入、知识处理、成长模型、报告与档案读取、知识协作队列。
2. Windows 学生终端：当前学生登录、资料上传、成长模型、学情报告、教育档案和关联项目知识只读访问。
3. Android 学生终端：当前学生登录、资料上传、屏幕采集、成长模型、学情报告、教育档案和关联项目知识只读访问。
4. 数据隔离：学生终端只返回当前登录学生及其有效关联项目，不回退到其他学生。
5. 恢复：日常备份包含完整学生记录；完整迁移包携带受管资料、应用状态和用户选择的外部目录，换机恢复后路径重映射并重建协作索引。
6. 安全：迁移包逐文件 SHA-256、空目录保护、暂存恢复和状态回滚；不迁移 License、API Token、固定主机身份、终端令牌、协作密钥或平台私钥。迁移包不再要求密码，但应由用户妥善保管并通过可信 U 盘或本机目录传递。

## 候选包真机门禁

| 场景 | 操作 | 通过标准 |
| --- | --- | --- |
| Windows 主机 | 新增一份资料并完成自动处理 | 首页依次出现处理中、知识更新；无需人工审核低风险结果 |
| Windows 学生终端 | 以学生 ID 登录后上传文件并查看成长模型 | 文件进入本人目标库；只显示本人及关联项目 |
| Android 学生终端 | 以同一学生登录，采集并上传图片 | 按钮有明确反馈；主机收到资料；报告和成长模型可读取 |
| 局域网与 Tailscale | 分别关闭一种通道完成一次上传 | 可用通道自动接替，普通用户不填写技术地址 |
| 换机恢复 | 在旧主机创建迁移包，在不同 Windows 用户名或盘符的新主机恢复并重新连接终端 | 受管文件数量、容量、SHA-256、学生与项目 ID 一致；外部目录按选择复制或明确待重新绑定；不重复导入历史包 |
| 损坏与冲突 | 分别使用篡改载荷、非空目标目录、空间不足和较旧主机版本恢复 | 均在正式切换前停止；新电脑原有资料、License、API Token 和主机身份不被覆盖 |
| 学生路径重绑 | 选择一个含真实正文的旧学生知识库，再选择空目录和错误学生目录 | 正确目录先显示文件清单并人工确认后绑定；空目录和错误目录在写入前被拒绝；用户正文不被全局替换 |
| 项目双路径重绑 | 分别更换工作空间和绑定知识空间 | 两个操作互不改写另一目录；项目 ID、知识空间 ID、来源关系和历史日志保持 |
| 学生档案协作同步 | 两端建立唯一学生 ID 映射后同步，再制造一对多映射 | 唯一映射仅同步已治理成果；原始资料和草稿不进入包；一对多映射停止同步且无跨学生写入 |
| 中断恢复 | 导出或暂存恢复期间中断工作线程 | 主线程保持响应；失败目录和诊断位置可见；未验证数据不会切换为正式资料根目录 |
| 异常恢复 | 传输中断后重启两端 | 自动续传或给出一次可执行的重试，不丢失、不重复 |

以上任一场景出现跨学生数据、空项目覆盖已有项目、重复资料膨胀或不可恢复阻塞，均阻止稳定版发布。
