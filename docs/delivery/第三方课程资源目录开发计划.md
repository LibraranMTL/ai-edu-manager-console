# 第三方课程资源目录开发计划

> 建立日期：2026-07-29  
> 计划代号：C0—C2  
> 产品定位：在教育管家中提供经过筛选的第三方课程入口，并把用户主动采集的课程资料纳入现有“原始资料—知识资产—分析结果”闭环；本计划不建设完整 LMS，不把第三方网页浏览等同于课程进度或学习效果。

## 一、开发目标

1. Windows 主机端、Windows 学生端和 Android 学生端提供统一的“精选课程”入口。
2. 课程名称、图片、简介、提供方、链接和适用范围来自统一的版本化课程目录，不分别写死在三个客户端。
3. 用户点击课程后在教育管家内安全打开第三方网页，不暴露本机文件、令牌或教育档案接口。
4. 课程网页与现有屏幕资料采集能力联动，但必须由用户主动开始系统录屏授权。
5. 采集资料绑定当前学生、课程、提供方和页面来源，可选择进入学生原始资料库或有效关联项目原始资料库。
6. 客户主机只负责接收、校验、缓存、启用、隐藏、排序和分配课程，不成为平台全局课程编辑后台。
7. 正常使用不增加技术配置、逐次审核或常驻高频轮询。

## 二、明确不做

- 不建设排课、考勤、作业批改、考试、收费和教师直播等完整 LMS 功能。
- 不声称仅凭网页打开、截图或录屏即可获得课程完成率、正确率或实时学情。
- 不后台录制全部课程活动，不绕过 Android/Windows 系统录屏授权。
- 不允许第三方网页直接调用教育管家本地文件、知识库、设备令牌或 Agent 接口。
- 不在客户主机端提供平台全局课程新增、修改、发布或签名私钥。
- 不在 C0—C2 建设完整多租户 RBAC、平台云端运营后台或复杂普通用户权限配置。

## 三、首批课程与素材

### 1. 美国英文小学数学

- 提供方：Starfall
- URL：`https://www.starfall.com/h/`
- 初始封面：`课程/mathg1.png`
- 目录文案必须标明第三方提供方、适用年龄/年级、语言、账号或会员要求和非隶属关系。

### 2. 少儿计算机编程与人工智能英文课程

- 提供方：Code.org
- URL：`https://code.org/en-US`
- 初始封面：`课程/code.png`
- 目录文案必须区分第三方免费课程与教育管家提供的设备、资料治理、知识整理或伴学服务。

首批课程上线前必须复核图片使用权、第三方商标及课程描述。缺少正式接口或合作证据时，不使用“实时同步纠错”“直通名校/国际大赛”“保证提分”等表述。

## 四、课程目录模型

### 1. 目录包

```json
{
  "schemaVersion": 1,
  "catalogVersion": "2026.07.29.1",
  "issuedAt": "2026-07-29T12:00:00+08:00",
  "minHostVersion": "0.14.0",
  "checksum": "...",
  "signature": "...",
  "courses": []
}
```

### 2. CourseCatalogItem 最小字段

```json
{
  "courseId": "platform:starfall-k5-math",
  "type": "platform_standard",
  "name": "美国英文小学数学",
  "provider": "Starfall",
  "url": "https://www.starfall.com/h/",
  "allowedHosts": ["www.starfall.com"],
  "coverAsset": "catalog-assets/starfall-k5-math.png",
  "summary": "...",
  "subjects": ["mathematics", "english"],
  "gradeRange": ["K", "1", "2", "3", "4", "5"],
  "languages": ["en"],
  "accountRequirement": "provider_defined",
  "effectiveAt": "...",
  "expiresAt": null,
  "legalNotice": "...",
  "status": "active"
}
```

客户自有课程使用 `tenant_custom`，必须拥有独立 `courseId`、来源责任和允许域名，不能覆盖平台标准课程的 URL、提供方、法律声明或签名内容。

## 五、三层目录

```text
平台标准目录
→ 客户机构策略
→ 当前学生有效目录
```

### 平台标准目录

- 由产品方内部课程发布工具维护；
- 包含平台课程元数据、域名、版本、校验值和签名；
- 支持发布、撤回、回滚和紧急下架；
- 签名私钥不进入客户安装包。

### 客户机构策略

C0—C2 只提供轻量设置：

- 启用或隐藏课程；
- 调整显示顺序；
- 设置适用年级或学生；
- 选择是否显示机构自有课程。

不要求普通家庭用户理解租户、RBAC、签名、JSON或安全域名。

### 学生有效目录

- 仅返回当前登录学生可见课程；
- Windows/Android 学生端只读；
- 不显示其他学生的分配信息；
- 主机端在返回目录时再次计算有效范围，不能只依赖客户端隐藏。

## 六、内嵌网页与采集

### Windows

- 使用隔离的 Electron `WebContentsView`，不使用普通 `iframe`；
- 独立 session，`nodeIntegration=false`、`contextIsolation=true`、`sandbox=true`；
- 仅允许 HTTPS 和课程项目声明的域名；
- 限制重定向、新窗口、下载、外部协议和权限申请；
- 第三方网页与主程序 IPC、文件系统及令牌完全隔离。

### Android

- 使用独立课程 WebView，不复用教育档案 Markdown WebView；
- 启用 Safe Browsing；
- 不提供原生 JavaScript Bridge；
- 限制域名、弹窗、下载、摄像头和麦克风权限；
- 退出课程后清理不必要的会话状态。

### 屏幕资料采集状态

```text
隐藏
→ 待开始
→ 请求系统授权
→ 采集中
→ 已暂停
→ 完成
→ 确认入库或丢弃
```

进入课程页面时只显示“待开始”的浮动采集入口，不自动启动录屏。采集记录至少绑定：

- `studentId`
- `courseId`
- `provider`
- 当前 URL
- 采集开始和完成时间
- 学生原始资料库或有效关联项目原始资料库目标

## 七、分阶段开发

## C0：目录合同、素材与边界

任务：

- [x] 冻结 `CourseCatalogPackage`、`CourseCatalogItem` 和机构策略 Schema；
- [x] 建立首批两门课程的合规文案和原创/授权素材清单；
- [x] 建立域名白名单、URL 规范化、目录版本和校验机制；
- [x] 提供产品方内部只读 JSON 生成及校验脚本；
- [x] 建立本地最后可用版本、失败回滚和离线签名目录包导入结构；
- [x] 明确第三方课程、教育管家服务和真人伴学服务之间的商务边界。

验收：

1. 同一目录包在三端解析结果一致；
2. 校验失败、签名失败、版本过低和未知域名均不会替换最后可用目录；
3. 课程文案不包含未经证实的效果承诺；
4. 普通用户不接触 JSON、签名或域名配置。

## C1：三端精选课程与安全内嵌浏览

任务：

- [x] Windows 主机端增加“精选课程”一级入口；
- [x] Windows 学生端和 Android 学生端增加当前学生有效课程入口；
- [x] 完成课程卡片、详情、提供方、账号要求和法律声明展示；
- [x] Windows 完成隔离 `WebContentsView`；
- [x] Android 完成独立安全 WebView；
- [x] 课程打开、返回、断网、登录、重定向和外部链接使用一致反馈；
- [x] 学生端目录继续服从当前学生登录范围。

验收：

1. 三端课程名称、图片、简介和有效状态一致；
2. 第三方页面不能访问教育管家文件、令牌或 IPC；
3. 非白名单跳转、新窗口和危险协议被阻止或交给受控外部打开流程；
4. 课程站点异常不会卡住教育管家主程序；
5. 进入课程的普通路径不超过一次点击。

## C2：采集闭环、机构策略与发布

任务：

- [x] 课程页面接入“待开始”的屏幕资料采集浮动入口；
- [x] Windows/Android 录屏均由用户主动选择目标并完成系统授权后才进入采集中；
- [x] 采集资料携带课程来源，投递到当前学生或有效关联项目原始资料库；
- [x] 主机端提供启用、隐藏、排序和学生分配的轻量机构策略；
- [x] 主机向学生端下发合并后的有效目录；
- [x] 专业版和机构版可通过四字段 Excel 导入机构自选课程，家庭版和试用版不能导入或下发；
- [x] 修复 Android 手机竖屏/自适应课程卡片沿用平板权重参数导致的图片下方异常留白；
- [x] 支持目录更新失败回滚、离线目录包和紧急下架；
- [x] 更新三端手册、网站源文件、CHANGELOG 和构建审计。

验收：

1. 未点击开始时录屏文件新增数量为 `0`；
2. 采集资料学生、课程、URL和目标资料库归属正确率 `100%`；
3. 同一采集文件重复提交不产生重复资料记录；
4. 学生端看不到未分配课程和其他学生策略；
5. 目录更新失败继续使用最后可用版本；
6. 打开课程或采集资料不被表述为课程完成率或学情结论。

## C3：延期的课程运营管理中心

课程数量、客户机构和运营人员规模显著扩大后再单独立项：

- 平台超级管理员；
- 内容编辑和审核角色；
- 多客户机构管理；
- 灰度发布和版本差异；
- 版权与授权到期提醒；
- 客户自有课程审核；
- 课程使用量、打开率和故障分析。

C3 不属于 C0—C2 发布阻塞项。

## 八、测试与性能

自动测试覆盖：

- 目录 Schema、版本、校验、签名和回滚；
- 平台目录、机构策略和学生有效目录合并；
- 未分配学生和跨学生访问；
- URL 规范化、白名单、重定向和危险协议；
- Windows/Android 页面生命周期；
- 录屏授权、暂停、恢复、完成和丢弃；
- 学生/项目目标归属、幂等和来源记录；
- 目录离线缓存和紧急下架。

性能要求：

- 空闲状态不轮询第三方课程网页；
- 目录更新采用低频拉取或随版本/用户操作触发；
- 图片缓存有大小和失效限制；
- WebContentsView/WebView 不阻塞主 UI；
- 退出课程后释放页面资源；
- 目录更新失败不影响资料、知识、报告等既有主流程。

## 九、完成定义

C0—C2 完成后：

1. 三端具有统一、安全、当前学生范围内的精选课程入口；
2. 课程目录可版本化、校验、回滚和离线更新；
3. 客户主机能做轻量启用、排序和分配；专业版和机构版可导入独立的机构自选课程，但不能编辑平台全局签名目录；
4. 用户可主动把课程页面采集为带来源的学生或项目资料；
5. 第三方网页不能越权访问教育管家本地能力；
6. 普通用户不需要理解课程目录协议、签名或底层浏览器安全配置；
7. 产品宣传能够区分第三方课程内容、教育管家技术服务和人工伴学服务；
8. 三端自动测试、人工界面评估和真机验收全部通过后才进入正式发布。
