# Agent 外部能力实现与验收记录

对应计划：[Agent 外部能力统一契约与安全基线开发计划](Agent外部能力统一契约与安全基线开发计划-2026-09-19.md)。本记录不把本地代码测试当成真实 Agent、真实设备、签名包或正式发布验收。

## 当前落地范围

Agent grant 允许的方法/路径闭集：`POST /api/agent/knowledge/query`、`POST /api/agent/conversation/submit`（只返回 `PREVIEW_REQUIRED`）、七个 `POST /api/agent/memory/*` 既有会话接口、`GET /api/agent/capabilities`、`GET /api/agent/openapi`、`POST /api/agent/invoke`、`POST /api/agent/write/preview|status|execute`。除此之外均由主机路由入口拒绝。管理员专用的 `/api/agent/grants/manage`、`/api/agent/write/pending|review|approve` 不在 Agent grant 闭集中。

- 主机 HTTP 入口对 `eak_` Agent 令牌实行方法+路径闭集。除登记的 `/api/agent/*` 路由外，所有普通 REST 路由一律拒绝；包括学生/项目资料上传、项目资产、学生档案文件、portable migration 创建/状态/下载、设备配对、协作直传。令牌撤销后返回 401。Agent 令牌只接受 loopback 调用，主机跨设备场景不承诺直接开放 Agent 令牌。
- Agent 调用按 grantId 每分钟 90 次限速；拒绝、能力调用、授权和撤销写入主机时间线，记录 grantId、路由及错误码，不记录令牌或请求正文。撤销持久阻止重启后自动补发；旧授权不会静默增加新能力。
- 版本化目录 `edu-manager.agent-capabilities.v1`；`GET /api/agent/capabilities` 返回当前授权可用的能力及输入 JSON Schema，`GET /api/agent/openapi` 返回 OpenAPI 3.1，`POST /api/agent/invoke` 是统一执行入口。错误码包括 `AGENT_ROUTE_DENIED`、`CAPABILITY_DENIED`、`STUDENT_SCOPE_DENIED`、`PROJECT_SCOPE_DENIED`、`INVALID_INPUT`、`RATE_LIMITED`。
- 统一入口目前提供 `knowledge.query`、`archive.list`、`task.status`、`student.overview`、`project.overview`、`report.list`、`report.read`。每次明确学生 ID，项目能力还需明确项目 ID 并同时通过学生绑定和 grant 项目绑定。多学生共享项目暂不向单学生 Agent grant 开放项目级内容，避免内容层无法分离时泄露另一学生资料。
- 目录只给文件名、相对路径和修改时间，不给主机绝对路径；任务只给紧凑状态字段；报告读取上限 64 KiB；列表最多 50 项并带游标。结果有 `edu://` 来源、学生/项目归属和时间。目录、任务等即时主机读取回执标记 `freshness: live`；`knowledge.query` 回执继承知识查询的 `local`、`live` 或 `offline_snapshot`，30 秒查询缓存命中则标记 `cached`（离线快照仍标记 `offline_snapshot`，内层保留 `cachedQuery`）。已完成但无直接依据时返回 HTTP 200 / `outcome: no_evidence`，不能解释为权限拒绝；暂不可用返回 HTTP 503 / `KNOWLEDGE_UNAVAILABLE`，权限拒绝仍为 403。
- MCP 保留既有知识查询/授权会话捕获工具，新增资料目录和任务状态两个精简工具，调用同一主机 `/api/agent/invoke`；CLI `electron/agent-capability-cli.cjs` 也调用该入口，输出 JSON，成功/参数或描述符错误/权限错误/主机错误分别为 0/2/3/4 退出码。
- 受控写事务覆盖 `conversation.submit`、`material.upload`、`task.create` 和 `report.draft`。Agent 只能提交 `POST /api/agent/write/preview`（必填幂等键），获主机批准后再 `POST /api/agent/write/execute`；`/status` 查询自有意图。主机管理员在 loopback 上用 `/api/agent/write/pending`、`/review`、`/approve` 审核，批准请求必须含意图 ID、预览返回的 `inputDigest` 与 `confirmed: true`。结果包含可追溯回执；草稿任务不自动执行，报告只写入独立草稿目录，不发布正式报告。执行中断保留可恢复状态，重复执行校验幂等；过期未完成意图清除原始输入。旧的 Agent 直接对话写入入口对 Agent grant 返回 `PREVIEW_REQUIRED`。
- Windows 主机“Agent 对话采集”页增加当前学生的只读/受控写入授权、撤销、待审核意图查看与批准/拒绝。审批前显示目标、内容预览和摘要；二进制资料只展示文件名/字节数/摘要，不展示或记录 base64 原文。`/api/agent/write/reject` 清除待写入内容。界面授权仍通过主机进程执行，不向渲染进程暴露 Agent token 或管理员 HTTP token。

## 授权与调用

旧 grant 维持旧权限。主机管理员使用原有主机管理员令牌、仅在 loopback 上对 `/api/agent/grants/manage` 提交 `{"studentId":"准确学生ID","action":"authorize-read","confirmed":true}` 才增加只读能力；写入需单独提交 `{"studentId":"准确学生ID","action":"authorize-write","capabilities":["material:upload","task:create","report:draft"],"confirmed":true}` 指定能力，再逐条批准写入意图；`action: "revoke"` 撤销并删除令牌文件。动作不能通过 Agent 令牌执行。撤销后重新授权必须显式提交授权动作。

以 MCP 描述符中的 `capabilityEndpoint` 和 `authentication.tokenFile` 为准，切勿复制令牌到提示词。CLI 示例：

```powershell
node electron/agent-capability-cli.cjs --descriptor "<本机学生描述符完整路径>" --name archive.list --studentId "<准确学生ID>" --limit 20
node electron/agent-capability-cli.cjs --descriptor "<本机学生描述符完整路径>" --name task.status --studentId "<准确学生ID>" --projectId "<准确项目ID>"
node electron/agent-capability-cli.cjs --descriptor "<本机学生描述符完整路径>" --phase catalog
node electron/agent-capability-cli.cjs --descriptor "<本机学生描述符完整路径>" --phase preview --name task.create --studentId "<准确学生ID>" --inputFile "<含 studentId/title/detail 的本机 JSON 文件>" --idempotencyKey "<本次请求稳定键>"
node electron/agent-capability-cli.cjs --descriptor "<本机学生描述符完整路径>" --phase execute --intentId "<已批准意图ID>"
```

API 请求体示例：`{"name":"archive.list","input":{"studentId":"准确学生ID","limit":20}}`。项目查询还传 `projectId`。若得到 403/429，应遵守错误码，不能改用普通 REST 或另一个学生作为回退。
