# 纵向学习分析：主机端代码 + AGENT.md 双层方案

> 日期：2026-09-19  
> 适用基线：Windows 主机版 0.17.9 工作树  
> 状态（2026-09-21 复核）：受管 Agent 规则、结构化资料/时间线回执、主机分析、查询及 UI 已形成候选闭环；普通 Agent 对话结束后自动提取学习事件尚未接通，故不称“双层方案全部完成”。已生成隔离的 Windows 候选包；真实 Agent、授权学生样本、真机运行、签名和发布验收仍未完成。

## 1. 可行性结论

方案可行，且与现有学生隔离、资料消化、证据治理、学习时间线和成长模型兼容。采用双层职责：

- Agent 负责理解学习互动，产出带来源的结构化 `learningEvents` 候选；
- 主机代码负责学生范围复核、知识点 canonical ID、Schema 校验、幂等去重、时间排序、状态计算、错误复发统计、保持置信度和查询；
- 学情报告读取结构化事实和状态，不把报告文字反向当作学习事实；
- UI 提供知识轨迹、证据下钻、错误模式和复测建议；正式报告发布仍沿用既有独立治理链。

不把原“六库”改名或破坏现有目录。学习分析作为学生知识库内 `.edu-manager/learning-analytics/` 的派生层接入，源证据仍受原资料库、知识治理和授权边界控制。

## 2. 本次已实现范围

### 2.1 受管 Agent 规则

内置 `AGENT.md` 模板新增“纵向学习分析 Protocol”：

这里修改的是 `src/main.tsx` 中 `rawBuildAgentMd` 生成的默认模板，章节标题为 `## 6.1 纵向学习分析 Protocol`，并未把原讨论稿的 `## Student Learning Progress Analysis` 英文示例逐字写入既有学生文件。`buildAgentMd` 遇到已选用的自定义模板时优先使用自定义模板；已存在且由用户维护的 `AGENT.md` 不会随程序升级自动改写。尤其不能仅因未复测就写入原示例中的 `forgotten` 状态。

1. 只有明确证据支持具体知识点表现时才输出事件；
2. 评分维度为概念理解、程序熟练度、方法选择、迁移、提示程度，统一 0–4，未知为 `null`；
3. 每条事件带当前学生稳定 ID、真实事件时间、canonical knowledge-point ID 和 `evidenceRefs`；
4. 一次答对、运行通过或提示后完成不等于独立掌握；
5. 长期未复测只降低保持判断的置信度，不自动认定遗忘；
6. Agent 不直接写最终 mastery score 或知识状态账本。

现有已被用户修改或接管的 `AGENT.md` 不会被静默覆盖；系统默认模板及新建受管档案使用新规则。旧档案在“智能体规则管理 → AGENT.md → 预览加入纵向学习协议”中只修改编辑区，用户核对后再保存。保存接口会为原文件留快照；已有未标记的同名章节不会被自动重写。

### 2.2 主机端学习分析模块

新增：

- `electron/learning-analytics.cjs`：事件校验、持久化、状态计算、错误复发、时间序列查询和来源撤销重建；
- `electron/learning-taxonomy-math.v1.json`：数学 MVP canonical taxonomy；
- `bridge:getLearningAnalytics`：按当前学生查询事件、状态和 misconception 的只读接口。

学生目录中的派生文件：

```text
学生知识库/
└─ .edu-manager/
   └─ learning-analytics/
      ├─ learning-events.json
      ├─ knowledge-states.json
      ├─ misconceptions.json
      ├─ rejected-events.json
      └─ history-changes-candidate.md
```

事件只接受当前学生、合法时间、可映射知识点、至少一项实际表现评分及已授权证据引用。0–4 之外的分数不会静默截断；提示程度单独存在不构成学习表现。不同学生、未知资料 ID、缺时间、缺表现和无法映射的知识点被逐条拒绝；局部拒绝不回滚同批合法事件。拒收代码和批次索引记入最近 100 条异常回执，供定位并重新提交；损坏或跨学生的事件账本会阻止追加，避免覆盖旧记录。

### 2.3 接入现有处理链

```text
已授权资料 / Agent 会话 / 学习时间线
  → 现有严格消化批次及逐文件回执
  → Agent 输出 learningEvents 候选
  → 主机复核 studentId + materialId/capture event
  → canonical knowledge-point mapping
  → 幂等写入 Learning Event
  → 确定性重建 Knowledge State / Misconception ledger
  → bridge:getLearningAnalytics 按 occurredAt ASC 查询
```

普通学生资料消化接受 `digest_material:<materialId>` 或兼容的 `source_material:<materialId>` 引用，且该资料必须已通过当前批次确认。学习时间线仅从完成且非纯视觉/待核实的活动段接受当前活动段内的 `capture_event` 或已由现有回执验证的其它证据。删除仍作为唯一来源的采集会话时，相应派生事件和状态随来源撤销重建；正式晋升资料若另有合法 material 引用，不受该会话派生记录删除影响。

## 3. Learning Event 契约

```json
{
  "studentId": "student-stable-id",
  "subject": "Mathematics",
  "knowledgePoint": {
    "id": "MATH.CALC.DIFF.STATIONARY_POINT",
    "label": "Stationary points"
  },
  "occurredAt": "2026-01-14T10:00:00+08:00",
  "taskId": "optional-stable-task-id",
  "taskType": "concept_question",
  "performance": {
    "conceptualUnderstanding": 1,
    "proceduralFluency": 2,
    "methodSelection": 1,
    "transfer": 0,
    "hintLevel": 3
  },
  "errors": [
    {
      "id": "WHY_DERIVATIVE_EQUALS_ZERO",
      "description": "Confuses f(x)=0 with f'(x)=0."
    }
  ],
  "evidence": "Student asked why the derivative must equal zero.",
  "evidenceRefs": [
    { "sourceType": "digest_material", "sourceId": "material-stable-id" }
  ],
  "recommendedNextStep": "Use a new context to verify independent method selection."
}
```

显式 `eventId` 或 `idempotencyKey` 优先；缺省时由学生、知识点、事件时间、任务、表现和来源引用生成稳定 ID。重跑同一消化回执不会重复累计；相同 ID 指向不同来源或表现时拒收，不能覆盖已存事件。

## 4. Canonical taxonomy

MVP 内置微分、积分、统计和二项分布的基础知识点及中英文别名。例如 `stationary point`、`stationary points` 和“驻点”统一映射到：

```text
MATH.CALC.DIFF.STATIONARY_POINT
```

其它学科可提交符合稳定 ID 规则、同时带明确 label 和 taxonomy version 的外部知识点；后续应按学科把外部 ID 逐步纳入版本化 taxonomy。taxonomy 变更不得静默改写旧事件，需通过迁移映射另行处理。

## 5. 确定性状态计算

Agent 只提供 0–4 的可观察维度，主机换算为 0–1 并计算：

```text
evidence score =
  concept × 25%
  + procedure × 20%
  + method selection × 20%
  + transfer × 20%
  （按实际存在的维度重新归一化）

hint penalty = hint level × 0.04
```

当前实现对最近八条事件使用越近权重越高的确定性聚合。保持置信度：

- 0–7 天：不衰减；
- 8–30 天：轻微下降；
- 31–90 天：中度下降；
- 90 天以上：继续降低但保留历史证据。

`currentMastery` 是结构化证据投影，不是心理测量意义上的精确能力概率。状态为 `introduced / developing / practiced / mostly_mastered / mastered / unstable / needs_review`。`mastered` 至少需要两次低提示强证据及一次迁移证据；长期无证据转为 `needs_review`，不自动写成 `forgotten`。

2026-09-21 起，`scores` 还分别保存 `conceptualUnderstanding / proceduralFluency / methodSelection / transfer` 的最近八条已观察事件加权投影。某维度从未观察到时为 `null`，不会显示为零分或推断为不会；缺失维度也不再计入模型置信度的完整性。

同一错误跨事件出现两次及以上才进入 recurring misconception。仅一次出现标记 `unverified`，没有再次出现不等于已解决，当前不会自动标记 resolved。

主机根据状态给出 `reviewPriority` 和 `recommendedReviewAt`，但状态固定为 `recommendation_only`；它不会绕过统一任务中心自动创建练习或打扰学生。

## 6. 查询规则

`bridge:getLearningAnalytics` 的输入最少包含 `studentId`，可选：

```json
{
  "studentId": "student-stable-id",
  "subject": "Mathematics",
  "knowledgePoint": "stationary points",
  "from": "2026-01-01T00:00:00+08:00",
  "to": "2026-12-31T23:59:59+08:00"
}
```

返回 `events / states / misconceptions / rejections / historyMarkdown`，事件固定按 `occurredAt ASC` 排序；状态在读取时按当前时间重新投影，避免陈旧保持度。接口先从学生索引重新解析实际知识库路径，调用方不能通过参数读取其他目录。

`/咨询` 对当前学生的问题如能匹配知识点名称或“薄弱、复习、变化、掌握”等纵向意图，主机会追加最多四个知识点、每点最近四条带来源事件的本机上下文。即使知识库查询暂不可用，也会明确标明只有本机候选证据，不能将缺失资料解释为不存在。团队范围不注入单个学生的私有轨迹。

“成长模型 → 知识轨迹”可以按知识点名称/ID 筛选、按复测优先级查看状态、点击知识点下钻到时间、表现、错误和来源 ID，并查看未发布的历史变化候选。候选文件不写入正式 `学情报告/历史变化.md`，也不会自动创建任务。

界面已增加四个分维度证据估计，未知显示“待观察”。周期报告任务读取当前学生、当前周期内最多八个知识点、每点最多三条事件的纵向候选索引；候选与成长模型的“可引用证据白名单”分离，只供定位需核对的知识点与来源，不能据此发布掌握或遗忘结论。已发布报告不会仅因候选变化自动重生成，正式结论仍须由现有确认成长证据支持。

## 10. 2026-09-21 连续屏幕采集与纵向分析的统一路线

**结论：增强既有学习时间线，不对连续截图建立第二条纵向分析链。** 当前时间线的受控正式消化回执已能在每个 `timelineObservations` 活动段携带 `learningEvents`，主机只接纳已完成、非待核实的活动段，复用同一学生的 Learning Event / Knowledge State 账本；纯视觉 `visionOnly` 结果不写学习事件。删除采集会话时，相应派生事件随来源撤销。2026-09-21 已把可选 `learningEvents` 字段及证据边界写入时间线资料包模板，并在入账层拒收只有 `capture_event` 截图来源的表现评分（`performance_source_visual_only`），避免仅凭画面补造分数。

上述屏幕链增强后的全仓测试：1054 项中 1053 通过、1 跳过、0 失败。第 7 节的 `longitudinal-20260921-v3` 候选包构建于本次屏幕链增强**之前**，不包含此处新增的资料包说明和纯截图拒收校验；需要发布或真机验收时须重新打包。

推荐的数据关系是“采集帧与 OCR/视觉观察 → 有界活动段 → 已核验证据 + Agent 候选学习事件 → 同一 Learning Event 账本 → 知识状态与复测建议”。时间线描述**何时发生什么活动**，纵向分析比较**同一知识点在不同日期的可证实表现**；前者不是后者的替代物。屏幕上的题目、提交按钮或页面变化只说明活动，不能单独证明答案正确、提示依赖、迁移或遗忘。遇到授权对话、题目答案、评分或教师反馈时，可在原活动段关联来源并提取事件，按来源 ID 去重；不重复读取全量图片。

对普通 Agent 对话，建议沿用同一 `learningEvents` 契约和账本，但使用独立的“对话结束后提取”任务与 `conversation_message` 来源引用，不把它伪装成屏幕采集事件。分析授权默认随**今后的**会话采集授权开启；单独撤销应停止后续提取，并明确区分“仅停止未来处理”和“删除未发布派生事件”，保留原始对话资料的既有治理规则。该对话任务、开关及撤销处理尚未实现，不能仅凭现有采集开关宣称自动学习分析已接通。
