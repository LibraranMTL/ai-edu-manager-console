# R21：MCP 查询兼容与包体优化（r14 候选）

## 任务范围

修复 WorkBuddy 反馈的空参数、跨学生查询参数声明、整体画像报告读取流程；保留现有统一 `edu-manager-knowledge` 安装身份、全局授权、学生隔离及写入规则。检查包体并做不删除功能的精简。Windows 候选版本为 0.21.1，标签 `external-agent-query-r21-20261016-r14`。

本次没有更新用户日常 WorkBuddy/Codex 配置，没有给真实学生写入测试档案，也没有发布到商店或覆盖正式下载 manifest。

## 查询修复

1. 无业务必填条件的只读工具允许省略 `input`，主机规范化为 `{}`。知识检索仍必须提供问题；报告读取仍必须提供报告 ID；写入工具不放宽。
2. `education_query_students` 从现有能力合同派生每个 `name` 的输入 schema，并用分支约束匹配。概览和报告列表不接受 `question`；归档/任务列表接受分页；知识查询要求 `question`。后台同时校验，不依赖 Agent 遵守声明。
3. `null`、数组、标量、未知字段均拒绝；`constructor`、`toString`、`__proto__` 也不能作为继承属性混入合同。跨学生接口不接受额外的学生/项目字段；每个目标继续检查当前授权。
4. 概览说明明确“仅 ID、姓名、关联项目”，不再让 Agent 将其误认为整体画像正文。工具描述和初始化指令引导“报告列表 → 报告读取”，整体画像报告 ID 为 `profile`。
5. 复用既有报告 ID 白名单和主机读取路径，不开放任意文件路径。报告新增 `offset`、`limit`、`contentHash`，返回 `nextOffset`、总字符数和内容哈希。后续页必须携带同一版本哈希；内容变化返回 `REPORT_CHANGED`，不能拼接新旧报告。旧调用仍默认读取前 65536 字符并保留 `content`、`truncated`、`uri`。
6. 为确实只读的工具提供 MCP 只读提示；该提示不是授权，主机的权限、学生范围、项目范围、撤权与会话代际检查保持有效。

## 测试方法与证据区分

### 已安装环境的真实资料验证

本 Codex 会话通过已连接 MCP 执行了：打开独立会话 → 授权学生目录精确定位 Hunter → 报告列表 → `report.read(profile)`。主机返回 3149 字符、`truncated: false`，来源为对应学生的 `edu://.../report/profile`。没有使用文件、终端或网页工具读取该报告正文。这里只记录回执元数据，交付文件不附私人报告全文。

这证明原有报告读取能力可用，但不能单独替代新版本空参数与分页的验收。

### 修订源码与候选包的真实厂商模型调用

复用 `verify-unified-connector-package.cjs`。测试在独立临时主机目录使用两名合成学生和随机报告末尾验收码，调用实际 WorkBuddy/Codex 厂商 CLI 与模型，不模拟模型回答。后端加载源码或最终 `app.asar` 的生产认证、MCP、网关以及 `invokeAgentCapability` / `agentCapabilityReceipt`；仅学生目录及报告路径指向合成夹具。

模型任务包含：学生定位、无 `input` 的列表、跨学生概览，以及携带版本哈希的报告分页。只有主机记录到实际查询回执、模型得到报告末尾随机码、调用记录没有文件/终端/网页工具，才记为通过。Agent 不获知报告的本地文件路径。

Codex 使用独立进程配置，仅为本次用户要求的六个 MCP 查询工具设置允许，保持文件/终端工具关闭，不修改全局审批配置。该配置依据官方 [Codex 配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)。

WorkBuddy 需要 `ToolSearch` 和 `DeferExecuteTool` 加载并调用延迟 MCP 工具。首次只允许发现工具时，实际被延迟执行审批拦截，未计为通过。用户随后明确允许“仅本次隔离只读验收”；只传 `--allowedTools` 仍被拦截，最后在该进程的内联 `--settings` 中同时声明对应 `permissions.allow` 后通过。仍禁用 Read、Write、Edit、Bash、PowerShell、Glob、Grep、WebFetch、WebSearch、Agent，主机同时拒绝全部非验收操作。没有使用 bypassPermissions，也没有持久化该权限。本次两端验收进程均已退出。

### 回归覆盖

新增用例覆盖空对象与缺省参数等价、非法类型/未知字段拒绝、能力参数分支、越权学生、目标缺失、写入约束不变、报告超长分页、Unicode 重组、版本变化、错误 offset/limit/hash，以及包体优化必须保留运行库和法律声明。

完整测试还覆盖 DOCX/XLSX 打包抽取、真实 Windows OCR、扫描 PDF、学习卡片、任务调度、写入幂等、迁移与事务恢复。测试通过不等同于所有设备和所有历史数据组合都已验收。

## 包体审计与优化

基线为 r12。检查包内文件清单、最大文件、哈希重复项、前端可达资源、打包依赖和构建配置。大头是 Electron、PDF 的 Skia、图形 DLL、ICU、媒体和许可证文件。它们不是可直接删除的冗余代码。

已采用：

- 课程 Excel 导入、文档抽取、学习卡片富文本、连接生命周期四个既有 bundle，仅启用空白压缩，不做变量重命名或语法重写，保留内联许可证。
- 候选封装改为 maximum 压缩；可能增加构建耗时，不删除文件或业务能力。
- 用 `audit-windows-package-size.cjs` 对比文件清单、哈希、压缩前后模块大小；用 `verify-compacted-runtime.cjs` 对比公式/恶意内容转义、CSS、课程许可门槛、Excel 模板跨版本读取结果。

保留：全部既有多语言、PDF 字体/CMap/WASM、OCR、原生渲染、媒体、图形回退、法定声明及现有功能模块。没有复制完整 node_modules，也没有新增 Node/Electron 运行时。

未做：删除看似未使用的主进程分支、移除历史格式兼容、合并会改变隔离边界的工作进程、裁剪图形/媒体 DLL、删除字体或许可证。现有动态调用与兼容场景不能仅凭文本引用次数判定无用。

## 安装与复测

先退出旧版教育管家，再启动本候选包，避免单实例机制继续使用旧进程。进入“系统设置 → Agent 连接管理 → 外部 Agent 连接器”，保存授权并对已安装宿主执行原位升级/修复，不添加第二套 MCP。重启 WorkBuddy/Codex，创建新会话加载更新后的工具声明。

建议复测语句：“只通过教育管家 MCP 查询 Hunter 的完整整体画像。不要直接读取本地文件；报告有后续页时继续读取，并给出来源。”不应再靠添加 `question` 填充概览参数，也不应从本地路径补读正文。

## 最终结果

- 完整回归：2251 项，2250 通过、0 失败、1 跳过；最终用时约 114 秒。
- 最终 `app.asar` 的真实厂商模型验收：Codex 通过（约 58 秒）、WorkBuddy 通过（约 68 秒）。两端均收到授权学生目录、无 `input` 的报告列表、无 `question` 的跨学生概览，以及 offset 0/101/202 的三页报告，最后一页完整。随机末尾验收码与主机回执吻合，没有文件读取兜底。
- 真实厂商调用使用合成学生夹具，不冒充两端桌面 UI 对真实学生的完整验收。另有本 Codex 已安装环境对真实 Hunter 报告的只读 MCP 基线验证，见上文。
- 包内链路验证：PowerShell → 打包 Electron Node → MCP → HTTP；原连接身份升级、别名兼容、学生分组、分学生幂等，以及卸载撤权和重装均通过（测试目录内执行）。
- 压缩等价性：9 组富文本/公式输入、CSS、课程许可与导出接口、Excel 模板交叉读取通过。242 个外部运行库文件哈希一致；既有前端 162 个文件完全一致；没有删除原有 electron 模块。
- 代码包 `app.asar`：21,056,301 → 19,497,338 字节，减少 1,558,963 字节（约 1.49 MiB / 7.40%）。解压总量减少相同大小。
- 最终 EXE：100,321,799 → 100,262,032 字节，减少 59,767 字节（约 58.37 KiB / 0.060%）。安装文件压缩后缩小有限，不宣称大幅减小安装包。
- 包内机密扫描 0 项发现；前端不可达资产 0 项。签名检查为 **NotSigned**：这是待设备复测的候选包，不是已签名正式发布。
