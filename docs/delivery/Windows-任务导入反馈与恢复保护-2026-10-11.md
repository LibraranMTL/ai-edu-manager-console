# Windows 任务导入反馈与恢复保护

日期：2026-10-11。源码版本保持 0.21.1；这是局部修复候选，不是系统任务优化三阶段全部交付。

## 一、核查结论

1. 手工导入的 WorkBuddy 结果属于旧 executionId 和旧资料批次；核查时相同资料任务已经转为新的 Codex 执行。拒收是必要的，不能改写旧结果编号强行入库。本次只读取任务状态，没有修改真实学生账本或重跑资料。
2. 原导入代码把“任务状态转换成功”和“结果通过校验”混为一谈；校验失败时可能返回 ok=true，界面据此清空输入。错误文案又优先使用 Agent 自报摘要，可能把“全部完成”显示为失败原因。
3. topic_suggestion_refresh 已有候选任务和规划服务，但内部执行器缺少分发入口。已补上本地证据更新；不在内部执行器偷偷调用模型，需 Agent 深化时仍走规划原入口。
4. 截图中的报告“观察项不能写成正式定论”是证据边界校验，不是网络问题。核查时对应历史变化任务已有后续成功记录，不能把旧截图当作当前仍失败。
5. 原取消逻辑不等待外部停止；原账本读取又可能把解析失败退化为空账本。这两处都可能引发重复处理或数据覆盖。

## 二、本轮已接入的修复

### 导入和快捷处置

- 增加异步粘贴、文件导入接口，保留旧接口兼容。文件选择与读取异步，JSON 限制 1 MiB；业务校验仍在既有宿主路径，不宣称重型校验已经全部离开主进程。
- 显示正在校验，防止重复点击；收到结果后将反馈滚到可见位置并按需刷新详情。
- 校验失败返回失败状态及宿主校验原因，保留输入；成功才清空本次未编辑过的内容。
- 本次界面会话中按任务保留粘贴草稿。切换任务不串内容；迟到响应不会清空其他任务输入。这不是跨重启草稿持久化。
- 按旧批次、报告证据、旧版内部入口、登录故障、执行不明分别给出处置说明，并支持复制；不提供不分原因的一键批量重试。
- 旧批次：保留粘贴内容，使用当前批次指令和结果；不要修改结果编号。
- 报告证据：修订对应观察项表述，保留证据和来源版本；不放宽成长模型校验。
- 取消不明：明确显示“核对中”。用户先到原工具确认未发送或已停止，再通过明确确认操作记录人工核对。该动作不伪称自动验证远端，不立即重跑。

### 选题任务

- 严格匹配任务类型、学生范围和 input.studentId 后调用现有本地规划服务。
- 通过 reviewing → succeeded 合法状态链完成本地建议更新，不要求额外人工确认，也不形成正式成长结论。
- 新任务声明 planning-guidance 目录及写建议操作。已忽略的历史任务不自动恢复。

### 存储故障保护（同步兼容层）

- 账本损坏、读写失败时停止新任务派发，保留原文件；不以空任务覆盖。
- 使用读取版本跟踪，拒绝旧快照覆盖更新；这种调用冲突与磁盘故障区别处理。
- 已见过的账本消失时拒绝重新创建空账本。
- 页面显示存储故障提示。修复磁盘或目录权限后重启主机；不要删除账本。
- **这仍是同步兼容层，不是全局单一异步写入队列。**

### WorkBuddy 探测基础

- 必须解析最终 JSON result=READY；普通日志、空输出、工具事件、零退出码错误不算授权通过。
- 独立空临时目录、无工具、严格空 MCP 配置；不以学生目录为探测工作目录。
- 实现成功 30 分钟、失败 5 分钟缓存及单在途合并；手动重新检测可强制失效。
- 诊断详情提供主动检测入口，说明可能消耗额度；共享资源许可不足或后台忙时不探测。
- 检测仅返回授权状态，不返回登录票据、完整 CLI 输出，也不据此启用原来的宽泛文件编辑模式。
- **条件式自动资料执行尚未开启。** 尚需逐业务类型的工具隔离、合成资料端到端和候选内容宿主提交验收。

### 恢复保护

- 取消请求不等同于外部停止；启动进程退出也不等同于子进程或远端任务停止。
- 未确认批次保留执行标识，禁止重试、重新派发、历史删除和候选刷新清空；同一学生/项目写入范围保持保护，其他范围可继续。
- 本机仍跟踪的进程不能被人工确认覆盖。人工核对绑定具体执行 ID，状态变化后旧确认失效，并留下审计记录。
- **这不是完整自动恢复机制。** 有界跨执行器重试、持久提交日志补收、休眠恢复和未知结果统一核对仍需后续迁移。
