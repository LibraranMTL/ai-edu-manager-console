## 1. 决策与交付边界

先把单个学生已授权的屏幕资料、Agent 会话、课程任务和作品版本组织成可追溯的“任务—初次尝试—指导—再次尝试—结果—延迟验证”序列。首先交付**可读的学习时间线、个体纵向变化和诚实的未知项**；个人行为预测只作为经过时间外验证后才启用的后续能力。当前不训练或宣称拥有可靠的“虚拟学生”。

屏幕截图是证据单位，采集会话是传输和处理单位；**有足够证据时，一次学习尝试 `attempt` 才是可比较的行为分析单位**。不能把所有屏幕活动强行归成尝试：先保留 `event → activity episode → candidate attempt → supported attempt` 层级。阅读、观看、思考或稀疏截图若缺少可辨任务/行为人/初答，只形成活动段或候选尝试，不计作成功、失败、独立学习或预测样本。同一任务可有多次尝试、跨应用、跨会话或跨天；同一有证据的尝试可有截图、会话和作品等多份证据，但只能计为一次表现。报表与预测是证据的投影，不反向成为学生行为事实。

本期不新增持续录屏、键盘/鼠标行为监控、私人聊天抓取、摄像头/麦克风、旧历史全量扫描、同龄人排名、情绪/动机/专注评分、有效学习时长、自动成绩判定或新的日常人工审核。已授权的 Codex 视觉服务仅在对应学生截图授权与实际处理位置边界内使用；其他 Agent 不继承 Codex 的视觉能力或授权。

## 2. 已核对的现状与真正缺口

| 现状 | 对 P1-T 的影响 | 目标改造 |
| --- | --- | --- |
| `capture-timeline.cjs` 在缺少 `capturedAt` 时可回退上传时间、会话开始时间或当前时间 | 时间顺序看似完整但真实事件时间未知 | 原始时间、替代时间、来源、精度及设备时钟偏差分别记录；不把替代时间表述为真实发生时间 |
| `capture-timeline-semantic.cjs` 以时间间隔、来源和画面差异形成活动段 | 有分段骨架，但未识别任务与多次尝试 | 加任务/尝试 ID 与事件角色，保留旧活动段只读兼容 |
| 现有视觉回执有主题、动作、阻碍、变化、结果；v3 的 `attempts` 仍可为空 | 无法稳定还原“初答—帮助—修正”的关系 | 同一次多帧观察输出带证据的事件和关系，不为每字段重复调用模型 |
| 当前 `guidanceResponses` 缺失时可生成“下一步建议” | 系统建议可能被误当成实际指导和学生响应 | `recommendation`、实际 `intervention` 与观察到的 `response` 分开存储、计数和展示 |
| 会话规范可把 student/parent/teacher 映射为 `user` | 协议角色不等于实际行为人 | 保留原 `role` 兼容，再增 `actorType` 与身份依据；未知不得默认为学生 |
| 现有日/周时间线主要聚合活动段字段和计数；`历史变化.md` 尚无统一状态转移输入 | 容易成为截图文字的再次汇总 | 建可比较的个体状态快照与变化账本，报告按证据链投影 |

上述是 2026-09-16 对源码结构的检查，不是对真实学生样本准确率、覆盖率或真机性能的证明。开发开始前重测基线；不读取或迁移未授权学生历史作样例。

## 3. 数据契约：事实、推断、建议和预测四轨分离

### 3.1 数据对象及信任边界

```text
RawEvidence（原图、原消息、任务/作品版本，不可变）
  → Observation（某时间点直接可见的内容，字段级证据）
  → LearningEvent（任务开始、尝试、阻碍、提示呈现、修订、提交等）
  → Attempt（同一任务的一轮实际尝试；可跨来源）
  → Episode（同一学习目标的一组尝试与真实空档）
  → StateTransition（单学生知识/策略状态的可解释变化）
  → ReportProjection（时间线、统计、历史变化）
  → PredictionRecord（若通过独立验证才启用，不写回事实层）
```

- `Observation` 只描述证据实际支持的画面、文字或记录。视觉模型的描述是**受控但可错的观察候选**；系统验证来源、哈希和交付，不等于验证文字一定符合画面。正式知识仍按既有 `AGENT.md` 与成长证据治理；时间线观察不能自动升级为能力事实。
- `LearningEvent` 至少区分 `task_seen / first_attempt / revision / error_observed / help_requested / guidance_presented / result_observed / verification_attempt`。无法判定的事件角色为 `unknown`，不能因为缺少画面就推断“未尝试”或“放弃”。
- `intervention` 是**实际存在的指导**，状态至少为 `generated / delivered / visible_in_evidence / responded / unknown`。生成不等于送达，画面显示不等于学生阅读，更不等于指导有效。系统建议另存 `recommendation`，永不计入历史指导样本。
- `outcome` 分开记录“是否提交/完成”“是否正确或达到质量标准”“是否独立”。运行成功、复制答案和一次提示后改对不直接等于学生理解。评价来源可为自动判题、教师评语、作品差异或仅视觉观察，并分别标置信度。
- `PredictionRecord` 保存目标、预测时点、可用历史截止点、模型/规则版本和随后真实结果的对账状态。预测或 AI 报告不得回摄入行为事实或模型训练标签。

### 3.2 最小字段和时间可信度

建议新增版本化的 `temporal-event.v1`、`learning-attempt.v1`、`knowledge-state-snapshot.v1`，以独立投影和关联索引接入既有 JSONL/资料包，不在原始事件里静默改写旧语义。关键字段：

| 字段组 | 必需信息与允许未知项 |
| --- | --- |
| 归属 | `studentId/deviceId/projectId/sessionId`、`actorType`、`actorEvidenceRef`；无法确定行为人时为 `unknown`，不跨学生猜测 |
| 时间 | `occurredAt`、`receivedAt`、`processedAt`、本地时区、`timeSource`、`timePrecision`、序号及可知的设备时钟偏差；时间回退须显式降级 |
| 任务 | 稳定 `taskId/taskVersion`、任务类型、概念 ID/版本、难度及其来源；名称相似或时间相近仅产生候选 |
| 尝试 | `attemptId`、前次尝试引用、原始回答/作品版本、修订范围、支持程度和证据 |
| 指导 | `interventionId`、原文/消息引用、提供者、指导强度、生成/送达/呈现时间、实际响应引用；缺项保留 `unknown` |
| 结果 | 完成、正确性/质量、评价来源、结果时间、独立性、后续验证任务；这些字段互不替代 |
| 证据 | 事件 ID、原始哈希、已授权来源、视觉/OCR 方法、分析器与策略版本、字段级引用及可追溯修正关系 |
| 覆盖 | 采集策略、原始采样间隔、被排除范围、暂停/休眠/断网、丢帧与未知空档；展示统计时共同呈现 |

时间按可信度分层：设备真实采集时间且时钟正常、可校准的设备时间、仅有上传/会话时间、完全未知。顺序不确定时只能说“分别观察到”，不能强排“先指导后改正”。跨午夜以带时区时间戳拆分；补传不能改变原事件时间，修正要留旧值及依据。

### 3.3 关联、去重与版本

先用显式任务 ID、作品/文档 ID、授权会话消息 ID、课程任务引用关联；其次用同归属内容与时间提出候选。**单纯时间相近不能自动确认同一任务、行为人或指导因果。**关联不确定仍可形成未关联观察，不阻断其他段消化。原截图、聊天和作品指向同一尝试时只增强证据，不增加成功/失败计数。

规范化事件、任务和尝试均有稳定键，关联规则与概念映射单独版本化。新解释通过 `supersedes/correctedBy` 修正旧解释，不覆盖不可变证据；来源撤销、删除、授权失效或错归属时，依赖该证据的状态、报告与预测须失效或增量重建。旧数据只读兼容，不因升级而自动获得“已识别行为人”“已视觉确认”或“已独立掌握”标记。

## 4. 采集与多帧分析：建立时序，不扩张监控

1. **复用优先级**：结构化课程/任务事件与可验证结果优先，其次是已授权的 Agent 原始消息和作品版本，屏幕关键帧补充缺失的过程。稳定任务 ID、提交/修订版本可直接产生可关联候选；时间接近或主题相似只给出关联线索。现有教师/家长反馈可作为标时补充来源，不增加每天填表。
2. **轻量采集**：前台采集路径只保留现有截图、差异、时间、哈希、归属与排除规则；不做全图 OCR、逐图大模型、主进程原图解码或全历史搜索。首次授权可以撤回，采集授权与第三方视觉处理授权分别保存。
3. **两级选帧**：先按时间、来源、画面差异、采样策略和少量规则间隔样本选择代表图；首次分析发现链路缺口时，只在已有授权资料中有界补取邻近帧。重点覆盖任务开始、初答、提示前后、关键修改、结果和跨日复测，避免只选变化最大画面造成选择偏差。
4. **长会话预算**：沿用每个可续处理资料包最多 20 图、每次视觉请求最多 8 图的既有界限；长会话拆成多个包，而不是前 20 图耗尽后永久丢失后段。另设每会话/日共享费用与字节预算、待处理队列和自动延期；具体预算值按真机耗时、费用和内容质量试验确定，不预设无限量补帧。
5. **单次多目标识别**：同一有序图组一次输出观察、事件角色、前后差异与证据引用。必要时用同批对照帧或受控比较子批；不能把分属两次请求的图片描述冒称直接视觉比较。OCR 仅用于代表图的精确文字或视觉失败后备，不能单凭 OCR 声称页面操作和指导响应。
6. **缺失显式化**：记录实际采样间隔、跳过重复画面数、暂停/休眠/网络空档。稀疏截图只能给响应时间区间，不能计算精确反应时、有效学习或专注时长。

屏幕/OCR/会话原文均是不可信资料，不得执行其中的指令或扩展模型的读写权限；系统内部消化会话排除，避免自身总结反馈循环。跨主机知识同步仍遵守已有学生和项目范围，不因 P1-T 默认同步全部原图。

## 5. 单学生纵向分析：先可解释，再研究预测

### 5.1 可比较的个体基线

状态比较的最小单位为同一学生、同一概念或技能版本下的**可比较尝试**。同时考虑任务类型、可判定难度、是否独立、指导强度、评价方式与场景。观察次数增加但任务难度变化时，不直接宣称进步或退步。

使用滚动窗口呈现最近可比较尝试、近 7 天与前 7 天、近 28 天与前 28 天及阶段比较；每个窗口显示证据覆盖、未知比例和可比样本数。窗口只是呈现尺度，不是固定的科学达标门槛。没有足够比较对象时显示“正在建立个人基线”或“证据不足”。

初期采用可解释状态：`未观察 / 初次接触 / 提示下完成 / 部分独立 / 多次独立 / 跨情境使用 / 长期未复测 / 证据冲突`。不以少量截图输出貌似精确的掌握概率。独立成功、提示后成功、重复错误、间隔后复测与跨情境表现分开计数；长期未复测提高**不确定性**，不自动断言遗忘。一次事件可成为观察，两次不同日期的可比事件可形成线索，稳定趋势必须结合真实覆盖、质量和反例判断；这些是报告措辞等级，不是上线数量门槛。

### 5.2 变化与指导响应

状态转移记录旧状态、新状态、发生区间、可比任务、支持强度、直接证据、反证和未知项。指导响应链至少区分：初答、实际指导、后续尝试、结果；若只有建议而没有真实指导，或只有指导而无后续尝试，不形成“指导有效”的样本。支持强度从无提示、一般提示、定向提示、示例到直接答案分别呈现；“提示后改对”不写成“独立掌握”。

进一步观察同一错误是否复发、是否会主动复查、隔天是否保持、换题型是否迁移。任务结果和指导方式相关不代表因果；不能忽略题目难度、初始状态与其它帮助来源。若缺少正常任务中的延迟验证机会，可在现有课程或行动建议中**建议**一次短验证，但不得自动创建新任务、额外打扰用户或把“尚未验证”写成“未掌握”。

### 5.3 报告与上下文复用

学习时间线按“事件 → 尝试 → 活动段 → 会话 → 日/周”逐层投影，默认讲清任务、初答、阻碍、真实指导、修订和结果；缩略图只作证据。上层只压缩已校验下层，不再次读取全部图片或重复调用模型。报告每条具体结论可下钻到对应版本的事件、消息或作品。

`历史变化.md` 应从状态转移而非两份报告文字的比较生成，包含：本期证据覆盖；可比较知识状态；独立与提示后表现；重复错误；策略变化；保持/迁移；证据冲突与未知；下次最小验证点。分别展示“新增证据但结论不变”“改善线索”“提示后改善、独立未验证”“重复困难”“资料不足”，避免一律显示“无实质变化”。正式报告仍只引用符合成长模型和知识治理条件的依据；未升级为正式知识的时间线观察可作为带状态的候选视图，不暗中变成发布结论。

跨 Agent 新会话只按学生、任务、概念和时段取最小必要上下文：当前状态、最近可比变化、关键反例、支持偏好及证据引用。默认不送全部截图或会话原文；需要时再在已授权范围内按需读取。源证据撤销后，索引和上下文包同步失效。

## 6. `AGENT.md` 与现有报告协议的实施要求

修改的是**受管模板和协议**，不是自动覆盖已存在、被用户手工修改或采用的学生 `AGENT.md`。实施时核对内置学生模板、默认规则文本、已有用户规则的受管区块与跨主机逻辑路径；只更新受管区块或提供可选择的差异，不重写私人规则。项目 AGENT.md 另守项目范围，未经现有知识贡献治理不得写入学生主档案。

在学生 `AGENT.md` 的消化 Protocol 增加简洁的强制规则：

1. 使用真实采集时间及其来源；上传/处理时间不得伪装为事件时间。
2. 先形成可追溯事件与尝试，再形成摘要和报告；单图只支持当时事实，变化需有有序的前后证据。
3. 分开记录实际指导、学生响应与系统下一步建议；未见帮助不等于独立完成。
4. 分开记录完成、正确、独立、提示后完成与未知；不从程序运行通过推断理解。
5. 每项状态变化写明可比任务、旧/新状态、时间、证据、反证及不确定性；证据冲突保留版本。
6. 不从画面停留推断专注、动机、情绪和有效学习时长。
7. 局部失败标记未知并继续处理其他证据；不得要求普通用户逐次审核。
8. 时序观察、正式知识、报告和预测保持各自来源与发布边界。

详细事件枚举、字段 Schema、示例与版本策略放入受管的时序策略文件，由 Agent 处理时按需读取，避免 `AGENT.md` 膨胀、历史截图全量进入上下文。同步检查 `learningReportProtocolText()` 等旧规则中“必须人工确认/审核”的措辞是否与现行自动校验发布流程冲突；该检查不意味着放宽高风险归属、授权或越权门。

## 7. 个人行为预测：前瞻验证后的受控能力

**P1-T 的主要交付是可解释状态和趋势，不是立即上线预测。**未来若启用 Personal Learning Dynamics Model，采用：个人状态估计 + 该学生相似历史检索 + 轻量预测器，不直接以单学生少量记录训练 DKT、AKT 或 StudentSim。

预测目标必须具体，例如“下一次同类任务的初次尝试是否需要提示”“指定指导呈现后是否会再次修订”“一周后同概念是否能独立完成”；每项有确定时域、可观察结果和缺失结果处理。初期以**静默影子评估**运行：预测在结果出现前封存时间、输入截止点、模型版本、预测与不确定性；仅在后续真实任务结果出现后对账，不把预测显示为学生能力定论，也不驱动自动任务分配。

时间外切分是硬要求：训练/检索只能使用预测时点之前的历史；同一任务重复截图、同一作品的多个版本与后续评价不能泄漏到预测输入。对比“沿用上次表现”“相似历史频率”和简单可解释规则等基线，记录覆盖率、错报漏报、概率校准（若输出概率）、不同任务类型的失效情形以及模型运行成本。不存在由未经验证的“10～30次”或“30～100次”即可启用的固定门槛；是否向用户展示预测，取决于足够的可比较独立样本、时间外表现稳定优于简单基线、校准与风险评估。单学生证据始终不足时，保持关闭并继续提供时间线与历史变化。

DKT、AKT、StudentSim 只作未来研究备选。特别是 StudentSim 的群体训练后个体适配结论，不可外推为单学生截图足以训练可靠数字分身；即使启用预测，也不承诺形成学生人格模拟或真实行为的因果机制。

## 8. 自动化、性能与失败恢复

- 用户流程维持现有授权、开始/结束采集；没有新增日常确认、逐图审核、逐题标注或失败手工恢复。仅学生/项目归属、外部处理授权和敏感范围等无法自动决定的事项提示用户，且只暂停受影响数据。若将来取消现有开始/结束操作，须单独设计明确授权范围内的生命周期自动采集，不由 P1-T 默许扩大监控。
- 事实写入、分段、受控视觉、局部 OCR、关联、状态更新和报告投影共用已有全系统重任务预算。同一学生同一处理链串行；采集进行或前台延迟超限时不启动新 AI/OCR 重任务，普通使用最多 1，插电且持续空闲、资源充足时最多 2 个互不依赖任务。任务在小批边界保存检查点并让行。
- 事实与索引按日/任务分区，任务、知识点与报告窗口增量更新；页面只读取预生成分页投影、证据图懒加载。打开时间线、成长模型和任务中心**不得触发全历史重算或图片重识别**。相同学生、证据哈希、授权 epoch、模型与策略版本命中缓存，不因更换正式消化 Agent 重看同图。
- 预算必须同时约束代表图、字节、模型请求、费用、队列时间和补帧次数；长会话可以有多个有界包，预算耗尽时自动延期并显示覆盖缺口，不把后段记录丢失或对用户声称已分析。
- 普通模型/OCR/网络/投影失败只影响对应最小单元：已成功事实、知识或报告不回滚；有界退避、后台恢复与必要时降级为 `unknown`，无持续重试风暴。授权撤销阻止新外发并处理缓存/衍生物失效；不可恢复的越权/错归属不得自动降级放行。
- **持续采集防饥饿**：上游规定采集期间新 AI/OCR 重任务并发为 0；如果会话不结束，后台分析可能长期排队。采集会话须按现有授权自动切成有界处理窗口，窗口关闭后再根据实际空闲/延迟资源许可处理，界面显示队列年龄和覆盖缺口；不能要求用户手工停采来解堵。若真机证明安全处理窗口仍无法得到资源，只保留事实并报告延期，不谎称双报告已完成。

沿用主线候选硬门槛：前台响应 P95 <150ms、主进程无新增 >200ms 同步长任务、采集期间新 AI/OCR 重任务并发 0、时间线首屏 P95 <1s、每包最多 20 图、每次视觉请求最多 8 图。另测启动增量、成长模型/任务中心切换、5000 事件分页、低配置与普通配置真机至少 60 分钟、休眠/断网恢复、连续后台队列及模型费用。以上是**待验证目标**，字段增加本身不代表真机不会卡顿；必须与同机同参数基线比较 P50/P95/最大值、CPU、内存、磁盘和排队年龄。

## 10. 验收样例、度量与发布门

1. **正确性样例**：同一题多次尝试、不同题时间接近、学生/家长/教师混合会话、指导已生成但未呈现、呈现后未响应、复制答案后运行成功、跨日复测、任务名称变更、难度升高、跨应用同一作品、旧截图补传、时钟回退、休眠/断网空档、模型只读失败与证据撤销。
2. **内容度量**：任务关联准确率、初答保留率、指导链完整率、结果可验证率、实际行为人识别率、时间可信度、重复事件率、未知/排除覆盖率、趋势有依据比例和无依据定论率。发布前用已获授权的小样本逐项抽检；失败分类透明记录。抽检只用于开发验收，不转化成每份用户报告审核。
3. **高严重度零容忍**：错学生/错项目、未授权外发、缺图却声称视觉确认、系统建议被计为真实指导、未来结果泄漏到预测、无来源能力定论。任何一项出现即停止相应候选发布并可回退新分析任务；已确认合法原始资料不随回退删除。
4. **性能门**：与同机基线对照主机/学生端采集、页面切换、后台队列与模型费用；既有主线性能门未通过则 P1-T 不发布。真机质量、代码测试、候选包、签名、官网发布和 Git 推送分别记录，不因方案完成或合成测试通过而混称正式交付。
5. **预测门**：T3 先离线/影子、后另行决定是否向用户展示；时间外表现、校准、覆盖、成本及失效场景未达可接受水平时继续关闭。没有预设保证能达到该门槛的日程或样本数。
