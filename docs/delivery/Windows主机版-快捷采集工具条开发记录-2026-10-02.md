# Windows 主机版快捷采集工具条开发记录

日期：2026-10-02

开发基线：本地 Windows 主机源码 `0.19.6`；工作树原有大量未提交改动，本轮仅修改快捷采集相关文件。
交付状态：**用户已确认 0.19.6 快捷采集候选通过真机验证；2026-10-05 进入正式便携包、官网、服务器与 Git 发布流程。程序仍未签名。**

## 已完成

| 计划阶段 | 本轮结果 |
| --- | --- |
| C0 合同 | 独立轻量窗口与受限 preload；白名单路由、主窗口／浮条 IPC 来源校验、学生 ID 主机复核、屏幕会话仍由主机持有；状态只含必要学生与会话摘要，不传原始截图或路径。 |
| C1 低风险入口 | “收集与整理”可显示浮条；托盘可显示／隐藏；紧凑态进入屏幕、录音、拍照；“更多”进入本机文件导入、资料收件箱、对话收集和自动会话采集。录音只跳现有页面，不开启第二个录制器；页面提示结束并取得回执前不要切页。 |
| C2 屏幕控制迁移 | Windows 主机原屏幕浮条由统一窗口接替，保留重点截取、暂停／继续、打开本次采集箱、结束。仅一套主机浮条；Windows 学生轻终端的旧控制条不在本轮范围。 |
| C3 部分 | 已有当前学生已登记收件箱待处理计数、隐藏后托盘恢复、键盘焦点与无学生时禁用操作；尚未加入最近项目选择、Agent 真实授权状态标识和完整无障碍／多屏真机验收。 |

屏幕录像按用户决定明确排除。浮条内录音 R1 仍是可选后续事项，不作为本次交付门槛。当前本机拍照、录音仍由原页面完成，工具条仅提供到达入口；“已打开页面”不等于“原件已接收”。

## 自动与界面验证

- `node --test tests/capture-control-window.test.cjs tests/quick-capture-window.test.cjs`：8 项通过。
- `pnpm exec vite build`：通过。构建的大块依赖提示属于现有告警，本轮未调整分包。
- `pnpm test`：1765 项中 1764 项通过、0 失败；另 1 项未计入通过。旧屏幕浮条合同和启动恢复测试已调整到统一浮条并单独复测。
- Playwright 使用本机 Chrome 检查静态浮条：紧凑态、展开态、屏幕活动态无溢出；录音、本机导入、暂停按钮均发出预期动作，无页面脚本错误。
- 以独立 `--user-data-dir` 启动 Electron 0.19.6：主窗口和浮条均加载；无有效主机学生时按钮禁用；展开“更多”和“切换学生”可打开主窗口学生面板；浮条未出现页面错误。该隔离环境不具备真实许可与学生资料，因此**未验证实际拍照、录音、屏幕截图、文件移动或学生间投递**。

## 尚未验收／后续门槛

1. 在已许可的独立测试环境至少创建三名非敏感学生，逐项验证浮条导航、学生切换、项目范围、屏幕来源与截图控制，不接触真实学生资料。
2. 真机测试多显示器／DPI、贴边位置、全屏及屏幕截图中浮条排除。`setContentProtection` 已尝试调用，但 API 调用成功不能代替画面验证。
3. 摄像头与麦克风的拒权、占用、切页、关闭窗口、异常退出；现有页面录音在切页时仍有中断／丢失风险，本轮仅提示与跳转，不能宣称稳定后台录音。
4. C3 的最近项目选择、授权状态、完整收件计数与辅助功能继续列为 P3；当前计数只覆盖当前学生**已登记**的采集收件项，不含下载文件夹尚未登记的文件。
5. 已构建带独立候选标识的 EXE／ZIP，并核查 Authenticode 为 `NotSigned`。未进行版本递增、性能对照、Git 提交或官网／服务器发布。文件版本仍为本地现有 `0.19.6`；不可把此候选称为正式发布。

## 真机验收与正式发布决定（2026-10-05）

用户已确认快捷采集候选在目标真机验证通过，并确认“更多”展开后收起可以恢复紧凑高度、切换操作时活动按钮颜色能够正确变化。基于该人工验收，本记录中的相关真机门槛转为通过；多显示器、摄像头／麦克风拒权等未被用户明确覆盖的场景不作额外推断。正式发布仍须重新执行全量自动测试、生产构建、哈希与敏感信息审计、线上备份和发布后下载核验。
