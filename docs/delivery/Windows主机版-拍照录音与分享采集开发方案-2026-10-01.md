# Windows 主机版拍照、录音与分享采集开发方案

日期：2026-10-01
适用范围：最新版 Windows 主机及已配对的 Windows／Android 学生、教师终端；本文件是后续开发方案，未完成的页面仍显示“功能建设中”。

## 1. 现状与目标

“收集与整理”已有拍照上传、录音采集、分享采集三个 Tab 占位；现有终端具备文件、相机和个人终端自动投递文件夹的上传路径，主机也有学生／项目资料接收与回执。现有终端的直接上传并不等于主机已经具备统一“分享资料收件箱”；不能把旧直达记录伪装成待投递项目。

目标是让三类新入口共用一条可恢复接收链：**固定接收时的学生与来源 → 保存受控暂存原件 → 预览和分类 → 选择学生原始资料库或关联项目收件箱 → 校验并投递 → 资料整理与消化 → 可回看的来源回执**。项目新模式沿用项目资料登记和固定版本；旧项目沿用兼容接收入口，不另建项目原始库。

## 2. 页面和操作

| Tab | 日常操作 | 失败时保留什么 |
| --- | --- | --- |
| 拍照上传 | 选择当前学生和目标；调用本机摄像头；拍摄、重拍、预览、提交。可一次拍多张并查看每张结果。 | 未提交或投递失败的本机照片；允许重拍、改目标或转资料导入。 |
| 录音采集 | 上传已有音频或现场录音；停止后预览；发起语音转文字；核对／修正转写；选择只保存音频、只投递核对文本或两者关联投递。 | 音频原件和已完成的转写草稿；识别失败不报“已整理”。 |
| 分享采集 | 按待处理、处理中、已投递、失败、回收站浏览；按来源、学生、项目、类型、时间筛选；多选投递、重试、移入回收站、恢复。 | 每项原件、固定学生归属、错误与重试回执；批次部分成功不回滚成功项。 |

分享收件箱集中显示来自学生端网页连接分享、Android 系统分享、Windows／Android 个人终端自动投递文件夹，以及明确选择“先进入收件箱”的文件。旧终端直接上传的资料可通过既有回执显示为“已投递”，不生成假的待处理项。用户点击删除时默认进入可恢复回收站；已投递原件和被知识／报告引用的版本必须先核对依赖，不能因删除收件箱记录而消失。

收件箱卡片显示来源渠道、发送设备／会话、固定学生、文件类型、大小、接收时间、建议类别、目标、状态和最近错误。普通操作只需“投递／删除”；批量规则和识别诊断放在展开区。切换学生时清空勾选与预览，后台任务仍按原学生完成。

## 3. 接收与数据合同

新增 `CaptureInboxItem.v1`，最小字段为 `itemId, studentId, sourceChannel, sourceDeviceId, sourceEventId, receivedAt, originalName, mime, byteSize, sha256, controlledObjectId, suggestedCategory, selectedTarget, status, revision, lastReceiptId`。外部上传的文件名只供展示，不能作为路径或身份；`sourceEventId + sourceDeviceId + studentId + sha256` 用于重试去重，不把相同内容但不同真实来源合并为同一学生行为。

状态为 `receiving → ready → delivering → delivered`，异常分别为 `needs_target, failed_retryable, unavailable, trashed`。接收回执只证明主机保存完整字节；投递回执必须再包含目标、资料 ID、固定版本和操作结果。音频另存转写版本、语言、识别器、起止时间、人工修订标记及对应原音频 ID；转写草稿不是学情结论。

所有入口由主机复核许可证、学生会话／教师权限、项目关联、封存状态、可写目标、大小和类型限制。对话或模型生成的分类仅是建议；目标由已授权用户指定或由主机确认规则决定，不执行模型给出的绝对路径。接收时固定 `studentId`，不因主机后来切换当前学生而改投。接收暂存目录、项目收件箱、学生原始库与备份清单遵循现有受控存储规则；日志和列表只显示必要元数据。

## 4. 三类来源的接入

### 4.1 本机拍照

主机在用户点击后申请摄像头；枚举不可用、拒权、设备占用和拍摄中断分别给出可操作提示。照片先进入当前学生受控暂存，校验格式与完整字节后登记；投递成功再清理应用自有暂存引用。多张照片独立回执，任何一张失败都保留原件。不得用摄像头权限做后台持续采集。

### 4.2 音频与转写

文件上传与现场录音进入同一音频接收合同，限制时长、格式、容量和并发；录音中要有明显的开始／暂停／结束状态。转写通过现有任务适配器异步执行，优先使用已验证的本地能力；缺少可用语音识别器时仍允许保存音频并显示“待识别”。转写结果按时间段保存、标注不确定处，人工可修改后再投递；原音频和文本各有版本与互相引用。不得把录音内容自动当作学生本人陈述或已确认成长证据。

### 4.3 分享与自动文件夹

- 学生端网页连接：在经过学生会话认证的页面提供系统文件选择与分享接收；网页只能投递会话所属学生，项目目标需实时取主机授权列表。断网保留本机待发送项，恢复后按上传编号和字节回执确认。
- Android 系统分享：接收 `ACTION_SEND`／`ACTION_SEND_MULTIPLE` 的文本、网页链接或文件 URI；复制获授权的内容到应用私有待发区并固定当时学生／教师选择，禁止只保存会过期的外部 URI。链接先作为链接资料待核对，不在接收时自动抓取网页全文。
- Windows／Android 个人终端自动投递文件夹：保持现有固定学生与目标授权；新客户端可选“先进入主机分享收件箱”。共享终端不启用持续文件夹监控。文件尚在写入时不发送；终端原文件不因成功上传而自动删除。
- 旧版终端：继续使用已有直接上传与回执；主机把结果投影到“已投递”列表，不改变旧协议语义。

## 5. 任务、失败恢复与权限

新接收和投递接口使用异步 IPC／有界流式上传，不阻塞 Electron 主进程。单项投递以来源版本、学生和目标形成幂等键；程序重启后恢复 `receiving/delivering`，核对原件与目标回执后决定继续、显示冲突或停止。AI 分类与转写不可用时，预览、手动投递、回收仍可使用。批量操作返回逐项结果，不能只显示一个总成功数。

分享收件箱删除只改变候选生命周期；彻底清理需区分尚未投递的应用暂存、已投递资料和已有下游引用。失败清理保留可见记录，不能把“目标已保存但原位置清理失败”称为完全成功。

## 6. 实施顺序与验收

| 阶段 | 交付 | 必须通过的场景 |
| --- | --- | --- |
| S0 接收合同 | 暂存登记、范围校验、状态机、列表／回收与逐项回执 | 错学生、错项目、重复上传、重启、磁盘满、源变化均不串资料或丢原件 |
| S1 拍照上传 | Windows 摄像头界面、拍摄预览、目标选择与投递 | 无设备、拒权、占用、多张部分失败、切学生和退出后可恢复 |
| S2 录音采集 | 音频上传、现场录音、转写任务与人工修订 | 音频保留、转写失败降级、时间段和文本版本可回溯 |
| S3 分享收件箱 | 网页分享、终端分享与文件夹可选暂存、集中列表和批量处理 | 网页断网重送、Android 分享重复激活、旧终端直达兼容、多选部分成功、回收恢复 |
| S4 联合验收 | Windows 主机及学生端、Android 学生／教师端真实设备与构建记录 | 本机、网页、系统分享和文件夹来源均能按固定学生进入正确目标，原件与回执可追溯 |

本轮只规划，不改变 Android、Windows 学生终端和网站版本。实施时按阶段更新源码、测试和候选包；真机摄像头、麦克风、系统分享与跨端离线回传必须单列实测结果。
