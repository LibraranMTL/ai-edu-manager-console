# Windows 0.21.2 统一异常自恢复与普通用户队列 R30

日期：2026-10-17  
基线：`Windows 0.21.2 llm-api-validation-r29-20261017`  
候选标识：`auto-recovery-r30-20261017`

## 交付目标

本候选处理 R29 中“内置任务被误判为外部任务”“核对中没有具体入口”“失败直接转人工”“任务中心暴露过多技术状态”等问题。它不重跑结果未知的任务，不把取消记录改成成功，也不覆盖既有有效研究或报告版本。

## 主要改变

1. 执行来源、回执查询能力、恢复预算和下一步统一持久化；未知结果仍禁止盲目重派。
2. 内置研究任务中断或取消由 Windows 主机确认停止，保留 executionId 和审计历史，迟到结果不发布。
3. 可查询通道进行最多 6 次回执检查；之后才生成包含具体工具和批次的人工接手卡片。
4. 报告进行最多 2 次证据保守的确定性修订；学生或成长版本不一致时停止，不自动“修”身份。
5. 任务中心首层只突出“自动处理中 / 需要你帮助 / 历史记录”，技术诊断默认折叠。

## 安全边界

- 没有删除任务、学生资料或历史结果。
- 没有在开发与测试阶段执行真实未知任务或调用付费模型。
- 账本冲突只重试持久化，不重跑模型或业务副作用。
- 取消、暂停和撤权状态不会被自动恢复成待执行。
- 外部工具没有状态查询能力时，最终仍需要用户在该具体工具中确认一次。

## 验证记录

- 针对性测试：内置停止确认、外部回执预算、三类队列、报告安全修订、R29 P0 回归。
- 前端生产构建：`pnpm build`。
- 完整回归与 Windows 候选构建：由 `pnpm build:win` 在候选生成时执行；最终数量、哈希、签名与 UI 验收结果在构建后补入本文件。
