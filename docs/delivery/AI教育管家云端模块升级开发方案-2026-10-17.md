# AI教育管家云端模块升级开发方案

版本：v1.2（开发评审稿）  
日期：2026年10月18日  
范围：Windows 主机界面、学生基础信息与云端资料、授权服务、远程 MCP、云端成果收件箱，以及既有 Android/Windows 客户端兼容。  
状态：方案已编制；本文描述的新增能力尚待开发、测试和发布。

## 1. 本次升级目标与决策

把云端能力组织为“业务页面查看资料、统一设置管理同步、外部 Agent 按授权调用”的完整流程。复用现有云服务入口 `https://www.greatbg.com/edu-cloud/`，先完成五类资料同步与版本治理，再接远程 MCP 和成果回传。

本方案按用户2026年10月17日的最新要求修订旧方案：设置入口确定为“Agent设置管理 → 云端同步设置”，不再新增独立的“系统设置 → 云端协同”菜单；“已下载的本机副本”保留在业务页面，仅迁走两项许可管理和服务连接设置。旧《AI教育管家不同设备智能体调用云端文档方案》与本文冲突的页面、版本治理、分期约定以本文为准。

2026年10月18日增补：某个学生的云同步经用户明确开启后，学生基础信息默认纳入上传和后续同步。默认字段包含姓名/显示名、年级、学校、学习目标、地区、手机号、邮箱、生日、地址及监护人信息；未填写的字段不补造。健康资料作为独立高敏范围，默认关闭，仅在单独许可后同步或读取。具体联合依赖、恢复和验收按 [`AI教育管家云端模块与自动恢复联合实施矩阵-2026-10-18.md`](AI教育管家云端模块与自动恢复联合实施矩阵-2026-10-18.md) 执行。

学生基础信息“默认同步”不表示软件安装后无授权上传，也不表示默认向任何 Agent 公开。同步许可、接收主机读取和Agent读取分别授权。

必须交付的结果：

1. 学习资料模块增加“云端学习资料”，支持授权学生的云端内容浏览、下载和导入本地。
2. Agent设置管理增加第四个同级 tab“云端同步设置”。
3. 学情报告中的“云端文档”按钮及目标页面名称改为“云端学情报告”，页面只浏览报告。
4. 原“Windows主机下载许可”迁入新设置页并明确命名为“家庭/自有主机下载许可”；“本机学生上传与授权”一并迁入；“已下载的本机副本”保留在云端学情报告页面。
5. 上传范围调整为“学生基础信息 + 学情报告、学习资料、选题建议、推荐比赛、学习卡片五类资料 + 单独许可的健康资料”；基础信息在用户开启该学生云同步时默认勾选并预览，五类资料仍分别控制，健康资料默认关闭；移除选题建议页的“分享至云端其他文档”按钮。
6. 同一逻辑资料更新后，默认只显示和检索当前版本；历史按需查看。
7. 增加云端 MCP 的连接、授权范围、有效期、暂停撤销和调用记录；后续提供成果收件箱。
8. 接收 Windows 主机尚无该学生本地档案时，在学生已明确授权该主机读取基础信息与文档后，可按稳定云端学生身份自动建立本地档案并绑定 cloudStudentId；同名、冲突或已有未绑定候选时不自动合并。

## 3. 页面与导航设计

### 3.1 目标结构

```text
学情报告
└─ 云端学情报告
   ├─ 授权学生 / 当前报告 / 历史版本 / 下载与预览
   └─ 已下载的本机副本（保留，可按学生管理报告缓存）

学习资料
├─ 本地学习资料
└─ 云端学习资料
   ├─ 学习资料 / 选题建议 / 推荐比赛 / 学习卡片 / 其他文档
   ├─ 预览 / 下载 / 导入本地 / 查看版本
   └─ 已下载的本机副本（资料缓存）

Agent设置管理
├─ AI 接入与调度中心
├─ Agent 数据管理
├─ Agent连接管理
└─ 云端同步设置（新增同级 tab）
   ├─ 服务连接与同步概况
   ├─ 学生基础信息同步（开启学生云同步后默认勾选并显示字段预览）
   ├─ 授权上传范围
   ├─ Windows主机下载许可
   ├─ 本机学生上传与授权
   ├─ 外部Agent云端访问（远程MCP）
   └─ 成果回传与版本保留（按阶段启用）
```

“云端学习资料”是非报告资料的统一下载入口，五类资料在设置中仍独立授权。学生基础信息不是普通文档，显示在云端学生页头和授权预览中，以独立 `student_profile` 版本管理。选题、比赛、卡片页面可显示“已同步/待同步/失败”和跳转入口；不再维护独立上传授权表单。已有“其他文档”迁入云端学习资料的兼容分类，不因页面拆分隐藏历史文件。

| 服务地址、连接测试、云端管理页链接 | 云端同步设置顶部 | 已绑定的地址保持现有保护，换服务器须走显式迁移 |

设置页无需选择本地学生也能打开：仅使用云端下载许可的 Windows 主机可以完成配对。管理设置需相应管理权限；“查看页面”本身不授予设备或Agent新权限。来源端批准下载仍由服务器检查授权资格，上传暂停不应与能否管理既有下载许可硬绑定。获准读取基础信息的接收主机可在无本地档案时自动建档，但不能按姓名选择或覆盖已有档案。

旧 `cloud-documents` 路由保留兼容重定向：报告定位到云端学情报告，旧文档深链定位到云端学习资料，旧设置锚点跳到云端同步设置。跳转保留学生和返回页面，不复制多套表单。

## 4. 学生基础信息与五类资料上传范围

上传策略按“云端账号/组织、明确映射的学生、来源设备”保存。用户明确开启某个学生的云同步后，`student_profile` 默认勾选并进入版本化同步；这不是安装后的无授权上传。五类资料分别授权，高级范围允许指定关联项目、资料集合或单项排除；学生重名不作为映射依据。新授权对象不得因切换当前页面学生而发生变化。

| 类别 | 同步内容 | 触发时点 | 默认不包含 |
|---|---|---|---|
| 学生基础信息 `student_profile` | 稳定学生ID映射、姓名/显示名、年级、学校、学习目标、当前地区、手机号、邮箱、生日、地址、监护人信息，以及资料版本、来源设备和更新时间；只同步已填写值 | 首次开启学生云同步；批准字段发生变化 | 登录ID、设备密钥、本机路径、Agent配置、健康资料、原始对话和原始证据 |
| 学情报告 `report` | 整体画像、学习变化、每周行动、阶段总结等正式发布结果 | 正式发布/更新成功 | 占位报告、未完成草稿、原始证据目录 |
| 学习资料 `learning_material` | 选定范围内的已归档学习资料；首期支持 Markdown/PDF/DOCX | 有效资料入库或版本更新 | 整个磁盘目录、原始录音截图；不支持格式须列出原因 |
| 选题建议 `topic_suggestion` | 已保存建议、适配依据、引用和待核实项的可阅读快照 | 当前建议集保存成功 | 生成中间过程、提示词、未授权学生依据 |
| 推荐比赛 `competition_recommendation` | 当前推荐集、届次、截止日期、来源链接、适配理由及核验时间 | 推荐集更新成功 | 自动报名、购买行为；过期推荐不得包装成当前有效比赛 |
| 学习卡片 `learning_card` | 已发布卡片题目、学习目标、资源引用、版本及显示规则 | 发布或修订成功 | 默认不含学生作答、录音、评分、掌握结论；答案随独立范围与展示规则控制 |
| 健康资料 `health_record` | 用户单独选择的健康档案、检查资料或健康教育记录；保留来源、版本和范围 | 独立许可启用后，指定资料入库或修订成功 | 默认全部不上传；不含未选择资料或其他学生资料，也不随普通文档许可自动纳入 |

类别决定业务语义，MIME 类型决定文件处理方式，两者不能互相替代。结构化选题、比赛、卡片保存版本化 JSON 数据及可阅读 Markdown 投影；普通下载可先取投影，原生模块导入需检查结构版本。附件必须逐个纳入分享范围，不能通过链接自动带出未授权文件。

首次开启学生云同步时，设置页先显示基础信息字段预览；`student_profile` 默认勾选，姓名/显示名、年级、学校、目标、地区、手机号、邮箱、生日、地址和监护人信息均在默认范围内，未填写字段不上传且不得推测补全。用户仍可在确认前取消具体字段；姓名或显示名至少保留一个可识别值，云端以稳定ID判定身份。首次启用资料类别时，设置页显示预计同步数量、大小和实际包含内容。推荐“当前有效内容 + 后续更新”，不默认补传所有历史。保存范围后按策略同步，无需每篇重复确认。健康资料始终单独许可且默认关闭；学习资料如选择原件同步，必须明确包含原件；仅摘要模式须在下载列表标明。

升级时保留现有报告开关和已上传副本；新增四类资料默认关闭。已有用户的 `student_profile` 在新版授权页默认勾选，但首次实际上传前必须展示新增字段范围并完成一次明确确认，不能后台静默补传。历史上手动分享过选题，不推定用户已授权持续自动上传。规划建议（guidance）不自动并入这次五类范围：其既有分享功能先保留，未来如合并须单列类别；不能因移除共用组件而误删该入口。

同步采用持久队列：发布/入库事件入队、短时合并重复变化、受限并发、指数退避、启动时补偿核对；不每次打开页面扫描整库。按“范围+源对象+源修订+投影版本”去重，先查回执再重试结果未知的上传。策略变更后，待上传任务及正在提交的任务重新校验当前授权。

设置文案明确区分：

- 暂停自动同步：停止后续上传，已上传资料继续按既有许可提供读取。
- 移出分享范围/撤回云端副本：阻止对应云端内容后续读取；本地原件仍保留。
- 撤销下载对象或 Agent：仅取消该对象后续读取，其他对象不受影响。
- 清除本机副本：只清理选定缓存；已正式导入本地的资料需在本地资料管理中另行处理。

## 5. 云端学习资料下载与本地使用

列表显示：授权学生、类别、名称、来源设备、内容更新时间、版本、大小、同步状态；提供类别/学科/项目筛选和分页。只读内容预览与下载不要求建立同名本地学生档案。

“下载”将指定修订保存到带学生和版本隔离的只读缓存，核对内容哈希后才标记完成。“导入本地”使用稳定云端学生绑定进入现有收件箱或资料入库流程，保留云端资料ID、来源、版本及哈希。接收主机没有该学生本地档案且下载许可包含 `student_profile.read` 时，按5.1自动建档；有同名或绑定冲突时待选择，不按姓名自动合并或覆盖本地资料。

重复下载命中同一缓存；重复导入返回原入库记录。云端出现新版本时显示“有更新”，下载新缓存；若本地已经编辑，展示云端与本地差异并按新来源版本导入，不覆盖本地修改。选题、比赛、卡片首期可作为资料导入；原生结构化导入在对应版本校验器完成后开放，不能把“文件下载”宣称为“业务对象已导入”。

报告缓存和资料缓存共用底层存储账本，但清理接口增加类别过滤。现有按学生整包清理接口须保留兼容，并把清理范围告知用户；新页面调用不能误删另一类别缓存。旧缓存迁移保留哈希、学生及修订，已下载副本不会被静默重新上传形成循环。

### 5.1 接收主机无本地档案时自动建档

可以自动建档，但前提是学生或有权管理该学生的用户已经明确授权该 Windows 主机读取 `student_profile` 和对应文档。配对成功本身只建立主机身份；服务端返回带 cloudStudentId、profileRevisionId、字段范围和签发来源的基础信息后，主机按以下顺序处理：

1. 已存在同一 cloudStudentId 的绑定时，复用该档案，不重复创建。
2. 不存在绑定，且本机没有可能冲突的未绑定同名档案时，自动创建“云端授权建立”的最小本地学生档案，生成本地 studentId，并保存 cloudStudentId、来源账号、profileRevisionId、授权ID及建档时间。
3. 存在一个或多个同名/相似候选、旧迁移记录或身份字段冲突时，暂停自动合并，只要求用户选择“绑定已有档案”或“另建档案”；不得凭姓名、手机号或学校自行覆盖。
4. 建档后才能创建标准学生工作区并导入获准文档。没有单独的 `health_record.read` 时，不下载健康资料，也不因健康资料缺失阻止基础档案建立。
5. 后续基础信息修订仅自动更新自上次云同步后未被本机修改的字段；本机和云端都修改过的字段保留两版并请求一次合并选择。撤销下载许可不会静默删除已建立的本地档案或正式导入资料，而是将云端绑定标为已断开，并提供明确清理入口。

自动建档不是按姓名复制一份目录，也不把只读缓存当作正式知识库。整个过程必须使用稳定幂等业务键，程序重启或重复领取同一授权不得创建第二个学生。

## 6. 版本治理：更新当前内容，历史按需查看

### 6.1 逻辑身份

建立稳定的 `materialId`（逻辑资料）和不可变的 `revisionId`（一次内容修订）。文件名、上传日期和内容哈希都不是逻辑资料的唯一身份。同名不同内容可以是新版，也可以是不同资料。

推荐系列身份：所属账号/组织 + 学生 + 业务类别 + 来源命名空间 + 稳定源对象ID。学生基础信息使用稳定 `studentProfileId` 和不可变 `profileRevisionId`；固定整体画像使用固定报告对象ID；学习资料使用已有资料记录ID；推荐集和选题集使用稳定集合ID；单张卡片使用 cardId。

同一学生有多个来源设备时，默认保留各来源系列。用户可指定主要来源供默认 Agent 查询，未经指定不能按“谁最后上传”覆盖另一设备。设备更换需要转移已有来源身份，而非凭同名合并。

持续更新的整体画像使用一个当前指针；周报、阶段报告如有明确期间，则每个期间为独立业务记录，期间内修订替代旧版。默认概览可只展示最近期间，历史对比按期间查询，避免把成长历史误认为重复文件。

### 6.2 上传与并发

1. 相同源修订/投影及哈希重复提交，返回同一回执，不新增版本。
2. 新内容校验成功后保存不可变修订，并在事务中切换 `currentRevisionId`；失败时旧当前版仍可用。
3. 使用源端递增修订号和 `expectedCurrentRevisionId` 比较更新；冲突返回可恢复状态。不能仅依赖日期：同一天可多次修改，设备时钟也可能偏差。
4. 迟到的旧修订不覆盖新当前版；冲突版本需核对来源序列或用户选择。整组报告/卡片发布保留集合修订和完成标记，不展示半组新旧混合结果。
5. 重命名保持 materialId；“另存为新资料”生成新ID。人工上传同名文件时提供“更新该资料/另存为新资料”，普通首次上传仍可直接完成。
6. 撤回当前版后不自动恢复旧版；用户明确选择恢复时创建一次可审计的新发布。重试不得复活被撤回内容。

### 6.3 默认查询与保留

业务浏览和 MCP 默认 `versionScope=current`，同一系列只返回一版；历史入口按需分页，精确引用固定 revisionId。搜索索引按当前指针发布；新文本尚未提取时返回“当前版索引处理中”，不能把旧版命中伪装成最新结果。索引命中在返回前再次检查权限、当前版本与撤回状态。

建议提供“仅当前版/当前版+最近若干版/按时间保留”策略，但上线默认不自动物理清理历史。先完成版本收拢以减少列表及模型上下文消耗，再根据容量设置启用清理。普通“曾下载”不自动形成永久保留锁；需长期追溯的关键引用可显式固定版本并计入配额。

历史对象回收必须检查所有引用、保留锁、处理中任务及内容寻址对象的共享关系。撤回、回收站、物理回收和备份保留分别计量；保留元数据墓碑，已清理版本返回“历史正文已清理”。已发送给 Agent 的内容不可能靠当前版本切换从对方上下文中移除。

## 7. 上传、下载与 Agent 授权

把三种主体分开管理：来源设备可上传；接收 Windows 主机可下载并在授权后自动建档；外部 Agent 可读取或提交成果。每种主体有自己的身份、许可、有效期和撤销记录。

有效权限为账号归属、学生范围、基础信息字段、资料类别、对象/修订范围、动作、接收主机、连接状态和有效期的交集。`report.write`、`cloud_document.read` 是旧合同，学生基础信息、新增五类资料和健康资料不能直接借这两个宽权限全部放行。增加类别/字段约束或新权限模型，并在列表、正文、附件、搜索、历史读取、自动建档和导入拉取中统一执行。

旧许可迁移成“原有报告及旧其他文档”的显式兼容范围；新增类别不自动扩权。未知类别或未来类别默认拒绝。来源设备被撤销后不能通过本机开关恢复；管理员根据学生归属建立/撤销许可，管理界面按钮本身不能绕过服务端校验。

单管理员试点扩展到 OAuth 前，必须补充明确的账号/组织拥有者与学生归属，即使首期只有单租户也要固定租户边界。读取权限不意味着可授予别人权限；邀请与批准资格单独校验。

### 7.1 学生基础信息权限

建议使用独立的 `student_profile.write` 与 `student_profile.read`，或在新 `/v2` 权限模型中表达等价的字段级动作。来源端获得基础信息同步权，不代表接收主机或Agent获得读取权。默认基础信息包含已填写的手机号、邮箱、生日、地址和监护人信息；用户在首次上传预览中仍可取消具体字段。健康资料使用独立的 `health_record.write` / `health_record.read`，默认关闭，不能由 `student_profile.read` 或 `cloud_document.read` 推导。

## 8. 远程 MCP 与设置内容

### 8.1 首期读取已分享云端副本

```text
不同设备上的 Agent → HTTPS远程MCP/REST → 用户与连接授权 → 云端当前版本资料
Windows/Android来源端 → 已授权同步队列 → 同一云端资料服务
```

建议端点为 `https://www.greatbg.com/edu-cloud/mcp`（拟新增，尚未部署声明）。页面地址不等于 MCP 端点。现有反向代理需要正确转发 MCP 请求、协议头及响应，OAuth 资源发现必须按规范处理根路径下的 well-known 路由，不能假定全部发现地址都在 `/edu-cloud/` 内。

采用 Streamable HTTP；OAuth 授权码加 PKCE、资源发现、签发者/受众/有效期校验。授权服务器与资料服务分工清晰，不透传外部令牌作为内部管理员身份。每个连接有独立 connectionId 和令牌；clientId 表示 OAuth 客户端，可被多个合法连接共用，不强求每台设备都成为新客户端。[MCP授权规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization)、[传输规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)。协议版本以实现和真实宿主兼容矩阵确定，不将此参考版本宣称为最新版本。

“外部Agent云端访问”区包含：总开关、添加连接、连接名称/提供商、授权学生、学生基础信息字段、五类资料范围、独立健康资料范围、只读/成果提交、历史与搜索范围、有效期、最近调用、连接测试、暂停、撤销、调用记录及用量。正文进入所选 Agent 提供商处理环境的提示放在连接授权时；普通设置不显示令牌、私钥和技术配置文件。

新增 Agent 默认先只读；云端收件箱上线后才可单独开启成果提交。上传授权不自动给 Agent 读取权；全局开关不等于所有未来 Agent 已获许可。权限变化对新请求立即生效，大文件提交/下载关键阶段重新校验；缓存不得延长已撤销授权。

拟提供工具名使用宿主兼容的下划线格式，旧方案点号命名作为语义名称映射：

| 工具 | 用途 | 阶段 |
|---|---|---|
| `cloud_connection_get_scope` | 返回该连接实际可用范围 | 只读接入 |
| `cloud_student_profile_read` | 按该连接获准字段读取指定学生当前基础信息 | 只读接入 |
| `cloud_material_list` / `cloud_material_read` | 分类别列当前资料、按指定修订分段读正文 | 只读接入 |
| `cloud_report_list` / `cloud_report_read` | 报告专用筛选与读取，共用资料底层 | 只读接入 |
| `cloud_material_search` | 授权范围内关键词检索，默认当前版 | 检索阶段 |
| `cloud_inbox_submit` / `cloud_inbox_status` | 提交成果、查看自己提交项的处理回执 | 回传阶段 |

结果保留学生、项目、类别、materialId、revisionId、内容哈希、来源设备、内容时间、上传时间、当前状态和 `source=cloud_copy`。Markdown 分段，PDF/DOCX 提供经授权的下载或派生文本；下载不能使用长期公开URL。文件下载时仍校验权限，短期 bearer URL本身不能称为“不可转让”。

只支持 stdio 的宿主可增加轻量云代理，或用同权 REST/OpenAPI 适配。安装路径兼容与实际工具调用分开验收；本地主机离线不影响读取已同步副本。

### 8.2 实时本地主机能力的边界

现有本地连接器继续管理本地资料。云端 MCP 首期不转发至 Windows。未来确需实时查询未上传资料时，可另建 Windows 主动出站中继，并单列“在线本地主机访问”授权；默认关闭，显示主机在线状态，离线不伪装成实时查询，也不自动开放本地全部能力。本次设置页不放可点击但尚不可用的实时访问开关。

## 9. 云端成果收件箱

预期流程为“Agent主动提交 → 云端暂存 → 指定教育管家主机主动拉取 → 本地收件箱 → 分类、消化、归档”。云端不会自动抓取第三方历史对话；如未来接平台导出API，应独立授权和适配。

提交合同至少包含 submissionId、connectionId、学生/项目、成果类型、正文及附件、来源引用、基于哪些云端修订、幂等键和内容哈希。同一幂等键不同内容拒绝；相同内容也要结合目标和来源去重，不能跨学生合并。成果保留“Agent生成/待核实”属性，不直接变为已确认成长证据。

每项指定一个负责入库的目标主机，其他主机不能同时消费为重复正式记录。领取采用可过期租约；本地持久落盘并校验后确认接收，网络重试用 submissionId 查本地账本。租约过期后可以重领，保证至少一次传输和幂等入库。

回执分开记录：云端已接收、等待主机、已下载、已登记本地收件箱、处理中、处理成功、失败可重试、归属待确认、已拒绝。下载成功不代表消化成功。明确目标且已有自动入库授权时复用既有自动流程；目标有歧义时才要求选择，避免逐项重复审批。

收件箱内容默认不加入云端共享资料列表或 Agent 检索索引。正式入库后如再发布，按该类上传策略生成独立来源链，防止“拉取→上传→再次拉取”的回流。成功落盘回执和保留期满足后才允许清理云端传输副本；失败和未领取项有配额、到期提醒与重试入口。

### 10.2 数据与接口

新增 `/v2` 合同承接：学生基础信息字段策略与修订、健康资料独立许可、五类资料策略、资料列表、修订上传与条件发布、精确版本读取、接收主机学生绑定与建档回执、变化游标、下载与导入回执、收件箱提交及领取。稳定分页游标与变化游标分离；变化流包含当前指针切换和撤回墓碑。五类资料共用合同，报告专用接口只作视图。

现有 `/v1` 的路径、响应和分页语义保持兼容：目前报告按接收时间正序增量读取，不能直接改为“只返回最新版”导致旧同步端漏事件。新浏览页面和 MCP 使用 `/v2` 当前视图；旧端继续读取原合同，并明确旧端可能仍展示历史。拟废弃接口待各端升级后再处理。

### 10.3 迁移顺序

1. 备份数据库、对象索引和设置，生成迁移预览；不触碰已有本地正式资料。
2. 加新表及字段，建立学生资料、旧报告revisionId/文档documentId到逻辑资料的映射，原ID读取继续有效。
3. 固定报告按学生、来源和类型分组；周期性报告须识别期间。旧文档缺少稳定源ID时，不仅按同名自动归并；生成候选分组供核对。
4. 保留全部正文和原始时间。当前版候选优先可靠源序列，其次核对业务时间；同日不同内容、跨来源和时钟异常标记冲突，不依上传先后静默决定。
5. 原报告上传开关、地址、凭据、配对和缓存保持原值；旧下载许可继续限定原有内容；新增四类教育资料和健康资料默认关闭。
6. 已有用户的学生基础信息在新版范围页默认勾选，手机号、邮箱、生日、地址和监护人信息也进入默认字段预览，但首次实际上传前必须明确确认，未填写值不补造。
7. 先启用服务端兼容层，再灰度Windows新界面、学生绑定/自动建档和同步，最后扩展Android及其他宿主。
8. 回滚用功能开关停新发布，保留新数据和回执，通过兼容读路径回退；不恢复旧备份覆盖已新增数据，不复活已撤销许可。部署回滚需包含 schema 兼容检查和恢复演练。

## 13. 开发依据与评审默认项

现有文件入口（相对仓库根目录）：

- `src/main.tsx`：AgentSettingsTab、学习资料页面、云端文档入口与设置tab。
- `src/CloudDocumentsPanel.tsx`：当前报告/其他文档、两项许可和已下载缓存。
- `src/PlanningResearchPanels.tsx`、`src/TopicSuggestionsPanel.tsx`：选题/规划分享及推荐比赛视图。

- `cloud-report-service/service.cjs`：报告与文档表、哈希去重、许可、列表、撤回、配对及审计。
- `cloud-report-service/http.cjs`：`/v1` 列表、上传、下载及管理路由。
- `docs/delivery/AI教育管家不同设备智能体调用云端文档方案-2026-10-15.md`：既有云端Agent方案，入口与范围以本文修订为准。

本稿采用的可评审默认项：用户明确开启学生云同步后，基础信息默认勾选并先预览，已填写的手机号、邮箱、生日、地址和监护人信息进入默认范围，本机技术信息不上传；健康资料默认关闭并单独许可；新增四类教育资料默认关闭；首次启用资料同步当前有效内容及后续更新；首期学习资料格式复用Markdown/PDF/DOCX；默认展示当前版本，历史先保留不自动删除；无本地档案的授权接收主机按cloudStudentId幂等建档，同名/冲突不自动合并；远程Agent先只读，成果提交单独授权；账号/学生归属先于OAuth上线；原生业务对象导入晚于文件下载。开发可据此展开，若要扩大格式、自动清理历史或新增实时主机能力，应在对应阶段明确修改范围。
