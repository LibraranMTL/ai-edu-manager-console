# 教师学生双主机知识协作与分发后续开发计划 v2

> 决策日期：2026-07-25  
> 当前基线：Windows 主机版 0.10.10  
> 核心决策：教育管家内置直传为默认方案；局域网优先，Tailscale 作为跨网络通道；Syncthing 降级为可选高级兼容方案。

## 一、调整结论

后续开发不再要求普通用户安装、配对或配置 Syncthing，也不再把“等待 Syncthing 同步完成”作为任务、附件、成果或反馈到达的必要条件。

新的默认链路为：

```text
教师或学生发起业务操作
→ 教育管家生成标准协作包
→ 本机持久发送队列
→ 优先通过局域网连接对方教育管家
→ 局域网不可达时尝试已配置的 Tailscale 地址
→ 对方临时目录分块接收
→ 完整性、学生归属和项目归属校验
→ 原子导入本机资料库或协作收件箱
→ 自动写回接收与业务处理回执
```

Tailscale 只提供跨网络可达，不承担文件同步、业务状态和数据归属判断。Syncthing 只保留给已经部署的高级用户、超大规模历史目录迁移和应急兼容，不属于默认安装依赖、首次使用步骤或普通验收路径。

## 二、调整目标

1. 普通用户完成一次主机连接后，可以直接向指定教师或学生发送任务、附件、成果、反馈、项目资料和知识快照。
2. 正常往返不增加人工审核、复制指令、检查交换目录或刷新 Syncthing 的步骤。
3. 对方离线时自动排队；重新上线后自动补发，不要求用户重复布置任务。
4. 只传输业务选中的资料，不持续镜像整个学生资料根目录。
5. 不同步本机索引、运行锁、令牌、Agent 缓存和绝对路径配置。
6. 接收端依据标准清单在本机创建项目结构、导入资料并增量重建索引。
7. 传输逻辑不进入 UI 主线程，空闲时不扫描完整资料库，不显著增加主机负荷。
8. 保留 0.10.10 已有协作关系、任务、附件、事件、反馈和成果记录。
9. Windows/Android 学生终端既有直传接口保持兼容，不为本次双主机升级重复建设另一套协议。

### 产品定位：AI 时代的知识协作与技能发展

教育管家不再以“教师管理学生”作为主要叙事，而是帮助学生、教师和家长围绕真实学习过程形成四个长期闭环：

1. **知识积累**：把多渠道资料、学习过程和可靠来源沉淀为可追溯知识资产；
2. **知识生产**：围绕问题、研究、讨论和作品形成新的总结、解释、方案和知识贡献；
3. **项目协作**：支持学生与教师、学生与学生之间定向发布项目、交换成果、反馈和版本；
4. **技能发展**：依据长期项目过程、作品和知识贡献更新成长模型、学情报告和教育档案。

AI 负责资料整理、知识关联、来源校验、任务路由、变化摘要和成长证据归集；普通用户主要围绕资料、项目、作品、反馈和报告操作，不直接处理协议、索引、哈希或审核工作台。

## 三、范围与边界

### 1. 默认直传范围

- 教师布置的学习任务和任务附件；
- 学生提交说明、成果文件和再次提交内容；
- 教师反馈、确认完成和协作消息；
- 教师分发的课程资料；
- 学生请求教师协助时选择的资料；
- 学习项目定义、指定项目资料和已确认知识快照；
- 学生主机执行 Agent 后形成的必要结果；
- 双方明确选择保存的对话、附件和知识贡献；
- 聚合资料统计和变化摘要。

### 2. 不直接跨主机同步

- 本机任务账本数据库；
- 教育管家本机索引数据库；
- Agent 运行中状态、缓存和锁文件；
- 设备令牌、连接密钥和本机配置；
- Electron 用户数据目录；
- 正在写入的 Agent 回执和临时消化批次；
- 某台电脑的绝对路径映射；
- 未经业务操作选中的完整学生资料根目录。

### 3. 暂不建设

- 云端中转服务器；
- 公网匿名访问；
- 远程桌面；
- 完整通用文件同步产品；
- 自动同步全部 Agent 对话；
- GBrain 默认接入；
- 向普通用户暴露哈希、端口、协议包、索引或审计工作台。

## 四、目标架构

```text
教育产品层
学生、学习项目、资料、知识、成长模型、学情报告
                    ↓
协作业务层
任务、附件、成果、反馈、项目分发、协助请求
                    ↓
协作协议层
Envelope、Manifest、Receipt、幂等、归属校验、隔离
                    ↓
传输协调层
持久队列、路由选择、分块、断点续传、重试、限流
            ↙                         ↘
局域网直连（默认）              Tailscale 地址（回退）
                    ↓
可选高级兼容层
Syncthing 交换目录导入，不参与默认业务状态
```

传输层必须通过统一接口接入：

```text
sendPackage()
resumePackage()
cancelPackage()
receivePackage()
acknowledgePackage()
getTransferStatus()
```

任务中心、项目模块和资料库不能直接依赖 Syncthing 路径。这样才能在不修改上层教育业务的情况下切换局域网、Tailscale 或兼容导入。

## 五、内置直传协议

### 1. 连接与路由

每个已建立的双主机协作关系保存：

- 固定节点 ID；
- 对端教育管家版本和协议版本；
- 最近有效局域网地址；
- 可选 Tailscale 地址；
- 最近连接成功时间；
- 当前可达状态；
- 传输能力声明。

路由顺序固定为：

```text
最近有效局域网地址
→ 重新扫描局域网
→ 已保存的 Tailscale 地址
→ 进入离线队列
```

不得同时通过两个通道重复发送同一协作包。IP 地址变化不能生成新的协作身份。

### 2. 协作包

每个协作包至少包含：

- `packageId`；
- `protocolVersion`；
- `sourceNodeId` 和 `targetNodeId`；
- `studentId` 双端映射；
- 可选 `projectId` 双端映射；
- 业务类型和业务对象 ID；
- 文件相对路径、大小、MIME 和 SHA-256；
- 创建时间、失效时间和重试次数；
- 完成标记；
- 上一事件 ID 或任务版本。

不得只靠文件名、绝对路径或学生姓名确定资料身份。

### 3. 分块和断点续传

- 传输前发送清单，对方返回已拥有的文件和分块；
- 文件写入 `.partial` 临时位置；
- 默认单通道传输，必要时最多两个并发文件；
- 每块独立编号，完整文件完成后校验 SHA-256；
- 校验通过后原子改名并进入导入流程；
- 中断后从已确认分块续传，不重新发送完整文件；
- 重复收到同一包只返回既有回执，不重复导入。

首个版本优先保证常见图片、PDF、Office、Markdown 和 ZIP 文件；单文件限额沿用当前终端上传策略，后续通过性能验收再扩大。

### 4. 离线队列

发送状态统一为：

```text
等待发送
→ 正在连接
→ 正在传输
→ 正在校验
→ 已送达
→ 已导入 / 已拒绝 / 已隔离
```

对方离线时：

- 业务操作立即写入本机持久队列；
- 页面显示“等待对方上线”，不显示失败；
- 使用退避重试，不进行高频轮询；
- 程序重新启动后继续队列；
- 用户可以暂停或取消尚未送达的项目；
- 已送达或已采用的资料不能通过取消操作远程删除。

### 5. 接收和导入

接收端依次执行：

```text
验证协作关系和目标节点
→ 验证学生及项目映射
→ 验证协议版本和包清单
→ 流式写入临时文件
→ 校验大小和 SHA-256
→ 检查重复、越界和路径穿越
→ 原子移入受控收件箱
→ 按业务规则导入本机资料库
→ 增量更新本机索引
→ 返回处理回执
```

异常包进入隔离区，不阻塞同一队列中的其他正常任务。

## 六、项目和知识分发

### 1. “同步整个项目”的产品含义

“同步整个项目”默认表示项目权威端将一个可运行、可继续学习的项目版本定向发布给指定教师或学生，不表示两台电脑对同一目录进行任意双向镜像。

项目发布能力不绑定永久身份：

- 教师创建的项目可以发布给一名或多名学生；
- 学生创建的项目可以发布给教师，请求指导或展示成果；
- 学生创建的项目可以发布给其他指定学生，形成各自的本地项目副本；
- 教师之间也可以交换课程项目模板；
- 发布目标必须来自已经建立的主机协作关系和明确的本地学生映射。

完整项目版本可以包括：

- 项目稳定 ID、名称、说明和阶段；
- 教师选定的现有项目工作空间；
- 项目原始资料库；
- 已确认知识快照；
- 项目目录模板和必要配置；
- 文件清单和来源关系。

以下内容始终不随“整个项目”发布：

- 教师主机本地任务账本和运行索引；
- Agent 缓存、锁、临时批次和正在写入的回执；
- 设备令牌和连接信息；
- 教师电脑绝对路径；
- `.git`、`node_modules`、构建产物、缓存和其他可重建大目录，除非高级设置明确纳入；
- 被标记为“仅教师本机”的资料。

项目发布采用三条职责通道：

| 通道 | 权威端 | 默认方向 | 内容 |
| --- | --- | --- | --- |
| 项目发布 | 项目创建方 | 创建方 → 指定教师或学生 | 项目模板、项目资料、参考资料、已确认知识 |
| 成果与反馈 | 成果产生方 | 接收方 → 发布方 | 作业、作品、过程记录、指导反馈和提交说明 |
| 知识贡献 | 贡献产生端 | 提议后导入 | 新知识、来源引用和修改建议 |

接收方修改自己的成果不会反向覆盖发布方原项目；发布方更新项目也不会覆盖接收方已经形成的成果。首期不建设同一文件的实时多人编辑。

### 2. 教师选用现存工作空间

教师创建项目并选择已有目录时，教育管家先建立只读基线：

```text
扫描项目逻辑区域
→ 识别文件、相对路径、大小、修改时间和 SHA-256
→ 识别可重建目录和本机运行状态
→ 识别已有 Syncthing 或其他外部同步范围
→ 生成 ProjectSyncProfile 和首版 ProjectManifest
→ 不移动、不重命名、不删除原目录
```

`ProjectSyncProfile` 至少记录：

- 项目稳定 ID；
- 教师端和学生端节点；
- 教师工作空间逻辑根；
- 学生端目标逻辑根；
- 同步范围；
- 每个范围的传输责任；
- 文件权威端；
- 当前基线版本；
- 忽略规则版本。

物理绝对路径只保存在各自主机的 `pathmap` 中，不进入跨主机项目身份。

### 3. 已由 Syncthing 同步的目录

同一个物理目录范围只能有一个传输责任方。不得让教育管家内置直传和 Syncthing 同时主动写入同一相对路径。

对已经由 Syncthing 同步的项目或子目录，系统提供两种处理方式：

#### 保持现有同步

- 将该目录登记为 `syncthing_compat` 范围；
- 教育管家只扫描、建立清单、校验归属和更新业务回执；
- 内置直传自动排除该范围；
- 其他尚未同步的项目目录仍可使用教育管家直传；
- 父目录使用直传时，必须排除由 Syncthing 管理的嵌套子目录。

这是检测到现有 Syncthing 目录时的推荐默认值。

#### 迁移到教育管家直传

- 先扫描双方现有目录并建立共同基线；
- 相同 SHA-256 文件登记为“已存在”，不重复传输；
- 只发送缺失文件和明确的新版本；
- 存在同路径不同内容时保留双方版本，不自动覆盖；
- 确认旧 Syncthing 范围不再写入后，才将传输责任切换为 `direct`；
- 切换失败时恢复旧责任标记，不删除双方文件。

不能以“教育管家发送成功”代替停止旧同步范围；切换必须保证任一时刻只有一个传输机制负责该路径。

### 4. 学生端接收机制

学生主机收到项目邀请后，默认使用教育管家管理的学生项目目录，不要求学生逐个创建文件夹。

接收流程：

1. 在本机创建或匹配学习项目；
2. 如果已有同一项目或用户指定的现存目录，先只读扫描；
3. 将接收端文件清单返回教师主机；
4. 按“相对路径 + SHA-256 + 对象 ID”计算差异；
5. 已存在的相同文件直接登记，不重复传输；
6. 缺失文件进入直传队列；
7. 同路径不同内容进入版本冲突区，不覆盖学生文件；
8. 使用学生端本机资料根目录生成 `pathmap`；
9. 原子导入资料和知识内容；
10. 在学生端增量重建资产索引、知识索引和项目状态；
11. 返回项目接收回执。

教师端索引、任务账本和绝对路径不进入分发包。

学生端只有在以下情况才需要一次选择：

- 同一项目存在多个候选目录，系统无法唯一匹配；
- 目标位置存在同名但不同身份的项目；
- 用户选择把默认管理目录改为已有目录。

其余情况由系统创建目标和完成接收，不要求学生审核逐个文件。

### 5. 首次发布和用户操作

教师点击“同步整个项目”后，系统后台扫描并只显示一张摘要：

- 将发布的文件数和总大小；
- 已由 Syncthing 或其他机制覆盖的范围；
- 学生端已经存在、无需重复发送的数量；
- 被自动排除的缓存、运行状态和本机文件数量；
- 预计使用局域网或 Tailscale。

普通用户只需一次“发布项目”确认。具体文件清单、哈希、传输范围和冲突详情继续放在高级诊断中。

### 6. 后续增量

项目更新只发送新增或发生实质变化的业务对象。相同 SHA-256 文件不重复传输；相同对象的新版本保留版本关系，不覆盖另一主机的权威版本。

增量更新由项目清单版本触发，不依赖每次全量扫描：

- 教育管家内发生的资料导入、知识更新和项目阶段变化直接标记项目为待发布；
- 外部工作空间使用范围受控的文件监听、去抖和低频兜底；
- 只重新计算发生变化的文件；
- 删除默认形成“来源端已移除”标记，不直接删除对方物理文件；
- 学生端离线时保留版本化差异包，上线后按顺序补发；
- 多次更新可合并为最新清单，但不得丢失已经提交的学生成果。

### 7. 大规模资料

- 按学生和项目分队列，不全量扫描全部学生；
- 批量操作先生成清单，再在后台逐包发送；
- 界面显示总体数量和失败摘要，不逐文件高频刷新；
- 默认优先在资料权威主机执行 Agent，只回传结果或知识快照；
- 完整资料库迁移继续使用独立备份/恢复工具，不能把直传当作唯一备份。

### 8. 学生创建项目后的定向发布

学生在完整 Windows 客户端中创建项目后，项目详情提供统一“发布项目”入口。发布时只需要：

1. 选择一个或多个已经连接的教师或学生；
2. 使用默认“可学习项目版本”，或在高级选项中调整发布范围；
3. 确认一次发布。

系统为每次发布建立：

- `projectLineageId`：项目来源谱系；
- `publicationId`：本次发布版本；
- `sourceProjectId`：发布方本地项目；
- `targetProjectId`：接收方本地项目；
- `publisherNodeId` 和可选 `publisherStudentId`；
- `targetNodeId` 和明确 `targetStudentId`；
- 发布范围、基线版本和后续更新策略。

接收方获得自己的本地项目 ID 和物理目录，同时保留来源谱系。这样可以做到：

- 后续识别同一来源项目的新版本；
- 不把不同学生的副本误认为同一个可写目录；
- 学生 A 的本地修改不覆盖学生 B；
- 教师反馈能够准确回到发起项目的学生；
- 接收方再次发布时保留原始来源和派生关系。

发布模式分为：

| 模式 | 默认行为 |
| --- | --- |
| 一次性快照 | 默认；接收方获得独立副本，不自动跟随更新 |
| 跟随发布方更新 | 只接收发布方后续确认发布的增量，不回写同一文件 |
| 协作贡献 | 接收方将成果或知识贡献作为独立包回传，由发布方按来源导入 |

普通用户默认使用“一次性快照”。只有明确开启“跟随更新”时才建立持续的增量关系。

### 9. 项目发布主体边界

项目创建、项目权威、定向发布和版本协作只属于完整知识节点。当前 Windows/Android 轻量学生终端不保存完整项目索引和知识引擎，因此：

- 可以把资料上传到主机已经创建并绑定的项目；
- 不提供 `CreateProjectRequest`、项目中心或项目发布入口；
- 不接收需要本地建库的完整项目包；
- 不承担项目直传队列或其他节点的项目权威；
- 学生有上述需求时，使用完整 Windows 客户端；未来可使用单独立项的 Android 知识节点。

## 七、客户端分层与系统设置模块

下一阶段必须把现有“系统设置”页面拆成三个子菜单。此次调整只重新组织入口，不新增普通用户必填项，不改变已有配置值。

### 1. 基础设置

归入：

- 使用模式；
- 学生资料根目录和本机存储位置；
- 默认 Agent 和自动处理总开关；
- 外观、启动和版本信息；
- 备份、恢复和更新；
- 高级诊断入口。

普通用户默认只看到常用设置，高级诊断继续折叠。

### 2. 主机连接

归入：

- 启动或停止主机服务；
- 固定机器码和连接信息；
- 局域网地址、扫描和连接诊断；
- Tailscale 安装检测、打开、下载和地址状态；
- Windows/Android 学生终端授权设备；
- 个人终端、共享终端模式；
- 已连接终端的重命名、撤销和恢复。

这里处理“学生终端怎样连接本机”，不展示双主机教学任务。

### 3. 知识协作

归入：

- 教师主机与学生资料权威主机的协作邀请；
- 对端节点、学生映射和协作状态；
- 跨主机任务、附件、成果和反馈；
- 发送队列、接收记录和失败重试；
- 项目分发和知识快照；
- 团队知识查询范围：允许本机团队查询、允许远程协作团队查询；
- 暂停、恢复和撤销协作；
- Syncthing 高级兼容入口。

完整 Windows 知识节点提供两个一次性开关：“允许本机团队知识查询”和“允许远程协作团队知识查询”。开关约束教育管家问答、本机 HTTP 接口以及 QClaw、Codex 等 Agent 原生工具，不能只控制界面显示。Windows/Android 轻量学生终端不继承团队查询能力，始终只读当前登录学生及其有效关联项目。

Syncthing 入口默认折叠，并明确标注“可选高级兼容”；未安装 Syncthing 不得显示错误，也不得阻止内置直传。

### 4. 页面迁移要求

- 使用原配置键和既有状态源，避免升级后设置丢失；
- 首页不再承载完整设置表单，只保留必要状态和进入设置的入口；
- 三个子菜单有独立路由或稳定锚点，刷新后保持当前位置；
- 同一设置只能有一个主要入口，避免重复卡片；
- 移动设置后更新 Windows 主机端、Windows 学生终端、Android 手册和网站说明；
- 增加 UI 合同测试，防止设置又堆回一个超长页面。

### 5. 完整 Windows 客户端的角色呈现

完整 Windows 客户端不设置永久“教师机”或“学生机”身份。节点身份保持中性，界面角色由三层信息自动计算：

1. **协作关系角色**：当前节点在具体协作中是教师协助端还是学生资料权威端；
2. **对象权威关系**：当前项目、资料或成果由哪个节点和学生拥有。

完整 Windows 客户端不增加“我的团队 / 我的学习”工作台切换。日常资料、项目、成长模型和报告继续使用现有主导航；跨主机关系、任务交换和恢复统一进入“系统设置 → 知识协作”。角色通过邀请和项目来源自动建立，普通用户不需要配置角色、权限表或策略文件。

### 6. Windows/Android 轻量学生终端边界

现有 Windows 和 Android 学生终端保持极简定位，不加入任务中心、项目创建、项目发布、本地知识库或 Agent。两端继续作为知识节点的采集与查阅入口。

保留能力：

- 个人 ID 或共享终端登录；
- 上传普通文件到学生原始资料库或主机已经绑定的项目原始资料库；
- 屏幕截图、录屏和移动采集资料上传；
- 个人终端自动投递文件夹；
- 查看本人提交数量、知识化进展和简要提醒；
- 查看本人学情报告和教育档案；
- 显示上传中、成功、失败和待重试反馈；
- 断线期间保留尚未成功上传的本地文件，恢复连接后重试。

明确不加入：

- 完整任务中心和跨主机协作收件箱；
- 新建、维护或发布学习项目；
- 本地项目索引、知识索引和知识治理；
- Agent 资料消化和本地知识问答；
- 成长模型、报告生成和档案发布；
- 跨主机直传队列、Syncthing 或协议配置；
- 多学生管理和高级诊断。

轻量终端可以继续把资料上传到主机已经创建并绑定的项目，但不能成为项目权威端。共享终端退出后必须清空上一名学生的项目目标、报告、档案和待上传会话。

### 7. 从轻量终端升级为知识节点

学生需要本地知识处理、项目创建、项目发布、任务协作或 Agent 时，不继续扩展轻量终端，而是升级为知识节点：

- Windows 设备安装完整 Windows 客户端，使用现有资料、项目和知识管理入口；
- 完整 Windows 客户端可以保存本地项目与知识库、运行 Agent，并作为项目权威端参与知识协作；
- 原轻量终端中的本地资料可以通过现有上传或受控导入进入新的知识节点；
- 轻量终端授权记录和知识节点身份分开，不能把终端令牌直接提升为完整节点权限。

未来 Android 知识节点单独立项，不作为当前 D0—D5 的发布阻塞项。它与 Android 轻量学生端共享协议和可复用界面组件，但形成独立安装目标或可选完整模块，至少需要：

- SAF 授权范围内的项目工作空间和知识空间；
- Room 本地项目、资产和任务索引；
- WorkManager 后台队列与进程恢复；
- 受限文件工具和可追溯 Agent 调用；
- 项目创建、定向发布和跨节点协作；
- 电池、存储、大文件和远程推理数据范围控制。

Android 知识节点不得要求全盘存储权限，也不能为了功能对齐把当前轻量 APK 变成高依赖、常驻运行的完整应用。

## 八、Syncthing 可选兼容策略

### 1. 定位

Syncthing 只用于：

- 已有用户继续使用旧交换目录；
- 一次性迁移大批历史文件；
- 特殊环境无法开放教育管家直传端口时的兼容通道；
- 高级用户主动选择的目录交换。

### 2. 默认行为

- 新安装不检测、不提示安装 Syncthing；
- 新建协作默认使用内置直传；
- 不要求填写 Syncthing 设备 ID 或 Folder ID；
- 普通任务状态不出现“等待 Syncthing”；
- Syncthing 不可用不影响局域网或 Tailscale 直传。

### 3. 兼容导入

旧交换目录仍可由教育管家扫描并按现有 Manifest、幂等和隔离规则导入。内置直传和 Syncthing 收到同一 `packageId` 时只能产生一次业务记录。

不得自动删除、移动或关闭用户已有 Syncthing 目录。用户确认内置直传真机稳定后，再自行停用旧同步。

## 十二、完成定义

本计划完成后应达到：

1. 主机与学生终端继续通过局域网或 Tailscale 直接上传，不依赖 Syncthing。

3. 局域网为默认通道，Tailscale 为跨网络回退，用户无需理解网络路由。
4. 对方离线时自动排队，上线后自动补发。
5. 教师或学生创建的项目可以定向发布给指定教师或学生，由接收主机自动建立本机目录、导入内容并重建索引。
6. 双方只交换必要资料和结果，不镜像本机运行状态。
7. 普通用户不安装、不配置、不检查 Syncthing。
8. Syncthing 作为可选高级兼容继续存在，但不决定业务完成状态。
9. 系统设置明确拆成“基础设置、主机连接、知识协作”三个子菜单。
10. 正常任务和资料闭环控制在一次确认以内，不新增人工审核。
11. 空闲状态不增加全目录扫描和高频轮询。
12. 所有阶段均通过自动测试、人工界面评估和真实双机验收。
