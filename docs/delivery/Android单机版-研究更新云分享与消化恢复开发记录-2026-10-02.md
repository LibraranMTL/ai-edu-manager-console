# Android 单机版：研究更新、云摘要分享与消化恢复

日期：2026-10-02。继续执行 Windows 0.19.3 架构对齐修订计划。源码版本仍为 Android 1.2.8 / 32；正式清单、签名及在线服务未更新。

## 本批完成的源码

### P4：研究更新调度与过期收藏提示

- 学校、专业、职业、路径、总体规划和比赛六类研究有独立自动更新授权；默认关闭，用户只授权当前类别，可单独关闭。
- 每日受网络、电量、存储约束的 WorkManager 检查月份及去标识档案/目标变化；每次最多处理一类。系统不保证精确执行时间，不会在授权前发送资料。
- 自动研究只用规划档案、年级与目标，不自动选原始文件；用户手动研究仍使用实际输入预览。
- 与学习卡片共用现有每学生每日最多 6 次请求上限。额度不足且尚未发送时留到次日，不登记成未知调用。
- 尝试标记在调用前持久化；失败、断网或进程中断不由后台自动重发。用户核对只结束调度状态，不清除模型未知回执。
- 研究结果仍为候选，实际供应商来源及关键字段来源合同沿用前批实现，不冒充已核验资格、录取、获奖或能力结论。
- 比赛详情按可解析日期提示已过截止日期；收藏与历史版本不删除。该提示不意味着已核验官方截止日期。
- 恢复后自动研究授权与自动练习一样关闭，须重新同意。

### P4：规划/选题候选摘要云分享

- 版本详情提供“预览并分享候选摘要”按钮；先显示实际上传文本，再由用户确认，不默认后台上传。
- 摘要只导出指定候选字段及对应 HTTP(S) 来源，排除完整档案、原始来源片段、作答和内部记录；基础去姓名/电话/邮箱不能代替完整人工匿名化审查。
- 拒绝本机路径及超过 32 KB 的摘要；上传前复核学生、版本指纹、摘要哈希、绑定及云地址。
- 使用现有来源设备凭据和学生写入授权，以 P-256 签名绑定实际 HTTP 方法、完整路由、原始字节哈希、时间与一次性 nonce；不发送 API Key。
- 发送前核对当前学生云文档及回收站。已存在的同名、同哈希、同来源设备版本复用回执；已撤回版本不自动复活。
- 本机先保存未知上传标记，丢失回执后先核对远端清单，不盲目重发；远端清单超过核对上限时停止，不进行不完整判断后的上传。
- 云服务流式文档提交增加事务内重复核对。并发/重放同一摘要复用文档 ID，撤回后重放返回撤回回执而不新建。

**部署边界：** 服务端修改仅在本地源码及模拟服务器中验证，未部署到阿里云。现有线上版本是否具备同样的流式幂等保护须在部署后检查；本批不宣称线上已同步。

### P2：普通资料消化成功缓存与写入重放

- 缓存键绑定学生、真实模型地址/型号、处理策略、实际提示词及完整原件/识别文本指纹，不包含 API Key。
- 合格模型响应与固定 Markdown 先保存到 Room 不可变检查点，再写入 SAF 衍生文件。后续重试可复用检查点，不重复付费请求。
- 响应尚未保存时中断保留未知调用标记，不把“没有检查点”当成可以自动再次调用的证据。
- 衍生文件名、声明与证据 ID 使用稳定内容标识；索引及日志按产物路径去重；写入前继续核对原件/识别文本哈希。
- OCR、视觉、ASR 和普通消化检查点均验证内容指纹；跨设备恢复不改写不可变检查点内的历史快照。
- 仍不是跨 SAF 文件、知识引擎、资料状态的一次原子事务；局部写入后恢复依赖幂等重放。所有采集入口统一 Room 权威登记及全入口断点恢复仍需继续开发。
