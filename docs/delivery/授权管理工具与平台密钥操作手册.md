# AI教育管家授权管理工具与平台密钥操作手册

**适用版本：授权管理工具 0.3.1 / Windows 主机 0.15.8**

> 本手册用于受控内部终端。平台 License 私钥和课程目录私钥是两套不同密钥；任何私钥都不得进入源码、安装包、课程包、聊天、日志或普通同步目录。

## 1. 两套密钥分别做什么

| 密钥用途 | 私钥所在终端 | 公钥交付方式 | 用途 |
|---|---|---|---|
| `license_signing` | 内部授权管理终端 | 可信发行方公钥按现有 License v2 流程部署到主机 | 签发平台版本、期限和设备策略 |
| `course_catalog_signing` | 指定平台课程发布主机 | 验证公钥随 Windows 主机安装包内置 | 签名课程目录、图片清单和版本 |

两套密钥不能互换。专业版和机构版发布本机自选课程不需要课程目录私钥。接收官方平台课程的主机不需要导入课程公钥包。

## 2. 初始化平台 License 密钥

1. 在离线或严格受控的 Windows 终端打开授权管理工具。
2. 在“平台 License 密钥管理”选择“创建新密钥”，生成 RSA 3072 位密钥；如已有正式密钥，选择“导入密钥对”。
3. 记录界面显示的 `keyId` 和完整 SHA-256 公钥指纹。界面不会显示私钥正文。
4. 按现有 License v2 信任流程部署可信发行方公钥。
5. 签发时只选择“平台版”、设备策略和期限，不再选择平台编辑、发布或管理员身份。
6. 将生成的 `.aielicense` 交给目标主机导入。平台版 License 直接授予平台课程编辑、发布和恢复能力；激活失败时不会删除当前机构版 License。

## 3. 配置平台课程发布主机

1. 使用有效平台版 License 激活指定发布主机。
2. 进入“精选课程 → 课程管理 → 平台课程编辑与发布草稿”。
3. 首次使用时点击“配置平台发布主机”，选择与当前安装包内置课程公钥匹配的官方发布凭据。
4. 系统执行公私钥签名挑战；只有与内置公钥匹配且挑战通过的私钥才会保存为发布凭据。
5. 此后编辑课程并点击“发布平台课程”即可自动签名。日常课程管理员不需要查看 `keyId`、指纹或密钥列表。
6. 专业版、机构版和平台版接收主机导入 `.edu-coursepkg` 时自动使用内置公钥验证，不需要单独配置。

## 4. 备份与恢复

1. License 私钥通过授权管理工具创建加密 `.aiekeys` 备份。
2. 课程目录发布凭据由平台运维单独加密备份，不在普通课程管理页面提供导出、轮换或撤销按钮。
3. 把备份保存到 BitLocker To Go 或等效加密 U 盘，制作第二份副本并分开放置；密码不得与介质放在一起。
4. 不要长期从 U 盘直接运行私钥。U 盘只用于离线备份和受控恢复。
5. 至少每年执行一次恢复演练，记录日期、操作者、备份标识、`keyId`、指纹和结果，不记录密码或私钥正文。

## 5. 密钥轮换与泄露处置

1. 怀疑私钥泄露时立即停止签发或发布，并隔离对应终端。
2. License 密钥按既有可信发行方轮换流程处理。
3. 课程目录密钥轮换由平台开发与运维统一完成：生成新的发布凭据，把对应验证公钥内置到新版 Windows 主机安装包，再切换发布私钥。
4. 不要求普通接收用户逐台导入公钥；需要验证新 `keyId` 时升级主机版本。
5. 保留仍需验证历史 License 或课程包的旧公钥，并记录事件范围和处置结果。

## 6. 发布前检查

- 授权管理工具显示 0.3.1，主机显示 0.15.8。
- 平台版许可证签发页面没有“平台身份”字段，主机获得统一平台能力。
- 平台发布主机显示“发布凭据已配置”；接收主机不显示课程公钥导入入口。
- 课程草稿版权状态为“已确认”，依据完整。
- 发布摘要中的新增、修改和撤回数量正确，并原样输入本次确认码。
- 新生成包已由主机立即回验；错误包或降级包不会替换最后可用目录。
- 安装包仍显示 `NotSigned` 时只允许受控分发，不作为正式公开版本。

## 7. 外部发布门禁

代码完成不等于生产发布完成。正式发布前还必须完成：实际生产密钥仪式、两份加密离线备份、独立恢复演练、Windows Authenticode、机构版原地升级平台版真机测试、平台发布/撤回/回滚测试，以及 Windows 和 Android 学生端按具体学生过滤的真机测试。
