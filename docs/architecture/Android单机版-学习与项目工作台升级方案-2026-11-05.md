## 1. 升级结论

Android 单机版升级为以当前学生为中心的“学情与项目工作台”，形成以下自动闭环：

```text
本地资料导入 / 拍照 / 扫描 / 对话归档
→ 自动识别、OCR、解析、去重和归属判断
→ 资料消化与来源校验
→ 知识点、五维学习状态、项目进展投影
→ 自动生成学习卡、周行动、学情报告和项目报告
→ 质量门校验与自动发布
→ 学生练习、订正、复测或补充项目证据
→ 下一轮状态更新

云端公共发布中心
→ 精品课程 / 公共学习卡模板发布
→ Android 按国家、地区、语言、年级和版本同步
→ 原子更新本地目录并保留最后可用版本

用户明确授权学生资料范围
→ 上传既有云端文档管理模块
→ 平台按授权范围分配 Windows 主机下载学生档案
```

本期不建设专家咨询业务闭环。授权页可保留说明：

> 用户授权后，平台将派遣专家一对一解读咨询。

该说明只表示平台后续服务安排，不表示 Android 已经具备专家分配、即时咨询、状态查询或结果回传功能。

## 2. 范围与边界

### 2.1 本期交付

1. 首页统一改名为“学情工作台”。
2. 首页显示本周行动、学习卡片、项目进展、本周资料和学情速览，并增加醒目的“请求真人专家解读咨询”入口。
3. 学情报告补充知识点跟踪、五维学习状态，并在页面末尾增加醒目、清晰可读的“请求真人专家解读咨询”转化入口。
4. “学习与行动”包含精品课程、学习卡片、学习模式导航和学习导师。
5. “项目成果”包含项目看板、项目进展报告、项目导师和成果库。
6. 资料整理、消化、状态计算、报告和卡片生成尽量自动完成。
7. 来源冲突、归属不明、敏感内容和质量失败先由规则自动处理，确实无法解决时才进入“需要处理”。
8. 精品课程由云端公共发布中心直接同步，不再把人工导入课程包作为日常流程。
9. 支持将用户明确授权的学生资料上传现有云端文档管理模块，并由平台授权指定 Windows 主机下载。
10. 整体画像、详细档案、报告和来源详情使用安全 Markdown 渲染弹窗或全屏阅读。
11. 保留现有版本更新、连接测试、产品授权、数据与存储、备份恢复和界面设置，只调整分组和说明。

### 2.2 明确不做

- 不把课程学习进度、学生作答或个性化卡片默认上传公共课程发布域。
- 不把云端公共卡片模板直接认定为学生掌握证据。
- 不依赖 IP 地址单独决定国家、地区或语言。
- 不建设机构自行发布课程的多租户后台；平台课程和机构推荐课程均由平台管理员维护。
- 不建设专家咨询状态和结果回传。
- 不把 Agent 文案直接认定为知识掌握、心理结论、项目完成或个人贡献。

### 4.1 项目模块与 Windows 主机版的对应关系

Android 的“项目成果”对应 Windows 主机版导航组“项目与成果”，具体映射如下：

| Android 单机版 | Windows 主机版当前对应 | 调整说明 |
| --- | --- | --- |
| 新建项目 | 项目与成果 → 项目知识管理 → 新建项目 | 保留项目名称、说明、目标、模板、学生关联和资料位置 |
| 接管已有项目 / 导入项目包 | 新建项目页及项目迁移能力 | 放入 Android“管理项目”，不隐藏在高级设置 |
| 已有项目与项目看板 | 项目与成果 → 项目知识管理 → 已有项目 | 增加里程碑、进展、阻塞和下一步摘要 |
| 项目资料与知识 | Windows 项目资料中心 | 对应“项目资料、需确认、项目知识、贡献证据”四类视图 |
| 项目进展报告 | Windows 项目综合报告及项目周期报告 | 使用同一项目事实、里程碑和贡献证据边界 |
| 项目导师 | Windows 项目导师/工具条中的项目导师能力 | Android 使用移动端导师面板，不假定控制外部 Agent 对话 |
| 成果库 | Windows“项目与成果”中的已确认成果、贡献证据及发布输出 | 只收纳已确认成果及版本，不等同于项目原始资料库 |

### 4.2 成果库内容边界

成果库包括：

- 项目最终或阶段性成果文件及其版本，例如报告、设计稿、代码、模型、演示文稿、图片和视频；
- 已发布的项目进展报告、阶段报告和项目总结；
- 与里程碑完成标准关联的成果证据；
- 已明确归属的个人贡献证据；
- 从项目导师会话中经用户确认保存的方案摘要、答辩稿或行动结果；
- 导出、分享和发布记录。

成果库不包括未经采用的原始项目资料、自动生成但未确认的导师建议、临时草稿、失败产物或仅有文件名的空壳成果。项目看板、项目导师和新建项目是功能入口，不是成果库中的“成果”；只有这些功能产生并通过确认的正式产物才进入成果库。

### 4.3 设置功能保留原则

本次升级是在现有设置之上重组，不删除原有核心设置。必须继续保留版本更新、产品授权、连接测试、数据与存储、目录授权、整机迁移、加密备份、备份恢复、界面皮肤、页面布局、任务回执和模型诊断。

唯一计划退出日常入口的是“导入离线课程包”：精品课程改为云端直连后，它只在迁移期或灾备模式下保留，不影响其他设置功能。

## 5. 学情工作台

### 5.1 展示合同

| 卡片 | 内容 | 点击目标 | 空状态 |
| --- | --- | --- | --- |
| 本周最重要的一步 | 从已发布周行动、到期复测、项目里程碑中选 1 项 | 对应行动、卡片或项目 | 本周暂无必须处理事项 |
| 请求真人专家解读咨询 | 复用统一真人专家卡和“授权上传学情资料”按钮；显示授权说明，不展示虚构咨询状态 | 当前学生授权范围预览 | 未生成报告时仍可授权已有学情资料，并明确资料范围不足 |
| 本周行动建议 | 最多 3 项，显示依据和截止时间 | 周行动详情或学习导师 | 尚未生成本周行动 |
| 今日学习卡 | 最多 3 张待开始、进行中或待复核卡片 | 卡片练习 | 尚未安排学习卡 |
| 项目进展 | 活跃项目、里程碑、阻塞和最近证据 | 项目看板或项目报告 | 暂无活跃项目 |
| 本周资料上传 | 近 7 日上传趋势图、本周文件数、已消化、处理中、需要处理；支持查看和分享 | 资料统计详情或对应资料筛选 | 本周暂无新增资料 |
| 学情速览 | 重点知识点、五维状态、报告更新时间 | 学情报告 | 资料不足，等待形成观察 |

每张卡片必须显示截至时刻、数据来源数和真实状态。首页刷新只读取或请求刷新投影，不直接启动 OCR、Agent、报告或卡片生成。

### 5.2 本周资料上传统计图表与分享

该卡片对齐 Windows 主机版当前学生资料统计和统计分享能力，并复用 Android 学生版“每周知识增长图”的图片预览、保存和分享交互，但必须区分两类指标：

| 视图 | 统计事实 | 不得推断 |
| --- | --- | --- |
| 资料上传 | 每日新增文件、来源渠道、已消化、处理中、需要处理和容量 | 文件多不等于学习投入高或知识增长快 |
| 知识增长 | 已消化资料产生的知识点更新、复测证据和项目知识变化 | 无稳定证据时不能宣称能力提高 |

默认显示“资料上传”近 7 日柱状/折线图；存在有效知识投影时可切换“知识增长”。统计口径：

- 使用当前学生、自然周和不可变资料 ID；同一文件重复导入不重复计数。
- 以本机实际接收/导入时间绘制每日新增，以资料状态事件计算已消化、处理中和需要处理。
- 分学生资料与项目资料显示来源，不把其他学生或未明确归属资料计入。
- 被撤回或判定为重复的资料保留审计，但从有效新增数中扣除并在详情注明。
- 图表显示统计截至时间、时区、周起止日期和统计版本。

“分享本周统计”显式生成一张可预览的 PNG 图片，建议使用与学生端知识增长图一致的 `1200 × 675` 版式。分享内容默认只含学生显示名/代称、周范围、统计数字、趋势图和生成时间，不含文件名、目录、正文、失败详情、设备 ID 或 Agent 配置。用户可在分享前隐藏学生姓名。系统分享只导出本次图片，不等于开启云端学生资料持续授权。

如果已有本周知识增长图，详情页提供“资料上传 / 知识增长”两个页签和各自分享按钮；两张图可以同屏关联解释，但不能把上传数量直接绘制成知识增长值。

### 5.3 响应式规则

- 横屏使用两至三列卡片；竖屏单列。
- 首屏突出一个学习重点行动；真人专家商业服务入口放在页面末尾，以高对比卡片保持可发现性但不抢占首要内容。
- 短详情使用 Markdown 弹窗；超长文档进入全屏阅读。
- 不使用模拟进度、虚构建议或把“0”当作资料完整。

### 5.4 首页真人专家解读咨询入口

新增可分派任务 `WP-018-T01`：在 Android 单机版“学情工作台”首页末尾加入与学情报告页一致的“请求真人专家解读咨询”卡片和“授权上传学情资料 →”按钮。卡片不占用首屏和首要行动位置，使用高对比标题、正文和按钮保持可发现、可读、可触达。

首页入口与 `WP-019-T01` 共用同一组件、文案、授权范围草稿和漏斗事件合同，仅通过 `sourcePage=android_home` 区分来源；不得生成重复授权单或重复上传。点击只携带当前 `studentId` 和已有学情资料类别进入 `WP-022` 授权范围预览，不直接上传、不创建咨询单。正式启用条件、隐私边界及专家服务闭环边界与 6.4 节一致。

## 6. 学情报告升级

### 6.1 知识点跟踪

新增 `KnowledgePointState`：

```text
studentId, knowledgePointId, label, subject, state,
observations[], sourceRefs[], latestObservedAt,
confidence, coverage, ruleVersion, asOf, revision
```

首版状态：`待建立`、`正在接触`、`需巩固`、`待复测`、`有稳定证据`、`资料不足`。

“有稳定证据”必须来自可比、独立作答、复测或人工确认；单份摘要、浏览记录、Agent 回答和课程打开次数都不能证明掌握。

### 6.2 五维学习状态

按目标、心态/自评、问题、方法、效率五个维度分别展示。每项标注学生自述、家长/教师观察、系统观察或系统推断，保留来源、时间和置信度。首版不做心理或医学诊断。

### 6.3 报告发布

- 使用固定 `asOf` 和状态快照指纹。
- 同一学生、报告类型、周期和指纹使用稳定幂等键。
- 只有有效来源、快照或规则版本变化才生成新版。
- 生成临时版本，校验通过后原子切换为 active；失败保留旧版。
- 来源撤回后自动标记依赖失效并生成更正版本。

### 6.4 真人专家解读咨询入口

新增可分派任务 `WP-019-T01`：在学情报告页面末尾放置与现有授权入口语义、文案和视觉风格一致的转化卡片：

- 标签：`真人专家`；
- 标题：`请求真人专家解读咨询`；
- 说明：`先核对准备上传的学情范围。点击本身不会上传、创建咨询单或改变授权。`；
- 主按钮：`授权上传学情资料 →`。

卡片位于详细报告内容之后的页面末尾；使用独立浅色背景、高对比标题、正文和主按钮，与普通报告信息卡拉开视觉层级。横竖屏滚动后必须可达，不得被侧栏或详情操作遮挡，并满足触控面积、字号、对比度及屏幕阅读器要求。页面只保留一个主转化按钮，避免与分享、刷新等次要操作争抢注意力。

点击按钮必须携带当前 `studentId`、报告类型、报告修订和建议资料类别进入 `WP-022` 的授权范围预览，不得直接上传。用户明确确认授权后才进入上传；取消、返回或授权失败均留在本机，不创建专家咨询状态。本期仍不建设专家分配、咨询进度或咨询结果回传闭环。

为评估商业转化，仅记录不含学生内容的漏斗事件：卡片曝光、按钮点击、授权预览打开、授权确认和服务端上传回执。事件使用匿名产品实例/会话标识，不记录学生姓名、报告正文、文件名或授权字段值；同一页面会话曝光去重。按钮必须在 `WP-021/022` 授权预览与回执闭环可用后才面向正式用户启用，不发布死按钮或虚假完成状态。

## 7. 学习与行动

### 7.1 精品课程

Android 直接从云端公共发布中心同步课程清单，不再要求普通用户导入 `.edu-coursepkg`。

同步规则：

1. 使用用户确认的国家/地区、应用语言、年级/年龄、产品版本和发布通道匹配目录。
2. IP 只可作为首次建议，不得覆盖用户设置。
3. 使用 `ETag`、清单版本和内容哈希增量下载封面、简介及必要资源。
4. 完整校验后原子切换目录；失败继续使用最后可用版本。
5. 课程撤回后停止新打开；已经下载的学习记录不删除。
6. 断网时可使用已校验缓存；从未同步成功时显示明确空状态。
7. 旧课程包在迁移期只用于导入既有目录或灾备恢复，不再作为日常发布方式。

课程目录与学生数据分离。云端只发布课程内容和适用范围，本机保存收藏、打开记录、学生分配和学习行动。

### 7.2 公共卡片模板与个性化卡片

| 对象 | 来源 | 是否含学生数据 | 用途 |
| --- | --- | --- | --- |
| `LearningCardTemplate` | 云端平台管理员发布 | 否 | 通用练习、课程配套卡片、多语言卡片包 |
| `LearningCardInstance` | 本机从模板实例化或依据学生证据生成 | 是 | 当前学生作答、反馈、订正和复测 |
| `student_learning_card` 云端文档 | 用户另行授权上传 | 是 | 私有跨设备文档，不进入公共发布目录 |

公共模板更新不能覆盖已经开始作答的实例；实例固定模板修订号。学生作答默认只留本机，只有用户开启相应学生资料类别授权时才进入私有云端文档域。

### 7.3 学习模式导航和学习导师

复用 Windows 学习模式的五组语义：学习、互动、测验、核验、计划。首批提供导师引导、费曼复述、逐题测验、错题复盘、目标设置、学习计划、每周行动和学习总结。

每次会话绑定当前学生、资料快照、可选项目、模式、模板版本和过期时间。输出区分资料事实、学生作答、系统推断和待核验内容。互动结果先成为候选，不直接修改掌握状态。

### 7.4 学习卡自动生成规则

允许触发：

- 同一知识点在设定窗口出现两个独立错误根；
- 明确到期的复测；
- 学生/教师确认的薄弱点；
- 导师会话中存在真实作答证据；
- 学习计划中的到期练习节点。

禁止触发：重复导入同一作答、只有资料数量增加、只有 Agent 答案、已有同业务键未关闭卡片、来源已撤回、答案不可验证。

默认每名学生每天最多自动发布 3 张，同一知识点同一复测窗口最多 1 张。卡片质量门包括题干完整、目标单一、答案或评分规则可验证、引用正确、无跨学生信息、难度适配和无重复。

## 8. 项目成果

“项目成果”必须保留完整的项目生命周期入口，而不是只展示报告：

1. 新建学习项目；
2. 接管已有项目；
3. 导入项目包；
4. 查看和管理已有项目；
5. 项目资料与知识；
6. 项目看板和里程碑；
7. 项目进展报告；
8. 项目导师；
9. 成果库。

新增 `ProjectMilestone`、`ProjectEvidence`、`ProjectContribution` 和 `ProjectReportSnapshot`。项目报告必须区分项目事实、导师建议、系统推断和个人贡献。

项目导师首批模式：问题澄清、研究计划、证据核验、方案评审、里程碑复盘、成果表达/答辩。导师建议可生成下一步行动，但未经证据或用户确认不得标记里程碑完成，也不得自动进入个人学情。

项目资料流水线：

```text
项目资料导入
→ 去重和项目归属校验
→ 解析 / OCR / 视觉理解
→ project_digest
→ 项目事实、概念、风险、待决问题、成果候选
→ 里程碑匹配和贡献归属
→ 项目进展快照
→ 项目报告、导师建议和下一步行动
```

## 9. 自动化编排

### 9.1 状态机

```text
imported
→ parse_queued → parsing → parsed
→ digest_queued → digesting → digested
→ facts_validating → facts_applied / auto_remediating
→ projection_dirty → projection_ready
→ outputs_queued → outputs_generating → outputs_validating
→ outputs_published → delivered
→ needs_attention（只有自动处理仍失败时）
```

每次状态变化写入事件账本和 Outbox。任务包含稳定业务键、输入哈希、租约、尝试次数、下一次重试时间、产物 ID 和回执状态。页面浏览、刷新和 Markdown 打开不得启动写任务。

### 9.2 触发矩阵

| 事件 | 自动动作 | 自动结果 | 最终转“需要处理”条件 |
| --- | --- | --- | --- |
| 文件/照片/扫描导入 | 哈希、去重、类型和归属识别 | 进入正确解析队列 | 自动归属评分仍不足、文件损坏或超限 |
| 图片/扫描 PDF | OCR，必要时受控视觉补充 | 页级文本和来源映射 | 多策略 OCR 均失败 |
| 文本文档 | 编码检测、切片和结构识别 | 进入消化 | 无法解码或伪装二进制 |
| 消化成功 | Schema、引用和范围校验 | 更新知识候选与索引 | 自动修复引用后仍无有效依据 |
| 来源冲突 | 时间、来源级别、哈希和独立证据规则比对 | 并列保留、选定可信项或降级为待核验 | 规则无法决定且影响正式结论 |
| 学生/项目归属不明 | 文件夹、导入入口、姓名/项目标识和历史映射评分 | 自动归属或隔离到候选 | 多个候选接近且无法安全确定 |
| 敏感内容 | 分类、字段最小化、读者投影和脱敏 | 保留本机或生成脱敏投影 | 无法确定允许读者或脱敏后失真 |
| 质量校验失败 | 确定性修复、保守模板、重新生成 | 发布合格版本或保留旧版 | 连续失败达到阈值 |
| 学情快照变化 | 标记报告 dirty | 自动生成和原子发布 | 无有效证据或发布门失败 |
| 项目快照变化 | 更新看板和里程碑 | 周期/关键节点生成项目报告 | 完成标准或贡献无法确认 |
| 学习卡作答 | 写入版本化回执 | 更新状态并安排至多一个下一行动 | 作答不完整或评阅未知 |
| 每日对账 | 查租约、孤儿产物、半提交、待重试 | 自动续跑和补记回执 | 永久失败或需要用户补充输入 |
| 公共内容清单变化 | 下载并校验清单和资源 | 原子切换新目录 | 签名/哈希/适用范围持续失败 |

### 9.3 自动处理优先级

1. 确定性规则修复。
2. 使用已有可靠映射或最后成功配置。
3. 降级为保守输出并保留旧正式版本。
4. 对独立任务继续执行，禁止一个文件阻塞整批或一个学生阻塞其他学生。
5. 只有缺少必要选择、存在不可消解冲突或永久失败时进入“需要处理”。

### 9.4 自动化策略

- `关闭`：只登记资料。
- `保守自动`：自动解析、消化和更新投影；结果生成但不自动切 active。
- `完整自动`：自动完成解析、消化、校验、发布和首页送达；异常才提示。

升级用户保持原有行为，首次启用新 Agent 调用或网络同步时明确说明。

### 9.5 自动发布政策

| 结果 | 完整自动模式 | 必须满足的质量门 | 失败处理 |
| --- | --- | --- | --- |
| OCR/解析文本 | 自动采用为解析产物 | 文件哈希一致、正文非空、页码/区域可追溯 | 自动切换解析器或补跑；仍失败才请求处理 |
| 摘要、概念、问答 | 自动进入知识候选和搜索 | Schema 完整、来源存在、无跨学生/项目 | 自动修复引用；冲突项并列保留并标为待核验 |
| 直接观察事实 | 自动发布为系统观察 | 原文、作答或成果直接支持，来源未撤回 | 推断性内容降级，不自动转为事实 |
| 知识点/学习状态 | 自动更新投影 | 版本化规则、来源、置信度和证据阈值完整 | 降级为正在接触、待复测或资料不足 |
| 学习卡片 | 自动校验并发布 | 题目可作答、答案可验证、来源和行动键完整 | 规则模板降级；仍不可靠则只保留行动意图 |
| 学情报告/周行动 | 自动原子发布 | 当前学生、有效来源、必需章节、截至时刻和引用通过 | 保留旧版；保守模板仍失败则进入异常 |
| 项目报告 | 自动原子发布 | 项目事实与建议分离，里程碑有证据，贡献归属明确 | 不明贡献只留项目层，旧报告继续有效 |
| 云端学生资料 | 永不因完整自动模式而默认上传 | 用户明确授权、范围预览、有效授权和服务端回执 | 立即停止，等待授权或对账原回执 |

### 9.6 失败重试与对账机制

失败分为：

- **瞬时失败**：网络、模型超时、存储暂时占用；按 `5 分钟 → 30 分钟 → 2 小时`退避重试。
- **能力缺失**：Agent、OCR 或解析器不可用；先走本地保守路径，无法降级时等待配置。
- **输入问题**：文件损坏、加密、超限或归属不明；执行自动修复和归属规则后再决定是否需要处理。
- **执行未知**：进程退出或回执丢失；先按业务键、任务 ID 和产物哈希查询，不直接重建任务。
- **永久失败**：达到重试上限或质量门持续失败；保留原资料、失败产物和恢复入口，不阻塞其他任务。

统一对账 Worker 在每日维护窗口运行，并在应用启动、网络恢复、升级迁移完成和用户点击“立即检查”时追加轻量检查：

1. 超出租约仍处于运行中的任务；
2. 已生成文件但缺少任务回执的孤儿产物；
3. 回执成功但资料状态未推进的半提交；
4. 来源已修改/撤回但报告、卡片或行动仍有效的脏依赖；
5. 已到重试时间却没有重新入队的任务；
6. 卡位、并发或设备约束解除后仍在等待的意图；
7. 云端已经收到内容但本机缺少回执，或授权撤销后仍有待上传任务；
8. 公共课程/模板 active 与 last-good 指针、资源哈希或撤回状态不一致。

对账只补记或续跑原业务键。单个文件失败不得阻塞同批其他文件，单个学生失败不得阻塞其他学生，项目任务和学生任务使用独立并发槽。

## 10. 云端授权分享

### 10.1 数据范围

沿用现有云端文档管理模块的类别和设备授权：学生基础信息、学情报告、学习资料、选题建议、推荐比赛、学习卡片，以及单独许可的健康资料。用户按学生、类别、字段、用途和有效期确认。

流程：

```text
选择当前学生
→ 预览基础信息和资料类别
→ 用户明确授权
→ 生成版本化私有资料投影
→ 加密上传并取得服务端回执
→ 平台为指定 Windows 主机签发下载许可
→ Windows 主机刷新授权并按需下载/建档
```

Android 不实现专家咨询单、专家状态和咨询结果回传。云端上传成功只显示“平台已接收资料”及下载授权状态，不能显示“专家已接收/咨询完成”。

### 10.2 安全边界

- 公共课程/卡片发布域与学生私有文档域使用不同 API、权限和存储前缀。
- 未授权、授权过期或范围变化时停止后续上传。
- 不上传 API Key、License、Keystore、系统提示、本机路径和其他学生资料。
- 上传未知结果先查原回执，不新建重复分享包。
- 撤权不自动删除已经正式导入 Windows 的本地档案；云端删除须以服务端回执为准。

## 11. 详情渲染

## 14. 实施前冻结项
