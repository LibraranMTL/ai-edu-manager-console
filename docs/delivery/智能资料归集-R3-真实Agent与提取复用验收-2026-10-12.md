## 4. 分类与消化是否重复

| 环节 | R3 行为 |
|---|---|
| OCR／Office／PDF／文本解析 | 同学生、同内容、同格式、同提取器及 OCR 参数，成功投递到受管项目后交接完整结果；消化命中后不再执行 OCR／解析 |
| 分类预览 | 最多 200 KiB；超长或有提取限制时仍按原策略留待确认。预览缓存从不作为完整消化结果 |
| 消化全文 | 从项目自己的缓存读取完整结果，保留警告、语言等元数据；真实文件固定版本和哈希仍重新验证 |
| AI 分类 | 决定资料去哪个学生／项目／分类；固定路由或精确规则可免去这次调用 |
| AI 消化 | 生成知识、证据与项目成果，仍是一轮不同合同的 AI 理解；不把分类建议当作消化结果 |

因此：**满足受控复用条件时消除了跨阶段重复 OCR，但没有合并两类 AI 理解。** AI 仍可能重复阅读部分文字，这是路由与知识生产的不同任务，不能宣称“只调用一次 AI”。

### 交接校验

1. 仅宿主持有的提取器能力可以交接，不新增 renderer／Agent 导入任意缓存 JSON 的接口。
2. 来源绑定学生与目标学生必须完全一致；共享未绑定来源、跨学生目标不交接，不建立全局内容缓存。
3. 目标必须是当前学生仍有权限的有效受管项目；登记已采用、活动归集关联、资料版本、内容哈希和操作回执必须匹配。
4. 来源固定快照与目标固定版本均校验；格式、解析器版本、OCR 语言、系统／OCR 桥接实现指纹必须一致；写入前再次检查授权及版本。
5. 只从完整提取缓存读取，经结果哈希验证后写入目标独立缓存；不使用分类外层截断缓存，不交接被标记截断的结果。记录来源资料版本、目标版本和学生范围。
6. 缓存丢失、被淘汰、损坏、参数变化、写入容量／权限不足时不假报复用成功，不影响已验证投递；消化使用原有受控提取流程。这些情形仍可能再次 OCR。

交接适用于现有受管项目消化链路；学生原始资料库、非受管旧项目保留既有行为，不宣称其旧式消化已接入新缓存。列表刷新不做交接、OCR 或 Agent 调用。原件、快照、旧项目引用保留规则未放宽。
