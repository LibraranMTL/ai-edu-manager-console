# Windows 系统任务性能优化：基础改造实施记录

日期：2026-10-11

状态：源码与基础链路验证已完成；**不是三阶段计划完成，也不是第一阶段全部验收通过**。沿用 0.21.1，仅生成独立基础候选包，不改变正式版本、线上安装包或已有外部服务授权。

## 1. 本次实际改动

| 项目 | 本次实现 | 范围限制 |
|---|---|---|
| 页面查询 | 新增异步分页与按需详情 IPC；每页 20 条，列表白名单只包含摘要 | 旧客户端保留兼容快照接口；旧接口仍可能传输完整任务数据 |
| 后台读取 | 共用一个任务 I/O worker，账本按文件元信息缓存，同查询合并在途请求 | 不是任务账本异步写入进程；关键写入仍走既有原子保存 |
| 只读页面 | 页面读取不再运行候选生成、回执扫描、超时结算或模型探测 | 手动刷新只获取最新已保存快照，业务目录由维护周期更新 |
| 手动模式初始化 | 后台独立维护任务目录，学生/项目之间让出事件循环；启动恢复就绪后延后初始化 | 每个来源内部仍有旧同步读取，未证明其最坏阻塞低于 100 ms |
| 心跳 | 内存合并，15 秒保存；不改变任务更新时间与排序，按执行批次应用 | 保存仍会序列化账本，尚未达到全量写入脱离主进程的目标 |
| 回执 | worker 异步读取与解析；单轮 50 个且总字节有界；等待文件稳定；未变化内容复用 | 宿主权限校验、业务提交与回执归档仍复用旧实现，尚未事务化改造 |
| 监听 | 监听只发变化通知；与正常扫描合并；60 秒维护兜底，分批继续 | 非正常文件系统上监听可能不可用，此时依赖周期检查 |
| 资源等待 | 原来每任务一个定时器改为共享唤醒队列；每轮最多 20 项，每项之间让出事件循环 | 这是等待资源，不是新增有限次数的业务重试策略 |
| 真实交接状态 | 未收到领取确认时显示“等待发送确认”；不能把请求打开当成已发送 | WorkBuddy 仍是辅助模式，未恢复无人值守执行 |
| 用户操作 | 原批次重开 WorkBuddy、复制原指令；没有已校验结果时不显示“打开结果文件” | 不会代替用户发送；不改变执行标识；其他工具的重开支持仍待补齐 |
| 阅读与状态刷新 | 技术编号/心跳等收进“诊断详情”；后台通知合并刷新；迟到列表/详情请求不覆盖新选择 | 普通页面的其他历史管理入口仍保留，未全面改成三分组简洁模式 |
| 生命周期 | 退出关闭 worker、监听及新增定时器；防止关闭后重新创建查询 worker | 不代表已完成四小时无泄漏验收 |

没有调用真实学生的 Agent，没有重发历史资料，没有改动用户运行目录中的任务账本。

## 2. 主要源码与测试

- `electron/task-read-model.cjs`：摘要白名单、分页、交接状态与结果可用性。
- `electron/task-io-worker.cjs` / `task-io-client.cjs`：异步读取、缓存、请求去重、回执监听与进程释放。
- `electron/task-inbox-reader.cjs`：分批、稳定文件与内容复用。
- `electron/task-progress-buffer.cjs`：心跳合并与执行身份核对。
- `electron/task-retry-queue.cjs`：共享资源等待唤醒队列。
- `electron/main.cjs` / `electron/preload.cjs`：宿主接线、兼容接口、交接操作及定时维护。
- `src/main.tsx`：分页、按需详情、筛选防串、交接提示与诊断折叠。
- `tests/task-performance.test.cjs`：新增读取、回执、心跳、资源等待与关闭测试。
- `scripts/benchmark-task-read-model.cjs`：可复跑的 1,000 / 10,000 条合成数据基准。

工作区原本已有大量未提交改动，均予保留。候选包基于当前整个工作区，不是仅包含本次补丁的干净基线包。
