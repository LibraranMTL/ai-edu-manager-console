# Windows 0.10.6 最小 P5 开发计划

> 更新日期：2026-07-24  
> 基线：Windows 主机版 / Windows 学生终端 0.10.5，Android 学生终端维持现有兼容接口。  
> 目标：以尽量少改动、零常规人工审核、低后台负荷为原则，完成“知识结果 → 成长模型 → 学情报告 → 教育档案”的自动更新闭环。  
> 边界：继续使用现有 LLM Wiki Engine、ArchiveAccess、统一任务中心、成长索引和四类报告；不安装 GBrain、数据库、向量服务、技能包或独立常驻服务。

## 一、实施原则

1. 正常批次零确认。资料通过既有治理质量门后，系统自动更新成长模型、报告和教育档案。
2. 不伪造人工审核。历史 `confirmed` 语义和审核记录保持兼容；P5 新增或复用明确的系统验证来源，自动决策必须记录规则版本、证据 ID、来源 URI、时间和原因。
3. 风险在后台分流，不向普通用户展示“候选、审核、批准、风险、哈希、批次”等术语。
4. 异常不阻塞主流程。单项异常只进入“需要补充”，其他资料、其他学生和旧版报告继续可用。
5. 无实质变化不生成新报告或新档案版本；打印版只在用户导出时生成。
6. 以事件驱动和按需重建替代全量高频扫描，不新增默认常驻服务。
7. 不改变学生目录、项目目录、稳定 ID 和现有知识库物理结构；新增索引或清单必须可删除后重建。

## 二、0.10.5 直接复用的能力

- `growth-model.cjs` 的成长索引、稳定证据 ID、能力维度、项目贡献、成熟度和趋势计算。
- `growth-index-consistency.cjs` 的来源指纹、过期判断和旧报告兼容识别。
- `learning-report-workflow.cjs` 的周/月周期、报告时效、章节校验和发布写入。
- 现有四类报告：整体画像、每周行动建议、历史变化、阶段总结。
- `ArchiveAccess v1` 的搜索、资源读取、变化列表和上下文包。
- 统一任务中心、Agent 结果收件箱、QClaw 分批回执兼容和知识治理质量门。
- 现有学生/项目范围隔离、备份恢复及人类可读 Markdown 文件。

## 三、自动决策与异常分流

| 后台等级 | 判定条件 | 自动处理 | 普通用户是否操作 |
| --- | --- | --- | --- |
| 可自动采用 | 来源可读、学生归属唯一、结构完整、无冲突、通过既有质量门 | 自动写入系统验证记录并更新受影响的成长观察；满足多源与稳定性规则后进入正式报告 | 否 |
| 继续观察 | 单次表现、仅 Agent 推断、证据较少或置信度一般 | 自动标记为观察；可进入证据附录或使用保守措辞，不形成长期定论 | 否 |
| 需要补充 | 来源缺失、跨学生证据、关键冲突、无法确认归属、正式结论无依据 | 不发布该项，保留上一版正式报告；合并成一条可读提示 | 仅异常发生时 |

以下情况才允许出现“需要补充”：

- 原始资料或知识资产已移动、损坏或无法读取；
- 证据指向其他学生，或学生归属无法唯一确定；
- 两组高可信证据形成关键冲突；
- 报告正式结论缺少可访问的证据 ID；
- 用户主动提出纠正、撤销或补充；
- 单次观察被错误提升为长期标签。

“查看依据”是可选查阅动作，不是批准按钮。技术明细只放在“高级与诊断”中。

## 四、分阶段开发任务

### P5-A：低负荷触发与增量更新底座

目标：先消除高频全量扫描，再接入新自动化。

- 为学生成长索引增加 `dirty` 标记、来源指纹和最后成功更新时间。
- 资料消化完成、项目贡献变化、成长证据变化时，仅把受影响的学生加入更新队列。
- 删除启动后对全部学生立即修复成长索引的行为，改为首次查看、报告到期或收到变化事件时按需修复。
- 将“每 60 秒扫描全部学生和全部报告”改为事件触发；保留低频兜底时，只扫描脏学生或到期任务。
- 同一学生的重复事件合并，使用 single-flight、防抖和幂等键避免并发重建。
- 后台异常采用退避重试，不持续占用主线程。

自动测试：

- 只有受影响学生被标脏并重建；
- 相同事件重复到达只执行一次；
- 应用启动不触发全学生成长模型重建；
- 无变化时不创建任务、不写文件；
- 异常重试不阻塞界面或其他学生。

人工评估：

- 0.10.5 既有档案可直接打开；
- 冷启动、切换学生和任务中心滚动无明显新增卡顿；
- 添加一份测试资料后只有对应学生进入更新流程。

### P5-B：成长模型自动增量构建

目标：复用现有成长索引，将可信知识和项目证据自动连接到成长模型。

- 新增一个幂等的 `growth_refresh` 内部任务，不为四类报告分别重复扫描来源。
- 汇入已采用知识、项目贡献和教师/家长管理的学生提交。
- 自动映射能力维度、项目、发生时间、来源、可信度和证据 ID。
- 可自动采用的内容写入系统验证记录；仅 Agent 推断和单次表现自动进入 `watching`。
- 禁止永久标签；长期趋势必须满足多次、跨时间或多来源条件。
- 借助 ArchiveAccess 校验来源存在性和学生范围，不直接遍历无关目录。

自动测试：

- 知识、项目贡献和普通学生提交均可增量进入正确学生的成长索引；
- 跨学生来源被拒绝，单次表现不会成为长期定论；
- 证据 ID、来源 URI、项目和时间映射完整；
- 重复执行不产生重复证据；
- 删除可重建索引后可从原有资料恢复。

人工评估：

- 导入并消化一份测试资料后，无需确认即可看到成长变化；
- 普通页面不出现审核队列；
- 资料不足时只显示“继续积累”，不生成武断标签。

### P5-C：四类学情报告自动校验与发布

目标：把现有 `pending_review → 人工采用 → published` 改为“生成 → 确定性校验 → 自动发布”。

- 四类报告继续使用现有模板和周期计算，不新增报告类型。
- 为报告任务使用 `auto_after_validation`，校验通过后调用现有发布写入能力。
- 自动校验至少包括：
  - 学生范围唯一且一致；
  - 必需章节齐全；
  - 正式结论均有证据 ID；
  - 证据可通过 ArchiveAccess 读取；
  - 不引用未采用或跨学生候选；
  - 不存在未解决的高可信冲突；
  - 报告来源指纹与当前成长模型一致；
  - 与上一版相比存在实质变化，或确已进入新的周/月周期。
- 校验失败时不覆盖正式报告，保留上一版并生成一条“需要补充”摘要。
- 资料不足时自动生成保守说明；无变化时只更新状态，不生成重复版本。

自动测试：

- 四类报告在校验通过后自动发布，正常路径不请求确认；
- 缺来源、跨学生、冲突和指纹过期时拒绝覆盖旧报告；
- 周/月边界触发正确；
- 同一输入重复运行不产生新版本；
- 单个报告失败不影响其他报告和其他学生。

人工评估：

- 普通用户只看到“报告已更新”或一条“需要补充”；
- 原有四个报告入口、文件位置和终端读取保持兼容；
- 报告内容为自然语言，不暴露 JSON、状态机或 Agent 名称。

### P5-D：结论“查看依据”

目标：用现有证据 ID 和 ArchiveAccess 提供最小可追溯入口，不建设新的审计工作台。

- 报告正式结论携带稳定证据 ID。
- 点击“查看依据”展示简明证据卡：资料名称、时间、项目、摘要和来源入口。
- 可继续下钻到成长证据、知识资产和原始资料；路径移动时优先按稳定 ID/URI 解析。
- 默认不展开技术字段，不提供逐条批准按钮。

自动测试：

- 每条正式结论至少有一个可解析证据 ID；
- 证据解析严格限制在当前学生/项目范围；
- 来源缺失时返回可读错误并进入“需要补充”；
- 历史报告仍可打开，缺少新字段时安全降级。

人工评估：

- 用户最多两步从结论到原始依据；
- 查看依据不触发修改、审核或重新发布。

### P5-E：轻量版本化教育档案

目标：只在有实质变化时形成可携带、可恢复的档案版本。

- 每个版本至少包含：
  - 人类可读 Markdown 汇总；
  - 结构化 JSON 清单；
  - `manifest`（版本、学生 ID、时间、来源指纹、文件校验）；
  - 变化摘要。
- 复用现有目录和备份机制，不引入数据库或新的档案服务。
- 只有成长模型或正式报告发生实质变化时创建新版本。
- 可打印输出按用户请求即时生成，不在后台批量生成 PDF。
- 保留最近版本和必要恢复点；清理策略必须先验证目标目录且可恢复。

自动测试：

- 无变化不创建版本；
- Markdown、JSON、manifest 和变化摘要相互一致；
- 版本可比较、备份和恢复；
- 0.10.5 旧档案原地兼容；
- 导出失败不影响当前正式档案。

人工评估：

- 用户一次操作即可导出完整教育档案；
- 离线环境可读取 Markdown 和 JSON；
- 恢复后报告、成长索引和来源引用一致。

## 五、明确不进入最小 P5

- 新能力维度配置器、复杂成长模型编辑器和实时图表大屏；
- 面向普通用户的审核中心、风险面板和逐条批准流程；
- 学生行动下发、打卡、自动反馈和行为监督；
- 身份角色、细粒度权限、敏感信息设置和 PIN；
- GBrain、外部数据库、向量服务、技能包和联网 MCP；
- 后台批量生成 PDF；
- 全量实时目录监听、全学生分钟级轮询；
- 重写现有学生/项目目录或迁移知识引擎。

## 六、发布闸门

每一阶段都必须先完成自动测试和人工评估，确认无回归后才进入下一阶段。P5 整体完成需同时满足：

- 正常资料批次从消化结果到成长模型、四类报告和教育档案更新为零人工确认；
- 可自动采用内容自动处理，继续观察内容不打扰用户，高风险异常不覆盖旧结果；
- 只有来源缺失、跨学生、关键冲突或用户主动纠正等真实异常出现一次简短提示；
- 正式报告结论证据引用完整率 `100%`，且来源可通过 ArchiveAccess 访问；
- 相同输入重复执行不产生重复证据、报告或档案版本；
- 应用启动不全量重建，空闲时不进行分钟级全学生扫描；
- 任一学生或报告失败不阻塞其他任务；
- 现有 0.10.5 数据、目录、报告入口、Windows 学生终端和 Android 读取接口保持兼容；
- 全量自动测试、构建审计、升级、断网、备份恢复和真机抽查通过；
- 发布 Windows 0.10.6 安装包，并同步 CHANGELOG、操作手册和下载页。

## 七、推荐执行顺序

```text
P5-A 低负荷触发
→ 测试与人工评估
→ P5-B 成长模型增量构建
→ 测试与人工评估
→ P5-C 报告自动校验发布
→ 测试与人工评估
→ P5-D 查看依据
→ 测试与人工评估
→ P5-E 版本化教育档案
→ 全量回归、打包与发布
```

## 八、2026-07-24 开发执行结果

P5-A 至 P5-E 已按顺序完成开发闸门，未增加普通用户日常审核步骤：

- P5-A：成长索引改为事件标脏、合并、防抖、单飞、限量处理和退避重试；取消启动全学生修复，兜底周期调整为 15 分钟且只处理脏学生。
- P5-B：通过一个幂等增长刷新路径，将通过治理的学生知识与学生专属项目证据转换为带来源的 `watching` 观察；跨学生、无来源和共享项目知识不会变成个人定论。
- P5-C：四类报告使用成长模型指纹与证据 ID 进行自动校验；通过后自动发布，失败保留上一版并只写一条后台“需要补充”记录。
- P5-D：报告页增加只读“查看依据”，从报告到证据一步、从证据到本机来源第二步；来源解析严格限制在当前学生及其绑定项目。
- P5-E：成长或报告发生实质变化后合并生成轻量档案版本，包含 `教育档案.md`、`education-archive.json`、`manifest.json` 和 `变化摘要.md`；相同指纹不重复生成，完整档案可一次导出，主机备份/恢复携带档案快照。

验证记录：

- 最终全量自动测试：`365/365` 通过。
- 生产构建：`pnpm build` 通过。
- 界面人工评估：学情报告页、“查看依据”和“导出完整档案”入口正常渲染，无控制台错误或警告；浏览器预览不具备 Electron 文件桥，因此真实本机定位和导出由主进程契约及文件系统测试覆盖。
- 交付构建：版本已提升为 0.10.6，CHANGELOG、三端操作手册和下载页已同步；Windows 主机 EXE/ZIP 与 Windows 学生终端 EXE 已通过隔离构建、结构审计和 SHA-256 复核。
- 签名状态：两个 EXE 的 Windows Authenticode 实测均为 `NotSigned`，当前属于本地未签名候选包，不标记为公开正式发布。
- 尚未完成的发布验收：执行 0.10.5 原地升级、断网、真实资料闭环和真机抽查；如需公开下载，还需完成代码签名或明确接受未签名分发风险后再上传。

### 2026-07-24 回执兼容修正

真实项目批次发现 QClaw 使用 `digestStatus`、`digestFiles` 和 `digestStats` 输出回执。Windows 0.10.7 增加有界兼容：只有项目、批次、完整文件集合、逐项 SHA-1 以及“实际消化数 + 明确跳过数 = 总数”全部闭合才自动结算；不完整或身份不一致的回执仍按原规则拒绝。该真实批次 46/46 个源文件 SHA-1 匹配，解析为 27 份实际消化、19 份明确跳过、0 份剩余。修正后全量自动测试为 `367/367`，主机端与学生终端 0.10.7 候选包均完成结构审计。
