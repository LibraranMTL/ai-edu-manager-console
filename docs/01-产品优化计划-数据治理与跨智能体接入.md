# AI教育管家产品优化计划：教育资料自动化、成长模型与可信学情报告

> 计划日期：2026-07-21  
> 当前基线：Windows 主机版 / Windows 学生终端 0.10.10；Android 学生终端维持现有兼容接口。
>
> 2026-07-25 产品定位：教育管家面向 AI 时代的学生—教师知识协作，围绕知识积累、知识生产、项目协作和技能发展形成闭环；Windows/Android 轻量学生端保持采集、上传和查阅的极简边界，需要本地知识处理与项目协作时升级为完整 Windows 知识节点，Android 知识节点未来单独立项；完整 Windows 客户端将“教学协作”统一改为“知识协作”。详细执行见 [内置直传版双主机后续开发计划](delivery/教师学生双主机知识协作与分发开发计划-v2-内置直传.md)。
> 修订版本：v6，已按“零常规人工审核、事件驱动、最低依赖和最少改动”原则收敛最小 P5；现有 LLM Wiki Engine 保持不变。
> 计划定位：在保持教育版稳定运行的前提下，优先打通“多渠道资料采集 → 原始资料 → 知识资产 → 消化与分析结果 → 成长模型 → 学情报告与教育档案定期输出”的顺滑闭环；可信数据治理和 Agent 调用细节在后台执行。  
> 相关计划：本计划面向整体产品；学习项目的既有闭环继续参照 [学习项目模块完整开发计划](delivery/学习项目模块后续开发计划.md)。

> 2026-07-21 决策：面向非专业用户的当前正式版本不增加外部知识引擎、数据库、技能包或常驻服务依赖。P0 以现有 LLM Wiki Engine 通过统一合同并完成暂缓决策为完成；GBrain 仅保留历史隔离评估材料，不再作为 P0/P1 补充闸门。

> 2026-07-22 决策：初期默认用户为教师、家长等可信成人。身份角色、细粒度权限、敏感信息设置、外部 Agent 授权和面向用户的审计功能全部后移至 P7；当前版本不提供对应设置入口。来源、去重、风险判断、证据链、事务回滚和历史记录仍由系统在后台维护，普通用户只看到结果、简明依据和真实异常提示。

> 2026-07-22 再聚焦：主机端作为管理员、教师和家长使用端，平板端作为学生使用端，当前以终端分工形成基础身份隔离。学生行动下发与反馈不进入本轮程序改造，继续由教师、家长管理学生提交并作为普通教育资料进入采集闭环。Agent 侧保留手工复制指令兜底，优先收敛现有直接执行和一站式任务收件箱；档案原生访问先建立统一只读合同，MCP 仅作为主机内嵌、零配置、可选适配方式，不成为普通用户必须理解或安装的组件。

> 2026-07-22 共享终端补充决策：不建设 PIN、密码和角色权限体系；学生终端分为个人终端与共享终端。个人终端固定绑定一名学生，共享终端通过扫码或输入稳定个人 ID 建立当前学生会话，主机按该会话限定资料上传、绑定项目、学情报告和教育档案。主机版“使用模式”由首页迁入系统设置并与主机服务、配对和设备模式合并。详细范围见 [Windows 0.9.9 使用模式与共享终端开发计划](delivery/Windows-0.9.9-使用模式与共享终端开发计划.md)。

> 2026-07-24 最小 P5 决策：正常资料批次不再设置人工确认闸门。系统按来源、学生范围、结构、冲突和多源稳定性自动分流；低风险可信内容自动采用，中风险内容自动继续观察，高风险异常不覆盖旧结果并合并显示为“需要补充”。不伪造人工审核记录，不增加分钟级全学生扫描。详细范围见 [Windows 0.10.6 最小 P5 开发计划](delivery/Windows-0.10.6-最小P5开发计划.md)。

## 一、优化目标

### 1. 总体目标

建立一套面向教师、家长等成人用户的教育资料与成长洞察系统。用户可以低门槛采集资料，系统自动完成整理、知识沉淀、成长证据归纳和学情报告生成；来源追溯、冲突处理和恢复机制在后台运行。当前底层固定使用现有 LLM Wiki Engine，统一接口只作为未来可替换边界。

### 2. 需要解决的核心问题

1. 文件资产治理较完整，但智能体对话、记忆、人设和规则的治理粒度不足。
2. LLM Wiki 主要是目录和 Markdown 协议，缺少稳定的 Claim、Evidence、实体和时间模型。
3. 教育资料进入系统后仍需较多人工整理、复制和确认，尚未形成连续自动处理流程。
4. 已确认知识尚未稳定、自动地沉淀为成长模型和可读的学情报告。
5. 身份角色、细粒度权限和敏感信息管理属于后续多主体部署问题，不作为当前主流程的前置条件。
6. 白皮书、README、操作手册和当前版本存在内容漂移。
7. 用户价值仍容易被内部流程和技术术语遮挡。
8. GBrain 已实现 Fact Store、Event Ledger、Relationship Graph、混合检索、MCP 和 Schema Pack，继续从零建设全部通用能力会造成重复投入。
9. 通用知识平台可以快速加载教育 Schema；教育管家必须把竞争壁垒推进到教育判断规则、儿童安全和行动效果反馈。

### 3. 明确不做

- 不在管家中重建一个功能弱于原生客户端的通用 Agent。
- 不要求所有 Agent 使用相同模型、插件、技能或内部工作流。
- 不让候选逐条打断用户；系统在后台自动分流，正常批次零确认，只有来源缺失、跨学生证据或关键冲突等真实异常提示“需要补充”。
- 不直接重写现有学生目录、ID、知识库或项目物理路径。
- 不一次性建立覆盖全部领域的庞大 Ontology。
- 不在当前阶段实施 A2A 多 Agent 编排、外部 Agent 授权或跨 Agent 查询接口。
- 不以增加更多报告、菜单和 Agent 名称代替数据协议建设。
- 不以追平 GBrain 的全部通用功能作为产品路线。
- 不在验证前把 GBrain 设为不可替换的唯一后端。
- 不把目录模板本身当作教育领域护城河。

## 二、目标产品架构

```text
教育产品与治理层（教育管家必须掌握）
Student / LearningProject / GrowthEvidence / LearningReport
教育判断规则 / 成长证据 / 报告规则 / 教师家长管理的学生提交
        ↓
Knowledge Governance Contract
Entity / Event / Claim / Evidence / Conflict / Review
        ↓
KnowledgeEngine 接口（可替换）
└─ 现有 LLM Wiki Engine（当前唯一部署实现）
        ↓
本地自动处理与任务网关
资料整理 / 知识候选 / ArchiveAccess / 可选内嵌 MCP / 成长建模 / 报告生成
        ↓
结果呈现、简明依据与一次确认

P7 延期储备（不属于当前主流程）：
身份角色 / 细粒度权限 / 敏感信息设置 / 对公网 MCP / ContextGrant / 跨主机 Agent 协作

采集入口贯穿各层：
文件 / 网页 / 截图 / 项目 / Agent 对话 / 人工录入
```

架构约束：

- 教育管家是教育规则、成长证据、报告规则和教育档案的权威层；学生行动反馈、权限与合规管理界面延期建设。
- KnowledgeEngine 提供存储、实体、事实、事件、图谱、检索和知识服务能力，但不能决定教育结论是否正式发布。
- Markdown/LLM Wiki 继续作为人类可读和可迁移层；结构化引擎不得成为不可导出的黑箱。
- GBrain 只能通过适配层接入，教育业务代码不能直接依赖其内部表结构或版本细节。

## 三、核心对象与数据协议

### 1. 最小通用对象

| 对象 | 作用 | 教育领域映射 |
| --- | --- | --- |
| `Profile` | 被持续管理的人或主体 | Student |
| `Project` | 有目标和生命周期的工作 | LearningProject |
| `KnowledgeSpace` | AI 筛选、分析和沉淀的知识空间 | 学生或项目 LLM Wiki |
| `Asset` | 文件、网页、截图等正式资料 | 文件资产 |
| `Interaction` | 用户与 Agent 的会话或消息 | 对话历史 |
| `Entity` | 人物、机构、课程、竞赛、能力等 | 学生、教师、学校、能力维度 |
| `Event` | 有时间的经历、考试、反馈或成果 | 项目节点、考试、教师反馈 |
| `Claim` | 可验证的事实、转述、推断或建议 | 能力判断、偏好、知识结论 |
| `Evidence` | Claim 的原始依据 | 文件、消息、项目、人工确认 |
| `Task` | 交给 Agent 或用户执行的工作 | 统一任务中心任务 |
| `AgentPolicy` | Agent 数据和工具权限（P7 延期对象） | 学生范围、知识范围、读写范围 |
| `DomainTemplate` | 领域对象、术语、目录和规则 | 教育模板 |
| `EducationPolicy` | 教育判断、证据和发布规则 | 成长证据、能力判断、申诉规则 |
| `KnowledgeEngine` | 可替换知识存储、检索与图谱接口 | 当前为 LLM Wiki；其他适配器暂缓 |
| `EngineBinding` | Profile/Project 与引擎实例的稳定绑定 | 学生知识库、项目知识空间 |

### 2. Claim 最小字段

```json
{
  "id": "claim-uuid",
  "profileId": "profile-uuid",
  "subjectId": "entity-uuid",
  "predicate": "learning.preference",
  "value": "更适合通过图形理解代数概念",
  "claimType": "observation",
  "observedAt": "2026-07-21",
  "validFrom": "2026-07-21",
  "validTo": null,
  "confidence": 0.78,
  "status": "pending_review",
  "evidenceIds": ["evidence-uuid"],
  "createdBy": "agent-or-user-id",
  "createdAt": "ISO-8601",
  "supersedes": null
}
```

`claimType` 第一阶段只允许：

- `fact`：有直接来源的事实；
- `reported`：某人或某资料的转述；
- `observation`：基于行为或资料的观察；
- `inference`：AI 或人工推断；
- `recommendation`：行动建议。

### 3. Evidence 最小字段

- 来源类型；
- 来源文件、对话、项目或人工记录 ID；
- 原始路径或稳定 URI；
- 原文片段或消息定位；
- 内容哈希；
- 来源时间；
- 采集时间；
- 提取 Agent；
- 是否仍可访问；
- 敏感等级。

### 4. AgentPolicy 最小字段（P7 延期协议草案）

本节仅保留未来多主体或外部 Agent 接入时的设计边界，当前版本不实现、不配置，也不向普通用户显示。

- Agent 身份和版本；
- 可访问的 Profile；
- 可访问的 KnowledgeSpace；
- 允许的资源类型；
- 是否允许读取原始资料；
- 是否允许读取敏感字段；
- 只读、提交候选或受控执行；
- 授权期限；
- 单次授权或持续授权；
- 调用和引用审计。

## 四、跨智能体协作协议（P7 延期储备）

本章不属于 P3—P6 当前交付范围。现阶段只复用已有本地任务能力完成教育资料自动处理，不新增对公网 MCP、外部 Agent 授权、跨主机 Agent 查询或协议设置界面。P4 的 `ArchiveAccess` 与可选内嵌 MCP 只是同一主机内的档案读取适配，不构成跨智能体授权体系。

### 1. 总体原则

> 任务标准化，Agent 内部能力不标准化。

管家统一任务身份、权限、上下文、产物、回执和审核；Agent 保留自己的模型、技能、插件、工具链和原生界面。

### 2. ContextGrant

管家为一次 Agent 工作生成短期上下文授权：

```json
{
  "grantId": "grant-uuid",
  "agentId": "codex-local",
  "profileIds": ["profile-uuid"],
  "resourceScopes": ["verified-claims", "project-assets"],
  "actions": ["read", "search", "propose"],
  "expiresAt": "ISO-8601",
  "taskId": "task-uuid"
}
```

默认不允许直接更新已确认知识。

### 3. TaskEnvelope

沿用并扩展现有统一任务中心协议，至少包含：

- `taskId`；
- `executionId`；
- `taskType`；
- `goal`；
- `contextGrantId`；
- 输入资源 URI；
- 预期输出；
- 风险等级；
- 超时和重试；
- 人工审核要求。

### 4. ResultEnvelope

Agent 返回：

- 执行状态；
- 产物列表；
- 实际引用的资源；
- 文件变更；
- 错误和未完成项；
- `KnowledgeProposal` 列表；
- 后续任务建议；
- Agent 和执行环境信息。

### 5. KnowledgeProposal

所有需要进入长期知识库的新内容都先成为候选：

```json
{
  "proposalId": "proposal-uuid",
  "taskId": "task-uuid",
  "claims": [],
  "evidence": [],
  "conflicts": [],
  "status": "pending_review"
}
```

### 6. 接入方式优先级

1. MCP Resources 和只读 Tools；
2. 原生 Agent 插件或技能；
3. 本地任务收件箱和结果目录；
4. CLI 或深度链接启动；
5. 复制指令、粘贴结果作为兼容降级。

A2A 仅在出现真正的 Agent 间委派、异步协作和远程 Agent 发现需求后引入。

## 五、分阶段优化计划

## 阶段 P0：KnowledgeEngine 边界与最低依赖决策

### 范围

1. 使用脱敏或虚构教育资料建立独立 GBrain 试验环境，不连接真实学生知识库。
2. 测试实体消歧、冲突事实、时间更新、图谱检索、MCP、多 Agent 查询和用户纠正。
3. 测试多学生隔离、敏感字段、原始资料权限、撤销和跨主机恢复。
4. 建立 `KnowledgeEngine` 合同，定义引擎初始化、导入、查询、事件、Claim、Evidence、关系、导出和健康检查能力。
5. 将能力分为 `adopt / adapt / build / defer`，形成正式技术决策记录。
6. 比较现有 LLM Wiki Engine 与 GBrain 在教育场景下的准确性、可追溯性、性能、运维和迁移成本。
7. 根据对比结论保持现有 LLM Wiki Engine，搁置 GBrain 生产接入、向量检索和长驻 transport 工作。

### 验收标准

- 不使用任何真实学生敏感数据完成验证。
- 十个预定教育场景均有可重复测试结果。
- 明确哪些通用能力直接复用、通过适配器使用、自研或暂缓。
- `KnowledgeEngine` 合同不暴露 GBrain 内部表结构。
- 任一引擎都能导出人类可读 Markdown/JSON 和稳定 ID 映射。
- 验证失败不会改变现有产品架构或知识库数据。

## 阶段 P1：Education Domain Protocol 与产品基线

### 范围

1. 冻结 `Student / LearningProject / GrowthEvidence / LearningReport / EducationPolicy` v1。
2. 定义事实、转述、观察、推断和建议的教育语义。
3. 定义什么可以成为成长证据，什么只能保持待观察。
4. 定义学生自述、家长观察、教师评价和 Agent 推断的不同证据权重与展示方式。
5. 定义反例、冲突、过期、申诉、撤销和历史保留规则。
6. 为现有 Student、文件资产、项目和成长证据建立兼容映射。
7. 更新产品白皮书，纳入可替换知识引擎、教育治理和跨 Agent 双入口定位。
8. 统一 Windows、Android、白皮书、README、手册和 CHANGELOG 的版本与术语。

### 验收标准

- Education Domain Protocol 有版本号、示例、必填字段和禁止行为。
- 同一份教师评价不会未经规则转换直接成为永久学生标签。
- 任一能力结论都能表达证据、反例、时间范围和审核状态。
- 白皮书、手册、版本清单和应用显示版本一致。
- 不再同时出现“每日行动建议”和“每周行动建议”作为不同现行概念。
- 现有学生 ID、项目 ID、文件和路径不发生改变。

## 阶段 P2：对话与多源资料可信治理

### 范围

1. 将原始对话保存为 `Interaction / ConversationAsset`。
2. 保存会话、消息、角色、工具、来源路径、时间和哈希。
3. AI 提取结果改为逐条 Claim 候选，不再直接追加到正式 UnifiedMemory 或 UnifiedSoul。
4. 增加逐条确认、拒绝、编辑、合并、冲突和过期操作。
5. 每条候选显示原始对话片段和消息定位。
6. 实现可恢复的知识晋升事务和真正的撤销。
7. 对话、截图、网页和 Agent 结果统一进入候选治理链路。
8. 增加重复检测、敏感数据提示、提示注入风险和批量上限。

### 验收标准

- 任一提取知识都能定位到原始内容和证据片段。
- 用户可以逐条选择，而不是只能按内容大类选择。
- 未审核候选不会进入正式长期知识。
- 撤销知识晋升后，正式文件、结构化索引和来源登记保持一致。
- 相同资料重复导入不会产生重复知识。
- 部分失败不会形成“界面成功、底层未写入完整”的状态。

## 2026-07-22 路线调整：先完成教育资料与档案自动化闭环

当前阶段假设主机操作者为管理员、教师、家长等可信成人，平板主要由学生使用。终端分工暂时承担基础身份隔离，不建设角色切换、复杂权限或学生行动反馈新功能。

近期唯一产品主线为：

```text
多渠道采集
→ 原始资料登记与去重
→ 知识资产筛选与生成
→ 多 Agent 消化、分析与结果回流
→ 成长模型增量构建
→ 学情报告与教育档案定期更新输出
```

已有来源记录、稳定 ID、去重、风险判断、候选状态、事务回滚和历史记录继续在后台生效。普通用户只看到“已收到、处理中、需要补充、已完成、报告已更新”和可读的来源依据，不承担审计工作。

### 目标可行性评估

| 能力 | 0.9.3 现有基础 | 主要缺口 | 更新决策 |
| --- | --- | --- | --- |
| 多渠道采集 | 文件、截图、分享收件箱、网页/对话/项目入口已有分散能力 | 入口、状态和后续处理不统一 | 建立统一采集中心和来源流水线 |
| 知识治理 | LLM Wiki、KnowledgeEngine 合同、来源/Claim/Evidence 和候选事务已存在 | 原始资料、知识资产、分析结果之间缺少统一可见状态 | 建立三层知识加工模型和自动晋升规则 |
| 多 Agent 执行 | 已有 Codex/OpenClaw 直接执行、QClaw 收件箱、ManualAdapter 和统一 TaskResult | 尚未贯穿整个资料到报告闭环；档案检索接口未产品化 | 复用任务中心，先统一收件箱，再增加只读档案访问合同 |
| 成长模型 | 已有成长证据、项目贡献和兼容映射 | 仍依赖分散触发，缺少稳定增量构建 | 由知识变化自动触发受影响部分更新 |
| 报告与档案 | 已有四类周期报告和教育档案 | 与知识/成长变化联动和定期输出不足 | 建立周期调度、差异更新和版本化输出 |
| 部署运维 | 当前 LLM Wiki 无额外数据库和常驻服务 | MCP 或外部引擎可能增加安装负担 | 不安装 GBrain；MCP 仅作为内嵌可选适配器 |

目标总体可行，工程重点不在更换知识引擎，而在统一采集、后台编排、档案访问和自动更新。所谓“不差于 LLM Wiki 和 GBrain”按核心教育场景体验验收，不要求复制 GBrain 的数据库、图谱工具数量或向量依赖。

## 阶段 P3：统一资料采集与三层知识流水线（建议 Windows 0.9.4）

### 范围

1. 建立统一“添加资料”入口，承接本机文件、文件夹、网页、截图、剪贴板、对话、项目资料、分享收件箱和 Agent 结果。
2. 自动识别资料类型、学生/项目归属、来源渠道和重复内容；无法判断归属时只询问一个业务问题。
3. 固化三层加工模型：`原始资料 → 知识资产 → 消化与分析结果`，每层使用稳定 ID 和来源 URI 建立关系。
4. 原始资料不可静默覆盖；重复内容只建立引用或更新来源关系，不重复生成知识。
5. 采集完成后自动创建后续处理任务，前台只显示“已收到、处理中、需要补充、已完成”。
6. 将资料数量、处理进度、结果摘要和唯一下一步收敛到同一主页面。

### 验收标准

- 新用户无需理解目录、哈希、批次或知识引擎即可在十分钟内添加第一批资料。
- 文件、网页、截图、对话、项目资料和 Agent 结果至少六类入口进入同一来源账本。
- 相同资料重复导入不重复保存、不重复消化、不重复形成知识。
- 每个知识资产和分析结果都能通过“查看依据”回到原始资料。
- 本阶段形成 Windows 0.9.4 程序包、CHANGELOG、构建审计和升级验证。

## 阶段 P4：知识自动治理与 Agent 原生档案访问（建议 Windows 0.9.5）

> 实际交付：Windows 0.10.3。保持现有 LLM Wiki Engine 和最低依赖部署，未引入 GBrain、数据库、向量服务或需要普通用户配置的长驻 MCP 服务。

### 范围

1. 复用现有 `TaskEnvelope / TaskResult / AgentExecutionAdapter`，把筛选、消化、摘要、实体/概念提取、综合分析和质量检查统一接入任务中心。
2. 建立一站式 Agent 收件箱：同一任务包包含目标、档案上下文清单、逻辑资源 URI、预期输出和引用要求；结果自动回到原任务。
3. 建立 `ArchiveAccess v1` 只读合同，最少支持 `search`、`getResource`、`listChanges` 和 `buildContextBundle`，默认只返回可用知识及来源引用。
4. Codex/OpenClaw 等可直接执行的 Agent 通过现有适配器获得受约束上下文；QClaw 等异步工具使用收件箱；不具备接口的工具继续使用复制指令和粘贴结果。
5. 在 `ArchiveAccess` 之上提供可选内嵌 MCP 适配器。由主机自动启动、自动发现和健康检查，不要求用户安装服务、配置端口或理解 MCP。
6. 多 Agent 自动化按任务能力路由，不在普通界面显示 Agent 角色、适配器、协议和路由评分；失败自动降级，最终保留人工复制兜底。
7. Agent 结果只能进入知识候选或分析结果层，由后台做来源、结构、重复和冲突检查，不能直接覆盖原始资料或正式成长结论。
8. 普通用户只执行一次“处理本批资料”或使用自动处理；正常批次最多一次结果确认。

### 验收标准

- 同一知识加工任务可分别通过直接执行、Agent 收件箱和人工复制三条路径完成，结果结构一致。
- Agent 无需用户逐次复制档案内容，即可检索任务所需知识并返回逐项引用。
- MCP 未启用或不可用时，主流程无功能损失，且不增加默认安装依赖。
- 自动路由、超时、重试、回执和降级均在后台完成，普通界面不出现 MCP、JSON、执行器或任务协议术语。
- 固定教育测试集的检索/治理场景保持至少 `10/10`，来源引用完整率为 `100%`。
- 本阶段形成 Windows 0.9.5 程序包、CHANGELOG、构建审计和升级验证。

## 阶段 P5：成长模型、学情报告与教育档案自动更新（目标 Windows 0.10.6）

> 本阶段采用最小改动方案，详细任务、自动分流规则和分阶段闸门见 [Windows 0.10.6 最小 P5 开发计划](delivery/Windows-0.10.6-最小P5开发计划.md)。
>
> 2026-07-24 开发状态：P5-A 至 P5-E 已完成；随后根据真实 QClaw 项目回执补充严格的 `digestStatus + digestFiles + digestStats` 兼容，形成 Windows 0.10.7 候选包。全量测试 `367/367` 通过，主机/学生终端安装包、CHANGELOG、三端手册和下载页已生成并审计。两个 EXE 的 Authenticode 状态均为 `NotSigned`；当前待完成原地升级、断网/真实资料闭环及真机发布验收。

### 范围

1. 先将启动全量修复和分钟级全学生扫描改为事件驱动、脏标记、按需重建及低频兜底，只处理受影响学生。
2. 将已采用知识、项目贡献和教师/家长管理的学生提交自动汇入成长模型；自动映射能力、项目、时间、来源、可信度和稳定证据 ID。
3. 后台自动分流：可信低风险内容自动采用；单次表现和仅 Agent 推断自动继续观察；来源缺失、跨学生或关键冲突不进入正式输出。
4. 不伪造人工 `confirmed` 审核记录；系统自动决策单独记录规则版本、来源、时间和原因。
5. 根据知识变化、项目阶段和周/月周期自动触发四类报告，确定性校验通过后自动发布；失败时保留上一版正式报告。
6. 报告正式结论通过“查看依据”下钻到成长证据、知识资产和原始资料；该入口只读，不承担批准功能。
7. 仅在发生实质变化时输出 Markdown、JSON、manifest 和变化摘要；可打印报告改为用户请求时生成。
8. 学生行动下发、平板打卡和自动反馈回流不改程序；教师、家长继续管理学生提交，提交内容按普通资料进入本闭环。

### 验收标准

- 新资料通过治理质量门后自动更新受影响的成长模型部分，不要求用户编辑 Markdown、索引或确认候选。
- 四类报告和教育档案按数据变化及周/月周期自动形成；无实质变化时不创建重复版本。
- 报告不使用观察项或异常项制造定论，资料不足时自动输出保守说明。
- 正常批次零人工确认；只有来源缺失、跨学生证据、关键冲突或用户主动纠正时显示一次“需要补充”。
- 启动不全量重建，空闲时不进行分钟级全学生扫描；单项异常不阻塞其他任务。
- 教育档案包可在无数据库和无 GBrain 环境中读取、备份、恢复和比较。
- 本阶段形成 Windows 0.10.6 程序包、CHANGELOG、构建审计和升级验证。

## 阶段 P6：体验基准、稳定交付与闭环验收（版本待 P5 验收后确定）

> P6 仅验收教育管家当前产品闭环，不引入外部知识引擎、外部数据库或新增常驻服务，也不设置外部知识引擎对比任务。历史技术调研不再作为 P6 开发、测试或发布闸门。

### P6-0：范围冻结与验收口径

- 固定九个子阶段、教育资料样本、统计口径、性能采样方法和发布阻塞项。
- 以当前 Windows 主机、Windows 学生终端和 Android 学生终端为唯一产品基线。
- 保持最低依赖部署、普通用户零技术配置、正常流程零人工确认和后台可信治理边界。

### P6-1：首页单一下一步

- 首页围绕“添加资料、处理中、需要补充、知识更新、成长变化、报告/档案更新”组织。
- 任一时刻只突出一个主操作；其余状态提供简洁进度和可选下钻。

### P6-2：普通模式术语降噪

- 普通模式隐藏候选、审核、风险、哈希、事务、回执、MCP、适配器和路由等内部概念。

### P6-3：固定资料集十场景

- 使用固定教育资料集验收六类采集、重复导入、自动消化、Agent 降级、档案检索、引用回溯、成长更新、周期报告、档案导出和备份恢复。
- 自动记录完成率、用户操作次数、检索命中、引用完整率、P95 等待时间和恢复成功率。

### P6-4：首次使用与零确认闭环

- 新用户在十分钟内完成首次资料采集并得到自动处理结果。
- 正常批次零人工确认；真实异常汇总为一条“需要补充”，不暴露治理细节。

### P6-5：升级、离线、降级与恢复

- 完成最低依赖新装、0.9.3 原地升级、断网读取和处理、Agent 全部不可用降级及异常中断恢复验证。
- 自动执行不可用时保留任务上下文，并降级到统一收件箱或人工复制，不要求重新创建任务。

### P6-6：引用、幂等、一致性与性能

- 正式结论来源引用完整率为 `100%`；相同输入重复执行不产生重复资产、知识或报告。
- 空闲状态不进行高频全量扫描；大资料库、历史协作包和大型工作空间采用增量、分页和有界处理。

### P6-7：三端与换机恢复联调

- 完成 Windows 主机主流程、Windows 学生终端、Android 学生终端现有资料提交/查阅能力和换机恢复联调。
- 学生端继续只显示当前学生及其有效关联项目；本轮不增加学生行动反馈交互。

### P6-8：稳定交付

- 完成独立版本程序包、CHANGELOG、构建审计、白皮书、网站和三端操作手册。
- 自动测试、人工界面评估和真机门禁均通过后，才进入正式发布。

### 验收标准

- 正常闭环为“添加资料后后台自动运行并更新结果”，普通用户不需要确认候选、选择 Agent 或理解知识引擎。
- 核心十场景和新增长流程均全部通过。
- 已采用结论来源引用完整率 `100%`，相同输入重复执行不产生重复资产、知识或报告。
- Agent 原生路径失败时自动回退到一站式收件箱或人工复制，任务上下文和结果不丢失。
- 0.9.3 升级、备份恢复、换机和断网读取均通过验证。
- 本阶段形成独立后续版本程序包、CHANGELOG、构建审计、白皮书和操作手册。

## 阶段 P7：延期能力与重新立项条件

以下工作不进入当前低门槛版本，只有出现学校多角色部署、外部联网 Agent、明确合规要求或真实客户需求时才重新立项：

1. 学生、家长、教师、管理员账号体系、角色切换和细粒度权限设置。
2. 敏感字段管理、授权期限、数据主体请求和专门审计操作台。
3. 学生行动下发、平板打卡、提醒和自动反馈回流。
4. 对公网 MCP、远程 Agent 授权、跨主机 Agent 查询和 A2A 编排。
5. GBrain 生产接入、向量检索、reranker 和外部模型查询扩展。
6. 通用内核、健康等新领域模板和跨领域迁移。

重新立项时必须保持当前教育版、Student 接口、业务 ID、知识库路径、`ArchiveAccess` 合同和最低依赖部署兼容；不得为了通用化要求现有用户迁移资料。

## 六、推荐开发顺序

```text
1. P0–P2 已完成：引擎边界、教育协议、审核减负和多源候选治理
2. P3 / 0.9.4：统一资料采集与三层知识流水线
3. P4 / 0.9.5：知识自动治理与 Agent 原生档案访问
4. P5 / 0.10.6：最小成长模型、学情报告与教育档案自动更新
5. P6 / 后续版本：体验基准、稳定交付与闭环验收
6. P7：出现明确需求后再立项角色权限、学生行动反馈、远程 Agent、GBrain 和通用内核
```

依赖关系：

- 没有 KnowledgeEngine 边界和当前引擎验证，不能安全推进教育数据治理。
- 没有 Education Domain Protocol，不能判断底层 Claim 是否可成为正式成长证据。
- 没有统一采集和“原始资料—知识资产—分析结果”流水线，后续模型仍会依赖大量人工搬运。
- 没有统一 Agent 收件箱和只读档案访问合同，多 Agent 自动化仍会退化为反复复制档案内容。
- 没有稳定的成长模型增量构建，学情报告和教育档案不能可靠定期更新。
- 角色权限、学生行动反馈、远程 Agent 和外部写回不再是当前教育主流程的前置依赖，整体后移到 P7。
- 没有兼容层，不能直接抽取通用内核或切换知识引擎。

## 独立开发线 C0—C2：第三方课程资源目录

第三方课程资源目录作为独立产品开发线推进，不改变 P3—P6 的教育资料自动化主线，也不并入 D4 知识协作协议。

目标是提供“精选资源 → 用户主动打开 → 主动采集 → 原始资料 → 知识整理”的低门槛入口，而不是建设完整 LMS。Windows 主机端、Windows 学生端和 Android 学生端使用统一的版本化课程目录；Windows 使用隔离 `WebContentsView`，Android 使用独立安全 WebView。课程采集必须由用户主动触发系统录屏授权，并绑定当前学生、课程、页面来源和目标资料库。

阶段划分：

1. C0：课程目录合同、首批素材、域名白名单、版本校验、回滚和商务/版权边界；
2. C1：三端“精选课程”入口、安全内嵌浏览和当前学生有效目录；
3. C2：屏幕资料采集闭环、主机轻量启用/隐藏/排序/分配、目录下发及正式发布；
4. C3：平台课程运营管理中心、多租户、审核和使用分析，待课程与客户规模扩大后重新立项。

客户主机在 C0—C2 只负责接收、校验、缓存、合并和分发课程目录，不提供平台全局课程编辑能力，不存放签名私钥，也不增加普通用户复杂角色权限设置。详细任务与验收标准见 [第三方课程资源目录开发计划](delivery/第三方课程资源目录开发计划.md)。

## 七、测试与发布闸门

### 1. KnowledgeEngine 合同与隔离测试

- 使用固定虚构教育语料持续验证现有 LLM Wiki Engine；历史外部引擎对比结果仅作决策证据；
- 验证稳定 ID、Claim、Evidence、关系、权限、导出和健康检查语义一致；
- 验证适配器停用、引擎不可用和版本不兼容时安全降级；
- 验证切换引擎不会改变 Student、LearningProject 和 GrowthEvidence 等教育对象 ID；
- 任何未来外部引擎试验均禁止导入真实学生资料，并与正式知识库、凭据和备份完全隔离；
- 导出的人类可读 Markdown/JSON 能在脱离原引擎后被审计和恢复。

### 2. Education Domain Protocol 测试

- 学生自述、家长观察、教师评价和 Agent 推断按不同证据类型处理；
- 单次行为、第三方转述和模型推断不能直接形成永久学生标签；
- 冲突证据、反例、过期、纠正和申诉能够保留完整历史；
- 学习建议、实际执行、反馈和结果变化彼此关联，但不自动推断因果；
- 教育协议版本不兼容时拒绝静默写入正式知识。

### 3. 数据一致性测试

- 原始资料、知识资产、分析结果的关系和状态全链路测试；
- 对话导入、提取、采用和撤销全链路测试；
- Claim、Evidence、来源索引和 Markdown 文件一致性；
- 失败回滚和重复执行幂等；
- 跨主机路径和稳定 ID；
- 旧知识库兼容。

### 4. 自动处理与 Agent 档案访问测试

- 文件、文件夹、网页、截图、剪贴板、对话、项目资料和 Agent 结果统一采集；
- 自动归属、去重、任务创建、回执核对、超时、重试和恢复；
- 直接执行、收件箱和人工复制生成一致 TaskResult；
- `ArchiveAccess` 搜索、资源读取、变化列表和上下文包结果带稳定来源引用；
- 内嵌 MCP 禁用、异常或未安装兼容 Agent 时自动降级，不影响主流程；
- 多 Agent 路由和治理细节不进入普通用户界面。

### 5. 成长模型、报告与档案测试

- 已确认知识到成长证据、能力画像、项目贡献和时间线的一致更新；
- 四类报告的数据变化和周期触发；
- 只引用已确认成长模型；
- 草稿生成、确定性校验、自动发布和报告刷新；
- 无实质变化与资料不足的保守输出；
- 报告结论下钻到成长证据和原始资料；
- 教育档案 Markdown、JSON 和可打印输出的版本、变化摘要与恢复；
- 相同输入重复执行幂等，无实质变化时不制造新结论或新版本。

### 6. 普通用户流程测试

- 十分钟内完成首次资料采集并得到自动处理结果；
- 正常批次零人工确认，真实异常最多汇总为一条“需要补充”；
- 主流程不显示 JSON、哈希、批次、MCP、事务或审计术语；
- 后台失败时显示可读状态并可自动重试；
- 无自动 Agent 时降级入口仍可用但不占据主流程。

### 7. 发布闸门

- 全量自动测试通过；
- 外部引擎形成明确的暂缓决策，不进入默认依赖、安装说明和发布闸门；
- KnowledgeEngine、ArchiveAccess 和 Education Domain Protocol 合同测试通过；
- 引擎切换、停用或导出不会改变教育业务对象 ID；
- 当前版本、白皮书、README、手册、CHANGELOG 和发布清单一致；
- 旧知识库只读迁移审计通过；
- 未通过来源、范围、结构、冲突和稳定性校验的 Agent 内容不能进入正式知识或报告定论；
- 当前单一可信成人、本机使用假设在发布说明中明确；
- 备份恢复和回滚验证通过；
- 0.9.3 原地升级与每阶段独立程序包验证通过。

## 八、产品效果指标

### 1. 激活指标

- 首次采集到第一条可确认知识的时间；
- 完成首次知识确认的用户比例；
- 从采集到知识候选的自动完成率。

### 2. 治理质量指标

- 未确认、冲突和过期 Claim 数量；
- 用户驳回率和纠错率；
- 重复资料和重复知识减少量；
- 撤销操作成功率。

### 3. 自动化使用指标

- 自动任务完成和结果匹配率；
- 无需复制粘贴完成的处理比例；
- 人工复制粘贴降级比例；
- Agent 档案查询引用完整率；
- 直接执行、收件箱和人工路径的结果一致率。

- 成长模型、学情报告和教育档案按期更新成功率；
- 用户主动纠错和补充的知识数量；
- 完整备份与恢复成功率。

## 九、主要风险与控制措施

| 风险 | 控制措施 |
| --- | --- |
| 重复自研外部平台已有的通用能力 | 只建设当前教育主流程确实需要、且能保持最低依赖的能力 |
| 被外部引擎的数据模型或版本锁定 | 当前不接入外部引擎；未来也只能经 KnowledgeEngine Adapter 使用 |
| 通用知识平台快速增加教育 Schema | 把壁垒放在 Education Domain Protocol、资料到档案闭环和家庭/学校交付，而不是目录模板 |
| Ontology 设计过重 | 从 Claim/Evidence 和少量稳定关系开始，按领域模板扩展 |
| Agent 接入后能力下降 | 复用已有本机 Agent 适配器，以 ArchiveAccess 解耦；MCP 只做内嵌可选适配，不成为依赖 |
| 用户操作继续复杂 | 普通模式只显示唯一下一步，处理、回执和治理细节在后台完成 |
| 错误知识被多个 Agent 放大 | 未确认内容默认不开放；查询结果强制带来源和状态 |
| 延期权限能力造成边界误解 | 发布说明明确当前仅面向单一本机可信成人；学校多角色或外部 Agent 场景必须重新立项 |
| 对话提取污染长期记忆 | 逐条候选、证据片段、冲突检测和可撤销晋升 |
| 学生行动反馈扩大范围和使用负担 | 本轮不改学生行动反馈程序；教师、家长管理的学生提交作为普通资料采集 |
| 通用化破坏教育版 | 保留 Student 适配层，原地兼容，按需迁移 |
| 自动 Agent 不可用 | 保留本地 API、人工任务包和复制指令降级，但收纳到高级操作 |

## 十、完成定义

本轮整体优化完成，应同时满足：

1. `KnowledgeEngine` 合同完成；现有 LLM Wiki Engine 通过合同测试，GBrain 已实现适配器或有证据充分的暂缓决策。
2. Education Domain Protocol 完成版本化，能够约束成长证据、推断、建议、纠正、申诉和禁止行为。
3. 文件、对话和 Agent 结果都进入统一的数据治理链路。
4. 正式知识以 Claim/Evidence 为核心，能够追溯、冲突、过期和撤销。
5. 文件、文件夹、网页、截图、剪贴板、对话、项目资料和 Agent 结果可以从统一入口进入后台自动处理。
6. 原始资料、知识资产和消化/分析结果形成稳定、可追溯、可重复执行的三层流水线。
7. 同一 Agent 任务可通过直接执行、一站式收件箱或人工复制完成；Agent 可通过 ArchiveAccess 原生读取所需档案并返回来源引用。
8. 已确认知识能够自动沉淀到成长模型，并保持能力画像、项目贡献、成长证据和时间线一致。
9. 四类学情报告和教育档案能够根据成长模型及周期变化自动形成，且不使用未确认候选制造结论。
10. 学生行动反馈不新增程序功能；教师、家长管理的学生提交可以作为普通资料进入闭环。
11. 普通用户不需要理解 JSON、SHA-1、MCP、任务批次、事务、Agent 路由或底层知识引擎即可完成主流程。
12. 正常资料处理、成长更新、报告发布和档案更新零人工确认；只有真实异常进入“需要补充”。
13. 核心教育治理十场景保持 `10/10`，正式结论来源引用完整率为 `100%`，Agent 不可用时可无损降级。
14. 身份角色、细粒度权限、敏感信息功能、学生行动反馈、远程 Agent、GBrain 和通用内核明确标记为延期能力。
15. 教育版现有学生、项目、路径和知识库保持兼容，并可导出为人类可读格式。
16. 后续每次阶段交付都有一致的版本号、程序包、构建审计、白皮书、手册和 CHANGELOG。
