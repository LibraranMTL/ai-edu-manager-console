# Windows 主机版快捷采集工具条开发计划（评估完善版）

日期：2026-10-01

状态：**基础工具条已于 2026-10-05 随 Windows 主机 0.19.6 正式发布；屏幕直接采集与悬浮拍照增量已完成开发和用户确认的真机验收，并于 2026-10-07 随 Windows 主机 0.19.9 正式发布。**实施证据见《Windows主机版-快捷采集工具条开发记录-2026-10-02.md》《Windows-0.19.9-工具条直接采集候选验收-2026-10-06.md》和《Windows-0.19.9-正式发布记录-2026-10-07.md》。
适用范围：Windows 主机便携版。学生端网页、Android 和未来安装包的系统分享集成只作为已有来源或后续独立事项，不因本计划自动升级。

## 1. 产品判断与目标

快捷采集工具条不是再造一个缩小版“收集与整理”页面，而是让用户在阅读网页、上课、讨论项目、使用 WPS 等场景中，以最少的切换完成“采集并确认已收到”。后续的分类、转写、投递、消化、形成成长证据，仍在主机的受控流程中完成。

产品价值应以**资料被正确归属、可追溯并进入学生或项目知识流程**衡量，而不是浮条按钮数量或采集次数。与通用网页剪藏、笔记工具相比，教育管家的差异化重点是学生隔离、来源回执、项目关联、证据状态和可恢复处理。浮条应优先降低资料进入系统的阻力，同时避免让“已接收”看起来像“已整理”或“已确认成长证据”。

本计划目标：新建一个统一、可最小化的快捷采集入口；逐步接入屏幕截图、录音、拍照、本机文件导入快捷入口、资料收件箱和已授权会话采集。**屏幕录像暂时排除在本计划之外**：不开发、不做本期可行性验证，也不显示录像按钮。第一期不把所有采集功能都塞进常驻浮条，也不以自动采集为默认。

## 2. 当前基线与不可混淆的边界

以 2026-10-01 的本地源码观察，主机已有屏幕采集会话及独立浮动控制条；它以连续截图、时间线和后续处理为主，**不是带音视频轨道的屏幕录像**。拍照和录音入口已经有初步可用的页面组件；录音使用页面内 `MediaRecorder`，切走页面会清理媒体流，且页面卸载后的停止回调不会再保存录音。拍照／录音单项收件箱目前限 20 MiB，录音最长 30 分钟；把同样的实现直接搬进会重绘或重新加载的浮条，不能解决中断和丢失问题。主机另有分享接收目录和可选下载文件夹入口，浮条应指向这些既有收件链，而非创建第二套收件箱。

| 能力 | 当前基线 | 本计划处理方式 |
| --- | --- | --- |
| 屏幕采集 | 已有独立控制条和截图会话 | 在验证控制能力后迁入统一外壳；旧入口保留兼容映射，避免两条浮条并存 |
| 拍照 | 页面内打开摄像头、拍摄、进入当前学生收件箱 | 从浮条唤起独立拍摄面板；保持预览、重拍与接收回执 |
| 录音 | 页面内录制、结束后整段提交 | 首版浮条只跳转“收集与整理 → 录音采集”；跨页面稳定录制通过验证后，才考虑浮条内控制 |
| 本机文件导入 | “收集与整理 → 资料导入”已有导入位置选择和本机资料导入操作 | 在浮条“更多”提供快捷入口，打开现有页面；不绕过文件、学生与目标确认 |
| 分享／下载文件 | 当前学生分享目录和用户指定下载文件夹分别存在 | 显示待处理数并打开既有收件箱；不声称浮条能接管所有系统“保存”对话框 |
| Agent 会话 | 存在受权接收及自动采集路径 | 只显示授权状态和待处理入口；不因打开浮条扩大权限或读取原始会话全文 |
| 屏幕录像 | 与现有截图采集不同 | 明确排除本计划；如未来重启需求，另立计划和验收 |

既有《Windows 主机版拍照、录音与分享采集开发方案》定义收件、投递与回执合同；本计划只增加跨场景入口和持续会话能力，不改写其受控资料归属规则。

## 3. 推荐交互：少而明确

### 3.1 默认与展开状态

默认紧凑态只展示当前学生简称、当前项目（如已选）、“屏幕采集”“录音”“拍照”和“更多”。首版“录音”按钮明确写作“打开录音采集”，跳转相应页面；没有浮条内录音会话时，不在浮条上显示虚假的录制计时、暂停或结束。只有后续稳定录音能力通过验收，才增加醒目的计时、暂停／结束和设备状态。空间不足时优先保留进行中会话的“停止／结束”和状态，不靠悬停才能看到关键操作。“更多”中提供**本机文件导入**、资料收件箱、分享接收目录、下载文件收件箱、会话采集状态及设置入口。收件箱角标仅代表当前已授权范围内的**待处理数量**。若后续实际使用数据显示本机导入明显高频，再允许用户把它固定到主浮条，首版不预设第四个常驻按钮。

浮条提供拖动、贴边吸附、隐藏／恢复、关闭浮条但不误结束采集，以及托盘恢复入口。不得默认遮住教学软件主操作区；多显示器、不同缩放比例、任务栏位置和窗口尺寸变化后，位置应被约束到可见工作区。全屏演示时遵循用户选择的“保持显示／暂时隐藏”，不自作主张覆盖内容。键盘可达、可读标签、显著焦点和高对比度状态是第一期验收项。

采集前可快速确认归属：**学生必选；项目可选**。开始会话时锁定 `studentId`、项目目标和来源；主界面后来切换学生，不会改变进行中的会话。若要改学生，先结束或取消当前会话，再明确开启新会话。浮条只显示最少的学生信息，不在桌面悬浮层展示敏感档案、转写全文或截图预览缩略图。

### 3.2 一个动作对应一个准确状态

对由浮条实际控制的会话，统一显示“准备中 → 采集中 → 保存中 → 已接收待投递 → 已投递”；需要转写／消化时另显示其独立状态。对首版录音跳转，只显示“已打开录音采集页面”，录制状态和结果以该页面及主机回执为准。失败分为“设备不可用／拒权”“原件未完整保存”“已保存但投递失败”“后续 AI 处理失败”，分别提供重试或打开收件箱。**只有主机校验完整原件并取得接收回执后，才显示‘已接收’。**

退出、锁屏、关机、麦克风拔出、摄像头占用、磁盘不足时，浮条须给出可恢复或明确不可恢复的结果。不能让旋转状态无限持续，也不能用“已采集”掩盖写入失败。任何自动恢复不得重新打开麦克风或摄像头；用户必须再次显式启动设备采集。

### 3.3 避免增加日常负担

默认“采集到当前学生收件箱”，不要求每次填写分类；可从浮条直接切到收件箱后选择“学生原始资料库／关联项目收件箱”。最近使用的项目可供显式选取，但不得静默继承到另一学生。高级选项（设备、画质、识别引擎、文件诊断、自动规则）收在设置页，不占默认浮条面积。“本机文件导入”仅打开现有“资料导入”页面并带上当前学生上下文，由用户在那里选择文件和导入位置、确认现有移动／导入规则；不能因点击浮条入口就自动移动本机文件。拍照／录音与手动文件导入在入口和状态上清楚区分，避免用户以为选文件就是完成设备采集。

## 4. 技术方案与接口边界

### 4.1 浮条外壳与会话内核分离

采用独立轻量 `BrowserWindow` 承载统一浮条，只负责呈现状态、发出用户命令和导航；主机侧的 `CaptureCoordinator` 持有唯一真实会话、权限校验、写入状态和接收回执。浮条销毁、重绘、切页面或隐藏，不应销毁已开始的合法采集会话。窗口与主界面通过异步 IPC 订阅同一个只读状态快照，命令带请求 ID 和会话版本；重复点击“开始／结束”不会生成重复资料。

控制器将来源适配器统一为“探测能力 → 准备 → 开始／暂停／结束 → 持久化 → 收件回执 → 清理资源”的合同，但**不强迫不同媒体共用同一个录制实现**。屏幕截图、麦克风录音、摄像头拍照、文件收件和授权会话各保留自己的设备、权限与资源边界。持久化结果统一落到既有学生专属受控目录与收件／项目机制；不在浮条 `localStorage` 里存原件或决定归属。

应增加可查询能力状态：可用、未授权、无设备、设备占用、宿主不支持、后端暂不可用。未知能力不可因为工具已安装或按钮存在而宣称“可用”。原有屏幕浮条退出统一外壳时须有迁移映射，且一个采集会话仅有一个主要控制面。

### 4.2 录音先跳转页面，稳定后再评估浮条控制

首版“录音”按钮只唤起主机窗口并定位到“收集与整理 → 录音采集”，不在浮条中申请麦克风或启动第二个 `MediaRecorder`。跳转时保留并确认当前学生；录音进行中若用户试图切页、换学生或关闭主机窗口，应在页面给出明确的中断风险提示。现有页面录音离开页面可能中断，因此该降级路径只能称为“快捷到达录音页面”，不能宣称“跨页面持续录音”或“关闭主窗口后继续录音”。

只有产品使用数据表明录音跨应用持续控制确有明显收益，且技术验证证实可靠，才另启浮条内控制：将录制生命周期从 `CaptureInboxPanel` 移出，优先验证在独立、不会因主界面切页而卸载的媒体窗口中采集，并将分片及时交给主机写入受控临时原件；若 Electron/Windows 组合下窗口销毁或后台行为不可靠，转为主机管理的受控录音进程／原生模块技术验证。不能继续把 30 分钟音频全部留在页面内存中，结束时一次性转 base64 提交。未达到可靠性门槛就继续保留跳转方案，不阻塞浮条其他入口交付。

如开展浮条内录音，保留现有 20 MiB 单项限制与 30 分钟上限作为**当前合同**，但这两个值的关系需在技术验证中核算；达到容量阈值前要预警并安全结束，不允许无声截断。分片必须有序号、校验、重试／去重和最终封口回执；未封口原件在重启后显示为“中断待处理”，由用户选择保留可恢复部分或移入回收站。原音频、转写文本、人工修订各有独立状态；未授权云端识别不上传音频。

### 4.3 屏幕、拍照与收件来源

- 屏幕截图：先复用现有会话语义（区域／窗口来源、暂停、结束、隐私排除与时间线），再把按钮迁到统一外壳。迁移时检查浮条本身不被采入画面、窗口隐藏前后来源 ID 不变、切屏和 DPI 变化不造成错误归属。
- 拍照：用户点击后才打开摄像头；设备面板完成预览／重拍、确认保存，取得主机接收回执后释放摄像头。浮条只保留入口和结果，不承载长期视频流。
- 本机文件导入：从浮条“更多”打开既有“收集与整理 → 资料导入”，保留当前学生且仍由主机重新校验学生与目标；不复制一套文件选择器、导入任务或成功提示到浮条。用户取消时不创建接收记录或移动文件；导入结果以原页面和主机回执为准。若当前学生在跳转期间改变，必须重新确认，不沿用旧学生的预选项目。
- 分享与下载文件：浮条打开既有分享收件箱或下载文件收件箱；只对明确选择的项目做投递、回收或删除，不自动吞入整个下载目录。WPS“另存为”和浏览器下载可由用户把目的地选成一个易找到的自定义文件夹；这是用户配置路径，不是系统级拦截。收件数应区分“已发现未登记”“待投递”“失败”，避免误导。
- Agent 会话：继续遵循已有授权范围与接收规则。浮条可显示“已授权／未授权／待处理”，并链接到管理页；不直接触发读取所有 Agent 历史或自动投递。

Windows 原生 Share Target 涉及应用包身份与系统注册。便携 EXE 不应承诺只靠新浮条就出现在系统分享面板；若未来确有需求，另立打包身份和系统兼容性验证，不作为本期交付门槛。

### 4.4 安全、隔离与性能

每次命令由主机复核当前许可、角色、`studentId`、项目可写范围与目标状态；UI 传入的学生和路径都不能单独作为授权依据。原件、暂存、回收及任务日志按学生分区，外部文件名仅作显示，不参与路径拼接。拒绝符号链接／越界路径、超限媒体和无权限来源。应用关闭、异常退出和重试均应留下可审计回执，不复制完整截图、对话或转写进普通日志。

悬浮窗只查询轻量会话快照和待处理计数；启动时不扫描全部学生档案或全量下载目录。计数使用增量索引／有界轮询，隐藏后降频。麦克风、摄像头和屏幕权限按实际使用时申请，停用后立即释放。Windows 内容保护、置顶行为与全屏排除必须在真机上验证，不以 API 存在替代验收。

## 5. 分期开发与每期退出条件

### 5.1 优先级评估

**整体建议定为 P2：重要的使用体验优化，但不是阻塞核心业务或当前版本发布的 P0／P1 修复。**理由是已有收集页面和屏幕采集浮条能完成基础入口，统一浮条主要减少跨应用操作步骤；与此同时，独立常驻窗会引入多屏定位、权限提示、学生归属和资源占用等新增风险。优先把“资料正确接收、投递与可恢复”“已有采集入口稳定”“已报告且仍未验收的云端同步／联网研究故障”处理到可用，再投入统一浮条。这里不推定这些历史问题目前一定仍存在，启动前应核对实际状态。

阶段内再分层：C0 范围／交互合同和 C1 的导航型入口可作为下一轮短周期 P2 任务；C2 的既有屏幕控制迁移以实测无回退为条件；C3 的个性化快捷配置、会话状态优化为 P3。**浮条内稳定录音属于可选 P3，不是首版依赖项**，继续跳转页面即可。若真实用户数据显示跨应用采集造成大量资料遗漏，且核心接收链已稳定，可将 C0–C1 提升为 P1；提升依据应是可核对的任务完成率、遗漏／重复投递和用户耗时，不凭按钮点击量决定。

### 5.2 分期与退出条件

| 阶段 | 范围和交付 | 进入下一期的退出条件 |
| --- | --- | --- |
| C0 合同与交互验证 | 锁定学生归属、会话状态、错误分类、窗口行为、收件回执；做可丢弃 UI 原型和设备权限验证 | 与既有收件／屏幕会话合同无冲突；普通用户能区分“已接收”和“已投递”；确定可恢复写入策略 |
| C1 统一外壳与低风险入口 | 独立浮条、托盘恢复、屏幕采集入口、拍照入口、录音页面跳转、“更多”中的本机文件导入与分享／下载收件箱入口；此期可继续唤起既有屏幕控制，不假称已统一 | 三学生切换不串档；多屏／缩放／最小化正常；拍照回执可靠；录音按钮正确打开当前学生录音页、没有第二条录音会话；文件导入取消不移动文件；无重复导入流程或收件箱 |
| C2 既有屏幕控制迁移 | 把现有屏幕截图控制迁入统一外壳，淘汰同时显示的旧浮条；录音仍按 C1 跳转页面 | 屏幕截图功能和性能不低于旧版；仅一套控制条；录音跳转不受迁移影响 |
| C3 会话与资料入口优化 | 授权会话状态、待处理计数、最近项目选择、收件／投递跳转和可访问性完善 | 未授权时不读取会话；待处理数与列表一致；失败可在原页面继续处理 |

可选 R1（不计入首版和 C0–C3 交付）：只有录音可靠性与产品价值双门槛通过，才实现主机可恢复录音会话、分片保存与浮条控制；测试页面切换、浮条重绘、异常重启、权限撤销和容量阈值。未通过则维持页面跳转，不回退其他已交付入口。

每一期只做一个可回退、可验收的增量。任何期次交付候选版时，须单列源码实现、自动测试、Windows 真机、不同硬件、签名、Git 与线上发布状态；未执行项写“未验收”。当前 0.19.5 源码版本观察只用于定位基线，本计划**不指定新版本号或发布日期**。

## 6. 测试矩阵与量化目标

自动测试覆盖会话状态机、命令幂等、不同学生和项目范围、旧链接兼容、错误回执、部分写入与重启恢复、收件计数、设备能力降级；模拟重复结束、迟到分片、保存成功但 UI 断线、切学生、撤销授权、磁盘满、网络断开和进程异常。媒体适配器使用伪设备合成测试，不把它当成真实硬件验收。

本机验收至少覆盖三名非敏感测试学生、两个项目、多显示器／DPI、主界面切页与关闭、浮条隐藏／恢复、锁屏、麦克风／摄像头拒权及占用、单项超限、后台任务失败、原件回收与重试。另测本机文件导入的学生与项目预选、文件选择取消、导入过程中切换学生、导入失败后源文件状态，核对与原页面结果一致。屏幕源中不得出现浮条或私密预览；录音须人工听检连续性；照片须核对清晰度、方向和目标归属。性能对照记录空闲占用、启动额外耗时、浮条唤起延迟和连续采集资源增长；以旧版屏幕采集为对照，发现明显退化则不替换旧浮条。

建议在 C0 冻结可量化门槛，并在候选验收报告填写实测值：例如“采集完成至接收回执时间”“错误学生归属次数（目标为 0）”“异常退出后可找回原件比例”“收件箱待处理数一致率”“浮条误遮挡／误点反馈”“资料接收后七日内完成投递的比例”。这些是后续产品指标，不应在未测前写成达成事实。避免以‘工具条点击率’替代资料价值。

## 7. 风险、取舍与待决策项

1. **功能拥挤**：默认只有高频直接采集，其他来源放“更多”；若真实使用数据显示高频项不同，再允许用户自定义排序，不在首版开放无限按钮插件化。
2. **录音丢失**：首版只跳转原录音页，并明确当前页面的离开中断风险；浮条内录制不是上线门槛。未来若开发浮条内录制，从页面解耦、分片写盘和异常恢复才是该能力的上线门槛，不能提前宣传为稳定录音。
3. **隐私与误归属**：学生／项目开始时锁定；会话切换需明确结束；媒体权限只在用户发起时申请；原始会话和未核验资料不自动变成学情结论。
4. **收件箱重复**：浮条是入口和状态视图，复用主机既有接收账本；下载文件夹为用户自选路径，不默认监控整台电脑。
5. **屏幕录像范围**：已按本次决定从本计划排除；现有“屏幕采集”仍指截图会话，不得更名或宣传为录像。
6. **平台差异**：便携 EXE 的系统分享集成、置顶和内容保护存在 Windows／Electron 约束；真实设备验收前不作为已实现卖点。

确定的产品取舍：整体按 P2 排期，先交付“轻量浮条 + 可靠归属 + 已有收件链”；录音先跳转相应页面，浮条内控制仅作可选 P3。本机文件导入需要快捷可达，但先放在“更多”中复用现有页面，不做第四条并行导入链。屏幕录像不属于本计划，也不作为本计划交付的前置条件。

## 9. 2026-10-06 执行增量：屏幕直接启动与悬浮拍照

用户已授权优先实施这两项优化。本节将这两项由第一阶段的页面入口推进为直接控制，其余阶段边界继续适用。

- 屏幕采集：工具条内展开来源缩略图、关联范围、时长和策略；用户明确选源后开始。沿用既有截图会话及暂停、继续、重点截取、结束和采集箱入口。取消设置、成功启动后恢复窄条；尚未启动时切换学生立即使设置失效。

- 主进程校验许可、有效学生、采集来源及项目关联／封存状态；屏幕启动防并发，照片保存按会话及照片编号去重。新窗口只允许自身主动请求视频权限，不授权麦克风或外部导航。
- 录音、文件导入、资料收件箱及会话入口保持原流程；录像继续排除。“使用上次设置快速启动”留待本轮真机验证后评估。
