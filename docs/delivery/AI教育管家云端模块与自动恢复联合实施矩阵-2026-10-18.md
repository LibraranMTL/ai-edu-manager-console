## 一、联合执行决策

1. 自动恢复方案是任务生命周期、恢复原因、共享预算、未知结果保护和普通用户交互的唯一规范来源。
2. 云端方案是学生基础信息、健康资料独立许可、云端资料分类、版本治理、同步权限、远程 MCP、成果收件箱和云端页面行为的唯一规范来源。
3. 本矩阵是阶段依赖、跨模块接口、联合验收、回滚边界和完成状态的唯一协调来源。
4. 发生冲突时，采用不扩大权限、不覆盖新数据、不重复执行、不跨学生写入的更严格规则；未知结果必须先查询，不能直接重派。
5. Windows R40 已形成的 P0/P1 恢复底座作为后续开发基线。云端工作不得重新实现第二套总任务队列。

## 四、联合最小身份与关联合同

| 字段 | 含义 | 生成方 | 约束 |
|---|---|---|---|
| tenantId/accountId | 用户云端账号边界 | 云端身份服务 | 不能从当前页面学生推断 |
| cloudStudentId | 云端稳定学生身份 | 云端学生服务 | 所有传输、检索、下载和审计都必须携带并复验 |
| localStudentId | 接收主机本地学生身份 | Windows学生服务 | 可以与cloudStudentId不同；必须通过bindingId关联 |
| bindingId | 一台主机上的云端/本地学生绑定 | 接收主机建档流程 | 同一主机、同一cloudStudentId最多一个有效绑定 |
| studentProfileId/profileRevisionId | 学生基础信息逻辑对象及不可变修订 | 云端学生资料服务 | 迟到旧修订不能覆盖新版 |
| projectId | 可选项目归属 | 本地业务模块 | 归属不明时请求最小人工选择 |
| taskId/businessKey | 逻辑任务及稳定业务键 | 任务中心 | 重启和重试不得创建新任务绕过预算 |
| executionId | 一次实际执行或派发 | 执行层 | 结果未知时保留，不能换ID规避查询 |
| correlationId | 任务与云端传输的关联标识 | 首次持久化意图的一方 | task、outbox、回执、inbox及审计一致 |
| materialId/revisionId | 逻辑云端资料及不可变修订 | 云端资料服务 | 不因重命名改变；不同来源不按同名合并 |
| healthRecordId | 健康资料逻辑对象 | 健康资料服务 | 只能在独立健康许可范围内列出和读取 |
| submissionId | 一项Agent成果提交 | 云端收件箱 | 目标主机领取及本地消费幂等 |
| idempotencyKey | 一次业务写入的幂等键 | 调用方按联合合同生成 | 同键不同内容拒绝；不能跨学生复用 |
| scopeFingerprint | 冻结项目成员、项目知识空间、读写根、策略版本与任务类型的权限摘要 | Windows项目执行范围服务 | 正文发送前、结果提交前和结果信封必须一致；变化后原任务不得重派 |

C0 必须确定上述字段的格式、持久位置、唯一约束、脱敏日志和兼容迁移。

## 五、学生基础信息与健康资料授权

### 5.1 默认基础信息

用户明确为某学生开启云端同步时，以下已填写字段默认勾选并随版本变化同步：稳定学生ID映射、姓名/显示名、年级、学校、学习目标、当前地区、手机号、邮箱、生日、地址和监护人信息，以及资料修订号、来源设备和更新时间。首次上传前展示字段预览，用户仍可取消具体字段；未填写字段不上传，也不根据其他资料推断补齐。

默认基础信息不包含登录ID、设备密钥、本机路径、Agent配置、原始对话、原始学习证据或健康资料。

### 5.2 健康资料单独许可

健康资料使用独立 `health_record.write` 和 `health_record.read`，默认关闭。授权至少指定学生、上传或读取动作、资料集合/单项对象、有效期和接收主体；基础信息、普通文档、报告或Agent宽权限均不能隐式带出健康资料。

### 5.3 同步与读取分离

基础信息同步许可、接收主机读取许可、外部Agent读取许可和健康资料许可分别判断。上传到云端不会自动产生读取权；撤销某个接收方不影响其他接收方。

## 六、无本地档案接收主机的自动建档

学生或有权管理该学生的用户明确授权某台 Windows 主机读取 `student_profile` 与文档后，该主机可以在没有本地学生档案时自动建档：

1. 服务端返回cloudStudentId、profileRevisionId、授权字段、来源账号和授权ID。
2. 已有同一cloudStudentId绑定时复用原档案，不重复创建。
3. 没有绑定，且没有可能冲突的未绑定同名档案时，创建“云端授权建立”的最小本地档案，生成localStudentId和bindingId，再初始化标准学生工作区。
4. 存在同名/相似候选、旧迁移记录或身份冲突时，不自动合并，只要求用户选择“绑定已有档案”或“另建档案”。
5. 没有单独 `health_record.read` 时，不下载健康资料，也不因健康资料缺失阻止建档。
6. 后续云端修订只自动更新本机未修改字段；双向都改过的字段保留两版并请求一次合并选择。
7. 撤销下载许可不静默删除本地档案或正式导入资料，只断开云端绑定并提供清理入口。

整个建档过程使用稳定幂等业务键；重启、重复领取授权或重复下载不得生成第二个学生。自动建档不是按姓名复制目录，也不把只读缓存当正式知识库。

## 七、云端、授权与统一任务状态映射

| 云端或传输状态 | 任务中心分组 | 自动动作 | 完成条件/人工边界 |
|---|---|---|---|
| 已持久化、等待发送 | 自动处理中 | 按授权、网络和计划时间唤醒 | 必须存在nextWakeAt或事件条件 |
| 正在上传、下载或处理 | 自动处理中 | 更新真实进展，受共享预算和超时保护 | 仅刷新心跳不能冒充有效进展 |
| 已下载、等待建档或导入 | 自动处理中 | 校验身份、授权、哈希和绑定后继续 | 下载成功不等于建档或业务成功 |
| 可重试失败 | 自动处理中 | 在共享预算内只重试失败阶段 | 预算耗尽或新增授权时转人工 |
| 结果未知 | 自动处理中或需要你帮助 | 先查服务器、回执、本地产物和审计 | 查询能力/预算耗尽后才请求核对 |
| 同名/绑定冲突、登录或授权决策 | 需要你帮助 | 保存已完成步骤，提供最小业务选择 | 用户完成后自动继续 |
| 传输和业务验收均成功 | 历史记录：已完成 | 固化回执、版本、绑定和产物 | 两层均成功后才记完成 |
| 已暂停、取消或撤权 | 历史记录或等待明确恢复 | 停止派发，隔离必要的晚到结果 | 仅用户明确恢复且权限有效时重新评估 |

### 7.1 Windows Agent 一次授权与启动恢复

R40 的持久化授权与短期任务合同验证是两层状态，不能互相代替。合同验证过期只代表需要后台复核，不能推导账号已经退出；普通健康检查也不能更新授权版本。

| 状态/变化 | 自动动作 | 用户界面 | 禁止行为 |
|---|---|---|---|
| 官方登录仍有效 | 启动先恢复持久授权，再合并执行一次后台健康检查 | 正在检查 → 已连接 | 打开登录页、阻止已授权任务或要求重复点击 |
| 任务合同约 30 分钟到期 | 下一次相关任务前使用合成数据复核受影响合同 | 等待自动复核；任务自动接续 | 把合同过期显示成账号未登录 |
| CLI／模型版本变化 | 使受影响合同失效并自动重验；保留账号授权 | 后台更新可用能力 | 递增授权版本或使其他合同全部失效 |
| 普通“验证连接” | 只读健康检查及必要合同复核；并发请求合并 | 检查完成后回到已连接/等待自动复核 | 调用授权失效、改变授权目录或递增授权版本 |
| Token 过期、撤销、账号退出 | 合法刷新失败且得到明确 `AUTHENTICATION_REQUIRED` 后停止相关新派发 | 需要重新授权；提供官方登录入口 | 在其他错误、检查中或合同过期时弹登录 |
| LLM API 配置未变化 | 复用本机加密密钥和配置指纹；按需复核模型能力 | 已连接或等待自动复核 | 重启时要求重新输入密钥或在日志中暴露密钥 |

已连接时，普通卡片隐藏“连接／授权”，显式更换账号或授权目录放到“高级 → 更换账号／重新授权”。重新授权不扩大原学生、任务类型、资料范围或费用授权；未知结果任务继续先查回执，不因认证状态切换而重派。

## 九、共享接口与事件约束

1. **持久化意图**：先写taskId、businessKey、correlationId、学生、授权快照和幂等键，再发起网络写入。
2. **查询回执**：按correlationId/idempotencyKey查询接收、修订、submission、建档或下载状态。
3. **学生绑定**：自动建档前以cloudStudentId查询有效binding；同名只作为冲突提示，不作为合并依据。
4. **健康隔离**：每次列出、下载和导入健康资料都重新校验独立许可，不缓存为普通文档权限。
5. **更新恢复计划**：云端状态更新统一原因、责任方、预算、nextWakeAt和用户动作。
6. **取消与撤回**：取消任务、暂停同步、撤回云端副本、撤销Agent、撤销主机许可和清除本机副本保持独立语义。
7. **晚到结果**：取消、暂停或撤权后的回执和成果隔离，不自动发布、不覆盖当前版、不复活任务。
8. **兼容接口**：旧 `/v1` 保留增量语义；新页面和远程MCP使用 `/v2` 当前视图。
9. **授权版本**：只在账号、授权目录、令牌主体或显式授权发生真实变化时更新；健康检查、合同复核、CLI/模型版本变化不得更新。
10. **合同复核**：按provider、任务合同及运行时指纹持久化；到期或指纹变化后用合成数据自动重验，失败按原因区分合同不兼容与 `AUTHENTICATION_REQUIRED`。
