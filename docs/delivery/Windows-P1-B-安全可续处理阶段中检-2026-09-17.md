# Windows P1 阶段 B：安全可续处理阶段中检

日期：2026-09-17。对应《Windows-0.17.9-屏幕采集消化优先与双报告-P1优化实施方案》的阶段 B（R0.5＋R1＋T0 收尾）。本记录是开发工作树检查，**不是 B 阶段通过、真机验收或新安装包交付**。

## 已完成的局部实现

- 时间线 Worker、报告修复、视觉队列与普通 CLI Agent 正式任务共用 `CaptureHeavyWorkGate`。采集活跃时不启动新的受管重任务；普通空闲最多 1 个，资源充足时最多 2 个，不同学生排队先到先服务，同学生串行。资源不足的 Agent 任务保持待执行，持久化等待信息，重启后恢复自动重试，不增加普通用户点击。
- 新采集的代表截图及带路径的视觉清单放在采集中心，正式原始资料目录仅收到不含图片路径的窗口 Markdown。旧会话的既有截图副本保留，不静默删除用户数据；旧版清单仍可兼容读取。
- 一个长会话可生成多个稳定窗口，各窗口独立进入学生/项目原始资料、以独立资料记录触发正式消化，并以 `windowId` 限定回执和知识链接。整场索引只聚合；未结算窗口不因首窗成功而标成完成。重复处理保留未变化窗口的正式结果；来源变化的旧窗口 Markdown 移入采集中心 `retired`，上传记录变为 `removed`，失效的时间线知识链接从投影中移除，相关报告安排重建。
- 视觉观察的写回不会把尚未正式消化的窗口误标为消化完成。已有 Codex 逐图交付、局部 OCR 等能力仍按原有独立授权工作；本阶段没有放开 WorkBuddy/QClaw 学生图片。

## 本机检查

- `node --test --test-reporter=tap tests/*.test.cjs`：1019 项，1018 通过、1 跳过、0 失败。
- `node --check`：主进程、时间线 Worker、语义处理与资源许可模块通过；相关差异 `git diff --check` 通过。
- 500 帧合成基准：5 个处理窗口、100 张代表图（每窗 ≤20），首轮 267.22 ms、重放 268.41 ms、主线程计时最大偏移 2.66 ms、语义查询 P95 1.52 ms。只说明合成输入上的后台处理未明显阻塞测试计时器，不代表真机前台响应、低配设备、模型费用或 60 分钟运行验收。

## B 阶段未通过的门

1. **操作系统级边界**：截图移出正式原始资料目录，且 Codex 视觉调用使用只读参数、关闭相关工具，但普通用户身份的正式 Agent 进程仍可能读取同一 Windows 用户可访问的采集中心。目录分离、隐藏路径和提示词都不是 OS 级权限证明。要达到方案要求，需要可打包、可测试的 Windows 受限进程/文件权限组件及独立安全验收；不可把现状标为硬隔离已完成。
2. **运行中让出与公平性真机门**：新任务有资源许可与自动排队；已启动的长 Agent CLI 任务尚无安全的逐文件检查点和采集中途协作让出。公平队列只有单元证明，缺少与真实 Codex/WorkBuddy/QClaw、采集和断网同时运行的长时测试。
3. **T0 收尾**：无独立证据的跨设备时钟偏差仍只能标疑似、不能自动校准；跨截图/已授权会话/作品的稳定候选去重和可续任务索引尚未完成。已有时间来源与行为人 `unknown` 字段不能代替这些能力。
4. **来源修订的正式知识治理**：时间线链接和报告可失效重建，但已经发布的知识资产若曾依赖被替代窗口，还需建立依赖失效审计及再次验证机制，不能仅靠移走原始 Markdown 视为已撤销。
5. **真机兼容与性能**：Windows 学生端 0.17.8、双机至少 60 分钟、休眠/断网、低配、前台 P95 和真实授权截图质量均未验收。

结论：阶段 A 仅通过本地开发门；阶段 B 已有可测试的局部实现，但上述安全、可续性与 T0 条件未通过。依照“五阶段逐段通过再进入下一段”的要求，**C、D、E 尚未启动；不构建或发布声称五阶段完成的正式包**。

## 2026-09-17 唯一门槛调整补记

以上是按原门槛形成的中检事实，不删改当时检查结果。用户最终仅采纳第 1 项的调整：B 阶段不再要求证明同一 Windows 用户身份的正式 Agent 在 OS 层读不到采集中心，也不以原生受限进程组件作为前置。仍需应用层只读/禁高风险工具配置、采集与外部视觉分别授权、归属/哈希校验、显式附件及正式消化不附截图路径；不得宣称已实现 OS 级隔离。

第 2—5 项及三服务能力探测、时钟校准/跨源去重、来源修订治理、长任务检查点、真机兼容与性能等其它验收要求保持原样。第 1 项被取消不代表 B 已通过；需按其余原门槛重新验收，C—E 也不得据此宣称完成。
