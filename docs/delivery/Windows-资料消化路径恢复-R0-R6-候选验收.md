# Windows 学生资料消化路径恢复 R0—R6 候选验收

**当前状态：2026-08-29 重新确认为 Windows 主机测试与后续开发基线。**
知识资产证书/事件账本/Top 10 大改版已暂停采用，不属于本候选包。

## 1. 候选范围

- R0：冻结现场基线，复现“资料已在原始资料库，但复制指令提示未建立批次”。
- R1：以当前学生原始资料库为唯一查找边界，建立稳定文件清单和 SHA-1 校验。
- R2：唯一同哈希候选自动修复；修复前备份资料索引与上传记录，并写入修复历史。
- R3：坏项隔离、2—5 秒写入稳定期、100 份/512 MB 限量批次和自动通道续批。
- R4：`materials.json` 作为当前路径和计数权威；取消 200/1000 条静默截断，保留完整账本。
- R5：资料处理卡片显示预检汇总，提供重新检查和经哈希验证的手工选文件。
- R6：自动测试、生产构建、包内复核、候选安装包和真机测试清单。

## 2. 安全边界

- 不跨学生目录搜索，不按相似姓名猜测学生。
- 不跟随符号链接离开当前学生原始资料库。
- 不移动、删除、覆盖或改写原始资料。
- 自动修复必须同时满足：当前学生目录内、普通非空文件、稳定、SHA-1 一致、候选唯一。
- 手工选择不能绕过目录边界和 SHA-1 校验。
- 一项失败不改变其他项的身份、状态和路径。

## 4. Windows 真机测试

1. 在同一测试学生下准备至少 205 份待处理图片，确认顶部与资料处理卡片数量一致，不再固定为 200。
2. 把其中一张图片移动到当前学生原始资料库的另一子目录，点击“开始处理”或“重新检查并自动修复”；确认显示自动修复且可建批。
3. 再制造四类问题：删除一张、复制两个同内容同名候选、保留一张正在写入文件、用不同内容替换一张；确认这些项列入待确认，而其他可读项仍建立批次。
4. 对缺失/多候选项点击“手工选择文件”：选择当前学生目录内正确原文件应成功；选择其他学生目录或不同内容文件应拒绝。
5. 检查学生知识库 `.edu-manager/material-path-repair-backups`、`material-path-repair-history.json` 和 `material-path-issues.json`。
6. 使用自动 Agent 完成第一批，确认后续批次继续；使用人工 Agent 时确认界面提示需要再次复制下一批指令。
7. 重启主机程序，确认待处理、已处理、后续批次和问题清单状态不丢失。

候选包通过自动测试和构建只代表源码与安装包可供测试。正式替换仍需完成上述 Windows 真机矩阵，并记录测试电脑、学生范围、资料数量、Agent 通道、结果与异常；没有真机证据时不得标记正式发布。
