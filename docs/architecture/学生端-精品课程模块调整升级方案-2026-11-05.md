## 1. 决策摘要

Android 学生端和 Windows 学生端都需要适配云端精品课程发布体系，但两端仍是**课程消费端**，不是课程管理端。首期不让学生端直接读取云端完整目录，也不增加课程编辑、导入、发布、审核、受众设置或回滚能力。

统一链路如下：

```text
云端内容与文档管理中心
  负责课程、语言、受众、版本、发布、撤回和公共资源
                ↓ 公共内容清单
Windows 主机版
  验签、缓存、last-good、本地启用/隐藏/排序/学生分配
                ↓ 当前学生有效课程投影
Android 学生端 / Windows 学生端
  展示、筛选、安全打开、记录本地打开行为和主动资料采集
```

学生端升级的核心不是重做课程管理，而是：

1. 兼容云端发布后的稳定课程 ID、修订、语言和撤回语义；
2. 准确展示主机投影出的当前学生有效课程；
3. 在断网、主机暂时不可用、目录更新或课程撤回时给出真实状态；
4. 保留安全浏览、域名白名单和学生主动采集边界；
5. 不把课程打开、浏览时长或一次作答自动解释为掌握证据。

## 2. 当前能力与缺口

### 2.1 已有能力

两个学生端当前已经具备：

- 进入学生空间后，按当前学生向主机请求有效课程；
- 展示课程封面、名称、提供方、简介、账号要求和法律说明；
- 在受限浏览器中打开课程；
- 限制协议、允许域名、弹窗、下载、证书绕过和越界跳转；
- 学生明确启动后进行屏幕资料采集，并携带 `courseId`、URL 和时间归属；
- 注销、断开或切换学生时关闭课程并清空当前课程缓存。

### 2.2 主要缺口

| 缺口 | 风险 |
| --- | --- |
| 当前接口主要使用目录版本，缺少发布清单修订、本地策略修订和投影修订 | 无法判断课程变化来自云端、本机策略还是学生切换 |
| 缺少明确的过期、撤回、最低客户端版本和语言回退状态 | 学生端可能把“不兼容”误显示为“没有课程” |
| 读取失败时直接清空界面或只显示通用错误 | 主机短暂离线会造成课程看似消失 |
| 缺少按主机和学生隔离的 last-good 投影合同 | 离线体验与撤回安全之间没有清晰边界 |
| Android 与 Windows 的状态文案和刷新触发不完全一致 | 同一学生在两端看到不同解释 |
| 课程字段仍允许自由语言值 | 11 种目标语言治理无法稳定落地 |
| “精选课程”“我的课程”等命名混用 | 用户难以理解与云端“精品课程”的对应关系 |

## 3. 范围与边界

### 3.1 本期交付

- 用户可见名称统一为“精品课程”；学生首页入口可继续使用“我的课程”。
- 支持统一的学生有效课程投影 v2。
- 支持稳定 `courseId`、`courseRevision`、`localizationRevision` 和投影修订。
- 支持 11 种规范语言代码及旧 `en`、`es` 的兼容映射。
- 支持加载、空目录、主机离线、使用缓存、课程撤回、版本不兼容和安全拦截等状态。
- 支持按主机、学生和目录修订隔离缓存，避免串学生或串主机。
- 主机目录变化时主动刷新，不依赖用户重启应用。
- 保留课程安全浏览、主动资料采集及原有学生归属。
- 两端建立一致的协议测试、状态测试和真实设备验收矩阵。

### 3.2 明确不做

- 不把学生端变成云端课程管理端。
- 不向学生端下发云端草稿、审核记录、全量受众规则或管理权限。
- 不让学生端绕过 Windows 主机的本地启用、隐藏、排序和学生分配策略。
- 不默认把课程学习进度、作答、个性化学习卡或学生身份上传公共内容域。
- 不把课程打开次数、浏览时长或采集数量自动认定为知识点掌握。
- 不在首期建设学生端直连云端的第二套认证、授权和同步链路。
- 不承诺第三方网页在断网时可学习；“离线可用”只表示可使用最后验证的目录和已明确缓存的公共资源。

## 4. 学生有效课程投影合同

### 4.1 主机输出

建议把现有学生课程接口升级为 v2 响应；旧客户端在迁移期继续读取 v1 兼容字段。

```text
StudentCourseProjection
  schemaVersion
  hostId
  studentId
  projectionRevision
  manifestRevision
  policyRevision
  generatedAt
  expiresAt
  cloudFreshUntil
  etag
  syncState
  courses[]
  tombstones[]
  disclaimer
```

单门课程最小字段：

```text
courseId
courseRevision
localizationRevision
locale
title
summary
provider
coverUrl
launchUrl
allowedHosts[]
gradeBands[]
accountRequirement
legalNotice
availability
offlineOpenUntil
minClientVersion
```

约束：

1. `studentId` 必须与当前登录学生完全一致，否则客户端拒绝展示。
2. `hostId + studentId + projectionRevision` 构成学生端缓存隔离键。
3. `courseId` 在语言、封面和内容修订间保持稳定。
4. 主机只下发最终匹配的本地化内容，不下发云端全部语言版本。
5. `tombstones` 只包含终端曾见过且现在需要停止新打开的课程，不暴露其他学生或全局目录。
6. 课程 URL 每次打开前仍由主机有效投影和客户端安全规则共同校验。
7. 投影不包含学生作答、报告、知识点状态或公共内容管理信息。

### 4.2 11 种目标语言

规范值：

```text
zh-CN, zh-TW, en-US, en-GB, fr, es, es-419, ja, ko, vi, ms
```

迁移规则：

- 旧 `en` 根据已知国家/用户设置映射到 `en-US` 或 `en-GB`；无法确定时进入迁移报告，不静默猜测。
- 旧 `es` 保留为西班牙语基础来源，由平台内容负责人确定 `es` 或 `es-419`。
- 未知值不进入正式发布投影；原值保留在审计报告。
- “只允许 11 种代码”不等于每门课程必须同时存在 11 个翻译版本。
- 没有匹配本地化时，由云端发布策略决定是否回退；学生端不得自行假定回退到英语。

## 5. 同步、缓存与撤回

### 5.1 刷新触发

| 触发 | 动作 |
| --- | --- |
| 学生登录或切换 | 清除内存课程状态，按新学生读取投影 |
| 主机连接恢复 | 使用 ETag 刷新，不阻塞学生首页 |
| 主机发出课程目录变化事件 | 对当前学生立即增量刷新 |
| 学生手动刷新 | 发起一次受控刷新，避免重复并发 |
| 应用从后台恢复且缓存超过刷新间隔 | 后台刷新，先显示可用 last-good |
| 课程打开前 | 再确认课程仍在当前有效投影中 |
| 注销、主机解绑或授权失效 | 关闭课程并清除对应敏感会话状态 |

### 5.2 last-good 规则

- 只缓存已由已绑定主机返回并通过字段、安全和学生范围校验的投影。
- 缓存按 `hostId/studentId` 隔离并加完整性校验；不得跨学生复用。
- 主机短暂不可用时可显示 last-good，并明确标记“离线目录，更新时间……”。
- 超过 `expiresAt` 后只展示历史入口说明，不允许新打开课程；具体最大离线时长在合同冻结阶段确定。
- 紧急撤回在终端重新连到主机后立即生效；高风险内容使用短有效期投影。
- 目录读取失败不得覆盖已有 last-good，也不得把失败解释为“课程已删除”。
- 第三方网页、登录态和视频能否离线使用由提供方决定，不能由目录缓存状态代替。

### 5.3 课程撤回与修订

- 普通修订：保持 `courseId`，更新修订和本地化内容；下次打开使用新 URL/白名单。
- 紧急撤回：关闭正在打开的课程，阻止新打开，保留历史采集归属和本地学习记录。
- 受众变化：课程从当前投影消失，但不删除既有记录；界面说明“当前不再适用于此账号/地区/年级”。
- 最低版本提高：保留课程卡片摘要，禁用打开并提示升级学生端。
- 同一课程重新发布：必须有新修订；是否重新可见由主机策略和云端发布规则共同决定。

## 6. 界面与交互

### 6.1 信息架构

```text
学生首页
└─ 我的课程
   ├─ 继续学习
   ├─ 全部精品课程
   ├─ 课程卡片
   ├─ 同步/离线状态
   └─ 安全课程浏览器
```

课程卡片显示：封面、课程名、提供方、简介、适用年级、当前语言、账号/收费说明和状态。首期不显示未经可靠回执支持的“完成百分比”。

### 6.2 状态文案

| 状态 | 学生端表现 |
| --- | --- |
| 正常 | 显示课程数量和目录更新时间 |
| 当前无课程 | “当前没有为你启用的精品课程” |
| 主机未连接且无缓存 | “连接已授权主机后读取课程” |
| 主机未连接但有有效缓存 | 显示课程并标记“离线目录” |
| 缓存已过期 | 课程卡片只读，禁止新打开，提示连接主机刷新 |
| 课程被撤回 | 停止新打开，保留历史记录，说明已下架 |
| 客户端版本过低 | 禁止打开并引导升级，不伪装成课程为空 |
| URL/证书/域名异常 | 保持在课程壳层并显示安全拦截原因 |
| 语言无匹配版本 | 按平台回退政策显示，或明确“暂无适用语言版本” |

### 6.3 安全浏览边界

- 每门课程使用隔离会话或受限 WebView。
- 仅允许 HTTPS；确需 HTTP 的历史课程必须有平台级例外、明确域名和到期时间。
- 禁止任意文件下载、未知协议、任意弹窗、证书绕过和白名单外跳转。
- 外部登录凭据由学生自行输入；教育管家不采集密码。
- 课程采集必须由学生主动开启，持续显示状态并允许随时停止。
- 采集结果进入学生资料流程，不进入公共课程发布域。

## 7. Android 学生端改造

### 7.1 主要改动

1. 将“精选课程”统一改为“精品课程/我的课程”。
2. 升级课程 DTO，解析投影修订、语言、可用状态、过期时间和 tombstone。
3. 新增按主机和学生隔离的投影缓存及原子替换。
4. 主机短暂离线时显示有效 last-good，不直接清空课程。
5. 在打开前重新校验课程仍有效；撤回或过期时阻止打开。
6. 保留当前 WebView 白名单、证书失败阻止、下载禁止和主动录屏授权。
7. 课程封面缓存使用修订或哈希键，避免同 URL 旧图长期残留。
8. 支持横屏平板、竖屏手机、大字体和长语言文本。

### 7.2 不应回归的能力

- 当前学生和资料投递目标归属；
- 采集会话中的课程 ID、URL、开始/结束时间；
- 登录、切换学生和退出时的会话清理；
- Android 系统录屏授权和前台服务提示；
- 危险 URL、证书异常和下载拦截。

## 8. Windows 学生端改造

### 8.1 主要改动

1. `Course` 和 `CourseCatalogResponse` 升级为投影 v2 类型。
2. `terminal-main.cjs` 使用 ETag、投影修订和 last-good；读取失败不覆盖有效缓存。
3. `terminal-preload.cjs` 只暴露只读投影、打开、关闭和变化通知接口。
4. React 学生界面统一状态、语言、更新时间和升级提示。
5. 主机课程变化事件触发当前学生目录刷新。
6. WebContentsView 打开前重新读取/确认有效课程，继续复用隔离分区和域名守卫。
7. 课程被撤回、学生切换、主机断开或授权失效时关闭浏览视图。
8. 保留主动屏幕采集和课程上下文投递。

### 8.2 IPC 边界

学生端 IPC 只允许：

- 读取当前学生有效课程投影；
- 请求安全打开一个当前有效 `courseId`；
- 关闭课程；
- 订阅当前课程浏览器和目录变化状态。

不得暴露课程草稿、发布、回滚、策略编辑、任意 URL 打开或签名私钥相关 IPC。

## 9. 隐私、学习证据与数据归属

- 云端公共内容回执不得携带学生 ID、姓名、作答或学情内容。
- 主机可记录匿名化的同步、打开失败和安全拦截指标；学生级学习记录保留在学生档案边界。
- “打开课程”“停留时长”“采集了资料”只属于活动事实，不能独立证明理解或掌握。
- 只有可比作答、复测、作品证据或人工确认，才可进入学情证据链。
- 学生删除本地课程活动记录不修改云端公共课程版本。
- 公共学习卡模板与学生个性化卡片继续使用不同 ID、存储和权限域。

## 10. 迁移方案

1. 先发布主机兼容接口：同时返回 v1 旧字段和 v2 新字段。
2. Android/Windows 学生端升级后优先读取 v2，失败时仅在过渡期回退 v1。
3. 旧课程 ID 通过 `legacyCourseId → courseId` 映射，禁止仅按课程名称匹配。
4. 旧 `en`、`es` 和未知语言值先运行只读审计，生成自动映射、待确认和阻塞三类清单。
5. 旧客户端继续使用主机 last-good，不直接读取云端新清单。
6. 两个学生端达到最低覆盖率且真实设备通过后，才停止 v1 投影。
7. 迁移结束仍保留历史活动和采集归属，不因课程撤回或换 ID 丢失证据。

## 11. 失败与对账

| 失败 | 自动处理 | 需要处理条件 |
| --- | --- | --- |
| 主机请求超时 | 使用未过期 last-good，指数退避 | 长期无有效目录 |
| 响应学生不匹配 | 拒绝展示并清除内存结果 | 连续出现或疑似串学生 |
| 投影修订倒退 | 保留当前投影并要求主机解释回滚 | 未声明回滚 |
| 课程字段无效 | 隔离单门课程，不阻塞其他课程 | 稳定 ID、URL 或白名单无效 |
| 封面下载失败 | 使用占位图，不阻塞课程打开 | 大范围资产失效 |
| 课程被撤回 | 关闭或阻止打开，保留历史 | tombstone 与有效目录冲突 |
| 浏览器越界跳转 | 阻止并记录安全事件 | 同课程反复触发或提供方变更 |
| 客户端版本过低 | 提示升级，保留可解释卡片 | 强制升级链路不可用 |

主机每日对账应覆盖：云端 active 清单、主机 last-good、本地课程策略、学生有效投影和学生端同步回执。学生端只回传设备级协议状态，不回传学生正文。

## 12. 测试与验收矩阵

### 12.1 合同测试

1. Android 与 Windows 对同一投影解析得到相同课程 ID、修订、语言和状态。
2. v1/v2 迁移期兼容；v2 必填字段缺失时安全失败。
3. 11 种语言代码通过，未知代码进入审计或被发布端阻止。
4. ETag 304、增量更新、显式回滚和 tombstone 行为一致。

### 12.2 学生隔离

1. 切换学生后不得短暂显示上一学生课程。
2. 同名学生、不同稳定 ID 不共享缓存。
3. 解绑主机后不得继续使用该主机的受保护会话。
4. Android 与 Windows 学生端都只获得当前学生有效课程。

### 12.3 故障与安全

1. 主机离线、网络抖动、应用杀进程和缓存损坏。
2. 课程撤回、受众变化、目录回滚和最低版本提高。
3. 证书失败、重定向到白名单外、未知协议、弹窗和下载。
4. 正在采集时课程撤回、学生退出或主机断开。
5. 大字体、长标题、长法律说明、横竖屏和低内存设备。

### 12.4 放行证据

- 自动化合同测试和安全浏览回归通过；
