## 1. 本批源码范围

### P0：任务事务及数据库升级

- 业务数据库升级为 Room Schema V2，保持数据库文件名 `education-business-v1.db`，保留 Schema V1 和原有模型回执、文件操作意图。
- 增加任务表、任务事件表和迁移元数据表；迁移为增量创建，不使用破坏性重建。
- 旧 `task-center/tasks.json`、`events.jsonl` 严格验证后导入；原文件不删除、不写回，迁移前另存原字节和指纹。
- 任务行、事件和导入标记在同一事务提交；完成后不重复导入旧 JSON。损坏、协议错误、重复 ID、学生作用域冲突阻止迁移，不能按空列表覆盖。
- 保持 Windows Task Protocol 1.2 的既有状态、权限和回执合同；界面状态映射不修改跨端协议。
- 创建、审批、启动、结果接收、取消及事件记录改为事务；更新有 revision 比较，迟到或错误 executionId 回执不能接受。
- 修复失败/阻塞/超时任务重新启动遗漏合法中间状态的问题。高风险任务每次启动均需有效审批。
- 上一进程遗留的运行/等待结果/审核任务标记结果未知、关闭自动重试，保留历史事件。不能把中断后的未知副作用当作未执行而重新调用模型。
- 所有 Room 访问要求后台线程；移除学生的忙碌检查改用无列表截断的 `EXISTS` 查询，并检查关联项目队列。

### P1：当前学生任务中心基础

- 首页新增“当前学生 · 任务中心”，保留原有模型诊断入口。
- 展示最近 100 条当前学生任务、每个关联项目最近一次队列、最近 50 条模型回执和云端报告状态；显示真实未知用量，而不是 0 Token。
- 支持全部、处理中、需要处理、已完成筛选，以及任务事件详情和取消未启动任务。
- 对话任务按 `input.studentId` 归属，而不是误用对话记录 ID；明确属于另一学生的任务不能因共享项目被展示。
- 异步请求带页面代次和当前学生校验，离开、切换或迟到结果不更新旧页面。
- 运行中任务不展示虚假的“已取消”操作；合作式网络/模型取消与任务级检查点仍需在后续队列阶段完成。

### P5 提前补齐：新增 Room 数据不能遗漏于备份

- 加密备份和整机离线迁移均加入业务数据库逻辑快照，涵盖模型回执、操作意图、任务、事件、元数据五张表。
- 快照在事务中生成，不复制正在使用的 SQLite/WAL 文件；运行中的任务或模型调用阻止快照导出。
- 恢复验证版本、表、字段、ID 和学生/项目归属；重映射任务授权中的逻辑路径。旧包没有快照时仍走验证后的旧任务导入。
- 只允许恢复到没有学生/项目、没有既存业务记录的空白单机版；项目索引损坏不能被当作空白库覆盖。
- 恢复前持久保存私有状态和设置检查点；恢复时先登记操作，数据库提交标记是最终判据。
- 若重启时发现未提交操作，回滚私有状态及原设置；若数据库已提交，则完成日志，不把已恢复的私有状态撤回。
- 用户 SAF 原件不会因回滚被删除；失败后新目标目录可能保留已校验的副本，必须保留/核对，不能宣称目录层面“零副作用”。
- 回滚检查点可能包含本机加密后的凭据，不进入备份或换机包；API Key、短时令牌和旧设备授权不因此迁移。
- 首页恢复检查先于自动任务恢复；项目队列、云端上传、任务读写和模型回执进入前增加恢复核对。
