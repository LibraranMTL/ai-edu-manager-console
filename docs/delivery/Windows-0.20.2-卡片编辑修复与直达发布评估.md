# Windows 0.20.2 卡片编辑修复与直达发布评估

日期：2026-10-09。本轮实现编辑器修复、自定义学科、纸张方向；对无需卡片包的发布进行现有源码核查与方案评估，未改动在线服务或学生端协议。

## 已实现

1. 图片／PDF 草稿重新打开后自动加载原文件预览。此前原文件引用保存在草稿中，但编辑器只在上传或手工点击预览后加载，造成“图片消失”的观感。加载失败明确提示重试，不清空原件。
2. 原版文件卡片可留空正文并保存到“我的卡片”，仍需标题、学科和有效文件。纯文字结构化卡片继续要求正文；启用原版卡片评阅仍要求题目对应关系、知识点与答案或量规。不因放宽保存而伪造题目或评阅依据。
3. 学科改为可输入的单个自定义标签，带常用学科建议。保存后的标签进入分类筛选，选项从当前学生可见资源聚合，不受当前分页／搜索影响，不泄露其他学生私有分类。此轮不增加多标签体系。
4. 纸张增加竖向／横向，支持 A4 和 Letter；预览框比例、结构化输出、图片／PDF 排版和系统打印使用相同方向。原版页面按比例缩放，不裁切；“另存原版文件”仍保存未修改的源文件。旧资源未记录方向时保持兼容，不改写旧版本哈希。

使用：学习卡片 → 卡片资源 → 制作我的卡片／卡片管理中的草稿。填写标题和自定义学科，上传图片或 PDF，正文可留空；右侧选择纸张和方向后保存。关闭并重开草稿应直接看到预览。

## 当前发布链路的实际边界

核查位置：

- `electron/main.cjs` 的 `handleCardResourceAction`：机构和平台发布当前均要求保存 `.edu-cardpkg`，完成保存后才提交本机资源版本。
- `electron/main.cjs` 的 `handleStudentCourses`：已配对、已授权学生通过主机 HTTP 获取有效课程目录；可复用会话和学生范围检查，不宜将卡片伪装成课程项。
- `electron/main.cjs` 的 `handleTerminalPractice` 和 `src/terminal-main.tsx`：学生端已有当前练习展示、开始和提交，但没有发布资源列表、原版文件资源接口及完整反馈列表。
- `cloud-report-service/http.cjs` 与 `service.cjs`：云端有设备认证、学生授权、文件哈希、流式上传、分页目录、审计与撤回。现有文档只支持 Markdown、PDF、DOCX，且按学生授权，不能直接当作面向所有学生的图片／结构化卡片目录。未核查线上部署是否已更新到本地源码版本。

因此，“机构或平台发布后学生直接看到”技术上可行，但并非取消一次导出对话框就已打通。

## 推荐方案：一个发布按钮，两个传输层

| 场景 | 发布与使用体验 | 复用与新增 |
|---|---|---|
| 主机在线，学生已配对 | 发布到本机 → 设置可见学生 → 学生刷新目录即可打开 | 复用课程的认证与分配方式、卡片资源版本和练习实例；新增学生卡片目录、详情、原件、开始与反馈接口 |
| 主机关机或跨机构／跨主机 | 在已配置云端同步的前提下发布并后台同步 → 学生通过轻应用使用 | 复用云端文档服务的设备认证、对象存储、授权和审计；新增卡片目录与分配、版本同步、作答回传和反馈查询 |
| 完全离线或人工备份 | 可选“导出卡片包” | 保留现有包机制，不再作为正常发布的前置条件 |

### 第一阶段：主机直达

- 机构／平台草稿底部主按钮改为“发布”，先提交本机不可变资源，不弹文件保存框；导出包作为发布后的次要操作。
- 沿用已配对学生的登录和授权，新增只读目录、卡片详情、受控原件下载、开始练习接口。所有请求由主机重新验证学生归属、分配范围、版本状态。
- 机构资源只对本机构被分配学生可见；平台资源只是平台类别，不自动意味着互联网公开。跨主机推荐另由云端可信发布者机制管理。
- 学生端增加“推荐／机构／我的练习”的轻量分类；首次点击才创建个人实例。图片／PDF 先支持浏览、保存与打印，只有具备评阅依据的卡片显示作答入口。
- 未开始的新使用取最新有效版本；进行中和历史练习固定版本。撤下阻止新使用，但不删除学生历史作答。
- 在线时主机承担评阅；旧客户端保留原当前卡片接口，通过能力标识提示升级，不让旧端调用不存在的目录能力。

建议先做此阶段，用户不需要新增云账户或服务器设置，现有课程与卡片模块也不需要合并。

### 第二阶段：云端文档轻应用扩展

继续部署一个轻服务，新增独立卡片资源表／路由与轻应用页面，不混入学情报告列表，不把每位学生的相同资源重复上传。

- 资源：可信发布者／机构、卡片 ID、版本、哈希、文件对象引用、状态；文件按哈希共用。
- 分配：机构、班级／学生的访问关系；本机学生 ID 与云学生 ID 必须有明确绑定，不按姓名自动配对。
- 同步：本机事务外发队列，幂等重试、版本游标、撤下记录；显示“本机已发布／同步中／学生可访问／同步失败”，不能把点击发布当作上传成功。
- 作答：学生登录下的只追加提交、客户端幂等编号、卡片固定版本引用；云端接收后主机拉取评阅并回传反馈。主机离线时显示等待处理，不假称已批改。
- 权限：新增卡片读取、作答写入及机构／平台发布能力；不能直接用现有 `report.write` 授予公共发布权。平台身份依靠服务器授权，不依赖包内自报 scope 或哈希。
- 隐私：仅同步授权的教学资源与需要的作答，不默认上传学情依据、完整档案；撤销授权后清除客户端受控缓存，已经下载或打印的文件不能远程收回。

若短期只需“看卡片”，可以先将卡片导出 PDF，使用已有云文档分发给授权学生；这是阅读过渡方案，不包含卡片分类、版本绑定、在线作答及评阅闭环。

## 验收与边界

- 新增回归覆盖：原版卡片空正文保存／重新打开／包导入、自定义分类与跨学生隔离、旧哈希兼容、方向参数校验、横向页面导出。
- 全量回归：1,841 项，1,839 通过、1 跳过、1 项既有失败（下载收件箱旧 React key 契约断言）。本次未修改该无关模块。
- 候选包 8 组冒烟通过，包括原版及结构化 PDF 的横向 A4 尺寸检查。PDF.js 可选 canvas 查找有警告，应用显式提供的本机渲染通道实际通过。
- 本轮未增加联网发布、未升级学生端、未上传学生数据或部署云服务；上述直达发布两阶段属于后续实施方案，不能作为当前已交付能力宣传。
