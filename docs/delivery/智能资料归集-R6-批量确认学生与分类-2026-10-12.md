# 智能资料归集 R6：批量确认学生，再智能分类

日期：2026-10-12（北京时间）。Windows 0.21.1，独立候选 `smart-inbox-r6-20261012`。开发候选，不是正式发布或完整产品验收通过声明。

## 一、操作与实现

- 新增常显入口“仅确认学生，由AI分类”：勾选同一学生的资料 → 选择“确认所属学生” → 点击“确认学生并智能分类（N项）”。无需指定项目，不改变整个共享来源。
- 版本、来源和学生校验成功后异步入队，复用原提取器、受控 Agent、资源准入与任务中心。界面说明正文可能提交给该学生配置且已授权的 Agent。
- 可信项按来源设置自动投递；不确定、敏感、冲突、提取不完整和通道不可用等保留人工处理。不明确项目时不自动使用学生原始资料库兜底。确认学生不会开启原本关闭的来源自动投递或解除学生／全局暂停。
- 原入口保留为“手动指定位置并投递／纠正”，明确说明是直接按人选位置投递，不等待 AI 推荐。
- 列表显示所属学生；未绑定待办显示“待确认学生／确认学生后推荐项目”。没有有效建议时“确认建议并投递”禁用。混入其他学生或不可处理状态时给出原因并限制提交。
- 资源准入失败后保存等待原因，原因未变不重复写入；成功后清除旧等待原因。刷新只读保存状态，不增加轮询、扫描、OCR 或 Agent 探测。React 沿用并行只读刷新、过期请求保护，选择状态就地计算。

## 二、自动会话等待原因

本机只读核查：该来源已有 75 份 pending 会话资料，分析次数合计 0；学生 activityStatus=paused、pauseAutomaticTasksWhenInactive=true；来源 enabled=true、automatic=false；全局自动任务开启。

学生暂停策略是本次后台分析的明确阻断条件，不是缺少学生绑定或 WorkBuddy 超时。来源 automatic=false 仅影响分析后的自动投递，并非此次等待分析的原因。

未改动真实学生状态、来源、正文或旧队列。若希望恢复持续自动分析，用户需自行在学生设置恢复该学生；仅做一次处理可在来源点“立即扫描”，沿用原手动处理路径。要持续可信自动投递，还需明确开启该来源相应设置。R6 会在批次准入被拒时保存可读等待原因。

## 三、隔离、审计与恢复

- 每份资料记录 studentConfirmation：学生、来源、来源修订、文件身份、请求 ID、请求资料版本、时间。不覆盖来源绑定，不生成项目路由规则，不改其他资料。
- 决策沿用串行队列、资料版本、请求内容哈希及回执。重复请求不重复执行；先登记待执行标记再保存确认，重启可恢复；丢失结果回执时从匹配的逐资料确认恢复结果。
- 已归属其他学生、未知执行、已投递或人工锁定资料不能借该入口重置。原件变化、来源改绑、跨学生建议仍失败关闭，不降低可信阈值。
- 共享来源中不同学生的相同正文仍独立提取／缓存／分类；完整提取结果仅在同学生、同版本和有效目标授权校验后交给消化阶段，避免重复 OCR／解析。
- 原件处理沿用来源策略：旧下载中转来源投递后归档，新通用目录默认保留。没有新增删除策略。
