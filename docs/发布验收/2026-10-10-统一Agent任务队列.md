# Windows 0.20.5：统一 Agent 任务队列

## 修改范围

- 资料整理队列的收件箱、结果目录、同步按钮跟随执行器筛选；全部执行器模式扫描所有已注册通道。
- 使用 `agent-inbox/<agentId>` 与 `agent-results/<agentId>`。任务包给出当前 taskId、executionId、agentId 及结果路径；后台校验批次、任务状态、通道归属与实际产物。
- WorkBuddy 桌面交接使用完整任务包指令；桌面与通用任务包等待用户操作时不再套用进程心跳超时，并修复历史误超时状态。
- 新学生、新项目和缺省配置使用 WorkBuddy；智能路由与安装推荐不再自动选择 QClaw。已有明确绑定不迁移、不覆写。
- 通用 Agent 任务包保留实际所选 Agent 身份，不把未接入自动接口的应用伪装成自动执行器。
- 修正资料同步、远程协作、初始化、记忆导入中的 QClaw 专属提示。通用任务目录不参与跨主机知识同步。

## QClaw 剩余引用分类

| 类别 | 处理 |
| --- | --- |
| 队列按钮、默认值、自动路由、安装推荐 | 已解耦，新增默认 WorkBuddy |
| QClaw 专用适配器、安装检测、启动、原生 MCP/生命周期集成 | 保留为用户显式选择的可选兼容能力 |
| 旧 qclaw-inbox/qclaw-results、旧 IPC 和回执 schema | 保留旧任务兼容；后台统一回收结果 |
| 历史资料来源、规则文件识别、已有 Agent 绑定 | 保留真实来源，不批量改名 |
| Android 学生端/教师端固定启动按钮 | 源码改为选择实际已安装应用，不猜测 WorkBuddy 包名 |
| Android 单机版模型中的 QClaw 默认值 | 新记录改为 WorkBuddy，旧记录绑定读写保留 |
| 历史文档、旧发布产物、兼容测试 | 不重写历史记录 |

## 能力边界

WorkBuddy 桌面登录不等于无交互 API：当前桌面交接可预填任务，仍需在 WorkBuddy 点击发送。其他没有自动执行接口的内置 Agent 使用复制任务包、标准结果回写的方式；不能写文件的 Agent 可返回 JSON 供导入。自定义应用启动项不因此获得自动任务 API。

本次统一的是资料整理任务队列。workspace-v1 项目资料受控消化仍保留其专门的 Codex 执行与隔离要求，不能把通用任务包兼容宣传为已支持所有 Agent 的受控项目消化。原始资料保护、执行身份检查与结果产物校验未移除。

本次只发布 Windows 主机程序；Android 改动仅完成源码和定向测试，未更新线上 APK。未执行 Git 提交或推送。
