# 统一任务中心开发计划

## 目标

将原“定时任务”升级为统一任务中心，集中管理学生档案、学习项目、知识加工、成长模型和系统维护产生的任务，并为不同 Agent 执行方式提供统一入口与审计记录。

## P0：统一任务台账与操作入口

- [x] 导航与页面由“定时任务”升级为“任务中心”。
- [x] 汇总学生每日资料消化和知识库维护任务。
- [x] 汇总项目资料消化、知识资产审核和贡献归档任务。
- [x] 统一任务状态：待处理、执行中、等待结果、已计划、已完成、阻塞。
- [x] 支持按状态、来源和执行者筛选。
- [x] 支持从任务中心定位到学生操作或项目工作流。
- [x] 汇总既有任务账本和最近执行历史。
- [x] 保留原有学生消化、lint、维护报告和单学生账本入口。

## 后续开发顺序

后续开发严格按照以下顺序推进。前一阶段通过验收后再进入下一阶段，避免在任务协议和安全边界尚未稳定时过早开发智能路由。

### P1：统一任务中心与状态协议

- [x] 定义版本化任务包 `TaskEnvelope`：任务 ID、协议版本、任务类型、来源、输入、预期输出、执行者、触发方式、优先级、截止时间、权限声明和幂等键。
- [x] 定义统一状态机：`draft → pending → approved → queued → running → waiting_result → reviewing → succeeded / failed / blocked / cancelled / timed_out`。
- [x] 定义标准结果包 `TaskResult`：执行摘要、结构化输出、产物路径、文件变更清单、日志引用、校验结果、失败原因和重试信息。
- [x] 建立状态流转校验，禁止 Agent 任意跳转或直接声明任务成功。
- [x] 为现有学生消化、项目消化、知识审核和贡献归档任务补齐统一协议字段。
- [x] 提供任务协议版本迁移，兼容现有任务账本和执行历史。

**阶段验收：**同一个任务包可以被任意执行器读取，任务中心能够完整显示其来源、状态、输入、输出和历史流转。

### P2：解除 Codex 硬编码，建立 Agent 执行适配器

- [x] 定义统一 `AgentExecutionAdapter` 接口：能力探测、任务提交、状态查询、结果读取、取消和健康检查。
- [x] 将现有 Codex CLI 直接调用迁移为 `CodexAdapter`，业务模块不再引用 Codex 专用命令。
- [x] 建立 Agent 能力注册表，记录是否支持自动提交、回调、轮询、取消、定时和结构化结果。
- [x] 实现 `ManualAdapter`：复制任务指令、导出任务包、人工导入结果和人工确认完成。
- [x] 建立统一降级规则：自动执行不可用、授权失效或能力不匹配时，平滑降级为人工执行，不丢失任务上下文。
- [x] 预留 Claude Code 等后续适配器接入点，但本阶段不扩展智能路由。

**阶段验收：**切换执行器不需要修改学生、项目或知识加工业务代码；移除 Codex 后，任务仍可通过人工模式完整执行并回写结果。

### P3：以“每日行动建议”打通第一个自动化闭环

- [x] 定义“每日行动建议”任务模板、输入范围、输出 Schema、生成时点和失效规则。
- [x] 按日期汇总学生最新资料、成长模型、未完成任务、项目状态和前一日反馈。
- [x] 建立工作流：数据准备 → 建议生成 → 结果校验 → 人工审核 → 发布 → 学生反馈 → 次日滚动更新。
- [x] 支持每日唯一任务和幂等执行，重复触发不得产生多份正式建议。
- [x] 支持建议完成、部分完成、跳过和原因反馈，并把反馈作为次日输入。
- [x] 自动执行失败时进入人工队列，可复制指令、导入结果并继续原任务状态链。

**阶段验收：**至少一个学生连续完成两天闭环，第二天建议能够读取第一天的完成反馈；每一步均可在任务中心查看、审核和追溯。

### P4：接通 OpenClaw 与 QClaw

- [x] 实现 `OpenClawAdapter`，支持 CLI / Gateway / Cron 能力探测、直接提交、状态轮询、结果读取和取消。
- [x] 将 OpenClaw 定时触发统一转化为任务中心任务，避免形成独立的第二套任务账本。
- [x] 实现 QClaw 任务收件箱：写入标准任务包、领取状态、处理中状态和结果回写。
- [x] 为 QClaw 建立回执与超时检测，无法主动调用时仍可通过收件箱和轮询完成异步协作。
- [x] 在任务中心展示实际执行 Agent、适配器状态、自动/人工模式及最后心跳时间。
- [x] 保留 ManualAdapter 作为两类 Agent 不可用时的统一降级路径。

**阶段验收：**同一“每日行动建议”任务可分别由 OpenClaw 自动执行、QClaw 收件箱执行和人工模式执行，结果均回到同一审核流程。

### P5：审批、权限、日志、超时与重试

- [x] 建立最小权限模型：允许读取和写入的学生、项目、知识空间、目录和操作类型。
- [x] 为删除、覆盖、发布成长证据、批量归档等高风险动作增加执行前审批。
- [x] 保存任务事件日志、Agent 调用日志、文件变更清单、审批记录和结果校验记录。
- [x] 增加超时、心跳丢失、取消、失败分类和可配置重试策略。
- [x] 重试沿用原任务 ID 和幂等键，并生成独立执行批次，避免重复写入和重复发布。
- [x] 支持任务重新指派、人工接管、失败恢复和必要的回滚记录。
- [x] 新资料、项目阶段变化和定时计划等事件统一创建任务，不允许绕过任务中心直接执行关键操作。

**阶段验收：**高风险任务未经审批无法执行；超时或失败任务可安全重试或人工接管；审计记录可以还原一次执行的输入、操作者、文件变化和最终结果。

### P6：多 Agent 智能路由

- [x] 建立 Agent 能力、在线状态、授权状态、成本、速度、历史质量和数据边界评价模型。
- [x] 根据任务类型、权限要求、数据位置、时限和质量要求生成候选 Agent 列表。
- [x] 支持固定指定、规则路由、智能推荐和人工确认四种模式。
- [x] 智能路由只负责选择执行器，不改变统一任务协议、审批规则和结果审核流程。
- [x] 记录路由原因、备选方案、执行成本和质量结果，用于后续策略优化。
- [x] 路由失败时按照预设顺序切换其他适配器，最终降级到 ManualAdapter。

**阶段验收：**同一任务可按规则或推荐选择不同 Agent，路由结果可解释、可覆盖、可审计，并始终具备人工兜底。

## 目标运行模式

```text
业务模块创建标准任务
        ↓
统一任务中心与状态机
        ↓
审批与权限检查
        ↓
AgentExecutionAdapter
        ↓
自动执行 / 任务收件箱 / 人工执行
        ↓
标准 TaskResult 回写
        ↓
结果校验与人工审核
        ↓
发布结果并记录完整审计日志
```

最终原则：任何 Agent 都接收同一种任务；具备接口的 Agent 自动执行，不具备接口的 Agent 平滑降级为人工执行；所有结果都回到同一个任务中心审核。

- P6：固定、规则、智能推荐、人工确认四种路由可用，并记录候选评分、选择原因、成本与质量指标。

## 0.7.37 审计缺口封闭记录

- 执行批次：协议、任务和执行批次强绑定；过期 QClaw 结果隔离，人工导入同样拒绝旧批次。
- 状态审核：`running`、`waiting_result` 不能直接成功，统一经过 `reviewing`。
- 每日闭环：严格校验 frontmatter、日期、生成时间、审核状态和非空章节；行为测试模拟第一天反馈进入第二天上下文。
- Cron 统一执行：明确标记且权限完整的教育管家 OpenClaw Cron 会先登记、再停用外部计划，并由任务中心按周期生成幂等执行批次。
- 行为测试：协议核心改为可直接执行的纯函数测试，覆盖状态、批次、Schema、两日反馈、权限、重试和 Cron，不再只依赖源码正则。

## 完成标准

- 任何任务都拥有唯一任务 ID、明确来源、状态、执行者和执行方式。
- 任何 Agent 都通过 `AgentExecutionAdapter` 接收标准任务，不允许业务模块硬编码特定 Agent。
- 自动执行失败时可以安全降级为人工执行。
- 自动、异步收件箱和人工执行必须使用同一状态协议与结果协议。
- 任务结果必须通过文件或结构化状态验证，不能只依赖 Agent 的文字声明。
- 删除、覆盖、发布成长证据等高风险动作必须经过人工确认。
- 所有任务结果必须返回任务中心统一审核，Agent 不得绕过审核直接发布正式成长结论。
