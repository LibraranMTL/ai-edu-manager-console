# R20 旧版回退与 FAT 测试准备方案

R20 是固定基线。本文件记录隔离试验和建议，**不是已获生产验收的一键回退流程**。生产数据不要直接覆盖或降级。

## 原因与原则

0.20.4 的项目数据来自 `projects.json`，R20 升级后项目更新写入 `project-state.sqlite3`。直接启动 0.20.4 只能看到迁移前的 JSON，不能看到升级后的项目修改。回退时至少要保留可校验的 R20 数据库一致性快照，并把数据库投影为旧版可读取的 JSON；同时不得丢弃旧文件、回执和升级后数据。

完整回退还涉及学生、任务、资产、收件箱、回执、项目资料登记和知识目录等，不能因为项目投影通过而断言它们全部兼容。旧版不认识的字段、状态、跨学生权限和新功能也不能默认安全。旧版在回退环境的新写入与 R20 的写入不能自行合并。

## 已验证的项目投影试验

1. 停止合成夹具的旧版和 R20 进程，R20 生产主机未参与。
2. 使用 SQLite backup 从 R20 合成项目数据库创建一致性副本，在副本做完整性检查并读取完整项目、暂存资料和工作区扫描记录。
3. 在新建隔离目录生成旧版 `version: 1` 项目 JSON，复制必要的合成目录；仅为隔离试验将项目路径指向该新目录。保留数据库快照和源数据。
4. 启动实际 Windows 0.20.4 便携程序，使用 `--qa-isolated`、独立用户数据目录和停用调度的测试环境，通过旧版 IPC 读取到两个合成项目；其中项目描述为“R20升级后写入的合成变化”，确认不是旧版升级前的旧描述。

## 生产方案需补齐的步骤

- 确定目标旧版和每类数据的兼容清单；明确无法表达的字段与状态，产生可供人工核对的差异报告。
- 在停写、任务停调度且进程退出的状态下，制作可校验的整个主机及学生资料备份，使用 SQLite 一致性快照而非直接复制运行中的数据库；记录版本、哈希和恢复步骤。
- 导出到全新的隔离目录，对项目、学生、任务、资产、收件箱与回执分别校验数量、身份、关联及文件指纹；发现不支持或冲突时停止，不覆盖现有目录。
- 在该副本启动目标旧版，核对读取、受控写入及原件访问；保留升级后 R20 快照和迁移清单。正式切换前需根据实际备份和差异确认可接受的功能损失，且制定返回 R20 的恢复办法。
- 禁止旧版和 R20 同时写入同一份资料；旧版写入若需回归 R20，须先设计并验证冲突检测与合并，不能以覆盖原文件代替合并。

这些步骤属于待实现和待验收方案；当前仅验证了项目投影的一项合成例子。

## 如何准备 FAT32 / exFAT 测试目录

1. 使用一块可擦写的 U 盘或其他可移动盘，先备份其中所有内容。若已有 FAT32 或 exFAT 且有足够空间，可以直接使用已有盘，不必格式化。
2. 在 Windows“此电脑”中查看盘符和“属性”，确认文件系统是 FAT32 或 exFAT。若需要格式化，先反复确认选中的是测试盘：**格式化会删除该卷内容**。在资源管理器中右键该测试盘选择“格式化”，选择 FAT32 或 exFAT 并完成；不要选择系统盘或资料盘。
3. 在测试盘根目录新建专用空文件夹，例如 `F:\edu-r20-fat-test`，其中 `F:` 应替换为实际测试盘符。请提供该目录的绝对路径，并确保测试期间不要拔盘。测试只应使用合成文件；不要把正式学生资料复制到该目录。
4. 测试前再次核对盘符、文件系统、空文件夹和可用空间。记录测试结果和备份后，再由测试脚本在专用目录中新建合成文件，确认硬链接行为、SQLite 可用性、迁移失败时的原件/备份及可恢复步骤。

WSL 中通过网络式共享访问 FAT32 镜像时，硬链接返回 `ENOTSUP`，但 SQLite 在更早阶段报锁定；该结果不替代 Windows 直接挂载 FAT/exFAT 卷的实测。当前计算机没有可写的此类卷。
