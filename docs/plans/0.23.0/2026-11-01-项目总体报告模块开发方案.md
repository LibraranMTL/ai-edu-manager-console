# AI教育管家项目总体报告模块开发方案

**交付目标**　在 Windows 主机的单个项目详情中提供「项目总体报告」。学生能找到下一步，家长能看到孩子有依据的贡献，老师能从关键判断定位到对应版本的材料。首屏回答四件事：当前阶段、本次变化、代表成果、下一步行动。

**开发路线**　先让一份有来源的阶段报告可读、可复核，再接入后台自动更新、历史比较与结项快照。报告沿用项目资料、统一任务中心和归档回执。主机负责证据校验、权限裁剪和正式版本写入，Agent 只返回结构化候选判断。

**技术与基线**　Electron、React、TypeScript、Node.js、SQLite 和现有 Worker。2026 年 11 月 1 日复核时，仓库 Git HEAD 仍为正式 Windows 0.21.6 所在提交 `1bc23c68`，但工作树中的 `package.json` 已标为 0.22.8，并包含大量未提交候选改动；现有 0.22.8 验收记录仍是“预候选、不得发布”。因此不能只用版本号或 HEAD 代表实施基线。任务 0 必须记录分支、提交、工作树状态摘要/指纹、数据库版本、目标包及 `app.asar` 指纹和验收状态，并从经确认的干净工作树实施。文中新增文件、表和接口均为拟议名称。[产品设计与原型](https://chatgpt.com/space/page_9e44d91769908191840a735cfa23b9de)

## 〇　评估结论与修订决策

**总体判断：方向正确，证据与故障边界完整，但原方案把三个不同难度的交付层同时称为“首版”，容易造成排期和验收失真。** 修订后将 M1 定位为可单独试用的“项目阶段摘要”，M2 才引入自动生成和版本差异，M3 才形成可对外交付的完整项目总体报告。

| 评估项 | 结论 | 修订后的处理 |
|---|---|---|
| 用户价值 | 高。首屏四问和原文下钻能直接支持学生、家长和老师。 | M1 保留四问，但证据不足时使用“已登记事实/待验证”，不显示综合性达标结论。 |
| 技术可行性 | 可行，但涉及项目快照、逐条引用、权限投影、报告版本、任务回执、归档与恢复七条链路。 | 分成 M1/M2/M3 三次独立放行；每次都能关闭且不破坏已有项目资料。 |
| 最大风险 | 脏基线、全量扫描造成卡顿、个人贡献越权、Agent 文本有引用但句意不成立、归档副作用。 | 先冻结基线；构建只读快照；主机校验 Claim；所有展示统一走当前授权投影；浏览零写入。 |
| 复用边界 | 与学情模块共享证据引用、截止时刻、授权投影、修订/撤回和幂等提交语义，但项目判断不能写入学生掌握度。 | 先冻结共享字段含义，不急于抽象成大型公共框架；由各域保留自己的状态机和存储。 |
| 工期可信度 | 原文没有人日估算，容易被误解为七项任务可一次完成。 | 基线冻结后重估；当前仅作低置信参考：M1 15–24 人日、M2 12–20 人日、M3 10–18 人日，另计真实材料等待和身份系统缺口。 |

**明确非目标。** M1 不建立真实家长账号、不自动对外分享、不把项目结论写成学生能力或知识掌握、不扫描未登记磁盘目录、不替代原有贡献审核、不把“打开页面”当作生成触发器。

## 一　交付里程碑

| 里程碑 | 用户能做什么 | 通过条件 |
|---|---|---|
| M1　可核查的项目阶段摘要 | 打开已有项目、看阶段摘要、点开一条依据、补充项目资料。无 Agent 时仍能读已登记的目标、作品和上次有效版。 | 只有目标时给补资料入口。一份已采用草图只能显示有来源的阶段事实和待验证项，不生成综合达标结论。打开页面对项目、队列和成长模型零写入。 |
| M2　随证据更新的报告 | 自动或手动更新，查看本次改变了哪项判断，按当前授权看团队成果与个人贡献。 | 新版实测材料能修正旧结论；重复提交、截断数据、撤权和迟到回执均有可复现测试。 |
| M3　结项与交付 | 回看阶段版与结项版，导出当前有权查看的报告，迁移到另一台主机后仍能找到历史版本。 | 成功归档只产生一份结项版本；恢复不会重做归档或重复发布。Windows 真机完成从资料到报告的全流程。 |

M1 可先交付内部试用，并在界面明确标为“阶段摘要”。完整首版以 M3 为准。本轮覆盖单项目 Windows 入口；跨项目总览、微信传播和独立云端登录属于其他交付范围。

## 三　报告内容和证据契约

| 报告栏目 | 首版的输出与判断边界 |
|---|---|
| 1 项目概况 | 从项目登记、任务书读取目标、预期交付物和成功标准。无明确标准时显示「尚未约定」。 |
| 2 阶段与本期变化 | 用实物、作品、记录或实测认定里程碑。首次生成单独标注；后续列出新增、修订、撤回的判断。 |
| 3 探究与迭代 | 选一至三次有依据的尝试。版本差异支持「改了什么」，署名说明或讨论记录支持「为什么改」，效果需测试或反馈。 |
| 4 成果与目标达成 | 按目标列标准、观察、结论和依据。使用已达到、部分达到、未达到、待验证、资料矛盾五种状态。仅有明确定义且可拆分的标准才给「部分达到」。 |
| 5 团队成果与个人贡献 | 团队作品只计一次。个人结论要求明确学生、可核验来源及已确认状态。只有审核权的读者可进入原有审核入口。 |
| 6 缺口与下一步 | 首屏显示一项最高优先行动，展开最多三项。每项写明做什么、原因及完成标志。建议、已完成动作分别标识。 |
| 7 展示材料 | 展示一至三件已获授权的代表材料，附版本和选择理由。选择材料用于正式作品集或对外分享由用户另行发起。 |

**建议冻结四个对象的接口。** 后端和界面先用同一份虚构项目夹具联调，再替换为真实数据。

| 对象 | 必备字段 | 用途 |
|---|---|---|
| `EvidenceSnapshot` | projectId、截止时间、输入指纹、授权指纹、代次、目标版本、成员确认关系、证据清单、覆盖与缺口 | 固定本次允许分析的输入。证据清单分别记录范围内、已成功读取、无法读取及尚未审核的项目。 |
| `Citation` | citationId、projectId、材料或知识 ID、版本、内容哈希、来源类型、定位、受众范围 | 定位支持页码、表格/工作表行、图片区域、视频时间或整份文件。无可靠锚点时标明「文件级依据」。 |
| `Claim` | 稳定判断键、栏目、目标、团队或学生范围、事实/判断/建议、观察值及单位、适用条件、状态、引用 ID | 比较前后版本，定位需要撤回的句子。稳定键按目标、判断种类及主体建立，改写措辞沿用原键。 |
| `ReportRevision` | 项目 ID、版本 ID、前版、阶段/结项/补充说明、生成时间、资料截止时间、提交键、内容指纹、判断及引用、归档回执（若有） | 保存不可变版本。当前可读版本由主机原子切换，展示时按最新权限投影。 |

这四个对象应与另两份方案统一以下字段语义：`SubjectScope`（学生或项目及其可信绑定）、`EvidenceRef`（来源 ID、版本、哈希和定位）、`AsOfCutoff`（截止时刻和时区）、`AccessProjection`（读者、用途和授权版本）、`CommitKey`（幂等业务键）、`Correction/Withdrawal`（追加式更正与撤回）。共享的是语义和测试夹具，不代表三个模块必须共用一张表。

**发布判例。** 虚构云台支架的目标是俯仰 ±30° 全程不碰线。只有 CAD 与修改说明时，可写「第二版调整了走线，实物效果待验证」。补入 T1 表后，若其中记录「±20° 内无碰线，+30° 碰线」，就写「第二版本次测试未达到全范围目标」，引用 T1 中对应行。−30° 缺观测时保持未知。首次出现的反例、未测端点和版本号都必须在生成后保留下来。

## 四　实施任务

**执行方式**　任务 0 先锁定基线。任务 1–3 打通 M1；任务 4–5 打通 M2；任务 6 验收 M3。每项先写表中失败场景，确认能复现，再实现、运行对应测试并独立提交。可用 `superpowers:executing-plans` 逐项执行。

### 任务 0　冻结目标版本和验收样本

- [ ] **交付负责人**从已确认候选建立干净、可回滚的实施工作树；不得直接在当前 0.22.8 脏工作树叠加开发。记录交付包对应的分支、提交、工作树状态指纹、包体/`app.asar` 指纹、候选验收状态、数据库版本、现有自动运行开关、项目管理权限和回执收口路径。
- [ ] 用隔离数据跑通已有项目资料、归档和任务测试，记录基线失败项。若目标候选仍处于“不得发布”，本模块只能形成开发候选，不能反向把底座描述成已发布版本。
- [ ] 建立 `tests/fixtures/project-overall-report/`，包含空项目、两版草图、带单位和角度的 T1 表、矛盾记录、两名学生及其不同的证据归属、旧格式项目。所有数据均为虚构。
- [ ] **完成条件**为每份夹具列出预期结论、当前读者能看到的行、可以打开的来源及下一步。将已知的 Windows 就绪门控、未知执行结果和宿主性能问题列入集成检查。

### 任务 1　生成完整且可重复的项目证据快照

- [ ] 新建 `electron/project-report-snapshot.cjs`，提供 `buildEvidenceSnapshot(projectId, generationScope)`。在受控后台作业中读取项目元数据原始 revision、成员、目标、当前完整登记清单和有效绑定；优先使用已有消化结果和可验证的文本/OCR 摘录，按需限量读取原件。
- [ ] workspace-v1 从完整 `materials / knowledge / evidenceBindings` 与项目 `studentEvidence` 形成关联；按授权知识目录补识别人工知识，区分已提交、已审核、正文已改和无固定来源。旧项目按其 rawPath、消化清单和知识审核记录适配。仅有文件名、无法解析的专有格式可证明交付物存在，更深入的判断需另有可读材料。
- [ ] 为大项目分页或分块归并，登记可核对的总量和处理失败原因，并记录各目标的覆盖范围。第 501 条、文本尾部或超限材料不得静默丢弃。若目标范围内仍有可能影响达标判断的材料未分析，相应目标保留待验证。报告版本、导出件和任务回执从原始证据中排除。
- [ ] 读取前后核对项目 revision、登记清单 revision 和授权范围。变化则丢弃混合快照、合并后重建。指纹涵盖目标、已采用内容版本/哈希、成员归属和状态；仅改文件显示名可刷新定位，不触发全文重算。
- [ ] **测试**　`tests/project-overall-report-snapshot.test.cjs` 覆盖材料超过 100、知识及贡献超过 500、尾部反例、旧项目、缺失原件和读到一半修改。读取前后正式项目资料、贡献、任务数相同。

### 任务 2　校验每条判断并按读者授权呈现

- [ ] 新建 `electron/project-report-claims.cjs` 和 `electron/project-report-access.cjs`。候选报告只能引用快照中的 ID；主机校验项目、学生归属、材料版本、引用锚点、数值、单位、正负号及测试条件。仅有引用存在还不足以证明句意。达标判断必须由结构化标准和可比观察值支持，或有已确认评价原文明确支持。其余主观评价归到「反馈」或「待复核」。已审核文档同路径改写后，先核对正文哈希与原审核版是否一致。
- [ ] 将团队共有事实与学生个人贡献分别处理，按证据依赖确定可见范围。分析包按受众范围隔离，个人资料不能悄悄影响共享摘要。来源撤回或授权变化后，正文、首屏摘要、版本差异、计数、附件及导出立即按当前授权重新裁剪；受影响且仍获授权的判断标为待复核。
- [ ] 主机从可信身份、项目及学生绑定派生权限。`localProjectSourceAccess` 验证的是管理员主窗口。若目标版没有经验证的家长或教师身份，Windows 的角色切换只能标作「受众预览」。向实际用户提供含个人内容的阅读或导出，必须通过真实身份绑定或管理员明确选择获授权读者的导出流程。不能验证范围时关闭相应个人视图。
- [ ] 原文入口只接受 `projectId / revisionId / citationId`。主机解析具体版本，复验当前采用状态、绑定、哈希和读取权限。无法精确定位时降到经过验证的整份文件。内容或权限已变时停止打开并给出原因，禁止回退到最新文件或任意磁盘路径。
- [ ] **测试**　`tests/project-overall-report-claims.test.cjs` 验证 T1、单位、正负号、无实测、矛盾；`tests/project-overall-report-access.test.cjs` 验证错学生、撤权、同名材料、路径穿越及摘要/历史/导出泄露。

### 任务 3　保存不可变版本并交付可读首页

- [ ] 在 `electron/project-state-store.cjs` 增加受版本管理的迁移；经现有项目状态 IO Worker 执行短事务。新增版本表与当前版本指针，按项目及提交键设唯一约束。目标版仍为 schema v3 时做 v3 到 v4 的迁移，若已占用则采用其下一可用版本。数据库只保存必要报告内容和证据清单，原件留在既有资产空间。
- [ ] 实现 `commitReportRevision(runKey, expectedEpoch, candidate)`。同一事务核对当前代次、记录版本和切换指针。同一请求重试返回原版本；与当前版只有文字润色时记录任务检查结果，用户版本号保持。若正文已生成但写账失败，继续显示上次安全可读版本。即使最新任务失败，已失效的依据也要按任务 2 的规则即时处理。
- [ ] 新增主机桥与 `src/ProjectOverallReportPanel.tsx`。页面提供「查看依据」「查看上版变化」「添加资料」及授权用户的「立即更新」。页面首次查询只读；无版时直接从已有元数据展示概况，有一项合格材料时可显示可核查的基础摘要。生成由项目变化事件或明确更新操作触发。浏览、刷新和切换项目均不派发任务。
- [ ] **测试**　`tests/project-overall-report-store.test.cjs` 验证迁移、重复请求、写入中断、迟到旧代次；`tests/project-overall-report-ui.test.cjs` 验证空态、四项首屏、单项目隔离、旧版可读及依据侧栏。在 M1 演示中用同一份草图从首屏点到原件。

### 任务 4　从统一任务中心受控生成和更新

- [ ] 注册任务 `project_overall_report`。在自动派发和操作白名单、执行合同、完整输入输出校验及任务详情中注册同一 kind。设置 `sourceType=project`、`sourceId=projectId`。新增最小只读报告 profile，冻结已许可的证据摘录，通过受控通道返回候选结构；正式版本写入只由主机完成。现有消化 profile 允许写项目知识根，不可直接用于此任务。
- [ ] 在项目目标、里程碑、采用材料、实测、贡献确认或撤回发生实质变化时标记待更新。建议首轮用 10 秒合并相邻事件，参数写入测试。撤权与来源失效的阅读保护即时生效，不等待这 10 秒。关闭自动运行时保留待更新标记；授权用户可手动触发。无执行器时显示原版、截止时间和可处理的状态，有基础材料时保留可核查摘要。
- [ ] 生成键由项目、代次、输入指纹、策略版本及报告类型构成。同一批手动与自动请求共享任务。新证据只提高代次，不篡改在途输入。实际执行沿用资源预算、就绪检查及回退顺序；执行结果未知先查原回执，只有确定未执行或已安全结束时才允许重新派发。
- [ ] 接入 `validateTaskCompletion` 与 `commitValidatedTaskResult` 的专用分支。检查任务 ID、执行 ID、冻结范围和逐条证据；通过后提交报告，再将任务记为成功。报告库与任务库之间使用持久提交键对账：若版本已入库而任务状态尚未写成，重启补记状态即可。旧代次不能覆盖当前指针。
- [ ] **测试**　`tests/project-overall-report-task.test.cjs` 从真实入队入口走到任务结算。注入重复点击、自动关闭、执行器未就绪、执行未知、旧回执、成员变更和「版本已提交但任务记账失败」。核对执行次数、版本数、最终任务状态。

### 任务 5　完成七栏报告和版本差异

- [ ] 在已通过校验的判断上生成七栏和四项首屏。项目类型只影响呈现：研究类突出主要发现和适用条件，设计类突出原型与测试，创作类突出作品与反馈。首页的下一步直接返回对应目标或当前项目的资料入口。
- [ ] 以稳定判断键比较当前版与上版，列出新增、修订、撤回和实质变化的理由。区分「尚未看到测试记录」「已记录尚未测试」「测试未达到目标」。待处理材料只影响依赖它的目标。用户发现错误时，从依据侧栏进入有权限的源记录或审核入口，保存订正理由并据此更新报告。个人行为继续交给既有贡献流程审核，查看报告或完成任务均不修改学生掌握度。
- [ ] **测试**　在同一 UI 夹具上先读 CAD，再加入 T1。屏幕应突出一条从「待验证」到「当前版本未达到 ±30° 目标」的变化，能打开正确测试行并看到复测建议。另测只改措辞、无可见变更、多人贡献和材料订正后的显示。

### 任务 6　结项快照、导出与恢复

- [ ] 对新式项目，在 `finishProjectPublicationTransaction` 的成功归档路径接入持久回执消费，并在启动恢复时补查。判定包括 `execute_archive_plan`、事务已提交、结果成功、项目已归档。以项目和真实归档事务 ID 去重；检查通过、归档任务排队、仅发布贡献都不能冻结结项版。
- [ ] 在归档事务中或其可恢复的准备记录内固定该时刻的报告输入及版本标识，只做轻量记录。事务已提交才发布结项快照。冻结当时有效的判断、缺口和截止时间；即便 Agent 离线也可据冻结输入生成基础结项版。已归档项目沿用禁止外部写入的规则；恢复只补派生报告。旧模式须同时核验持久化归档状态、时间和匹配成功的执行记录，使用其独立运行 ID。缺少可靠凭据时明确提示「结项记录待核对」。
- [ ] 归档后获授权的订正生成补充说明并关联原版。新增 Markdown、PDF 导出适配，以当前读者可见的报告投影为唯一输入。保存前再次验范围，移除内部路径和标识。撤权作用于后续应用内查看与导出；已经发送给接收方的本地副本不具备远程撤回能力。
- [ ] 扩展宿主迁移、恢复、软删除/恢复及项目包边界。现有 SQLite 备份可带走新增表，但旧恢复逻辑只执行项目 `readAll() → replaceAll()`，需显式迁移版本、指针和提交回执。保留 ID、校验引用、按当前授权展示。旧备份缺报告时显示无历史版；恢复不得留下目标机上同 ID 项目的无关旧报告。
- [ ] **测试**　`tests/project-overall-report-archive.test.cjs` 覆盖归档前后、提交后崩溃、重复回执、旧模式和补充说明。`tests/project-overall-report-export.test.cjs` 验证导出与当前投影一致。迁移到第二个隔离目录，核对版本链、结项回执和固定来源；撤权后复测历史与导出。

## 五　发布前验收

| 必测输入或故障 | 放行条件 |
|---|---|
| 只有目标，随后加入一张草图 | 概况可读；采用后出现阶段事实及其来源；单纯访问不生成任务、不写贡献草稿。 |
| 重复导入同一内容，多次打开，再同时手动与自动更新 | 同一代次一次有效执行、一次提交；单纯浏览不派发。 |
| CAD 后补 T1 表 | 首屏、达标状态、原始行、单位及下一步与判例一致。 |
| 冲突、撤回或撤销读者权限 | 显示待复核或裁剪相应判断；首屏、正文、差异、历史、原文及导出结果一致。 |
| 两名学生，仅一人有已确认且能追溯的贡献 | 团队作品一份，个人结论只出现在对应获授权视图。管理员预览与真实身份测试分开记录。 |
| 无执行器、未知结果、回执迟到、提交后断电 | 旧版可读；未重复执行；任务与已经持久化的版本可对账；较旧结果不能覆盖新结论。 |
| 第 501 条为反例，或关键观测位于材料末尾 | 报告纳入反例，或明确指出覆盖缺口并暂缓目标判断；不能显示「全部通过」。 |
| 归档有阻塞，随后归档成功并重复恢复 | 阻塞期间有阶段报告；归档后准确一份结项版；恢复报告不会再次归档。 |

**自动化与性能。** 在同一台代表性 Windows 主机上，用同一份大项目分别测试关闭和开启新功能，每种状态至少进行 30 次热打开，另测首次生成。记录数据规模、首页及报告首屏 P95、主窗口长任务和后台峰值内存。首轮建议门槛为已有报告的热打开 P95 不超过 1 秒，原有大型项目门禁继续通过；目标版本已有更严格预算时取其更严者。打开旧报告应只读当前版本及授权索引；原始树扫描、文档解析、哈希或等待 Agent 进入打开路径即判为失败。上述数值是待验收标准。

**试用、回退与交付物。** 候选版默认关闭新入口与自动生成，先在隔离项目启用，再由少量获授权用户试用。出现跨范围可见、虚假达标、重复派发或归档副作用，立即关闭生成及受影响的读取/导出入口，隔离未核准结果。保留原始材料、现有归档和审计记录。程序降级前按数据库版本策略使用升级前备份，验证恢复后再放行。最终交付目标包标识、通过/未通过清单、一份匿名阶段版与结项版、从测试表到结论的录屏，以及重启与跨机恢复记录。

## 六　与另外两份方案的依赖

1. 可复用“每周知识增长统计图”验证过的单学生范围解析、同一截止时刻快照和 PNG/导出权限复验方式，但项目报告不能直接使用其知识点首次登记账本。
2. 可复用“学情分析与学习模块”的 `EvidenceRef`、更正/撤回和读者投影语义；项目报告中的个人贡献只有经过项目贡献确认后才可进入学情证据，不能由报告文本反向推断能力。
3. 建议先完成共享契约夹具和权限泄漏测试，再开发 M1；M2 的自动任务应等现有 0.22.x 自动执行底座达到目标候选门禁后再启用。
4. 三个模块分别保留功能开关、数据库迁移和回退路径；任何一个模块关闭都不得让另外两个模块的数据不可读。

## 七　项目入口与“作品集项目”模板补充任务

### 7.1 首页项目相关入口

- [ ] 首页“项目进展”直接进入现有项目工作台并默认聚焦进行中项目；保留所选学生和返回首页的导航状态。打开入口只读取项目摘要，不触发报告生成、资料扫描或 Agent 执行。
- [ ] 首页“推荐选题”进入现有推荐选题页，“推荐比赛”进入现有推荐比赛页。两者沿用当前学生和授权范围；没有学生、没有结果或结果过期时分别显示真实状态，不能用示例推荐冒充实时结果。
- [ ] 为三个入口增加路由、学生切换、权限撤回和零副作用测试。项目统计若依赖资产总量，必须使用补充方案中带代次的统一资产统计快照，不读取曾经访问资产页留下的旧 `assetIndex.total`。

### 7.2 新增“作品集项目”

- [ ] 在前端模板列表和主进程模板白名单同时新增 `portfolio / 作品集项目`，工作空间只预置三个一级文件夹：`参考资料`、`过程文档`、`最终成果`。
- [ ] 建议模板说明为“用于设计、艺术、写作、研究或跨学科作品的过程沉淀与成果展示”；建议交付物为作品集成品、项目说明和过程反思。说明与交付物属于待负责人确认的产品建议，用户指定的三个文件夹名不得擅自改变。
- [ ] 新建项目或向既有项目应用模板时只创建缺失目录，不移动、重命名、覆盖或删除已有文件。复制、导入、导出和恢复必须保留模板 ID 与目录结构；旧版本遇到未知模板仍按普通项目安全打开。
- [ ] 对文件夹名执行路径安全校验，覆盖重复点击、非空项目、中文路径、复制、导入、恢复和旧项目不变测试。前后端模板定义不一致时测试必须失败。

详细状态和验收见同目录 `2026-11-01-Windows基础体验与项目新建补充开发方案.md`。这些补充任务可与项目报告 M1 分开交付；模板出现不代表项目报告或总体报告已完成。
