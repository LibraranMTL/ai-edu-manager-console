# Windows 个人终端自动会话采集 0.16.10 修复验收

## 1. 当前状态

0.16.10 已完成 Windows 主机端与 Windows 学生端的成对修复、自动化验证和本地正式包构建。根因是此前实际运行的 Windows 主机 0.16.9 正式包不含学生端调用的个人终端采集接口，学生端请求返回 404；同时学生端只有在授权成功后才写入 Agent 清单，导致界面误显示 `0/0 个已安装 Agent 已接入`。

本次安装包尚未上传网站或推送到 Git，也未完成两台真实 Windows 电脑与六种真实 Agent 的完整验收，因此不能把“本地正式包构建成功”写成“真机验收通过”或“已经上线”。

## 2. 用户操作

1. Windows 主机将学生电脑设为“个人终端”，并固定绑定一名学生。
2. 学生在 Windows 学生端进入本人学习空间，打开“设置”。
3. 在“自动会话记忆”卡片点击“授权采集”。
4. 授权前页面先显示本机检测到的受支持 Agent 数量；授权成功后再显示已接入数量和待补交事件数量。
5. 之后在受支持 Agent 中开始新会话；无需在每个新会话重复输入授权语句。
6. 需要停止时点击“停止采集”。已有归档不会删除。

当前自动探测和接入的 Agent 为：Codex、QClaw、WorkBuddy、OpenClaw、Claude Code、Hermes。未安装的 Agent 不会报错，也不会要求用户配置。

## 3. 数据边界

- 只适用于已经登录且固定绑定学生的 Windows 个人终端；共享终端不能启用。
- Hook 配置不保存主机地址、设备令牌或学生会话令牌，只写入固定学生范围、固定设备授权编号和本机队列路径。
- 只接收授权之后由 Agent 生命周期发出的新会话事件，不读取授权前历史、系统提示、工具密钥或教育管家任务中心上下文。
- 学生端使用当前学生会话令牌向主机补交事件；主机再次校验 Windows 平台、个人终端模式、设备、绑定学生、授权状态和 Agent 白名单。
- 普通断网时事件留在本机队列，连接恢复后补交；主机明确返回 401 或 403 时，本机立即关闭采集描述符。
- 主机返回 404 时，学生端保持未授权、不安装新的生命周期 Hook，并明确提示同时升级主机端与学生端到 0.16.10 或更高版本。
- 切换为共享终端、断开主机或学生会话退出时，本机描述符立即停用；切换为共享终端或断开主机还会移除或禁用受管 Hook/插件。

## 5. 正式发布前真机验收

至少使用一台 Windows 主机和一台独立 Windows 学生电脑：

1. 配对学生电脑，设为个人终端并绑定测试学生。
2. 安装其中至少一种受支持 Agent，点击“授权采集”，确认接入数量变化。
3. 在 Agent 中发送一条用户消息并取得一条助手回复，正常结束会话。
4. 在主机“智能体知识管理 → 自动会话记忆”确认会话归入唯一绑定学生，正文、Agent 来源和时间正确。
5. 断开学生电脑网络，完成一段新会话，确认显示待补交；恢复网络后确认同一会话只归档一次。
6. 切换为共享终端，确认开关不可用且新会话不再采集；再换一名学生登录，确认没有前一名学生的事件或内容。
7. 分别对已安装的 Codex、QClaw、WorkBuddy、OpenClaw、Claude Code、Hermes 执行真实生命周期验收。未安装项应记录为未覆盖，不得写成通过。

相关操作手册、发布清单和本地网站文件已更新到 0.16.10，但尚未上传线上。全部真机结果通过后，才可以继续网站发布与 Git 发布，并把该安装包作为公开正式版本分发。
