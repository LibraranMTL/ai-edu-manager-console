# 课程管理模块：平台版权限与课程编辑修改方案

> 制定日期：2026-08-01
> 建议目标版本：Windows 主机端 0.15.6 受控候选
> 方案状态：0.15.8 已按统一平台权限和内置验签公钥简化，待 Windows 真机验收
> 核心决定：不增加独立平台客户端，不增加新的网络端口；继续使用同一 Windows 主机安装包，由 License 决定版本、身份和能力。

本文件保留 0.15.6 的课程管理技术设计；生产密钥初始化、机构版升级、密钥备份轮换、运维体验和后续发布门禁，以《[平台版新增功能完整开发计划](./平台版新增功能完整开发计划.md)》为后续实施主计划。

> **现行决策覆盖说明（2026-08-02）：** 平台版不再区分编辑、发布和管理员身份；有效平台版 License 统一获得平台课程编辑、发布和恢复能力。专业版、机构版和平台版接收主机使用安装包内置公钥自动验签，不再导入课程验证公钥包。本文后续出现的旧角色字段和手工公钥分发描述仅保留为历史设计记录，不再作为实现要求。

## 一、目标

1. 保持“精选课程 → 课程学习 / 课程管理”现有二级菜单不变。
2. 家庭版、专业版和机构版现有课程能力不降级。
3. 在现有“课程管理”页面内，为平台版增加平台课程新增、编辑、校验、发布、撤回和回滚能力。
4. License 管理平台发放许可证时只选择版本；Windows 主机根据签名许可证自动显示对应功能。
5. 平台课程继续使用签名目录，客户侧无法伪造或覆盖 `platform_standard` 课程。
6. 平台课程目录、课程图片和版本信息作为一个完整签名包发布。
7. License 签名私钥和课程目录签名私钥相互独立，均不进入 Windows 安装包。

## 二、不做事项

- 不新增“平台运营端”安装包。
- 不新增平台课程专用常驻服务或网络端口。
- 不允许专业版、机构版通过修改本地缓存获得平台课程编辑权。
- 不把课程目录签名私钥写入源码、安装包、License 或普通配置文件。
- 不允许平台课程草稿未经校验直接替换当前最后可用签名目录。
- 不在本阶段建设完整云端多租户课程商城、收费、排课或学习进度系统。

## 三、版本与能力模型

### 1. 版本

| edition | 用户界面名称 | 课程能力 |
|---|---|---|
| `TRIAL` | 试用版 | 课程学习；服从已下发目录 |
| `FAMILY` | 家庭版 | 课程学习；服从已下发目录 |
| `PRO` | 专业版 | 机构自选课程、课程策略和学生分配 |
| `ORG` | 机构版 | 机构自选课程、课程策略和学生分配 |
| `PLATFORM` | 平台版 | 包含机构版能力，并统一获得平台课程编辑、发布和恢复能力 |

平台版暂定为内部或定向授权，不进入公开购买页面。

### 2. 平台权限

平台版采用统一权限，不再设置编辑、发布或管理员身份。签名 License 的 `edition=PLATFORM` 是平台课程编辑、发布和恢复能力的唯一产品级授权条件；发布主机还必须配置与安装包内置公钥匹配的课程签名凭据。

### 3. 能力代码

主机端不应把全部逻辑散落为 `plan === 'PLATFORM'`，统一解析为能力：

```text
course_learning
course_policy_manage
tenant_course_manage
platform_course_edit
platform_course_publish
platform_course_rollback
```

默认映射：

- `PRO / ORG`：`course_learning + course_policy_manage + tenant_course_manage`
- `PLATFORM`：以上能力加 `platform_course_edit + platform_course_publish + platform_course_rollback`

所有写操作必须同时在渲染层和 Electron 主进程 IPC 层检查能力。隐藏按钮不能代替主进程鉴权。

## 四、License 管理平台修改

### 1. 发放界面

在现有 License 管理平台增加：

- 版本：试用版、家庭版、专业版、机构版、平台版；
- 平台版不显示身份字段；
- 客户/机构标识；
- 学生上限、设备上限；
- 生效时间、到期时间；
- 可选设备绑定策略；
- 签发人、签发时间和许可证唯一编号。

### 2. 新许可证结构

```json
{
  "schema": "edu-manager.license.v2",
  "licenseId": "lic_...",
  "customerId": "customer_...",
  "tenantId": "tenant_...",
  "edition": "PLATFORM",
  "capabilities": [
    "course_learning",
    "course_policy_manage",
    "tenant_course_manage",
    "platform_course_edit",
    "platform_course_publish",
    "platform_course_rollback"
  ],
  "studentLimit": 10000,
  "deviceLimit": 3,
  "devicePolicy": "optional_binding",
  "issuedAt": "2026-08-01T00:00:00.000Z",
  "expiresAt": "2027-12-31T23:59:59.000Z",
  "issuer": "license-platform",
  "keyId": "license-platform-2026",
  "signature": "..."
}
```

`capabilities` 必须由签发端依据 `edition + role` 生成，License 管理人员不能任意输入未知能力字符串。

### 3. 签名机制升级

当前 v1 离线许可证由发码端和客户端共享 HMAC 密钥，不适合授予平台发布权限。修改为非对称签名：

```text
License 管理平台：保存 License 私钥并签发
Windows 主机端：只内置 License 公钥并验证
```

具体要求：

- License 签名使用独立 RSA-SHA256 密钥对并支持 `keyId` 轮换；
- 普通版本签发密钥不能签发 `PLATFORM`；
- 平台版使用单独的高权限 License 签发密钥；
- 客户端按公钥元数据限制每个签发密钥允许授予的最高版本；
- License 公钥可以进入安装包，私钥不得进入仓库和安装包；
- 在线发放可继续显示短激活码，主机用短码换取签名许可证；
- 离线发放提供 `.edu-license.json` 文件导入，避免要求用户手工输入超长签名文本。

### 4. 兼容策略

- 0.15.6 暂时兼容现有 v1 许可证，但 v1 只能映射到 `TRIAL / FAMILY / PRO / ORG`；
- v1 许可证即使把文本修改成 `PLATFORM`，主机也必须拒绝；
- 所有新发许可证优先使用 v2；
- 平台版权限只接受 v2 非对称签名许可证；
- 后续版本再根据换证完成率决定是否停止接受 v1。

## 五、课程管理界面修改

### 1. 导航保持不变

```text
精选课程
├─ 课程学习
└─ 课程管理
```

不新增一级菜单，也不新增独立客户端。课程管理页面内部增加标签：

```text
课程管理
├─ 课程设置
├─ 机构自选课程
└─ 平台课程发布    仅具有 platform_course_edit 时显示
```

### 2. 不同身份看到的课程操作

| 课程类型 | 专业版/机构版 | 平台编辑 | 平台发布/管理员 |
|---|---|---|---|
| `tenant_custom` | 新增、编辑、启用、排序、分配 | 同左 | 同左 |
| `platform_standard` | 只可启用、排序、设置年级和学生 | 可编辑平台草稿，不改变已发布目录 | 可编辑、发布、撤回和回滚 |

平台课程处于草稿状态时不得下发到学生端。学生端只读取最后通过签名校验的已发布目录。

### 3. 平台课程列表

每张课程卡片显示：

- 已发布课程名称和封面；
- `courseId`；
- 当前发布版本；
- 草稿状态：无草稿、已修改、校验失败、待发布；
- 课程状态：启用、预定生效、已撤回、已到期；
- 最近编辑时间和最近发布人；
- “编辑草稿”“预览课程”“校验”按钮；
- 有发布权限时显示“签名并发布”“撤回”“回滚”。

专业版和机构版不显示平台草稿及发布信息，只显示“平台签名课程由平台维护”。

### 4. 平台课程编辑表单

基础必填字段：

- 课程名称；
- 课程提供方；
- 课程简介；
- HTTPS 课程链接；
- 课程图片；
- 法律与版权说明。

课程范围字段：

- 学科；
- 适用年级；
- 课程语言；
- 账号或会员要求；
- 生效时间；
- 到期时间；
- 状态：启用或撤回。

安全字段：

- `courseId`：新增时自动生成 `platform:<slug>`，首次发布后不可修改；
- `allowedHosts`：根据课程链接自动提取，允许平台编辑者增加必要的精确域名；
- 不允许 `*` 通配符、HTTP、用户名密码、危险协议或本机地址；
- 预览时继续使用现有受限 `WebContentsView`，不能因平台版授权降低浏览器隔离规则。

版权审核字段：

- 权利状态：待确认、已确认、已到期；
- 权利证据引用或内部备注；
- 商标/封面使用确认；
- 审核人和审核时间。

权利状态不是“已确认”时允许保存草稿，但禁止正式发布。

### 5. 图片处理

- 支持 PNG、JPG/JPEG、WebP；
- 单图最大 5 MB；
- 渲染层只获得一次性图片令牌，不获得任意本地文件读取能力；
- 主进程重新检查扩展名、图片魔数、大小和尺寸；
- 保存草稿后把图片复制到平台草稿受控目录；
- 发布包使用内容哈希文件名，并在签名清单中记录 SHA-256。

## 六、平台课程草稿与发布数据

### 1. 草稿存储

建议新增：

```text
userData/
└─ platform-course-authoring/
   ├─ drafts.json
   ├─ assets/
   ├─ releases/
   └─ audit.json
```

草稿与当前 `last-good.json` 必须物理分开。保存草稿不能直接改变当前学生可见课程。

### 2. 草稿记录

```json
{
  "schema": "edu-manager.platform-course-draft.v1",
  "courseId": "platform:example-course",
  "baseCatalogVersion": "2026.07.30.1",
  "draftRevision": 3,
  "course": {},
  "rights": {},
  "createdAt": "...",
  "updatedAt": "...",
  "updatedBy": "licenseId-or-operator-id",
  "validation": {
    "ok": false,
    "issues": []
  }
}
```

### 3. 平台签名课程包 v2

将当前“仅签名 JSON”升级为包含图片的签名包，扩展名建议为 `.edu-coursepkg`：

```text
course-catalog-2026.08.01.1.edu-coursepkg
├─ manifest.json
├─ catalog.json
├─ assets/
│  ├─ <sha256>.png
│  └─ <sha256>.webp
└─ signature.json
```

`manifest.json` 至少记录：

- Schema 版本；
- 目录版本；
- 签发时间；
- 最低主机版本；
- 每个文件的相对路径、字节数和 SHA-256；
- 发布说明；
- 签名 `keyId`；
- 正常发布、撤回或回滚意图。

签名内容覆盖 `manifest.json + catalog.json + 全部资源哈希`。导入时必须防止 ZIP 路径穿越、重复文件名、超大文件、未知类型和资源哈希不一致。

### 4. 两套私钥必须分离

```text
License 私钥：签发版本、身份和能力
课程目录私钥：签发课程目录和图片资源
```

平台版 License 只授予调用发布流程的权限，不携带课程目录私钥。课程目录私钥可存放在 Windows 证书库、受控加密文件或外部安全介质中；主机仅在发布动作期间调用，不写入普通设置和日志。

## 七、编辑、发布与回滚流程

### 1. 编辑

1. 平台版用户进入“精选课程 → 课程管理 → 平台课程发布”。
2. 新增课程或对已发布课程创建草稿。
3. 填写字段并上传图片。
4. 保存草稿；此时不影响任何学生端。
5. 在受限浏览器中预览课程和允许域名跳转。

### 2. 校验

发布前自动执行：

- License 能力与有效期检查；
- 必填字段和长度检查；
- HTTPS、精确域名和重定向检查；
- 课程 ID 唯一性检查；
- 图片格式、大小和哈希检查；
- 生效、到期和撤回状态检查；
- 权利状态和法律说明检查；
- 新目录版本必须高于最后可用版本；
- 目录包完整性和签名前自检。

### 3. 发布

1. 发布者查看本次变更摘要。
2. 输入发布说明并二次确认。
3. 主进程再次检查 `platform_course_publish`。
4. 调用外部课程目录签名密钥生成 `.edu-coursepkg`。
5. 立即使用内置公钥回验刚生成的包。
6. 回验通过后写入发布历史，并可选择在当前主机应用。
7. 其他主机通过现有离线导入入口导入，未来可复用版本更新通道下发。

### 4. 撤回与回滚

- 撤回通过新版本把课程状态改为 `withdrawn`，不删除历史版本；
- 回滚必须选择一个历史签名版本并生成明确的回滚发布记录；
- 普通导入禁止低版本覆盖；只有包中存在合法回滚意图且当前身份具有 `platform_course_rollback` 时允许；
- 发布后如果当前正在打开的课程被撤回，沿用现有机制立即关闭课程视图。

## 八、主进程接口调整

建议新增独立能力模块，避免继续在 `electron/main.cjs` 中散落版本判断：

```text
electron/license-entitlements.cjs
electron/platform-course-drafts.cjs
electron/course-package-v2.cjs
```

建议增加或调整 IPC：

```text
bridge:getLicenseEntitlements
bridge:listPlatformCourseDrafts
bridge:savePlatformCourseDraft
bridge:validatePlatformCourseDraft
bridge:publishPlatformCourseCatalog
bridge:withdrawPlatformCourse
bridge:rollbackPlatformCourseCatalog
bridge:importOfflineCourseCatalogPackage
```

每个 IPC 都必须在主进程中检查：

- License 签名是否有效；
- License 是否过期；
- 版本和角色是否允许；
- 对应 capability 是否存在；
- 操作目标是否为允许的课程类型；
- 文件路径是否位于受控目录或来自一次性选择令牌。

## 九、兼容与迁移

1. 现有 `tenant_custom` 课程、课程图片、启用策略和学生分配保持不变。
2. 已有平台课程 ID 保持不变，避免机构策略和历史采集记录失去关联。
3. 当前签名 JSON 目录继续作为 v1 只读目录被接受。
4. 第一次进入平台课程发布页时，可从最后可用 v1 目录创建初始草稿，不修改原文件。
5. 新平台发布功能只生成 v2 签名课程包，并设置最低主机版本为支持 v2 的版本。
6. 专业版和机构版升级后界面行为不变，仍不能编辑平台课程。
7. 许可证升级失败时保持原许可证权限，不得自动提升版本或角色。

## 十、审计要求

审计记录至少包含：

- 操作类型；
- License ID、版本、身份和签名 `keyId`；
- 课程 ID；
- 修改前后摘要哈希；
- 草稿修订号；
- 发布目录版本；
- 时间、结果和失败原因；
- 发布包 SHA-256；
- 回滚或撤回目标版本。

日志不得记录 License 私钥、课程目录私钥、私钥密码或完整敏感凭证。

## 十一、测试矩阵

### 1. License

- v1 家庭版、专业版和机构版兼容；
- v1 伪造平台版被拒绝；
- v2 签名、篡改、过期、未知 `keyId` 和设备绑定检查；
- 普通签发密钥不能签发平台版；
- 非平台版不能调用发布、撤回和回滚 IPC；
- 渲染层伪造 capability 不能绕过主进程。

### 2. 课程编辑

- 新增和编辑平台课程草稿；
- `courseId` 首次发布后稳定；
- 无图片、超限图片、伪造扩展名、HTTP、未知域名和重复 ID 被拒绝；
- 权利状态未确认时可保存但不能发布；
- 保存草稿不改变最后可用目录和学生有效目录。

### 3. 签名课程包

- 目录和全部图片哈希正确；
- JSON、图片或清单任意一项被修改后验证失败；
- ZIP 路径穿越、重复条目和超限资源被拒绝；
- 新版本正常导入，低版本默认拒绝；
- 合法撤回和显式回滚可执行；
- 导入失败继续使用最后可用版本。

### 4. 版本隔离

- 专业版和机构版可编辑机构自选课程，但不能编辑平台课程；
- 平台编辑身份只能保存和校验草稿；
- 平台发布身份可以发布；
- 学生端只能获得当前学生有效课程，不能获得草稿、其他学生策略或平台权限信息。

### 5. 发布包审计

- Windows 主机生产构建通过；
- 包内不得出现任何 License 私钥和课程目录私钥；
- 对源码、ASAR 和发布目录执行私钥特征扫描；
- 全量自动测试、包内资源审计和 Windows 真机课程打开门禁通过；
- Authenticode 未签名时继续标记为受控分发，不表述为公开稳定版。

## 十二、实施阶段

### P0：权限和许可证基础

- 新增 edition、role、capability 模型；
- 新增 v2 非对称签名 License；
- v1 兼容但禁止平台版权限；
- License 管理平台支持选择版本和身份；
- 主机端统一 capability 检查。

### P1：平台课程草稿编辑

- 在现有课程管理页面增加平台课程发布标签；

- 当前主机立即应用和离线包导出。

### P3：迁移、审计与交付

- v1 平台目录迁移为初始草稿；
- 完整操作审计；
- 更新主机操作手册、网站、License 管理说明和版本日志；
- 完成自动测试、构建审计和真机验收；
- 生成 Windows 0.15.6 受控候选包。

## 十三、完成定义

只有同时满足以下条件才视为完成：

1. 同一个 Windows 主机安装包可依据有效 License 正确显示家庭、专业、机构和平台能力。
2. 专业版、机构版不能编辑、签名或发布平台课程，直接调用 IPC 也会被拒绝。
3. 平台编辑身份可以保存和预览草稿，但不能正式发布。
4. 平台发布身份可以生成包含图片哈希的签名课程包，并由内置公钥立即回验。
5. 草稿、发布目录和最后可用目录相互隔离；失败发布不影响学生当前课程。
6. 平台课程撤回和回滚均保留完整版本及审计记录。
7. License 私钥、课程目录私钥和密码均未进入源码、安装包或日志。
8. 现有专业版、机构版自选课程和学生分配升级后保持不变。
9. 三端学生隔离、安全浏览、主动录屏和资料归属规则没有回归。
10. 文档、测试、构建审计和真机门禁均完成后，才生成可交付候选包。
