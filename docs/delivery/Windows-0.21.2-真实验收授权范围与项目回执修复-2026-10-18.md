# Windows 0.21.2 真实验收授权范围与项目回执修复

候选：`real-acceptance-scope-receipt-fix-preview-20261018`  
性质：真实设备验收缺陷的内部修复候选，不覆盖 R41、既有预览候选或正式更新清单。

## 一、真实验收问题

1. “本机学生上传与授权”的勾选状态不能保存。
2. 项目资料消化任务在发送前被权限检查拦截：预期回执位于项目知识空间的同级 `.edu-manager` 目录，超出冻结的项目写入范围。

## 二、原因与修复

### 2.1 授权范围保存

- 原 v1 许可没有 v2 上传范围，保存接口直接要求重新开通，导致页面上的选择看似可编辑但不能持久化。
- 现在先把选择按本机学生 ID 持久保存；未开通或仍使用 v1 许可时不扩大服务端授权，使用新版开通码后自动采用已保存范围。
- v2 许可继续按既有写入意图和回执流程同步到云端；重启后页面优先恢复本机已保存选择。
- 姓名仍为自动建档必需项；健康资料仍保持独立授权，不进入普通上传范围。

### 2.2 项目摘要回执越界

- `ProjectExecutionScope` 只允许 Agent 读写项目知识空间，权限检查本身行为正确。
- 原任务信封却把宿主回执文件声明为 Agent 预期产物，且该文件位于知识空间外，因此在正文发送前被拒绝。
- 对已迁移的 `workspace-v1` 项目，预期产物改为 `project_digest_host_receipt + hostManaged`，不再向 Agent 暴露项目外回执路径；回执仍由主机按现有事务流程生成。
- 只有已迁移项目才启用项目范围 v2；未迁移项目继续保留旧合同，不因全局授权被隐式提权。
