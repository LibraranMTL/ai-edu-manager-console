日期：2026-09-08
范围：Windows 主机控制台（`edu-launcher-app`）

### 1.2 学情报告直接发布

新流程：

`生成报告 → 结构与证据校验 → 原子发布 → 自动刷新界面`

- 不再向用户展示“报告草稿—采用—退回修改”的审核动作。
- Agent 生成文件先进入内部校验区；这是防止损坏正式报告的技术暂存，不是用户审核草稿。
- 校验成功后系统直接发布；内容无实质变化则保留当前版本。
- 校验失败时不覆盖上一版，只生成异常记录并提示缺少的章节、证据或身份字段。
- 兼容旧版 `pending_review` 文件，可自动恢复并发布，不要求用户补做一次审核。

### 2.2 必须保留人工确认

这些操作会改变正式档案边界、授权关系或产生难以自动判断的教育结论，不建议取消：

- 项目知识/个人成长证据跨学生发布，尤其是多人项目中的个人贡献归属。
- 高风险、相互冲突、来源缺失或涉及敏感信息的成长证据。
- Agent 会话采集授权、学生采集对象切换，以及学生/项目身份归属不唯一的会话。
- 设备配对、协作主机信任、学生映射、撤销授权和对外共享私有知识。
- 永久删除、覆盖已有规则文件、恢复备份、迁移/重绑定知识库路径。
- 许可证移除、API Token 重置、课程正式删除和平台课程包发布。
- 已发布知识贡献的物理撤销或回滚清理。

原则：普通成功路径零操作；只有“越权、冲突、归属不明、不可逆、对外发布”进入人工注意队列。

## 3. 后续性能优化路线

### P1：数据访问与刷新去重

1. 为 `students.json`、`projects.json`、任务账本和成长索引增加“文件修改时间 + 内存快照”缓存，写入时主动失效。
2. 将任务中心候选构建拆成学生/项目增量缓存，只重建发生变化的范围。
3. 对 QClaw/Agent 结果目录使用文件监听加低频兜底轮询，避免每次状态查询扫描整个目录。
4. 报告、档案和项目列表只读取列表所需元数据；正文进入详情页后再加载。

### P2：主进程 I/O 与前端体积

1. 把深层目录遍历、SHA-1、大 Markdown 解析迁移到 Worker，并设定每轮文件数量和耗时预算。
2. 将 `main.tsx` 按首页、项目、成长模型、报告、会话、设置拆分为懒加载页面；当前生产主入口约 618 KB（压缩前），仍有拆分空间。
3. 对大型列表统一虚拟滚动；减少隐藏页面的派生计算和 React 节点数量。
4. 记录 IPC 的耗时、扫描文件数、缓存命中率和最长任务，形成可在设置页导出的本地性能诊断。

## 4. 验收指标

- 主进程单次同步处理目标小于 50 ms；任何外部进程和深层扫描不得走同步 IPC。
- 报告任务轮询不调用全量任务中心构建。
- 同一学生一次任务中心刷新最多执行一次报告证据扫描。
- 学情报告无人工审核按钮；自动校验成功后直接发布，失败不覆盖上一版。
- 低风险自动化有审计事件和可追溯来源；高风险写入仍需显式确认。
- 使用 10、50、100 名学生样本分别记录任务中心首开、二次缓存刷新和报告页轮询的 P50/P95 耗时。
