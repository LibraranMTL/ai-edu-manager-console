# 教育内容智能出版 P0-P3 实施说明

## 产品目标

把已经可信治理的学情报告和教育档案，转换为适合阅读、打印和分享的表达层文件。出版过程只读来源，不反向修改成长模型、知识资产或原始资料。

## P0：统一出版内核

- 来源同时绑定学生 ID、来源类型、文件路径和 SHA-256；禁止跨学生替代。
- 内置正式报告、简明报告、成长要点卡、黑白打印四个轻量模板。
- 支持 PDF、PNG 和 Markdown；全部在本机渲染，不依赖图片生成 API。PNG 为既有图片格式，本阶段不增加 JPG。
- 规则文件、日志、回执、审计目录和内部索引禁止作为出版来源。
- 每次生成记录模板、格式、色彩、来源哈希、输出路径和时间。

## P1：学情报告导出与分享

- 原来分散的 Markdown/PDF 按钮合并为“导出与分享”。
- 提供模板、格式和彩色/黑白打印选择，并在生成前显示可编辑预览。
- 正式报告完整保留原报告主体，只移除开头 YAML 表头和末尾“依据来源/来源依据/证据来源”章节；普通正文分隔线不会被误删。
- 教育档案来源额外隐藏“基本信息 / Basic Info”“与其他页面的关系 / Relations”“风险与不确定性 / Risks & Uncertainty”“来源 / Source”四类内部说明章节；学情报告中的同名正文不受此规则影响。
- 简明报告与成长要点使用完整句子和来源章节进行确定性归类，不再按固定字符数截断；无法从来源找到的内容不会自动补写。
- Markdown 表格按真实表头、列和数据行渲染，宽内容在单元格内换行，不再把分隔符作为普通正文输出。
- 成长卡按栏目聚合内容，同一栏目标题只显示一次；长标题和内容自动使用紧凑排版，PNG 按实际页面高度完整截图，超出安全上限时提示改用 PDF，而不是静默裁切。
- 编辑仅作用于本次派生文件，不修改原始学情报告或教育档案；可随时恢复系统自动整理稿。
- Markdown、PDF 和 PNG 共用同一份出版草稿，避免预览与最终导出内容不一致。

## P2：教育档案生成报告或卡片

- 在“查看教育档案”的当前 Markdown 阅读器中增加“生成报告或卡片”。
- 仅允许当前学生学情分析汇总目录内的 Markdown。
- 使用标题、章节、清单和正文进行确定性要点提取；来源内容不足时明确提示，不编造结论。

## P3：生成记录与维护

- 显示当前学生最近 20 条生成记录。
- 支持打开、按原配置重新生成和删除派生文件。
- 来源哈希发生变化时显示“来源已更新，建议重新生成”。
- 删除只影响派生文件和生成记录，不删除原始档案。

## 验收重点

1. A 学生不能选择或生成 B 学生的档案。
2. AGENT.md、log.md、回执和 `.edu-manager` 文件被阻止。
3. 学情报告可生成彩色 PDF、黑白 PDF 和要点卡 PNG。
4. 教育档案阅读器可生成报告或卡片，且原文内容与时间戳不变。
5. 修改来源后，旧记录显示来源已更新；重新生成产生新记录。
6. 删除派生文件后，来源 Markdown 仍可正常阅读。
7. 正式报告主体内容逐段保留，开头 YAML 表头和末尾依据来源不进入成品。
8. 简明报告与成长要点中的自动内容均能在来源正文中找到依据，并保持完整语句。
9. 格式列表包含 PDF、PNG、Markdown，不包含 JPG。

## 增强层 P0-P3（Agent 可选）

- P0：内容生成方式增加“忠实原文（推荐）/ Agent 智能提炼”。默认不调用 Agent，不增加普通用户日常操作；智能提炼失败时自动保留忠实原文草稿。
- P1：内置正式报告优化、简明报告、成长要点、家长沟通、学生行动和项目成果提示词模板。Agent 只返回结构化 JSON，每条内容必须携带逐字原文摘录和来源章节。
- P2：沿用统一任务中心及现有 Codex/QClaw 路由。任务属于低风险草稿操作；逐条依据、数字和结构协议自动校验，通过后自动采用，不增加人工审核环节。
- P3：PDF、PNG 和 Markdown 继续共享同一份出版草稿。结构化章节支持叙述、指标、时间线、优势、关注与行动语义，以及重点强调，为后续图表和视觉模板保留稳定接口。
- 表格兼容：对历史报告中被压缩为单行、以 `||` 拼接的 Markdown 表格先自动修复为标准行列，再统一渲染；宽表使用较小字号、单元格换行和跨页安全规则。
