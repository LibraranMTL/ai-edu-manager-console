# 教育管家档案架构升级说明

版本：Windows 0.6.8 起，0.6.9 补充知识贡献发布闭环

## 升级目标

本次升级采用渐进式方式，把现有学生知识库、资料上传、学情报告和主机 API 保持兼容，同时新增四层能力：

- 文件资产中心：为导入和上传文件建立资产索引、SHA-1 指纹和引用关系。
- 学习项目知识空间：让短期学习项目拥有独立的 LLM Wiki 知识空间。
- 知识贡献申请：项目完成后用 Markdown 贡献报告替代简单文件夹合并。
- Growth Layer：把学情报告升级为成长模型输出，而不是普通摘要文件夹。

## 已实现范围

### 文件资产中心 v1

- Windows 手动导入、平板上传记录、多资料来源导入会同步登记资产。
- 资产记录包含文件名、SHA-1、大小、类型、物理路径、所属学生、引用空间、来源和更新时间。
- Windows 端新增“文件资产中心”高级视图，可按学生、关键词、重复文件筛选。
- 支持扫描历史上传记录和学生原始资料库，为旧文件补建资产索引。

### 学习项目知识空间 v1

- Windows 端新增“学习项目”对象，可绑定学生。
- 创建项目时自动生成用户项目空间和项目知识空间。
- 项目知识空间使用 LLM Wiki schema：项目原始资料库、概念库、实体库、摘要库、问答精华库、综合汇总库、项目报告、知识贡献。
- 可从资产中心选择文件加入项目，建立项目引用并复制到项目原始资料库。
- 项目资料不会自动写入学生主档案。

### 知识贡献申请 v1

- Windows 端可为项目生成 Markdown 形式的“知识贡献申请”。
- 报告包含项目概况、资产清单、建议归档项、成长证据、冲突检查和 Agent 执行指令。
- v1 不自动覆盖学生主档案，由管理员复制给 Agent 或人工确认后执行。

### Growth Layer v1

- Windows 端新增“成长模型”入口。
- 可为学生补建“成长模型”目录，包含 `index.md`、`能力画像.md`、`成长证据.md`、`项目贡献.md`。
- 学情报告模板增加成长证据来源和项目贡献来源字段。
- 后续报告生成优先引用成长模型、综合汇总库和项目贡献记录。

## 0.7.2 多学生项目绑定

- 学习项目创建时支持一次绑定多个学生，符合“一个学习项目可服务一个或多个学生”的原始架构设计。
- 已创建的学习项目可在项目详情中继续调整绑定学生，调整后归档确认清单和发布目标会重新按最新绑定关系生成。

## 0.7.3 研究暂存层 v1

- 学习项目详情新增“研究暂存层”，可先导入论文、网页快照、截图、候选素材等项目研究资料。
- 暂存资料默认只写入项目工作空间下的 `研究暂存` 目录，并维护 `staging-index.json` 与 `研究暂存清单.md`；未晋升前不会进入正式文件资产中心。
- 暂存资料支持生命周期状态：已收集、已初筛、选入分析、已分析、已晋升、已归档/丢弃。
- “晋升为正式资产”会把选中的暂存资料复制到项目原始资料库，并登记为项目资产引用；随后才参与项目资料消化和知识贡献流程。
- “丢弃/归档”只更新状态，不删除物理文件，便于后续追溯研究筛选过程。

## 0.7.4 研究暂存层增强与 AI 初筛导入

- 研究暂存层新增搜索和状态筛选，可按文件名、路径、AI建议和AI理由快速定位候选资料。
- 新增“复制 AI 初筛指令”，可把当前项目暂存资料清单复制给 QClaw / OpenClaw / Hohu 等 Agent 工具，要求其输出严格 JSON 初筛结果。
- 新增“导入 AI 初筛结果”，支持从 `.json`、`.txt`、`.md` 文件中解析 AI 输出，并按暂存项 ID、文件指纹、文件名或路径匹配资料。
- 导入结果只更新暂存资料的状态、AI建议、评分和理由，不会自动晋升为正式资产，仍需管理员人工确认。
- AI结果解析增强：兼容 Markdown 代码块、中文智能引号和未转义的 Windows 路径反斜杠，减少“看起来像 JSON 但无法导入”的情况。
- `研究暂存清单.md` 增加 AI建议和 AI理由列，便于后续追溯资料筛选过程。

## 0.7.5 研究暂存治理建议

- 学习项目详情新增“生成治理建议”，可对研究暂存层进行重复识别、暂存天数统计和状态治理分析。
- 治理建议会标记：建议检查重复、建议复核、建议决定去留、建议分析或晋升、建议归档清理、已晋升无需处理等动作。
- 控制台会生成 `研究暂存治理建议.md`，包含总览、治理动作分布、重复候选、清理/复核候选和全量治理清单。
- 治理建议只写入清单和暂存项元数据，不自动删除、不自动移动、不自动晋升资料，保持“人工确认优先”的安全策略。
- `研究暂存清单.md` 增加治理建议和治理理由列，便于项目结束时回溯哪些资料被保留、归档或进入正式资产。

## 0.7.6 知识贡献与成长模型联动增强

## V2.1 架构补充：研究暂存层与知识资产晋升机制

### 新增目标

在现有“文件资产层（Asset Layer）→ 知识层（Knowledge Layer）”之间增加“研究暂存层（Research Staging Layer）”，用于处理项目研究过程中大量临时参考资料、AI搜索结果、网页、论文、截图和候选素材。

该补充的核心判断是：并非所有研究资料都应立即进入正式文件资产中心。项目资料应先进入研究环境，经过筛选、引用或知识化处理后，再晋升为正式资产，避免文件资产中心长期积累低价值、重复或未使用资料。

### 新增分层

```text
Research Staging Layer
研究暂存层

        ↓

Asset Layer
文件资产层

        ↓

Knowledge Layer
LLM Wiki知识层

        ↓

Project Insight Layer
项目洞察层

        ↓

Growth Layer
学生成长模型
```

### 研究暂存层职责

研究暂存层属于项目工作区的一部分，主要用于资料收集、初筛和生命周期管理。典型内容包括：

- 网络搜索资料、在线论文、参考案例。
- 临时截图、网页快照、AI搜索中间结果。
- 未阅读文献、候选数据集、视频或图片素材。

这些资料默认不进入学生长期知识库，也不默认成为正式文件资产；系统可以对它们进行批量筛选、去重分析、来源记录和自动清理。

### 资产晋升机制

正式资产采用生命周期管理：

```text
Collected
已收集

↓

Screened
已初筛

↓

Selected
已选入分析

↓

Analyzed
已完成AI分析

↓

Promoted
已晋升正式资产

↓

Archived / Discarded
归档或清理
```

只有满足以下条件之一时，资料才进入正式文件资产中心：

- 被项目正式引用。
- 被 AI 分析实际使用。
- 支撑项目结论。
- 被教师确认。
- 被学生标记为重要。
- 成为最终成果组成部分。

### 来源保存策略

- Full Copy：保存完整文件。适用于原始数据、最终作品、教师反馈、官方文档。
- Reference Only：仅保存标题、作者、URL、发布时间、获取时间等来源信息。适用于网络文章、在线论文、官方网页。
- Snapshot：保存关键页面或关键片段。适用于新闻页面、长网页、在线课程内容。

## V2.2 架构补充：知识库可迁移与路径抽象层

### 评估结论

接管已有知识库后，如果该知识库来自另一台主机，`AGENT.md` 中保留的绝对路径可能与当前主机实际目录不一致。这个问题不是简单的字符串替换问题，而是说明当前知识库规则、逻辑目录和物理存储路径仍存在耦合。

该修正可行且必要。它应作为“接管已有知识库”和“多主机同步”之间的基础层能力纳入开发计划，目标是让知识库从“绑定某台电脑路径的文件夹”升级为“可迁移、可接管、可重新映射的知识工作空间”。

### 设计原则

后续 `AGENT.md` 应主要描述知识组织规则和工作协议，不应长期保存强绑定本机的绝对路径。真实路径应由当前主机的路径映射和学生记录负责解析。

推荐原则：

- `AGENT.md` 负责知识 schema、工作规则、资料消化流程和写入规范。
- `.ai-manager/metadata.json` 负责知识库身份、schema 版本和来源信息。
- `.ai-manager/pathmap.json` 负责逻辑路径到当前主机物理路径的映射。
- 控制台学生记录继续保存 `rootPath`、`rawPath`、`summaryPath`、`agentPath` 等当前主机真实路径。
- 复制给 Agent 的指令可以使用当前主机绝对路径，但知识库内部长期规则应优先使用逻辑路径占位符。

### 逻辑路径建议

第一版建议支持以下逻辑路径：

```text
@KB_ROOT
@AGENT_FILE
@RAW_DIR
@SUMMARY_DIR
@OUTPUT_DIR
@GROWTH_DIR
@PROJECT_ROOT
@ASSET_ROOT
```

示例：

```markdown
该 Agent 的工作协议使用：@AGENT_FILE
后续所有学习资料消化围绕 @KB_ROOT 执行。
新增原始资料读取：@RAW_DIR
沉淀结果写入：@SUMMARY_DIR
成长证据写入：@GROWTH_DIR
```

当前主机解析后可以得到：

```text
@KB_ROOT -> D:\学生资料\张三知识库
@AGENT_FILE -> D:\学生资料\张三知识库\AGENT.md
@RAW_DIR -> D:\学生资料\张三知识库\张三原始资料库
@SUMMARY_DIR -> D:\学生资料\张三知识库\张三学情分析汇总
```

### 工作空间元数据

每个标准或接管知识库建议维护隐藏目录：

```text
知识库根目录
└── .ai-manager
    ├── metadata.json
    ├── pathmap.json
    ├── health-report.md
    └── migration-log.md
```

`metadata.json` 建议字段：

```json
{
  "workspaceId": "student-kb-...",
  "workspaceType": "studentKnowledgeBase",
  "schemaVersion": "2.2",
  "studentName": "张三",
  "createdBy": "AI教育管家控制台",
  "knowledgeBaseMode": "standard",
  "createdAt": "2026-07-12T00:00:00.000Z"
}
```

`pathmap.json` 建议字段：

```json
{
  "@KB_ROOT": "D:\\学生资料\\张三知识库",
  "@AGENT_FILE": "D:\\学生资料\\张三知识库\\AGENT.md",
  "@RAW_DIR": "D:\\学生资料\\张三知识库\\张三原始资料库",
  "@SUMMARY_DIR": "D:\\学生资料\\张三知识库\\张三学情分析汇总",
  "@OUTPUT_DIR": "D:\\学生资料\\张三知识库\\输出结果",
  "@GROWTH_DIR": "D:\\学生资料\\张三知识库\\成长模型"
}
```

### 接管已有知识库流程调整

接管已有知识库时新增“路径健康检查与修复”步骤：

1. 扫描 `AGENT.md`、规则文件、Soul/Memory 模板中出现的 Windows 绝对路径。
2. 判断这些路径是否存在于当前主机。
3. 根据当前选择的知识库根目录生成 `.ai-manager/pathmap.json`。
4. 生成 `health-report.md`，列出：
   - 当前知识库根目录。
   - 已识别逻辑目录。
   - 已失效旧主机路径。
   - 建议替换为当前主机路径或逻辑路径的条目。
5. 默认不自动覆盖用户已有 `AGENT.md`。
6. 提供三个操作：
   - 复制当前主机工作规则。
   - 生成逻辑路径版 AGENT.md 草稿。
   - 备份后修复 AGENT.md 中的旧路径。

### Agent 指令生成策略

为兼容 QClaw、OpenClaw、Hohu、Marvis 等工具，短期策略采用“双轨”：

- 给本机 Agent 执行的一次性初始化/消化指令：允许使用当前主机绝对路径，确保工具可直接执行。
- 写入知识库长期保存的规则文件：优先使用逻辑路径占位符，并配套 `.ai-manager/pathmap.json`。

这样既保证现有 Agent 工具可用，又为多主机同步和知识库迁移保留升级空间。

### 验收标准

- 接管从其他主机同步来的知识库时，能识别 `AGENT.md` 中已失效的旧绝对路径。
- 能生成当前主机 `.ai-manager/pathmap.json`。
- 能生成路径健康检查报告。
- 不自动破坏或覆盖原有 `AGENT.md`。
- 能复制当前主机可执行的工作规则。
- 后续上传资料、档案浏览、消化指令均使用学生记录中的当前主机真实路径。
- 标准新建知识库也自动生成 `.ai-manager/metadata.json` 和 `.ai-manager/pathmap.json`。

## 0.7.8 已实现：学生知识库路径核对与 `.ai-manager` 工作空间配置

本版本把“知识库可迁移与路径抽象层”的第一阶段落到 Windows 主机端，重点解决已有学生和接管知识库在跨主机同步后路径不一致的问题。

### 已实现能力

- 对每个学生知识库生成隐藏配置目录：`.ai-manager/`。
- 自动写入 `.ai-manager/metadata.json`，记录工作空间身份、学生、知识库模式、Agent 工具和 schema 版本。
- 自动写入 `.ai-manager/pathmap.json`，记录当前主机的逻辑路径映射：`@KB_ROOT`、`@AGENT_FILE`、`@RAW_DIR`、`@SUMMARY_DIR`、`@OUTPUT_DIR`、`@GROWTH_DIR`、`@ASSET_ROOT`。

- 检查完成后生成 `.ai-manager/health-report.md`，并追加 `.ai-manager/migration-log.md`。
- “迁移/重命名知识库目录”后会同步更新学生记录中的 `rootPath / rawPath / summaryPath / agentPath / outputPath`，并重写当前主机 pathmap。

### 设计边界

- 本版本默认不自动替换旧 `AGENT.md` 或规则文件中的绝对路径，避免误改同步文件或破坏旧主机兼容性。
- 健康检查只提示疑似旧主机路径，管理员可据此更新 Agent 工具中的 Soul、角色设定、长期背景或规则文件。
- 现有 `.edu-manager/` 运行状态目录保持不变；`.ai-manager/` 只承担可迁移工作空间身份、路径映射和健康报告职责。

### 验收要点

- 已有标准学生可以点击“检查知识库路径”生成 pathmap 和健康报告。
- 接管知识库可以识别来自其他主机的旧绝对路径。
- 标准新建和接管学生后，后续上传资料、档案浏览、消化指令仍使用学生记录中的真实路径。
- 未激活 Windows 授权时，该维护动作仍受许可证限制，不允许执行路径核对写入。

## 0.7.9 已实现：旧路径备份修复与定时维护 / lint 拆分

本版本在 0.7.8 的路径核对基础上继续补齐“可执行修复”和“定时维护任务”。

### 已实现能力

- 在“查看教育档案 / 知识库路径核对”面板中新增“复制当前主机工作规则”按钮，便于把当前主机真实路径更新到 Agent 工具的人设、Soul 或长期背景中。
- 新增“复制逻辑路径版 AGENT 草稿”按钮，输出使用 `@KB_ROOT`、`@RAW_DIR`、`@SUMMARY_DIR`、`@OUTPUT_DIR`、`@AGENT_FILE` 等占位符的可迁移规则草稿。

- 定时维护 / lint 指令只要求 Agent 生成报告和建议，不授权 Agent 自动删除或覆盖文件。

### 验收要点

- 定时任务页面应同时显示“定时消化”和“定时维护 / lint”两组任务。
- 未激活 Windows 授权时，路径核对与修复仍受只读限制。
