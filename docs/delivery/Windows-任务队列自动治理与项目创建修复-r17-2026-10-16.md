# Windows 任务队列自动治理与项目创建修复 R17

## 交付结论

本候选包基于 R16 延续开发，候选标识为 `task-queue-governance-r21-20261016-r17`。本轮同时解决统一任务队列的自动触发、历史任务治理、批量取消/归档/删除，以及所有新建 `workspace-v1` 项目首次读取资料状态时缺少项目 ID 的问题。

本包仍是候选包，不替代正式发布清单；Authenticode 实测为 `NotSigned`。

## 本轮实现

### 1. 自动化优先的任务队列

- 新项目继承全局自动运行设置，不再默认关闭项目自动化。
- 定时调度补齐学生资料消化、选题建议、维护检查等已具备合同的任务；没有待处理资料时不再产生空的项目消化占位任务。
- 智能资料箱创建任务改为稳定批次标识和单次持久化，同一批资料不会因为重复点击或恢复而生成多条待处理任务。
- 继续遵守安全回退边界：明确未发送且可安全重试才切换执行器；执行结果未知、正在运行、等待结果、审核中或已有结果时不自动重派。

### 2. 一般化任务治理

- 统一任务队列新增多选、选择本页、批量取消、批量归档、恢复归档和批量删除。
- 所有批量操作先生成五分钟有效的预览令牌，提交时再次核对任务仓库版本和每条任务的可操作性，避免预览后状态变化造成误处理。
- 批量取消仅适用于从未启动、无执行批次、无结果的任务；批量删除仅适用于已归档或终态历史任务。
- 归档恢复为“已取消”状态，不会自动重新执行；删除只移除任务中心历史记录，保留任务产物和审计事件。
- `archived` 已进入任务协议、读模型、统计、筛选、状态标签和 Windows/Android 协议一致性检查。

### 3. R17 首次启动迁移

- 首次启动且项目归档恢复检查通过后，自动识别并归档两类安全历史任务：旧版下载资料入口产生、超过一小时且从未启动的孤儿任务；待处理数为零且从未启动的项目消化占位任务。
- 迁移前备份 `tasks.json` 和存在的事件日志，迁移目录为任务中心下的 `migration-backups/task-governance-r17-<时间戳>`，同时写入 `migration-report.json`。
- 迁移版本写入任务仓库，重复启动不会重复迁移。
- 运行中、等待结果、审核中、恢复状态为未知、已有执行批次或已有结果的任务均不迁移。

### 4. 新建项目失败修复

- 主机生成 `projectId` 后，立即构造带 ID 的规范化项目对象，再执行首次资料消化状态和资料登记索引读取。
- 修复覆盖所有无 ID 的新建 `workspace-v1` 项目，与项目名称无关。
- 新增回归用例验证：首次 digest/registry 读取收到同一个新 ID；新项目固定使用 `workspace-v1`，并继承全局自动化开关。

## 安装后验证建议

1. 首次启动后打开统一任务队列，确认历史孤儿任务进入“已归档”，运行中和结果未知任务保持原状态。
2. 查看迁移报告中的归档数量和任务 ID；需要回查时使用同目录的迁移前备份，勿直接覆盖正在运行的任务仓库。
3. 新建任意名称的学习项目，确认创建成功、资料页面可进入，并检查新项目是否按全局自动运行设置工作。
4. 从已归档筛选中选择少量任务测试恢复；恢复后的任务应为已取消，不应自行重跑。
