# 学习卡片：最新版教育管家架构衔接与实施方案

日期：2026-10-01。依据：《每天10分钟提分卡片开发计划.md》v1.2（2026-08-01）。本文件更新实施位置与现有能力的衔接，不改变原计划的学生隔离、证据、三触发一任务、打印与真机门槛。当前 Windows 源码版本为 0.18.7；“学习卡片”仍是建设中占位，不代表已发布。

## 1. 本轮架构调整

原计划的“今日提分卡”独立一级菜单不再采用。入口固定在 **学情与学习 → 学习卡片** 页内 Tab；进入时默认显示“今日卡片”，页内再分“今日卡片／练习计划／自动记录／卡片模板”，不增加侧栏层级。首页可显示当前学生今日卡片摘要和跳转，不出现跨学生卡片。主机顶部保留当前学生姓名及 ID；切换学生时清空预览、筛选和未保存计划，但后台任务仍按创建时锁定的学生执行。

展示文案采用“每日 10 分钟针对性练习”；“提分”仅保留原计划名称，不承诺成绩改善。普通用户流程为“查看依据 → 立即生成或等待计划 → 查看、作答并明确提交”。模板、打印和生成诊断放在次级操作。

现有正式学情报告、知识轨迹、学习资料、成长模型、项目活动与贡献是候选来源，不等于都可直接证明薄弱知识点。生成器只读取指定学生**已发布、已确认、可追溯且适用**的证据版本；未确认成长证据、原始截图、未经核验的对话及其他学生资料不得进入。优先使用报告明确指出的知识点和复习建议；项目活动可解释兴趣与应用情境，但不可单独推出知识掌握等级。一次提示后成功或长期未复测不得写成“已掌握／已遗忘”。

## 2. 页面与现有模块连接

| 工作区 | 主操作 | 复用与边界 |
| --- | --- | --- |
| 今日卡片 | 显示当前／下一张、唯一知识点、预计时长、来源摘要；手动生成、预览、投递、导出 | 从学情报告、知识轨迹与已确认成长证据取得来源；无依据时显示“需补充学情依据” |
| 练习计划 | 生成方式、今日／周／月／自动范围、八科／自动、难度、固定时间、待完成上限 | 使用现有学生选择、任务调度与许可；高级项容纳防抖、预览和重试 |
| 自动记录 | 已生成、已投递、已开始、已提交、过期、失败；按学生和时间查询 | 读取卡片及作答回执，不把页面停留或点击记为完成 |
| 卡片模板 | 内置样式、长卡、黑白／打印、可选用户自有图片 API | 只影响呈现，不改变题目或答案；图片 API 未配置时仍可生成内容 |

首页和“收集与整理 → 自动整理任务”只展示任务摘要与状态；卡片领域数据以学生专属存储为准。资料消化成功后的“根据本次学情生成”必须等确认、索引和有效证据指纹形成后才启用，不能以文件刚上传为触发条件。学生端首页收到本人的卡片后进入作答；Windows、Android 与网页连接沿用现有学生会话与授权，不建第二套账号。

## 3. 合同与处理流程

沿用原计划四个实体：`PracticePlan`、`PracticeCard`、`PracticeAttempt`、`PracticeTemplate`。实施前补充 `EvidenceSnapshot`，至少记录 `studentId`、证据 ID／类型、版本、正式状态、发布时间、适用知识点、来源 URI、摘要哈希、读取时间和 `evidenceFingerprint`；只保存必要引用及短摘要，不复制完整报告、截图或对话进入任务文本。卡片内容与答案分存，学生初始载荷不含 `answerKey`。

八科为语文、数学、英语、物理、化学、生物、历史、地理；另设“自动选择”。自动选择只在有有效知识点证据的科目中决策。每张卡只针对一个知识点，预计 5—15 分钟、默认约 10 分钟。生成结构化题目、提示、答案和解析后，主机验证学生范围、来源完整性、题答一致性、题量、难度、年级适配、内容安全及可用时长；不通过则保留失败回执，不投递。Agent 负责理解和拟题，主机负责身份、证据快照、计算、状态和审计。

手动、有效学情更新、每日定时或兜底三种触发，统一进入 `practice_card.generate.v1`。幂等键为 `studentId + localDate + evidenceFingerprint + planRevision`，并保存触发原因；同时触发、重复回执、重试和重启只能产生同一有效卡。默认合并连续 10 分钟的有效学情更新；无新证据、与计划知识点无关或超过最大待完成数时只记录检查回执。当前卡未开始可换版；已开始或已完成不能覆盖，只能准备下一张建议卡。无可用 Agent 时保留任务与最后有效卡，不以通用题目伪装个性化结果。

建议在现有 Electron 任务适配器和 preload 上增加异步主机接口：`getPracticeDashboard`、`savePracticePlan`、`generatePracticeCard`、`getPracticeHistory`、`deliverPracticeCard`、`exportPracticeCard`。每次重验当前学生、许可证、证据和状态；生成、图片及 PDF 不阻塞主进程。主机服务对学生端增加经会话授权的 `GET /api/student/practice/current`、`GET /api/student/practice/:cardId/content`、`POST /api/student/practice/:cardId/attempt` 和历史接口；路径参数不能替代会话学生身份。提交使用 `attemptId` 幂等，离线队列恢复时以主机回执确认，不重复计入。

作答只有点击“提交练习”才进入完成态，并记录“太简单／正合适／有点难”和信心反馈。时长只作辅助信息。结果形成**待审核练习证据候选**，不能自动提升为正式成长结论；报告或成长模型需要现有审核链确认。

## 4. 渲染、隐私和失败降级

规范化内容模型一次生成，派生 4:3 平板、9:16 手机、约 1.7 倍长卡和 A4 PDF；提供 PNG/JPG/PDF 导出及独立黑白规则。黑白版去除深底、渐变、阴影和仅靠颜色的状态提示；检查中文字体、截断和异常留白。58 mm／80 mm 热敏纸单列实机验收，不以浏览器预览代替。导出文件名携带卡片与学生 ID，但不得写入学生姓名或完整档案。

图片 API 仅可接收去身份化视觉提示词，不发送姓名、学情、题目答案或原档案；密钥进入系统凭据库，不进任务、日志和备份。视觉服务失败退回内置模板，不阻断已校验的练习题。断网时可浏览已投递卡与本机作答；明确提示“待同步”，恢复后按 `attemptId` 回传。来源失效、证据撤回、学生切换、设备解绑、许可变化等情形重新校验并给出原因，不回退到其他学生卡片。

## 5. 实施顺序与验收门槛

| 阶段 | 具体交付 | 放行门槛 |
| --- | --- | --- |
| C0 合同与界面 | 将原 Demo 适配“学情与学习 → 学习卡片”；冻结四实体、证据快照、状态机、八科与复习范围 | 学生切换、无证据空态、触发语义和完成定义获确认 |
| C1 主机本地 MVP | 真实证据读取、手动生成、结构校验、今日卡、学生专属持久化和重启恢复 | 两名不同学生得到依据不同的卡，资料不足者不生成；不存在跨学生读取 |
| C2 自动调度与终端闭环 | 有效学情更新触发、每日兜底、幂等重试、Windows／Android 定向投递与离线提交 | 三触发相遇只留一张有效卡；提交只记一次；断网和重启均可恢复 |
| C3 输出与模板 | 内置模板、PNG/JPG/PDF、长卡、黑白／打印、可选图片 API | 同题同答案同来源；密钥不外泄；视觉服务失败可降级 |
| C4 候选与真机 | 单测、合同、端到端、隔离、打印、权限、升级及回滚记录 | 主机和学生端真机闭环、签名与 SHA-256 等发布门槛分别记录 |

自动测试至少覆盖：跨学生与跨项目拒绝、未发布证据排除、报告撤回、一次成功不定掌握、来源快照版本、三触发去重、已开始卡不覆盖、答案不提前泄露、重复提交、离线恢复、文件导出一致性和图片 API 脱敏。真机分别检查 Windows 主机、Windows 学生端、Android 竖／横屏、A4 与 58／80 mm 打印。尚未执行的真机、签名、Git 和线上发布项目保持“未验收”。

## 6. 与原计划的差异及当前状态

原计划的能力合同、三触发一任务、八科、四种复习范围、长卡和黑白打印要求保留；**仅导航从一级“今日提分卡”改为现行的“学情与学习 → 学习卡片”，并衔接当前学生总览、任务中心和学情证据链**。原计划中的 28—37 开发日是旧架构估算，不作为最新版承诺；C0 需基于当前接口和终端状态重新估算。现有高保真 Demo 不是正式业务实现；当前页面仍为“功能建设中”，本轮只提交开发方案，不升级 Android、Windows 学生端或网站版本。
