## 2. 目标、边界和借鉴

### 2.1 用户可见目标

用户在已有学生/项目范围内一次授权采集，停止会话后自动完成“封存事实 → 选代表图 → 自动晋升资料包 → 正式消化 → 两份报告”。报告按活动段讲清可观察的**尝试、阻碍、变化、产出**，以截图和其他授权来源作为可展开证据；另一份报告按小时/日/周统计可观察活动，不把缩略图排列称为分析结果。普通失败后台恢复，只有归属、外部处理授权或敏感范围等实质决定才提示用户。

新增“知识状态与指导响应”：只基于已经校验的知识成果、授权任务/会话及可追溯活动观察，给出当前证据覆盖、下一步可操作建议和未知项；它是报告中的解释层，不另设人工审核、单独录入或第二次模型处理。

### 2.2 Meridiona 的可借鉴部分与明确不采用部分

Meridian 的公开架构是“本机采集事实与 OCR/辅助功能文本 → 按应用活动与时间缺口做 ETL → 归一化本地 Agent 会话 → 汇总和草稿”，采用持久化状态、幂等处理和失败复盘。借鉴**事实与解释分层、真实空档、Agent 来源归一化、排除自身总结会话、失败分类评估**。它不是教育场景的逐图视觉证明方案，也不是迁移技术栈的理由。

本次**不**将 Rust/Tauri/SQLite 替换现有 Electron/JSONL，不增加全屏连续 OCR 或新的键盘/点击监控；不照搬开发者工具的 focused time、工时或对外项目管理发帖审批。Meridian 的隐私文件也说明选用第三方模型汇总时会传送相关文本；教育管家的学生截图、文字与会话均须按实际处理位置分别授权，不能用“本地启动 CLI”冒充“模型本地处理”。

参考：[Meridian 公开架构](https://github.com/Meridiona/meridian/blob/main/ARCHITECTURE.md)、[隐私说明](https://meridiona.com/privacy)、[更多 OCR 上下文可能误导分类的复盘](https://meridiona.com/writing/eval-loop)。这些是对方公开资料，不构成对其安装包真实性能或隐私实现的独立审计。

### 2.3 硬边界

- 仅处理已有采集授权覆盖的窗口与学生/项目；采集授权不自动授权外部视觉服务、私聊抓取或跨学生共享。外部处理范围须一次性明确选择并可撤回，不逐会话弹窗。
- 原始截图和采集时间是事实，不证明两帧间持续学习；不输出“有效学习时长”“专注时长”、能力分数、自动成绩判断或从画面猜测动机。
- 视觉观察可在系统交付证据和逐段校验后自动进入学习时间线，但不因此成为正式知识或已发布学情报告；知识成果仍由现有 `AGENT.md` 治理，学情报告按原证据规则引用。
- 不做旧历史全量重算，不要求普通用户逐图确认、手工复制回执或反复重试。仅手动执行器/关闭自动化时明确显示等待，不暗中改用未经授权的服务。

## 3. 目标架构与端到端状态

```text
已有授权采集 / 学生端可靠送达
  → 不可变事件、归属、时间、图像哈希；标记休眠/空闲/断网造成的未知间隔
  → 会话封存、非 OCR 规则分段及选帧（≤20 图/会话）
  → 自动晋升一个幂等资料包；其他原始资料按既有规则独立处理
  → 可选关联同学生/项目且已授权的 Agent 会话、课程任务、知识成果
  → 能力/处理位置判断 + 共享后台资源许可 + 只读视觉边界
  → 当前 Agent 视觉 / 另行授权的独立视觉适配器 / 局部 OCR / 证据不足
  → 受控视觉子批（≤8 图/请求）产出结构化观察
  → AGENT.md 正式消化及逐段结构化回执；系统独立记录附件交付
  → 按具体结论校验来源，跨子批合并，同批知识/时间线/统计独立结算
  → 自动发布已成功的本地报告投影，失败单元自动恢复
```

阶段状态至少为 `fact_recorded → bundle_ready → waiting_capability_or_resource → vision_processing/ocr_fallback → digest_partial_or_complete → report_ready`。状态与下一次自动重试时间可查；业务成功不依赖用户看到状态页。图片、知识、报告各有稳定键和独立检查点；网络、模型或投影局部失败不得回滚其他合法成果。

## 4. R0：基线、契约与能力探测

1. 保存 0.17.9 EXE/审计哈希、构建时版本说明、当前源码 Git 状态、相关未提交/未跟踪源码及构建输入的文件清单与哈希、本机性能基准；生成下一版候选时记录新增差异，绝不覆盖 0.17.9 包。状态哈希不冒充可复现源码快照。验证学生端 0.17.8 的授权、会话 ID、逐图送达与断网恢复接口。
2. 为每个执行器/模型/实际处理位置建立独立能力记录：显式图片附件、受控工具读图、只读文本、是否能提供接口确认、最大图数和可授权的处理位置。用非学生测试图探测，配置变更或连续失败后重新探测；不假设 Codex、QClaw、WorkBuddy 能力相同。视觉提取与负责正式知识消化的 Agent 解耦：当前 Agent 无视觉能力时，仅可自动选用同一授权范围内另行配置的视觉适配器；否则降为局部 OCR 或证据不足，绝不静默外发。
3. 固定资料包、系统交付日志、Agent 回执三份**不同信任来源**的协议与版本。旧 `timelineObservations` 保持兼容读取，但新回执使用带字段级证据的版本；历史数据不因升级变成“已视觉观察”。
4. 建立带阅读、练习、订正、编程/创作、仅时间相近无关会话、模糊/敏感画面的受控样例集；记录 0.17.9 实际可观察的质量、队列耗时、CPU/内存、模型费用，而不把合成测试冒充真实 Agent 质量。

R0 完成判据：对每个可选执行器明确“能送图、只能读图、只能文本或未知”，把用户授权与真正的模型服务位置对应起来；测试基线与未提交源状态均可追溯。

## 5. R1：可靠事实层、活动段与资料包

在已完成的非 OCR 选帧骨架上补齐：按采集时间、来源变化、画面差异和已存在的课程边界分段；明确休眠、重启、断网和超过采样阈值的时间缺口，未知空档不并入活动持续时间。长会话按活动窗口拆成可续处理的资料包，每包选帧覆盖始末和中途变化，每段优先 1～3 图、每包上限 20；不得因整场会话先到 20 图就让后续活动永久无证据。普通采集事件不做全图 OCR、视觉推理或主进程原图解码。

资料包冻结 `studentId/projectId/captureSessionId/bundleId`、策略版本、每个 `eventId/sequence/capturedAt/originalHash/assetId`、活动段边界、原始采样间隔和已授权候选来源。关键图引用保留；重复送达、重启或重复晋升按稳定键去重及原子写，不复制第二份正式知识。学生端只传已有授权范围内的采集资料，主机完整校验后才封存。无需为了模仿 Meridian 而改数据库或增加持续采集源。

R1 完成判据：同一会话重放不重复图/段/资料包，跨午夜、休眠、断网和长会话都有正确事实边界；无视觉 Agent 仍保留事实，且不会卡住其他学生。

## 6. R2：受控视觉、按需 OCR 和多源正式消化

### 6.1 各 Agent 的实际图片交付

视觉提取先于正式知识写入，采用无知识目录写权限的只读执行上下文，只允许读已授权、已冻结的代表图并返回固定结构观察；截图/OCR/会话中的指令不得触发工具调用或获得知识写权限。正式 `AGENT.md` 消化只接收受控观察和引用，原有知识发布边界不变。若执行器不支持可靠只读隔离，该执行器不承担视觉提取，自动尝试其他已授权适配器或降级。

- **Codex**：当前任务入口只传文本；优先利用现有 CLI 的显式图片附件能力，按 ≤8 图子批送入受控输入。记录实际读入字节及运行标识，不将“命令里有图片路径”当作成功。CLI 无逐图服务器回执时，可把“受控文件字节校验 + 显式附件参数 + 该次执行成功结束”记为 `cli_completed_with_attachment`，不得标成 `api_ack` 或模型内部注意力证明。
- **QClaw/WorkBuddy**：分别验证可用的图片输入或受控读图能力；能给接口接受回执则记录 `api_ack`，能提供工具打开轨迹则记录 `tool_read_confirmed`。仅接受文本指令/收件箱回执的版本视为 `text_only`，自动进入已授权的局部 OCR 路径；不可因模型名称或 Agent 的 `viewedEventIds` 自述升级视觉状态。
- 当前消化 Agent 为 `text_only` 时，可先由**另行授权、实际处理位置明确、具备只读能力**的视觉适配器完成一次结构化提取，正式知识消化仍交给原 Agent；不存在此适配器时才走局部 OCR。视觉观察按冻结哈希缓存，不因更换消化 Agent 重看同一图。
- 每次调用前核对原图文件的学生/项目归属、授权状态与冻结哈希；如果传缩放/裁剪图，记录 `originalHash → submittedHash`、变换版本及实际提交的 `eventId`。输入日志由系统在受控边界记录 `executionId/requestId`、执行器、提供商、实际处理位置、子批、成功/失败和时间，不由 Agent 填写。提交状态、完成状态和不可确认状态分开；崩溃/超时后按稳定请求键对账或有界重试，避免把未确认提交直接记为已读或无限重复付费。
- 同一逻辑 `bundleId/digestBatchId` 可包含多个视觉子批；**每个请求 ≤8 图，但一个活动段可引用不同子批中的前后图**。如果要直接比较边界两帧，优先在选帧时让这对图同批，或补一个只含所需前后图的受控比较子批并复用缓存；否则只能把两次独立观察表述为“前后记录有所不同”，不得冒称已直接视觉比较。先持久化子批观察，再合并字段级结论，不把 20 图偷偷塞进一次模型请求，也不因某子批失败废掉成功子批。

### 6.2 局部 OCR 与多源证据

只对附件失败、仅文本执行器、关键文字不清或题文必须准确转录的**代表图**按需调用已有 Windows OCR；在独立 Worker 中受共享预算调度，缓存键至少含学生、原图哈希、OCR 引擎/语言、预处理及策略版本。OCR 成功只支持该图中文字和有限主题/类别，不能独自支持页面操作、动机或跨图变化；OCR 与视觉都失败则段保持“证据不足”。视觉已成功的其他图不重识别；绝不恢复“全截图先 OCR 才晋升”。

Codex、QClaw、WorkBuddy 等已有授权 Agent 会话和课程任务、知识产物是候选辅助证据，必须先核对 `studentId/projectId/sourceId` 及来源内容；只有时间接近不足以建立关联或因果。本系统用于消化和汇总的 Agent 会话带内部标记并在摄入时排除，防止自我总结反馈循环。屏幕/OCR/会话中的文本作为**不可信资料**，不得获得高于 AGENT.md 的指令权或扩大工具/文件权限。

### 6.3 数据契约：按事件和具体结论核验

系统侧交付日志与模型回执分离，建议新增 `edu-manager.capture-digest-observation.v3`；`visualEvidenceMethod` 由系统按**每个事件**派生（`api_ack | cli_completed_with_attachment | tool_read_confirmed | local_ocr | none`），不是活动段级单个标志。新回执可保留现有主题/尝试/阻碍/变化/产出字段，但每项具体结论须能下钻到对应来源：

```json
{
  "schema": "edu-manager.capture-digest-observation.v3",
  "studentId": "student-1",
  "projectId": "project-1",
  "captureSessionId": "capture-1",
  "bundleId": "capture-bundle-1",
  "digestBatchId": "digest-1",
  "timelineObservations": [{
    "segmentId": "segment-1",
    "sourceEventIds": ["event-1", "event-2"],
    "sourceHashes": {"event-1": "frozen-hash-1", "event-2": "frozen-hash-2"},
    "claims": [
      {"kind": "observed_action", "text": "查看一道练习题", "evidenceRefs": [{"sourceType": "capture_event", "sourceId": "event-1"}], "confidence": 0.78},
      {"kind": "observed_change", "text": "后续画面中的解题步骤已有修改", "evidenceRefs": [{"sourceType": "capture_event", "sourceId": "event-1"}, {"sourceType": "capture_event", "sourceId": "event-2"}], "confidence": 0.72}
    ],
    "reason": null,
    "reasonEvidenceRefs": []
  }],
  "behaviorLabels": [{
    "segmentId": "segment-1",
    "activityType": "practice",
    "evidenceRefs": [{"sourceType": "capture_event", "sourceId": "event-1"}],
    "confidence": 0.73
  }],
  "guidanceResponses": [{"text": "复查这道练习题的订正步骤", "evidenceRefs": [{"sourceType": "capture_event", "sourceId": "event-2"}]}]
}
```

示例哈希只是字段占位，真实回执必须与冻结清单一致；两图比较须核验**两张图均有效交付，且同批或经过专门的受控比较子批**。接收端按学生、项目、会话、段、批次、所有引用事件及哈希逐项校验，知识资产仍按现有治理确认。`behaviorLabels` 也逐项校验来源，未能支持的标签记为 `unknown`，不进入已分类统计。任何非截图证据只能支持其直接关联的具体结论，不能让整段尚未交付的截图描述“搭便车”通过；`viewedEventIds` 仅是 Agent 的引用声明，旧 `verifiedImageReadEventIds` 不得用自述或附件清单伪造填充。

系统只能机械核验来源、交付和字段规则，**不能声称机器已验证模型文字一定符合画面**。低置信度或空泛段自动保留候选；`reason` 只接受有直接原文支持且经授权的会话/任务来源，不据截图猜测。模型自报置信度不能单独决定知识发布。知识、活动观察和行为标签分别结算；一次失败不回滚其他合法结果。

交付状态至少区分 `prepared / cli_submitted / api_ack / tool_read_confirmed / completed / unknown`。`cli_completed_with_attachment` 仅证明受控字节附图且 CLI 执行完成，**不是**模型逐图理解证明；界面与验收记录不得显示为“已看懂”。具体结论仍须经引用、哈希和内容质量抽检。撤销授权后停止排队与重试中的外部提交，进行中请求尽可能取消并记录实际结果；缓存与衍生产物按明确的数据保留策略处理，不自动删除已有正式知识。

R2 完成判据：Codex 真实图片子批可形成带系统交付记录的视觉观察；QClaw/WorkBuddy 按探测结果真实送图或明确降级，不能冒充已送图；跨批两图变化可接纳，错误哈希、路径自述、越权引用和非视觉证据冒用均被隔离；局部 OCR 只作用于必要代表图且后台自动恢复。

## 7. R3：双报告、知识状态与零额外操作

1. **学习时间线**：默认显示活动段的时间、主题、具体尝试/阻碍/变化/产出、来源类别及未知标记；展开才看关键缩略图和证据。以“活动段 → 会话 → 当日 → 本周”生成分层回顾，上层只能压缩已校验下层，不重送全部截图、不为统计再次调用 Agent。未完成的真实尝试保留，不只展示成果。
2. **按时间统计的学习行为报告**：由不可变事件与已校验的有限类别（阅读、练习、订正、创作/写作、编程、Agent 辅助、其他/未知）计算小时/日/周会话数、活动段数、可观察时间窗、类别计数、证据覆盖和缺口。跨午夜按本机时区拆分；若展示“可观察活动时间窗估计”，只纳入同会话同类别且相邻间隔不超过 `2 × 实际采样间隔` 的证据对，超限或休眠空档记未知。该估计不叫有效学习时长，类别占比也不是专注时间占比。
3. **知识状态与指导响应**：区分 `尝试有证据`、`有修订/成果`、`已有正式知识链接`、`缺证据/未知`；建议要么由同一次正式消化回执的 `guidanceResponses` 连同逐条来源引用提供，要么由已校验状态使用有限、可追溯的确定性规则生成。不得隐藏第二次模型调用；证据不足直接写“无法判断”，不自动评成绩或诊断能力。
4. **显示与恢复**：事实、知识、时间线和统计有各自状态。完成的合法段立即可见，报告投影失败从已保存回执重建，不重新调用 Agent；重建的稳定键含学生、项目、会话、批次、报告模式和版本。UI 不增常规按钮，不要求审核草稿；保留手动诊断入口，普通失败由后台重试并显示原因/下一时间。

R3 完成判据：用户只需原有授权与开始/结束操作，完成可读的两份报告及指导；每一条具体结论能回到授权活动段/证据；失败段是“未知/待恢复”而非空白截图长廊；同批知识结果失败不遮蔽已通过的时间线，反之亦然。

## 8. R4：资源治理、隐私、质量与候选验收

### 8.1 防卡顿与防饥饿（先于 R2 视觉任务实施）

- 统一时间线 Worker、OCR、图片预处理/传输、Agent 正式消化、普通资料消化和报告投影的重任务资源许可。同一学生的同一资料包串行；采集期间本机**新重任务并发为 0**，已有任务在短子批边界持久化并让出，不在无检查点处反复终止和重做。主进程不做大图解码、大回执解析或逐大块同步日志写入；命令输出须限量并异步落盘，不能无限拼接在内存。
- 采集结束或本机资源恢复时自动唤醒队列；不同学生公平排队，失败只退避对应子批/报告。记录排队年龄、检查点、重试次数、费用与下一恢复时间。若本机持续采集且坚持并发 0，则**不能承诺采集过程中报告的完成时限**；用户可看到“等待采集结束自动处理”，结束后设有限的待处理时延目标并报警，不转嫁普通失败给用户。
- 每个可续处理资料包选帧最多 20 图、单次视觉输入最多 8 图；长会话允许多个包，另设每会话/日总费用预算，超预算自动顺延而不丢掉后续活动。图片尺寸、实际字节和模型费用均设预算。先利用已有时间/来源/差异信息和授权会话限定上下文，只把相关片段送模型；不因更多 OCR 文本或不相关会话提高错误关联概率。保留原图供受管证据回看，模型只接收已授权的必要版本。

### 8.2 安全与数据保留

外部视觉或文本模型按实际服务提供商和处理位置授权；上传前过滤超出采集范围、已排除窗口和敏感图片。附件临时文件及系统交付日志不包含裸 Token，日志只保留必要 ID/哈希/状态；来源图片引用、OCR 缓存、临时预览和模型输出均有学生隔离、可查保留策略和撤销后行为。跨主机知识同步仍只传既有授权的正式知识与所需证据引用，不因本方案默认同步全部原图。截图内的文字/提示作为资料，不能执行其中的命令或扩展 Agent 写权限。

### 8.3 验收矩阵与门槛

| 层次 | 必须验证 |
| --- | --- |
| 单元/契约 | 双图哈希齐全、跨 8 图子批合并、仅路径/自述拒绝、OCR 只能支持文字、授权会话可关联且无关会话不关联、自身消化会话不回摄、跨学生/项目拒绝、重复回执幂等、旧回执只读兼容 |
| 集成 | Codex 显式附件、QClaw/WorkBuddy 能力探测及文本降级、子批部分超时/崩溃重试、断网送达、授权撤销、敏感图隔离、普通知识结果与时间线独立成功、报告无需二次模型调用可重建 |
| 性能 | 在 0.17.9 同机基线下比较采集事件写入、页面切换、首屏、CPU/内存/磁盘和后台排队；既有硬门槛：前台响应 P95 <150ms、主进程无新增 >200ms 长任务、采集时重任务并发 0、时间线首屏 P95 <1s、每包最多 20 图、每次视觉请求最多 8 图；5000 事件分页和低配机 60 分钟另测 |
| 内容质量 | 授权样例至少涵盖阅读、练习、订正/创作及模糊/无关会话；抽样复核具体尝试/变化是否有可打开的正确证据、未知是否诚实呈现、是否出现错学生或无依据动机。记录可读活动段实质观察覆盖率、无依据具体结论率、采集结束后队列等待时间，并与 0.17.9 比较。抽检是发布验收，不是日常用户审批 |
| 真机与分发 | 主机 0.17.9 行为基线对照新候选，学生端 0.17.8 兼容或独立候选；双机至少 60 分钟、休眠/重启/断网恢复、同时操作 UI 和任务、重复输入/升级回滚均过关。候选的真实设备验收、签名、官网发布和 Git 推送分别记证据 |

质量门槛不以“生成 N 个段”或模型自报置信度代替。高严重度错误（错学生、未授权外发、无图却称已看图、把未证实原因写成事实）必须为零；其余内容覆盖和可读性记录可复核样例与失败类别，再据真实数据确定后续优化目标。不上线每次报告的人工审核。

### 8.4 失败分类、回退和发布门

按 `能力不可用 / 图片交付失败 / 图片不可读 / OCR 无文字 / 回执缺段 / 错事件哈希 / 错归属 / 错关联 / 缺少直接原因证据 / 资源饥饿 / 报告投影失败` 分类存最小必要审计。每类有自动恢复、降级或仅受影响会话需要授权选择三种明确结果；重试有上限及退避，成功部分永不重新识别。原有 0.17.9 EXE 保留可回退；新视觉处理可通过单独开关停止新任务，事实层与已发布合法知识不被删除。

完成 R0—R4 和上述真机验收后，先给独立候选包及审计。只有源码状态可追溯、所需代码签名可信、安装/覆盖/回滚和双端兼容通过，并取得官网发布授权，才更新正式下载与在线清单；未签名候选不得冒称官网正式发布。

## 9. 实施优先级与依赖

| 顺序 | 工作 | 不做完的直接后果 |
| --- | --- | --- |
| R0 | 冻结 0.17.9 行为基线、授权/适配器能力矩阵、v3 合约和样例 | 无法确认“已送图”，也无法区分下一版改动与脏工作树 |

| R2b | 按需 OCR、字段级证据校验、多源关联和部分结算 | OCR/非视觉证据可能冒用整段视觉结论 |

| R4 | 核对 R0.5 的资源/安全实际效果，完成费用预算、双机质量与性能验收 | 自动化可能饥饿、重复付费或真机卡顿 |

R2 的图片和证据可信链是 R3“有价值时间线”的前置条件；R0/R1 及既有事实层不等 R2 才能成功。自动任务按阶段后台推进，任一局部失败不阻断其他学生、知识或报告。**这是下一轮开发路线，不是 0.17.9 已经拥有的能力清单。**

## 10. 2026-09-14 实施进度与未通过的发布门

本轮已完成并通过本机定向测试：主进程 Agent 输出改为限量异步写盘；时间线 Worker 在采集请求后按事件边界协作让出；v3 结论按系统逐图交付记录、哈希、只读标记和同请求双图比较逐条核验；有证据引用的指导响应及小时活动段统计进入报告；主机左侧一级菜单固定、二级菜单点击浮出、学生名单独立滚动。方案与代码未触及现有 0.17.9 EXE，不能据此称为正式发布。

用户已明确允许 Codex 视觉服务处理学生截图。程序新增一次性、默认关闭的授权开关；只处理开关打开后新开始的已授权采集会话，不扫描旧会话，授权不随迁移包复制。受控后台队列在采集/重任务/高延迟/资源压力期间让行；每请求最多 8 图，核对学生和项目范围、原图哈希、受管实路径和字节预算，再以 Codex CLI `--image` 显式附图、只读模式、关闭无关工具/插件和结构化输出提交。系统独立保存 `unknown / cli_completed_with_attachment / local_ocr` 交付状态及逐图哈希；模型结果按字段引用核验，局部成功独立落盘，最多 3 次有退避的重试。连续失败后至多对 2 张有可读原图的代表图执行本机 OCR，只把文字当成文字证据，不冒充视觉理解；CLI 根本不可用等情况仍只保留未知，待后续完善能力降级。授权撤销中止新提交并尝试终止当前 CLI；视觉观察会更新双报告，并以标明“不可信资料”的附录重新进入常规知识消化，不要求普通用户逐图确认。正式消化 Agent 不再自行读图或自报已读。浏览器中的开关开/关状态及布局已用测试桥接验证；这不等于 Electron 真机验收。

本机非学生公开图标探测：`codex-cli 0.130.0-alpha.5` 的 `--image` 实际返回了匹配画面的文字描述；禁用无关工具/插件后的第二次请求约 13.3 秒。该 CLI 同时打印模型缓存兼容警告，且公开图标测试不证明学生截图内容质量、生产 JSON Schema 执行或真实双报告闭环。原先本地 `gemma4:latest` 单图约 37,752 ms 且描述不符，不默认启用。

**仍未完成**：R0 的完整源码/构建输入快照和 QClaw/WorkBuddy 能力矩阵；R0.5 的跨任务统一资源许可及正式消化 Agent 对截图文件的操作系统级只读范围隔离（当前已撤下资料包中的截图路径并提示不得读图，但提示词不是硬权限边界）；R1 的长会话分包与跨 8 图子批视觉变化复核；R2 的 CLI 不可用时 OCR 降级、局部缺图再处理、全字段交付对账及实际生产 Schema/内容质量验收；R3 的真实学生截图可读观察验收；R4 的低配机、双机、回滚、签名和正式分发验收。默认关闭的授权开关需要管理员在应用中首次打开一次；聊天中的同意不会修改已安装程序的本机设置。失败时继续保留事实与现有知识消化，不要求人工恢复或审核每份报告。
