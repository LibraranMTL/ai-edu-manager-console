# Windows 0.8.6 固定机器码与双向局域网连接

**Windows 主机版本：0.8.6**  
**Android 平板版本：0.5.8**

## 本次交付

- Windows 主机和 Android 平板分别生成长期固定、可备份恢复的机器码。
- 平板可查找局域网主机并发起请求，由 Windows 核对平板名称、机器码和 IP 后接受或拒绝。
- 平板开启“等待主机连接”后，Windows 可查找平板并发送邀请，由平板核对主机名称、机器码和 IP 后接受或拒绝。
- V2 不显示一次性校验数字；协议内部使用随机请求令牌，请求两分钟后失效。
- 同一平板重复发起时，新请求替代尚未处理的旧请求；超时和取消保留最近记录。
- 设备连接后仍必须在 Windows 授权学生。已撤销设备不能自行恢复。
- 二维码、六位配对码、粘贴连接信息和连接备份保留在“其他连接方式”。
- 同版本修订后，Windows 会向全局广播和各物理网卡定向广播地址同时查找；Android 等待页持有 Wi-Fi 多播锁并周期声明在线状态。
- 平板发现列表按 UDP 来源 `IP:端口` 和完整主机身份双重合并；同一 IP 上先后收到的 V1、V2 响应只显示一次，并以包含固定主机码的 V2 记录为准。
- 同一主机的 V2 发现结果会覆盖 V1 兼容结果；固定主机码筛选只进入 V2 连接，不会再弹出六位配对码。

## 实机验收清单

以下项目需要在真实 Windows 主机和 Android 平板上完成：

1. 同一 Wi-Fi 下，平板查找主机并由 Windows 接受，随后授权学生。
2. 平板开启等待模式，Windows 查找平板并邀请，平板接受后授权学生。
3. 拒绝、两分钟超时、重复发起和取消后，双方状态一致且可重新申请。
4. Windows 防火墙允许专用网络时可发现；访客网络或客户端隔离时显示明确提示，并能改用备用连接方式。
5. 平板切到后台后停止等待监听，返回应用后不会无提示恢复监听。
6. 备份并恢复主机或平板连接配置后，固定机器码保持不变。
7. 已撤销设备不能通过 V1 或 V2 自行恢复；主机人工恢复后可以重新连接。
