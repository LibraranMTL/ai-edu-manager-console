AI教育管家 Windows 主机端操作手册

适用版本：Windows 主机 0.9.10

配套学生终端：Windows 0.9.10 / Android 0.6.2

1. 启动与升级

  1. 关闭所有旧版 AI教育管家窗口。
  2. 启动新版程序。程序启用单实例保护，重复启动时会聚焦已有窗口。
  3. 首页应显示“今日教育资料闭环”，并根据当前资料状态只突出一个主要下一步；版本与诊断信息收纳在高级工具中。
  4. 升级后系统优先读取主机学生索引，并同步界面缓存；不移动学生知识库物理目录。
  5. 升级前建议执行“备份主机数据”，完整迁移电脑时还应单独备份学生资料根目录。

2. 创建学生档案

  1. 打开“初始化教育管家”或“新建教育智能体”。
  2. 填写学生姓名、年级、学校和学习目标。
  3. 选择创建标准知识库或接管已有知识库。
  4. 点击“保存学生档案并初始化”。

一次操作会创建知识库目录、AGENT.md、LLM Wiki 目录、索引、日志和基础学情报告。右侧 Agent 工具连接是可选步骤，不会再次创建目录或覆盖 AGENT.md。

点击任一 Agent 步骤卡片即可复制该步骤指令；如在“高级”中修改过内容，则复制修改后的指令。

3. 接管已有知识库

  1. 选择“接管已有知识库”。
  2. 选择现有知识库根目录。
  3. 确认系统识别出的 AGENT.md、原始资料库、综合汇总和输出目录。
  4. 对未识别目录进行手动指定。
  5. 查看路径健康检查；需要时生成逻辑路径草稿或执行“备份后修复旧路径”。
  6. 确认接管。

接管不移动、不复制、不删除原文件。系统使用工作空间身份、逻辑路径和当前主机映射处理跨电脑同步后的路径差异。

4. 资料收集与处理

资料可从 Windows 主机本地导入、Windows 学生端上传、Android 学生端上传、项目工作空间晋升或屏幕采集箱进入系统。主机本地导入时也需要选择资料归属：

  • 学生原始资料库：用于日常作业、学习记录和不属于特定项目的资料；
  • 绑定项目原始资料库：用于项目研究、作品、过程资料和项目参考资料。

选择项目资料库时，只显示当前学生已经绑定且未封存的项目。处理区按学生显示：

  • 待提交消化：尚未交给 Agent 的资料；
  • 等待 Agent 回执：已提交，但 Agent 尚未写回完成证据；
  • 已处理：已匹配完成回执；
  • 失败或需复核：回执失败、低置信度或覆盖不足。

5. Agent 资料消化

  1. 选择学生，确认页面显示待处理数量。
  2. 点击“开始处理”。系统会重新核对真实待处理资料、冻结本批文件清单，并自动选择当前可用的 Agent 通道。
  3. 页面进入“处理中”后可以离开当前页面；顶部后台任务条会持续显示状态，Agent 返回结果时系统自动校验并更新，无需再点击“标记已提交”或“同步结果”。
  4. 全部通过时显示“已完成”；只完成部分资料时显示“部分完成”，点击“重试未完成项”只会处理剩余资料。
  5. 点击“查看新增知识”可打开现有知识目录。

学生资料和学习项目均使用严格的逐文件批次。只有当前批次、资料身份、相对路径、SHA-1 和知识产物全部匹配时，系统才会把对应资料标记为完成；没有有效回执或产物时不会误报完成。批次、哈希、JSON 回执和内部任务状态只保留在“高级与诊断”中，普通使用无需查看。

如果本机没有可直接调用的 Agent，页面会自动降级为人工方式：系统准备并复制一次完整指令，用户在已有 Agent 中粘贴执行，再把 Agent 返回结果粘贴回当前页面。整个过程不需要进入任务中心，也不需要手工修改资料状态。

6. 消化覆盖审计

大量图片或复杂资料消化后建议执行二次核对：

  1. 点击“生成覆盖审计”。
  2. 查看完整覆盖、部分识别、失败、待回执、源文件缺失等状态。
  3. 选择待复核资料并复制二次核对指令。
  4. 将指令交给任意可访问知识库的 Agent。
  5. Agent 独立执行视觉识别、OCR 和逐文件比对，并把当前轮次结果写入 digest-review-receipt.json；首次消化的 digest-receipt.json 保持不变。
  6. 点击“同步复核结果”。

系统只接收与当前 digest-review-request.json 中复核轮次、消化批次和资料 ID 完整匹配的新回执。若 Agent 只在对话中报告、回执过期或缺少资料，界面会保持原状态并明确提示原因。回执包含未转义引号或字符串换行时，系统会尝试容错修复并保留无效回执备份。

7. 屏幕资料采集

位置：资料收集与处理 → 屏幕资料采集。

Windows 支持整个屏幕或指定应用窗口，并提供智能混合、内容变化、固定间隔三种策略。可设置 15 至 120 分钟，采集中支持暂停、继续、重点截取和结束。

快捷键：

  • Ctrl+Shift+1：立即截取；
  • Ctrl+Shift+2：暂停或继续；
  • Ctrl+Shift+3：标记重点。

截图先进入候选采集箱并登记为候选资产。只有点击“晋升资料”后，才进入学生原始资料库和待消化队列。

8. 文件资产中心

文件资产中心用于查看资产身份、来源、版本、重复组、引用关系和治理风险。

选择学生后，资产总数、重复组、治理候选、风险、最近七日曲线、资产列表和详情会统一切换到该学生范围。搜索、来源、类型和“只看重复”只筛选列表，不改变学生范围看板。

“最近 7 天资产变化”包括每日新增资产和每日新增引用。旧记录缺少历史日期时不会猜测日期，并会显示未计入数量。

9. 新建学习项目

位置：学习项目 → 新建学习项目。

  1. 填写项目名称、类型、目标和参与学生。
  2. 选择项目模板或自定义模板配置。
  3. 自定义项目工作空间文件夹，或选择“使用已有项目文件夹”。
  4. 确认工作空间与知识空间位置。
  5. 创建项目。

项目工作空间面向学生和教师，项目知识空间使用原始资料、概念、实体、摘要、问答精华、综合汇总的统一结构。

10. 学习项目四步工作流

已有项目页会根据当前状态推荐下一步，日常操作按四步完成：

  1. 添加资料：扫描工作空间，导入网页、论文、截图和草稿等候选资料；核心资料也可直接采用，已有正式资产可直接复用。
  2. AI 整理建议：AI识别相关性、重复和资料价值；用户主要确认冲突、低置信度和需排除资料。
  3. 确认并消化：确认完整副本、来源记录或关键快照等保存策略，把采用资料加入项目原始资料库，再将严格批次任务交给 Agent 消化并检查回执。
  4. 完成项目：审核风险知识和每名学生的独立成长证据，生成归档清单并发布到学生长期档案或成长模型。

“系统建议下一步”会依据真实待整理、待消化、待审核和待归档数量突出一个主操作。筛选、批量状态、手工保存策略和目录模板仍可在“高级操作”中使用。

“核心资料直接采用”适合已经确认的官方文件、原始数据、教师反馈和最终成果，会跳过暂存筛选，但仍保留来源和资产登记。

11. 已有学习项目

位置：学习项目 → 已有学习项目。

项目详情提供：

  • 打开项目根目录、项目工作空间、项目原始资料库和项目知识空间；
  • 编辑项目记录，但不改动物理目录；
  • 重新定位丢失或迁移后的项目路径；
  • 复制项目模板和知识策略，不复制无关资料或历史贡献；
  • 导入、导出项目包；
  • 安全删除项目和从“已删除项目”恢复；删除只移出项目索引，不删除工作空间、知识空间、资产或审计文件；
  • 生成贡献申请、归档确认、贡献审计和发布到成长模型。

扫描、资料整理、加入知识库、Agent 回执、知识审核和完成项目的结果会显示在当前阶段，并提供下一阶段定位入口。

多学生项目共享项目知识，但每名学生的成长证据独立生成和审核。

12. 项目仪表盘

仪表盘用于检查资料治理、知识覆盖、待审核项、贡献状态和风险。可查看指标应作为入口打开对应清单，不只是静态数字。

自动化触发可由新资料、项目阶段变化和定时任务产生。关闭自动运行总开关后，触发器只生成待办，不会自动调用 Agent。

13. 统一任务中心

任务中心统一承接 Agent 自动任务和人工任务，记录任务输入、执行工具、权限、决定状态、日志、超时、重试和结果校验。用户不再需要手工填写审批意见：按当前状态点击“允许执行”“采用并发布”“需要修改”“忽略本次”等按钮即可；高风险执行仍会要求一次确认，后台完整保留审计记录。

支持方式：

  • OpenClaw：受支持任务可直接执行；
  • QClaw：通过任务收件箱领取；
  • Codex CLI、Marvis 或其他 Agent：复制任务指令并人工回填结果；
  • 手动模式：一次关闭全部自动运行，避免后台任务消耗资源。

四类学情输出统一由任务中心调度：能力画像按月更新，历史变化按周更新，阶段总结按月更新，每周行动建议按周更新。新增成长证据、能力模型变化或项目阶段变化时，对应报告任务会重新进入待处理状态。每名学生在同一周期只保留一项当前任务，旧周期任务退出当前队列但保留历史记录。

每周行动建议包括每日固定动作、每周重点、阶段性里程碑，以及分别面向学生、家长和老师的建议。能力画像、历史变化和阶段总结只使用已确认的成长证据；没有实质变化时必须明确写明“本周期无实质变化”，不得虚构进展。

点击“查看任务”后，页面会定位到任务详情并直接显示 Agent 反馈摘要、校验状态和行动反馈；存在结果文件时可点击“打开结果文件”。点击“打开来源”会进入对应学生的资料处理、每周行动建议或教育档案页面，不再顺带复制和提交新指令。

人工 Agent 完成任务后，可把返回的 JSON 或文字直接粘贴到任务详情的“粘贴 Agent 结果”，再点击“导入粘贴结果”。标准 JSON 会严格核对任务 ID 和当前执行批次；普通文字由当前任务显式绑定，但仍会检查实际输出文件、更新时间和规定结构。学生或项目资料消化在严格校验通过后自动验收；正式报告、成长证据和其他发布类任务仍进入待审核，不会直接发布。需要兼容旧流程时，可使用“从文件导入”。

每周行动建议的更新闭环为：执行任务、粘贴或同步 Agent 结果、系统校验草稿、人工点击“审核并发布”。发布成功后，控制台会自动进入学情中心并刷新“每周行动建议”。界面名称已经按周呈现，底层继续写入原 每日行动建议.md 以兼容既有学生知识库。用户提交“本周已完成 / 本周部分完成 / 本周跳过”后，反馈保存到任务历史，并作为下一周建议的输入。

14. 学生成长模型与学情报告

项目知识不是直接复制到学生目录。项目结束后生成知识贡献申请，用户审核新增概念、实体、成果和能力证据，再发布到成长模型。

成长模型看板分为三个视图：

  • 能力画像：按能力维度汇总已确认、观察中和待审核的证据，并显示成熟度、趋势、来源项目和最近观察时间；
  • 项目贡献：列出项目状态、贡献发布状态、支撑能力和已确认证据，可点击进入对应学习项目；
  • 成长证据：按状态、能力和关键词筛选候选证据，并执行确认、观察或驳回。

成长证据默认显示“需要关注”，不会用低风险项目证据占满日常待处理列表。点击“一键处理本批次”只需确认一次：系统批量确认低风险项目证据，把中风险证据设为“继续观察”，高风险证据保持不变、留待逐条审核。用户可切换到“低风险”或“全部”查看被隐藏的候选；隐藏不等于删除或自动发布。每条批量处理记录仍保留同一批次 ID、审核时间和审核历史。

“成长模型目录”卡片可直接打开学生知识库下的成长模型文件夹。旧版 成长证据.md 会在结构化索引升级时兼容导入，不移动、不删除、不覆盖原文件。

学情报告是独立呈现层，只读取成长模型中的已确认结论：整体画像引用能力画像，历史变化引用能力时间线，阶段总结引用项目贡献和成长证据，每周行动建议由统一任务中心生成并审核发布。为兼容已有知识库，底层仍沿用原 每日行动建议.md 文件名。报告为空时，应依次检查：资料是否完成消化、成长证据是否确认、项目贡献是否发布、成长模型索引是否刷新。

页面中的流程按钮采用当前皮肤的颜色变量自动引导：主题强调色表示现在建议点击的唯一下一步，绿色表示已经完成，主题描边表示可选操作，灰色表示条件不足。颜色由真实资料、Agent 回执和确认状态计算，不能通过跳着点击后续按钮绕过前置条件。

14.1 对话与多源知识候选

在“对话历史”中先粘贴或导入对话并点击“保存对话导入记录”。系统会保存不可变原文，生成 Interaction、ConversationAsset、稳定消息 ID 和内容哈希；相同内容重复导入不会产生重复记录。

复制新的 AI 提取指令时，每条结果必须返回候选内容、逐字原文和消息 ID。点击“保存为逐条候选”只登记候选，不会直接改写 UnifiedMemory、UnifiedSoul、咨询精华或待办。

“P2 逐条候选治理”支持：

  • 查看候选内容、逐字原文、消息定位和风险原因；
  • 编辑与补证、拒绝、合并、标记冲突、标记过期或恢复候选；
  • 对敏感信息进行明确风险确认；
  • 选择通过的候选并点击“事务晋升所选”；
  • 在事务列表点击“撤销本次晋升”。

缺少来源、原文不匹配、提示注入或冲突未解决时，整批候选都不会写入。撤销只移除该事务写入的标记内容，并同步更新候选索引；原始对话不会删除。

15. 使用模式与学生终端

  1. 在“系统设置 → 使用模式”选择“主机-终端模式”，并启动学生终端协作服务；只在本机管理时选择“主机模式”。
  2. Windows 学生端可粘贴主机连接信息，或使用主机地址和六位配对码完成登记。
  3. Android 学生端可查找局域网主机、扫码、粘贴连接信息或导入连接备份；主机与 Android 也可通过固定机器码双向发现并确认。
  4. 在设备卡片选择“个人终端”或“共享终端”。个人终端固定绑定一名学生；共享终端不绑定学生范围。
  5. 系统为每名既有和新建学生自动生成稳定的学生登录 ID 和二维码，可在“学生登录 ID 与二维码”中查看或复制。
  6. 共享终端由学生输入 ID 或扫码进入；未进入时不返回学生名单，进入后只返回本人资料和本人绑定且未封存的项目，退出即清空会话。
  7. Windows 学生端和 Android 学生端均不提供档案初始化、项目管理、知识治理或报告发布功能。

学生登录 ID 不替换内部学生 ID，不改名、不移动既有学生目录，也不需要额外 PIN。旧设备若原来只授权一名学生，会自动迁移为个人终端；原来授权多名或全部学生的设备迁移为共享终端。

局域网主机服务默认使用端口 18777，Android 自动发现使用端口 18778。若学生终端找不到主机，请确认两端位于同一局域网、主机服务正在运行，并允许 AI教育管家通过 Windows 防火墙的专用网络。部分访客网络或启用客户端隔离的网络会阻断局域网广播，此时使用粘贴连接信息等兼容方式。

为兼容旧版客户端，主机可能同时发送新版 V2 发现信息和旧版 V1 发现信息。Android 0.6.2 会按发现端点和设备身份自动合并同一主机：同一 IP、同一端口或同一主机身份只显示一条记录，并优先保留包含固定主机码的 V2 记录。该兼容广播不会创建第二台真实主机。

展开“其他连接方式”后，仍可使用二维码、6 位配对码、粘贴连接信息或连接备份。旧客户端可继续使用 V1 六位短码；局域网广播不包含 API Token、设备令牌或旧配对码。

设备可在卡片内重命名。已撤销设备可恢复或删除记录；活跃设备需先撤销才能删除。删除授权记录不会删除历史上传审计。

16. 备份与恢复

“备份主机数据”保存固定主机身份、完整学生档案字段、设备授权、上传记录和应用索引。恢复后固定主机码、学生列表、学习项目、文件资产和主机状态会立即刷新。平板连接备份同时保存设备身份、固定平板码及已连接主机身份。

注意：主机状态备份不等于完整知识库文件备份。迁移电脑或更换磁盘时，还必须备份学生资料根目录中的 PDF、图片、Word、Markdown 和项目文件。

17. 常见问题

新版看不到原学生

先确认旧版窗口已关闭。0.9.10 使用单实例保护和主机索引校准；如仍缺失，恢复主机备份并检查学生知识库路径。

待消化数量不变

无需手工标记提交或同步。先等待最多 5 秒让页面自动刷新；如果仍未变化，展开“高级与诊断”查看简短原因。Agent 只生成知识文件但没有写回严格回执时，系统会继续显示处理中；可点击“重试未完成项”，或在人工降级区粘贴正确结果。

项目消化回执已写入但无法同步

Windows 0.9.10 会自动读取回执并同步项目状态，也可读取带 UTF-8 BOM 的 Agent JSON。若进入人工诊断，回执必须使用当前请求中的 projectId 与 digestBatchId，并为每个实际完成的源文件填写原始 materialId、relativePath 和 sha1。只完成部分资料时，合法完成项会立即结算，其余资料保留给“重试未完成项”。

数学图片未被识别

生成覆盖审计，选择失败或低置信度图片，执行二次核对并同步复核结果。

项目知识空间打不开

先执行“重新定位”，确认知识空间目录存在；再使用项目详情中的文件夹入口。路径健康检查中存在错误时先修复映射。

学生终端已连接但没有学生

个人终端请在主机设备卡片绑定学生；共享终端请让学生扫描主机生成的本人二维码或输入完整学生 ID。共享终端不会显示可选择的学生名单。

Android 学生端找不到附近主机

确认 Windows 0.9.10 主机服务已启动，主机和学生终端连接同一局域网，且路由器没有启用访客网络或客户端隔离。允许 Windows 防火墙的专用网络访问后重新搜索。Android 发起时选择“查找局域网主机”，在 Windows 的“等待主机接受”中确认机器码后接受；主机发起时先在 Android 开启“等待主机连接”，再由 Windows 查找并邀请。仍无法发现时，可展开“其他连接方式”，使用二维码、六位配对码、粘贴连接信息或连接备份。

Android 学生端发现两个 IP 相同的主机

Windows 为兼容旧版客户端，可能同时发送新版和旧版发现信息。Android 0.6.2 会自动把同一发现端点或同一设备身份合并为一台主机，并保留带固定主机码的新版记录。若仍看到两个相同 IP 的条目，请确认 Android 终端确为 0.6.2，退出连接页后重新进入并再次查找；不要选择不显示主机码的旧版记录。

程序运行变慢

在任务中心关闭全部自动运行，停止不需要的屏幕采集会话，并检查是否存在大量待处理 OCR、审计或资产扫描任务。
