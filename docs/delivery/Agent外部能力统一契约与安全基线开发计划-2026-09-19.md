# Agent 外部能力统一契约与安全基线开发计划

> 2026-09-19；后续开发计划，不属于 Windows 0.17.9 纵向学习分析候选包的已验收功能。

> 实施进展与未完成的真实联调/发布门槛见 [2026-09-20 实现与验收记录](Agent外部能力实现与验收记录-2026-09-20.md)。该计划不能因本地代码测试通过而标记为正式发布完成。

## 目标与现状

让外部 Agent 通过 API、MCP、CLI 在授权范围内查询教育管家知识并调用业务能力。采用“主机端能力层 + AGENT.md 指引”：AGENT.md 说明如何使用，学生/项目隔离、权限、审批、审计和副作用控制由主机强制执行。

现有主机已有 `/api/agent/knowledge/query`、`/api/agent/conversation/submit`、Agent 记忆端点、`electron/agent-knowledge-mcp.ps1` 单一知识查询工具及通用 REST 路由。这些入口尚不等于统一的全业务 capability 合同。当前 HTTP 认证可解析 `agent_grant`，部分通用路由在 `requireAuth` 后按学生范围过滤；是否仍可被 Agent 令牌访问，需要 P0 逐路由审计，不能仅凭已有范围过滤推定安全。

## 实施顺序

### P0 安全基线（任何扩权之前）

1. 枚举 Agent 令牌可达的全部 REST 路由及方法，特别检查资料上传、portable migration 创建/下载、项目与资产路由。
2. 对 `agent_grant` 默认拒绝非 Agent 专用路由；每个允许操作重新验证 capability、studentId、projectId、设备/会话范围。`requireStudentAccess` 只解决对象范围，不替代操作权限。
3. 本机适配器优先 localhost/stdio；跨设备要求受控网络通道、认证与速率限制。记录调用、拒绝、撤销和轮换审计，不保存明文令牌或无关原始隐私内容。
4. 增加跨学生/项目、越权写入、令牌撤销、并发和拒绝路径测试。P0 未通过前，不开放新的通用写工具。

### P1 统一能力契约

主机建立版本化 capability registry：名称、JSON Schema、只读/写入/高风险等级、scope、权限、幂等键、审批要求、返回 receipt、稳定错误码。REST、MCP、CLI 调用同一业务服务，不维护三套不一致实现。结果统一携带来源 URI、freshness、学生/项目归属、证据和错误码。

### P2 首批只读能力

先开放知识检索与有限片段读取、资料目录/元数据、任务与消化状态三个高频工具；再扩展学生/项目概览、报告列表和有权限的报告读取。所有查询必须精确过滤学生/项目，禁止跨学生回退；配套分页、速率限制、脱敏和大结果截断。

### P3 受控写入

对话提交、材料登记/上传、任务创建和草稿报告采用 `preview/dry-run → 用户确认或策略批准 → execute → receipt`，要求幂等键和可恢复状态。正式知识提升、报告发布、批量导出/迁移、删除和跨端同步保留主机端审批，不作为无确认通用工具。

### P4 API、MCP、CLI 三种入口

API 提供 OpenAPI/Schema；MCP 只暴露精简任务型工具与资源，不机械映射全部 REST；CLI 支持机器可读 JSON、明确退出码和 scope 参数。三者共享 Agent grant 的绑定、撤销和审计。MCP tool annotations 只是提示，不是权限检查。

### P5 文档与 AGENT.md

文档覆盖能力目录、调用示例、权限矩阵、目标选择、错误处理、来源/新鲜度、审批、审计与撤销、兼容迁移。AGENT.md 指导 Agent 先选学生/项目、先查证据、写入先预览，不绕过主机权限，不把令牌或原始隐私资料写入提示词/日志。现有自定义规则采用预览和兼容迁移，不静默覆盖。

### P6 验收与发布

用单元、集成和端到端测试核对 API/MCP/CLI 的同一操作语义；覆盖拒绝、跨学生/项目、授权撤销、重复请求、并发、断连恢复、审计与回滚。分别记录本地代码、真实 Agent 联调、真实设备、签名包和正式发布状态，不互相替代。

## 第一可交付切片

`P0 安全基线 + 知识查询/资料目录/任务状态三个只读工具 + 同源 API/MCP/CLI 契约与测试`。通过后再扩展写操作。普通用户目标体验为一次授权、后台调用，仅在异常或高风险动作时确认。
