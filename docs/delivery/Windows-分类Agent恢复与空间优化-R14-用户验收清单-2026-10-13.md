# Windows 分类 Agent 恢复与空间优化 R14 用户验收清单

候选目录：`release/windows/candidates/smart-material-agent-recovery-r14-20261013/`。当前候选未签名，尚未安装到正式环境。

只需要您参与以下项目；技术回归、包内探针、合成资料 Agent 调用和迁移副本验证已经由开发侧完成。

## 1. 安装前

- 退出当前 AI 教育管家。
- 保留现有用户数据目录备份。R14 会对可证明“正文未发送”的旧认证失败记录做一次迁移，并尝试清理已验证的历史重复副本。
- 安装候选 EXE；若 Windows 提示未知发布者，是因为该候选仍未签名，只在您确认文件哈希与验收报告一致时继续。

## 2. WorkBuddy 一次性授权

1. 打开“资料收件箱”，选择需要使用 WorkBuddy 的学生。
2. 点击“自动准备并授权 WorkBuddy”。应用会自动下载并验证官方 CLI，然后打开官方登录页；不需要上传 JSON、选择文件夹、提供密码或 Token。
3. 在官方页面完成登录后，回到应用点击“我已完成登录，继续”。
4. 放入一份无敏感信息的代表性资料，确认状态能从“等待 Agent”进入建议、待确认或已投递，而不是再次要求选择 JSON。

如果只希望使用 Codex 备用，可在该学生的提示中点击“允许 Codex 作为备用并继续”。这是学生级一次性授权；资料可能提交给 Codex。正文可能已发送、敏感拒绝或范围冲突时系统不会自动切换。

## 3. 分类与手工兜底

- 用一份项目标识明确的资料验证自动建议或可信自动投递。
- 用一份归属含糊的资料验证系统进入人工确认，而不是随意自动投递。
- 选中一份待处理资料，展开“手动指定位置并投递／纠正”，选择学生和项目后投递；再在“已投递”中改投一次，确认新目标成功且旧关联按引用规则处理。

## 4. 单副本存储

- 对“下载文件”或明确设置为“专用中转目录”的来源投递一份测试文件。
- 投递成功后确认：中转目录中不再保留该原件，也不再创建来源下的“已投递”副本；“已投递”页的“原件”仍能打开受管目标中的登记原件。
- 对 Documents、图库等普通来源再投递一份测试文件，确认用户原件仍保留。该类来源保留用户原件属于预期行为。
- 首次启动后如历史副本没有被删除，先查看诊断记录。路径、回执或哈希不能完全核验时系统会安全跳过，不应手工批量删除。

## 5. 请反馈的结果

请记录：学生、来源类型、文件类型、最终状态、是否使用备用、建议项目是否正确，以及专用中转目录是否只剩受管目标的一份原件。不要发送资料正文、密码或 Token。
