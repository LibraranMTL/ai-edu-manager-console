# Windows 0.7.35：统一任务协议与多 Agent 执行

## 本次交付

- 统一使用 `TaskEnvelope 1.0` 和受约束状态机管理学生消化、项目消化、知识审核、贡献归档、知识库维护与每日行动建议。
- 业务模块不再直接绑定 Codex，统一通过执行适配层选择 Codex、OpenClaw、QClaw 任务收件箱或人工任务包。
- 每日行动建议按学生和日期幂等生成，读取成长模型、绑定项目、未完成任务和前序反馈；结果必须先生成草稿、校验并经人工审核后才能发布。
- QClaw 使用标准任务包、领取回执和结果文件异步协作；不具备直接接口的工具平滑降级为人工复制指令和导入结果。
- 高风险任务执行前审批，所有任务保留事件日志、执行日志、校验记录、超时、取消和重试批次。
- 智能路由综合可用性、授权状态、任务匹配、历史成功率、速度、成本和数据边界生成可解释候选列表，最终始终保留人工兜底。

## 数据位置

统一任务中心位于资料根目录下：

```text
.edu-manager/task-center/
├── tasks.json
├── events.jsonl
├── executions/
├── qclaw-inbox/
├── qclaw-results/
└── manual-outbox/
```

## 验收要点

1. 任务详情可以查看协议字段、状态、风险、审批、执行批次、路由理由和产物校验。
2. 自动执行、QClaw 收件箱和人工导入结果共用同一状态链，并统一进入审核。
3. 每日行动建议的空白模板不会被视为已发布；审核发布后写入当日本地日期和 `published` 状态。
4. 指定 Agent 不可用时不会丢失任务上下文，而是自动降级到下一可用适配器，最终导出人工任务包。
