# Windows 统一发布第一阶段：开发与候选验收

日期：2026-10-11。状态：本地实现与自动化验证完成，候选包供双机真机验收；不是线上正式发布。

## 1. 本阶段完成了什么

第一阶段只做“本机制作 → 指定学生发布 → 已配对学生使用 → 作答 → 反馈”，课程与卡片共用发布管理、学生范围及版本约束。没有新建商家商城，也没有改变成长模型的审核规则。

- 卡片编辑器直接“发布给学生”，发布与学生范围在同一个索引事务内保存；不再必须选择卡片包导出位置。默认当前学生，可以显式选择指定学生、年级或全部本机学生。
- 原课程管理增加“课程与卡片发布”，可筛选类型、状态、名称，发布课程、调整范围、停止新使用。机构课程和平台课程保持原有编辑器与授权边界。
- 平台版可以把平台课程草稿直接发布给学生。课程包在后台工作进程制作、完整性校验并本机归档，不要求用户选择导出位置；原离线导入、导出仍保留。
- Windows 学生端增加卡片资源、我的练习、作答与反馈。支持分类、搜索、收藏、开始练习、查看提示、文字或文件作答、反馈、修改稿和历史卡片；难度与信心选填。
- 图片卡片没有正文也可保存、重新打开、发布及预览；自定义学科、横向纸张沿用现有编辑能力，本轮已做界面回归。没有评阅依据的原版练习仅浏览、另存，不强行评分。
- 卡片原件和练习使用固定版本；停止新使用后仍保留已开始练习及历史反馈。课程首次打开固定课程入口版本，后续新学生使用新版本。
- 新接口以已认证学生会话确定学生，不接受客户端切换到其他学生；学生接口不提供发布、教师确认等管理动作。答案与量规不会随普通题目详情提前返回。

课程是现有外部网站课程入口，不是内置章节课程。版本固定涵盖课程名称、网址、允许域名、封面等入口数据，不能冻结外部网站的实际内容。硬删除、到期、权限撤销及提供方网站下线不保证旧入口还能继续打开；本机发布记录仍保留。

## 2. 如何使用

### 发布卡片

1. 主机选择学生，进入“学情与学习 → 学习卡片 → 卡片资源 → 卡片管理”。
2. 选择“机构卡片”或“平台卡片”，新建或编辑草稿。
3. 填写题目、答案或量规；也可上传 PDF/图片并选择知识讲解或空白书写。
4. 在“谁可以使用”核对学生范围，点击“发布给学生”。默认不会分享给全部学生。
5. 已配对的新版 Windows 学生端打开学习卡片，刷新后查看或开始练习。

### 发布课程与调整范围

1. 在“精选课程 → 课程管理”使用原编辑器制作机构课程或平台课程草稿。
2. 在“课程与卡片发布”选择课程，核对学生范围，再“发布当前课程版本”。
3. 平台草稿使用“发布平台课程草稿给学生 → 确认发布平台课程草稿”。
4. 已发布项目可以保存学生范围或停止新使用。原课程的全局启用、到期和许可限制继续有效；发布不绕过这些限制。

离线卡片包、课程包仍用于其他独立主机之间手动传递。本阶段的“直接可见”要求学生端已连接并配对当前主机，不等于互联网云端市场发布。不同主机不会自动同步。

## 3. 技术实现与兼容

| 位置 | 本次职责 |
|---|---|
| `electron/publication-policy.cjs` | 共用学生范围校验与匹配 |
| `electron/course-publications.cjs` | 课程发布版本、受众、学生版本绑定及幂等回执 |
| `electron/publication-center.cjs` | 课程/卡片的轻量统一管理适配层 |
| `electron/student-publications.cjs` | 学生动作白名单及安全返回字段 |
| `electron/course-publish-worker.cjs` | 平台课程包后台校验、安装与重试约束 |
| `electron/card-resources.cjs` | 直接发布、范围原子保存、停止新使用与开始操作串行化 |
| `electron/course-catalog-store.cjs` | 保留旧课程分配，新制作课程先作为待发布资源 |
| `electron/main.cjs`、`preload.cjs` | 主机异步桥与学生会话 HTTP 接口 |
| `electron/terminal-main.cjs`、`terminal-preload.cjs` | 新学生端桥及首次课程打开版本固定 |
| `src/PublicationManager.tsx`、`PublicationAudience.tsx` | 复用的发布管理与受众控件 |
| `src/StudentPublishedCards.tsx` | 学生资源、练习和反馈页面 |
| `src/PracticeResourcesPanel.tsx` | 原卡片编辑器直接发布入口 |

没有重写原课程库、许可签发、知识点跟踪或成长模型。原学生端接口保留；新学生端连接旧主机时，按能力标志回退旧练习页面。Android 客户端未在本阶段升级。

版本与恢复：

- 发布同一事务重试复用回执；同编号但不同内容拒绝。旧草稿版本拒绝发布。
- 卡片共享资源保持不可变，学生实例保存固定引用，不按学生复制资源文件。
- 平台课程包制作与本机安装复用原完整性校验机制，完整性不等于官方身份认证。
- 发布中断后刷新列表确认已生效部分，保留的草稿可重新发布；平台多草稿发布不是跨目录数据库事务，不宣称任意中断时整批全有或全无。未完成范围发布的新课程保持不可见。
- 卡片列表、反馈列表按 20 条分页；文件预览按需加载；打开或刷新不调用模型。
- 学生提交只有收到主机回执才显示已保存。新卡片页面连接失败会保留当前页面输入供重试，但关闭程序前尚未送达的输入未新增持久离线队列，务必先另存原件。

## 5. 候选包与正式发布边界

主机沿用当前开发基线 0.21.1；Windows 学生端沿用独立基线 0.18.6。两者均以 `publication-stage1-20261011` 标识候选，不冒充新的稳定版本。

- 主机目录：`release/windows/candidates/publication-stage1-20261011/`，包含 EXE、ZIP、构建审计报告。
- 学生端目录：`release/windows-terminal/candidates/publication-stage1-20261011/`，包含 EXE、ZIP、构建审计报告。
- ZIP 内是对应便携 EXE；SHA-256 以同目录 `*-build-audit.json` 和本次交付校验文件为准。
- EXE 为未签名候选，Windows 可能提示未知发布者；没有宣称商业代码签名。
- 没有更新网站/阿里云，没有 Git 提交或推送，没有改变正式下载清单。
- 仓库原有大量未提交修改；本候选在该工作区基线上构建，不是隔离于其他在研变更的纯单功能正式发布。

本任务开始前的源码备份：`.codex_tmp/publication-stage1-baseline-20261011/`，保留以便对照本次变更；它不包含真实业务数据备份。

## 6. 真机放行清单

- [ ] 先关闭旧程序并备份真实主机数据目录，特别是 `course-catalog`、`card-resources` 和学生目录下的 `practice-cards`；实际路径以本机目录设置为准，不要只备份源码。
- [ ] 同一家庭/机构的两台 Windows 设备配对，验证课程与卡片发布后刷新可见。
- [ ] 当前学生、另一学生、指定年级、未分配学生分别核验；切换身份后不残留上一学生资料。
- [ ] 用实际图片、PDF、DOCX 作答，检查本地 OCR 或已授权 Agent；模糊件保留并给出可操作提示，不伪造反馈。
- [ ] 断网、回执丢失、重启后核对提交记录；确认没有错误显示“已保存”或重复计数。
- [ ] 发布新版本及停止新使用，核对已开始卡片、原件和历史作答仍引用旧版。
- [ ] 真实打印机、PDF 输出、字体与横竖纸张人工验收。
- [ ] 在四核/8 GB/SSD 机器上执行性能验收。

降级须退出程序后恢复与旧版本匹配的业务备份，先另存新作答和原件；不要让旧版忽略新分配规则后继续面向学生提供服务。

阶段二仍未实施：云端资源目录、跨主机自动同步、商家产品/服务目录、订单支付、预约与履约。第一阶段保留轻量 `kind` 适配层作为后续扩展点，不先引入通用可执行插件或复杂商城框架。
