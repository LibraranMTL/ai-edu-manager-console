# AI教育管家 Android 单机版：Windows 0.19.3 架构对齐完整开发计划（修订版）

日期：2026-10-01

状态：实施中。已完成 P0 数据安全/模型基础、任务 Room 迁移与 P1 部分资料体验及任务中心基础，并提前接入新增业务数据库备份恢复；全阶段、真机及正式发布验收尚未完成。逐项进度见[开发执行记录](Android单机版-架构对齐开发执行记录-2026-10-01.md)及[2026-10-02 续批记录](Android单机版-Room任务中心与恢复开发记录-2026-10-02.md)。

Windows 参考基线：本地候选 `0.19.3 / 243`

Android 源码基线：`1.2.8 / versionCode 32`

目标产品：主要由一个家庭在一台 Android 手机或平板上长期使用的 Android 单机版

本文件逐项修订此前讨论形成的 Android 单机版计划，并吸收以下评估结论：

1. 先完成“保存资料—自动整理—统一查找—形成可追溯结果”的核心闭环，再扩展低频规划功能。
2. 普通用户不逐份确认明确分类，不反复配置模型、目录和后台任务；系统只在冲突、低置信度和高风险动作时请求处理。
3. Qwen3.6-Flash 一类支持文本、图片、结构化输出、Function Calling 和联网搜索的 API 可作为首版主力 AI 引擎；录音转写另接 ASR。
4. 模型负责理解与生成，Android 代码负责身份、授权、文件、队列、版本、检索、计算、幂等和恢复。
5. 高频任务、上传回执和作答记录使用事务性存储；SAF 保存用户文件；少量配置继续使用受控私有文件和原子写入。
6. 正式版不在 APK 中放产品共享长期 API Key；开发阶段允许开发者自带 Key，试点和正式交付通过受控网关获得短时凭据和额度。
7. 真机测试仍放在全部阶段源码、自动化和候选构建完成后统一执行；在真机证据完成前只称源码候选或构建候选。

旧文件《Android家庭版-视觉优先全自动闭环开发计划-2026-09-24.md》继续作为视觉、自动证据和报告投影的历史设计依据。本文件作为 Windows 0.19.3 功能对齐、实施顺序和产品取舍的当前执行计划；发生冲突时以本文件为准。

## 1. 产品定位与首要成果

Android 单机版的定位为：

> 家庭随身教育资料与成长管家：随手保存学习与项目资料，自动整理并形成可追溯的学习、项目和成长记录，再依据这些记录给出下一步行动。

核心价值链固定为：

`资料采集 → 统一归档 → 自动整理 → 知识与证据提炼 → 学情/项目复盘 → 学习卡片或行动建议 → 新资料和反馈继续沉淀`

第一优先级不是扩大 AI 工具数量，而是让用户能够确认以下四件事：

- 新资料已经保存，原件位置清楚；
- 系统完成了哪些整理和分析，哪些还在处理；
- 任何摘要、学情或建议都能回到资料来源；
- 资料增长后仍能搜索、浏览、复用和安全迁移。

规划、比赛、择校、专业和职业研究属于有价值的增值能力，但只有在资料闭环、学生档案、联网来源和任务恢复稳定之后进入正式交付。

## 2. 原计划逐项修改

| 原计划内容 | 修订后的处理 | 修改原因 |
| --- | --- | --- |
| Android 直接展示与 Windows 相同的八个一级入口 | 八个业务域保持一致；手机默认“首页、资料、学习、项目＋全部功能”，平板大屏可展示完整导航，用户可固定常用入口 | 保持信息架构一致，同时降低移动端认知和点击成本 |
| P1 同时改完整导航、档案和所有任务基础 | P1 聚焦当前学生、渐进式档案、资料闭环、搜索与分类体验；高级能力按使用场景逐步出现 | 缩短首次获得价值的时间 |
| 项目资料模块主要做导航接入 | 增加“人工分类优先、明确目录免确认、AI 仅处理未分类/冲突项、批量撤销”的规则 | 解决已放入正确工作空间仍显示“待分类”的真实问题 |
| 所有新增任务、收藏和回执都可使用 AtomicFile | 高频任务、作答、收藏、上传回执使用 Room 事务；SAF 保存文件；AtomicFile 只处理少量清单与配置；跨存储修改使用操作日志 | 单文件原子写入不能保证文件、索引和任务状态共同成功 |
| 现有学生索引读取失败时继续兼容 | 区分“首次使用、文件不存在、索引损坏、读取失败”；损坏时只读恢复，禁止按空列表覆盖写回 | 防止索引异常导致已有学生被清空 |
| AgentAdapter 作为笼统的模型入口 | 增加明确的 ModelProvider、StructuredGeneration、VisionUnderstanding、WebResearch、UsageReceipt、Cancellation 能力合同 | 模型名称和安装状态不能证明实际能力可用 |
| 联网研究服务暂未确定 | 首版优先验证阿里云百炼 Qwen3.6-Flash 类 API；固定测试快照，保留可替换供应商接口 | 官方能力覆盖文本、图像、结构化输出、工具调用和联网搜索，能较快形成可验收实现 |
| Android 本机直接保存产品 API Key | 开发人员可使用自带 Key；试点/正式版经轻量网关获得短时凭据、学生范围、额度和用量回执 | 防止共享长期密钥被提取和滥用 |
| 一个模型承担全部输入类型 | Qwen 类多模态模型承担文本、图片及研究；音频先由独立 ASR 转写，转写文本再进入模型 | Qwen3.6-Flash 官方输入模态不包含音频 |
| 完整规划与比赛推荐在 P2 进入 | 移到 P4；P2 先完成收集箱、资料处理和云端回执，P3 完成学习卡片与项目选题 | 优先高频、容易验证、与产品定位一致的价值 |
| 学习卡片只从正式学情证据生成 | 增加“根据选定资料练习”和“根据近期学习情况练习”两种入口 | 新用户没有历史报告时也能立即体验，又不会凭单份资料推断弱项 |
| 学习卡片主要依赖第二个 Agent 复核 | 确定性校验优先；Agent 复核用于语言、范围和来源一致性，不能单独证明答案正确 | 减少额外成本并提高可解释性 |
| 收集、分类、知识采用可能分别确认 | 明确目录和人工分类直接生效；普通分析按一次范围授权自动进行；只有冲突、低置信度、正式贡献证据等例外需要确认 | 避免连续确认造成操作疲劳 |
| 统一收件箱主要汇总入口 | 增加内容指纹、来源事件、原件引用、重复接收、回收恢复和向资料库投递的状态机 | 收件箱必须成为可靠入口，而不只是列表 |
| WorkManager 每日任务按设置时间运行 | 表述为“每日自动检查，条件允许时执行”；应用启动补查，并保留手动立即处理 | Android 周期任务受省电、休眠和约束影响，不能承诺精确整点 |
| 云端报告主要看上传是否成功 | 增加远端修订回执、未知结果核对、撤回不复活、版本/学生重新校验和“其他文档”摘要 | 避免重复上传和跨版本覆盖 |
| 八个业务域全部作为首轮市场卖点 | 对外先突出资料整理、可追溯报告和项目成果；学习卡片提升使用频率，规划研究作为增值服务 | 形成清晰差异化，控制模型与维护成本 |
| 只以功能完成作为开发成功 | 增加首次导入完成率、找回资料耗时、自动分类改回率、建议执行率、四周留存和付费意愿 | 证明用户和市场价值，而不只证明代码存在 |

## 3. 产品范围和移动端信息架构

八个业务域继续与 Windows 保持语义一致：

1. 首页；
2. 收集与整理；
3. 学情与学习；
4. 项目与成果；
5. 规划与指导；
6. 知识与协作；
7. 精选课程；
8. 系统设置。

移动端按设备宽度呈现：

- 手机默认显示“首页、资料、学习、项目”四个核心入口和“全部功能”；
- 平板竖屏使用底部导航加全部功能，横屏或大屏使用侧边导航；
- 规划、课程、协作和设置不删除，进入全部功能并可固定到首页；
- 原有 `教育档案、资料收集与处理、课程中心、AI助手问答、成长模型、学情报告、学习项目` 等入口保留迁移映射和深链兼容；
- 当前学生在所有业务域持续可见；学生切换后清除旧预览和未保存表单，正在运行的任务继续绑定启动时的学生。

首页只突出用户真正需要处理的事项：

- 最近保存的资料及其位置；
- 正在处理、等待联网和需要用户处理的任务；
- 当前项目的风险或待整理资料；
- 最新可追溯报告、学习卡片或规划更新；
- 搜索全部资料的入口。

模型、请求 ID、用量和重试详情只在任务详情或高级诊断中显示。

## 4. 技术架构

### 4.1 总体责任边界

```text
文件选择/拍照/分享/录音/对话
             ↓
当前学生与来源范围校验
             ↓
SAF 保存原件 + Room 登记资料和任务
             ↓
文本抽取/OCR/ASR/多模态理解
             ↓
结构化结果校验 + 来源定位 + 内容指纹
             ↓
分类/摘要/知识/证据候选/学习卡片/建议
             ↓
本机版本、检索、报告、导出或经授权云端分享
```

模型不能直接移动文件、修改学生档案、创建项目、发布正式贡献证据或改写历史版本。模型返回建议和结构化结果，Android 代码完成授权检查、字段验证、幂等写入和可撤销操作。

### 4.2 存储分工

| 数据 | 权威位置 | 规则 |
| --- | --- | --- |
| 用户原始资料、项目工作空间、报告和导出文件 | 用户授权的 SAF 目录 | 保持用户可见；安全临时写入、备份、重命名失败关闭 |
| 学生基本索引、少量兼容清单和静态配置 | App 私有受控文件 | 原子写入；读取失败不降级为空列表 |
| 资料登记、任务、收藏、作答、模型调用和上传回执 | Room | 使用事务、唯一约束和状态迁移；支持分页和恢复 |
| API Key、刷新令牌和设备私钥 | Android Keystore | 不显示明文，不写日志，不进入普通备份 |
| 搜索和分类索引 | 可重建索引 | 不能作为原件存在的唯一证明 |

SAF 与 Room 的联合操作采用操作日志：先记录意图，写入文件并校验哈希，再提交数据库状态；进程终止后根据日志继续或回滚。每个学生的资料写入串行化，不同学生可在设备资源允许时有限并行。

### 4.3 模型服务架构

首版只接一个正式主力提供方，建议以阿里云百炼兼容接口完成 P0 试验。供应商层定义以下能力：

- `textGeneration`：摘要、知识提炼和报告语言生成；
- `visionUnderstanding`：图片、扫描页和截图理解；
- `structuredGeneration`：严格 JSON Schema 输出；
- `webResearch`：开启搜索并返回来源列表、URL 和检索信息；
- `functionCalling`：只允许调用应用声明的只读或受控工具；
- `usageReceipt`：输入/输出 Token、搜索次数、模型、区域、请求 ID、耗时和结果状态；
- `cancellation`：用户取消、配置变化或学生切换后废弃迟到结果。

P0 可使用 `qwen3.6-flash-2026-04-16` 快照做可复验基线；正式上线前允许评估更新型号，但必须使用同一组样本重跑，不能只修改模型名称。模型 ID、区域、思考模式、提示版本和 Schema 版本全部写入回执。

调用策略：

- 分类、标签、短摘要默认非思考模式、低温度、短输出；
- 项目选题、学习卡片和报告使用受限输出预算；
- 规划与比赛研究才允许联网搜索和较高预算；
- 长资料先本机解析、分段和去重，再只发送相关片段；
- 相同学生、内容指纹、提示版本、模型版本和任务类型复用已验证结果；
- 每项任务有超时、最大重试、月度额度和明确的“待联网/额度不足/需要处理”状态。

开发阶段允许装机人员自带 API Key 直连，以验证模型能力。家庭试点和正式版采用轻量网关：Android 用设备和许可证换取短时调用凭据；网关校验设备、学生范围、功能额度和并发，不持久保存原图、全文或完整提示词，只保存必要的用量和错误回执。界面明确说明选定内容会发送到模型服务处理。

### 4.4 录音转写

音频处理使用独立 ASR 能力，不把 Qwen3.6-Flash 当作音频模型。流程为：

`本机录音原件 → 明确云端处理授权 → ASR 转写 → 待校核文本副本 → Qwen 提炼/分类`

连接测试不上传录音；转写结果保留引擎、模型、原录音哈希、时间和 `machine_observed/pending_review` 状态。转写文本不自动成为学生能力或成长证据。

## 5. 核心数据合同

### 5.1 学生档案 V2

在现有学生记录上增加：出生日期、人工年龄段、当前地区、意向地区/国家、规划路径、目标阶段、兴趣、优势学科、职业方向和规划偏好。

- 有出生日期时动态计算年龄；
- 没有出生日期时使用人工年龄段；
- 不从年级推断精确年龄；
- 旧字段缺失时按空值读取，不自动制造资料；
- 只有进入相关功能时才提示补充必要信息；
- 保存前记录 Schema 版本，迁移可回退。

### 5.2 资料与分类

每份资料至少记录 `studentId、materialId、sourceId、sourceChannel、sourceUri、sourceSha256、eventTime、receivedAt、workspaceCategoryId、classificationSource、classificationStatus、digestStatus、version`。

分类状态固定为：

- `user_classified`：用户放入明确目录或主动选择，直接采用；
- `rule_classified`：命中用户已授权的确定性规则；
- `ai_classified`：模型建议通过类别和置信度校验后自动采用；
- `needs_review`：类别冲突、低置信度或不存在；
- `unclassified`：尚未处理；
- `superseded`：被新版分类或迁移替代，保留历史。

人工分类优先于规则和模型。系统不能因为尚未消化、尚未成为知识或尚未成为贡献证据，就重新显示为“待分类”。分类、知识采用和正式贡献证据是三个独立状态。

### 5.3 任务与模型回执

任务记录包含学生、输入指纹、任务类型、阶段、依赖、配置版本、重试次数、取消标记、检查点和最终结果引用。状态至少包括 `queued、running、waiting_network、waiting_quota、needs_user、succeeded、failed、cancelled、superseded`。

模型回执记录模型和供应商返回的实际用量，不用本机估算替代正式账单。请求超时但服务端状态未知时标记为 `unknown`，先查询或依赖幂等键核对，不直接重复提交。

### 5.4 规划、收藏与学习卡片

- 选题、规划和比赛结果使用不可变版本；
- 收藏保留候选 ID、版本 ID、当时依据、来源和保存时间，独立于研究存储；
- 从选题建议采用只生成幂等项目草稿，不自动创建项目；
- 学习卡片包含计划、卡片、作答、模板和证据快照；
- 作答记录进入 `pending_review`，不直接写成掌握结论。

## 6. 功能模块实施要求

### 6.1 收集与整理

统一文件、拍照、屏幕、录音、Android 分享、对话和课程采集的登记合同。资料先绑定准确学生，再写入原件或登记已有原件引用。

- 相同来源事件重复到达时幂等；
- 相同内容从不同来源进入时保留来源记录，复用模型处理结果；
- 已在工作空间中的文件登记其实际目录类别，不复制原件；
- 支持批量分类、批量采用建议、批量撤销最近一次自动整理；
- 回收只改变登记状态，默认不删除原件；
- 异常项显示原因和用户可采取的动作。

### 6.2 统一资料浏览和搜索

首轮必须提供跨原件、摘要、知识、项目、报告和收藏的统一搜索，并能从任何结果返回原件或来源位置。搜索结果显示学生、资料类型、项目、工作空间分类、处理状态和更新时间。

资料浏览提供至少三种视角：

- 按工作空间类别；
- 按来源和时间；
- 按知识主题及其来源。

项目资料继续保留“资料、待整理、知识、贡献证据”四视图；已有 1.2.7 的 SAF 权威目录、固定版本消化队列、重定位、迁移回滚和项目包交换作为复用基础，不重写。

### 6.3 学情、知识与报告

模型生成的页面观察、摘要和知识条目必须带资料 ID、页码或片段、原件哈希和处理版本。没有来源定位的结果只能作为草稿或失败结果。

家庭自动流程使用 `machine_observed/insufficient`，不伪装成人工 `confirmed`。报告可以自动生成和发布描述性事实；掌握、退步、遗忘等纵向结论需要代码确认存在同知识点、时间、提示程度和结果可比较的样本。单次或提示后成功不等于掌握，无复测不等于遗忘。

### 6.4 学习卡片

提供两种入口：

1. “根据这份资料练习”：用户选择资料、主题、难度和数量，卡片只陈述来源，不推断弱项；
2. “针对近期学习情况练习”：根据已发布报告和已确认的学习证据推荐，并显示推荐原因和证据时间。

答案、格式、题目数量和来源完整性由代码先校验；Agent 复核语言、范围和引用。支持文本、图片、PDF、DOCX、TXT 和 Markdown 作答，限制文件类型、魔数和大小。分享和打印输出不含答案、作答历史或内部证据载荷。

手动闭环稳定后再启用“证据更新、每日检查、用户手动”三种触发。三种触发进入同一幂等任务，同一学生同一天不生成内容等价的重复卡片。

### 6.5 选题建议与项目草稿

建议输入使用学生兴趣、优势、职业方向、目标、相关项目和已确认成长信号的去标识快照。结果包含主题、问题、学科方法、可执行步骤、所需资源、风险、学生依据和证据版本。

支持版本、筛选、比较、收藏、忽略和准备项目草稿。学生资料或证据无实质变化时不新增版本。草稿生成后仍由用户在原项目创建流程中确认项目名称、参与学生、目录和模板。

### 6.6 规划与比赛研究

该模块在 P4 开发，建立在 `webResearch` 能力通过 P0/P3 样本闸门之后。研究先获取公开来源，再结合去标识学生档案生成适配建议。

- 每个来源必须有真实 HTTP(S) URL、标题、抓取/检索时间和支持的字段；
- 比赛资格、届别、报名截止、费用和安全风险分别记录；
- 学校、专业、职业和升学路径分别生成决策字段，不能复制同一段通用内容；
- 缺少官方来源或时效核验时标为待核验；
- 失败、取消、超时和资料变化不覆盖上一有效版本；
- 收藏过期项目继续保留并显示已过期；
- 不自动报名、申请学校或修改学生档案。

### 6.7 云端报告与其他文档

默认正式服务地址为 `https://www.greatbg.com/edu-cloud`。旧自定义地址不静默覆盖，只有用户或装机人员明确执行迁移后切换。

- 学生授权、设备绑定、上传开关和最后回执分别显示；
- 只上传正式报告或用户预览确认的规划/选题摘要；
- 上传前重新校验学生、版本和内容哈希；
- 未知上传结果先读取远端修订清单；
- 远端已撤回版本不能由本机后台任务复活；
- 原始资料、完整学生档案、作答文件和本机路径默认不上传。

### 6.8 知识、协作、课程和 Agent 设置

AI 助手问答并入“知识与协作”。Android 使用 HTTPS 或浏览器 Intent 打开网页工具，使用显式 Intent 和白名单打开已安装 App，不支持 Windows EXE 工具，也不直接修改桌面 Obsidian 配置。

Agent 设置按真实能力显示文本、视觉、结构化输出、联网研究和音频转写。已配置模型名称不等于能力通过；每种能力有独立的无个人资料测试和最近验证时间。

## 8. 模型样本与质量闸门

P0 建立可重复测试集，至少覆盖：

- 明确类别、跨类别和无法分类的文本资料；
- 清晰照片、模糊照片、手写作业、公式、表格和多页扫描 PDF；
- 同内容重复导入、不同来源相同内容、同名不同内容；
- 两名学生的相似资料和故意错学生请求；
- 选题、学习卡片、报告摘要和无充分依据样本；
- 有官方来源、失效链接、冲突来源和没有来源的比赛/规划研究；
- 超时、限流、断网、取消、迟到结果、结构化输出不合格和额度用尽。

P0 根据样本实测冻结正式阈值。建议入场目标为：

- 明确分类样本的自动分类准确率达到 90% 以上；低于阈值的类别只建议不自动整理；
- 结构化结果经一次有限修复后合格率达到 99%，仍不合格则失败关闭；
- 100% 的正式摘要、报告事实和研究关键字段能回到本机资料或远端来源；
- 跨学生、越权路径和不存在类别的自动执行为 0；
- 同一内容和相同策略重复运行不产生重复文件、知识、卡片、版本或账单任务；
- 每个模型任务保留实际耗时、用量、重试和费用估算，P0 后再确定家庭额度。

这些阈值是开发入场建议，不是未经测试的产品承诺。手写、复杂公式和表格如达不到阈值，首版明确显示“需要人工查看”，不冒充完整识别。

## 9. 用户体验验收

1. 新用户只创建学生、选择资料目录并添加第一份资料，即可看到保存位置和处理状态；规划字段按需补充。
2. 用户把文件放入“工作日志”等明确目录后，系统直接登记该类别，不再次要求确认。
3. AI 自动整理默认只处理未分类资料；用户改过的类别保持人工优先。
4. 首页不展示技术队列，普通状态只使用“处理中、已更新、待联网、需要处理”。
5. 搜索可同时找到原件、摘要、项目、报告和收藏，并能返回准确来源。
6. 所有批量自动整理都能查看最近操作并撤销；撤销不删除原件。
7. 学习卡片在无历史报告时可以从选定资料启动；有证据时才显示个性化推荐理由。
8. 规划和比赛研究失败时继续显示上一版本及更新时间，不出现空白页或伪造内容。
9. 网络或额度不可用时，本机资料浏览、搜索、历史报告和已有卡片继续可用。

## 10. 性能、稳定性与恢复

- 列表、搜索和统计读取索引，不在每次打开页面时全量哈希原件；
- 哈希、OCR、视觉、消化和报告分别缓存，策略升级只重算受影响层；
- 长文档按页/小批处理，第 2 页失败只重试第 2 页；
- 周期任务只扫描待办和变更，不定期重扫全部资料；
- 每学生限制并发，模型请求、网络和电量约束可配置；
- 存储空间不足、SAF 授权失效和文件消失时停止受影响任务并保留恢复入口；
- 完整备份包括用户资料与必要的私有数据库快照；不包括 API Key、短时令牌和运行锁；
- 恢复后校验学生 ID、文件哈希、项目清单和数据库版本，再恢复后台任务。

发布前至少使用两台不同 Android 真机进行七天连续运行，覆盖断网、休眠、省电、进程终止、存储不足、权限撤销、API 限流、模型失败、云端未知回执和覆盖升级。

## 11. 商业模式与成本治理

产品权益按可感知成果划分：

- 本地基础授权：资料采集、整理、分类、搜索、浏览、项目资料、报告查看和导出；
- AI 服务额度：视觉理解、知识提炼、学习卡片、报告生成和 ASR；
- 增值服务：联网规划、比赛研究、云端文档和跨设备阅读；
- 高级用户：允许自带符合合同的 API Key，界面明确费用和数据处理方。

权益到期后，用户仍能读取和导出已经存在的本机资料与结果；只暂停新的付费模型调用和云端增值服务。首版不承诺无限研究、无限转写或无限视觉处理。

试点记录每户每月新增资料数、视觉页数、输入/输出 Token、搜索次数、ASR 时长、缓存命中、失败重试、云端存储和客服异常。价格在 P0/P2 真实账单后确定。

## 12. 市场验证计划

先选择一小批有持续资料整理需求的家庭进行四周试点，优先覆盖课程资料、日常作业和科创项目三种场景。核心指标为：

- 首次添加并完成整理的成功率；
- 找回一份历史资料所需时间；
- AI 自动分类被用户改回的比例；
- 用户每周新增资料和主动搜索次数；
- 报告或项目摘要被查看、导出或分享的比例；
- 学习卡片开始、完成和再次使用比例；
- 推荐行动被实际采用的比例；
- 四周留存、客服问题和付费意愿；
- 每户成功完成一次资料处理、学习卡片和联网研究的实际成本。

市场文案首先使用“资料不再散落、找得到、看得懂变化、能够继续行动”。比赛获奖、升学结果、能力提升和分数提高只能描述为可能支持的方向，不能作为保证。
