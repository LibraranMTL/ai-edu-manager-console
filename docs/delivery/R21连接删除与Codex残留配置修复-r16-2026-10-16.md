# R21 连接删除与 Codex 残留配置修复（r16 候选）

## 修复范围

本候选包含 r14 的空参数兼容、按能力声明跨学生查询参数、整体画像 MCP 分页读取和安全包体优化；另修复本次截图中的两项问题。

### 已撤销连接可删除

- “连接管理”中仅已撤销凭据显示“删除记录”，有二次确认，取消不会改变状态。
- 后台独立检查用户确认和撤销状态；活跃或停用连接不能跳过撤权直接删除。
- 删除连接记录和该连接的会话绑定；不删除学生资料、知识成果、会话原文、写入回执或其他连接。保留审计及宿主卸载记录，防止旧自动注册逻辑重新启用连接。
- 旧令牌删除后仍无法认证；重新安装生成新的连接。删除记录不等于卸载外部 Agent 的 MCP 配置，提示中明确说明。
- 宿主面板在对应凭据记录删除后明确显示需要重新安装，不再沿用“已验证”状态。

### Codex 已删 MCP 却提示冲突

本机只读检查确认：`C:/Users/bxw00/.codex/config.toml` 已不存在教育管家 MCP 表，仅剩一个 `EDU-MANAGER-KNOWLEDGE-MCP:edu-manager-knowledge:END` 注释。旧安装器要求开始/结束标记配对，因此误报同名冲突。

修复后以解析出的 MCP 服务为准。没有教育管家服务时，只清除精确匹配的遗留标记行，并比较清理前后的完整 TOML 解析值，保证没有改变其他配置。标记出现在多行字符串中、真正的同名未知服务、并列连接或损坏配置仍拒绝自动覆盖。错误附上具体配置文件路径。

“刷新外部连接”会重新检查卸载待完成的真实配置。宿主已经手动移除 MCP 时，显示“已卸载并撤权”，不继续展示过期错误，也不恢复旧权限。检查本身只读。

本机已实际清除上述孤立注释，清理前后全部解析值相等，其他 MCP 未改变，也没有重新安装教育管家 MCP。备份：`C:/Users/bxw00/.codex/config.toml.pre-r21-orphan-marker-20261016.bak`。
