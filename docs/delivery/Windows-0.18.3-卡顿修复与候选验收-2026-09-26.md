# Windows 主机 0.18.3 卡顿修复与候选验收

日期：2026-09-26。状态：本地候选已构建并启动验证；未替换用户正在运行的 0.18.2，未部署 ECS、未上传官网、未提交或推送 Git。

## 已确认的问题与修复

1. `getAgentToolInstallStatus` 同步执行注册表、应用商店和 PATH 查询。旧包 CPU profile 的主要非空闲热点是同步子进程等待。改为异步后台查询，最大并发 2、每项超时 8 秒；重复请求合并，空结果和失败也缓存，刷新失败保留旧结果。界面自动接收后台结果；未完成检测不修改默认 Agent、不作为卸载判据。
2. `readStudentMaterials`、`readStudentDigestState` 原来调用完整工作区初始化：创建 Agent 目录、读取各工具记忆、写入两个索引和工作区 metadata/pathmap。主机状态每次对 7 名学生各读取两次，造成 56 次文件写入。现改为只读，缺失状态在内存返回 idle 默认值；创建、接管及实际修改保留原有写入入口。

未通过禁用云同步、降低许可检查或删除学生资料改善性能。未盲目缓存可变的项目对象。Android 与学生端源码/版本不因本次修复递增。

## 对比测量

同一开发机，旧 0.18.2 暂存源码与新 0.18.3 暂存源码，Electron 43，分别使用隔离目录。学生 7 个、项目 10 个、资产 5000 条来自本机索引的脱敏副本；所有绝对资料路径重定向到临时目录。不复制许可、云端凭据或真实资料正文。性能脚本禁用任务执行器，非正式全负载验收。

| 测项 | 0.18.2 | 0.18.3 |
| --- | ---: | ---: |
| 冷工具检测同步调用耗时 | 1501 ms | 39 ms |
| 连续 5 次已预热主机状态查询总耗时 | 539 ms | 108 ms |
| 上述 5 次查询的文件写入次数 | 280 | 0 |

以上是单机样本，不是所有场景的耗时保证。初次基线另测到约 1695 ms 工具检测阻塞。新包真实 EXE 的 10 次已缓存工具状态查询为 0.7–3.7 ms。新测量包含额外页面操作，主线程最大事件循环延迟仍有约 321 ms，不能宣称所有卡顿已消除。

证据保存在候选目录的 `qa/baseline-performance.json`、`qa/fixed-performance.json`、`qa/report.json` 与页面截图。
