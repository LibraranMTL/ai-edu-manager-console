# Skills 自定义存档位置迁移修复

日期：2026-10-19。最终修复候选：`skills-migration-r2-20261019`。基线：上一轮 `performance-size-r1-20261019` 优化候选及当前对应源码。

## 用户现象与检查结论

用户反馈“路径没有变”。只读检查发现当前主机的 `skill-library-location.json` 仍指向默认 `skill-library`，没有迁移历史。没有修改这个真实配置或替用户指定迁移目标。

检查确认了以下代码问题，但未取得用户当时的错误提示，因此不将其中任何一个认定为此次现象的唯一原因：

- 旧实现先删除用户选择的空目录，再整体重命名替换。目录占用导致删除失败时，迁移终止且路径不变。在真实 Windows 子进程以所选文件夹为工作目录的对照实验中，旧代码返回 `EBUSY`，修复代码成功切换；另有模拟 EBUSY 回归防止复发。
- 迁移错误只显示在页面上方；存档设置位于页面较下方，用户容易只看到路径未变化。迁移按钮也没有过程状态。
- 后端成功之后若刷新列表失败，原界面会将整个操作当成失败，仍可能显示旧路径。
- 迁移只改根目录指针，没有同步改写当前安装记录中的库内备份路径，可能影响后续回滚。

## 修复内容

1. 保留所选空文件夹本身，复制到隔离暂存目录并校验，再发布库内条目；不再删除所选目录。
2. 目标位于磁盘根下一层（如 `D:\\skillbackups`）时，不再对已经存在的 `D:\\` 重复执行 `mkdir`，避免 Windows 返回 `EPERM`。
3. 新位置的设置和账本准备完毕后，最后提交位置指针；失败时继续使用旧库，并保留已产生的副本供恢复，不覆盖用户现有文件。
4. 校验普通空文件夹、绝对路径、目录包含关系和目录链接；拒绝当前库及其上下级，避免递归复制。磁盘/网络根不可访问时明确报错。
5. 所有复制文件核对哈希，存档对象复核内容树；保留旧库。当前安装记录的库内备份路径随迁移更新，历史回执不改写。
6. 迁移成功后废弃旧安装/回滚预览；扫描期间拒绝迁移。
7. 目录选择改为异步 Electron 对话框，并按有无父窗口调用正确重载。
8. 根据 React 最佳实践，将迁移逻辑保留在用户点击事件内；按钮旁显示选择、复制校验、成功、取消和错误状态。成功后立即采用返回的新路径，即使列表刷新失败也不会误报迁移失败。

目标仍要求空文件夹。若希望存放到一个已有资料的目录，请在其下新建专用空文件夹后选择；不会自动混入或覆盖已有资料。

## 使用与边界

先完全退出旧实例（包括托盘），运行新候选 EXE，再进入 Skills 管理 → Skill 存档管理 → 迁移到自定义位置，选择一个新建的空文件夹。成功后页面显示新路径；后续存档使用新库，旧库保留。

本轮没有更改用户的真实存档指针、Skill 来源、Agent 配置或学生资料。测试只在隔离夹具中迁移。未自动清理旧库或失败副本；失败后如目标已有副本，应保留并选择另一个空文件夹重试，不要直接覆盖。

Codex/WorkBuddy 安装范围、QClaw 只读及暂缓 MCP/插件安装的边界不变。上一性能优化包保留，正式更新清单仍指向 0.21.1 stable；修复包为未签名候选，并非已发布正式版。

测试中的目录选择由模拟对话框返回路径，未宣称自动操作了用户真实的 Windows 文件选择框；真实设备上的选择交互仍需用户复测。
