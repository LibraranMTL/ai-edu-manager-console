# AI教育管家 Android 家庭版：视觉优先全自动闭环开发计划

日期：2026-09-24
状态：开发计划，尚未实施或完成家庭真机验收
代码基线：`android-standalone-manager` 正式版 `1.2.5 / code 29`。家庭版主闭环在 Android；Windows 主机仅新增经授权的云端学情报告只读下载路径。普通 Android 学生端现有协议不变。

## 1. 产品目标与用户流程

面向主要使用一台 Android 平板的家庭。首次完成学生空间、资料目录和服务授权后，普通用户只需添加资料、主动开始需要系统授权的屏幕采集，或从其他应用分享对话；其余处理在后台自动完成。不设置成长证据审核、报告预览确认或手动发布步骤。

`资料进入当前学生空间 → 持久任务队列 → 视觉识别/文本抽取 → 资料消化 → 纵向知识轨迹与成长模型 → 自动生成并发布学情报告 → 有网后同步已发布报告到云端`

家庭版首页保留“添加学习资料、继续课程、教育档案”三个主要动作。资料入口包含文件、拍照、屏幕采集、智能体对话分享/粘贴；项目知识库在教育档案或当前项目下进入；服务状态只显示“处理中、已更新、待联网、需要重新提交”。学生、连接、备份和异常诊断进入“我的/设置”。

“全渠道”限定为本应用拥有或用户明确交付的内容：文件选择、拍照、课程与屏幕采集、Android 分享、粘贴、公开导出文件及未来正式合作接口。不能承诺读取第三方应用的私有对话历史。屏幕采集每次会话仍由用户完成 Android 系统授权。

## 2. 当前基线与必须补齐的断点

| 现有基础 | 断点与本次改造 |
| --- | --- |
| `FileAssetService`、`ConversationImportService`、课程/屏幕采集已能登记资料 | 统一为当前学生的入队事件、来源指纹和状态回执；保证各入口只触发一次处理 |
| `OcrVisionService` 对图片和 PDF 做本机 OCR，可选视觉模型 | 当前 PDF 仅把**第一页预览**送视觉模型；改为逐页、按预算送视觉模型，以视觉输出作为主要理解输入，OCR 作为辅助定位与降级信息 |
| `StudentDigestOrchestrator` 使用文本/OCR 结果生成知识与成长证据候选 | 消化输入改为结构化页面观察；保留页码、原文件哈希、片段与观察时间，不把模型解释当成原始事实 |
| `AutoDigestWorker` 每日处理已准备好的资料 | 新增资料入队后自动触发解析→消化；每日任务用于漏项扫描、重试和报告更新，不要求用户开启复杂开关 |
| `GrowthModelService` 只从 `confirmed` 证据生成正式报告 | 增加**家庭版自动证据策略**与报告投影，不沿用人工审核状态伪装成“已确认”；旧档案与旧报告保持可读 |
| 四类报告可在本机生成、导出 | 增加变化检测、自动发布、版本与失败回退；仅同步当前学生已发布且正文有效的报告 |
| 本机 Agent 配置支持 OpenAI 兼容接口 | 家庭版改由产品账号获得有额度限制的模型服务；技术配置放高级诊断，不让家庭用户填写共享 API Key |

### 2.2 再次评估后的执行优化

- **先证明一条纵向链路**：P0 用三页 PDF 验证逐页来源、证据及报告句子的对应关系，再扩到所有采集入口；避免采集入口全部改完才发现报告规则无法接纳机器证据。
- **分层缓存与合并账单**：视觉识别、消化和报告分别缓存，规则升级只重算受影响层；模型请求回执按家庭、学生、资料、页和请求 ID 归集，费用上限由真实样本决定。
- **把身份启动列入 P0 决策**：P2 网关需要最低限度的家庭/设备/学生授权，不能等 P5 才讨论家庭账号；试点凭据与正式监护人授权分开。
- **按失败范围恢复**：页失败只重试该页，报告组失败保持上一完整版本；用户只看到可理解的处理状态，后台保留详细错误和检查点。
- **把外部条件单列为闸门**：真实授权样本、模型试点资源、可调试 Android 真机、云端账号/域名和正式签名证书分别记录；缺少任一必需条件时继续完成不依赖它的准备，但不宣布对应阶段通过或进入下一阶段。

## 3. 技术合同

### 3.1 资料与任务

- 区分**导入记录**与**分阶段处理缓存**：每次导入有独立 `materialId/sourceId` 和来源时间，不抹去用户交付记录；视觉页缓存键使用 `studentId + sourceSha256 + pageHash + parserVersion + visionModelVersion`，消化缓存键另使用页面观察版本与 `digestPolicyVersion`，均不含随机导入 ID。同一学生重复导入相同内容复用已完成的页观察与消化结果，不再次调用模型；只改消化规则时不重做视觉识别。跨学生不得共用可识别内容的缓存或证据。策略变更时显式开新版本并有界重算。现有 SHA-1 索引保留兼容，新流程另存 SHA-256。
- 每份资料持久记录 `queued → extracting → digesting → projected → published → synced`；失败记录阶段、错误类型、重试时间和已完成页，不静默标记成功。
- 文件、照片、PDF、纯文本、Markdown、JSON/CSV、对话正文首批支持。Office 文档需先明确转换适配器和最大页数；不以“全渠道”掩盖不支持的格式。
- Android `WorkManager` 负责持久排队和受网络/电量条件约束的重试；长文档按页/小批处理，跨进程、重启、断网后从检查点继续。只增量处理新资料，不周期性重扫全部图片。

### 3.2 视觉优先处理

- 冻结 `family-page-observation.v1`：每页包含 `studentId`、`materialId`、`sourceType`、`sourceSha256`、`pageNumber/pageCount`、`pageHash`、来源事件时间与处理时间（分开记录）、视觉/OCR 模型及解析版本、`completed/partial/failed` 状态、可见文字、题目/作答/订正等**页面直接可观察信息**、页内定位/短片段、无法判定字段的 `unknown`、错误码和模型用量回执。来源事件时间缺失时不可用处理时间冒充。
- 视觉模型处理每一受支持页面；视觉观察作为消化的主要输入，本机 OCR 用于文字定位、交叉检查及视觉请求失败时的有限降级。OCR 降级不得标记为视觉完成，也不得产出需要看图才能成立的结论。整份资料只有在全部应处理页面完成后才标为完成；部分成功时只使用成功页面并显示覆盖范围，PDF 不得只凭第一页总结整份文件。
- 按源文件哈希与页哈希缓存；限制单文件页数、单页像素、每批页数、单户月用量及重试次数。超限文件保持“待处理/需要补充”，不生成假报告。
- 输出只允许描述可见内容。屏幕截图、作业照片、智能体对话分别保留来源类型；对话文本不能冒充学生独立完成的作业证据。缺失时间、学生归属、作答结果或可辨认内容时记录 `unknown`。

### 3.2.1 页面观察进入自动证据的合同

- 冻结 `family-machine-evidence.v1`：消化结果须保存 `studentId`、知识点/主题、观察类型、学生行为与提示程度（可见才填写）、`materialId + sourceSha256`、事件时间、处理版本和 `machine_observed/insufficient`。图片/PDF 的来源定位为 `pageNumber + pageHash + 页内片段/位置`；纯文本/对话的来源定位为 `segmentId + 字符范围/片段`，页码留空，且对话角色不可辨时为 `unknown`。模型给出的解释与来源直接观察分字段保存；代码校验学生归属、来源单元存在、哈希和定位后才能入账。模型不能凭叙述生成不存在的引用。
- 纵向投影按可比的同知识点样本比较，保留事件时间和导入时间、提示程度、作答结果及证据覆盖。缺任一关键条件就保留观察，推断为“资料不足”；无复测不等于遗忘，单次或提示后成功不等于稳定掌握。后到资料可重算投影，原始页面观察和证据不被静默改写。
- 旧 `confirmed` 人工证据与家庭版 `machine_observed` 并存、分别标明来源。家庭版自动流程不写入 `confirmed`，也不批量转换旧 `pending/confirmed`；迁移须可回退。

### 3.3 零审核报告策略

- 删除家庭版用户流程中的“审核待确认、确认采用、预览后发布”。这是产品交互改造；开发与发布前的质量测试仍须执行。
- 自动证据使用独立状态 `machine_observed` 和 `insufficient`；不把它写成旧协议的 `confirmed` 或“人工确认”。家庭版报告投影与 `ReportDraftPolicy` 增加独立规则：`machine_observed` 只支持有来源的描述性事实；掌握、进步、退步等纵向结论须通过确定性可比样本规则；`insufficient` 不得支持肯定结论。每条报告事实必须指向本机资料 ID、页码/片段和处理版本；报告正文标明“AI 自动生成，依据已采集资料”。
- 成长模型只存可追溯的观察与变化候选。单次正确作答、受到提示后的成功、没有复测资料，都不得自动推断稳定掌握、退步或遗忘。依据不够的章节写“资料不足/尚无可比样本”。
- 新证据到达后只更新受影响学生、知识点和报告。连续导入按安静窗口合并触发，同一证据集合、报告规则版本和报告周期形成同一修订指纹；常规自动报告每学生每天最多发布一组，明确的补录/修复任务可例外且留回执。四类报告一次生成一个不可变修订集，本机原子切换为最新已发布版本；任一报告生成或校验失败，整组不发布，继续展示上一有效版本并标明更新时间。后台执行不承诺固定整点。
- 冻结 `family-report-revision.v1`：包含准确 `studentId`、四类报告类型、报告周期、证据集合指纹、规则/模型版本、`revisionHash`、生成与发布时间、`draft/published/failed` 状态、逐项事实的本机引用及对外可展示的来源名称/时间。发布前代码核对引用属于本学生且状态允许、四份正文非空、同组版本一致；云端只接收 `published` 修订及必要来源摘要，本机原件路径和页面内容不随报告上传。
- 旧档案已有的 `confirmed` 证据和已发布报告继续可读；迁移逻辑保留原状态，不批量重标历史证据。

### 3.4 模型服务与云端报告

- 首版只选一家模型提供方，固定一个文字消化模型和一个视觉模型。先用真实样本测质量、页均费用、延迟和失败率，再锁定模型 ID、区域、输入限制及替代方案。不得在 APK 内放产品共享长期密钥。
- P0 冻结模型调用合同，P2 提供可供试点纵向闭环使用的**最小网关路径**：按家庭/设备授权，签发短时调用凭证，限制学生范围、额度、并发和重试；网关仅转发处理内容，不持久保存原图、全文或提示词。模型提供方仍会收到为处理所需的资料内容。日志只留请求 ID、用量、状态和脱敏错误。P5 再完成生产级密钥轮换、监控、告警与容量治理；P2–P4 测试账单与用量不能只依赖开发者直连密钥推算。
- “只传报告到自有云”指**云端持久保存范围**：仅已发布报告正文、版本号、学生归属、生成/同步时间与必要的来源引用标识。模型网关可能短暂传输原始内容，不能宣称原始资料从未经过网络。
- 报告发布接口使用当前家庭和学生授权，按 `studentId + reportType + revisionHash` 幂等上传；服务端拒绝跨学生写入、草稿、空报告和旧版本覆盖。云端只读展示，不在云端改写报告；撤销与删除同步到云端。
- 平板离线时本地报告照常可读；联网上传使用持久队列和退避重试。云端报告不是完整备份，本机原始资料、成长模型及知识库仍需现有加密备份/换机恢复路径。

### 3.5 Windows 主机经授权下载报告

此能力可行，属于**报告阅读扩展**，不把 Windows 主机重新变成家庭版资料处理的必备节点。Android `StudentRecord.create()` 当前生成 `student-UUID`，Windows 普通新建流程当前生成 `时间戳-姓名`；因此不能用现有普通新建按钮生成 ID 后仅按姓名关联，也不能悄悄修改已有学生 ID。

- Windows 新建学生档案增加“从家庭版云端添加”分支。家庭用户提供一次性邀请二维码/短码；Windows 向云端请求绑定，Android 家庭端或同一家庭的监护人账号显示主机名称、设备标识、学生与权限范围，由监护人一次授权。一次授权覆盖有效期内的后续报告更新，不要求每次下载确认；请求待授权时只显示等待状态并设置过期时间。不得仅凭学生 ID 或报告链接获得权限。
- 授权成功后，Windows 用云端返回的**准确 Android 学生 ID**调用专用受控建档路径，先检查本机 ID、姓名和目录冲突、许可证学生容量及重复绑定。若已有相同 ID，只有原绑定凭据一致才可继续；若同名但不同 ID，停止并要求处理冲突，不自动合并。未授权、已过期或冲突时不得创建貌似已连接的档案。
- 授权内容固定为 `report.read`、准确 `studentId`、Windows 安装/设备标识与有效期；允许监护人撤销。Windows 主动拉取最新报告清单并下载变化的正式修订，不向云端开放主机入站端口，也不要求局域网或 Tailscale。
- 下载的报告保存在当前 Windows 用户的**独立只读云端报告缓存**，以学生 ID、报告类型和修订哈希分层。现有 `学情报告/` 本机权威目录、已有正式报告和历史版本不得被云端下载覆盖；界面标记“来自 Android 家庭版”、报告生成时间、最近同步时间和过期/离线状态。一个学生同时有本机报告时并列选择来源。
- 撤销授权立即阻止新的清单/下载请求，短时下载凭证自然过期；已下载到 Windows 的本地副本不会因云端撤销而自动消失。主机提供“删除此学生的云端报告缓存与绑定”操作，产品说明这一边界。换机需重新授权，不复制旧设备的读取凭据。

### 3.6 云端最小功能与数据范围

首版只建设**私有报告文件仓库 + 很薄的授权服务**。对象存储承担报告正文与不可变修订；一个小型 HTTPS 服务保存家庭/学生/设备绑定、授权状态、报告最新修订清单和幂等回执。试点可使用单服务实例和有备份的轻量关系库；无需全文检索、在线知识库、课程商城、原始资料同步或云端报告生成。

最小接口为：`申请/确认/撤销设备绑定`、`发布报告修订`、`列出当前学生已发布报告`、`领取短时下载凭证`、`删除家庭云端报告`。服务端在每次列表与凭证签发时复核授权、学生 ID、设备与修订；对象存储保持私有，客户端只拿短时、限对象的凭证。撤销后已经签发的凭证可能在其短暂有效期内继续可用，因此有效期应尽量短并纳入验收。

管理功能只保留家庭/学生/设备绑定状态、最近同步结果、容量与用量、撤销设备、删除报告、服务异常与备份恢复。云端对象名使用不含学生姓名的不可猜测标识；服务日志不得记录报告正文、原始资料或完整提示词。服务端按家庭与学生校验每一次读写，不以客户端提供的路径作为存储位置。报告删除包含现行版本和历史修订的保留策略，并在产品中解释 Windows 已下载副本的处理边界。家庭首次开启云端报告服务时明确告知报告上传、模型服务资料处理与监护人授权范围；不满十四周岁学生信息的处理须取得监护人同意。[个人信息保护法](https://www.npc.gov.cn/WZWSREL25wYy9jMi9jMzA4MzQvMjAyMTA4L3QyMDIxMDgyMF8zMTMwODguaHRtbD9yZWY9aW1i)

云端报告只提供正文及必要来源名称/时间/标识，不承诺在云端或 Windows 展开 Android 本机原件；完整证据仍由 Android 持有。云端必须备份授权数据库和报告清单，定期核对对象与清单的一致性。试点账单按报告存储量、请求量与下载出网流量统计，不预设固定价格。[OSS 私有对象与短时下载说明](https://www.alibabacloud.com/help/en/oss/user-guide/how-to-obtain-the-url-of-a-single-object-or-the-urls-of-multiple-objects)、[OSS 计费项](https://www.alibabacloud.com/help/en/oss/billing-overview)。

## 4. 分期开发与交付物

工期为规划量级：Android 主开发 1 人，后端兼职 1 人，Windows 主机开发按阶段投入，产品/测试配合；模型供应商、账号系统和已有云资源可复用情况会影响排期。增加逐页视觉、家庭版证据投影和 Windows 授权读取后，试点总计暂按 **12–20 周**排程，P0 样本实测后再给正式工期与报价。P0–P4 是可运行的本地自动闭环及最小模型网关试点，P5/P5-W 才构成报告云同步与跨设备阅读交付。

| 阶段 | 预计 | 代码工作与交付 | 完成闸门 |
| --- | --- | --- | --- |
| P0 基线、合同与样本 | 1–2 周 | 冻结独立安卓版基线；准备经授权、去标识的照片、扫描 PDF、文本、对话、课程截图样本；锁定 `family-page-observation.v1`、`family-machine-evidence.v1`、`family-report-revision.v1` 及模型调用/用量回执合同；确定学生 ID、报告修订和授权协议；先用本机 Ollama 视觉模型做逐页视觉→证据→报告纵向小样 | 有字段/状态/错误码与示例载荷、兼容迁移图、本机逐页正确率/延迟/资源回执；一张照片和三页内容各异 PDF 均能追到正确页，缺页/模糊/重复/错学生/无事件时间有预期结果；列出真机与现有 APK 差距，通过同 ID 建档和撤销权限协议评审。商用模型费用另列为 P2 入场条件 |
| P1 统一采集队列 | 1–2 周 | 各来源统一入队；区分导入记录与内容处理缓存；学生归属、状态与断点；首页状态收简 | 重复导入保留来源记录但复用处理结果；断网、杀进程、重启不丢任务；共享设备不串学生 |

| P3 自动消化与轨迹 | 2–3 周 | 结构化页面观察进入消化；证据来源与状态校验；按事件时间和可比样本做纵向投影；旧档案兼容 | 无家庭用户审核入口；模型伪造页引用、跨学生引用均拒绝；重复处理不重复入账；单次/提示成功和缺复测不标掌握/遗忘；旧 `confirmed` 与新 `machine_observed` 均可读且互不混写 |
| P4 自动报告 | 2–3 周 | 家庭版独立报告规则、四类报告自动生成、合并触发、无依据降级、不可变修订集、原子发布与上一有效版回退 | 无确认按钮也能产出四报告；每项事实均有合法证据引用，纵向结论符合可比样本规则；同一证据集不重复生成/发布；空、超时、部分失败或跨学生内容不覆盖旧报告 |
| P5 轻量云端与 Android 发布 | 2–3 周 | 账号/设备授权、生产级模型网关密钥轮换与监控、私有报告文件仓库、修订清单、幂等上传、撤销/删除与重试 | 云端持久层只含约定的报告数据；跨学生访问拒绝；离线后能补同步且不重复；授权库/清单备份可恢复 |
| P5-W Windows 报告读取 | 1–2 周 | “从家庭版云端添加学生”、监护人授权、同 ID 受控建档、主动拉取、独立只读缓存与来源标记 | 异 ID/同名冲突拒绝；拒绝跨学生/撤销后读取；本机正式报告不被覆盖；断网展示最后同步时间 |
| P6 家庭试点与发布 | 1–2 周 | 简化 UI、升级迁移、费用实测、Android/Windows 联合真机连续运行、签名与发布材料 | 完成第 5 节验收后才生成正式包并更新下载清单 |

P0 可使用本机 Ollama 作为**开发测试模型**，不要求先取得商用 API 密钥；它在 Windows 主机运行，不能据此认定安卓家庭单机版已具备最终模型服务。进入 P2 前必须选定商用视觉模型、处理区域与试点凭据，并用真实样本测每页费用、延迟和失败率。P2–P4 使用具备授权、额度与用量回执的最小网关测试路径，不等待 P5 报告云仓库完成。P5 才开放家庭账号和生产额度。P5-W 依赖 P5 的授权、修订清单和短时下载接口，可与 P6 部分并行。每阶段形成独立代码提交、验收记录和可回退的候选包，避免直接在当前有其他未提交改动的工作树上覆盖发布文件。

**2026-09-24 闸门调整：**用户同意在本开发机 `adb devices -l` 仍为空时先开发，并再次确认推后真机测试。P0 的合同、合成样本和本机 Ollama 回执可作为 P1 开发入场证据；真机基线与经授权真实样本标为待补，不将 P0 记录为完整验收通过。各阶段可先完成桌面自动化测试并保留真机待验项，下一阶段仅开发不依赖该待验项的功能；真机补验必须在 P6 联合验收和任何 Android 对外交付前完成。涉及系统授权、长时后台任务和实际机型兼容的功能，在真机证据到位前只可标为待验。P2 商用模型、区域、凭据和成本闸门不因本次调整而放宽。

## 5. 验收样本与发布门槛

先用固定样本做阶段闸门，再做第 1–9 项联合发布验收。每个闸门保留输入样本清单、预期与实际结果、模型调用/用量回执、失败日志和对应版本；家庭用户不参与审核。

| 阶段 | 固定样本与可复验通过条件 |
| --- | --- |
| P0 合同 | 至少覆盖单张清晰照片、模糊照片、三页内容各异 PDF、重复导入、错学生、无事件时间、提示后成功、视觉失败八类样本；三份 v1 合同有字段约束、状态迁移、示例载荷及旧数据迁移规则。三页纵向小样须展示“第几页观察→哪条证据→报告哪句事实”；缺页不能出现整份资料结论。记录本机模型逐页正确率、耗时、用量和资源占用；商用 API 费用与额度在 P2 开发前实测并锁定。 |
| P2 页面 | 固定三页 PDF 的三页视觉观察各有不同页哈希、定位和回执，消化入口实际读取这些观察；模拟第 2 页失败、进程终止后续跑，仅补未完成页。重复内容在同学生同版本下不再发起模型调用；跨学生不共用证据。OCR 单独成功时保持视觉未完成/降级状态，超限页不得伪装成已处理。 |
| P3 证据与轨迹 | 用同知识点的独立作答、提示后作答、无复测、时间缺失和后到旧资料样本核对投影；单次/提示成功不显示稳定掌握，无复测不显示遗忘。伪造页码/哈希/学生归属被拒绝；重复运行无重复证据。升级样本中的旧 `pending/confirmed` 状态原样保留，家庭用户无审核或确认按钮。 |
| P4 报告 | 固定样本自动生成四类非空报告；逐项事实引用能回到本机正确学生、资料和页/片段，纵向结论只来自合格的可比样本。连续导入合并成同组修订，同证据集重跑不产生新修订；任一类型生成失败、引用非法或正文为空时四类均不切换，上一有效组可读。资料不足写明范围，云端摘要不含原件路径/全文。 |

模型超时后的服务商实际计费可能无法由本机缓存消除；验收以本系统不主动重复调用已完成页、能核对请求 ID 与用量回执、超时重试有上限为准，不作“绝不重复计费”承诺。

1. **零繁琐操作**：首次配置后，用户只执行“添加/分享资料”或法定的屏幕采集系统授权；视觉解析、消化、报告与同步无需逐项点击。
2. **资料覆盖**：使用至少 100 份授权样本，覆盖照片、作业扫描、多页 PDF、文字/表格、文本资料、对话导入与屏幕采集；每个不支持的格式都给出明确状态，不冒充完成。
3. **报告事实**：抽查至少 20 个自动报告修订，事实表述必须能定位到本机资料和页/片段；无资料、模糊页、单次提示成功、缺失复测时出现保守表述，不出现凭空的能力诊断。
4. **可靠性**：至少两台不同 Android 真机，分别执行七天连续采集与更新；覆盖断网、休眠、省电、进程终止、存储空间不足、API 限流与模型失败。恢复后已完成页不主动重复调用模型、无重复报告修订、无跨学生串档；记录受系统约束的实际完成耗时，不以固定整点作为验收条件。
5. **云端范围**：检查云端持久数据和日志，确认没有原图、全文、完整提示词；报告版本只增不乱序，设备离线后补同步，撤销授权后不能继续上传或读取。
6. **升级/换机**：从正式 `1.2.5` 覆盖升级；旧学生档案、报告、课程和备份可读。用已有加密备份/整机迁移在另一真机恢复完整本地档案，证明“云端只有报告”不会被误当作完整恢复方案。
7. **发布**：Android `check`、相关契约测试、真机验收、产品证书签名、包名/版本/证书指纹和 APK SHA-256 全部留回执；此前仅称候选版。
8. **Windows 联合验收**：一名 Android 学生经监护人授权后，在 Windows 用准确学生 ID 新建档案并下载报告；另测同名不同 ID、已有相同 ID 但不同绑定、未授权、过期、撤销、Windows 离线、报告更新和本机已有报告。所有异常均不得串学生或覆盖本机报告。
9. **云端最小运维**：检查私有对象、短时凭证、权限撤销、家庭/学生/设备隔离、报告删除与历史修订策略；演练授权库备份恢复和对象/清单不一致修复。云端管理页只显示授权、同步、容量和异常信息。

## 6. 预算与运营观察

试点记录每户每月新增页数、视觉成功页、重复页、文字消化输入/输出量、报告生成次数、模型失败重试量、云端报告容量/请求/下载流量及客服异常。模型与对象存储账单按实际供应商、模型、区域和账期计算；不在计划中写死价格。设置家庭月额度和单文件限制，达到额度时保留待处理任务并给出可理解的状态，不清除资料。

主要运营指标是“用户添加资料后无需再操作即可看到更新报告的比例与耗时”、“有依据报告比例”、“每户月模型成本”、“失败任务可恢复比例”和“七天无串档/丢档”。试点达标后再确定套餐与正式支持范围。
