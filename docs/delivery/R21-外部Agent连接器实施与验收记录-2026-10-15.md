R21 的一次授权、独立连接、固定会话范围和可靠回写基础已实现，完成合成环境、真实业务写入函数、MCP 子进程测试及 Windows 便携候选包验收。当前已生成本地候选包，但没有代码签名，也不是正式发布版本。

## 实现范围

| 方案要求 | 本次落地 | 复用的现有基础 |
|---|---|---|
| 一次授权 | read / read_memory / full 三档，准确对应 6 / 9 / 13 项；暂停、恢复、撤销；新增学生及连接继承 | 原设置页、已授权的主机 IPC |
| 高级例外 | 全局及连接的权限禁用、学生/项目排除、期限、逐次确认；只做减权 | 原授权检查及严格业务合同 |
| 独立连接 | 每连接随机凭据，存储哈希；主机私有目录单独保存凭据文件；配置中只有文件引用 | 原本机服务、限流、闭合路由白名单 |
| 会话归属 | 单学生自动绑定，多学生在设置页首次选择；显式切换产生新代次；网页选择不改变会话 | 原学生/项目记录和单学生项目边界 |
| 查询 | 当前学生与多个已授权关联项目；共享项目默认不返回；仍拒绝研究工具权限扩张 | `agent-capability-contract.cjs` 和原知识查询 |
| 自动写入 | 新连接持久授权下直接登记、自动批准并执行；高级逐篇确认时进入旧审核流程 | `agent-write-intents.cjs`、`applyAgentWriteIntent` |
| 业务落地 | 对话原文、受管资料目录/工作空间登记、任务草稿、报告草稿；明确目标不分类或静默回退 | 原对话归档、项目材料台账、上传记录、任务中心、报告草稿目录 |
| 恢复 | 幂等记录不再按 500 条截断；未完成执行保留输入；完成写入只恢复后续处理 | 原输入摘要、意图状态机和资料执行器 |
| 来源 | 保存来源事件、内容摘要、原文/派生分类和 derivedFrom；同一会话、同一事件可跨采集/导入通道去重 | 原资料原文登记及对话内容去重 |
| 处理回执 | 保存、消化任务、资料版本、知识来源与索引验证分别返回；源文件、知识文件哈希及版本重新检查 | 原消化工作流、项目知识提交台账和查询接口 |
| 升级兼容 | 首次新授权修改前备份旧授权、意图、调度文件；旧凭据不扩权；历史待审不自动放行；撤销不被重新授权复活 | 原学生级凭据、旧 MCP/API 继续受其原范围约束 |

外部连接器不受内部调度开关扩权。旧凭据额外受到新的全局减权/暂停/撤销限制；为兼容旧流程，其原调度停用检查仍保留。新的独立连接与旧内部调度开关分开。

修复了复用路径中的两个问题：并发写入完成时不能用旧台账覆盖其他操作；未知来源 Agent 归档时应使用已解析的目标学生，不能引用未定义变量。

候选打包前继续清零了一个便携版剩余问题：便携 EXE 每次启动的实际运行路径可能变化，原连接配置又同时保存了本次进程路径和本机端口。现在创建连接时会确保主机服务启动；应用重启时若存在活动连接会自动启动主机服务；监听成功后为未撤销连接刷新无密钥 `connection.json` 和 `mcp-config.json`。授权、凭据和写入台账不因此重建或扩权。

## 新增代码与设置入口

- `electron/external-agent-connector.cjs`：唯一权限目录、授权存储、连接、会话绑定、冻结范围解析与迁移备份。
- `electron/external-agent-writes.cjs`：在原写入意图上增加持久批准、并发合并、来源去重、恢复、处理回执。
- `electron/external-agent-host.cjs`：窄接口网关；业务调用重查权限，会话记忆使用已认证身份。
- `electron/external-agent-mcp.cjs`：通用 stdio MCP 桥；经本机 HTTP 调用同一网关，不是远程 HTTP MCP 服务。
- `electron/external-processing-receipt.cjs`：当前版本知识来源关联和真实查询结果核验。
- `src/ExternalAgentConnector.tsx`：独立懒加载设置面板，减少主页面耦合。复用现有 Agent 设置样式和 IPC。

入口：系统设置 → Agent 调用能力设置 → Agent连接管理 → 外部 Agent 连接器。普通用户选择一个档位并确认；会话首次涉及多学生时选择归属。高级设置默认折叠。

原“Agent连接管理”中的独立“外部写入审核”页面已删除。它的写入预览、批准/拒绝、恢复处理、处理回执和查询核验能力统一收口到“外部 Agent 连接器”的“写入记录与异常”区域；完整受控读写档位仍按全局授权自动保存，不恢复逐篇审核。原 IPC/运行时兼容接口暂时保留，避免已有调用方断裂。AI 接入与调度中心只负责教育管家调用 Agent 的内部调度，不再展示或管理外部连接器。

AI 接入与调度中心同时补充了 WorkBuddy `research.v1` 自动执行合同。它不是“查看合同内容”：用户可在 WorkBuddy 的任务合同中选择“联网研究”，并通过“验证联网研究合同”执行不含学生资料的合成检测。WorkBuddy 只开放 `WebSearch`，禁用 MCP、插件、Hook、会话持久化及额外目录；主机对搜索结果声明的每个 HTTPS 来源独立执行受控抓取，校验公开 DNS/IP、固定连接地址、逐跳重定向、HTTP 状态、内容非空及 512 KiB 容量上限，再次校验输出 Schema、CLI 哈希和授权范围。这样避开当前 WorkBuddy 2.164.0 对后台 `WebFetch` 的交互式 `PreToolUse` 审批，同时不放宽 CLI 权限，也不把仅有搜索文字的结果冒充已核验网页。取消、超时、授权变化及发送结果不明都不能转为成功或自动换用另一执行器。

已有安装中已保存的 WorkBuddy 三项合同不会被静默扩权；“联网研究”需由用户明确选择并单独验证。全新默认配置会展示四项可选合同：资料分类、资料消化、学习卡片、联网研究。该合同属于“教育管家调用 WorkBuddy”的内部执行能力，与“外部 Agent 调用教育管家”的连接器方向相反，设置入口仍归 AI 接入与调度中心。

配置文件由主机生成；R21 不自动改写 WorkBuddy/Codex 的真实配置。每个连接的本机目录含 `credential`、`connection.json` 和不含密钥的 `mcp-config.json`。不要分享整个连接目录，不要把 `credential` 提交到 Git。

## Windows 候选包

### r7：补齐登录继续闭环，修复连接超时与联网核验兼容

当前首选候选目录：`release/windows/candidates/external-agent-connector-r21-20261015-r7/`，保留 r6 原包，不覆盖用户正在运行的程序或学生资料。

- 登录闭环：显示“我已完成登录，继续”，独立轮询官方登录状态；已有后台登录时明确无需再次打开登录页，失败/超时可重新授权。继续验证成功才清除登录提示，验证失败保留提示并刷新当前状态。轮询不启动 Agent、不恢复学生任务，也不覆盖未保存的设置。
- 连接验证：真实 WorkBuddy 合成分类花费 87,422 ms，原 60 秒上限会误终止；调整为最多 180 秒，并在界面说明等待上限。Codex 同样的真实合成分类测试通过（18,472 ms）。Codex 原始通用 `agent_failed` 未再次复现，不能认定其历史失败也是超时；新增不含厂商原文/令牌的登录、网络、额度和模型错误分类提示，不放宽终态或无工具校验。
