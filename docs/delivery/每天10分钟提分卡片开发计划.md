# 每天 10 分钟提分卡片开发计划

版本：v1.2
日期：2026-08-01
对应 Demo：`prototypes/daily-practice-card-demo/index.html`

## 1. 交付目标

基于学生最近一次已发布、可追溯的学情证据，由主机端为指定学生生成一张约 10 分钟完成的针对性练习卡，并投递到该学生的 Windows 或 Android 终端。学生明确提交练习后，主机端保存练习结果和主观难度反馈，为后续练习调整提供依据。

功能闭环：

> 已发布学情证据 → 生成单一知识点练习 → 主机校验 → 定向投递 → 学生作答并提交 → 记录结果 → 调整下一张卡

本功能复用现有学生身份、学生成长、任务中心、本地 Agent、主机服务和备份机制，不另建平行账号体系或独立后台。

本版采用“三种触发、一个任务”机制：教师可手动立即生成；有效学情更新后可自动生成；每日定时只作为固定生成方式或兜底检查。三类触发统一创建同一种卡片生成任务，使用同一份来源快照、幂等规则、校验协议和投递流程，不建立三套平行实现。

## 2. 产品边界

### 2.1 必须做到

- 主机端必须先选定唯一学生，读取和写入均绑定该学生 ID。
- 生成来源仅限该学生已发布的学情报告、成长档案和已审核知识证据。
- 练习科目覆盖语文、数学、英语、物理、化学、生物、历史和地理，并支持“自动选择”；自动选择只能在存在有效学情依据的科目中决策。
- 复习范围支持今日要点、本周要点、本月要点和“根据学情报告与教育档案自动选择”，默认使用自动选择。
- 支持手动立即生成、学情更新后自动生成、每日固定时间生成或兜底检查；任何触发方式都不得绕过来源固化和内容校验。
- 每张卡只聚焦一个知识点，预计用时 5—15 分钟，默认 10 分钟。
- 每张卡保留来源、证据编号、生成时间、生成器版本和内容摘要哈希。
- 学生打开、浏览或点击选项均不等于完成；只有明确提交才记为完成。
- Windows 与 Android 学生端只显示当前登录学生获准接收的卡片。
- 网络中断时允许本地作答；恢复连接后幂等回传，不能重复记入练习。
- 没有足够证据时停止生成并给出“需要补充学情依据”，不得推测薄弱点。
- 主机端支持 PNG、JPG 图片下载与 PDF 输出，导出文件继续绑定原卡片和学生 ID，不产生新的公共副本。
- 支持标准卡与长卡片版式；长卡片高度为普通手机卡的 1.5—2 倍，首版基准取约 1.7 倍。
- 支持黑白打印模式；必须针对黑白激光、喷墨及热敏打印简化底色、阴影和低对比装饰，不能只做机械灰度转换。

### 2.2 暂不纳入首版

- 公共课程市场、教师间共享卡片和跨机构模板交易。
- 自动把一次练习结果升级为正式成长结论。
- 未经用户确认向外部大模型或图片服务发送学生数据。
- 排名、学生横向比较和以分数为导向的奖惩体系。

### 2.3 宣传合规

“提分卡片”作为内部功能名，不构成效果保证。对外页面和手册统一描述为“每日 10 分钟针对性练习”“巩固薄弱知识点”“根据已记录学情生成练习”，不使用“保证提分”“必然提高成绩”等表述。

## 3. 用户界面

### 3.1 Windows 主机端

在主导航中设置一级菜单“今日提分卡”，其下使用可折叠二级菜单：

- 练习计划：设置生成方式、星期和兜底时间、复习范围、科目轮换、目标难度、答案策略和最大待完成数。
- 自动记录：按学生查看已投递、已开始、已完成、过期和生成失败记录。
- 卡片模板：选择内置主题，或使用本地 Agent/自有图片 API 生成纯视觉素材。保留当前 Demo 已有的图片 API 设置方式，本轮不新增一级、二级菜单或额外设置入口。

练习计划中的普通设置固定为：

- 生成方式：跟随学情更新并定时兜底（推荐）、每日固定时间生成、仅手动生成；
- 复习范围：今日要点、本周要点、本月要点、根据学情报告和教育档案自动选择（推荐）；
- 科目：语文、数学、英语、物理、化学、生物、历史、地理、自动选择（推荐）。

学情更新后的合并等待时间、是否仅生成预览、失败重试等技术选项放入高级设置，不暴露在普通用户的日常流程中。

点击一级菜单“今日提分卡”进入当天卡片页面；点击折叠箭头展开或收起三个二级菜单。主机端顶部必须持续显示当前学生姓名和学生 ID；切换学生后，清空前一学生的卡片预览、练习计划、自动记录筛选和未保存草稿。

今日提分卡不是公共内容。创建卡片前必须锁定唯一 `studentId`，生成依据、卡片、投递任务和练习结果沿用同一个学生 ID。审核通过后只推送到该学生的学生端，禁止广播给同一家庭、同一机构或同一项目中的其他学生。

今日卡片工作区增加统一的“输出设置”：

- 版式：标准 4:3、手机竖版、长卡片、A4 PDF。
- 色彩：彩色、黑白打印；黑白模式使用独立渲染规则，预览结果必须与导出结果一致。
- 下载：PNG 高清图片、JPG 通用图片、PDF 打印文件。图片文件名包含卡片 ID 和学生 ID，避免多学生文件混淆。

今日卡片工作区持续提供“立即生成今日卡片”主按钮；资料消化成功反馈中提供“根据本次学情生成今日卡片”快捷动作。两处都创建同一种标准任务。默认动作为生成、校验并投递；“仅生成预览”放入高级操作，不增加普通用户的必经步骤。

### 3.2 学生端

- 首页任务区显示“今日 10 分钟练习”，同时标明科目、主题和预计用时。
- 学生端只接收 `card.studentId` 与当前登录学生完全一致的卡片；不一致时拒绝下载和展示。
- 支持 4:3 平板布局、Android 竖屏自适应布局及长卡片查看；长卡片内容按自然高度滚动，不拉伸图片制造留白。
- 图片容器随内容高度收缩，不设置占据剩余屏幕的固定最小高度，避免图片下方大面积留白。
- 作答后显示由计划决定的即时反馈；完整答案可设置为提交后或家长端查看。
- 最后一步由学生点击“提交练习”，再选择“太简单 / 正合适 / 有点难”和信心程度。
- 离线状态明确显示“已保存在本机，联网后同步”。

### 3.3 家长查看

家长端只展示结果摘要、学生反馈、练习依据和建议，不开放修改原始答案。未提交的练习只显示“未完成”，不能以停留时长推断已掌握。

## 4. 数据合同 v1

### 4.1 PracticePlan

| 字段 | 说明 |
| --- | --- |
| `planId` | 计划唯一 ID |
| `studentId` | 精确学生 ID，不允许为空 |
| `enabled` | 是否启用自动生成 |
| `triggerPolicy` | `manual_only`、`scheduled` 或 `evidence_updated_with_schedule_fallback` |
| `weekdays` / `localTime` | 本地星期与固定生成或兜底检查时间 |
| `evidencePolicy` | `today`、`week`、`month` 或 `auto` |
| `subjects` | 语文、数学、英语、物理、化学、生物、历史、地理的优先级及轮换规则；可使用 `auto` |
| `difficultyTarget` | 1—5 级目标难度 |
| `deliveryFormats` | 电子卡、PNG、JPG、PDF |
| `layoutProfile` | `standard_4_3`、`mobile_9_16`、`long_card`、`a4_landscape` |
| `colorMode` | `color` 或 `monochrome`；热敏打印沿用 `monochrome` 规则 |
| `answerPolicy` | 即时反馈或提交后显示 |
| `maxPending` | 未完成卡上限，默认 3 |
| `revision` | 计划修订号，用于幂等计算 |
| `autoDeliver` | 校验通过后是否自动投递；默认开启 |
| `evidenceUpdateDebounceMinutes` | 连续学情更新合并等待时间，默认 10 分钟 |
| `updatedAt` | 最近更新时间 |

### 4.2 PracticeCard

| 字段 | 说明 |
| --- | --- |
| `cardId` / `studentId` | 卡片和所属学生 |
| `triggerOccurrenceId` | 本次手动、学情更新或定时触发 ID |
| `triggerType` | `manual`、`evidence_updated` 或 `scheduled` |
| `subject` / `skillCode` | 科目与唯一目标知识点 |
| `estimatedMinutes` | 预计完成分钟数 |
| `content` | 题干、选项、提示、步骤等结构化内容 |
| `answerKey` | 与学生初始载荷分离保存的答案与解析 |
| `sourceSnapshot` | 来源 URI、版本、发布时间、摘要哈希、证据 ID、复习范围和证据指纹 |
| `templateId` | 视觉模板 ID |
| `renderProfile` | 版式、目标像素、DPI、色彩模式和答案页策略 |
| `generator` | Agent、模型和提示词模板版本 |
| `status` | 草稿、已审核、已投递、已完成、过期或失败 |
| `createdAt` / `deliveredAt` | 创建和投递时间 |

### 4.3 PracticeAttempt

| 字段 | 说明 |
| --- | --- |
| `attemptId` / `cardId` / `studentId` | 唯一作答及归属关系 |
| `startedAt` / `submittedAt` | 开始和明确提交时间 |
| `answers` | 学生答案及必要的题目版本号 |
| `durationSeconds` | 练习时长，仅作辅助信息 |
| `perceivedDifficulty` | 太简单、正合适、有点难 |
| `confidence` | 学生自评信心 |
| `syncState` | 本地待同步、已同步、冲突待处理 |
| `evidenceCandidateId` | 可审核的证据候选 ID，不自动成为正式结论 |

### 4.4 PracticeTemplate

模板只保存版式、颜色、字体、装饰素材和视觉提示词。模板生成请求不得包含学生姓名、学情、题目答案或档案正文。

## 5. 技术设计

### 5.1 主机端

- 在 Electron 主进程增加每日练习领域模块，负责计划、卡片、尝试记录、幂等键和审计事件。
- 通过 preload 暴露最小 IPC：读取状态、生成草稿、保存计划、审核投递、查询历史、导出 PNG/JPG/PDF、管理模板。
- 使用现有原子 JSON/持久化约定保存控制数据；卡片正文、PDF 和素材写入对应学生工作区。
- 任务中心只保存调度和执行状态，不在任务文本中复制学生隐私正文。
- 备份清单纳入练习计划、卡片元数据、自动记录和本地模板；外部 API 密钥不进入备份。

### 5.2 生成与校验

生成流程分为六步：

1. 解析并锁定唯一学生和允许的项目范围，生成不可为空的 `studentId`。
2. 按计划的复习范围读取最新的已发布报告、教育档案、成长档案、已审核知识证据和该学生既往练习反馈。
3. 固化来源快照，生成内容 JSON。
4. 执行 JSON Schema、时长、题量、答案一致性、来源完整性和安全词校验。
5. 生成桌面、Android、长卡片和打印输出共用的规范化卡片模型，并按 `renderProfile` 派生各目标尺寸。
6. 创建绑定相同 `studentId` 的定向投递任务；低风险日常卡片通过全部自动校验后可直接投递，只有依据不足、范围冲突、超纲或结果不合法时进入异常提示，不增加逐卡人工审核。

同一 `studentId + localDate + evidenceFingerprint + planRevision` 只允许产生一个有效卡片。重试、三种触发相遇或程序重启都必须复用幂等键，不生成重复任务。

### 5.3 三种触发、一个任务

三种触发统一创建 `practice_card.generate.v1` 任务：

1. **手动立即生成**：教师可从今日卡片页面直接生成，也可在资料消化成功后点击“根据本次学情生成今日卡片”。
2. **学情更新触发**：只有消化回执校验通过、知识写入和索引完成，并形成新的有效证据指纹后才触发；仅扫描目录、重复回执和无新增资料不得触发。
3. **每日定时触发或兜底**：固定时间到达时先检查当天是否已有与最新证据一致的有效卡片；已有则不重复生成，没有才生成。

普通用户只需要选择：

- 跟随学情更新，定时兜底（推荐）；
- 每日固定时间生成；
- 仅手动生成。

自动触发还必须遵循：

- 连续多批消化默认合并等待 10 分钟，只产生一次生成任务；
- 新证据与计划科目、知识点无关时不更新当前卡；
- 当前卡未开始时可生成新修订并替换；已经开始或完成时不得覆盖，只能生成下一张建议卡；
- 最多保留一张当前卡和一张下一张卡，避免任务堆积；
- Agent 暂不可用时任务保留并按统一任务中心规则重试或降级，不丢失上下文。

任务结果必须使用结构化回执，至少包含科目、唯一知识点、题目、答案、解析、预计用时、依据 URI、证据指纹以及 Agent/模型/提示词版本。教育管家校验并渲染后自动回写任务中心和卡片记录。

### 5.4 主机服务接口

建议增加经过现有学生会话认证的接口：

- `GET /api/student/practice/current`：返回当前学生可见的待完成卡片。
- `GET /api/student/practice/:cardId/content`：获取允许展示的卡片内容。
- `POST /api/student/practice/:cardId/attempt`：幂等提交答案和反馈。
- `GET /api/student/practice/history`：返回当前学生自己的精简历史。

接口必须同时验证当前会话学生、卡片所属学生和有效项目关联；任何一项不一致均拒绝返回。

### 5.5 图片、PDF 与打印

- 采用固定打印样式和内嵌字体策略，避免中文缺字和不同主机分页漂移。
- 首版支持 A4 横向一页；内容超限时阻止生成并要求缩短，而不是静默分页破坏布局。
- PNG 默认输出 2 倍预览像素的无损图片；JPG 使用白色背景和不低于 90% 的质量参数；两者均不得包含界面工具栏。
- 长卡片高度限定为对应手机卡的 1.5—2 倍，内容不足时收缩到下限，内容超限时停止导出并提示精简，禁止用大面积空白补足高度。
- 黑白模式使用专门的颜色令牌和元素降级表：取消渐变、阴影、深色背景与纯装饰图形；信息不得只依靠颜色区分，答案状态同时使用边框或纹理。
- 热敏打印至少验证 58 mm 和 80 mm 两种纸宽；正文最小可读字号、边距和断行规则单独设门槛。
- 电子卡、图片与 PDF 使用同一规范化内容模型，答案页是否输出由计划策略控制。

### 5.6 图片 API 安全

- 首选操作系统凭据库保存密钥，界面只显示掩码和“测试连接”。
- 日志、任务、学生档案、导出包和备份中不得出现密钥。
- 向图片服务发送的内容仅限去身份化视觉提示词。
- 图片生成失败时自动回退到内置模板，不能阻塞练习内容生成。
- 图片 API 保留为高级可选视觉来源，但本轮不修改 Demo 中已有的设置入口，也不把 API 配置变成练习计划的必经步骤。

## 6. 分阶段开发计划

以下工作量按一名熟悉现有代码的开发者估算，评审、真机等待和发布签名时间另计。

| 阶段 | 预计 | 主要交付 | 验收门槛 |
| --- | ---: | --- | --- |
| C0：合同与界面定稿 | 2—3 天 | 菜单位置、科目/复习范围、三种触发、状态机、数据 Schema、Demo 评审稿 | 产品边界、学生隔离、触发语义和完成定义确认 |
| C1：主机本地 MVP | 7—9 天 | 计划存储、真实证据读取、Agent 生成、校验、手动立即生成、今日卡和 PNG/JPG/PDF | 能为唯一测试学生一键生成并投递且来源可追溯 |
| C2：调度与闭环 | 8—11 天 | 学情更新触发、定时兜底、合并防抖、幂等重试、Windows/Android 投递、离线提交 | 三种触发共用一个任务且不重复，学生提交可可靠回传 |
| C3：模板与安全配置 | 5—6 天 | 内置模板、黑白降级规则、本地 Agent 主题、自有图片 API、密钥安全存储 | 外部请求不含学生数据，失败可回退，黑白输出可读 |
| C4：质量与发布 | 6—8 天 | 单元/合同/E2E/真机与打印测试、手册、网站、安装包 | 全部发布门禁通过并完成回归记录 |

总开发量：约 28—37 个开发日。

### C0：合同与界面定稿

- 以当前 Demo 为交互基线，确认“今日提分卡”一级菜单及“练习计划、自动记录、卡片模板”折叠二级菜单。
- 冻结八个科目、“自动选择”、四种复习范围及年级适配规则。
- 冻结三种触发共用的任务协议、四个数据 Schema、状态机、错误码和证据指纹幂等规则。
- 保留当前图片 API 设置入口，不新增导航或额外设置入口。
- 确认授权策略。建议：学生查看和完成不单独收费；练习计划自动执行、自定义模板和图片 API 仅专业版与机构版开放，最终以产品决策为准。
- 输出桌面 4:3、Android 竖屏、1.5—2 倍长卡片、A4 PDF、58/80 mm 热敏打印五套验收尺寸。
- 冻结 PNG/JPG/PDF 下载、彩色/黑白输出的交互与命名规则。

### C1：主机本地 MVP

- 接入当前学生选择器和学生级数据边界。

## 7. 测试与发布门禁

### 7.1 自动化测试

- Schema：缺失学生 ID、来源、答案或版本时必须失败。
- 隔离：学生 A 的会话无法查询、缓存或提交学生 B 的卡片。
- 来源：待审核、已拒绝和其他学生证据不得进入生成上下文。
- 幂等：任务重启、断网重试和重复提交均只保留一条有效结果。
- 触发合流：手动、学情更新和定时触发同时到达时只产生一张有效卡；重复消化回执和无新增资料不触发。
- 科目与范围：新增五个科目和自动选择可保存、恢复并正确限定证据；今日/周/月/自动范围不得越界读取。
- 卡片更新：未开始卡可安全换版；已开始或已完成卡不被覆盖，只产生下一张建议卡。
- 状态：打开、开始、作答、提交、同步和审核状态转换准确。
- 内容：题干与答案一致，预计时长和题量不超限。
- 安全：日志、备份、崩溃信息和学生端载荷不含图片 API 密钥。
- 导出：PNG/JPG/PDF 文件包含正确卡片与学生标识；不同格式的题目、答案和来源摘要一致。
- 版式：长卡片高度落在手机卡的 1.5—2 倍范围，内容区无异常大留白或截断。
- 黑白：彩色模板切换到黑白模式后，不依赖颜色表达答案状态，纯装饰元素正确降级。

### 7.2 真机测试

- Windows 主机：手动立即生成、学情更新后生成、定时兜底、自动投递、打印和重启恢复。
- Windows 学生端：收到唯一卡片、作答、提交、历史刷新。
- Android 竖屏：320—480 CSS 像素宽度下无横向溢出，图片下方无异常大留白。
- Android 横屏/平板：4:3 内容完整，触控目标不小于 44 CSS 像素。
- 离线场景：断网作答、重启应用、恢复网络后只同步一次。
- 打印场景：A4 横向、58 mm 与 80 mm 热敏纸、中文字体、答案页策略和二维码/链接均正确。
- 图片下载：PNG 透明度/背景策略正确，JPG 白底且压缩后文字清晰，标准卡与长卡片均可打开。

### 7.3 发布条件

只有以下条件全部满足，才可进入正式安装包：

- 学生隔离、来源追溯和幂等三项门禁全部通过。
- Windows 与 Android 真机闭环均有测试记录。
- 安装包版本、签名、SHA-256 和更新说明一致。
- 操作手册和网站已同步功能范围、版本要求与授权限制。
- 已明确记录未实现项，不把静态 Demo、源码完成或候选包等同于正式发布。
