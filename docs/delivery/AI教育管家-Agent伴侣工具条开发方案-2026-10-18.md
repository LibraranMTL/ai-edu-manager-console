## 实施状态（2026-10-19）

本轮已完成 P0 与剪贴板伴侣核心能力：

- 正式浮条使用 `54px` 收起高度、`96px` 学习展开高度和 `820px` 推荐宽度；低分辨率自动隐藏按钮文字；
- 第一行保留截屏、录音、拍照、会话和收件箱，并增加作用明确的“目标 Agent”；
- 第二行依次提供资料范围、消化、闪卡、测验、导图、学习模式、归档和 AI设置，AI设置固定在最后；
- 目标 Agent、资料范围、学习模式和更多操作使用无 Node 权限、上下文隔离的临时子窗口；
- 通用和自定义 Agent 只启用剪贴板能力；资料查询和归档只有在执行器与学生 MCP 注册均验证通过时才开放；
- 资料消化、闪卡、测验、导图及 16 种学习/模拟/核验/记录动作均生成学生固定、范围固定、带哈希且 10 分钟失效的提示词包；
- AI设置对已验证内置 Agent 复用 `buildInitSteps(...).find(id === 'full')` 的完整连接指令；通用和自定义 Agent 使用不宣称已接通的安全协作指令；
- 只复制并校验系统剪贴板，不自动粘贴、不模拟 Enter、不读取 Agent 界面或历史；
- 学生切换会清除所有尚未使用的短时提示词包，并把资料范围重置为当前 Agent 能力允许的范围；
- 原屏幕快速截屏/连续采集、拍照、录音页面、会话和收件箱入口继续复用原逻辑。

本轮明确未实现：Agent 原生预填、Windows 前台受控粘贴、自动发送、直接读取当前 Agent 对话、未确认归档写入，以及服务器/官网/正式包发布。

### 按钮与交互速查

| 控件 | 当前行为 | 降级与边界 |
| --- | --- | --- |
| 目标 Agent | 选择通用、已验证或自定义 Agent | 自定义 Agent 不获得资料查询或归档能力 |
| 截屏/录音/拍照/会话/收件箱 | 延续原采集入口 | 录音仍跳转专用页面；截屏和拍照保持现有受控流程 |
| 学习 | 展开或收起第二行 | 收起后恢复 `54px` 设计高度 |
| 资料范围 | 当前对话、学生授权资料或关联项目 | 未验证查询能力时只能选择当前对话 |
| 消化/闪卡/测验/导图 | 复制学生和范围固定的学习提示词 | 结果留在当前 Agent，不创建后台任务 |
| 学习模式 | 打开学习、模拟、核验、记录四组共 16 种模式 | 可设置难度、时长和本次目标 |
| 归档 | 仅对已验证归档能力的 Agent 开放，复制先预览后确认的归档指令 | 不把复制成功显示为归档成功 |
| AI设置 | 复制当前学生与当前目标 Agent 的连接指令 | 不自动创建 Agent、不自动发送 |
| 更多 | 本机文件导入、会话自动采集、切换学生 | 低频入口不占用常驻高度 |

## 一、重新设计结论

工具条不再定位为“教育管家主界面的缩小入口”，而定位为覆盖在 WorkBuddy、Codex 等 Agent 工作界面上的轻量学习伴侣层：

- 用户继续留在当前 Agent 对话中提问、追问和接收成果；
- 工具条负责锁定当前学生、准备学习提示词、把提示词填入或复制到 Agent 输入框；
- 普通学习操作不打开教育管家主窗口、不建立后台任务，也不把结果强制转回教育管家显示；
- 只有用户明确点击“归档成果”时，才启动受控写入，并在工具条小面板内完成目标确认和回执展示；
- 教育管家仍负责学生授权、知识范围、提示词模板和可选成果归档，但退到后台成为 Agent 的教育上下文服务。

目标体验不是复制 NotebookLM 界面，而是复用外部 Agent 的对话、模型和工具能力，为其补上学生长期资料、学情边界、学习动作和成果沉淀能力。

## 二、当前基线与可复用能力

当前快捷采集工具条已经具备独立置顶窗口、学生上下文、位置保存、收起/展开、屏幕截图、连续屏幕采集、拍照、收件箱入口和导航能力。当前常量为收起高度 `72px`、展开高度 `160px`，普通状态宽度 `520px`。

现有工程还可复用：

- 主进程剪贴板写入及写后校验；
- 按学生生成 `/消化` 指令和自定义 `digest-prompt.md`；
- WorkBuddy `workbuddy://task` 提示词预填深链；
- Codex、WorkBuddy、OpenClaw 等安装及授权状态识别；
- `query_education_knowledge` 的当前学生只读资料查询；
- `submit_education_conversation`、写入意图、主机复核和归档回执；
- 学生和项目范围校验、许可校验、幂等和审计基础。

当前没有发现可直接复用的 Windows 前台 Agent 输入框识别、可靠焦点恢复或通用自动粘贴实现。WorkBuddy已有任务深链，但它可能打开新的任务界面；Codex当前只有应用/网页打开及后台任务通道，不能据此宣称能够向当前可见对话输入框直接填词。因此“填入当前 Agent 输入框”必须作为独立技术验证，不用后台 CLI 调用冒充前台对话体验。

当前工作树存在大量其他未提交修改。本方案只新增文档和 Demo，不清理、覆盖或解释为本功能成果。

## 三、产品范围

### 3.1 本期包含

1. 缩小工具条默认高度、字体、按钮和间距。
2. 删除展开区长期说明文字，把必要说明移到工具提示和动作反馈。
3. 增加 Agent 目标状态和图标化“学习助手”展开入口。
4. 增加六个学习动作：资料消化、知识闪卡、生成测验、思维导图、归档成果、AI设置。
5. 建立版本化提示词模板、学生范围和资料范围合同。
6. 提供三档提示词交接：Agent原生预填、受控前台填入、剪贴板回退。
7. 让普通学习成果留在 Agent 对话；归档作为用户明确发起的独立动作。

### 3.2 本期不包含

- 不读取或抓取外部 Agent 的完整界面、系统提示、其他会话或历史记录；
- 不监听全局键盘输入，不记录用户在 Agent 中输入的内容；
- 不默认模拟 Enter，不自动替用户发送提示词；
- 不把后台 CLI 返回结果隐藏后再复制到 Agent 界面；
- 不把普通学习动作登记为教育管家任务中心任务；
- 不因工具条选择学生而静默改变已经包含另一学生内容的 Agent 会话；
- 不开发屏幕录像；
- 不升级 Android、云服务或官网版本。

## 四、核心用户流程

```text
用户在 WorkBuddy / Codex 中学习
            │
      工具条显示当前学生
            │
      点击一个学习动作
            │
  生成受限、可预览的提示词
            │
  ┌─────────┼─────────┐
原生预填   受控填入   复制提示词
  │           │           │
  └─────────回到 Agent 输入框─────────┘
            │
      用户检查并发送
            │
   Agent 在当前界面返回成果
            │
   继续追问 / 再生成 / 可选归档
```

工具条只把状态标为“提示词已准备”“已填入输入框”或“已复制”，不能在未收到 Agent 回执时显示“已执行”或“已生成”。

## 五、界面方案

### 5.1 收起态

推荐目标：

| 项目 | 当前值 | 目标值 |
| --- | ---: | ---: |
| 窗口高度 | 72px | 52–56px |
| 内容行高度 | 56px | 42–46px |
| 普通按钮高度 | 36px | 30–32px |
| 主文字 | 12px | 11px |
| 次文字 | 10px | 9–10px |
| 品牌标记 | 32px | 26–28px |

默认布局：

```text
[教][赵书源⌄][Codex⌄] [截屏] [录音] [拍照] [会话] [收件箱] [✦] […] [×]
```

- 窄屏时采集按钮可退化为图标，悬停和键盘焦点显示文字；
- 当前学生和 Agent 为状态信息，不做大卡片；
- 星标学习助手按钮使用主色，负责展开第二行；图标悬停、键盘焦点和首次使用时显示“学习助手”；
- “更多”继续承载本机文件导入、资料收件箱、会话自动采集等低频入口；
- “收件箱”是高频待处理入口，可在使用数据证明低频后移入“更多”；
- 宽度采用自适应策略：优先保持两行单行排列；低分辨率下把次要文字退化为图标或移入“更多”。窗口不得超过当前显示器工作区宽度的 `70%`，也不得为了保持所有文字而接近铺满屏幕。

### 5.2 学习助手展开态

展开后只增加一行：

```text
[知识闪卡] [生成测验] [思维导图] [消化资料] [归档成果] [AI设置]   [提示词已复制]
```

- 总高度目标不超过 `96px`；参考 V2 采用紧凑双行，不再设置占宽的“学习助手”文字标签；
- 删除“录音跳转……屏幕采集不是录像”等常驻说明；
- 必要限制放到按钮 `title`、首次提示和执行后的短状态；
- “提示词已复制”等反馈采用数秒后消失的状态胶囊，隐藏后释放其宽度，不作为长期说明文字；
- 展开、收起、屏幕选择和拍照预览使用明确窗口状态，不能共享一个残留固定高度；
- 用户收起“AI任务”后必须立即恢复收起高度。

### 5.3 最小交互状态

工具条底部或短暂 Toast 只显示一条结果：

- `已填入 Codex 输入框，请检查后发送`
- `Codex 输入框未通过验证，提示词已复制`
- `已复制提示词，按 Ctrl+V 粘贴`
- `学生已切换，请为新学生开启新会话`
- `归档请求已接收，等待确认`
- `成果已归档 · 查看回执`

不在浮层显示学情正文、完整提示词、Agent长回答或学生敏感资料。

## 六、学习动作设计

六个按钮不是六段固定字符串，而是六个版本化的学习动作合同。

### 6.1 资料消化

工具条中的“资料消化”采用对话模式，不直接复用后台批量消化的全部写盘行为。

默认提示 Agent：

1. 优先理解当前对话中已经提供的资料；
2. 如已连接教育管家资料工具，再查询当前学生授权范围；
3. 输出核心摘要、关键概念、相互关系、仍不确定的信息和可继续追问的问题；
4. 保留 `edu://` 或原资料引用；
5. 不自动覆盖学情报告、成长模型或学生目标；
6. 结果直接回复在当前 Agent 对话。

后台正式消化继续使用原任务中心和批次回执，不与这个按钮混为同一任务。

### 6.2 知识闪卡

名称固定为“知识闪卡”，与“每天10分钟提分卡片”区分。

默认行为：

- 基于当前资料生成适量问答闪卡；
- 每张包含问题、简短答案、解释、难度和来源；
- 支持“浏览全部”或“逐张练习”两种对话方式；
- 不把生成闪卡自动发布为正式学习卡片；
- 不从一轮回答推断学生已经掌握。

### 6.3 生成测验

优先采用交互测验，而不是一次性显示题目和全部答案：

- Agent每次只提出一道题；
- 学生回答后再给反馈、解释和下一题；
- 结束时总结本次表现、提示依赖和待复测点；
- 未经过教育管家证据确认前，不写“已掌握”“能力提升”等正式结论；
- 用户可在提示词预览中选择题量、题型和难度。

### 6.4 思维导图

默认输出两层：

1. 所有 Agent 都可显示的 Markdown 层级大纲；
2. Agent支持时附带 Mermaid `mindmap` 或 `flowchart`。

提示词必须要求关键节点带来源，资料不足的分支标记“待补充”，不为了图形完整虚构内容。

### 6.5 归档成果

“归档成果”不是返回教育管家查看结果，而是让用户在当前 Agent 对话完成后，明确要求 Agent 把选定成果提交到教育管家。

推荐流程：

```text
用户点击归档成果
→ 工具条显示学生及目标（学生资料/关联项目）
→ 生成一次性、短时有效的归档意图
→ 提示词填入当前 Agent
→ Agent提交用户指定的当前成果
→ 工具条弹出精简确认，不打开主窗口
→ 主机复核学生、目标、内容哈希和权限
→ 工具条显示成功或失败回执
→ Agent对话中的原成果继续保留
```

归档按钮不得默认解释为“归档Agent上一条全部回复”。用户需确认归档对象和目标；附件、长文、代码或图片按各自合同提交。若当前 Agent 没有归档工具，退化为复制归档说明或选择本机文件，不显示虚假成功。

### 6.6 AI设置

“AI设置”位于第二行最后、“提示词已复制”状态胶囊之前。点击后直接复制“当前学生＋工具条当前选择的Agent”的完整 Agent 连接指令，供用户粘贴到 Codex、WorkBuddy 等智能体中。

实现时必须复用现有 `buildInitSteps()` 中 `id === 'full'` 的“完整 Agent 连接指令”，不能复用 `buildToolPrompt()` 或界面现有的“完整初始化指令”。原因是完整连接指令明确假定学生知识库已经由教育管家初始化，并要求智能体不要重新创建目录、覆盖 `AGENT.md` 或移动已有资料；完整初始化指令则可能包含目录创建、写入 `AGENT.md` 和执行初始化，不适合工具条日常连接。

行为规则：

- 未选择学生时按钮禁用，并显示“请先选择学生”；
- 未选择目标Agent时按钮禁用，并显示“请先选择Agent”；
- 连接指令按当前工具条选择的Provider生成，而不是静默使用学生档案中过去选择的Agent；
- 点击即复制，不自动粘贴、不自动发送、不自动创建Agent；
- 复制前重新校验学生仍有效、Provider仍可用；
- 成功状态显示“AI设置已复制”，失败显示明确原因；
- 连接指令可能包含学生名称和本机逻辑/物理路径，因此沿用提示词预览、剪贴板哈希校验和清除机制；
- 只复制连接、角色、记忆和任务配置，不包含电话、邮箱、原始资料正文或其他学生信息；
- 重复点击只更新剪贴板，不创建任务中心任务或归档记录。

## 七、资料范围与NotebookLM式体验

工具条增加一个紧凑的资料范围状态，默认不展开：

```text
资料范围：当前对话 + 当前学生授权资料
```

可选范围：

- 仅当前对话；
- 当前学生最近资料；
- 当前学生全部授权资料；
- 当前学生的指定项目；
- 用户明确选择的文件或资料批次。

“当前对话”由 Agent 自己理解，工具条不抓屏或读取其内部消息。“学生授权资料”通过教育管家已授权工具按需查询，不把整个知识库复制进剪贴板。

为了形成类似 NotebookLM 的学习体验，所有学习提示词都应包含：

- 以资料为依据，资料外信息明确标记；
- 显示来源或引用；
- 支持连续追问；
- 不确定内容与已知事实分开；
- 主动提出下一步学习问题；
- 测验、闪卡和导图共用当前对话上下文；
- 结果优先在 Agent 当前对话展示，不强迫生成文件。

## 八、Agent识别与提示词交接

### 8.1 三档交接模式

| 模式 | 使用条件 | 用户体验 | 第一版策略 |
| --- | --- | --- | --- |
| Agent原生预填 | Agent提供正式深链、SDK或当前对话预填接口 | 点击后回到Agent，输入框已有提示词 | WorkBuddy先验证；不能假设所有版本都保持当前会话 |
| 受控前台填入 | 已识别并验证前一个前台Agent窗口及输入控件 | 工具条恢复目标窗口焦点，只粘贴、不发送 | 独立技术验证，通过稳定性和防误粘贴门槛才开放 |
| 剪贴板回退 | 任何Agent或识别失败 | 提示词已复制，用户手工粘贴 | 第一版必备且始终保留 |

### 8.2 前台填入安全规则

点击工具条会改变焦点，因此主机需在工具条获得焦点前保存最近一个合格 Agent 窗口快照：进程路径、窗口句柄、进程启动时间、签名/发布者、窗口标题摘要和输入控件指纹。

执行填入前再次核对：

- 窗口仍存在且属于同一进程实例；
- 目标在已启用的 Agent 白名单；
- 没有切换到密码框、管理员窗口、系统安全桌面或其他应用；
- 当前学生和准备提示词时一致；
- 剪贴板内容哈希仍与本次准备结果一致。

验证通过后只执行“聚焦输入框并粘贴”，绝不自动按 Enter。任一检查失败都只保留剪贴板结果并提示用户手工粘贴。

浏览器中的 Agent 标签页难以仅靠窗口标题可靠区分，第一版默认使用剪贴板；只有浏览器扩展或正式集成能确认标签页、域名和输入控件时才开放自动填入。

### 8.3 Provider能力声明

新增伴侣专用能力，不复用后台任务的“可执行”布尔值：

```text
canOpen
canPrefillNewConversation
canPrefillCurrentConversation
canForegroundPaste
canQueryEducationKnowledge
canSubmitEducationArtifact
canRenderMermaid
```

某 Agent 能运行后台 CLI，不等于它能把提示词和结果呈现在用户当前可见对话；两个能力分别探测和验收。

## 九、学生切换和会话隔离

同一个 Agent 对话可能已经包含旧学生资料。为了避免串档：

1. 工具条准备每条提示词时绑定 `studentId`、范围版本和随机 `promptId`；
2. 切换学生立即使尚未填入的提示词失效；
3. 切换学生后默认提示“为新学生开启新会话”；
4. Provider支持新会话预填时，可一键创建新对话；不支持时只复制开场提示词；
5. 不自动把同一对话从学生A改成学生B；
6. 当前 Agent 工具凭据仍限制为一个学生及其关联项目；
7. 归档时主机重新校验学生、项目和许可，不信任提示词中的名称或路径。

工具条允许内联切换学生，但普通学习动作不要求打开教育管家主窗口。新增/编辑档案仍属于低频管理操作，可以从“更多”进入主程序。

## 十、提示词注册表与数据合同

新增版本化 `CompanionActionRegistry`：

```ts
type CompanionActionDefinition = {
  id: 'digest' | 'flashcards' | 'quiz' | 'mindmap' | 'archive' | 'agent_setup'
  version: string
  title: string
  allowedScopes: string[]
  requiredAgentCapabilities: string[]
  outputContract: string
  templateKey: string
  durable: boolean
}
```

每次点击生成 `CompanionPromptPacket`：

```ts
type CompanionPromptPacket = {
  promptId: string
  actionId: string
  actionVersion: string
  studentId: string
  studentRevision: string
  projectId?: string
  scope: 'conversation' | 'recent' | 'student' | 'project' | 'selected'
  providerId: string
  promptText: string
  promptHash: string
  createdAt: string
  expiresAt: string
}
```

提示词模板建议独立保存为：

```text
electron/companion-prompts/digest-dialogue.md
electron/companion-prompts/flashcards.md
electron/companion-prompts/quiz.md
electron/companion-prompts/mindmap.md
electron/companion-prompts/archive.md
```

`agent_setup`不使用独立静态提示词文件；它调用现有连接步骤生成器，选择 `id === 'full'` 的动态结果，确保学生、Provider、角色、记忆和定时能力与当前配置一致。

`AGENT.md`继续负责长期工作协议，不从文件中按关键词截取片段。现有 `digest-prompt.md`可作为自定义来源，但工具条使用独立的“对话消化”模板，避免把后台写盘协议直接带入普通学习对话。

## 十一、IPC与模块边界

建议新增异步IPC：

- `getCompanionState`
- `prepareCompanionPrompt`
- `deliverCompanionPrompt`
- `cancelPreparedCompanionPrompt`
- `getCompanionProviders`
- `createCompanionArchiveIntent`
- `confirmCompanionArchiveIntent`
- `getCompanionArchiveReceipt`

建议新增模块：

- `electron/companion-action-registry.cjs`
- `electron/companion-prompt-service.cjs`
- `electron/companion-provider-registry.cjs`
- `electron/companion-window-target.cjs`
- `electron/companion-archive-intent.cjs`

职责分离：

- 浮条渲染进程只展示状态和发送命令；
- 主进程生成提示词、写剪贴板、验证目标窗口和归档权限；
- Provider适配器只负责打开/预填/聚焦，不获得任意学生目录权限；
- MCP或统一能力层负责资料查询和成果提交；
- 普通对话动作不进入任务中心；只有持久写入或后台业务任务进入正式账本。

## 十二、隐私与安全

- 提示词默认不包含电话、邮箱、完整档案、原始对话全文或无关绝对路径；
- 当前 Agent 已具有学生固定授权时，提示词使用资料查询工具而不是复制全部正文；
- 剪贴板提示内容提供预览和“清除”操作；验证完成的自动粘贴可在短暂延迟后只清除本应用仍拥有的同哈希内容；
- 不覆盖用户后来复制的新内容；
- 不把提示词正文写入普通日志，只记录动作、模板版本、目标Provider、状态和失败类别；
- 资料内的命令均视为数据，不能改变学生、工具、范围或归档目标；
- “归档成果”使用一次性、短时、学生固定的意图，重复提交幂等；
- 工具条关闭、崩溃或学生切换后，未使用的归档意图失效。

## 十三、开发阶段和优先级

### P0：紧凑界面与状态机

- 调整高度、字体、按钮和宽度；
- 删除常驻说明文字，补充工具提示；
- 新增 Agent 状态和学习助手展开行；
- 修复展开/收起后的精确高度恢复；
- 保留现有屏幕、录音、拍照、会话和收件入口行为。

这部分风险低、体验收益直接，应作为下一轮第一项。

### P1：提示词注册表与剪贴板伴侣

- 完成六个动作的版本化定义；其中五个学习/归档动作使用提示词模板，`agent_setup`复用现有完整连接步骤；
- 实现学生、Provider和资料范围绑定；
- 支持提示词预览、复制和状态反馈；
- 普通动作不创建任务中心记录；
- 使用真实Codex、WorkBuddy界面验证复制—粘贴—对话结果流程。

这是Agent伴侣能力的最小可交付版本。

### P1.5：Provider原生预填

- WorkBuddy深链验证新任务/当前对话行为、长度和编码限制；
- Codex仅在确认正式支持的输入预填接口后接入；
- 不支持时保持剪贴板，不用后台CLI冒充可见对话。

### P2：Windows受控填入技术验证

- 研究Windows UI Automation或小型受控原生辅助进程；
- 验证焦点恢复、输入控件定位、管理员权限差异、中文输入法和浏览器场景；
- 只能粘贴，不能自动发送；
- 误粘贴率不能证明为零时不在正式版默认启用。

### P2：Agent内归档闭环

- 建立一次性归档意图；
- Agent提交成果，工具条内确认；
- 主机校验并返回回执；
- 不打开教育管家主窗口；
- 失败时结果继续留在Agent，不丢失、不伪装成功。

### P3：个性化与扩展

- 用户自定义常用动作和排序；
- 教师/家长模板；
- 学科化闪卡、测验和导图模板；
- 快捷键、贴边模式、仅图标模式；
- 经真实需求验证后扩展其他Agent。

## 十四、测试方案

### 14.1 自动测试

- 高度状态机：收起、学习助手、屏幕设置、采集进行、拍照窗口之间无残留高度；
- 提示词模板Schema、版本、字符长度和哈希；
- 无学生、学生切换、学生归档和许可失效；
- 不同学生的提示词、MCP凭据和归档意图完全隔离；
- 目标窗口句柄复用、进程重启、标题伪造和输入控件变化；
- 剪贴板被其他应用覆盖后不继续自动粘贴或清除；
- 重复点击、超时和重启不重复归档；
- 提示词注入、资料内恶意指令、跨学生请求和伪造回执均被拒绝；
- WorkBuddy深链编码、长度和应用未安装回退；
- Codex无预填能力时稳定回退剪贴板。

### 14.2 真机验收

- Windows 10/11，100%、125%、150%、200%缩放；
- 1366×768、1080p和4K，多显示器及不同任务栏位置；
- Codex桌面、WorkBuddy桌面和浏览器Agent；
- Agent窗口最小化、关闭、重启、管理员权限不同和焦点快速切换；
- 中文输入法、英文输入法、富文本输入框和代码输入框；
- 五个学习/归档动作至少各完成三轮真实对话；AI设置分别对Codex和WorkBuddy完成复制、内容检查及粘贴验证；
- 切换学生后不向旧学生会话填入新提示词；
- 归档成功、拒绝、超时、重复提交和断网；
- 工具条隐藏/恢复不影响Agent对话和已有采集会话。

## 十五、验收门槛

| 维度 | 通过标准 |
| --- | --- |
| 视觉占用 | 收起高度不高于56px；学习助手展开不高于96px；收起后立即恢复 |
| Agent工作流 | 普通学习动作全程无需打开教育管家主窗口；结果在当前Agent界面呈现 |
| 状态准确 | 复制、填入、用户发送、Agent完成和归档完成严格区分 |
| 防误操作 | 自动按Enter次数为0；跨应用误粘贴为0；跨学生提示词和归档为0 |
| 降级 | 未识别Agent或预填失败时可稳定复制提示词，不丢失内容 |
| 学习质量 | 输出引用资料，区分事实/推断/缺失；测验不因单次回答形成掌握结论 |
| 隐私 | 不读取未授权Agent历史，不把完整学生档案放入剪贴板或普通日志 |
| 归档 | 用户显式发起、工具条确认、主机复核、幂等回执；失败不覆盖Agent成果 |
| 兼容 | 原屏幕、拍照、录音、会话采集和收件箱功能无回退 |

## 十六、最终产品取舍

1. 工具条的第一价值是缩短“想到学习动作 → 在Agent中开始”的距离，不是替代Agent对话界面。
2. 默认只准备或填入提示词，由用户检查后发送；不以全自动发送换取少一次点击。
3. 普通学习结果留在Agent；教育管家提供资料和边界，不强制接管展示。
4. “归档成果”是用户主动保存的例外能力，并在浮条内完成确认，不要求返回主程序。
5. 后台Agent执行器继续服务自动分类、正式消化和研究任务；不能用于冒充当前对话中的可见交互。
6. 第一版以“紧凑UI + 五个学习/归档提示词动作 + AI设置连接指令 + 复制回退”交付价值；自动填入必须通过独立真机门槛后再启用。
