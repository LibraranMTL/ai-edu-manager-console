# P1-T：个人行为预测与数据采集规范——支线讨论参考

日期：2026-09-16

状态：用户要求将支线讨论加入主线作为参考。本文整理讨论结论，不表示实现完成，不替代主线实施方案，也不新增模型训练、扩大采集或发布授权。

## 1. 对主线的建议

当前阶段优先建设单学生长期时序证据与纵向追踪能力。现有屏幕截图、授权 Agent 会话、课程任务和作业资料可以继续复用；重点补齐“任务—初次尝试—指导—再次尝试—结果—延迟验证”的关联。

现有方式足以支持资料整理、学习回顾和初步观察；要支持可靠的个人行为预测，仍缺少稳定任务标识、实际行为人、独立性判定、真实指导响应和可验证结果。

以上判断来自讨论期间的源码结构检查，未抽检真实学生资料，不代表真实采集覆盖率、识别准确率或真机性能已经通过验收。代码行号可能随主线开发变化，实施时应重新核验。

## 2. 个人学习行为模型的建议形态

暂称 Personal Learning Dynamics Model（个人学习行为动力模型），采用三部分组合：

1. 可解释的个人状态估计：知识表现、重复错误、策略使用、支持依赖、保持与迁移及不确定性。
2. 相似历史检索：按知识点、任务类型、可比较难度、支持程度和错误模式寻找该学生自己的历史尝试。
3. 经时间外测试验证的轻量预测器：预测下一步行为、任务结果、指导后修正及后续保持。

预测必须具有明确目标、时间范围与可用历史边界。只使用预测当时已经获得的信息，保存预测版本与时间，待后续真实结果出现后对账。

初期使用“未观察、初次接触、提示下完成、部分独立、多次独立、跨情境使用、长期未复测、证据冲突”等可解释状态。未校准前不输出貌似精确的掌握概率。

DKT、AKT、StudentSim 作为后续研究方向，不作为 P1-T 的交付依赖。StudentSim 使用群体训练后个体适配，不能直接据此认为单学生少量历史已足够训练同等模型。

## 3. 当前源码检查发现的优先缺口

- `electron/capture-timeline.cjs` 的 `captureEventFromSessionItem`：缺少采集时间时可能回退到上传时间、会话开始时间或当前时间。应区分实际时间、替代时间及其精度。
- `electron/agent-conversation-submission.cjs` 的角色规范：学生、家长、教师可统一映射为 `user`。应另存实际行为人，不改变原有对话角色兼容性。
- `electron/capture-timeline-semantic.cjs`：`guidanceResponses` 缺失时可生成下一步建议。建议与实际发生的指导、学生响应必须分开，不能将建议当成学习样本。
- 当前视觉观察虽有动作、阻碍、变化和结果字段，仍不足以表示多次尝试及其关系；v3 观察处理中的 `attempts` 为空数组。

## 4. 收集规范：以一次学习尝试为分析单位

截图是证据单位，会话是采集单位；用于分析和预测的单位为 `attempt`。同一任务允许多次尝试、跨应用和跨天关联。

建议最小字段组：

| 字段组 | 内容 |
| --- | --- |
| 身份与范围 | studentId、deviceId、projectId、actorType、身份依据 |
| 时间 | occurredAt、receivedAt、processedAt、时区、时间来源、精度、序号；必要时记录设备时钟偏差 |
| 任务 | taskId、任务版本、任务类型、conceptIds、难度及其来源；未知可为空 |
| 尝试 | attemptId、previousAttemptId、任务引用、原始回答/作品版本、修改内容 |
| 支持 | interventionId、指导原文引用、来源、强度、呈现时间、呈现状态、关联依据 |
| 响应与结果 | responseTo、完成状态、正确性/质量、支持程度、评价来源、结果时间 |
| 证据与版本 | evidenceRefs、来源哈希、识别方法、分析器版本、未知字段、修正关系 |
| 覆盖 | 授权采集范围、实际采样策略、缺失区间、暂停/排除/断网等已知原因 |

“任务完成”“答案正确”“独立完成”分别记录。不能将程序运行通过直接解释成学生理解。

相同事件在截图、聊天记录、作品中出现时合并为一条尝试的多份证据，不计成多次表现。

跨来源优先采用稳定任务 ID、文档 ID 和显式引用。时间接近只产生关联候选；归属或关联不确定时保留未关联，不阻塞其他记录。

## 5. 收集方式与低操作负担

优先复用已有结构化任务事件，其次是授权 Agent 会话和作品版本，屏幕资料补充没有接口的过程。现有教师/家长反馈可作补充，不增加日常填表。

Agent 会话保留原始消息 ID、角色、实际行为人、消息时间及必要原文片段；不能仅存总结。指导已生成、已呈现、学生已响应是不同状态，不能仅凭生成记录推断学生看过。

缺少角色或结果时默认 unknown，后台继续处理。普通失败自动恢复，只有无法自动解决且确需决定的范围问题才提示用户。

长期保持与迁移不能只靠被动截图保证观察到。可在现有课程或行动建议中安排适量短验证任务，复用正常任务结果；没有机会验证时保留“尚未验证”。该项为方案建议，不是本次新增任务安排授权。

## 6. 选帧策略修正

“每会话最多 20 图”不宜成为长会话永久的证据上限。建议评估改为分处理窗口预算，并设置全日总预算、排队与延期策略，保持前台资源边界。

两级选帧：先依据时间、来源和画面变化低成本选帧；初次识别后，只针对关键链路缺口，在已有授权资料中有界补取邻近帧。

优先保留任务开始、初次回答、提示前后、关键修改和结果。同时保留少量规则间隔样本，避免只收集大幅变化画面造成选择偏差。

记录采样间隔、跳过重复画面数量、暂停和未知空档；截图稀疏时只能报告响应时间区间。补帧不能变成持续全图 OCR 或无预算的模型调用。

## 7. 分析与训练数据边界

- 原始观测、模型推断、系统建议、预测结果分开存储。
- 未观察到帮助不等于独立完成；未观察到提交不等于失败或放弃。
- 长期未复测降低判断确定性，不自动认定遗忘。
- AI 报告、建议与预测不得重新充当学生行为事实。
- 指导与响应的时间关联不自动构成因果关系；比较指导方式须考虑任务难度和起始状态。
- 任务/知识点映射需要稳定 ID 和版本，避免名称变化造成趋势断裂。
- 修正采用可追溯版本，不静默覆盖原有判断；删除来源后，相应推断与预测数据也应按现有治理规则失效或重建。
- 训练与测试按时间划分，避免同一任务、重复证据或未来结果泄漏到预测输入。

前次讨论中“10～30 次建立基线、30～100 次建模”等数字属于未经验证的初步示意，不能作为科学门槛或上线判据。应依据可比较任务覆盖、独立样本数、时间外测试表现及概率校准决定是否启用预测。

## 8. 效率与验收

字段登记和结构化关联通常不是主要成本；视觉识别和重复全历史分析才是风险重点。建议：

- 采集路径保持轻量；识别、补帧及关联在后台执行。
- 同次识别输出多个字段，按证据与策略版本缓存。
- 同一学生状态更新串行，后台全局自适应并发。
- 只更新受影响任务、知识点和时间窗口，报告复用结构化结果。
- 前台只读取分页投影，打开页面不触发历史重算。
- 局部失败不阻断整体，未知字段不成为自动化阻塞条件。

沿用主线性能目标并进行实际基准验证；不能依据字段开销较小就宣布真机无卡顿。

内容验收关注：任务关联准确率、初始尝试保留率、指导响应链完整率、结果可验证率、时间可信度、重复事件率和未知覆盖范围。抽样质量检查用于开发验收，不转化为用户每次使用的审核流程。

建议主线实施优先顺序：真实时间与缺失记录 → 实际行为人 → 任务/尝试 ID → 指导建议与真实响应分离 → 结果及评价来源 → 个体纵向状态 → 经验证后启用预测。
