# Windows 任务有界恢复与派发保护

日期：2026-10-11。当前源码版本 0.21.1，本轮为未完成任务优化计划中的一批增量交付，不是三阶段全部完成。

## 本轮实际接入

### 失败分类和有界重试

- 登录、权限、来源/内容校验、未知错误不进入自动重试。
- 临时网络、服务繁忙、限流仅在执行器明确确认没有残留执行时允许重试。通用 CLI 退出不证明远端已停止；无法确认时进入“核对中”。不会为提高成功率假定外部已停止。
- 重试计划默认间隔约 1 分钟、5 分钟，跨执行器共用最多 3 次上限；最多延后 10% 的抖动。支持独立 Retry-After 头的秒数/日期，不早于服务要求。
- 将重试资格、归属、业务批次/来源版本、executionId、次数、下次时间保存进现有账本。读取归一化不会丢失这些字段。
- 新增共享业务重试队列，复用现有队列实现；不是新增任务平台或为每条任务创建定时器。长 Retry-After 避免 Node 超长定时器溢出成 1 毫秒忙循环。
- 删除原先“失败/超时后最多 30 秒直接换执行器”的独立 setTimeout 路径。调度器与恢复入口共用同一资格校验，不能抢先重跑。
- 升级只恢复带本版完整决策记录的安全重试，不批量重新运行历史失败任务。暂停学生、许可证、自动化开关及存储故障仍是派发前置条件。

### 超时与重启核对

- 超时先请求停止并保留进程归属、执行编号和批次；不直接删除进程记录或启动替代任务。正在提交的受控资料事务不被超时取消。
- 未确认状态仍保留原执行接收通道：同一批次的迟到结果可继续走原宿主校验；取消、替代或身份不符的结果仍拒收。
- 原批次结果完整通过宿主校验后才解除“核对中”，不因收到任意输出、进程退出或校验失败解锁。
- 主机重启时，没有本机有效运行句柄的自动外部任务标为“核对中”；不清空 executionId 后假装未执行。仍在当前进程运行的任务和桌面待发送任务不被误判为崩溃。
- 未知状态仍使用现有“原工具核对 → 取消本机接收 → 明确确认外部已停止 → 手动继续”路径。本轮没有伪造外部自动停止能力。

### 存储故障及列表语义

- 通用 CLI 与受控项目资料派发前，账本读取、关键状态保存失败会释放预留资源，并阻止启动 Agent。通用 CLI 的日志准备失败也不会启动进程。
- 存储保护触发时，共享重试唤醒不读取坏账本或派发新任务。
- 只有具备有效持久重试决策的条目显示“稍后继续”，归为计划等待；旧 nextRetryAt 字段不再冒充必定会自动恢复。
- 保留原任务、学生、资料目录、权限、报告发布、卡片反馈和成长模型流程。
