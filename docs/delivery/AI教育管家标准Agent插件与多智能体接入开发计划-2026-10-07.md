# AI教育管家外部 Agent 统一连接器开发计划

> 修订日期：2026-10-15；版本：v4（接入《Agent连接器是否必须这样设置》的用户交接结论）。原文件名保留，既有引用继续有效。
>
> 本文是后续开发方案。现有基础、待开发内容、自动测试、配置验证、真实宿主验收和正式发布分别记录；本文不表示所列功能已交付。本版替代此前关于逐学生授权、逐篇审批、NotebookLM资料包开发及首批同时适配全部宿主的安排。

## 一、产品定位与本轮决策

外部 Agent 统一连接器让用户在常用 Agent 中调用 AI 教育管家的私人知识，并将有价值的对话、资料和分析成果持续保存到教育管家，参与后续整理、消化和查询。

教育管家积累的是用户的经历、作品、报告、项目、个人批注和长期成长上下文。公域资料作为相关研究的参考来源；外部 Agent 产生的分析作为派生内容保留来源，经过既有知识治理规则形成长期知识。

本轮确定以下原则：

1. 普通用户一次性选择全局授权档位，覆盖本主机管理范围内现有及未来学生，无须逐学生、逐项目授权。
2. 获得写入授权后，正常资料自动保存，无须逐篇审批。
3. 默认每个会话绑定一名学生；用户可主动选择“一个会话访问所有授权学生”。跨学生查询按学生分别执行、分组返回，每项写入必须明确唯一目标学生。
4. 系统为每个连接自动配置独立凭据，用户只管理授权和连接状态。
5. 高级设置首期只收窄全局权限，不建立多层扩权规则。
6. 首批完成 WorkBuddy、Codex 的真实知识积累闭环，再扩大宿主覆盖。
7. NotebookLM资料包和LMS暂不开发；NotebookLM成果沿用现有导入、分享和屏幕采集入口。
8. 商业推荐首期仅保留可复用的信息返回和事件记录，收费统计、交易和佣金结算后置。
9. WorkBuddy/Codex 原位升级已安装的 `edu-manager-knowledge`；不并列安装 `edu-manager-external-<UUID>`。两端独立凭据，保留原 12 项工具名兼容入口，但参数升级为显式会话范围，须重启宿主刷新工具声明。

### v4 分步实施与验收边界

- 第一步：统一安装身份、两种学生范围、最小授权学生目录、连接状态、跨学生只读查询、明确学生的单项写入、学生来源与独立回执。提供原位升级按钮、配置备份、旧固定凭据不扩权；区分凭据生成、配置更新、重启加载和真实调用验证。
- 第二步（尚未开发）：批量写入的一次确认、部分失败恢复、跨学生工作会话档案、自动拆分学生专属摘要。首期拒绝多学生完整对话和自动记忆写入，避免整篇混写到单个学生；明确归属的成果可使用资料保存入口。
- 旧生命周期采集依赖“当前活动学生”，升级对应宿主后停用该旧入口，不把它自动迁移成多学生采集。单学生记忆继续使用经过授权与会话绑定的工具。
- 兼容不表示旧参数仍自动生效。没有 sessionId/contextRevision 或全学生模式下没有 targetStudentId 时返回明确错误，不回退到活动学生。
- 当前实现与验收证据见 `R21-统一知识连接器与WorkBuddy兼容修复-r10-2026-10-15.md`；用户在真实 WorkBuddy/Codex 重启后调用的最终验收单独记录。

## 二、调用方向与范围

| 功能 | 调用方向 | 职责 |
|---|---|---|
| AI 接入与调度中心 | 教育管家 → Agent／模型 | 分类、消化、卡片等内部任务的执行、路由和结果回收 |
| 外部 Agent 连接器 | 外部 Agent → 教育管家 | 知识查询、授权会话记忆、资料和草稿回写、结果查询 |
| 现有资料采集入口 | 用户选择的文件、分享、屏幕内容 → 教育管家 | 接收原始资料，按明确目标投递或进入归属确认 |

外部连接器位于“系统设置 → Agent 调用能力 → Agent 连接管理”。全局连接器授权只管理入站数据访问；内部任务如何运行继续由原调度规则决定。

本期以 Windows 本机 stdio MCP 为交付主线。MCP是统一调用入口；宿主插件、Skill及配置文件是安装和调用规则的适配形式。支持标准MCP不代表所有宿主插件包都可直接通用。

本期不增加默认常驻云服务、云端档案镜像、新数据库或独立分类／消化引擎。远程HTTP MCP、移动端专用连接、NotebookLM自动同步和LMS另行评估。

## 三、现有基础与复用安排

以下依据前序源码核对制定；实施开始时重新检查实际版本和未提交改动，不能把已有模块视为本方案已完成。

| 基础 | 本轮处理 |
|---|---|
| 外部能力合同与MCP入口：electron/agent-capability-contract.cjs、electron/agent-knowledge-mcp.ps1 | 复用工具业务逻辑，补齐连接身份、会话范围和自动执行合同 |
| 全局控制：electron/agent-control-plane.cjs | 拆清出站调度与入站授权职责，增加档位、暂停、撤销和权限版本 |
| 写入意图：electron/agent-write-intents.cjs | 保留持久执行记录，增加持久授权自动放行和恢复，支持高级逐次确认 |
| 会话采集与治理 | 复用当前会话事件、原文登记和记忆体系，统一来源标识及去重 |
| 智能分类与资料投递 | 复用主机目标校验、项目登记和回执；明确目标直接投递，归属不明才分类 |
| 学生／项目资料消化与任务中心 | 复用现有队列、资源限制、执行器与结果校验，补齐写入回执到知识产物的关联 |
| 设置页和连接配置生成 | 普通页简化，高级例外折叠；为每个连接生成独立配置和凭据引用 |

新增重点是“连接登记、会话绑定、权限解析、执行记录关联”。不另建一套用户档案、知识库或任务中心。

## 四、普通用户操作流程

### 4.1 一次性全局授权

首次启用时在一个页面完成选择：

| 显示名称 | 内部档位 | 权限数 | 实际能力 |
|---|---|---:|---|
| 仅查询 | read | 6 | 查询档案、报告、项目知识和任务状态 |
| 查询与会话记忆 | read_memory | 9 | 增加当前授权会话的记忆保存、读取与交接 |
| 查询、记忆与自动回写 | full | 13 | 增加会话归档、资料接收、任务草稿、报告草稿 |

页面明确显示“适用于本主机管理的现有及未来学生”。用户确认一次后持续生效；修改档位只影响之后的调用和尚未提交的操作，不删除既有资料。

“会话记忆”表示允许记录授权后的当前会话；实际自动采集取决于宿主已验证的事件接口或工具调用支持。只会查询的宿主不能因为获得该权限就显示为“自动采集中”。

新连接由用户在“添加连接”时确认继承当前授权，不再次展示13项选择。可勾选“以后由我添加的新连接自动继承当前授权”。仅检测到已安装软件不会自动创建有效凭据。

### 4.2 日常设置

普通页面展示当前档位、学生访问范围（单学生会话／全授权学生会话）、连接列表、最近处理状态，以及：

- 添加连接；
- 原位升级 WorkBuddy/Codex 已安装的 edu-manager-knowledge；
- 暂停／恢复连接；
- 修改授权；
- 撤销授权；
- 高级设置。

“暂停”保留配置和授权，停止接受新调用及启动尚未提交的写入。“撤销”使凭据和授权代次失效，恢复使用需重新授权。连接单独暂停或撤销不影响其他连接；全局操作影响全部连接。

### 4.3 默认模式：会话归属只选择一次

- 仅有一个可用学生时，主机自动绑定，并返回当前归属。
- 有多个学生且无明确归属时，首次使用返回“请选择学生”，通过教育管家提供的选择界面完成一次选择。
- 用户在当前对话明确指定且可唯一匹配的学生，可绑定到该学生；重名或不明确时只返回最小候选信息，不读取档案正文。
- 后续查询和回写沿用该会话绑定，无须反复选择。
- 同一Agent的不同会话可以分别绑定不同学生。
- 用户明确切换学生时建立新的上下文代次。后续工具返回只含新学生上下文；已经启动的任务继续使用启动时的学生、项目和资料版本。
- 教育管家主界面切换学生不会改变外部会话绑定。
- 若需隔离外部聊天中已经展示的旧学生内容，应开启新的聊天；连接器不能删除宿主已收到的历史内容。

学生选择只确定工作对象，不是再次授权。会话结束或绑定失效后，再按上述规则确定下一次会话的对象。

### 4.4 全授权学生会话（主动选择）

策略 `accessMode=all_authorized_students`，默认仍为 `session_bound`。未来新增学生是否继承由用户选择，高级排除与到期设置继续生效。改变模式提升现有会话上下文版本，清除原默认归属，不接受旧版本请求。

`list_authorized_students` 只返回学生 ID 与姓名。查询可指定单名、多名或全部已授权学生（每次最多 50 名，超出需分批），返回每名学生独立结果及来源；不得合并来源而丢失归属。姓名重复时先由用户确认 ID。

普通写入必须带唯一 `targetStudentId`，不能以“当前学生”或 all 代替；项目必须独占归属于该学生。不同学生使用独立幂等记录和回执；其他学生的权限不能因一次成功而被推定有效。首期没有自动批量写入工具。

## 五、全局授权、连接凭据与运行时范围

### 5.1 全局策略与独立凭据

全局策略由主机所有者／管理员设置。系统为每个连接实例签发独立凭据，至少关联连接ID、宿主类型、授权代次、创建时间和凭据版本。同一宿主的不同配置实例使用不同连接ID。

凭据从主机受管存储读取，Agent配置只保存凭据引用。主机根据凭据确定连接身份，不能信任调用方自报的agentId作为身份认证依据。该身份代表持有凭据的连接，不宣称能够证明操作系统中某个进程绝对真实。

全局策略覆盖全部授权学生；工具执行上下文仍由主机生成并限制到单个学生。既有固定学生凭据在迁移前继续保持原范围，不能仅凭模型传入studentId扩大范围。

撤销、轮换和连接停用由主机统一处理，避免向用户暴露令牌或配置细节。

### 5.2 查询与写入范围

| 操作 | 范围规则 |
|---|---|
| 学生综合查询 | 单学生会话查询绑定学生；全学生会话按明确学生逐项查询、分组返回，可覆盖各自获授权关联项目 |
| 指定项目查询 | 当前学生关联且获授权的指定项目 |
| 学生资料写入 | 单学生会话使用绑定学生；全学生会话强制唯一 targetStudentId，写入其受管收件箱或相应业务草稿位置 |
| 项目资料写入 | 一个明确的关联项目，由主机解析真实目标 |
| 未确定学生 | 单学生会话先绑定；全学生查询先确定授权目录或指定 ID，每项写入必须明确唯一目标 |
| 未确定项目 | 学生已明确且用户未指定项目时可进入该学生收件箱；用户明确要求某项目但匹配失败时等待解决，不退回其他位置 |

项目可以包含多名成员，但返回给当前学生的内容必须能依据既有项目访问规则过滤；无法隔离的共享资料不在首期连接器中开放。不得仅凭“项目绑定了该学生”就返回其他成员私人资料。

封存项目的读取沿用既有只读权限；封存后拒绝新写入。删除学生、解绑项目或高级排除后，后续请求按最新范围处理。

### 5.3 有效权限计算

有效权限 = 当前全局档位权限 − 全局禁用项 − 连接禁用项，再应用学生／项目排除、期限和暂停／撤销状态。

工具列表按权限过滤，每次执行仍由主机重新检查；权限降级后旧工具列表和缓存不得继续授权。授权选择不取消学生范围检查，也不开放任意磁盘路径或全体学生批量导出。

## 六、高级设置的首期范围

高级页面只提供：

1. 单独停用或撤销连接。
2. 排除指定学生或项目。
3. 全局或按连接关闭个别权限。
4. 全局或按连接恢复“每次写入前确认”。
5. 设置全局或连接有效期。

高级设置只能收窄当前档位。相同请求匹配多条限制时采用更严格结果；连接到期后保持不可用，不自动回退到全局许可。恢复某项权限不能超过当前全局档位。

频率和大小限制先采用主机统一默认值；自定义配额、多层学生／项目权限组合、额外allow规则后置。系统保留13项能力目录，用户在高级页面可以查看授权状态及生效原因。

记忆和交接由既有会话工具承担，因此13项权限与12个能力操作不一一对应。连接身份、会话绑定、回执查询属于支撑协议，不因新增这些接口就扩大业务权限。

使用单一ExternalPermissionDescriptor注册表生成档位、工具过滤、高级矩阵和测试数据。memory:write只允许会话记忆持久化，不得成为通用资料或正式档案写入的旁路。

## 八、自动写入、消化与再次查询

### 8.1 写入流程

正常写入不弹出逐篇审批，但仍持久记录写入意图及自动放行依据：

外部提交 → 身份与归属校验 → 建立执行记录 → 持久授权自动放行 → 主机提交资料 → 返回回执 → 按既有规则排队消化 → 关联知识产物 → 后续查询可引用新增知识。

高级逐次确认只在用户主动开启时生效；沿用同一执行器和回执链，避免维护第二套写入逻辑。

对旧的“预览／执行”工具可保留兼容接口，由主机按策略自动放行；同一意图的执行调用返回同一操作状态。不能只在前端隐藏审批按钮而让后台永久停留在待批准状态。

### 8.2 投递与消化

- 学生和目标项目明确：直接进入项目收件箱，跳过跨项目分类。
- 学生明确、项目未定：使用学生收件箱，或按已开启的智能分类规则在该学生范围内推荐目标。
- 学生不明确：等待归属确定，不用分类模型猜测身份。
- 项目内部类别建议可复用已有分类能力，但不阻塞资料安全保存。
- 自动消化沿用用户现有调度设置、合格执行器和资源限制。已启用时自动排队；关闭时明确显示“已保存，等待消化”，不为连接器另增默认费用或第二套执行设置。
- 不依赖原Agent持续在线领取后续任务；主机接收后的处理由现有任务体系负责。
- 消化成功后记录知识产物和索引状态；只有检索确实能返回新增内容及来源，才显示“可查询”。

task:create只创建任务草稿。任务是否运行由原有任务类型、授权和调度策略决定；允许创建不等于允许任意命令、联网任务或付费执行。

report:draft只保存报告草稿。普通研究笔记、概念和摘要可以按既有规则自动沉淀；能力判断、项目贡献、健康结论和正式报告发布仍遵循原采纳流程。免逐篇导入审批不会改变这些业务规则。

### 8.3 状态展示与失败恢复

用户可见状态为“已接收、已保存、待消化、消化中、已沉淀、可查询”，并单独显示失败或待确认原因。任务草稿、报告草稿按自身生命周期展示，不强行显示为知识已沉淀。

系统内部至少关联operationId、receiptId、materialId及版本、digestTaskId、knowledgeRefs和indexStatus，支持分别重试失败阶段：

- 已保存但响应丢失：重试返回已有回执，不重复导入。
- 已保存但消化失败：重试消化，不再提交原件。
- 已沉淀但索引未更新：只恢复索引，不重跑模型。
- 写入结果不确定：先核对持久账本和目标记录，再决定恢复；不得盲目重复执行。
- 同一幂等键但内容不同：返回冲突，保留原记录。
- 已批准的旧请求：执行前重新校验当前权限和范围。

幂等键至少按连接、学生、目标和操作类型隔离。重试使用原操作ID，内容哈希用于验证一致性。

暂停或撤销后拒绝新请求，未提交写入重新检查后停止。已经完成原子提交的资料保留真实回执；已交付给管家的资料继续遵循现有资料处理设置，不因断开外部连接自动删除。撤销时说明这一结果，不能承诺收回已发送给外部Agent的数据。

## 九、会话、资料和派生知识的去重

三层数据承担不同职责：

| 层级 | 保存内容 | 去重原则 |
|---|---|---|
| 原始对话／原始资料 | 原文、消息角色、附件、来源与时间 | 相同来源事件重试不重复登记 |
| 会话记忆 | 授权范围内用于续聊的摘要和状态 | 关联原始会话，不把摘要当成新独立证据 |
| 长期知识 | 消化形成的概念、研究结论和用户确认内容 | 关联原件与版本，派生关系不增加原始证据数量 |

自动Hook采集、MCP提交、手工导入与屏幕采集采用统一来源登记，记录connectionId、sessionId、contextRevision、sourceEventId／messageId、contentHash、receivedAt及来源方式。

优先按真实来源ID去重。只有相同文本而来源不同时保留来源关联，不能把两个学生或两次真实经历直接合并。缺少来源ID的截图OCR或外部导出只能形成疑似重复提示，不凭语义相似自动删除。

会话采集只覆盖授权后的新事件，当前会话内容在新代次下重新校验。内部分类、消化、总结任务带内部来源标记，不回灌为用户外部聊天。

成果记录derivedFrom、generatedBy、来源资料版本及用户确认状态。教育管家资料经外部Agent分析再返回时保留派生关系，重复摘要不得变成新的成长证据；来源未知时明确标注未知，不推断完整血缘。

## 十、设置页与调用结果

“Agent 连接管理”保留两个页面：

- 外部 Agent 连接器：授权档位、暂停／恢复、连接列表、添加连接、撤销及高级设置。
- 写入记录与异常：资料保存、消化和查询可用状态；支持按连接、学生、项目筛选。

正常保存和后台处理采用状态提示，不持续弹窗。需要选择归属或处理冲突时给出具体下一步。“重新分类”“重新消化”“重试同步”分别重试对应阶段。

每个查询结果包含来源、学生／项目范围、内容类型和更新时间。原始事实、用户陈述、外部AI分析与已确认知识明确区分；资料不足、离线或尚未消化时说明实际状态。

每个写入结果返回稳定回执和处理状态。Agent收到“已保存”时不能告知用户“已更新正式档案”或“已完成知识沉淀”。

## 十一、宿主接入和安装

首批重点验收WorkBuddy和Codex。OpenClaw、Claude Code及通用MCP客户端列入后续覆盖矩阵；已有配置代码可以保留，不扩大首期正式支持声明。

安装流程：检测已知宿主 → 用户添加连接并继承全局策略 → 自动签发独立凭据 → 备份和合并配置 → 握手 → 合成资料自检 → 引导真实使用验证。

配置写入只修改教育管家自有条目，重复接入复用或明确建立新连接；升级和卸载保留其他MCP配置。无法安全识别配置格式时给出手工步骤。自动继承只适用于已登记接入的连接，不向任意发现的进程分发凭据。

连接状态分别记录“已配置、握手成功、查询已验证、回写已验证、自动会话采集已验证”。真实闭环验收是发布证据，不要求普通用户每次运行测试。

标准MCP工具承担业务调用；Skill或宿主规则提示Agent按需查询和保存。连接器不能强制所有宿主在任何教育问题中优先调用，也不能控制其全部回答；明确请求“依据教育管家资料”时的真实调用、引用和失败提示必须实测。

## 十二、授权迁移与兼容

1. 实施前备份现有授权、连接配置和未决写入账本，记录版本和哈希。
2. 旧版已明确授权的权限按实际记录映射到等价档位及禁用项；无法证明曾授权自动写入时，升级后由用户完成一次档位确认。
3. 全局授权覆盖未来学生；用户主动排除的范围在升级后保留。
4. 已有固定学生描述符保持原绑定，迁移时登记连接并换发凭据；不能静默把已流出的旧凭据改为全局访问凭据。
5. 历史待人工审核意图仍待用户处理，不因开启full自动执行；新请求遵循新策略。
6. 为旧工具名、预览／执行接口保留一个发布周期兼容，所有入口调用同一策略解析和主机提交服务。
7. 回滚恢复配置和策略前重新核对权限代次；已撤销凭据不得因恢复旧备份复活。新产生的资料与执行记录保持可追溯，不随配置回滚删除。
8. 安装、配置、授权、测试、候选构建、签名和正式发布分别记录状态。

## 十三、数据合同与实现要点

以下为设计合同，实施时与现有存储和类型收敛，不要求新建数据库。

| 对象 | 关键字段 | 约束 |
|---|---|---|
| ExternalGlobalAuthorization | status、preset、paused、inheritForNewStudents、inheritForNewConnections、authorizedAt、expiresAt、authorizedBy、revision、authorizationEpoch | status为unconfigured／active／revoked；preset为read／read_memory／full；暂停与撤销独立 |
| ExternalConnection | connectionId、hostType、credentialRef、credentialVersion、status、acceptedPolicyRevision、createdAt | 每个连接实例独立凭据；审计使用主机解析的connectionId |
| ExternalSessionBinding | connectionId、sessionId、studentId、defaultWriteTarget、contextRevision、boundAt | 唯一学生；切换新代次；任务执行范围冻结 |
| ExternalRestrictions | excludedStudentIds、excludedProjectIds、disabledPermissions、connectionRestrictions、expiresAt、requireWriteConfirmation | 不含allow扩权；连接限制仅停用、禁用权限、期限和逐次确认 |
| ExternalPermissionDescriptor | id、group、label、description、exposedOperations、presetMembership | 单一权限目录，档位权限数6／9／13 |
| ExternalWriteOperation | operationId、connectionId、sessionId、scopeSnapshot、policyRevision、approvalMode、idempotencyKey、payloadHash、status、receiptId | approvalMode为persistent_policy或manual；先持久登记再执行 |
| KnowledgeProcessingReceipt | receiptId、materialId、materialVersion、digestTaskId、knowledgeRefs、indexStatus、error | 保存、消化、索引分别查询和恢复 |
| SourceProvenance | sourceEventId、messageId、contentHash、sourceType、generatedBy、derivedFrom、receivedAt | 来源事实与派生分析分开；未知来源保持未知 |

支撑接口至少覆盖：连接登记／撤销、会话绑定／切换、有效权限查询、受控写入提交、操作状态查询及处理状态查询。

会话切换必须有用户显式选择或对话中的明确指令依据，不能由资料正文中的指令触发。来自查询结果、上传文件和截图的文字只作为数据处理，不改变连接身份、授权或执行目标。

所有新写入口复用主机生成资源ID、路径解析、版本校验和幂等提交。执行前校验权限与上下文代次；已运行任务以冻结范围恢复，不能因UI切换或会话切换改投其他学生。

## 十六、NotebookLM与商业功能边界

NotebookLM资料包暂不开发，也不增加专用映射中心、浏览器采集扩展或自动上传同步作为本轮依赖。用户可在现有采集入口选择学生和对应项目；明确归属的资料使用直接投递，未知归属再分类。普通截图只代表已采集画面，不能标注为完整NotebookLM对话或已完成自动同步。

商业推荐首期复用已有商家资料或推荐能力，返回时标明合作／推广属性，保持与知识证据可区分。只记录connectionId、推荐条目ID、请求／回执ID、时间和实际返回状态；没有宿主展示证据就不记为展示，没有成交核验就不记为成交。

推荐目录扩建、广告计费、CRM、订单、支付和佣金结算不阻塞连接器发布。商家联系、报告分发及商业数据共享沿用独立业务授权，不从连接器全局授权推导。
