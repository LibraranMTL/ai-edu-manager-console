## 1. 决策摘要

Windows 主机版不再承担平台课程和机构课程的内容编辑、Excel 导入、课程包制作、发布及回滚职责。以上能力统一迁入云端公共内容发布中心。

Windows 端保留两类能力：

1. **精品课程学习**：浏览、搜索、安全打开云端发布的有效课程。
2. **本地课程设置**：按本机学生启用/隐藏、排序、年级适配和学生分配，查看同步与离线缓存状态。

因此不建议直接删除整个课程模块，而应把现有“精选课程 → 课程管理”改造成轻量的“精品课程 → 课程设置”。删除整个模块会同时丢失学生分配和本地策略，且安装包只会减少很小体积。

## 2. 当前能力与问题

当前源码把课程能力分散在 `src/main.tsx`、`electron/main.cjs`、`electron/preload.cjs` 以及多个课程运行模块中：

- `platform_standard`：平台课程，平台版主机可编辑、发布、导出和回滚课程包；
- `tenant_custom`：机构课程，专业版/机构版/平台版可直接新增、Excel 导入、编辑和删除；
- 本地策略：启用、排序、年级和学生分配；
- 课程学习：安全浏览、域名限制和学生端下发；
- 离线课程包：人工导入并保留最后可用目录。

主要问题：

1. 课程内容分散在不同 Windows 主机，难以保证版本一致。
2. 平台课程和机构课程发布工具与普通主机共包，权限和运维边界复杂。
3. 多语言、多国家和多地区目录难以依靠人工课程包持续维护。
4. Android 单机版需要重复导入课程包，无法自然继承最新发布内容。
5. Excel 导入、课程图片复制和课程包导出增加代码与测试面，但不是主机日常核心价值。

## 3. 目标架构

```text
云端公共内容发布中心
├─ 平台课程
├─ 机构推荐课程（仍由平台管理员维护）
├─ 多语言内容与区域适用范围
├─ 发布清单、灰度、撤回和回滚
└─ 公共学习卡模板
          │
          ├── HTTPS 同步 → Windows 主机版
          └── HTTPS 同步 → Android 单机版

Windows 主机版
├─ 精品课程学习
├─ 本地课程设置
│  ├─ 启用/隐藏
│  ├─ 排序
│  ├─ 年级适配
│  └─ 学生分配
├─ 最后可用目录与资源缓存
└─ 向 Windows/Android 学生终端提供当前学生有效课程
```

云端负责“发布什么”，Windows 本机负责“哪些学生使用什么”。学生身份、分配、打开记录和学习状态不因课程同步而上传公共内容域。

## 4. 命名与导航

现有界面使用“精选课程”。本方案建议用户可见名称统一为“精品课程”，底层 `courseId`、历史目录和 API 字段保持兼容。

```text
精品课程
├─ 课程学习
└─ 课程设置
   ├─ 云端同步状态
   ├─ 本机启用与排序
   ├─ 年级/学生分配
   └─ 缓存与诊断
```

删除以下普通主机入口：

- 新增/编辑/删除平台课程；
- 新增/编辑/删除机构课程；
- 下载 Excel 模板和 Excel 导入；
- 导入平台课程包（日常入口）；
- 发布、重新导出和回滚平台课程包；
- 平台发布机、课程私钥或发布确认相关界面。

迁移期可在高级诊断中保留只读的旧课程包导入工具，但默认隐藏，并在迁移结束版本删除。

## 5. 云端同步合同

### 5.1 客户端请求上下文

Windows 主机向公共内容接口提供：

```text
deviceId, appId, appVersion, releaseChannel,
country, region, locale, supportedLocales,
gradeRange, ageRange, catalogRevision, manifestEtag
```

国家/地区和语言来自用户或管理员确认的应用设置。IP 只能提供首次建议，不能静默改变目录。

### 5.2 响应和本地状态

```text
PublicContentManifest
  manifestId, revision, issuedAt, expiresAt,
  minClientVersion, audience, courses[], cardPacks[],
  assetIndex, signature, keyId

LocalCoursePolicy
  courseId, enabled, order,
  allowedGrades[], assignedStudentIds[], updatedAt

CourseSyncState
  activeRevision, lastGoodRevision, lastCheckedAt,
  lastSuccessAt, status, errorCode, pendingRevision
```

同步顺序：

1. 使用 `If-None-Match` 请求适用清单。
2. 校验 HTTPS、清单签名、版本、适用范围和路径安全。
3. 只下载新增或变化的资源，并校验哈希。
4. 在临时目录组装并进行完整性复核。
5. 原子切换 active 目录，保留 last-good。
6. 按稳定 `courseId` 合并本地策略。
7. 发布本机课程目录变化事件，刷新学生端有效课程。

同步失败不得清空现有目录；没有任何成功目录时才显示“尚未取得课程目录”。

### 5.3 同步触发

| 触发 | 行为 |
| --- | --- |
| Windows 启动后 | 延迟检查一次，不阻塞主界面 |
| 网络恢复 | 对到期或失败目录进行去重续跑 |
| 每日维护窗口 | 使用 ETag 轻量检查 |
| 国家/地区/语言设置变化 | 重新计算适用目录并请求确认 |
| 用户点击“检查更新” | 立即查询，但复用正在执行的同一任务 |
| 服务端撤回通知/短轮询 | 取得新清单后按原子流程更新 |

同一设备、受众和目标修订只允许一个同步任务。结果未知先查本地清单和服务端修订，不重复下载完整资源。

## 6. 本地课程设置

### 6.1 保留字段

- 课程启用/隐藏；
- 本机展示顺序；
- 允许年级；
- 指定学生；
- 收藏和最近打开；
- 本地备注（不覆盖云端课程正文）；
- 缓存状态和最后同步时间。

### 6.2 合并规则

1. 云端新增课程默认按发布清单的 `defaultEnabled`，管理员可在本机调整。
2. 云端修订同一 `courseId` 时保留本地启用、排序和学生分配。
3. 云端撤回课程时本地策略保留为 tombstone，不再向学生展示。
4. 云端重新发布同一稳定 `courseId` 时，只有发布策略允许时才恢复；不得自动复活已被本机管理员隐藏的课程。
5. 云端按地区或语言不再返回课程时，视为当前受众不可用，不删除历史学习记录。
6. 本机学生分配只使用稳定学生 ID，不按姓名匹配。

## 7. 旧数据迁移

### 7.1 `platform_standard`

- 由平台管理员导入云端发布中心。
- 尽量保留原 `courseId`、来源、链接、允许域名、封面哈希和法律说明。
- 原平台课程包版本写入 `legacyOrigin`，便于审计和回滚。
- 云端正式发布且客户端成功同步后，旧包只读保留一个迁移周期。

### 7.2 `tenant_custom`

用户已经明确平台课程和机构课程均由平台管理员统一维护，因此现有机构课程不能继续由客户主机本地编辑。迁移流程：

1. 扫描本机机构课程并生成迁移清单。
2. 对相同链接、同名不同内容、无封面、无版权说明和失效链接进行自动检测。
3. 可可靠映射的课程批量提交平台待发布区。
4. 冲突课程生成报告，由平台管理员决定合并、修订或不发布。
5. 云端发布后按 `legacyCourseId` 映射本地策略和学生分配。
6. 未迁移课程在过渡期只读显示，并明确“本地旧课程”；到期前导出清单，不静默删除。

机构推荐课程只是内容分类或来源标签，不是多租户所有权。首期不允许机构账号自行维护，但数据模型保留可选 `sourceOrganizationLabel`，不得用它绕过平台发布审核。

## 8. 权限调整

删除或停用普通主机的下列能力：

```text
tenant_course_manage
platform_course_edit
platform_course_publish
platform_course_rollback
offline_course_package_import（日常权限）
```

保留并收窄为：

```text
course_read
course_local_policy_manage
course_sync_diagnose
course_cache_clear
```

前端隐藏和主进程 IPC 必须同时移除或拒绝，不能只删除按钮。旧调用返回明确的迁移提示和错误码，不执行写入。

## 9. 包体与性能评估

删除课程管理不会显著缩小 Windows 安装包：

| 调整 | 预计影响 |
| --- | --- |
| 只隐藏菜单 | 几乎 0 MB |
| 删除管理 UI，但保留运行模块 | 数十至数百 KB |
| 删除 Excel 导入、课程包生成/发布和相关运行代码 | 安装包预计减少约 0.5—1 MB；未压缩应用内容约 2.5—3 MB |

当前发布脚本将 Excel 课程导入及其依赖打成约 2.33 MB 的未压缩运行文件，压缩后约 0.42 MB；其余课程独立运行文件原始合计约 89.6 KB。Electron/Chromium、语言包和主应用仍占绝大多数。

本次调整的主要收益是减少重复维护、权限复杂度和版本不一致，不是显著减包。若要获得实际包体收益，构建配置必须排除已废弃文件，同时移除 `exceljs` 及发布脚本中的课程导入打包步骤。

## 10. 失败与对账

| 场景 | 自动处理 | 用户可见状态 |
| --- | --- | --- |
| 网络不可用 | 使用 last-good，按退避重试 | 离线使用上次目录 |
| 清单签名或哈希错误 | 拒绝新目录并上报审计 | 更新校验失败，旧目录可用 |
| 客户端版本过低 | 不切换不兼容目录 | 需要升级客户端 |
| 资源部分下载 | 续传同一 pending 修订 | 正在恢复下载 |
| 课程撤回 | 更新有效目录，保留策略 tombstone | 课程已由平台撤回 |
| 本地策略孤儿 | 等待相同 courseId 恢复或进入迁移报告 | 课程当前不可用 |
| 同步结果未知 | 比对 revision、ETag、目录哈希 | 正在核对，不重复下载 |

每日对账检查 active/last-good 指针、资源哈希、孤儿策略、卡住下载、撤回课程和学生端目录投影。修复使用原业务键，不新建替代目录。

## 11. 开发改造清单

| 范围 | 调整 |
| --- | --- |
| `src/main.tsx` | 删除课程编辑/导入/发布 UI；课程管理改为课程设置和同步状态 |
| `electron/main.cjs` | 移除本地课程写入、平台发布、Excel 导入 IPC；增加云端同步与本地策略 IPC |
| `electron/preload.cjs` | 收窄桥接接口，暴露只读目录、同步和本地策略方法 |
| 课程运行模块 | 保留目录解析、安全浏览和策略；新增公共清单客户端与缓存仓库 |
| 构建脚本 | 移除课程 Excel 运行时打包和废弃发布安全模块的强制包内检查 |
| 学生终端接口 | 继续返回当前学生的本机有效课程，不把云端完整目录直接暴露给学生端 |
| 操作手册和许可 | 更新导航、权限、迁移和离线说明 |

删除前必须做依赖追踪，避免误删仍被学生端安全浏览、域名白名单、封面缓存或目录校验复用的函数。

## 12. 统一工作包

本方案不再维护独立 W0–W5 编号和成本。唯一编号如下：

| 统一工作包 | Windows 交付 | 放行条件 |
| --- | --- | --- |
| `WP-003` | 参与公共清单、学生投影和撤回合同冻结 | Windows/Android 使用同一合同夹具通过 |
| `WP-008` | 公共目录同步、验签、last-good、缓存和诊断 | 断网、坏签名、部分下载不破坏旧目录 |
| `WP-009` | 启用、隐藏、排序、年级和学生分配 | 云端更新后本地策略不丢失、不串学生 |
| `WP-010` | 学生有效课程投影 v2 | v1/v2 兼容、ETag、tombstone 和目录事件通过 |
| `WP-014` | 平台/机构课程、语言、资产和策略迁移 | 迁移报告可追溯，未迁移课程不静默删除 |
| `WP-015` | Windows 主机及学生终端课程 MVP 验收 | 紧急撤回、回滚和真实设备端到端通过 |
| `WP-025` | 移除旧 UI、IPC、Excel、课程包发布和构建依赖 | 只在 MVP 灰度稳定和迁移只读期结束后执行 |

## 13. 验收矩阵

1. 同一云端发布在 Windows 和 Android 得到相同稳定课程 ID 和修订。
2. 中文、中国地区与英文、加拿大地区获得各自目录；用户切换设置后结果可解释。
3. 云端课程内容更新后，本机学生分配、排序和隐藏状态保持。
4. 断网、清单损坏、资源下载中断和进程退出均继续使用 last-good。
5. 撤回课程不会继续向新学生展示，也不会删除既有学习记录。
6. 旧 `tenant_custom` 课程有迁移清单、冲突报告和策略映射。
7. 已移除 IPC 不能通过开发者工具或旧 Renderer 调用绕过。
8. Windows 学生终端只收到当前学生有效课程。
9. A/B 构建记录实际安装包和 `app.asar` 差异，不用源码文件大小冒充发布包结果。
10. 候选构建、源码测试和正式发布分别记录，未签名候选不得称为正式版本。

## 14. 实施前冻结项

1. UI 是否从“精选课程”统一改名为“精品课程”。
2. 国家、地区、语言和年级的匹配优先级。
3. 本地策略对云端 `defaultEnabled` 的覆盖规则。
4. 旧机构课程迁移截止版本和未迁移课程的只读期限。
5. 灾备课程包是否保留在平台运维工具中，而不是普通主机 UI。
6. 公共内容签名算法、公钥轮换和紧急撤回机制。

本方案按 `PH-0 → PH-3 → PH-6` 实施。Windows 主机作为云端公共目录的受控消费者和本机学生分配节点；退出旧发布能力由 `WP-025` 单独放行。
