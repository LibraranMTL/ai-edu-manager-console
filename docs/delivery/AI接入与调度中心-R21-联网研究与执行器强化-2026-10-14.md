# AI 接入与调度中心 R21：联网研究与执行器强化

## 交付结论

本次在 R20 源码基础上完成 R21 Windows 候选。方案方向保留，仅补充两个安全边界：

1. “已配置 LLM API”不等于“已具备联网研究能力”。联网研究按具体协议和当前配置单独验证。
2. “Agent 自动通道可启动”不等于“已通过教育任务合同”。未完成合同验证的 Agent 继续手工交接，不进入分类、消化、卡片或研究的自动候选。

## 已实现

- LLM API 保持单一配置入口，新增协议选择：OpenAI 兼容 Chat Completions、OpenAI Responses、Anthropic Messages。
- 旧配置无损迁移为 Chat Completions，继续支持资料分类、消化与学习卡片；不会自动获得联网研究权限。
- 页面同时提供“结构化连接测试”和“联网研究合同测试”。联网研究测试要求：
  - 服务返回已完成的真实网页检索调用；
  - 每个采用的 `https` 来源都能对应供应商返回的网页引用；
  - 缺检索事件、缺引用、部分来源未引用、内网或本地 URL 均拒绝；
  - 配置、协议、模型或密钥变化后，旧研究资格立即失效。
- 通过研究测试的 LLM API 才进入 `research.v1`，调度顺序为已启用且合格的 Agent，随后是 LLM API；未知结果、取消和授权变化不回退。
- OpenClaw、QClaw、TRAE CLI、Qoder CLI 的既有自动通道状态会显示为“自动通道已连接”；在尚未通过教育结构化合同前，教育任务仍保持手工交接。Claude Code、Hermes 及其他桌面/网页工具也不因“已安装”被误标为自动执行。
- Host 包排除了独立发布的 Windows 学生/教师终端入口文件，保留 20 MiB `app.asar` 安全上限；终端产品源码与独立构建不受影响。

## 迁移说明

- 配置文件版本仍为 `edu-manager.llm-api.v1`；老文件读取时补充 `protocol=openai-chat` 与空的研究资格字段，不重写密钥。
- 保存 API 地址或协议、替换/清除密钥时，同时清除普通连接资格和研究资格，要求重新测试。
- 全局授权、学生/项目归属、任务执行身份、未知结果与等待手工交接状态保持不变，不因升级重复派发。
- LLM API 仍固定在自动 Agent 之后、手工交接之前；普通 Chat Completions 不会被研究任务选中。
