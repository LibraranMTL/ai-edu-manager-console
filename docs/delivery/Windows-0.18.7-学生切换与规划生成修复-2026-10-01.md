# Windows 0.18.7 学生切换与规划生成修复

日期：2026-10-01。状态：本地候选，未推送 Git、未更新官网。原工作区已有大量未提交变更，本次保留其他平台及项目资料相关工作。

## 四项反馈与修复

| 反馈 | 核实根因 | 本次处理 |
| --- | --- | --- |
| 首页选择赵书源却显示包晓闻待处理任务 | 首页仍对所有学生汇总，并优先选择有待处理资料的学生 | 首页任务、项目知识、风险、待处理数量限定当前学生及其关联项目；主操作不再跳转到其他学生 |
| Agent Tab 白底白字 | 使用了未定义的 `--primary`、`--muted` 变量 | 映射到既有主题深色和文字色；蓝、粉、绿、紫、橙五套主题已检查 |
| 编辑学生进入学情资料，红线下方内容多余 | 学生编辑与资料浏览复用同一页面但没有区分区域 | 标题改为“学生档案”，该入口隐藏分类关键词、分类 Tab、资料浏览和预览；学习资料入口继续保留资料浏览 |
| 规划不生成，“研究合同未通过” | 所有执行器的联网标志固定为否，规划服务没有实际 `search` 执行函数 | 接通 Codex CLI，研究请求去标识化，校验结构化结果和实际网页访问记录；改为明确的可用/未接通状态及错误原因 |

“研究合同”原本指程序内部约定的结果格式及能力校验，不是法律合同，也不需要用户签署。WorkBuddy、OpenClaw 的安装或登录状态不能等同于已接入本模块，新版明确标注尚未接入。

## 同时发现并处理的遗漏

- 学生切换后，旧的规划、选题和成长请求可能晚返回并覆盖新页面：增加学生范围校验、状态清理与请求失效处理。
- 首页曾以资料处理量补位成长证据数：取消这种替代；成长数据尚未读取时显示查看入口，不把未读取当作没有成长。
- 规划页面首次路径曾默认境内：首次改用学生档案中的规划路径和目标地区，已保存的用户规划设置仍优先。
- 规划设置未传给研究：目标地区、路线和关注点纳入查询及版本输入指纹。
- 同一学生重复更新可能并行写入：合并进行中的研究；研究期间档案或设置变化时拒绝写入过时结果。
- 不同规划 Tab 原先重复显示全部结论：按升学路径、择校、专业、职业展示对应结论；总览保留全部。
- 失败信息被重新读取覆盖，且无旧版时仍显示保留旧版：保留实际失败原因并区分有无旧版。
- 长规划结论曾复用短字段的 160 字限制：保留完整结论及其末尾的限制条件，增加专项测试。
