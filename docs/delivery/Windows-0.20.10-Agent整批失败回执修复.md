# Windows 0.20.10 Agent 整批失败回执修复

## 现场结论

- 赵书源批次 `student-digest-2026-10-08T13-03-11-ecf23d` 的 5 份原始资料仍在冻结批次中，没有被误标为已处理。
- Agent 返回内容明确为本地工具初始化失败、已处理 0 个，知识库与正式教育档案未修改。
- 结果接入层在外部任务结果上补了 `status: completed`，同时把真实回执放在 `data` 内；旧逻辑优先读取外层状态，造成界面语义错误。

## 修复

- 对回执候选按批次号、范围 ID、逐文件字段和 schema 评分，优先采用信息更完整的结构化内层结果。
- 当没有任何可识别的成功资料，且结果明确出现“本批未完成”“初始化失败”“处理 0 个”“无法写回回执”或“需要重试”时，统一判定为 `batch_execution_failed`。
- 整批失败不允许借助已有 `index.md` / `log.md` 推断完成；全部冻结资料保持待重试。
- 保留真实部分完成兼容：只要存在可核验的成功资料，仍按逐文件结果结算。
- 对项目工作区内已登记但随后稳定修改的来源，自动生成新版本并继续受控提取；若读取期间继续变化或发生版本竞争，仍会停止并保留资料。
- 扫描回执时明确排除 `edu-manager.digest-batch.v1` 输入清单，防止把批次 `files` 误认为已处理文件。

- 目标回归测试全部通过：资料消化结果/回执兼容 19 项、项目资料任务 16 项、版本与 P4 校验 20 项。
