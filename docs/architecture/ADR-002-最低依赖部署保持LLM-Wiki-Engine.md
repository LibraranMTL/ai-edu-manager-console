# ADR-002：最低依赖部署保持 LLM Wiki Engine

> 状态：接受  
> 日期：2026-07-21  
> 决策范围：P0 完成、P1 冻结及近期产品交付

## 决策

AI 教育管家现阶段以非专业用户能够直接部署、备份和恢复为首要约束，只启用现有 `llm-wiki-local` KnowledgeEngine。

- 正式知识继续保存为普通 Markdown、JSON 和 JSONL 文件。
- 不要求用户安装 Bun、GBrain、数据库、技能包、向量服务或额外常驻进程。
- GBrain 的评估适配器、脚本和虚构测试结果作为历史研究证据保留，但不进入默认启动、安装、升级、健康检查或发布闸门。
- 不迁移、移动或改写现有学生 ID、项目 ID、知识空间和物理路径。
- 保留 `KnowledgeEngine` 合同，以避免教育业务代码与本地文件实现耦合；可替换性是代码边界，不代表当前必须部署多个引擎。

本决策补充并覆盖 ADR-001 中关于继续推进 GBrain 生产适配的近期安排。ADR-001 的隔离评估结果仍有效，但相关后续工作全部搁置。

## 原因

1. 两套引擎在十个结构化教育治理场景中均为 `10/10`，当前没有可证明的准确性差距。
2. LLM Wiki Engine 无额外运行时和数据库，普通用户能用现有文件同步和备份工具维护。
3. GBrain 当前逐操作 CLI 路径不适合交互式生产使用；语义检索、权限隔离和恢复流程仍需额外验证。
4. 当前产品差异化重点是 Education Domain Protocol、成长证据审核和未成年人治理，而不是扩展通用知识基础设施。

## GBrain 重新评估条件

只有在出现以下任一明确需求时，才重新立项，而不是自动恢复：

- 现有本地精确检索在真实规模下无法满足质量或性能要求；
- 用户明确需要多跳图谱、长驻 MCP 或多主机共享知识服务；
- 能提供非专业用户可接受的一键安装、无凭据默认模式、备份恢复和卸载回退；
- 有独立资源完成未成年人数据隔离、权限和外部数据边界验收。

## 验收

- 默认依赖树不包含 GBrain、Bun 或独立数据库。
- 未安装任何外部知识引擎时，现有学生知识库、项目知识空间、成长证据、报告和导出均可工作。
- `llm-wiki-local` 通过 KnowledgeEngine 合同及十个教育场景测试。
- 文档和执行看板不再把 GBrain 补充验证作为 P0/P1 完成前提。
