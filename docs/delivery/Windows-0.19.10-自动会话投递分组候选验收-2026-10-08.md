# Windows 0.19.10 自动会话投递分组候选

日期：2026-10-08。Windows 0.19.10 / versionCode 250，候选标识 `session-status-20261008`。

## 本次变化

- 默认「待投递」，其余范围为「已投递」「全部」「回收站」。全部包含未回收的待投递与已投递记录。
- 以主机保存的真实投递回执判断分组，旧记录自动兼容，无需迁移或手工整理。一次成功投递即可归入已投递；该状态不代表已投递到所有可能目标。
- 成功项刷新后退出待投递，失败项保留；已投递会话可再投递到其他目标，也可主动移入回收站。不会在成功投递后自动回收或删除原记录。
- 已投递记录可展开查看最近投递时间和目标，最多显示最近 20 条回执；缺失时间明确显示未记录。
- 回收站恢复后，有投递历史的回到已投递，没有历史的回到待投递。下游依赖保护、许可、学生隔离、批量防重及部分失败处理沿用上一候选。
- 仍为最近 100 条授权会话、每页 20 条；全选只针对当前分组内的所有分页。

保留快速截屏与上一轮批量会话操作。本次未提交／推送 Git，未部署服务器或更新正式官网。

## 复测步骤

1. 打开「收集与整理 → 会话自动采集」，确认默认待投递不包含此前已经投递的会话。
2. 勾选至少两条，选择学生原始资料库或关联项目投递；成功项进入已投递，失败项留在待投递。
3. 进入已投递，展开投递明细，检查目标和时间；可再次投递到其他目标。
4. 将已投递项主动移入回收站再恢复，确认回到已投递；未投递项恢复后应回到待投递。
5. 切换学生，确认勾选及分组重置，显示该学生自己的记录。
