# 教师学生双主机知识协作、分发与 Agent 接入开发计划

> 调整版：以教育协作和成长治理为产品核心，以 LLM Wiki 为当前默认知识底座，GBrain 暂列远期可选接入。
>
> **2026-07-25 状态：本文件保留为 Syncthing 传输架构的历史设计基线。后续开发已改用
> [内置直传版后续开发计划](教师学生双主机知识协作与分发开发计划-v2-内置直传.md)：教育管家内置直传为默认方案，局域网优先，Tailscale 作为跨网络通道，Syncthing 仅作为可选高级兼容方案。**

## 一、计划定位

本计划面向两台或多台运行同一套 AI 教育管家 Windows 程序的主机。

不开发“教师主机版”和“学生主机版”，安装包、数据库结构、任务中心、知识引擎和升级通道完全相同。系统也不为一台主机写死永久类型。

教师和学生只是在一次协作关系中的角色：

- 某个用户可以在一项协作中作为教师；
- 某个本机学生档案可以在另一项协作中作为学生数据主体；
- 同一台主机可以同时拥有教学协作和个人学习协作；
- 角色由登录身份、协作绑定和对象权威关系决定，不由安装包或机器名称决定。

不包含家长端，不包含简化学生终端，也不把远程桌面作为日常协作主流程。

本计划同时合并原“Agent 双向信息共享与知识访问开发计划”，统一建设以下能力：

- 用户在原生 Agent 中明确要求后，把选定对话、附件和来源保存到教育管家；
- 本机 Agent 调用本机教育管家的学生或项目知识库；
- 教师 Agent 通过教师主机教育管家，调用学生授权的远程知识库；
- 教师把 Agent 任务提交到学生主机，由学生本地 Agent 调用本地资料执行；
- QClaw、OpenClaw、Codex 及后续 Agent 共用同一工具合同、任务协议和治理流程。

### 当前架构决策

1. 教育管家不建设另一个通用知识引擎，也不把产品定位为教育版 GBrain。
2. 当前正式运行继续使用低依赖、可读、可迁移的 LLM Wiki 文件结构和 `llm-wiki-local` KnowledgeEngine。
3. 教师学生双主机协作、权限、任务、证据治理和成长反馈由教育管家负责。
4. Tailscale 只负责网络可达，Syncthing 只负责受控文件传输，两者都不决定教育业务状态。
5. GBrain 不进入 P0 至 P3 的安装依赖、运行依赖或发布验收，暂列远期可选知识引擎适配。
6. 所有知识引擎能力必须通过 `edu-manager.knowledge-engine.v1` 边界调用，避免业务代码绑定具体后端。
7. Windows 端只维护一个统一客户端，不通过不同安装包区分教师和学生。
8. 节点身份保持中性，教师、学生和数据权威均通过可撤销的角色分配表达。

本计划采用四层职责边界：

```text
第一层：连接与传输
Tailscale + Syncthing
负责网络可达和受控文件传输

第二层：知识底座
LLM Wiki + llm-wiki-local KnowledgeEngine
负责可读知识、来源、检索、关系和快照

第三层：协作协议
NodeIdentity + Grant + Manifest + TaskEnvelope + Receipt
负责身份、授权、任务、幂等、一致性和审计

第四层：教育产品
学生 + 项目 + 资产 + 成长证据 + 成长模型 + 学情报告
负责教育工作流和长期成长闭环
```

边界原则：

- 不重复开发 Tailscale、Syncthing 已经解决的网络与传输能力；
- 不重复开发 GBrain 已经擅长的通用图谱、时间线和 MCP 基础设施；
- 优先建设教育领域对象、教师学生协作、证据治理和普通用户体验；
- 任何远期知识引擎替换不得改变上层学生、项目、权限、任务和成长证据语义。

本计划在现有 Tailscale 和 Syncthing 使用方式上建设“教育管家同步协调与教学协作层”：

```text
Tailscale
负责教师主机与学生主机之间的安全可达
        ↓
Syncthing
负责受控目录中的文件传输
        ↓
教育管家同步协调器
负责对象身份、同步清单、索引、版本、冲突和删除保护
        ↓
教育管家教学协作中心
负责任务、协作请求、远程知识访问、Agent执行和结果回传
```

核心目标：

> 教师和学生在各自主机上独立使用教育管家；教师可以布置任务、发送资料或发起协作；学生授权后，教师可以查看指定知识或让学生主机上的 Agent 处理本地资料；双方只交换必要资料、知识、结果和反馈。

Agent 侧的核心目标是：

> Agent 负责对话、理解和执行；教育管家负责长期存储、知识治理、权限、溯源与成长沉淀。

## 二、现状与问题

### 1. 当前可用基础

当前用户已经可以：

- 使用 Tailscale 连接不同网络中的主机；
- 使用 Syncthing 同步指定文件夹；
- 在两台主机上分别运行教育管家；
- 在各自主机上执行 Agent 和教育管家任务；
- 必要时通过远程桌面操作另一台主机。

当前教育管家也已经具备：

- 学生档案和学习项目；
- 文件资产与知识空间；
- 统一任务中心；
- Agent 任务和结果协议；
- 本机只读知识访问 `ArchiveAccess`；
- 设备配对和学生范围授权的基础机制。
- Agent 标准任务包和标准结果包；
- QClaw、OpenClaw、Codex 和人工执行适配基础；
- 可生成带 `edu://` 来源的最小知识上下文。

### 2. 当前方案的主要缺口

Syncthing 只能判断文件是否发生变化，不能判断：

- 文件属于哪个学生或项目；
- 文件是否已经登记为资产；
- 文件是否完成资料消化；
- 哪台主机是正式知识的权威主机；
- 两份成长证据哪个有效；
- 同一个任务是否已经执行；
- 冲突文件应采用、合并还是排除；
- 删除是否应该传播到其他主机。

因此可能出现：

- 文件已同步，但教育管家索引没有更新；
- 两台主机对同一资料重复消化；
- Agent 回执和消化批次 ID 不一致；
- 同一任务在两台主机重复执行；
- 正式知识出现多个冲突版本；
- 一台主机删除文件后，其他主机也被同步删除；
- 本机绝对路径在另一台主机失效；
- 学生成长证据重复发布或被错误覆盖。
- Agent 对话需要人工复制、保存位置和来源不统一；
- 本机 Agent 缺少面向普通用户的一站式知识调用入口；
- 教师 Agent 无法在统一授权下查询学生远程知识；
- 不同 Agent 可能各自形成独立收件箱、结果格式和状态；
- Agent 直接读取同步文件夹时可能绕过教育管家的权限、来源和索引。

### 3. 本计划的解决方式

不重新开发底层网络和文件传输，而是在其上增加教育管家能够理解的同步与协作协议：

```text
文件变化
→ 等待同步完成
→ 校验同步清单和内容哈希
→ 识别学生、项目、对象和版本
→ 更新教育管家索引
→ 创建待处理、冲突或协作任务
→ 按权威节点规则发布正式结果
```

## 三、核心原则

### 1. 学生主机是学生知识的权威节点

学生主机负责保存和正式发布：

- 学生原始资料；
- 学生个人知识库；
- 学生项目知识；
- 成长证据；
- 成长模型；
- 学情报告。

教师主机可以获得授权副本、查询结果和协作资料，但不能未经学生授权直接覆盖学生正式知识。

### 2. 教师主机是教师课程资料的权威节点

教师主机负责：

- 教师发布的课程资料；
- 教学任务模板；
- 教师反馈；
- 面向多个学生的公共项目资料；
- 教师形成的知识贡献。

学生采用教师资料后，学生主机建立自己的资产引用或个人版本。

### 3. 同步内容，不同步运行状态

可以同步：

- 指定原始资料；
- 教师课程资料；
- 学生提交成果；
- 已确认知识快照；
- 项目协作资料；
- 标准任务包和标准结果包；
- 知识贡献。

禁止直接同步：

- 本机任务账本；
- Agent 运行中状态；
- 本机索引数据库；
- 缓存和锁文件；
- 设备令牌；
- 本机路径配置；
- 正在写入的 Agent 回执；
- Electron 用户配置；
- 临时消化批次。

### 4. 优先远程执行，减少原始资料搬运

教师需要处理学生资料时，默认把任务发到学生主机，由学生主机上的 Agent 调用本地资料执行。

只有在教师必须使用自己主机上的特殊工具时，才请求传输指定原始文件。

### 5. 权限与协作分离

教师布置任务不等于获得学生资料访问权。

教师可以无资料权限地：

- 布置任务；
- 发送通知；
- 分发课程资料；
- 查看学生主动提交的成果。

教师访问学生知识、原始资料或本地 Agent 时，需要独立的协作授权。

### 6. 普通用户不需要理解底层技术

产品界面使用：

- 教师主机；
- 学生主机；
- 资料同步；
- 教学任务；
- 协作请求；
- 教师贡献；
- 冲突处理。

普通用户界面不直接展示：

- Tailscale IP；
- Syncthing Folder ID；
- 节点内部 UUID；
- JSON 任务包；
- 文件哈希；
- 网络端口。

### 7. Agent 明确触发，不采集全部对话

只有在以下情况下才保存 Agent 对话：

- 用户明确说“保存到教育管家”；
- 用户点击 Agent 中的保存工具；
- 用户在教育管家中主动粘贴或导入对话；
- 用户预先启用了范围明确的保存规则。

默认禁止后台同步 Agent 的全部聊天历史。

### 8. Agent 查询默认只读

Agent 可以在授权范围内搜索和读取知识，但普通查询权限不能用于：

- 删除原始资料；
- 覆盖正式知识；
- 修改学生基础事实；
- 直接发布成长证据；
- 绕过统一任务中心执行高风险操作。

### 9. 本机和远程使用同一工具合同

Agent 调用教育管家时，不需要区分底层是本机文件、Syncthing 快照还是远程学生主机。

请求统一指定：

```text
targetNodeId
studentId
projectId
operation
```

教育管家根据目标自动选择：

- 本机知识访问；
- 远程知识访问；
- 离线知识快照；
- 远程任务执行；
- 文件收件箱或人工粘贴降级。

## 四、目标架构

```text
统一教育管家节点 A                            统一教育管家节点 B
├── 按关系显示“教学协作”                      ├── 按关系显示“我的协作”
├── 本机课程与项目                            ├── 本机学生档案与项目
├── 统一任务中心                              ├── 统一任务中心
├── 本机知识与资料                            ├── 本机知识与资料
└── Agent 网关                                └── Agent 网关
          │                                             │
          └──────── 教育管家协作协议 ──────────────────┘
                        │
                 Tailscale：安全可达
                 Syncthing：受控文件传输

每台主机内部：

教育业务层
学生 / 项目 / 资料 / 证据 / 报告
        ↓
协作与治理层
授权 / 任务 / 清单 / 回执 / 审计
        ↓
KnowledgeEngine 稳定接口
        ↓
LLM Wiki 默认后端
```

协作方式分为四类：

1. 教师向学生布置任务；
2. 教师或学生发起协作请求；
3. 教师远程查询学生授权知识；
4. 教师提交任务到学生主机本地执行。
5. 教师或学生在 Agent 中把选定对话保存到教育管家。
6. 本机 Agent 调用本机知识，或在授权后通过教育管家调用远程知识。

选择性文件同步用于课程资料、提交成果、离线知识和必要原始资料；远程桌面只作为故障支持入口。

### KnowledgeEngine 边界

当前阶段统一通过 `edu-manager.knowledge-engine.v1` 提供：

- `health`；
- `importAsset`；
- `upsertClaim`；
- `getClaim`；
- `search`；
- `appendEvent`；
- `upsertRelationship`；
- `exportSnapshot`。

教师学生协作协议不得直接读写具体知识引擎内部数据库。业务层只保存稳定的教育对象 ID、逻辑 `edu://` URI、来源、权限和状态。

### GBrain 远期定位

GBrain 暂不参与当前开发阶段。未来只有在以下条件全部满足后，才进入独立接入评估：

- 向量或混合检索在真实教育语料中产生可量化收益；
- 多学生权限隔离、长期运行传输、备份恢复和回滚通过验收；
- 不要求普通用户额外理解或维护 Bun、数据库、MCP 和技能包；
- 可以作为 KnowledgeEngine 适配器或只读影子索引接入；
- 不改变 LLM Wiki 可读文件和教育领域对象的权威地位；
- 同一教育基准下的准确率、来源完整率、跨学生泄漏、延迟和迁移成本达到门槛。

## 五、主机与数据身份

### 1. NodeIdentity

每台完整主机拥有稳定且不带教师或学生类型的节点身份：

```text
NodeIdentity
├── nodeId
├── displayName
├── machineCode
├── ownerIdentityId
├── publicKey
├── capabilities[]
├── createdAt
└── revokedAt
```

节点身份不能由 IP、Windows 用户名或同步目录路径推导，也不能通过 `nodeType` 把一台机器永久标记为教师端或学生端。

### 2. PeerBinding

两台统一客户端配对后建立：

```text
PeerBinding
├── bindingId
├── participantNodeIds[]
├── roleAssignments[]
│   ├── nodeId
│   ├── actorId
│   ├── role: educator | learner_authority
│   ├── studentId
│   └── scope
├── sharedSecretRef
├── status
├── capabilities
├── createdAt
├── lastSeenAt
└── revokedAt
```

同一个学生可以分别绑定不同教师，但每个绑定拥有独立角色、权限和撤销状态。同一节点在不同绑定中可以承担不同角色。

### 3. 权威对象

每个可同步对象必须记录：

```text
ownerNodeId
authorityNodeId
studentId
projectId
objectId
objectType
```

正式知识只能由其权威节点发布。其他节点的修改以“贡献”形式返回。

“学生数据权威节点”是对象级属性，不是主机类型。例如同一台主机可以：

- 作为本机学生档案 A 的权威节点；
- 作为远程学生 B 的教师协作节点；
- 保存教师课程资料并成为这些资料的权威节点；
- 对不同对象分别拥有读取、贡献或发布权限。

### 4. AgentRegistration

每个接入教育管家的 Agent 都需要独立登记：

```text
AgentRegistration
├── agentId
├── agentType: qclaw | openclaw | codex | generic
├── displayName
├── hostNodeId
├── transport: mcp | http | file_inbox | manual
├── capabilities[]
├── status
├── lastSeenAt
└── revokedAt
```

设备配对不自动代表 Agent 获得知识访问权限；Agent 登记也不自动获得其他主机权限。

### 5. AgentGrant

Agent 的最小权限对象：

```text
AgentGrant
├── grantId
├── agentId
├── hostNodeId
├── allowedStudents[]
├── allowedProjects[]
├── allowedKnowledgeTypes[]
├── allowedOperations[]
├── createdAt
├── expiresAt
└── revokedAt
```

建议操作类型：

- `conversation:create`
- `asset:submit`
- `knowledge:search`
- `knowledge:read`
- `task:submit`
- `task:claim`
- `task:result`

### 6. ConversationArtifact

保存用户明确选中的 Agent 对话，而不是复制整个聊天数据库：

```text
ConversationArtifact
├── artifactId
├── agentId
├── hostNodeId
├── conversationId
├── messageIds[]
├── title
├── selectedMessages[]
├── attachments[]
├── sourceLinks[]
├── studentId
├── projectId
├── capturedAt
├── contentHash
└── governanceStatus
```

对话进入系统后默认先进入 Agent 收件箱和研究暂存层。

### 7. RemoteKnowledgeRequest

远程知识请求必须包含：

```text
RemoteKnowledgeRequest
├── requestId
├── sourceNodeId
├── targetNodeId
├── agentId
├── grantId
├── studentId
├── projectId
├── operation
├── query
├── knowledgeTypes[]
├── confirmedOnly
├── maxResults
├── createdAt
└── expiresAt
```

响应返回最小必要上下文、可信状态和 `edu://` 来源，不返回远程主机绝对路径。

### 8. StudentMaterialStatsSnapshot

教师端查看的不是学生文件目录，而是由学生权威主机在本地计算、按授权发送的资料统计快照：

```text
StudentMaterialStatsSnapshot
├── snapshotId
├── authorityNodeId
├── viewerNodeId
├── studentId
├── generatedAt
├── schemaVersion
├── totalCollectedCount
├── addedLast24Hours
├── addedLast7Days
├── addedLast30Days
├── stagingCount
├── managedAssetCount
├── pendingGovernanceCount
├── pendingDigestCount
├── digestedCount
├── digestFailedCount
├── projectCount
├── projectBreakdown[]
├── sourceTypeBreakdown[]
└── dataFreshness
```

统计口径：

- `totalCollectedCount`：已进入学生主机资料收集范围的资料数量；
- `stagingCount`：仍处于研究暂存层、尚未晋升为正式资产的数量；
- `managedAssetCount`：已经登记为正式文件资产的数量；
- `pendingGovernanceCount`：等待去重、筛选、确认或资产晋升的数量；
- `pendingDigestCount`：已经进入知识处理范围但尚未完成消化的数量；
- `digestedCount`：已经形成有效消化回执的数量；
- `digestFailedCount`：消化失败或需要人工处理的数量；
- `projectBreakdown`：按授权项目汇总资料、待消化和已消化数量；
- `sourceTypeBreakdown`：按本地上传、屏幕采集、Agent 保存、教师分发等来源汇总。

隐私边界：

- 默认只发送数量、阶段、项目汇总和快照时间；
- 不发送文件名、相对路径、绝对路径、内容摘要或原始文件；
- 教师只能查看已绑定学生以及授权项目的统计；
- 更细的文件列表仍需单独的协作授权；
- 学生可以暂停统计共享，暂停后教师端显示“统计共享已关闭”；
- 学生主机离线时，教师端只显示最后一次快照，并标记“数据可能已过期”。

刷新机制：

```text
学生主机资料状态变化
→ 本地重新计算增量统计
→ 生成带节点身份和时间的统计快照
→ 通过协作协议发送教师主机
→ 教师端校验节点、学生和授权
→ 更新学生列表和资料统计看板
```

不得让教师端高频远程遍历学生目录。在线状态通过心跳维护，统计采用事件触发并设置最短刷新间隔；无变化时不重复发送完整快照。

## 六、同步目录与协议

### 1. 独立受控同步目录

教育管家不直接同步完整学生知识库根目录，而是建立独立协作目录：

```text
education-collaboration/
├── protocol.json
├── nodes/
├── envelopes/
│   ├── teacher-node-id/
│   └── student-node-id/
├── receipts/
├── snapshots/
├── contributions/
├── conflicts/
└── quarantine/
```

每个节点只写入自己拥有的命名空间，避免两个节点同时修改同一协议文件。

### 2. SyncManifest

每份同步资料拥有清单：

```text
SyncManifest
├── protocolVersion
├── envelopeId
├── senderNodeId
├── targetNodeId
├── objectId
├── objectType
├── studentId
├── projectId
├── ownerNodeId
├── authorityNodeId
├── revision
├── relativePath
├── sha256
├── size
├── syncPolicy
├── createdAt
└── expiresAt
```

系统不得仅根据文件名判断资料身份。

### 3. 同步稳定检测

Syncthing 将文件写入本机后，教育管家执行：

```text
发现变化
→ 等待文件大小和修改时间稳定
→ 检查清单是否完整
→ 校验文件大小和 SHA-256
→ 校验发送节点和目标节点
→ 检查学生、项目和权限
→ 原子导入本机目录
→ 更新资产索引或任务中心
→ 写回处理回执
```

不完整、过期、越权或哈希错误的资料进入隔离区，不能直接进入知识库。

### 4. 同步策略

支持以下用户可见策略：

| 策略 | 含义 |
| --- | --- |
| 仅本机 | 不离开当前权威主机 |
| 远程查询 | 不同步文件，只允许授权搜索和读取 |
| 仅同步知识 | 同步摘要、概念、实体等知识快照 |
| 同步指定资料 | 传输用户选择的原始文件 |
| 同步当前项目 | 传输当前协作项目所需内容 |
| 临时共享 | 到期后停止访问，不再继续分发 |
| 教师课程分发 | 从教师主机发送到学生资料收件箱 |

### 5. 删除保护

同步删除不直接执行物理删除。

处理流程：

```text
收到删除标记
→ 生成 tombstone
→ 移入本机协作回收站
→ 更新索引为“已移除”
→ 保留恢复期限
→ 用户确认后再执行物理清理
```

## 七、核心业务功能

### 1. 教师布置学习任务

教师选择学生，填写：

- 任务名称；
- 任务说明；
- 参考资料；
- 截止时间；
- 预期提交内容；
- 是否允许学生使用 Agent；
- 是否需要教师反馈。

任务状态：

```text
已创建
→ 已发送
→ 学生已收到
→ 已接受 / 稍后处理 / 无法完成
→ 进行中
→ 已提交
→ 教师已反馈
→ 已完成
```

布置任务本身不授予教师知识库权限。

### 2. 教师主动发起协作

教师可以申请：

- 查看指定项目知识；
- 查看指定原始资料；
- 获取项目上下文；
- 在学生主机上执行 Agent 任务；
- 下载指定文件；
- 向学生提交知识贡献。

请求必须说明：

- 协作目的；
- 涉及学生和项目；
- 申请操作；
- 资料范围；
- 有效期限。

学生端提供：

```text
[同意] [调整范围] [拒绝]
```

### 3. 学生主动请求教师协助

学生选择：

- 需要协助的任务或项目；
- 允许查看的资料；
- 是否允许教师调用学生主机 Agent；
- 是否允许下载指定文件；
- 协作有效期。

教师处理后，以结果和贡献返回，不直接覆盖学生正式知识。

### 4. 教师资料分发

教师可以向一个或多个学生发送：

- 课程讲义；
- 作业模板；
- 项目要求；
- 教师反馈；
- 参考链接；
- 公共项目资料。

学生主机收到后进入“教师资料收件箱”。

学生可以：

- 采用并登记为资产；
- 加入指定课程或项目；
- 暂时保留；
- 拒绝；
- 删除本机接收记录。

### 5. 学生成果提交

学生可以提交：

- 文件；
- 项目成果；
- 知识摘要；
- Agent 处理结果；
- 任务完成说明。

教师端接收的是学生明确提交的内容，不是学生知识库的自动镜像。

### 6. 远程知识查询

学生授权后，教师主机可以调用学生主机的知识网关：

- 搜索知识；
- 读取指定知识；
- 查看项目知识；
- 获取最近变化；
- 生成带来源的最小上下文；
- 查看原始资料元数据和允许的预览。

查询结果使用：

```text
edu://student/{studentId}/knowledge/{resourceId}
edu://project/{projectId}/knowledge/{resourceId}
```

不得返回学生主机绝对路径。

### 7. 学生主机本地 Agent 执行

教师提交远程任务后：

```text
教师主机创建标准 TaskEnvelope
→ 任务包进入协作同步目录
→ 学生主机导入统一任务中心
→ 学生确认或由预授权规则接受
→ 学生本地 Agent 执行
→ 生成标准 TaskResult
→ 返回教师主机
→ 教师查看结果和反馈
→ 学生决定是否进入正式知识
```

任务必须包含唯一：

- `taskId`；
- `executionId`；
- `idempotencyKey`；
- `sourceNodeId`；
- `targetNodeId`。

同一个执行批次只能由学生权威主机执行一次。

### 8. 教师知识贡献

教师形成的：

- 摘要；
- 概念；
- 实体；
- 项目建议；
- 作品反馈；
- 能力观察；
- 成长证据建议。

统一作为 `KnowledgeContribution` 返回学生主机。

学生主机处理：

```text
[接受并采用] [保留观察] [拒绝]
```

成长证据必须继续经过教育管家现有证据和发布规则，不能由教师主机远程直接发布。

### 9. 在 Agent 中保存对话到教育管家

用户可以在本机原生 Agent 中提出：

> 把这段对话和附件保存到教育管家，关联到我的 Physics IA 项目。

Agent 调用统一工具：

```text
conversation.save
```

处理流程：

```text
用户明确要求保存
→ Agent 选择相关消息、附件和来源
→ 教育管家检查 AgentGrant
→ 创建 ConversationArtifact
→ 内容哈希和重复检测
→ 写入 Agent 资料收件箱
→ 进入研究暂存层
→ 后续资料治理和知识消化
→ 返回记录 ID、保存位置和处理状态
```

如果学生或项目不明确，系统必须要求选择，不能由 Agent 自行猜测。

### 10. Agent 调用本机教育管家知识库

本机 Agent 统一调用：

- `knowledge.search`；
- `knowledge.read`；
- `knowledge.list_changes`；
- `knowledge.context`。

例如：

```text
学生本机 Agent
→ 本机教育管家 Agent 网关
→ ArchiveAccess
→ 学生或项目知识库
→ 返回带 edu:// 来源的最小知识上下文
→ Agent 生成回答
```

默认只返回已确认知识。草稿、推断和待观察内容必须显式请求并标明状态。

### 11. Agent 通过教育管家调用远程知识库

教师在教师主机 Agent 中提出：

> 查询赵书源授权的物理项目知识，分析实验设计中还存在什么问题。

处理流程：

```text
教师本机 Agent
→ 教师主机 Agent 网关
→ 检查 AgentGrant
→ 检查 CollaborationGrant
→ 生成 RemoteKnowledgeRequest
→ 通过 Tailscale 访问学生主机知识网关
→ 学生主机按授权范围执行搜索
→ 返回最小上下文、可信状态和 edu:// 来源
→ 教师 Agent 生成回答
→ 两台主机记录访问事件
```

教师 Agent 不直接获得学生主机令牌、物理路径或完整知识库副本。

### 12. 统一 Agent 工具合同

第一期统一工具：

```text
conversation.save
保存用户选定的 Agent 对话

asset.submit
提交附件、网页、截图或文件

knowledge.search
搜索本机或授权远程知识

knowledge.read
读取指定知识资源

knowledge.context
获得当前任务所需的最小上下文

task.submit
向本机或远程主机提交 Agent 任务

task.status
查询任务或资料处理状态

task.result
回写标准处理结果
```

适配顺序：

1. 支持 MCP 的 Agent 直接调用工具；
2. 支持本机 HTTP 的 Agent 调用教育管家 API；
3. QClaw 等通过通用文件收件箱；
4. 无接口 Agent 使用复制指令和粘贴结果。

四种方式共用同一对象、权限、任务状态和治理流程。

### 13. 教师查看学生主机资料统计

学生主机在线且允许共享统计时，教师可以在“教学协作中心”查看：

- 最近 24 小时、7 天和 30 天新增资料数量；
- 研究暂存、正式资产、待治理、待消化、已消化和失败数量；
- 已授权项目的资料数量和知识消化进度；
- 资料来源分布；
- 最近一次统计时间和数据新鲜度；
- 是否存在积压、失败或长时间未消化的风险提醒。

教师点击统计卡片时，第一层只查看聚合数据。若需要查看具体文件，必须另行申请文件列表或原始资料访问权限。

统计数据只用于协作提醒和教学支持，不能直接推断学生能力、学习态度或成长结论，也不能自动写入成长模型。

## 八、协作授权

### 1. CollaborationGrant

```text
CollaborationGrant
├── grantId
├── issuerNodeId
├── granteeNodeId
├── authorityNodeId
├── studentId
├── projectIds[]
├── operations[]
├── knowledgeTypes[]
├── assetIds[]
├── createdAt
├── expiresAt
└── revokedAt
```

### 2. 操作权限

建议包括：

- `task:assign`
- `material:send`
- `material:stats:read`
- `submission:read`
- `knowledge:search`
- `knowledge:read`
- `asset:preview`
- `asset:download`
- `agent:execute`
- `contribution:create`

默认不提供：

- `asset:delete`
- `knowledge:overwrite`
- `growth:publish`
- `device:control`

### 3. 长期课程授权

学生可以为固定教师设置课程范围授权，例如：

```text
教师：王老师
范围：高一物理
期限：本学期

允许：
布置任务
查看该课程范围的资料统计
查看该课程项目知识
查看主动提交的成果
发起低风险 Agent 整理任务

禁止：
访问其他学科
删除或覆盖资料
查看私人对话
发布正式成长证据
```

超出范围时必须重新发起协作请求。

### 4. Agent 与协作授权组合

远程 Agent 查询必须同时满足：

```text
AgentRegistration 有效
        +
AgentGrant 允许当前操作
        +
CollaborationGrant 允许当前教师访问当前学生或项目
        +
目标学生主机在线且没有暂停远程访问
```

任何一项不满足都应拒绝请求，并返回普通用户可理解的原因。

设备配对、教师协作授权和 Agent 授权必须分别撤销，不能共用一个永久万能令牌。

## 九、冲突与一致性

### 1. 单一写入权

正式对象遵守：

- 学生知识由学生主机写入；
- 教师课程资料由教师主机写入；
- 其他主机只创建新版本或贡献；
- 同步副本默认只读；
- 共享任务由目标主机执行。

### 2. 冲突类型

教育管家需要识别：

- 文件内容冲突；
- 对象版本冲突；
- 同一资料重复登记；
- 任务重复执行；
- 旧结果覆盖新结果；
- 删除与修改冲突；
- 权威节点不一致；
- 不同版本协议不兼容。

### 3. 冲突处理

普通用户只看到：

```text
发现两个不同版本

教师版本：7月20日
学生版本：7月22日

[保留学生版本]
[保留教师版本]
[两个都保留]
[稍后处理]
```

原始冲突文件进入隔离区，不直接混入正式知识。

### 4. 索引重建

每台主机提供：

- 根据同步清单重建协作索引；
- 根据正式文件重新核对资产状态；
- 查找缺失对象；
- 查找未登记文件；
- 修复过期本机路径；
- 输出重建报告。

## 十一、远程桌面定位

远程桌面继续作为外部辅助工具，适用于：

- 软件安装；
- 网络配置；
- 故障排查；

第一阶段教育管家只提供：

- 远控工具快捷入口；
- 当前远控状态提示；
- 打开前确认；
- 协作日志中的远控记录。

不在教育管家中重新开发完整远程桌面协议，也不允许教师通过协作授权自动获得桌面控制权。

## 十二、开发顺序

前一阶段必须完成自动测试、真实双机行为验收和回滚演练，才能进入下一阶段。不得以单机模拟、接口返回成功或文件已出现代替双机业务验收。

### P0A：同步一致性与安全基线

目标：先解决“文件同步了，但教育管家不知道发生了什么”的问题。本阶段不接入远程 Agent，不开放远程知识查询。

#### P0A.1 节点身份与受控目录

- [ ] 建立稳定 `NodeIdentity` 和 `PeerBinding`，不以 IP、主机名或路径识别节点。
- [ ] 支持两个统一客户端配对、暂停、恢复和撤销，并为具体协作分配角色。
- [ ] 实现 `RoleAssignment`，允许同一节点在不同协作中承担 educator 或 learner_authority。
- [ ] 角色调整只修改协作关系，不迁移数据、不更换安装包、不重建节点身份。
- [ ] 所有写入权限依据对象 `authorityNodeId` 判断，不依据当前界面或默认使用模式判断。
- [ ] 创建独立 `education-collaboration` 目录，每个节点只写自己的命名空间。
- [ ] 自动排除任务账本、索引、缓存、令牌、运行状态和本机配置。
- [ ] 接管现有 Syncthing 文件夹时只建立基线，不自动移动或删除原文件。

#### P0A.2 清单、导入与幂等

- [ ] 实现 `SyncManifest`、完成标记、对象版本和 SHA-256 校验。
- [ ] 文件稳定且清单完整后，才允许导入资产索引。
- [ ] 校验发送节点、目标节点、学生、项目、对象类型和协议版本。
- [ ] 同一对象重复到达只更新接收状态，不创建重复资产或重复任务。
- [ ] 写回接收、采用、拒绝、隔离或失败回执。

#### P0A.3 冲突、删除与恢复

- [ ] Syncthing 冲突副本一律进入隔离区。
- [ ] 建立 tombstone、协作回收站和恢复动作。
- [ ] 同步删除不得直接触发物理删除。
- [ ] 提供增量重建索引和完整重建索引。
- [ ] 同步不是备份，单独建立可恢复的协作状态快照。

#### P0A.4 最小状态界面

- [ ] 显示节点在线、最近同步、等待导入、异常、冲突和隔离数量。
- [ ] 学生数据权威节点生成最小 `StudentMaterialStatsSnapshot`，至少包含资料总数、最近 7 天新增、待治理、待消化、已消化和失败数量。
- [ ] 教师端学生列表显示在线学生的资料统计摘要。
- [ ] 学生离线时显示最后快照时间和过期状态。
- [ ] 提供学生端“共享资料统计”开关。
- [ ] 提供“立即检查同步”“重建索引”“暂停全部协作同步”。
- [ ] 所有失败显示对象、原因、恢复动作和审计记录。

**P0A 发布门槛：**

1. 文件完成传输前进入正式索引的数量为 `0`。
2. 同一对象重复同步产生的重复资产和重复任务均为 `0`。
3. 任务账本、本机设置、令牌和缓存进入同步目录的数量为 `0`。
4. 冲突文件进入正式知识库的数量为 `0`。
5. 删除传播导致物理文件不可恢复的数量为 `0`。
6. 断网、重启和重连后，清单、文件和资产索引一致率为 `100%`。
7. 完成至少一次备份恢复和一次索引重建演练。
8. 教师端统计与学生端相同口径本地统计一致率为 `100%`。
9. 教师端统计响应中出现文件名、路径或内容的数量为 `0`。
10. 学生关闭统计共享后，教师端不再获得新快照。
11. 同一客户端可以同时显示教学协作和个人学习协作，数据与权限不串用。
12. 修改默认使用模式不会改变已有授权、对象权威或数据目录。

### P0B：教师学生最小任务闭环

目标：在不开放远程资料浏览的前提下，先实现教师任务和学生结果的可靠往返。

#### P0B.1 教师布置任务

- [x] 教师选择学生，填写任务说明、截止时间、提交要求和可选附件。
- [x] 生成标准 `TaskEnvelope`，包含唯一 `taskId`、目标节点、学生和幂等键。
- [x] 学生端支持接受、稍后处理、无法完成和拒绝。

#### P0B.2 学生提交与教师反馈

- [x] 学生提交成果后生成标准结果事件，并绑定原任务和结果标识。
- [x] 教师端收到结果并回到原任务，不创建另一条无关联任务。
- [x] 教师反馈、补充要求和关闭状态同步回学生端。
- [x] 旧版本、重复结果和身份冲突进入幂等处理或隔离，不覆盖当前任务。

#### P0B.3 资料分发与协作请求

- [x] 教师向单个学生分发资料，学生可采用、加入项目、暂存或拒绝。
- [x] 教师和学生均可发起协作请求。
- [x] 协作授权与任务分配分离，未授权任务不自动获得资料读取权。
- [x] 教师贡献以 `KnowledgeContribution` 草稿返回，不直接写入学生正式知识。

**当前验证状态（2026-07-24）：**

- 协议、双节点离线交换、重复导入、冲突隔离、任务状态机、附件隔离与界面契约已通过自动化测试。
- 项目资料采用支持学生原始资料库和所选项目原始资料库；同一批附件重复采用不会生成重复副本。
- Windows 0.10.8 已补齐学生或协助方随结果返回成果附件，接收方只能从受控协作收件箱查看，不自动写入正式资料库；重复同步保持幂等。
- 生产渲染构建、400 项全量回归及主机/学生终端候选包审计通过；安装包内部确认包含任务编排、成果附件选择和接收入口。P0B 的教师任务、学生协助请求、附件采用与结果往返仍需在两台真实主机上完成发布前验收。

**P0B 发布门槛：**

1. 教师任务、学生接受、结果提交、教师反馈和任务关闭完整跑通。
2. 同一任务在多次同步和重启后只执行、只结算一次。
3. 未授权任务不能读取学生原始资料。
4. 教师贡献不能直接覆盖学生正式知识和成长证据。
5. 两台主机离线积压后恢复，任务状态一致率为 `100%`。

### P1：本机 Agent 双向接入

目标：先让 Agent 与本机教育管家可靠交换资料和知识，再考虑跨主机调用。

#### P1.1 统一 Agent 合同

- [ ] 定义 `AgentRegistration`、`AgentGrant`、`ConversationArtifact`、`TaskEnvelope`、`TaskResult` 和回执 Schema。
- [ ] QClaw、OpenClaw、Codex 和人工执行共用同一任务账本和状态链。
- [ ] 提供 MCP、本机 HTTP、文件收件箱和人工粘贴入口。
- [ ] 自动接口不可用时平滑降级，不丢失任务身份和来源。

#### P1.2 保存对话到教育管家

- [ ] 实现 `conversation.save`，只保存用户明确选择的消息、附件和来源。
- [ ] 默认进入研究暂存层，不直接成为正式知识。
- [ ] 使用内容哈希和幂等键防止重复保存。
- [ ] 支持确认学生、项目、用途，无法判断时要求用户选择。
- [ ] 每次保存、失败和降级均显示明确反馈和可打开记录。

#### P1.3 本机知识调用

- [ ] 提供本机 `knowledge.search`、`knowledge.read`、`knowledge.list_changes` 和 `knowledge.context`。
- [ ] 通过 KnowledgeEngine 接口访问，不直接读取后端内部数据库。
- [ ] 返回 `edu://` URI、来源和可信状态，不暴露绝对路径。
- [ ] 默认只返回已确认知识，草稿和推断必须明确标记。
- [ ] 提供 Agent 自动访问总开关、限流、超时和审计。

**P1 发布门槛：**

1. 至少一个本机 Agent 能保存选定对话和附件，并可在教育管家中打开。
2. 相同对话重复提交不产生重复资料。
3. Agent 能搜索和读取授权本机知识，并返回完整来源。
4. 关闭自动访问后，自动调用停止，人工导入仍可使用。
5. Agent 解析失败不会卡住主程序，原始结果可进入人工粘贴流程。

### P2：受控远程知识与本地数据执行

目标：默认让任务靠近数据执行；只有小范围只读知识才跨主机查询。

#### P2.1 远程任务在学生主机执行

- [ ] 教师提交标准任务，学生确认后由学生主机本地 Agent 执行。
- [ ] Agent 只获得任务所需的最小上下文。
- [ ] 学生可查看任务使用了哪些资料和返回了哪些产物。
- [ ] 同一执行批次只能被一个执行器领取。
- [ ] 大型或敏感原始资料默认不传输到教师主机。

#### P2.2 远程只读 ArchiveAccess

- [ ] 将搜索、读取、变化列表和上下文包扩展为跨主机受控服务。
- [ ] 同时校验 `AgentGrant` 和 `CollaborationGrant`。
- [ ] 使用 `targetNodeId` 路由，不向 Agent 暴露远程令牌和物理路径。
- [ ] 查询默认只返回已确认知识，并记录请求、返回资源和拒绝原因。
- [ ] 越权、过期和撤销后的请求立即拒绝。

#### P2.3 按需资料与离线快照

- [ ] 原始资料默认只返回元数据和安全预览。
- [ ] 下载指定文件必须单独申请、确认并记录。
- [ ] 大文件支持中断、重试和哈希校验。
- [ ] 支持具有版本、时间和有效期的只读知识快照。
- [ ] 教师对快照的修改以贡献返回，不直接修改学生权威知识。

#### P2.4 多 Agent 执行兼容

- [ ] 学生可选择 QClaw、OpenClaw、Codex 或人工执行。
- [ ] 切换执行器不改变任务和结果协议。
- [ ] 执行结果必须经过批次、权限、来源和产物校验。
- [ ] Agent 不得直接发布正式成长证据。

**P2 发布门槛：**

1. 教师可以查询一个已授权项目的已确认知识，来源完整率为 `100%`。
2. 未授权学生、项目和原始资料的跨范围返回数量为 `0`。
3. 大型资料任务能够在学生主机本地完成，只回传必要结果。
4. 同一任务切换执行器后仍回到同一任务中心。
5. 学生主机离线时，只能使用有效快照或人工资料包，不伪装为实时查询。
6. 权限撤销后，新请求立即失效，历史访问记录仍可审计。

### P3：普通用户产品化与规模化

#### P3.1 一站式设置

- [ ] 教师创建邀请，学生接受并选择学生档案。
- [ ] 同一安装包根据协作邀请自动建立角色关系，不要求重新安装或切换程序版本。
- [ ] 提供“主要用于教学 / 主要用于个人学习”导航偏好，并允许随时切换。
- [ ] 同时拥有两种角色时显示“教学协作”“我的协作”两个入口。
- [ ] 自动检查 Tailscale 可达性和 Syncthing 受控目录。
- [ ] 自动生成排除规则和首轮同步清单。
- [ ] 普通界面不要求用户理解 IP、MCP、HTTP、哈希或清单文件。

#### P3.2 多学生与批量操作

- [ ] 教师按学生筛选任务、提交、授权和同步状态。
- [ ] 教师按学生筛选资料统计，并按最近新增、待治理、待消化、失败和数据过期状态排序。
- [ ] 提供最近 7 天新增曲线、项目分布、来源分布和消化覆盖率。
- [ ] 统计卡片可进入详情，但具体文件列表继续受独立权限控制。
- [ ] 支持批量分发资料和任务。
- [ ] 每名学生保持独立权限和知识范围。
- [ ] 批量操作不得产生跨学生资料串档。

#### P3.3 诊断、恢复与资源控制

- [ ] 诊断网络不可达、Syncthing 暂停、协议不兼容和索引不一致。
- [ ] 提供安全重试、重新登记、重建索引和恢复快照。
- [ ] 提供同步、远程查询、远程任务和 Agent 自动访问总开关。
- [ ] 常驻服务按需启动，主程序关闭自动运行后不得持续消耗资源。

#### P3.4 Agent 与协作界面产品化

- [ ] 提供 Agent 登记、测试、暂停、恢复和撤销界面。
- [ ] 提供资料收件箱、任务记录、知识访问记录和权限记录。
- [ ] 用户可从回执直接打开对应资料、任务或知识。
- [ ] 统一显示本机调用、远程调用、快照和人工降级状态。

#### P3.5 远程支持入口

- [ ] 仅配置外部远程桌面工具快捷入口。
- [ ] 打开前要求学生确认，并记录目的、开始和结束时间。
- [ ] 不在教育管家中自研远程桌面协议。

**P3 发布门槛：**

1. 普通教师和学生无需查看网络地址即可完成设置和日常协作。
2. 多学生批量测试中跨学生泄漏数量为 `0`。
3. 常见同步、权限和任务故障均能显示可执行的恢复动作。
4. 一键暂停后停止协作后台任务，两个主机仍可独立使用教育管家。
5. 真实普通用户完成首次配对、发送任务和返回结果的流程不需要修改协议文件。
6. 教师可以从在线学生列表查看资料统计，并准确识别积压和失败状态。
7. 离线、关闭共享和授权撤销三种情况下，教师端均不会继续显示为实时数据。
8. 一台主机同时作为教学协作节点和本机学生数据权威节点时，两套权限均能正确工作。

- 教师通过统计接口推导未授权项目存在性；
- 学生关闭统计共享后仍持续上报；
- 伪造旧快照或其他学生快照覆盖当前学生统计。
- 通过切换到“教学协作”界面提升访问权限；
- 同一节点多角色导致任务或学生档案串用；
- 已撤销角色继续访问历史授权对象。

### 4. 性能测试

- 大量小文件同步；
- 大型图片和视频传输；
- 文件同步时主程序响应；
- 索引增量更新；
- 多学生并发任务；
- 离线积压后批量恢复；
- 文件监听去抖和重复事件；
- 暂停协作后的后台资源消耗；
- 大型 Agent 对话和多附件异步导入；
- 高频知识查询限流；
- 远程上下文大小限制；
- 关闭 Agent 自动访问后的轮询和资源消耗；
- 教师端多学生列表和任务列表的增量刷新；
- 多名在线学生统计快照并发更新；
- 资料变化事件合并和统计刷新节流；
- 学生资料数量较大时，本地统计不得同步遍历全部文件；
- Syncthing 大批量事件不得在 UI 主线程逐项处理；
- 冷启动、空闲、同步中和批量恢复四种状态分别记录 CPU、内存和磁盘占用。

### 5. 阶段发布质量门槛

每个阶段都必须输出可审计的测试报告，至少包含：

| 指标 | 门槛 |
| --- | --- |
| 跨学生资料或知识泄漏 | `0` |
| 未授权远程访问成功数 | `0` |
| 重复资产、重复任务、重复结算 | `0` |
| 已完成同步对象的文件、清单与索引一致率 | `100%` |
| 正式知识和远程查询来源完整率 | `100%` |
| 冲突文件误入正式知识库 | `0` |
| 不可恢复的同步删除 | `0` |
| 关闭协作后的本机核心功能可用率 | `100%` |
| 教师端与学生端同口径统计一致率 | `100%` |
| 统计响应中的文件名、路径和内容泄漏 | `0` |

测试证据必须区分：

- 单元测试；
- 单机集成测试；
- 两台真实 Windows 主机行为测试；
- 断网、重启、版本差异和恢复演练；
- 合成测试数据与真实脱敏教育场景。

不得用“接口返回成功”“文件已经存在”或“合成场景通过”替代真实双机端到端验收。

## 十四、现有方案迁移

### 1. 接管而不是破坏

对于现有 Tailscale 和 Syncthing 用户：

1. 识别现有同步文件夹；
2. 生成文件清单和备份；
3. 标记哪些目录是内容、运行状态或风险目录；
4. 建立新的独立协作目录；
5. 现有文件先登记为基线版本；
6. 不因首次登记重新消化全部资料；
7. 不自动删除或移动现有文件；
8. 用户确认后逐步停止同步旧运行目录。

对于现有 Agent 任务和收件箱：

1. 保留现有 `qclaw-inbox`、`qclaw-results` 和人工任务包；
2. 在通用 Agent 网关中建立兼容映射；
3. 新任务逐步写入通用收件箱；
4. 旧目录结果继续可以被统一任务中心读取；
5. 不重复导入已经完成的任务和回执；
6. 完成兼容验证前不删除旧目录。

### 2. 首次基线

首次启用时记录：

- 文件数量；
- 总大小；
- 相对路径；
- 内容哈希；
- 学生和项目归属；
- 当前教育管家索引状态；
- 冲突文件；
- 缺失文件。

两台主机确认基线后才开始增量协作。

### 3. 回滚

迁移失败时：

- 停止教育管家协作监听；
- 保留原 Syncthing 配置；
- 恢复迁移前索引备份；
- 不删除新增协作目录；
- 输出失败清单供人工检查。

## 十五、风险与控制

| 风险 | 控制 |
| --- | --- |
| Syncthing 冲突文件被误当正式知识 | 冲突隔离和权威节点规则 |
| 两台主机重复执行任务 | 唯一任务 ID、执行批次和目标主机 |
| 文件传输未完成就被扫描 | 稳定检测、清单完成标记和哈希校验 |
| 同步删除传播 | tombstone、回收站和延迟物理删除 |
| 教师访问超范围资料 | CollaborationGrant 和学生确认 |
| 教师贡献覆盖学生知识 | 贡献申请，不直接多主写入 |
| 本机路径在其他主机失效 | 对外只使用逻辑 URI 和相对路径 |
| Tailscale 在线不代表应用授权 | 网络连接与教育管家身份授权分离 |
| Syncthing 同步不等于备份 | 继续保留独立版本备份 |
| 常驻监听拖慢主程序 | 增量事件、去抖、按需索引和总开关 |
| 普通用户操作复杂 | 一站式向导和普通语言状态提示 |
| Agent 自动保存全部对话造成隐私风险 | 仅响应用户明确保存指令，默认只选相关消息 |
| Agent 越权访问远程知识 | AgentGrant 与 CollaborationGrant 双重校验 |
| Agent 绕过教育管家读取同步目录 | 只通过 Agent 网关和受控工具提供知识 |
| 多 Agent 重复领取任务 | taskId、executionId、领取锁和目标主机唯一执行 |
| 知识内容诱导 Agent 执行指令 | 检索内容一律作为不可信资料，不作为系统指令 |
| Agent 接口常驻拖慢主程序 | 总开关、按需启动、限流和异步队列 |
| 资料统计被误用为学习能力评价 | 统计只用于资料流程治理，不自动写入成长模型或学情报告 |
| 教师从统计中推断未授权项目 | 快照按 CollaborationGrant 裁剪，未授权项目不返回存在性信息 |
| 在线统计频繁刷新拖慢学生主机 | 本地增量计数、事件合并、最短刷新间隔和无变化不发送 |
| 同一主机多角色造成权限混淆 | 节点身份、角色分配和对象权威分离，所有请求按协作关系重新校验 |
| 用户把导航模式误认为账户权限 | 文案明确“仅影响首页”，权限只由授权关系决定 |
| 计划范围扩展成通用同步或 Agent 平台 | 严守四层边界，当前阶段只建设教育协作能力 |
| 业务代码绑定具体知识引擎 | 所有调用通过 `edu-manager.knowledge-engine.v1` |
| 同步目录损坏后无法恢复 | 独立备份、状态快照、恢复演练和索引重建 |
| GBrain 评估能力被误当生产能力 | 远期独立 ADR、同语料基准和生产门槛通过前不得接入正式数据 |

## 十六、明确不做

本计划第一阶段不开发：

- 家长端协作；
- 简化学生终端协作；
- 公网匿名访问；
- 自动同步全部学生知识库；
- 两台主机同时直接编辑同一正式成长模型；
- 自动合并相互矛盾的成长证据；
- 教师未经学生授权读取私人资料；
- 教师远程直接删除学生资料；
- 教育管家自研完整远程桌面协议；
- 用 Syncthing 冲突文件代替知识治理；
- 用同步替代独立备份。
- 默认同步 Agent 的全部聊天历史；
- Agent 自由读取未授权学生或项目；
- Agent 直接持有远程主机永久万能令牌；
- Agent 直接发布正式成长证据；
- 强制普通用户安装或理解 MCP；
- 为每种 Agent 建立独立任务账本和知识协议；
- 让 Agent 直接操作远程物理路径；
- 在 P0A 至 P3 中安装或强制依赖 GBrain、Bun、技能包或额外数据库；
- 单独开发、打包或维护“教师主机版”和“学生主机版”；
- 通过不同数据库 Schema、升级通道或物理目录区分教师程序和学生程序；
- 根据用户选择的首页模式自动授予教师权限；
- 重写 GBrain 已具备的通用图谱、时间线、MCP 或混合检索引擎；
- 把 LLM Wiki 文件变成不可读、不可导出或依赖单一数据库才能恢复的格式；
- 在没有独立备份的情况下把 Syncthing 作为唯一恢复手段。

## 十七、完成定义

本计划完成后应达到：

1. 教师和学生可以继续独立使用各自教育管家。
2. 教师可以主动布置任务、分发资料和发起协作请求。
3. 学生可以主动请求教师协助，并控制授权范围和有效期。
4. 教师能够在授权后查询学生指定知识。
5. 大量或敏感资料优先由学生主机本地 Agent 处理。
6. 双方只交换必要资料、处理结果和知识贡献。
7. Syncthing 同步完成后，教育管家索引和状态能够自动一致更新。
8. 同步冲突、重复任务、旧批次结果和删除传播得到控制。
9. 普通用户无需理解 Tailscale、Syncthing 和协议文件。
10. 暂停协作后，两台主机仍可完全独立运行。
11. 用户可以在 Agent 中明确要求保存选定对话和附件。
12. 本机 Agent 可以调用本机教育管家知识库并获得带来源结果。
13. 教师 Agent 可以通过教育管家调用学生授权的远程知识库。
14. 大型或敏感资料可以在学生主机本地由 Agent 处理。
15. MCP、HTTP、文件收件箱和人工粘贴共用同一对象和治理流程。
16. 关闭 Agent 自动访问后，知识库、任务中心和人工协作继续可用。
17. 教育业务层只依赖 KnowledgeEngine 稳定合同，不直接依赖具体知识引擎内部实现。
18. 当前正式版本在不安装 GBrain、Bun、技能包和额外数据库时仍可完整运行。
19. LLM Wiki 文件、来源关系和教育对象能够独立备份、导出、迁移和重建索引。
20. 每个阶段均有真实双机验收、失败清单、恢复记录和可回滚版本。
21. Windows 端只有一个安装包和一套升级通道。
22. 同一节点可以在不同协作中承担不同角色，角色切换不改变对象权威。
23. 所有教师能力均来自明确协作授权，不来自程序版本、主机名称或导航模式。

最终产品说明：

> 教师和学生在各自电脑上独立使用教育管家。教师可以布置任务、发送资料或发起协作；学生同意后，教师可以查看指定知识，或让学生电脑上的 AI 直接处理本地资料并返回结果。用户还可以在 Agent 中把选定对话保存到教育管家，调用本机知识，或通过教育管家调用已授权的远程知识。系统只同步必要资料、知识和成果，兼顾协作便利、数据独立和学生隐私。
