# R21：WorkBuddy / Codex 统一连接器安装闭环（r12 候选）

## 结论与验收边界

本次补齐同一个 `edu-manager-knowledge` 的首次安装、原位升级、验证、修复、卸载撤权。不是增加第二套 `edu-manager-external-*` 服务，也没有发布到商店。

这是待宿主会话验收的 Windows 测试候选包，不是“全部真实验收通过”的正式发布。已区分配置写入、本机 MCP 往返与实际 Agent 模型调用三个层级；进程退出码为 0、模型复述 nonce 均不能单独证明调用成功。

## 用户操作

1. 打开“系统设置 → Agent 连接管理 → 外部 Agent 连接器”。
2. 选择并保存全局授权，以及“每个会话绑定一名学生”或“一个会话访问全部授权学生”。高级减权设置保留。
3. 在 WorkBuddy 或 Codex 卡片点击“一键安装”或“安装 / 升级”。首次安装自动创建必要配置；已有受管服务原位更新并备份。
4. 安装后自动验证本机 MCP 握手、工具目录及带随机 nonce 的授权主机往返。可单独点击“验证连接”重试。
5. 关闭旧 Agent 会话，重启相应 Agent 后新建对话，让其调用 `education_connector_health`，例如 nonce 为 `manual-health-20261016`。工具若延迟加载，先使用宿主的工具发现功能；宿主要求批准时应由用户在界面批准，不关闭审批保护。
6. 路径或配置变化时点击“修复连接”；不用再手动添加另一个 MCP。卸载时点击“卸载并撤权”。

注意：本机验证成功不代表外部 Agent 已重新加载工具或完成模型调用。旧版固定学生会话及缓存必须关闭；本次自动卸载的撤权范围是相应宿主的 R21 凭据，不宣称能按宿主精确撤销旧版共享的固定学生凭据。

## 实现及复用

- 保留 `external-agent-install.cjs` 导入入口，统一实现放在 `external-agent-lifecycle.cjs`；复用原有 PowerShell 桥、R21 认证与学生隔离、写入回执、主机 HTTP、IPC、界面动作机制。
- Codex 支持 `CODEX_HOME`，默认 `.codex/config.toml`。清理已知学生目录内属于本应用的旧项目级覆盖项，避免继续遮蔽全局连接；不扫描或修改未知工程。
- WorkBuddy 复用已有 `.workbuddy/mcp.json` / `.codebuddy/.mcp.json`；全新安装创建前者。两个镜像均先预检，再提交。
- 每宿主独立凭据；重复安装复用现有有效凭据。修复缺失凭据时先撤销旧凭据，保留原有减权条件；已停用连接不会因修复而自动扩权。
- 检测同名未知服务、别名受管脚本、并列教育管家服务、损坏配置后停止，提供冲突提示。未知配置不覆盖；受管文件保留唯一备份；多文件中途失败尝试回滚自己的改动，不覆盖并发外部修改。
- 卸载先撤销相应宿主的全部 R21 凭据，再移除受管服务。配置损坏时仍保留“已撤权、移除待完成”状态。持久化卸载记录阻止旧自动注册及旧活动学生采集重新恢复。学生资料及其他 Agent 不删除。
- 新增 `education_connector_health`：不读取学生资料、不创建学生会话，通过认证后回显随机 nonce 和连接 ID。主机端验证确实收到匹配回执，才能算通道通过。
- 安装动作串行化；初始化或验证失败释放忙碌锁，用户能够重试。
- React 宿主卡片独立复用，状态由服务端快照派生，不再把“已生成凭据”显示成“已安装验证”。

### 实际 Agent 验证：仍有未通过项

实测使用正常已有账号的厂商 CLI、临时 MCP 配置、仅允许健康检查的合成主机。成功标准是服务端收到同一次调用的 nonce 和正确 connectionId，不是模型声称成功。

- Codex：旧 CLI 曾返回模型要求升级，随后使用正在运行的桌面应用所配新版 CLI。新 CLI 已识别并实际尝试调用 `education_connector_health`，但宿主返回 `MCP tool call requires approval, but approval policy is never`。没有绕过审批，没有记为通过。
- WorkBuddy：启动记录明确显示 `edu-manager-knowledge` connected，且 `education_connector_health` 已发现。模型曾声称工具不可用；加入只读工具发现提示后仍未产生主机健康检查回执，因此真实模型调用未验收通过。退出码 0 和回答中的 nonce 不构成成功证据。
- 上述厂商会话证据保存在 r11 候选目录的 `codex-live-mcp-diagnostic.json`、`workbuddy-live-mcp-discovery.json`。不能将其替代为最终桌面会话验收；需用户重启安装后的宿主、允许该健康检查，并提供真实返回。用户最后发送了“workbuddy测评结果：”，尚未附评测正文或截图。

## 包体与发布

复用既有 Electron / PowerShell 运行时，没有再捆绑 Node 或整套连接器。新增 TOML 解析器仅随连接生命周期模块打包，不将完整开发依赖目录放入程序包。未进行有风险的运行时裁剪。

候选标签：`external-agent-lifecycle-r21-20261016-r12`。保留此前候选，不覆盖正式 manifest，不上传、不公开发布。签名状态须以 `Get-AuthenticodeSignature` 为准，不能用构建日志中的 signing 字样代替。
