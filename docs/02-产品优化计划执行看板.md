## 2026-07-22 路线调整

1. 当前主机端由管理员、教师、家长使用，平板端主要由学生使用；终端分工暂时承担基础身份隔离，不建设身份角色切换和复杂权限设置。
2. `AgentPolicy`、`ContextGrant`、敏感字段管理、专门审计界面、外部 MCP 和跨 Agent 服务整体移至 P7。
3. P1/P2 已有来源、去重、风险、候选、事务和回滚继续在后台生效，不作为普通用户的审计任务展示。
4. 近期唯一主线调整为：多渠道采集 → 原始资料 → 知识资产 → 多 Agent 消化/分析 → 成长模型 → 学情报告与教育档案定期输出。
5. 现有设备授权、学生范围隔离和敏感正文不回显等基础保护保留，但暂不扩展为多角色权限产品。
6. 学生行动下发与反馈不改程序，继续由教师、家长管理学生提交，提交内容作为普通资料进入闭环。
7. Agent 调用复用现有直接执行、QClaw 收件箱和人工任务包；新增统一档案访问合同，MCP 只作为主机内嵌可选适配，不增加默认安装依赖。

## 2026-07-24 最小 P5 自动化调整

1. 正常资料批次零人工确认；不再把“审核、批准、确认”设置为成长模型、报告或档案更新的常规闸门。
2. 低风险可信内容自动采用，中风险内容自动继续观察，高风险异常不覆盖旧结果；只有真实异常合并显示为“需要补充”。
3. 不伪造人工 `confirmed` 记录；系统决策保留规则版本、证据 ID、来源、时间和原因。
4. 四类报告通过学生范围、章节、证据可访问性、冲突、来源指纹和实质变化校验后自动发布。
5. 先取消启动全量重建和分钟级全学生扫描，再开发成长模型与报告自动更新，避免增加主机负荷。
6. 详细计划：[Windows 0.10.6 最小 P5 开发计划](delivery/Windows-0.10.6-最小P5开发计划.md)。

### 已生效的后台规则

以下是现有数据层的兼容约束，不建设为普通用户的角色、权限或审计操作流程：

- 事实、转述、观察、推断和建议分开；
- 学生自述、家长观察、教师评价、学习制品、系统记录和 Agent 推断分开；
- confirmed 必须有人类审核和完整审核记录；
- 画像级结论至少两个独立来源并完成反例检查；
- 禁止永久学生标签；
- Agent 推断不能单独发布为事实；
- 建议必须有失效或复核时间。

### P1 完成项

1. Student、LearningProject、GrowthEvidence、LearningReport、EducationPolicy v1 Schema 已冻结。
2. 旧 confirmed 证据进入补审队列；本机确认会记录 reviewerRole、reviewerId、reviewedAt 和审核历史。
3. 纠正、申诉、superseded、撤销和修订历史具有统一展示模型。
4. 不同年龄阶段的学生知情、异议、纠正和监护人确认策略已冻结。
5. 项目贡献兼容映射保持原 ID、来源和路径，不迁移或改写现有学生资料。

### P1.1 审核减负完成项

1. 后端依据来源完整性、敏感内容、冲突、Agent 推断、置信度和项目上下文重新计算高、中、低三级风险，不信任界面传入的风险标签。
2. 默认“需要关注”视图隐藏低风险候选和已处理记录；用户仍可切换到“低风险”和“全部”查看，不删除任何记录。
3. “一键处理本批次”只触发一次确认：低风险项目证据批量确认，中风险证据转入继续观察，高风险证据保持不变并要求逐条审核。
4. 同一次批量操作写入统一批次 ID、审核人、时间和逐条审核历史，保留可追溯性。
5. 低风险候选不会在无人确认时自动发布；“默认忽略”只表示不占用日常待处理视图。

6. 晋升先写可恢复事务日志，再原子更新正式文件；异常中断可自动回滚已写标记。
7. 撤销只删除对应事务标记块，同时把候选索引更新为 revoked，原始对话保持不变。
8. 单次提取上限 80 条，单次晋升上限 50 条，避免异常批量写入。
