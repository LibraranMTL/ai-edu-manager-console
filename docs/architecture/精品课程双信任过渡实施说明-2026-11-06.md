# 精品课程双信任过渡实施说明

> 日期：2026-11-06
> 状态：源码已实现并通过自动化及候选公网同步验证；四端安装包、签名、覆盖升级和真机验收尚未完成。

## 1. 目的与边界

课程发布密钥从旧发布者平滑切换到新发布者时，客户端暂时同时信任两把公钥。新发布只使用新私钥；旧私钥不再用于新增发布，但旧签名目录和离线包在观察期内仍可验证。私钥不进入代码、安装包、管理页面或本文档。

双信任只扩大“可验证的发布者集合”，不允许以下降级：

- 不允许忽略 `keyId` 后用任意公钥试验验签；
- 不允许未知、冲突或 `revoked` 的 `keyId`；
- 不允许 HTTP 清单或课程入口；
- 不允许跳过 canonical JSON、RSA-SHA256、资源 SHA-256、撤回和离线租约检查；
- 学生端不获得云端管理权限，也不直接读取管理员接口。

## 2. 冻结的过渡策略

策略修订：`course-trust-transition-2026-11-06-v1`

| `course-catalog-primary-2026` | `transition` | `92b75a570a3913da111bd116202c3bdcee8adde652261a4dcbfe011206091a75` | 验证旧目录、旧离线包和过渡期缓存 |
| `course-catalog-candidate-20261106` | `active` | `f16f9b2028b74ef2360db56ef35a4db4f8d64396467a6d3b8414381f38dda60d` | 候选及后续新发布验签 |

`active` 与 `transition` 可验签，`revoked` 和未知状态不可验签。同一 `keyId` 对应不同公钥指纹时整份策略失败关闭。

## 3. 四端责任

| 客户端 | 信任处理 |
| --- | --- |
| Windows 主机 | 从内置策略加载两把公钥，按清单 `keyId` 精确选钥；验证清单、撤回、资源和 last-good；把已验证发布者写入学生投影 |
| Android 单机版 | 从 `res/raw` 内置策略加载两把公钥，复核指纹后按 `keyId` 精确选钥；同步结果记录发布者和策略修订 |
| Windows 学生端 | 不直接读取云端清单；验证主机/学生范围，并要求投影中的 `publisherKeyId` 属于本版本过渡策略，策略修订必须一致 |
| Android 学生端 | 使用独立的新缓存命名空间，拒绝旧缓存、未知发布者和策略修订不一致的投影 |

学生投影的 `publisherKeyId`、`trustPolicyRevision` 进入 `projectionRevision` 哈希，不能在不改变 ETag/修订的情况下被替换。

## 4. 发布顺序

1. 候选云端继续使用新密钥签名，正式云端暂不切换。
2. 先发布含双信任策略的 Windows 主机和 Android 单机版候选。
3. 再发布验证投影发布者的 Windows 学生端和 Android 学生端候选；主机先于学生端升级，避免新版学生端连接缺少信任字段的旧主机。
4. 四端覆盖升级、缓存、304、撤回、离线租约和课程打开前复核真机通过后，切换正式云端新发布到新密钥。
5. 保持旧密钥 `transition`，完成回滚演练和观察期。
6. 达到退出条件后，在下一版四端策略中把旧密钥改为 `revoked`，随后禁止任何旧密钥新发布和回滚。

## 5. 旧密钥退出条件

必须同时满足：

- 正式环境已使用新密钥完成至少一次正常发布、一次撤回和一次回滚演练；
- 四端目标版本均完成真实设备覆盖升级验收；
- 30 天观察期内没有需要旧私钥生成新发布的情况；
- 最近 14 天在线同步回执不再出现仅支持旧策略的受管客户端；
- 所有允许回滚的发布快照均可由新策略客户端验证；
- 已准备旧钥匙撤销版本、客户升级提示和紧急回退制品。

若旧私钥疑似泄露，不等待观察期：立即停止旧钥匙发布、冻结相关发布单、发布安全升级，并把旧钥匙标记为 `revoked`。由于信任策略内置在客户端，撤销生效依赖客户端安全升级，不能把普通课程墓碑当作密钥撤销机制。
