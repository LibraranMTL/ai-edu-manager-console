# Windows 学习卡片生成自动修正候选

## 问题与原因

用户截图显示独立复核已发现候选卡片的提示与公式结构不一致。源代码 `electron/practice-cards.cjs` 在任何复核拒绝后立即抛错，缺少可修正内容的自动修正路径。这属于候选内容质量未通过，不等同于 CLI 无法启动。

## 本次修复

- 正常路线保持“生成 → 独立复核 → 保存”，模型调用仍为两次。
- 明确有效的内容或语言拒绝，进入一次“依据意见修正完整卡片 → 再次独立复核”。最多四次模型调用，不无限重试。
- 复核时检查题目、标题、提示、答案和解析的一致性。再次复核不携带前次判定，避免要求评阅器直接认可修改。
- 修正后仍执行字段、学科、引用依据、语言和独立复核校验。不硬编码截图中的数学答案，不放宽质量标准。
- 复核格式错误、网络及登录异常不自动增加修正调用。
- 连续点击复用同一在途请求；修正前和保存前检查当前学情、语言、计划版本；取消后不保存迟到结果。
- 旧卡片及作答在新卡成功保存前不变。再次拒绝显示“已自动修正一次、原卡片已保留”及重试/调整重点路径。
- 成功卡片本地保存初次及最终复核摘要和修正次数；不把初次复核详情新增暴露到学生卡片投影。

## 验证

- 定向测试：26 / 26 通过。新增 7 个测试覆盖提示冲突修正、复核持续拒绝、语言拒绝、格式/网络失败、伪造引用/学科变更、证据变化、取消及迟到结果。
- 完整回归：1,949 项，1,948 通过，1 跳过，0 失败；耗时 166.7 秒。日志：`.tmp/card-generation-repair-tests.log`。减少无变化快照读取后的最终版本另复跑上述 26 项，全部通过。
- 打包后合成验证：Electron 43.0.0 下加载候选内的模块，3 个相关运行文件与源码哈希一致；4 次模拟调用完成自动修正和再次复核，未提前暴露答案。日志：`.tmp/card-generation-repair-package-probe.log`。
- 本次不调用真实学生资料或真实模型、不修改现有学生卡片、不重跑历史任务。

## 真机验收

1. 退出旧程序，运行本次候选 EXE，进入原学生的“今日卡片”。
2. 点击“根据学情生成卡片”，等待本次生成完成；首次质量问题可自动修正，耗时可能比正常生成更长。
3. 检查提示与本题实际方法一致，语言设置正确，旧卡片和作答仍可查看。
4. 若仍不通过，应看到明确拒绝原因和处理路径，而不是生成不合格卡片。
5. 若提示复用已有卡片，这是学情/计划/语言未变化的既有去重规则；可以完成当前练习，或根据实际需求调整练习重点，不把刷新当作强制换题。
