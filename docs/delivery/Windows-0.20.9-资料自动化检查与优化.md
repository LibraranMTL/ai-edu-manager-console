# Windows 0.20.9 资料自动化检查与优化

检查日期：2026-10-11（北京时间）。检查对象为 Windows 主机学习资料、项目资料、统一任务队列及本机 Agent；没有将 Windows 检查结果外推为 Android 真机验收。

## 结论与本轮修改

资料处理已有自动提取、分批、来源核对、自动接收合格结果及知识入库能力。主要操作负担来自调度和恢复缺口，以及把人工交接入口误认为自动执行能力。本轮按这两类实际问题修改，没有要求用户逐份审核正常资料。

| 环节 | 实际发现 | 0.20.9 处理 |
| --- | --- | --- |
| 项目启动 | 资源忙直接返回失败，用户需要再点一次 | 保存等待状态并自动续排 |
| WorkBuddy 连续任务 | 已有交接时后续任务直接报错 | 后续任务排队，前项结束后自动打开下一项 |
| 项目自动扫描 | 扫描与能力刷新同时启动，可能使用旧能力；前轮扫描未结束仍可能启动下一轮 | 能力刷新后等待扫描完成，再继续统一调度 |
| 自动任务归属 | 项目定时任务未传自动执行标记 | 贯穿自动提交标记，使暂停规则正确生效 |
| 批次续处理 | 关闭自动化后，旧定时器仍可能发起下一批 | 定时器和异步能力刷新之后再次检查开关 |
| 排队恢复 | 取消、删除的任务可能因资源长期繁忙不断重排 | 先检查任务仍存在且可执行，再检查资源；重新启用调度后恢复仍有效的等待项 |
| 重复点击 | 已运行任务仍尝试第二次提交，出现误导性错误 | 直接返回已有运行状态 |
| 处理状态 | 排队或 WorkBuddy 尚未发送也显示待处理/处理中 | 显示“排队中”或“待发送”，提供对应说明 |
| OpenClaw 探测 | Gateway 命令退出码为零，但正文报告连接失败 | 检查连接失败内容，避免错误地走 Gateway 模式 |

自动校验仍由系统执行，包括原文版本、输出归属和来源引用。它们无需用户逐项操作。真实来源冲突、缺失文件、成长贡献确认以及正式归档等需要判断的情况仍会保留明确提示。

## 两条处理链路

学习资料：进入学生资料登记 → 路径预检及可确定的自动修复 → 固定批次 → 按配置的 Agent 执行 → 收取结果/扫描产物 → 校验合格后自动接收 → 在自动化开启时继续后续批次。来源无法确定的文件仍需一次定位；普通完成结果不要求用户粘贴 JSON。

项目资料：扫描并登记工作区原文 → 采用状态及来源版本核对 → 提取正文/OCR → 有界分批 → 受控 Codex 返回知识内容 → 宿主核对并提交五类知识 → 更新资料完成状态。已有行为会隔离单份不支持或损坏资料，让可处理资料继续；有知识提交检查点时可复用已生成结果。

并非所有工作区文件都应自动当作项目正式资料。未采用来源、代码目录、无归属文件等仍沿用已有规则，避免家长因一次目录绑定就导入不相关内容。系统没有在本轮擅自启用原本关闭的项目自动化。

## Agent 实测与能力边界

| Agent | 本轮证据 | 可用结论 |
| --- | --- | --- |
| Codex 桌面附带原生 CLI | 0.130.0-alpha.5；合成项目完整处理 20.7 秒，五类知识均入库、来源事实齐全、原文未变 | 当前受控项目消化可用；此次没有处理真实学生资料 |
| 另一个 npm Codex CLI | 同一合成任务返回 agent_failed；其 exec 帮助不列出隔离入口所需 ignore-user-config / ignore-rules 参数 | 不能把任意已安装 Codex 都视为兼容；当前已有版本发现逻辑优先更新的 CLI |
| WorkBuddy | 桌面进程和 IPC 描述存在；无工具 READY 探测返回 authentication required，退出码仍为零 | 桌面可交接，后台授权不能复用；仍需在桌面点击发送，不宣称无人值守可用 |
| OpenClaw | 2026.6.8；Gateway 127.0.0.1:18789 连接被拒绝；默认模型 ollama/gemma4:e4b 不在 ollama list 中 | 当前配置不能顺畅执行；需恢复 Gateway 或配置可用本地执行模型。没有擅自切换模型、下载大模型或重启服务 |
| Hermes | CLI 0.14.0 能返回版本；当前教育管家通过通用任务交接，而非专用无人值守适配器 | 已安装不等于资料任务端到端验收通过 |
| Claude Code / 其他通用 Agent | 当前任务系统保留通用交接和结果回收；本次未取得端到端实测通过证据 | 不标记为已验证自动执行 |
| QClaw | 历史通道与回执兼容仍保留，智能路由排除默认选择 | 保留旧记录兼容，不作为新自动化默认依赖 |

对普通用户，当前已实测完整可用的项目资料后台处理是 Codex 通道。选择 WorkBuddy 时，教育管家可以准备和回收任务，但桌面授权限制仍导致一次发送操作；本轮消除了后续任务需要重新提交的负担。
