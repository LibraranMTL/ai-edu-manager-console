# Windows 主机备份迁移合同 v1

## 1. 目标

`edu-manager.migration-package.v1` 用于把 Windows 主机端的受管教育资料和可迁移应用状态复制到另一台电脑。迁移遵循“盘点、复制、校验、暂存恢复、原子切换、保留回滚”的顺序，不移动或删除来源电脑数据。

日常主机状态备份继续保留。日常备份适合索引和配置恢复；完整迁移包用于换电脑或更换资料磁盘，两者不能混用。

## 2. 权威数据范围

默认进入迁移包：

- 当前学生资料根目录中的原始资料、正式知识、报告、教育档案、成长模型、任务中心、采集资料和项目资料；
- 学生、项目、资产、上传记录、协作账本和教育出版索引；
- 机构课程、课程图片、平台课程草稿、公开可信发行方信息、资产版本快照和路径健康报告；
- 用户明确勾选的外部接管知识库、项目工作空间或项目知识空间。

默认不进入迁移包：

- License 激活信息；
- API Token、终端授权令牌和配对请求；
- 固定主机身份；
- 协作直传密钥；
- 平台 License 私钥、课程目录私钥及其他私钥；
- Electron 缓存、GPU 缓存、临时下载、可重新生成的平台课程缓存和诊断噪声。

新电脑必须使用自己的主机身份和 API Token，重新激活 License，并重新连接终端和跨主机协作关系。恢复不能让两台离线电脑同时冒用同一固定主机身份。

## 3. 包结构

```text
AI教育管家迁移包-时间-迁移ID/
├─ migration.json
├─ manifest.json
├─ manifest.sha256
├─ migration-report.md
└─ payload/
   ├─ managed/
   ├─ external/
   └─ state/
```

`manifest.json` 使用 `edu-manager.migration-manifest.v1`，至少记录迁移 ID、创建版本、来源受管根目录、加密参数、逐文件逻辑分类、相对路径、原始容量、原文 SHA-256、包内载荷 SHA-256，以及外部目录的复制或待重新定位状态。

目录式迁移包避免单一压缩文件的 4 GB 限制，并允许逐文件校验和失败定位。迁移包禁止符号链接、`..`、绝对载荷路径、空相对路径和目标目录越界。

迁移包保存目录必须位于全部受管资料、接管知识库和项目目录之外；程序在创建任何载荷前检查真实路径边界，禁止把迁移包写进正在迁移的源目录。逐文件复制前后使用 SHA-256 确认内容稳定；单个文件在复制过程中变化时立即停止，避免写入撕裂内容。文件完成稳定复制后，活跃知识库再次新增、删除或修改派生状态文件不会让整包失败；系统把变化数量和文件示例写入清单及迁移报告，说明导出开始后产生的后续内容可能未包含。

迁移包的物理目录采用短英文根目录和 `payload/objects/<前缀>/<SHA-256>.enc|bin` 扁平对象布局，避免复制到 U 盘或经 Windows 压缩文件夹传输时因原资料的中文深层路径超过系统限制。原始中文相对路径仅记录在已校验的 `manifest.json` 中，恢复时按清单重建。读取端仍兼容清单中保存旧式物理载荷路径的既有迁移包。

## 4. 完整性与旧包兼容

- 新创建的迁移包不设置密码、不加密载荷，以减少创建、复制和恢复步骤；
- 清单使用独立 SHA-256 文件校验；
- 每个包内载荷记录并验证 SHA-256；
- 恢复到暂存目录时再次校验原文 SHA-256；
- 恢复端继续兼容旧版 AES-256-GCM 加密迁移包；只有识别到旧版加密包时才显示密码输入框，并使用原有 scrypt、随机盐、独立 IV 和认证标签完成解密校验。

旧版迁移包的密码仍不得写入迁移包、日志、设置或诊断文件，密码丢失时不提供绕过恢复。

## 5. 外部目录

受管资料根目录之外的接管知识库和项目目录必须在导出界面逐项展示。用户可以：

1. 勾选复制：文件进入 `payload/external`，恢复到新资料根目录的 `.edu-manager/migrated-external/<id>`，相关学生或项目路径自动重映射；
2. 不勾选：只在清单中登记为 `needs_relocation`，保留原路径元数据，恢复报告提示用户在新电脑重新定位。

系统不得静默复制任意外部盘符，也不得把一个学生的外部路径绑定给另一个学生。

## 6. 恢复事务

1. 验证迁移包版本、清单和全部载荷哈希；旧版加密包额外验证密码；
2. 验证目标目录不是磁盘根目录、当前为空且可用空间不少于原始数据容量的 110%；
3. 全部文件恢复到目标目录同盘符的隐藏暂存目录；
4. 重映射受管根路径和已复制的外部目录路径；
5. 再次核对暂存文件数量和 SHA-256；
6. 把受管暂存目录切换为正式目标目录；
7. 写入应用状态前，在 `userData/migration-rollbacks/<migrationId>` 保存被替换状态；
8. 任何状态写入失败时恢复原状态，并把未激活的数据目录保留下来供诊断，不静默删除；
9. 成功后生成 `.edu-manager/migration-report.json`，列出恢复量、路径映射、待重新定位目录和下一步授权操作。

来源版本高于当前主机版本时必须先升级，不能向旧版强制恢复。

## 7. 性能与进度

目录盘点、哈希、复制和恢复全部在独立 Node 工作线程执行，不能在 Electron 主线程同步遍历大目录。旧版加密包的解密也在工作线程执行。渲染进程只接收文件数、容量、当前文件和阶段事件，不接收文件内容；旧包密码只用于当次恢复。

## 8. 验收门禁

- 同一迁移样本导出、校验、恢复后，全部受管文件数量、容量和 SHA-256 一致；
- 学生、项目、资产和知识对象 ID 保持不变；
- 不产生跨学生资料、重复项目或重复原始资料；
- 错误密码、损坏载荷、非空目标、空间不足、版本过低均在切换前失败；
- 迁移包保存到任一来源目录内部时必须在复制前失败；仅修改时间变化而内容哈希不变时不得误报目录变化；活跃知识库在文件稳定复制后继续写入时应完成迁移并生成变化警告；
- 失败不会覆盖目标电脑现有索引、License、API Token 或主机身份；
- 已复制外部目录自动重映射，未复制目录明确进入待重新定位报告；
- Windows 候选包内必须包含迁移模块、工作线程、IPC 和界面入口；
- 候选包仍需在两台真实电脑、不同 Windows 用户名和不同盘符之间完成真机迁移后，才能考虑正式发布。
