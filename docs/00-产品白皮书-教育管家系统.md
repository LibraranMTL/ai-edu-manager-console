# AI教育管家产品白皮书

> 当前产品基线：Windows 主机版 0.9.3，Android 平板终端 0.5.8。

## 1. 产品定位

AI教育管家是一套面向学生长期成长的 AI 原生知识操作系统。它不是单纯的网盘、项目管理软件或一次性问答工具，而是把学习资料、项目经历、教师反馈和学习行为转化为可追溯的知识资产与成长证据。

核心目标是：

> 让每一份学习资料产生知识价值，让每一次项目经历沉淀为成长证据。

## 2. 方法论

系统采用五项互相衔接的方法：

1. **研究暂存**：允许学生自由收集大量候选资料，不要求所有内容立即成为长期资产。
2. **文件资产管理**：以资产身份、版本、来源、引用关系和生命周期管理正式资料。
3. **LLM Wiki 知识加工**：把原始资料持续加工为概念、实体、摘要、问答和综合汇总。
4. **项目双空间**：人在项目工作空间中完成项目，AI 在项目知识空间中理解和沉淀项目。
5. **知识贡献与成长模型**：项目知识经审核后贡献到学生长期档案，形成能力证据、趋势和行动建议。

## 3. 总体架构

```text
资料采集入口
文件上传 / 平板上传 / 屏幕连续采集 / 项目导入
        ↓
Research Staging Layer
研究暂存、初筛、去重、治理候选
        ↓
Asset Layer
正式文件资产、来源记录、版本与引用关系
        ↓
Workspace + Knowledge Layer
项目工作空间 + 项目知识空间（LLM Wiki）
        ↓
Knowledge Promotion
知识贡献申请、审核、冲突处理与发布
        ↓
Growth Layer
能力证据、成长趋势、每周行动建议
        ↓
Presentation Layer
学生档案、学情报告、家长/教师/升学视图
```

## 4. 研究暂存与资产晋升

项目研究中下载的网页、论文、截图和案例先进入研究暂存层。系统支持 AI 初筛、重复识别、来源治理和人工选择，但不会把所有候选资料无条件长期保存。

资料的典型生命周期为：

```text
已收集 → 已初筛 → 已选入分析 → 已分析 → 已晋升 → 已归档或丢弃
```

晋升后的正式资产可采用三种来源保存策略：完整副本、来源记录或关键内容快照。项目原始资料库不是工作空间的复制品，而是经过选择并用于知识加工的来源资产集合。

## 5. LLM Wiki 知识协议

面向非专业用户的正式版本采用最低依赖部署：现有 LLM Wiki Engine 直接使用 Markdown、JSON 和 JSONL 文件，不要求额外安装数据库、GBrain、Bun、技能包或向量服务。`KnowledgeEngine` 合同继续保留为代码边界，但当前只有 `llm-wiki-local` 进入默认运行和交付路径。

所有学生和项目共用统一的知识空间结构：

```text
原始资料库
概念库
实体库
摘要库
问答精华库
综合汇总库
```

项目模板不会改变这一底层协议，而是在其上配置项目工作目录、知识加工重点、成长维度和成果要求。每个知识对象保留来源文件、生成时间、Agent、置信度、审核状态和关联项目，使 AI 结论可以核对和复用。

## 6. 学习项目双空间

### 项目工作空间

面向学生和教师，可自定义文件夹，也可直接采用已有项目目录。这里容纳资料、草稿、过程记录和成果，允许按真实工作习惯组织。

### 项目知识空间

面向 AI 和长期知识沉淀，固定使用 LLM Wiki schema。工作空间资料经初筛、治理和晋升后，以资产引用进入原始资料库，再生成概念、实体、摘要、问答和综合洞察。

项目支持编辑记录、重新定位、复制、导入导出、移除与恢复。编辑项目不改动物理目录，移除记录不彻底删除项目文件。多学生项目共享项目知识，但为每位学生形成独立成长证据。

## 7. Agent 与统一任务中心

系统以统一任务协议解除对单一 Agent 的硬编码。QClaw、OpenClaw、Codex CLI、Marvis 及其他 Agent 接收同一种任务：

- 具备接口的 Agent 由适配器自动执行；
- 不具备接口的 Agent 平滑降级为复制指令、人工执行和结果导入；
- 所有结果回到统一任务中心审核；
- 任务统一记录审批、权限、状态、日志、超时和重试；
- 用户可一次关闭全部自动运行，切换为手动模式。

每周行动建议是首个完整自动化闭环，由成长模型生成严格结构化建议，经审核后进入任务中心并按周更新；底层保留旧文件名只用于兼容历史档案。

## 8. 资料消化与质量复核

资料消化区分“待提交消化”和“等待 Agent 回执”。Agent 完成后写回状态与逐文件回执，控制台同步后才把匹配资料标记为已处理。

对于大量图片或低置信度内容，系统可生成消化覆盖审计，检查完整覆盖、部分识别、失败、源文件缺失和无逐文件回执。用户可复制二次核对指令给任意 Agent，并同步复核结果，避免“生成了部分摘要但遗漏若干图片”的隐性失败。

## 9. 屏幕资料采集

Windows 与 Android 均支持用户主动启动的限时连续采集。采集策略包括智能混合、内容变化和固定间隔，并提供暂停、继续、重点截取和结束操作。

截图先进入候选采集箱，经过变化检测、去重和人工晋升后才成为正式资产。Android 采集始终由用户授权，并显示前台通知；系统不提供无提示的全天候监控。

## 10. 文件资产中心

文件资产中心展示资产总数、重复组、治理候选、风险、引用关系和最近七日趋势。学生筛选会联动整个看板、曲线、列表与详情。

最近七日统计包括：

- 每日新增正式资产数量；
- 每日新增唯一引用次数；
- 缺少历史日期的兼容提示。

## 11. 跨端协同与可靠恢复

Windows 主机保存学生知识库并管理平板设备授权。平板首次连接后进入待授权状态，Windows 可授权全部或指定学生。设备支持重命名、撤销、恢复和删除记录。

Android 0.5.8 支持导出连接备份和导入并连接，用于同一平板重装恢复。连接备份包含设备身份和授权令牌，属于敏感文件，不应转发或公开存储。

Windows 启用单实例保护，并在启动时以主机学生索引校准界面缓存。主机备份保存完整学生档案字段，恢复后立即刷新学生、项目、资产和主机状态。完整迁移电脑时仍需额外备份学生知识库物理目录。

## 12. 核心价值

**对学生**：项目不再只是完成任务，而会积累可复用知识和可证明能力。

**对家长**：从单次成绩转向理解长期趋势、优势、问题和下一步行动。

**对教师与机构**：形成可追溯的学生画像、项目证据和个性化培养依据。

**对 AI 教育**：从一次性回答升级为理解多年学习过程、能够审计和持续改进的成长伙伴。

## 13. 产品总结

AI教育管家连接资料、资产、项目、知识、能力和成长：

```text
资料进入 → 研究筛选 → 资产治理 → AI 理解 → 项目沉淀
→ 知识贡献 → 成长模型 → 学情报告 → 下一步行动
```

最终目标是让每位学生拥有一个持续成长、可迁移、可验证且不断进化的 AI 数字成长档案。
