# Windows 0.9.4 资料消化自动闭环发布说明

> 发布日期：2026-07-22  
> 升级基线：Windows 0.9.3  
> 配套平板：Android 0.5.8（本次未修改）

## 版本目标

0.9.4 将学生资料和学习项目资料的日常消化操作收敛为一次“开始处理”。系统在后台完成批次登记、Agent 通道选择、结果等待、严格校验和状态回写，普通用户不再需要进入任务中心、标记提交、手工同步或审核技术回执。

## 主要变化

- 新增统一 `DigestBatch v1`，按资料稳定 ID、相对路径和 SHA-1 冻结每次处理范围。
- 学生资料启用严格逐文件回执；新批次不再依赖文件时间或模糊日志推断整批完成。
- 项目资料复用既有严格回执，并接入同一自动编排入口。
- OpenClaw、Codex、QClaw 收件箱和人工粘贴共用一套结果校验与状态回写。
- 机器校验通过的学生/项目资料消化任务自动验收，不向普通用户暴露审核步骤。
- 支持部分完成、仅重试剩余资料、重复结果幂等处理、异步结果轮询和应用重启恢复。
- 学生资料页和项目消化步骤统一显示“待处理、处理中、部分完成、已完成、需要帮助”五类状态，并只保留一个主操作。
- 批次、任务、执行器、回执和哈希等技术信息移入高级诊断区。

## 数据与兼容性

- 不移动、删除或强制迁移学生和项目原始资料。
- 保留旧版学生 `digest-state.json`、索引和日志读取路径；只有 0.9.4 新建批次强制使用严格回执。
- 保留旧项目 `digestedFiles` 回执格式，并在内部归一化为统一逐文件结果。
- 原有任务中心、Agent 适配器和人工执行方式继续可用。
- 成长模型、正式学情报告、教育档案和高风险发布不会因资料消化完成而自动改写。

## 低依赖原则

本版本没有引入 GBrain、MCP、数据库、Docker、Python 常驻服务、新技能包或新的 npm 运行依赖。没有可直接调用的 Agent 时，系统自动保留一次复制、一次粘贴的人工降级路径。

## 用户操作

1. 把资料导入学生原始资料区，或加入学习项目原始资料库。
2. 点击“开始处理”。
3. 等待页面自动显示“已完成”或“部分完成”。
4. 部分完成时点击“重试未完成项”；完成后点击“查看新增知识”。

正常流程无需点击“标记已提交”“同步结果”或“审核回执”。

## 故障处理

- 显示“需要帮助”：点击“重试未完成项”；详细原因可在“高级与诊断”查看。
- 没有原生 Agent：按页面提示把已复制的指令粘贴给现有 Agent，再把返回结果粘贴回当前页面。
- 应用在处理中关闭：重新打开后系统会检查原批次和已到达结果，不会重复建立同一批次。
- 回执与本批资料不匹配：系统不会修改原始资料或误标完成，修正结果后重新导入即可。

## 回滚

0.9.4 新增的批次、回执和任务记录均为旁路元数据。需要临时退回旧版时，先备份主机数据和学生资料目录，再关闭 0.9.4 并启动 0.9.3；原始资料与既有知识目录不需要迁移。0.9.4 已严格确认的完成状态和知识产物不会被主动删除。
