# Windows 智能资料自动化 R11 候选验收

日期：2026-10-13。版本：Windows 0.21.1 开发候选。候选标签：`smart-material-automation-r11-20261013`。本记录不等同于正式发布、代码签名、真实学生资料质量或四核／8GB目标机验收。

## 1. 结论

本轮已落实方案中四个直接影响自动化和卡顿的技术收口项：Agent 资格持久化、学生资料受控自动消化、阻塞原因分流、任务心跳轻量持久化。它们足以消除“每次重启都要求重新检测”“支持的学生消化只能桌面交接”“临时资源等待被误报成人工阻塞”“万条任务下每次心跳重写整个账本”等已定位原因，但尚不能单凭开发机测试宣称业务目标全部达标。

- WorkBuddy 分类与消化资格按执行器、任务档、CLI 内容哈希和有效期分别保存。程序变化或资格过期会失效；一个任务档通过不会给另一个任务档越权。
- Codex／WorkBuddy 支持的学生消化进入现有受控项目资料管线：固定原件版本、统一提取、Agent 无工具返回候选、宿主校验并提交，再按原学生批次结算。原件不移动，来源变化时拒绝结算。
- 分类与消化继续复用相同学生、相同资料版本和相同提取参数下的完整提取结果。分类预览不冒充全文；条件变化时安全重提取。因此避免的是重复解析／OCR，不是取消两次职责不同的 AI 判断。
- 心跳改为追加 `progress.jsonl`；业务状态变化仍由既有 Worker 原子写完整账本。崩溃启动会重放同一任务和执行批次的有效进度，完整快照成功后吸收日志。
- 认证、资格、资源等待、敏感资料、人工选择和未知执行具有不同阻塞原因。只有确认未执行且可恢复的状态自动继续；敏感、跨学生冲突和结果未知仍保留人工安全门。

## 2. 实施与安全边界

| 问题 | 实施结果 | 保留边界 |
| --- | --- | --- |
| Agent 授权反复显示待恢复 | 资格保存到任务运行账本，重启可复用；执行前再次校验 CLI 哈希和有效期 | 桌面普通对话不等于后台 CLI 授权；哈希变化必须重新检测 |
| 学生资料整理依赖人工交接 | 支持的 Provider 自动注册学生批次到受控资料存储，并走统一消化、提交、回执链 | Agent 不写官方知识目录；真实学生知识质量仍需人工抽验 |
| 分类与消化重复 OCR | 完整提取结果按学生、资料版本、解析器和 OCR 参数受控交接 | 截断文本、跨学生、版本或参数变化不复用 |
| 队列阻塞过多 | 自动等待与人工安全判断分开，资源忙和资格复检可自动恢复 | 敏感、冲突、学生／项目业务歧义不自动放行 |
| 万条任务卡顿 | 高频心跳不再克隆和重写完整任务账本；查询仍使用 Worker 读模型 | 真正业务状态变更仍需完整耐久写；目标低配机仍需验收 |

学生受控资料采用稳定的学生范围合成项目 ID，原件只在该学生原资料根登记；重复批次事件幂等。Agent 输出中的路径、学生、项目或完成声明均不能直接改变正式记录。宿主在提交前后核对任务执行批次、学生存续、允许写入范围、资料版本和完整提交结果；已引用资料沿用保留策略。

## 4. 性能结果与解释

开发机为 12 核、63.8 GiB，以下是合成基准，不是低配目标机结论：

- 10,000 条、80.7 MB 任务读模型：冷加载 368.95 ms，热查询 P95 0.55 ms，主事件循环最大延迟 11.54 ms。
- 10,000 条、27.2 MB 写入基准：并发查询 P95 278.50 ms；完整耐久写 P95 355.74 ms。完整写在 Worker 内执行，但主进程准备完整快照仍可能出现 85.81 ms 峰值，属于后续继续优化点。
- 新的进度日志 50 次写入 P95 1.61 ms，且任务主账本大小和修改时间均未变化，证明高频心跳已脱离全量账本写入。
- 10,000 文件无变化三轮扫描均没有正文读取、OCR、Agent 或内容哈希调用；增加 10 份只提取和分类这 10 份。查询 P95 1.96 ms，并发查询 P95 1.85 ms；RSS 增量 44.38 MiB，加载加扫描增量 52.62 MiB。

这些数据支持“主要高频卡顿路径已降载”，但不支持宣布四核／8GB／SSD P95、相对劣化和四小时稳定性已经通过。完整业务状态写入仍比进度写入重，应继续保持批次化，不能退回逐文件顶层任务。

5. 候选未签名，不应作为正式公开安装包发布。
