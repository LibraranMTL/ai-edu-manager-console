# Windows 0.7.36：统一任务中心 P1-P6 闭环加固

## 本次目标

逐项封闭统一任务中心 P1-P6 审计中发现的协议、安全、执行、可靠性与路由缺口，使学习项目归档和每日行动建议都只能通过同一任务状态链完成。

## 已完成

- 高风险项目归档、成长证据发布和归档回滚不再直接写入，统一创建任务、人工审批，再由内部受控适配器执行。
- 任务协议升级为 `1.1`，补充操作白名单、读写路径边界、执行批次、心跳、重试退避、路由尝试和标准结果字段。
- 执行层改为适配器注册表，业务模块不再硬编码 Codex；Codex、OpenClaw、QClaw 收件箱、内部执行器和人工任务包共用状态协议。
- Codex 以 `workspace-write` 沙箱和显式可写目录运行；Windows `.cmd` 包装器改为解析 Node 入口，完整保留多行中文任务指令。
- OpenClaw 增加 CLI、默认模型、Ollama 模型、Gateway 和 Cron 实际探测；不可用时不参与路由。
- OpenClaw Cron 在 Gateway 健康时汇入任务中心，任务中心仍是唯一审核与结果账本。
- 每日行动建议必须包含今日重点、学生、家长、老师、不建议事项、观察点和依据来源，并校验日期与待审核状态。
- QClaw、人工导入和自动执行结果统一规范为 `TaskResult`，保存产物、文件变更、校验、失败原因、重试和指标。
- 增加执行心跳、心跳丢失、超时分类、取消、退避重试和自动降级；最终始终可落到人工任务包。
- 智能路由综合可用性、授权、任务类型、数据边界、截止时间、历史质量、速度和成本，并保存候选分数与选择原因。

## 真实环境验收

- 任务中心显示协议 `1.1`，统一展示任务状态、来源、执行者、审批、心跳、路由模式、任务输入、预期输出和权限。
- 本机 Codex 配置存在无效枚举值，健康探测已识别为异常，不再误报授权或进入自动路由。
- 本机 OpenClaw 默认指向未安装的 Ollama 模型，适配器已识别为不可执行并降级到 QClaw 或人工路径。
- 高风险归档任务在界面保持待审批，未发生绕过任务中心的直接发布。

## 验证命令

```powershell
pnpm test

node --check electron/preload.cjs

```

## 运行前提

自动执行依赖对应 Agent 的本机配置与模型可用。适配器异常不会导致任务丢失，任务会保存原始上下文并按候选顺序降级，最终进入人工任务包。
