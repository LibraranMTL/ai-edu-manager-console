# Windows 0.8.4 学习项目数据一致性整改

## 交付范围

本批次只整改学习项目闭环的数据一致性，不提前交付 0.8.5 的界面流程精简。

- 严格项目消化批次与逐文件回执。
- 正式资产复用和幂等来源记录。
- 跨主机稳定知识身份与真实来源约束。
- 暂存审核、知识审核、归档和发布状态机。
- 暂存晋升事务回滚和项目完成统一闸门。

## 协议变化

项目消化提交后，控制台写入：

- `.edu-manager/project-digest-request.json`：只读请求，冻结项目、批次、相对路径和 SHA-1。
- `.edu-manager/project-digest-receipt.json`：Agent 独立写入的逐文件完成回执。
- `.edu-manager/project-digest-state.json`：控制台维护的状态与历史批次，不允许 Agent 覆盖。

旧回执、错误项目、错误批次、缺少逐文件清单、SHA-1 不一致或消化期间发生变化的文件都不会被标记为完成。部分有效回执只确认对应文件，其余文件继续待处理。

## 归档与发布闸门

归档前必须满足：

1. 已绑定至少一名学生。
2. 项目消化无待处理、等待回执或失败状态。
3. 暂存资料均已晋升、分析或排除。
4. 项目知识均已完成审核。

发布还必须满足：

1. 项目已经归档。
2. 每名绑定学生至少有一条已确认且带来源路径的个人成长证据。

## 旧数据只读审计

2026-07-20 对本机 3 个既有项目执行只读检查：

- 3 个项目根目录和工作空间均可访问。
- 1 个历史项目为“消化中、无提交文件”的不可能状态；0.8.4 读取时自动恢复为待处理或已收口，不改写原资料。
- 1 个历史已发布项目仍有 35 份未收口暂存资料和 1 条待审核知识；0.8.4 保留历史发布记录，但将其列为风险，并阻止再次归档或发布，直到人工治理完成。

审计遵循“登记接管、原地兼容、按需迁移”：不批量移动项目文件，不重建资产身份，不静默覆盖用户审核结果。
