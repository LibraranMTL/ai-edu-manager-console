# Agent 接入与调度中心 R16：计划优化与实施记录

基线：Windows 0.21.1 R15 `smart-material-correction-r15-20261013`。用户指定 EXE 的 SHA-256 已核对为 `ECAD9C1DF687F07CF9964F99FBCDA45034078302AEE2F53DE38C74A80EE35E20`。沿用当前包含 R15 成果的工作区；没有重置用户改动、安装或发布正式版本。

## 对 P0–P2 的优化

1. **先定义权限继承，再集中界面。** 本机登录可复用，分类、消化、卡片和研究分别授权；R15 的分类备用同意不扩张为消化备用同意。项目消化默认继承学生设置，可显式覆盖；学生停用仍约束项目。分类、卡片和研究只接受学生级策略，避免显示不会实际生效的项目设置。
2. **统一认证配置与任务资格分开。** 分类和消化使用同一官方连接描述；任务资格仍各自绑定程序指纹、认证范围、认证版本和有效期。修改连接后不能复用另一授权环境的资格。刷新页面零模型调用，合成验证只在明确验证或执行边界发生。
3. **发送状态决定切换。** 只有明确的发送前不可用、认证失败或资格失败可尝试已授权备用。发送未知、已有执行编号、敏感保护、未知异常不自动切换；路由记录必须先耐久写入。桌面交接需另行启用，表示等待用户检查发送，不显示为后台成功。
4. **统一设置采用增量覆盖。** 原学生、项目、授权、会话与厂商凭据存储保留，首次读取只投影旧配置，不重写历史。中心新增独立的版本化策略文件，串行写入、乐观版本检查、变更历史和首次更新备份。损坏时拒绝执行，不回退为宽权限默认值。
5. **执行状态必须闭环。** 消化派发失败同时更新任务为 blocked、学生消化状态为 failed，并记录尝试原因，防止页面仍显示执行中。授权在实际发送与知识提交前复核。
6. **验收分层。** 纯策略测试、生产主进程加真实 Worker 的组合测试、真实组件浏览器测试、包内一致性、真实厂商合成调用分别记录，不能用某一层替代其余层。

## 数据和回滚

- 新策略文件：应用数据目录下 `agent-control/policies.json`，schema 为 `edu-manager.agent-control.v1`。
- 现有 `classification-auth` 连接描述复用为中心连接信息；其中只保存官方配置位置和版本，不复制凭据。
- 旧配置没有中心覆盖时按原范围读取；首次启用消化备用和桌面交接须由用户在中心确认。
- 保存时不修改真实学生资料、知识产物或历史任务身份。不批量重派旧任务，不自动核销未知执行。
- `policies.json.pre-update.bak` 保存第一次变更前的既有中心策略；变更历史保留最近200条。回滚程序前先退出应用，备份整个应用数据；恢复旧策略应恢复相应完整备份，不能把删除策略文件当作“撤销授权”。

## 验收边界

这是独立开发候选，未自动安装、未上传、未推送、未修改正式版本清单。实际厂商通道、签名、包内探针与最终测试数字以追加记录为准。其他 Agent 的新后台接口、真实学生长期无人值守质量、目标低配机四小时运行没有因本轮中心改造自动获得验收。

## 用户操作验收

1. 退出旧版本、备份应用数据后启动候选。进入 Agent 接入与调度中心，确认当前学生。
2. 在资料消化中设置首选 WorkBuddy、备用 Codex；需要手工兜底时开启 WorkBuddy 桌面交接，确认并保存。
3. WorkBuddy 后台未认证且 Codex 合格时，任务应记录两条尝试并由 Codex 接管；没有学生范围授权的 Agent 不得被选择。
4. 后台均不可用且已授权桌面交接时，任务进入等待用户发送；桌面程序打开不等于任务完成。
5. 切换学生检查权限独立；已有分类备用不会自动勾选消化备用。刷新中心不会产生模型请求。
6. 停用消化后，新消化应阻塞；有未知执行编号的历史任务仍须在队列核对，不能强行重派。
